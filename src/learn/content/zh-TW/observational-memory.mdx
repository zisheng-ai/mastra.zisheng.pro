基本的訊息歷史有其限制。隨著對話增長，原始歷史很快就會堆積起來：Tool 呼叫、等待時間查詢、天氣檢查、擷取的樂園資料。在本課程中，你將啟用 Observational Memory，將持續增長的歷史壓縮成密度更高、Agent 真正能運用的 context。

你會將 Agent 切換至 `observationalMemory`，並將 scope 設為 `resource`，讓 memory 能跨 thread 跟隨使用者。接著，你會在 Studio 中進行測試：先在一個 thread 開始對話，再到新的 thread 延續對話。即使 thread 是全新的，先前的偏好仍會保留下來。

這點很重要，因為 Observational Memory 以自動壓縮取代手動調整 `lastMessages`。即使經歷長時間的 session 與多個 thread，對話仍能保持連貫，不必在每次呼叫時都帶上全部的原始歷史。

> 「你不會記得一生中每場對話的每一個字。你會觀察發生過的事，久而久之，這些觀察會凝聚成更有用的資訊。OM 正是以相同的概念為基礎。」
>
> — Guil Hernandez
