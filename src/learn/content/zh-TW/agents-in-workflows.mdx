購票 Workflow 可以建立報價、暫停以等待核准，並模擬扣款。在本課程中，你會用兩種方式擴充它，藉此呈現 Tool 和 Agent 如何各自在 Workflow 中發揮作用，以及何時該選擇其中一種。

你會先加入 `validatePark` 步驟，使用樂園查詢 Tool 確認提交的樂園名稱，完成後才執行其他作業。扣款後，你會加入直接呼叫主題樂園 Agent 的 `postPurchaseSummary` 步驟——它會使用自己的 Tool 產生簡短的遊園摘要，並以串流方式將內容納入最終輸出。

這點很重要，因為 Workflow 中的每個步驟並不都有相同需求。驗證作業要求嚴謹且具確定性，因此適合呼叫 Tool。產生實用的遊園摘要需要情境與判斷，因此呼叫 Agent 很合理。Workflow 掌控執行順序；每個步驟則採用最適合該項工作的方式。

> 「一開始由 Tool 處理嚴謹的查詢，最後由 Agent 負責推理，而 Workflow 自始至終掌控執行順序。」
>
> — Guil Hernandez
