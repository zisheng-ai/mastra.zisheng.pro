隨著課程逐步推進，你的 Theme Park Agent 正從「依照 instructions 聊天」，進展到能可靠地處理現實世界的資料。在本課程中，你會加入第一個缺少的基礎元件：一個能將人類使用的樂園名稱轉換成正式樂園 ID 的 Tool。

你會建立專用的樂園查詢 Tool，用它查詢遠端 endpoint、透過 schemas 驗證輸入與輸出，並在名稱可能對應多個結果時，回傳一小組相符項目。接著，你會直接在 Mastra Studio 中測試 Tool，最後將它連接至 Theme Park Agent，讓 Agent 在對話期間能自動呼叫該 Tool。

這點很重要，因為後續每個 Q Times request 都必須有正確的樂園 ID，不能只使用猜測的樂園名稱。藉由驗證 Tool 的回傳結構，並在 observability 中檢查 Tool calls，你就能打下可靠的基礎，以便下一步擷取即時等候時間。

> 「Tools 適合用在 Agent 需要真實情境資訊的時刻，例如將樂園名稱轉換成其他每個 API call 都依賴的唯一 ID。」
>
> — Guil Hernandez
