Agent はすでにパークを検索し、リアルタイムの待ち時間を取得し、Web ページから詳細情報を抽出し、天気も考慮できます。しかし、1 回の Tool 呼び出しでは収まらないタスクもあります。このレッスンでは、人間による承認ゲートを備えた複数ステップのチケット購入 Workflow を構築します。

モックのチケット購入 Workflow に、見積もりの作成、ユーザー承認のための一時停止、決済処理という 3 つの明示的なステップを作成します。各ステップには独自の入力スキーマと出力スキーマがあるため、データはステップ間を明確に流れます。Workflow を Mastra のエントリーポイントに接続して Studio で実行し、一時停止と再開を含むすべてのステップが順番に実行される様子を確認します。

この仕組みが重要なのは、手数料の計算、入力の検証、金額の確認など、一部のロジックは決定論的であり、言語モデルを通すべきではないからです。Workflow を使えば実行順序を制御でき、金銭が動く前に承認を待つための明確な場所を設けられます。

> 「決定論的な処理を、モデルに推論させないでください。Workflow のステップに置くだけでよいのです。」
>
> — Guil Hernandez
