チケット購入 Workflow では、見積もりの作成、承認待ちでの一時停止、決済のシミュレーションを実行できます。このレッスンでは、Workflow 内で Tool と Agent がそれぞれどのような役割を担えるのか、また両者をどう使い分けるのかが分かるように、2 つの機能を追加します。

まず、パーク検索 Tool を使って、送信されたパーク名をほかの処理より先に確認する `validatePark` ステップを追加します。決済後には、テーマパーク Agent を直接呼び出す `postPurchaseSummary` ステップを追加します。このステップは、Agent の Tool を使って簡潔な訪問ガイドを生成し、最終出力の一部としてストリーミングします。

この区別が重要なのは、Workflow のすべてのステップが同じ要件を持つわけではないからです。検証は厳密かつ決定論的なので、Tool の呼び出しが適しています。役立つ訪問ガイドの生成にはコンテキストと判断が必要なので、Agent の呼び出しが適しています。Workflow が処理順序を管理し、各ステップはその処理に最適な手段を使います。

> 「最初の厳密な検索は Tool が担い、最後の推論は Agent が担います。その間の処理順序は、すべて Workflow が管理します。」
>
> — Guil Hernandez
