隨着課程逐步推進，你的主題樂園 Agent 正由「按照指示聊天」轉變為可靠地處理現實世界的數據。在本課中，你會加入第一個缺少的基本元件：一個 Tool，讓 Agent 可以把人類使用的樂園名稱轉換為標準樂園 ID。

你會建立專用的樂園查找 Tool，查詢遠端 endpoint、使用 schema 驗證輸入和輸出，並在名稱含糊時傳回少量相符結果。然後，你會直接在 Mastra Studio 測試 Tool，最後把它接入主題樂園 Agent，讓 Agent 在對話期間自動調用它。

這一點很重要，因為後續每個 Q Times 請求都必須取得正確的樂園 ID，而不能只靠猜測樂園名稱。驗證 Tool 的回傳結構，並在 observability 中檢查 Tool 調用，能為下一步取得即時輪候時間打好可靠基礎。

> 「當 Agent 需要真實情境時，就要使用 Tool——例如把樂園名稱轉換成其他所有 API 調用都依賴的唯一 ID。」
>
> — Guil Hernandez
