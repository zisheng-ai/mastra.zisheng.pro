基本訊息記錄有其限制。對話愈來愈長時，原始記錄會迅速累積：Tool 調用、輪候時間查找、天氣檢查，以及從樂園網頁抓取的數據。在本課中，你會啟用 Observational Memory，把持續增長的記錄壓縮成更密集、Agent 真正能夠使用的情境。

你會將 Agent 切換至 `observationalMemory`，把 scope 設為 `resource`，讓 Memory 可以跨 thread 跟隨用戶，然後在 Studio 中測試：先在一個 thread 開始對話，再於新 thread 繼續。即使 thread 是全新的，先前的偏好仍會保留。

這一點很重要，因為 Observational Memory 以自動壓縮取代手動調整 `lastMessages`。即使經過長時間對話和多個 thread，對話仍可保持連貫，而毋須在每次調用時帶上所有原始記錄。

> 「你不會記得自己每次對話的每一個字。你會觀察發生過的事，而這些觀察會隨時間濃縮成更有用的內容。OM 正是建基於同一理念。」
>
> — Guil Hernandez
