チケット購入 Workflow を構築した今こそ、Agent と Workflow の役割を明確に区別しておきましょう。これらの用語は大まかに使われがちですが、ここで重要なのは、実際にどう動作し、このプロジェクトでどう連携するかです。

Agent は、システムの「会話する頭脳」です。Tool と Memory を備えた言語モデルであり、進む経路は事前に決まっていません。何を行い、どの Tool を呼び出し、いつ完了するかをモデルが判断します。Workflow はその逆で、ステップ、順序、そして何をもって「完了」とするかを開発者が定義します。最も分かりやすい例がチケット購入フローです。モデルにチェックアウト方法を考えさせるのではなく、その手順を定義します。Mastra では、Workflow 内で Agent を使うことも、Workflow を Agent の Tool として使うこともできます。

この違いを理解しておけば、単純なタスクを Workflow にして過剰設計したり、決定論的に制御すべき処理をモデルに任せたりせず、適切な方法を選べます。

> 「モデルにチェックアウト方法を考えさせるのではありません。チェックアウトを私たちが定義するのです。」
>
> — Guil Hernandez
