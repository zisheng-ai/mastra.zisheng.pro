購票 Workflow 可以建立報價、暫停以等待批准，並模擬收費。在本課中，你會以兩種方式擴展它，展示 Tool 和 Agent 如何各自在 Workflow 中發揮作用，以及甚麼時候應該選用其中一種。

你會先加入一個 `validatePark` 步驟，使用樂園查找 Tool，在執行其他操作之前確認提交的樂園名稱。收費後，你會加入一個 `postPurchaseSummary` 步驟，直接調用主題樂園 Agent——它會使用自己的 Tool 產生一份簡短的遊覽摘要，並以串流方式將摘要作為最終輸出的一部分傳回。

這一點很重要，因為 Workflow 中並非每個步驟都有相同要求。驗證必須嚴謹而且具確定性，因此適合調用 Tool。產生實用的遊覽摘要則需要情境和判斷，所以調用 Agent 更合理。Workflow 負責整個次序，而每個步驟都會使用最適合該部分工作的方式。

> 「開始時由 Tool 處理嚴謹的查找，結束時由 Agent 負責推理，而 Workflow 從頭到尾掌控次序。」
>
> — Guil Hernandez
