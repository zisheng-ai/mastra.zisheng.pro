购票 Workflow 已经可以生成报价、暂停等待审批并模拟扣款。本课将从两个方向扩展它，展示 Tool 和 Agent 如何分别在 Workflow 中发挥作用，以及应该如何选择。

首先添加 `validatePark` 步骤，在其他操作开始之前使用公园查询 Tool 确认用户提交的公园名称。扣款之后，再添加 `postPurchaseSummary` 步骤，直接调用主题公园 Agent。它会使用自己的 Tool 生成简短的游园摘要，并将其作为最终输出的一部分流式返回。

这很重要，因为 Workflow 中的各个步骤有不同的要求。验证需要严格且确定性的结果，因此适合调用 Tool；生成实用的游园摘要需要上下文和判断力，因此适合调用 Agent。Workflow 负责整体执行顺序，每个步骤则选择最适合该任务的方式。

> “开头的严格查询交给 Tool，结尾的推理交给 Agent，而完整执行顺序始终由 Workflow 掌控。”
>
> — Guil Hernandez
