Leçon après leçon, votre Agent de parc à thème passe d'une « conversation fondée sur des instructions » à un travail fiable avec des données réelles. Dans cette leçon, vous ajouterez le premier élément manquant : un Tool que l'Agent peut utiliser pour transformer le nom humain d'un parc en son identifiant canonique.

Vous créerez un Tool dédié à la recherche de parc, qui interroge un point de terminaison distant, valide les entrées et sorties avec des schémas et renvoie un petit ensemble de correspondances lorsque le nom est ambigu. Vous le testerez directement dans Mastra Studio, puis le relierez à votre Agent de parc à thème pour qu'il puisse l'appeler automatiquement durant les conversations.

C'est important, car chaque requête QTimes ultérieure dépend du bon identifiant de parc, et non d'un simple nom deviné. En validant la forme de retour du Tool et en inspectant les appels de Tool dans l'observabilité, vous établissez une base fiable pour récupérer ensuite les temps d'attente en direct.

> "Les Tools servent lorsque votre Agent a besoin d'un contexte réel, par exemple pour transformer un nom de parc en l'identifiant dont dépend tout autre appel d'API."
>
> — Guil Hernandez
