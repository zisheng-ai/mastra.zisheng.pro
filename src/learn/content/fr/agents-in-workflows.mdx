Le Workflow d'achat de billets peut établir un devis, attendre une approbation et simuler un paiement. Dans cette leçon, vous l'étendrez de deux façons qui montrent comment les Tools et les Agents peuvent chacun jouer un rôle dans un Workflow, et quand privilégier l'un ou l'autre.

Vous ajouterez d'abord une étape `validatePark` qui utilise le Tool de recherche de parc pour confirmer le nom soumis avant toute autre opération. Après le paiement, vous ajouterez une étape `postPurchaseSummary` qui appelle directement l'Agent de parc à thème : il génère un bref récapitulatif de la visite à l'aide de ses Tools et le diffuse dans la sortie finale.

Cette distinction est importante, car toutes les étapes d'un Workflow n'ont pas les mêmes exigences. La validation est stricte et déterministe ; un appel de Tool convient donc parfaitement. Générer un récapitulatif de visite utile demande du contexte et du discernement, ce qui justifie l'appel à l'Agent. Le Workflow pilote la séquence et chaque étape utilise ce qui convient à cette partie du travail.

> "Un Tool effectue la recherche stricte au début. L'Agent assure le raisonnement à la fin. Le Workflow pilote la séquence de bout en bout."
>
> — Guil Hernandez
