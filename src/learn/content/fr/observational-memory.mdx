L'historique de messages de base a ses limites. À mesure que les conversations s'allongent, l'historique brut s'accumule rapidement : appels de Tools, recherches de temps d'attente, vérifications météo, données de parc extraites. Dans cette leçon, vous activerez Observational Memory, qui compresse cet historique croissant en un contexte plus dense que l'Agent peut réellement utiliser.

Vous basculerez l'Agent vers `observationalMemory`, définirez le scope sur `resource` pour que la mémoire suive l'utilisateur d'un thread à l'autre, puis le testerez dans Studio en commençant une conversation dans un thread et en la reprenant dans un nouveau. Les préférences précédentes sont conservées, même si le thread est nouveau.

C'est important, car Observational Memory remplace le réglage manuel de `lastMessages` par une compression automatique. La conversation reste cohérente au fil de longues sessions et de plusieurs threads sans transporter tout l'historique brut à chaque appel.

> "Vous ne vous souvenez pas de chaque mot de toutes les conversations que vous avez eues. Vous observez ce qui s'est passé et, avec le temps, cela se condense en quelque chose de plus utile. OM repose sur cette même idée."
>
> — Guil Hernandez
