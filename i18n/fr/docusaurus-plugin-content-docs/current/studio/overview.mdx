# Studio

Studio fournit une interface utilisateur interactive pour créer, tester et gérer vos agents, workflows et tools. Exécutez-le localement pendant le développement, ajoutez une [authentification](/docs/studio/auth) ou [déployez-le](/docs/studio/deployment) en production afin que votre équipe puisse gérer les agents, surveiller les performances et obtenir des informations grâce à Observability intégrée.

:::tip[📹 Watch]

Regardez la [présentation de Mastra Studio](https://youtu.be/ojGu6Bi4wYk) pour une courte démonstration de la création, des tests et de la gestion d’agents dans Studio.

:::

## Démarrer Studio

Si vous avez créé votre application avec `create mastra`, démarrez le serveur de développement avec le script `dev`. Vous pouvez aussi l’exécuter directement avec `mastra dev`.

```bash npm2yarn
npm run dev
```

Une fois le serveur en cours d’exécution, vous pouvez :

- Ouvrir l’interface Studio à l’adresse [`localhost:4111`](http://localhost:4111/) pour interagir avec vos agents, workflows et tools.
- Ouvrir [`localhost:4111/swagger-ui`](http://localhost:4111/swagger-ui) pour découvrir l’API REST sous-jacente et interagir avec elle.

Pendant l’exécution de Studio, vous pouvez modifier vos [agents](/docs/agents/overview), [workflows](/docs/workflows/overview) et d’autres parties de votre application Mastra en temps réel.

## Déployer Studio

Lorsque vous êtes prêt à partager Studio avec votre équipe, vous pouvez le déployer en production avec [Studio sur la plateforme Mastra](/docs/mastra-platform/studio) ou votre propre infrastructure. Consultez la [documentation de déploiement](/docs/studio/deployment) pour savoir comment faire.

## Éléments fondamentaux

### Agents

Discutez directement avec votre agent, changez de [modèle](/models) et ajustez des paramètres comme la température et top-p pour comprendre leur effet sur la sortie.

Lorsque vous interagissez avec votre agent, vous pouvez suivre son raisonnement et consulter les sorties d’appels de tool. Vous pouvez également [observer](#observability) les traces et journaux pour voir comment les réponses sont générées.

Vous pouvez également attacher des [scorers](#scorers) pour mesurer et comparer la qualité des réponses au fil du temps.

Vous pouvez envoyer un message de suivi dans le même thread pendant le stream de réponse d’un agent. Studio affiche le message comme en attente jusqu’à sa confirmation par le stream, puis poursuit la réponse sous ce suivi. Les autres onglets Studio ayant ouvert le même thread peuvent observer le stream actif.

Utilisez [Editor](/docs/editor/overview) pour permettre aux membres non techniques de l’équipe d’itérer sur les agents, de versionner chaque modification et d’exécuter des expériences sans redéploiement.

### Workflows

Visualisez votre workflow sous forme de graphe et exécutez-le pas à pas avec une entrée personnalisée. Pendant l’exécution, l’interface se met à jour en temps réel pour afficher l’étape active et le chemin suivi.

Lors de l’exécution d’un workflow, vous pouvez aussi consulter des traces détaillées indiquant les appels de tool, les sorties JSON brutes et les éventuelles erreurs survenues.

### Processors

Consultez les processors d’entrée et de sortie attachés à chaque agent. Le panneau de détails de l’agent liste chaque processor par nom et type afin que vous puissiez vérifier le bon branchement de vos garde-fous, limiteurs de tokens et processors personnalisés avant les tests.

Consultez [processors](/docs/agents/processors) et [garde-fous](/docs/agents/guardrails) pour les détails de configuration.

### MCP servers

Listez les serveurs MCP attachés à votre instance Mastra et explorez leurs tools disponibles.

### Tools

Exécutez les tools seuls pour observer leur comportement et les tester avant de les attribuer à un agent. En cas de problème, réexécutez un tool de façon isolée pour déboguer la situation.

### Workspaces

Parcourez les fichiers du système de fichiers de workspace de votre agent avec un navigateur de fichiers intégré. Basculez entre les montages de workspace, créez des répertoires et affichez le contenu des fichiers avec coloration syntaxique. Les workspaces accessibles en écriture permettent la création de répertoires et la suppression de fichiers ; les workspaces en lecture seule sont indiqués comme tels. L’onglet Skills liste toutes les skills découvertes avec leurs instructions, références et métadonnées. Installez des skills communautaires depuis [skills.sh](https://skills.sh) ou supprimez celles qui existent déjà.

Consultez [workspaces](/docs/workspace/overview) pour les détails de configuration.

### Request context

Définissez des variables d’exécution qui alimentent les instructions et les tools de votre agent par injection de dépendances. Modifiez le contexte de requête en JSON ou utilisez un formulaire piloté par schéma lorsque votre agent définit `requestContextSchema`. Les valeurs persistent entre les chats de test et les expériences ; vous pouvez ainsi déclencher des flux conditionnels sans redémarrer.

Consultez [request context](/docs/server/request-context) pour les détails de configuration.

## Évaluation

Utilisez le filtre de date pour limiter les métriques de score à une plage temporelle prédéfinie ou personnalisée.

### Scorers

L’onglet Scorers affiche les résultats des scorers de votre agent à mesure qu’ils s’exécutent. Lorsque des messages passent par votre agent, les scorers définis évaluent chaque sortie de manière asynchrone et affichent leurs résultats ici. Vous pouvez comprendre comment vos scorers réagissent à différentes interactions, comparer les performances entre les cas de test et identifier les améliorations possibles.

### Datasets

Créez et gérez des collections de cas de test pour évaluer vos agents et workflows. Importez des éléments depuis CSV ou JSON, définissez les schémas d’entrée et de vérité terrain, et épinglez des versions précises afin de reproduire exactement les expériences. Exécutez des expériences avec des [scorers](/docs/evals/overview) pour comparer la qualité entre les prompts, modèles ou modifications de code.

Consultez la [vue d’ensemble des datasets](/docs/datasets/overview) pour l’API complète et les détails de versionnement.

### Experiments

Exécutez tous les éléments d’un dataset avec un agent, un workflow ou un scorer et rassemblez les résultats en un seul endroit. Sélectionnez une cible, attachez éventuellement des scorers et déclenchez l’expérience. La vue de résultats affiche l’entrée, la sortie, l’état et les ventilations de scores de chaque élément. Comparez deux expériences côte à côte pour mesurer l’impact de modifications de prompt, de modèle ou de code.

Consultez la [vue d’ensemble des datasets](/docs/datasets/overview) pour les détails de configuration.

## Settings

Configurez la connexion entre Studio et votre serveur Mastra. La page de paramètres comprend :

- **URL de l’instance Mastra** : l’URL de base de votre serveur Mastra, par exemple `http://localhost:4111`.
- **Préfixe d’API** : préfixe de chemin facultatif pour toutes les requêtes d’API, par défaut `/api`.
- **En-têtes personnalisés** : ajoutez des paires clé-valeur envoyées avec chaque requête, utiles pour les tokens d’authentification ou les en-têtes de routage.
- **Thème** : basculez entre les thèmes sombre, clair et système.

## Code configuration

En plus de l’interface de [paramètres](#settings), vous pouvez aussi configurer le serveur de développement local et Studio avec l’option [`server`](/reference/configuration#server-options) de votre fichier `src/mastra/index.ts`.

Par défaut, Studio s’exécute à l’adresse [http://localhost:4111](http://localhost:4111). Vous pouvez modifier [`host`](/reference/configuration#serverhost) et [`port`](/reference/configuration#serverport).

Mastra prend également en charge le développement HTTPS via l’indicateur [`--https`](/reference/cli/mastra#--https), qui crée et gère automatiquement les certificats de votre projet. Lorsque vous exécutez `mastra dev --https`, une clé privée et un certificat sont générés pour localhost, ou pour l’hôte configuré. Consultez la [référence HTTPS](/reference/configuration#serverhttps) pour en savoir plus.
