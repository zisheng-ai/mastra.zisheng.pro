# Exporter Arize

[Arize](https://arize.com/) fournit des plateformes d'observabilité pour les applications d'IA avec [Phoenix](https://phoenix.arize.com/) (open source) et [Arize AX](https://arize.com/generative-ai/) (entreprise). L'exporter Arize envoie les traces au moyen d'OpenTelemetry et des conventions sémantiques [OpenInference](https://github.com/Arize-ai/openinference/tree/main/spec), compatibles avec toute plateforme OpenTelemetry prenant en charge OpenInference.

## Installation {/* #installation */}

```bash npm2yarn
npm install @mastra/arize@latest
```

## Configuration {/* #configuration */}

### Configuration de Phoenix {/* #phoenix-setup */}

Phoenix est une plateforme d'observabilité open source qui peut être auto-hébergée ou utilisée via Phoenix Cloud.

#### Prérequis {/* #prerequisites */}

1. **Instance Phoenix** : déployez-la avec Docker ou inscrivez-vous à [Phoenix Cloud](https://app.phoenix.arize.com/login)
1. **Point de terminaison** : l'URL de votre point de terminaison Phoenix (elle se termine par `/v1/traces`)
1. **Clé d'API** : facultative pour les instances sans authentification, requise pour Phoenix Cloud
1. **Variables d'environnement** : définissez votre configuration

```bash title=".env"
# Required
PHOENIX_COLLECTOR_ENDPOINT=http://localhost:6006/v1/traces  # Or your Phoenix Cloud URL

# Optional
PHOENIX_API_KEY=your-api-key  # For authenticated Phoenix instances
PHOENIX_PROJECT_NAME=mastra-service  # Defaults to 'mastra-service'
```

#### Configuration automatique {/* #zero-config-setup */}

Une fois les variables d’environnement définies, utilisez l’exporter sans configuration :

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { ArizeExporter } from '@mastra/arize'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      arize: {
        serviceName: 'mastra-service',
        exporters: [new ArizeExporter()],
      },
    },
  }),
})
```

#### Configuration explicite {/* #explicit-configuration */}

Vous pouvez également transmettre les identifiants directement ; ils prévalent sur les variables d’environnement :

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { ArizeExporter } from '@mastra/arize'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      arize: {
        serviceName: process.env.PHOENIX_PROJECT_NAME || 'mastra-service',
        exporters: [
          new ArizeExporter({
            endpoint: process.env.PHOENIX_COLLECTOR_ENDPOINT!,
            apiKey: process.env.PHOENIX_API_KEY,
            projectName: process.env.PHOENIX_PROJECT_NAME,
          }),
        ],
      },
    },
  }),
})
```

:::info[Démarrage rapide avec Docker]

Effectuez un test local avec une instance Phoenix en mémoire :

```bash
docker run --pull=always -d --name arize-phoenix -p 6006:6006 \
  -e PHOENIX_SQL_DATABASE_URL="sqlite:///:memory:" \
  arizephoenix/phoenix:latest
```

Définissez `PHOENIX_COLLECTOR_ENDPOINT=http://localhost:6006/v1/traces`, puis exécutez votre Agent Mastra pour consulter les traces sur [localhost:6006](http://localhost:6006).

:::

### Configuration d'Arize AX {/* #arize-ax-setup */}

Arize AX est une plateforme d'observabilité d'entreprise qui offre des fonctionnalités avancées aux systèmes d'IA en production.

#### Prérequis {/* #prerequisites-1 */}

1. **Compte Arize AX** : inscrivez-vous sur [app.arize.com](https://app.arize.com/)
1. **Identifiant d'espace** : l'identifiant de l'espace de votre organisation
1. **Clé d'API** : générez-la dans les paramètres d'Arize AX
1. **Variables d'environnement** : définissez vos identifiants

```bash title=".env"
# Required
ARIZE_SPACE_ID=your-space-id
ARIZE_API_KEY=your-api-key

# Optional
ARIZE_PROJECT_NAME=mastra-service
```

#### Configuration automatique {/* #zero-config-setup-1 */}

Une fois les variables d’environnement définies, utilisez l’exporter sans configuration :

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { ArizeExporter } from '@mastra/arize'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      arize: {
        serviceName: 'mastra-service',
        exporters: [new ArizeExporter()],
      },
    },
  }),
})
```

#### Configuration explicite {/* #explicit-configuration-1 */}

Vous pouvez également transmettre les identifiants directement ; ils prévalent sur les variables d’environnement :

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'

        ],
      },
    },
  }),
})
```

## Options de configuration {/* #configuration-options */}

L'exporter Arize accepte une configuration avancée permettant d'ajuster précisément le comportement d'OpenTelemetry :

### Configuration complète {/* #complete-configuration */}

```typescript
new ArizeExporter({
  // Phoenix Configuration
  endpoint: 'https://your-collector.example.com/v1/traces', // Required for Phoenix

  // Arize AX Configuration
  spaceId: 'your-space-id', // Required for Arize AX

  // Shared Configuration
  apiKey: 'your-api-key', // Required for authenticated endpoints
  projectName: 'mastra-service', // Optional project name

  // Optional OTLP settings
  headers: {
    'x-custom-header': 'value', // Additional headers for OTLP requests
  },

  // Debug and performance tuning
  logLevel: 'debug', // Logging: debug | info | warn | error
  batchSize: 512, // Batch size before exporting spans
  timeout: 30000, // Timeout in ms before exporting spans

  // Custom resource attributes
  resourceAttributes: {
    'deployment.environment': process.env.NODE_ENV,
    'service.version': process.env.APP_VERSION,
  },
})
```

### Options de traitement par lots {/* #batch-processing-options */}

Contrôlez la mise en lots et l'exportation des traces :

```typescript
new ArizeExporter({
  endpoint: process.env.PHOENIX_COLLECTOR_ENDPOINT!,
  apiKey: process.env.PHOENIX_API_KEY,

  // Batch processing configuration
  batchSize: 512, // Number of spans to batch (default: 512)
  timeout: 30000, // Max time in ms to wait before export (default: 30000)
})
```

### Attributs de ressource {/* #resource-attributes */}

Ajoutez des attributs personnalisés à tous les spans exportés :

```typescript
new ArizeExporter({
  endpoint: process.env.PHOENIX_COLLECTOR_ENDPOINT!,
  resourceAttributes: {
    'deployment.environment': process.env.NODE_ENV,
    'service.namespace': 'production',
    'service.instance.id': process.env.HOSTNAME,
    'custom.attribute': 'value',
  },
})
```

### Métadonnées personnalisées {/* #custom-metadata */}

Les attributs de span non réservés sont sérialisés dans la charge utile OpenInference `metadata` et apparaissent dans Arize/Phoenix. Vous pouvez les ajouter au moyen de `tracingOptions.metadata` :

```ts
await agent.generate(input, {
  tracingOptions: {
    metadata: {
      companyId: 'acme-co',
      tier: 'enterprise',
    },
  },
})
```

Les champs réservés tels que `input`, `output`, `sessionId`, les identifiants de thread et d'utilisateur ainsi que les identifiants OpenInference sont automatiquement exclus.

## Conventions sémantiques OpenInference {/* #openinference-semantic-conventions */}

Cet exporter implémente les [conventions sémantiques OpenInference](https://github.com/Arize-ai/openinference/tree/main/spec) pour les applications d'IA générative, ce qui fournit une structure de trace normalisée entre les différentes plateformes d'observabilité.
