# Vue d’ensemble du déploiement

Les applications Mastra peuvent être déployées dans tout environnement compatible avec Node.js. Vous pouvez déployer un serveur Mastra, l’intégrer à un framework web existant, le déployer auprès de fournisseurs cloud ou utiliser la [plateforme Mastra](/docs/mastra-platform/overview) pour Observability, Studio et le déploiement de serveur.

## Environnements d’exécution pris en charge

Mastra peut s’exécuter dans les environnements suivants :

- Node.js `v22.13.0` or later
- Bun
- Deno
- Cloudflare

## Options de déploiement

### Mastra server

Mastra fournit un [serveur](/docs/server/mastra-server) basé sur Hono qui peut être déployé indépendamment. Utilisez la commande `mastra build` pour build votre application et déployer la sortie sur la VM, le conteneur ou la plateforme PaaS de votre choix.

Utilisez cette option lorsque vous avez besoin d’un contrôle total sur votre infrastructure, de processus de longue durée ou de connexions WebSocket. Le [guide de déploiement du serveur Mastra](/docs/deployment/mastra-server) fournit davantage de détails.

### Monorepo

Déployez un serveur Mastra dans une configuration monorepo, en suivant la même approche que pour un déploiement autonome.

Consultez le [déploiement monorepo](/docs/deployment/monorepo).

### Mastra platform

La [plateforme Mastra](/docs/mastra-platform/overview) fournit trois produits pour déployer, surveiller et gérer les applications d’IA créées avec le framework Mastra :

- [**Observability**](/docs/mastra-platform/observability) : un produit hébergé autonome fournissant des traces, journaux et métriques consultables dans les projets et déploiements Mastra
- [**Studio**](/docs/mastra-platform/studio) : un environnement visuel hébergé pour tester les agents, exécuter les workflows et inspecter les traces
- [**Server**](/docs/mastra-platform/server) : une cible de déploiement de production qui exécute votre application Mastra en tant que serveur API

Pour en savoir plus, consultez la [vue d’ensemble de la plateforme Mastra](/docs/mastra-platform/overview).

### Fournisseurs cloud

Les applications Mastra peuvent être déployées auprès de fournisseurs cloud et sur des plateformes serverless. Mastra inclut des déployeurs intégrés facultatifs pour Vercel, Netlify et Cloudflare afin d’automatiser le processus de build et de déploiement.

Utilisez cette option pour l’auto-scaling, une gestion minimale de l’infrastructure ou si vous utilisez déjà l’une de ces plateformes.

- [Amazon EC2](/guides/deployment/amazon-ec2)
- [AWS Lambda](/guides/deployment/aws-lambda)
- [Azure App Services](/guides/deployment/azure-app-services)
- [Cloudflare](/guides/deployment/cloudflare)
- [Digital Ocean](/guides/deployment/digital-ocean)
- [Kubernetes](/guides/deployment/kubernetes)
- [Netlify](/guides/deployment/netlify)
- [Vercel](/guides/deployment/vercel)

### Sandbox

Déployez un serveur Mastra dans un sandbox d’espace de travail éphémère, tel que Vercel Sandbox ou E2B, et obtenez une URL publique active en quelques secondes.

Utilisez cette option pour des aperçus instantanés, des déploiements depuis votre pipeline CI, la vérification d’applications créées par des agents ou l’exécution d’instances non fiables par utilisateur. Consultez le [guide de déploiement en sandbox](/docs/deployment/sandbox).

### Web Framework

Lorsque Mastra est intégré à un framework web, il se déploie avec votre application selon le processus de déploiement standard du framework. Les guides ci-dessous couvrent les exigences de configuration propres à chaque framework pour le déploiement.

Utilisez ces guides lorsque vous ajoutez Mastra à une application Next.js ou Astro existante.

- [Avec Next.js sur Vercel](/docs/deployment/web-framework#with-nextjs-on-vercel)
- [Avec Astro sur Vercel](/docs/deployment/web-framework#with-astro-on-vercel)
- [Avec Astro sur Netlify](/docs/deployment/web-framework#with-astro-on-netlify)

## Workflow runners

Les workflows Mastra s’exécutent par défaut avec le moteur d’exécution intégré. Pour les charges de production nécessitant une infrastructure gérée, les workflows peuvent aussi être déployés sur des plateformes spécialisées telles qu’[Inngest](https://www.inngest.com), qui offrent la mémorisation des étapes, les nouvelles tentatives automatiques et la surveillance en temps réel.

Consultez le [guide des exécuteurs de workflows](/docs/deployment/workflow-runners) pour les options d’exécution et le [guide de déploiement Inngest](/guides/deployment/inngest) pour les instructions de configuration.

## Workers

Pour les déploiements de production, Mastra peut exécuter l’orchestration des workflows, la planification cron et l’exécution de tools en arrière-plan dans des processus worker dédiés, séparés du serveur API. Vous pouvez ainsi mettre à l’échelle chaque préoccupation indépendamment et isoler les défaillances. Consultez [Workers](/docs/deployment/workers) pour plus de détails.
