# Studio sur la plateforme Mastra

Studio sur la plateforme Mastra est un espace de travail visuel hébergé qui permet de tester des agents, d’exécuter des workflows et d’inspecter des traces. Utilisez-le lorsque vous souhaitez partager Studio avec votre équipe sans héberger vous-même l’interface utilisateur de Studio.

Vous pouvez déployer Studio depuis la CLI comme indiqué ci-dessous, ou associer un dépôt GitHub pour déployer par push. Consultez l’[intégration GitHub](/docs/mastra-platform/github) pour le flux associé à un dépôt.

:::note
`mastra studio deploy` est l’ancien parcours de déploiement séparé. Les nouveaux projets doivent utiliser la commande unifiée [`mastra deploy`](/docs/mastra-platform/deploy), qui ajoute la validation préalable, les environnements et les bases de données gérées par la CLI.
:::

## Démarrage rapide {/* #quickstart */}

<Steps>
  <StepItem>
    Suivez le [guide de démarrage](/docs) pour créer votre premier projet Mastra.
  </StepItem>

  <StepItem>
    Installez globalement la CLI `mastra` :

    ```bash npm2yarn
    npm install -g mastra
    ```
  </StepItem>

  <StepItem>
    Déployez Studio avec une seule commande :

    ```bash
    mastra studio deploy
    ```

    Lorsque le déploiement réussit, la CLI affiche l’URL de votre instance Studio déployée.
  </StepItem>
</Steps>

Lors de votre premier déploiement, la CLI vous invite à créer un nouveau projet ou à en sélectionner un existant. Elle crée ensuite un fichier `.mastra-project.json` dans le répertoire de votre projet. Ce fichier associe votre projet local à un projet de la plateforme. Il contient les valeurs `projectId`, `projectName` et `organizationId`. Validez ce fichier dans votre dépôt afin que la CI/CD sache quel projet déployer.

## Fonctionnement du déploiement {/* #how-deploy-works */}

La commande `mastra studio deploy` build votre projet et compile `src/mastra/` dans `.mastra/output`. Elle empaquette cette sortie sous la forme d’un artefact ZIP, puis l’envoie et le déploie dans un sandbox cloud.

Un déploiement passe par les états **queued → uploading → starting → running**, ou par **failed** en cas de problème. Si un sandbox est déjà en cours d’exécution pour votre projet, la plateforme le met à jour sur place sans indisponibilité. Sinon, elle crée un nouveau sandbox. L’URL de votre instance est attribuée selon le slug du projet et reste stable entre les déploiements.

Consultez la [référence de la CLI `mastra studio deploy`](/reference/cli/mastra#mastra-studio-deploy) pour la liste complète des indicateurs et son utilisation en CI/CD.

## Fichiers d’environnement {/* #environment-files */}

Un fichier env local est facultatif. Lorsqu’un fichier `.env` ou `.env.*` est présent dans le répertoire du projet, le déploiement regroupe ses variables d’environnement.

Lorsque plusieurs fichiers env sont présents, la CLI vous invite à en choisir un. Pour le sélectionner sans interaction, passez `--env-file` :

```bash
mastra studio deploy --env-file .env.production --yes
```

Pour exécuter la même base de code dans `production` et `staging`, utilisez plutôt la commande unifiée [`mastra deploy --env`](/docs/mastra-platform/deploy#deploy-to-another-environment). Les [environnements](/docs/mastra-platform/environments) remplacent l’ancien modèle d’un projet par environnement.

## Créer un projet sans interaction {/* #create-a-new-project-non-interactively */}

`mastra studio deploy` peut créer un projet lors de sa première exécution. Si `--project <name>` ne correspond pas à un projet existant, la CLI utilise cette valeur comme nom du nouveau projet et le crée après confirmation. Combiné à `--yes`, ce comportement est entièrement scriptable :

```bash
mastra studio deploy --project "my-new-project" --yes
```

Utilisez cette commande depuis la CI ou des agents de programmation IA au lieu de `mastra studio projects create`, qui fonctionne uniquement de manière interactive.
