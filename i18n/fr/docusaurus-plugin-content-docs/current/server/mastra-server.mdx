# Vue d’ensemble de Server

Mastra s’exécute comme un serveur HTTP qui expose vos agents, workflows et autres fonctionnalités en tant qu’endpoints d’API. Le serveur gère le routage des requêtes, l’exécution des middlewares, l’authentification et les réponses en streaming.

:::info

Cette page couvre les options de configuration [`server`](/reference/configuration#server-options) transmises au constructeur `Mastra`. Pour exécuter Mastra avec votre propre serveur HTTP, comme Hono ou Express, consultez [Adaptateurs de serveur](/docs/server/server-adapters).

:::

## Fonctionnalités de Server

- **[Middleware](/docs/server/middleware)** : interceptez les requêtes pour l’authentification, la journalisation, CORS ou l’injection de contexte propre à la requête.
- **[Routes d’API personnalisées](/docs/server/custom-api-routes)** : étendez le serveur avec vos propres endpoints HTTP ayant accès à l’instance Mastra.
- **[Request Context](/docs/server/request-context)** : transmettez des valeurs propres à la requête aux agents, tools et workflows selon les conditions d’exécution.
- **[Adaptateurs de serveur](/docs/server/server-adapters)** : exécutez Mastra avec Express, Hono ou votre propre serveur HTTP au lieu du serveur généré.
- **[Adaptateurs personnalisés](/docs/server/custom-adapters)** : créez des adaptateurs pour des frameworks qui ne sont pas officiellement pris en charge.
- **[SDK client Mastra](/docs/server/mastra-client)** : client sûr du point de vue des types pour appeler agents, workflows et tools depuis des environnements navigateur ou serveur.
- **[A2A](/docs/agents/a2a)** : exposez les agents par des cartes d’agent et des flux de tâches A2A, ainsi que des notifications push.
- **[Authentification](/docs/server/auth)** : sécurisez les endpoints avec JWT, Clerk, Supabase, Firebase, Auth0 ou WorkOS.

## Configuration

Configurez le serveur en transmettant un objet `server` au constructeur `Mastra` :

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    port: 3000, // Defaults to PORT env var or 4111
    host: '0.0.0.0', // Defaults to MASTRA_HOST env var or 'localhost'
  },
})
```

Consultez la [référence de configuration](/reference/configuration#server-options) pour obtenir la liste complète des options de serveur disponibles.

## Deploy your server

Les serveurs Mastra peuvent être déployés dans tout environnement compatible avec Node.js. Déployez-les en production avec la [plateforme Mastra](/docs/mastra-platform/overview) ou votre propre infrastructure. Consultez la [documentation de déploiement](/docs/deployment/overview) pour savoir comment faire.

## Server architecture

Mastra utilise [Hono](https://hono.dev) comme framework de serveur HTTP sous-jacent. Lorsque vous build une application Mastra avec `mastra build`, cette commande génère un serveur HTTP fondé sur Hono dans le répertoire `.mastra`.

Le serveur fournit :

- Des endpoints d’API pour tous les agents et workflows enregistrés
- Des routes d’API et middlewares personnalisés
- Une authentification couvrant plusieurs providers
- Un contexte de requête pour la configuration à l’exécution
- La suppression de données des streams pour sécuriser les réponses

## REST API

Vous pouvez explorer tous les endpoints disponibles dans la spécification OpenAPI à l’adresse [http://localhost:4111/api/openapi.json](http://localhost:4111/api/openapi.json), qui détaille chaque endpoint et ses schémas de requête et de réponse.

Pour explorer l’API de manière interactive, ouvrez Swagger UI à l’adresse [http://localhost:4111/swagger-ui](http://localhost:4111/swagger-ui). Vous pourrez y découvrir les endpoints et les tester directement depuis votre navigateur.

:::note

Les endpoints OpenAPI et Swagger sont désactivés par défaut en production. Pour les activer, définissez respectivement [`server.build.openAPIDocs`](/reference/configuration#serverbuild) et [`server.build.swaggerUI`](/reference/configuration#serverbuild) sur `true`.

:::

## OpenAI Responses API

Mastra expose des routes Responses et Conversations compatibles avec OpenAI, qui vous permettent d’utiliser les agents Mastra comme une Responses API. Ces routes sont des adaptateurs reposant sur les agents, la mémoire et le stockage Mastra ; les requêtes s’exécutent donc via l’agent Mastra sélectionné plutôt que comme un proxy brut de provider.

Ces API sont actuellement expérimentales.

Utilisez `agent_id` pour sélectionner l’agent Mastra qui doit traiter la requête. Les requêtes initiales ciblent directement un agent, et les tours de suivi stockés peuvent se poursuivre avec `previous_response_id`. Vous pouvez également transmettre `model` pour remplacer le modèle configuré de l’agent pour une seule requête. Si vous omettez `model`, Mastra utilise le modèle déjà configuré sur l’agent.

Les routes Responses prennent en charge le streaming, l’appel de fonctions avec les tools, les continuations stockées avec `previous_response_id`, les threads de conversation avec `conversation_id`, le passthrough spécifique au provider avec `providerOptions` et la sortie JSON avec `text.format`.

Pour le contrat complet des requêtes et réponses, consultez la [référence de l’API Responses](/reference/client-js/responses) et la [référence de l’API Conversations](/reference/client-js/conversations). Pour la liste complète des routes HTTP, consultez les [routes du serveur](/reference/server/routes#responses-api).

## Stream data redaction

Lors du streaming des réponses d’agent, la couche HTTP masque les prompts système, définitions de tools, clés d’API et données similaires dans chaque chunk avant de l’envoyer aux clients. Ce comportement est activé par défaut.

Ce comportement ne peut être configuré qu’en utilisant des [adaptateurs de serveur](/docs/server/server-adapters#stream-data-redaction). Pour les adaptateurs de serveur, le masquage des données de stream est également activé par défaut.

## TypeScript configuration

Mastra exige des paramètres `module` et `moduleResolution` compatibles avec les versions modernes de Node.js. Les options héritées telles que `CommonJS` ou `node` ne sont pas prises en charge.

```json {4-5} title="tsconfig.json"
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ES2022",
    "moduleResolution": "bundler",
    "esModuleInterop": true,
    "forceConsistentCasingInFileNames": true,
    "strict": true,
    "skipLibCheck": true,
    "noEmit": true,
    "outDir": "dist"
  },
  "include": ["src/**/*"]
}
```
