# Run.timeTravel()

La méthode `.timeTravel()` réexécute un Workflow à partir de n’importe quelle étape spécifique, en utilisant les données d’un instantané stocké ou le contexte personnalisé que vous fournissez. Utilisez-la pour déboguer des Workflows ayant échoué et tester des étapes individuelles avec différentes entrées. Elle peut aussi permettre de récupérer après des erreurs sans réexécuter l’ensemble du Workflow.

## Exemple d’utilisation

```typescript
const run = await workflow.createRun()

const result = await run.timeTravel({
  step: 'step2',
  inputData: { value: 10 },
})
```

## Exemples d’utilisation avancés

### Time travel avec un contexte personnalisé

```typescript
const result = await run.timeTravel({
  step: 'step2',
  context: {
    step1: {
      status: 'success',
      payload: { value: 0 },
      output: { step1Result: 2 },
      startedAt: Date.now(),
      endedAt: Date.now(),
    },
  },
})
```

### Time travel vers une étape de Workflow imbriqué

```typescript
// Using dot notation
const result = await run.timeTravel({
  step: 'nestedWorkflow.step3',
  inputData: { value: 10 },
})

// Using array of step IDs
const result = await run.timeTravel({
  step: ['nestedWorkflow', 'step3'],
  inputData: { value: 10 },
})
```

### Time travel avec un état initial

```typescript
const result = await run.timeTravel({
  step: 'step2',
  inputData: { value: 10 },
  initialState: {
    counter: 5,
    metadata: { source: 'time-travel' },
  },
})
```

### Time travel avec le contexte de Workflows imbriqués

```typescript
const result = await run.timeTravel({
  step: 'nestedWorkflow.step3',
  context: {
    step1: {
      status: 'success',
      payload: { value: 0 },
      output: { step1Result: 2 },
      startedAt: Date.now(),
      endedAt: Date.now(),
    },
    nestedWorkflow: {
      status: 'running',
      payload: { step1Result: 2 },
      startedAt: Date.now(),
    },
  },
  nestedStepsContext: {
    nestedWorkflow: {
      step2: {
        status: 'success',
        payload: { step1Result: 2 },
        output: { step2Result: 3 },
        startedAt: Date.now(),
        endedAt: Date.now(),
      },
    },
  },
})
```

## Remarques

- Le time travel exige qu’un stockage soit configuré, car il s’appuie sur des instantanés persistants de Workflow
- Lors de la réexécution d’un Workflow, le Workflow charge l’instantané existant depuis le stockage, s’il est disponible
- Les résultats des étapes antérieures à l’étape cible sont reconstruits à partir de l’instantané ou du contexte fourni
- L’exécution commence à l’étape spécifiée avec les données d’entrée fournies ou reconstruites
- Le Workflow se poursuit jusqu’à son terme à partir de ce point
- Le time travel peut être utilisé sur des Workflows qui n’ont pas encore été exécutés en fournissant un contexte personnalisé ou des données d’entrée pour l’étape de départ.
