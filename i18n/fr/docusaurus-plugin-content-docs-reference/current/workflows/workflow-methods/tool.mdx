# Workflow\.tool()

La méthode `.tool()` ajoute un Tool comme étape déclarative. Les schémas d’entrée et de sortie propres au Tool s’appliquent ; la sortie de l’étape précédente doit donc satisfaire le schéma d’entrée du Tool. Utilisez `.map()` pour transformer les données s’ils ne correspondent pas.

Contrairement à l’encapsulation d’un Tool avec `createStep()`, `.tool()` enregistre une entrée déclarative dans le graphe du Workflow. Le Workflow devient ainsi portable : le même graphe peut être sérialisé et conservé comme [Workflow dynamique](/docs/workflows/dynamic-workflows).

## Exemple d’utilisation

```typescript filename="src/mastra/workflows/test-workflow.ts" prettier:false
workflow.tool(testTool).commit();
```

## Référencer un Tool par ID

Transmettez une chaîne pour référencer un Tool enregistré sans l’importer. Le Tool doit être enregistré dans l’instance Mastra lorsque le Workflow s’exécute :

```typescript filename="src/mastra/workflows/test-workflow.ts" prettier:false
workflow.tool("lookup-customer", { retries: 2 }).commit();
```

## Conserver les étapes de Tool

Les Workflows construits avec `.tool()` se sérialisent dans les mêmes entrées déclaratives que les [Workflows dynamiques](/docs/workflows/dynamic-workflows). Seuls `retries` et `metadata` effectuent un aller-retour via le stockage. Une option `scorers` dont la valeur est une fonction lève une erreur lorsque le Workflow est conservé.
