# Mastra.addDynamiqueWorkflow()

:::experimental

Dynamique workflows sont dans beta. Breaking changes peut occur sans a major version bump until the API est stable.

:::

The `.addDynamicWorkflow()` method validates a dynamic Workflow definition et registers it comme a live Workflow sur the instance, persisting it via the `workflowDefinitions` storage domain. Once registered, the Workflow runs like tout autre Workflow via [Mastra.getWorkflow()](/reference/core/getWorkflow).

See [Dynamique workflows](/docs/workflows/dynamic-workflows) pour a complete setup example et the [dynamic Workflow definition reference](/reference/workflows/dynamic-workflow-definition) pour the accepted fields et graph entries.

## Exemple d’utilisation

```typescript
await mastra.addDynamicWorkflow({
  id: 'greeting-workflow',
  description: 'Returns a greeting for the supplied name',
  inputSchema: {
    type: 'object',
    properties: { name: { type: 'string' } },
    required: ['name'],
  },
  outputSchema: {
    type: 'object',
    properties: { message: { type: 'string' } },
    required: ['message'],
  },
  graph: [
    {
      type: 'mapping',
      id: 'create-greeting',
      mapConfig: JSON.stringify({
        message: { template: 'Hello, ${initData.name}!' },
      }),
    },
  ],
})

const run = await mastra.getWorkflow('greeting-workflow').createRun()
const result = await run.start({ inputData: { name: 'Ada' } })
```

## Renvoie

Un promise that resolves once the definition est validated, registered, et persisted.

## Behavior

- The definition est fully validated (structure, references, schema flow) avant anything est mutated. Agents, tools, et workflows referenced par the graph doit already be registered sur the instance.
- Adding a definition avec an existant ID replaces both the stored definition et the live registration. In-flight runs keep the graph they started with.
- Without a storage adapter that supports the `workflowDefinitions` domain, the Workflow est still validated et registered dans memory, mais the definition est lost sur restart.
- Pour ajouter a root Workflow together avec helper workflows it nests, utilise [Mastra.addDynamiqueWorkflows()](/reference/core/addDynamicWorkflows).
