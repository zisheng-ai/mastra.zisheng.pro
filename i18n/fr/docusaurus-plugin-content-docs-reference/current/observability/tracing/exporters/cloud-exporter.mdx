# CloudExporter

**Ajouté dans :** `@mastra/observability@1.8.0`. **Obsolète depuis `1.12.0`** au profit de [`MastraPlatformExporter`](/reference/observability/tracing/exporters/mastra-platform-exporter).

:::warning[Obsolète]

`CloudExporter` est conservé pour assurer la rétrocompatibilité et sera supprimé dans une prochaine version majeure. Utilisez [`MastraPlatformExporter`](/reference/observability/tracing/exporters/mastra-platform-exporter) pour les nouveaux projets. Les deux classes partagent le même constructeur, les mêmes variables d'environnement et le même comportement à l'exécution ; `CloudExporter` conserve son nom d'exporter d'origine `mastra-cloud-observability-exporter` dans `name`, ainsi que les ID d'erreur `CLOUD_EXPORTER_*`, afin que les règles de surveillance qui en dépendent continuent de fonctionner.

:::

Envoie les spans de traçage, logs, métriques, scores et retours à la plateforme Mastra afin de les visualiser et de les surveiller en ligne.

## `CloudExporterConfig` {/* #cloudexporterconfig */}

```typescript
interface CloudExporterConfig extends BaseExporterConfig {
  /** Maximum number of spans per batch. Default: 1000 */
  maxBatchSize?: number

  /** Maximum wait time before flushing in milliseconds. Default: 5000 */
  maxBatchWaitMs?: number

  /** Maximum retry attempts. Default: 3 */
  maxRetries?: number

  /** Cloud access token (from env or config) */
  accessToken?: string

  /** Project ID for project-scoped collector routes (letters, numbers, hyphens, underscores) */
  projectId?: string

  /** Base cloud observability endpoint */
  endpoint?: string

  /** Explicit cloud traces endpoint override */
  tracesEndpoint?: string

  /** Explicit cloud logs endpoint override */
  logsEndpoint?: string

  /** Explicit cloud metrics endpoint override */
  metricsEndpoint?: string

  /** Explicit cloud scores endpoint override */
  scoresEndpoint?: string

  /** Explicit cloud feedback endpoint override */
  feedbackEndpoint?: string
}
```

Étend `BaseExporterConfig`, qui comprend :

- `logger?: IMastraLogger` : instance du logger
- `logLevel?: LogLevel | 'debug' | 'info' | 'warn' | 'error'` : niveau de log (valeur par défaut : INFO)

## Variables d'environnement {/* #environment-variables */}

L'exporter lit les variables d'environnement suivantes si elles ne sont pas fournies dans la configuration :

- `MASTRA_PLATFORM_ACCESS_TOKEN` : token d'authentification des requêtes `CloudExporter`
- `MASTRA_PROJECT_ID` : ID du projet à utiliser lors de la dérivation de routes de collecte propres au projet, telles que `/projects/:projectId/ai/spans/publish`
- `MASTRA_PLATFORM_OBSERVABILITY_ENDPOINT` : remplacement du point de terminaison d'observabilité. Transmettez une origine de base ou une URL complète de publication des traces. La valeur par défaut est `https://observability.mastra.ai` dans `@mastra/observability@1.9.2` et les versions ultérieures

## Méthodes {/* #methods */}

### `exportTracingEvent` {/* #exporttracingevent */}

```typescript prettier:false
async exportTracingEvent(event: TracingEvent): Promise<void>
```

Traite les événements de traçage pour l'export Cloud.

Seuls les événements de traçage `SPAN_ENDED` sont exportés. `SPAN_STARTED` et `SPAN_UPDATED` sont ignorés. Les spans correspondants sont placés en mémoire tampon, puis envoyés au point de terminaison des traces Cloud lors du prochain flush.

### `onLogEvent` {/* #onlogevent */}

```typescript prettier:false
async onLogEvent(event: LogEvent): Promise<void>
```

Traite les signaux de log pour l'export Cloud.

Chaque `LogEvent` transmis à ce gestionnaire est placé en mémoire tampon et exporté vers le point de terminaison des logs Cloud dérivé du point de terminaison de base configuré. Contrairement au traçage, aucun filtrage supplémentaire selon l'état de l'événement n'est effectué au niveau de `CloudExporter`. Si l'exporter est désactivé, cette méthode n'effectue aucune opération.

### flush {/* #flush */}

```typescript prettier:false
async flush(): Promise<void>
```

Force l'envoi de tous les événements en mémoire tampon vers la plateforme Mastra sans arrêter l'exporter. Utile dans les environnements serverless où vous devez vous assurer que les spans sont exportés avant la fin de l'environnement d'exécution.

### shutdown {/* #shutdown */}

```typescript prettier:false
async shutdown(): Promise<void>
```

Envoie les événements restants et effectue le nettoyage.

## Comportement {/* #behavior */}

### Authentification {/* #authentication */}

Si aucun token d'accès n'est fourni dans la configuration ou une variable d'environnement, l'exporter :

- Consigne un avertissement avec des informations d'inscription
- N'effectue aucune opération (ignore tous les événements)

### Traitement par lots {/* #batching */}

L'exporter regroupe les spans de traçage, logs, métriques, scores et retours afin d'optimiser l'utilisation du réseau :

- Effectue un flush lorsque le nombre total d'événements en mémoire tampon atteint `maxBatchSize`
- Effectue un flush lorsque `maxBatchWaitMs` s'est écoulé depuis le premier signal placé en mémoire tampon dans le lot
- Effectue un flush lors de l'appel à `shutdown()`

### Gestion des erreurs {/* #error-handling */}

- Utilise des nouvelles tentatives avec backoff exponentiel, dans la limite de `maxRetries` tentatives
- Abandonne les lots après l'échec de toutes les tentatives
- Consigne les erreurs, mais continue de traiter les nouveaux événements

### Routage des points de terminaison {/* #endpoint-routing */}

- Les origines de base dérivent automatiquement les points de terminaison des signaux
- Sans `projectId`, les routes dérivées utilisent `/ai/{signal}/publish`
- Avec `projectId` ou `MASTRA_PROJECT_ID`, les routes dérivées utilisent `/projects/:projectId/ai/{signal}/publish`
- Les URL de publication complètes explicites sont utilisées telles quelles, même si `projectId` est configuré

### Traitement des signaux {/* #signal-processing */}

- `exportTracingEvent()` exporte uniquement les événements de traçage `SPAN_ENDED`
- `onLogEvent()`, `onMetricEvent()`, `onScoreEvent()` et `onFeedbackEvent()` placent en mémoire tampon chaque événement reçu pour leur type de signal respectif
- Tous les lots de signaux pris en charge sont envoyés vers leurs points de terminaison de publication Cloud correspondants pendant `flush()` et `shutdown()`

## Utilisation {/* #usage */}

```typescript
import { CloudExporter } from '@mastra/observability'

// Uses environment variable for token
const exporter = new CloudExporter()

// Explicit configuration
const customExporter = new CloudExporter({
  accessToken: 'your-token',
  projectId: 'project_123',
  maxBatchSize: 500,
  maxBatchWaitMs: 2000,
  logLevel: 'debug',
})
```
