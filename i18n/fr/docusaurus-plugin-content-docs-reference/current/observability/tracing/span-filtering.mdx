# Filtrage des spans

Le filtrage des spans détermine les spans exportés depuis une configuration d’Observability. Utilisez-le pour réduire le bruit ou diminuer les coûts par span. Il permet également de ne conserver que les spans pertinents pour un Exporter ou un environnement précis.

Pour une présentation plus concise de la configuration du traçage, consultez [Traçage](/docs/observability/tracing/overview).

## Exemple d’utilisation {/* #usage-example */}

L’exemple suivant montre comment combiner `excludeSpanTypes` et `spanFilter` dans une même configuration d’Observability :

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { SpanType } from '@mastra/core/observability'
import { Observability, MastraStorageExporter } from '@mastra/observability'
import { LangfuseExporter } from '@mastra/langfuse'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-app',
        exporters: [new MastraStorageExporter(), new LangfuseExporter()],
        excludeSpanTypes: [SpanType.MODEL_CHUNK, SpanType.MODEL_STEP],
        spanFilter: span => {
          if (span.type === SpanType.TOOL_CALL && span.attributes?.success) {
            return false
          }

          return true
        },
      },
    },
  }),
})
```

### `excludeSpanTypes` {/* #excludespantypes */}

Utilisez `excludeSpanTypes` lorsque vous souhaitez supprimer des catégories entières de spans avec une configuration minimale.

Pour connaître l’ensemble actuel des valeurs prises en charge, consultez l’[énumération `SpanType`](https://github.com/mastra-ai/mastra/blob/main/packages/core/src/observability/types/tracing.ts).

```ts title="src/mastra/index.ts"
import { SpanType } from '@mastra/core/observability'

excludeSpanTypes: [SpanType.MODEL_CHUNK, SpanType.MODEL_STEP, SpanType.WORKFLOW_SLEEP]
```

### `spanFilter` {/* #spanfilter */}

Lorsque le filtrage dépend du contenu du span exporté, utilisez `spanFilter`.

```ts title="src/mastra/index.ts"
import { SpanType } from '@mastra/core/observability'

spanFilter: span => {
  if (span.type === SpanType.MODEL_CHUNK) return false
  if (span.type === SpanType.TOOL_CALL && span.attributes?.success) return false

  return true
}
```

Exemples supplémentaires :

```ts title="src/mastra/index.ts"
// Only export spans from production
spanFilter: span => span.metadata?.environment === 'production'

// Exclude spans from a specific entity
spanFilter: span => span.entityId !== 'noisy-agent'
```

## Ordre de traitement {/* #processing-order */}

Le filtrage des spans s’effectue au moment de l’exportation, dans l’ordre suivant :

1. Les spans internes sont éliminés, sauf si `includeInternalSpans` vaut `true`.
1. `excludeSpanTypes` supprime les types de spans correspondants.
1. `spanOutputProcessors` transforme les spans restants.
1. `spanFilter` détermine si le span final exporté doit être conservé.

Si `spanFilter` génère une erreur, Mastra conserve le span et consigne l’erreur afin d’éviter une perte de données silencieuse.
