# Vue d’ensemble du stockage

Le stockage Mastra est organisé en domaines. Chaque domaine possède un ensemble de tables ou de collections. Selon votre adaptateur et votre configuration, vous pouvez utiliser tous les domaines ou seulement un sous-ensemble.

## Domaines de stockage

`MastraCompositeStore` peut router les clés de domaine suivantes :

Tous les adaptateurs de stockage n’implémentent pas chaque domaine. Le stockage composite vous permet de mélanger les adaptateurs par domaine lorsque les packages d’adaptateurs exportent les classes de domaine correspondantes.

| Domaine | Description |
| - | - |
| `memory` | Persistance des conversations : messages, fils de discussion et ressources (y compris la mémoire de travail). |
| `workflows` | Instantanés d’exécution de Workflow utilisés pour suspendre et reprendre. |
| `workflowDefinitions` | Définitions persistantes de [Workflow dynamiques](/docs/workflows/dynamic-workflows) (bêta). Chargées et enregistrées dynamiquement au démarrage. |
| `scores` | Enregistrements des scores d’évaluation issus des exécutions d’eval. |
| `observability` | Traces et spans utilisés par les exportateurs d’observabilité et Studio. |
| `datasets` | Enregistrements de datasets, éléments versionnés et versions de datasets utilisés par les expériences. |
| `experiments` | Exécutions d’expériences et résultats d’expérience par élément. |

Les définitions de schéma ci-dessous couvrent les tables intégrées adossées à une base de données documentées pour `memory`, `workflows`, `scores` et `observability`. Les autres domaines et les adaptateurs qui ne s’appuient pas sur une base de données utilisent des structures de stockage propres à leur implémentation.
