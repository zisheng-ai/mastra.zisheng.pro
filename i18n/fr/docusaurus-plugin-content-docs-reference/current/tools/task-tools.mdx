# Tools de tâches

Quatre Tools intégrés et indépendants de l'Agent qui gèrent une liste structurée de tâches pour l'exécution d'un Agent. La liste de tâches est conservée dans le domaine de stockage `threadState` propre au thread et projetée sur le canal de [Signal d'état](/docs/long-running-agents/signals) de l'Agent afin de survivre à la troncature de la [mémoire observationnelle](/docs/memory/observational-memory).

Le suivi des tâches nécessite un thread adossé à une mémoire (`threadId` + `resourceId`). Sans mémoire, les Tools renvoient une erreur expliquant que le suivi des tâches nécessite la mémoire de l'Agent.

La configuration recommandée est [`TaskSignalProvider`](/reference/signals/task-signal-provider), qui regroupe les quatre Tools et `TaskStateProcessor` dans un seul enregistrement. Consultez le guide conceptuel des [Tools intégrés](/docs/agents/using-tools#task-tracking).

## Exemple d'utilisation {/* #usage-example */}

```typescript title="src/mastra/agents/index.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'
import { TaskSignalProvider } from '@mastra/core/signals'

const agent = new Agent({
  id: 'coder',
  name: 'Coder',
  instructions: 'Track your progress with the task tools.',
  model,
  memory: new Memory(),
  signals: [new TaskSignalProvider()],
})
```

Vous pouvez également importer les Tools directement :

```typescript title="src/mastra/agents/index.ts"
import { taskWriteTool, taskUpdateTool, taskCompleteTool, taskCheckTool } from '@mastra/core/tools'

const agent = new Agent({
  id: 'coder',
  name: 'Coder',
  instructions: 'Track your progress with the task tools.',
  model,
  memory: new Memory(),
  tools: { taskWriteTool, taskUpdateTool, taskCompleteTool, taskCheckTool },
})
```

## `task_write` {/* #task_write */}

Crée ou remplace toute la liste de tâches. Chaque appel remplace la liste précédente.

### Schéma d'entrée {/* #input-schema */}

<PropertiesTable
  content={[
  {
    name: 'tasks',
    type: 'TaskItemInput[]',
    description: 'Liste de tâches mise à jour complète.',
    isOptional: false,
    properties: [
      {
        type: 'TaskItemInput',
        parameters: [
          {
            name: 'id',
            type: 'string',
            description:
              "Identifiant stable de la tâche (par exemple, 'task_investigate_tests'). Conservez-le inchangé lors des mises à jour. Généré automatiquement lorsqu'il est omis.",
            isOptional: true,
          },
          {
            name: 'content',
            type: 'string',
            description: "Description de la tâche à l'impératif (par exemple, 'Corriger le bug d'authentification').",
          },
          {
            name: 'status',
            type: "'pending' | 'in_progress' | 'completed'",
            description: 'Statut actuel de la tâche.',
          },
          {
            name: 'activeForm',
            type: 'string',
            description: "Forme indiquant une action en cours affichée pendant l'exécution (par exemple, 'Correction du bug d'authentification').",
          },
        ],
      },
    ],
  },
]}
/>

### Sortie {/* #output */}

Renvoie un `TaskToolResult` contenant un résumé `content` lisible par les utilisateurs, le tableau `tasks` complet avec les identifiants attribués et un indicateur `isError`.

### Comportement {/* #behavior */}

- Les identifiants doivent être uniques au sein d'un même appel. Les identifiants explicites dupliqués reçoivent une valeur de repli générée.
- Lorsqu'un identifiant est omis pendant la réécriture d'une liste existante, une tâche dont la correspondance est sans ambiguïté réutilise son identifiant précédent à des fins de stabilité.
- Une seule tâche peut avoir le statut `in_progress` à la fois. L'envoi de plusieurs tâches `in_progress` renvoie une erreur.

## `task_update` {/* #task_update */}

Met à jour une tâche au moyen de son identifiant stable. Incluez uniquement les champs qui ont changé.

### Schéma d'entrée {/* #input-schema-1 */}

<PropertiesTable
  content={[
  {
    name: 'id',
    type: 'string',
    description: 'Identifiant stable de la tâche à mettre à jour.',
    isOptional: false,
  },
  {
    name: 'content',
    type: 'string',
    description: "Nouvelle description de la tâche à l'impératif.",
    isOptional: true,
  },
  {
    name: 'status',
    type: "'pending' | 'in_progress' | 'completed'",
    description: 'Nouveau statut de la tâche.',
    isOptional: true,
  },
  {
    name: 'activeForm',
    type: 'string',
    description: 'Nouvelle forme au présent continu.',
    isOptional: true,
  },
]}
/>

Au moins l'un des champs `content`, `status` ou `activeForm` est obligatoire.

### Comportement {/* #behavior-1 */}

- Lorsque la mise à jour définit une tâche sur `in_progress`, toute autre tâche `in_progress` est automatiquement rétrogradée à `pending`.
- Renvoie une erreur contenant les identifiants des tâches disponibles lorsque l'identifiant est introuvable.

## `task_complete` {/* #task_complete */}

Marque une tâche comme terminée au moyen de son identifiant stable.

### Schéma d'entrée {/* #input-schema-2 */}

<PropertiesTable
  content={[
  {
    name: 'id',
    type: 'string',
    description: 'Identifiant stable de la tâche à marquer comme terminée.',
    isOptional: false,
  },
]}
/>

### Comportement {/* #behavior-2 */}

Renvoie une erreur contenant les identifiants des tâches disponibles lorsque l'identifiant est introuvable.

## `task_check` {/* #task_check */}

Vérifie le statut d'achèvement de la liste de tâches. N'accepte aucun paramètre d'entrée.
