# Contexte recall scorer

The `createContextRecallScorer()` fonction creates a scorer that evaluates how well retrieved context covers the claims dans a ground-truth reference answer. It measures retrieval completeness par checking what fraction de the ground truth's claims sont attributable à the retrieved context.

Ce scorer requires a ground-truth reference answer, making it suitable pour labeled datasets dans CI ou test environments. When `groundTruth` isn't fourni dans the run, the scorer returns a score de 0 rather than throwing an error.

## RAG retrieval evaluation

Ideal pour evaluating retrieval completeness dans RAG pipelines where:

- You need à verify the retriever fetches tous les necessary information
- You ont labeled datasets avec known-correct answers
- You want à catch regressions dans what the retriever returns

## Jeu de données-driven testing

Use when running evaluations against curated test sets:

- CI pipelines avec ground-truth labeled questions
- A/B testing retrieval strategies
- Benchmarking embedding models pour coverage

## Scoring details

### Claim attribution

Contexte Recall uses a two-step LLM evaluation followed par a deterministic score calculation:

1. **Claim extraction**: The ground-truth answer est decomposed dans atomic claims
1. **Attribution check**: Chaque claim est checked against the retrieval context pour support

The score est then calculated comme the ratio de attributed claims à total claims, multiplied par scale.

### Scoring formula

```
Context Recall = attributed_claims / total_claims × scale

Where:
- attributed_claims = number of ground-truth claims supported by the context
- total_claims = total number of claims extracted from the ground truth
- Attribution is binary: a claim is either supported (yes) or not (no)
```

### Score interpretation

Ces ranges assume the par défaut `scale` de 1. Lorsque vous utilisez a personnalisé scale, multiply accordingly.

- **0.9-1.0**: Excellent recall, context covers nearly tous les ground-truth claims
- **0.7-0.8**: Good recall. Most claims sont covered, avec minor gaps
- **0.4-0.6**: Moderate recall, substantial information missing depuis context
- **0.1-0.3**: Poor recall, most ground-truth claims ne pas found dans context
- **0.0**: No recall, none de the ground-truth claims sont dans the context

### Reason analysis

The reason field explains:

- Which ground-truth claims étaient found dans the context
- Which claims étaient missing et what information gaps exist
- Specific context pieces that pris en charge attributed claims

### Optimization insights

Use results to:

- **Improve retrieval**: Identify what types de information the retriever misses
- **Tune chunk size**: Ensure chunks contain enough detail à cover ground-truth claims
- **Evaluate embeddings**: Test different embedding models pour better information coverage
- **Expand knowledge base**: Ajouter documents that cover frequently missed claims

### Exemple calculation

ground truth: "Einstein était born dans 1879. He developed relativity. He won the Nobel Prize."

Claims extracted: 3

- "Einstein était born dans 1879" → attributed (context mentions birthdate)
- "Einstein developed relativity" → attributed (context covers relativity)
- "Einstein won the Nobel Prize" → ne pas attributed (context doesn't mention Nobel Prize)

Recall = 2/3 = 0.67

## Scorer configuration

### Dynamique context extraction

```typescript
const scorer = createContextRecallScorer({
  model: '__GATEWAY_OPENAI_MODEL__',
  options: {
    contextExtractor: (input, output) => {
      const query = input?.inputMessages?.[0]?.content || ''
      const searchResults = vectorDB.search(query, { limit: 10 })
      return searchResults.map(result => result.content)
    },
    scale: 1,
  },
})
```

### Statique context evaluation

```typescript
const scorer = createContextRecallScorer({
  model: '__GATEWAY_OPENAI_MODEL__',
  options: {
    context: [
      'Document 1: Einstein was born on 14 March 1879 in Ulm, Germany.',
      'Document 2: Einstein published the theory of special relativity in 1905.',
      'Document 3: Einstein moved to the United States in 1933.',
    ],
  },
})
```

## Exemple

Evaluate RAG retrieval completeness against a labeled dataset:

```typescript title="src/example-context-recall.ts"
import { runEvals } from '@mastra/core/evals'
import { createContextRecallScorer } from '@mastra/evals/scorers/prebuilt'
import { myAgent } from './agent'

const scorer = createContextRecallScorer({
  model: '__GATEWAY_OPENAI_MODEL__',
  options: {
    contextExtractor: (input, output) => {
      // Extract context from tool invocation results in the agent output
      return output
        .filter(msg => msg?.role === 'assistant')
        .flatMap(msg => msg?.content?.toolInvocations ?? [])
        .filter((tool: any) => tool.state === 'result')
        .map((tool: any) => JSON.stringify(tool.result))
    },
  },
})

const result = await runEvals({
  data: [
    {
      input: 'What are the health benefits of green tea?',
      groundTruth:
        'Green tea contains antioxidants that reduce inflammation, L-theanine that improves focus, and catechins that boost metabolism.',
    },
    {
      input: 'How does photosynthesis work?',
      groundTruth:
        'Photosynthesis converts sunlight into chemical energy using chlorophyll in chloroplasts, producing glucose and oxygen from carbon dioxide and water.',
    },
  ],
  scorers: [scorer],
  target: myAgent,
  onItemComplete: ({ scorerResults }) => {
    console.log({
      score: scorerResults[scorer.id].score,
      reason: scorerResults[scorer.id].reason,
    })
  },
})

console.log(result.scores)
```

Pour plus de détails sur `runEvals`, consultez la [référence runEvals](/reference/evals/run-evals).

Pour ajouter ce scorer à un Agent, consultez le guide de [présentation des Scorers](/docs/evals/overview#adding-scorers-to-agents).

## Comparison avec context precision

Choose the right scorer pour your needs:

| Use case | Contexte Recall | Contexte Precision |
| - | - | - |
| **What it measures** | Coverage de ground truth | Relevance de retrieved chunks |
| **Direction** | Ground truth → context | Contexte → ground truth |
| **Position sensitive** | No | Yes (rewards early placement) |
| **Requires ground truth** | Yes | Yes |
| **Failure mode caught** | Missing information | Irrelevant noise |

Use both together pour a complete picture de retrieval quality: precision catches junk dans the context, recall catches gaps.
