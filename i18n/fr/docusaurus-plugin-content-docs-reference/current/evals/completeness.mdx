# Completness scorer

The `createCompletenessScorer()` fonction evaluates how thoroughly an LLM's output covers the clé elements present dans the input. It analyzes nouns, verbs, topics, et terms à determine coverage et provides a detailed completeness score.

## Paramètres

The `createCompletenessScorer()` fonction doesn't take tout options.

Ce fonction returns an instance de the MastraScorer class. Consultez the [MastraScorer reference](./mastra-scorer) pour details sur the `.run()` method et its input/output.

## Element extraction details

The scorer extracts et analyzes several types de elements:

- Nouns: Key objects, concepts, et entities
- Verbs: Actions et states (converted à infinitive form)
- Topics: Main subjects et themes
- Terms: Individual substantial words

The extraction traite includes:

- Normalization de text (removing diacritics, converting à lowercase)
- Splitting camelCase words
- Handling de word boundaries
- Special handling de short words (3 characters ou less)
- Deduplication de elements

### `extractStepResult`

From the `.run()` method, you peut obtient the `extractStepResult` objet avec the following properties:

- **inputElements**: Key elements found dans the input (e.g., nouns, verbs, topics, terms).
- **outputElements**: Key elements found dans the output.
- **missingElements**: Entrée elements ne pas found dans the output.
- **elementCounts**: The nombre de elements dans the input et output.

## Scoring details

The scorer evaluates completeness via linguistic element coverage analysis.

### Scoring Process

1. Extracts clé elements:
   - Nouns et named entities
   - Action verbs
   - Topic-specific terms
   - Normalized word forms
1. Calculates coverage de input elements:
   - Exact matches pour short terms (≤3 chars)
   - Substantial overlap (>60%) pour longer terms

Final score: `(covered_elements / total_input_elements) * scale`

### Score interpretation

Un completeness score entre 0 et 1:

- **1.0**: Thoroughly addresses tous les aspects de the query avec detailed detail.
- **0.7 à 0.9**: Covers most important aspects avec good detail, minor gaps.
- **0.4 à 0.6**: Addresses certains clé points mais missing important aspects ou lacking detail.
- **0.1 à 0.3**: Only partially addresses the query avec substantial gaps.
- **0.0**: Fails à address the query ou provides irrelevant information.

## Exemple

Evaluate agent responses pour completeness across different query complexities:

```typescript title="src/example-completeness.ts"
import { runEvals } from '@mastra/core/evals'
import { createCompletenessScorer } from '@mastra/evals/scorers/prebuilt'
import { myAgent } from './agent'

const scorer = createCompletenessScorer()

const result = await runEvals({
  data: [
    {
      input:
        'Explain the process of photosynthesis, including the inputs, outputs, and stages involved.',
    },
    {
      input: 'What are the benefits and drawbacks of remote work for both employees and employers?',
    },
    {
      input:
        'Compare renewable and non-renewable energy sources in terms of cost, environmental impact, and sustainability.',
    },
  ],
  scorers: [scorer],
  target: myAgent,
  onItemComplete: ({ scorerResults }) => {
    console.log({
      score: scorerResults[scorer.id].score,
    })
  },
})

console.log(result.scores)
```

Pour plus de détails sur `runEvals`, consultez la [référence runEvals](/reference/evals/run-evals).

Pour ajouter ce scorer à un Agent, consultez le guide de [présentation des Scorers](/docs/evals/overview#adding-scorers-to-agents).
