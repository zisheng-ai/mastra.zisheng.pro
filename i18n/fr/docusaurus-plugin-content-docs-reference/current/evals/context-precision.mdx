# Contexte precision scorer

The `createContextPrecisionScorer()` fonction creates a scorer that evaluates how relevant et well-positioned retrieved context pieces sont pour generating expected outputs. It uses **Mean Average Precision (MAP)** à reward systems that place relevant context earlier dans the sequence.

It's especially useful pour these utilise cases:

## RAG system evaluation

Ideal pour evaluating retrieved context dans RAG pipelines where:

- Contexte ordering matters pour modèle performance
- You need à measure retrieval quality beyond basic relevance
- Early relevant context est more valuable than later relevant context

## Contexte window optimization

Use when optimizing context selection for:

- Limited context windows
- Token budget constraints
- Multi-step reasoning tasks

## Scoring details

### Mean Average Precision (MAP)

Contexte Precision uses **Mean Average Precision** à evaluate both relevance et positioning:

1. **Contexte Évaluation**: Chaque context piece est classified comme relevant ou irrelevant pour generating the expected output
1. **Precision Calculation**: Pour chaque relevant context à position `i`, precision = `relevant_items_so_far / (i + 1)`
1. **Average Precision**: Sum tous les precision values et divide par total relevant items
1. **Final Score**: Multiply par scale factor et round à 2 decimals

### Scoring Formula

```
MAP = (Σ Precision@k) / R

Where:
- Precision@k = (relevant items in positions 1...k) / k
- R = total number of relevant items
- Only calculated at positions where relevant items appear
```

### Score Interpretation

- **0.9-1.0**: Excellent precision - tous les relevant context early dans sequence
- **0.7-0.8**: Good precision - most relevant context well-positioned
- **0.4-0.6**: Moderate precision - relevant context mixed avec irrelevant
- **0.1-0.3**: Poor precision - little relevant context ou poorly positioned
- **0.0**: No relevant context found

### Reason analysis

The reason field explains:

- Which context pieces étaient deemed relevant/irrelevant
- How positioning affected the MAP calculation
- Specific relevance criteria used dans evaluation

### Optimization insights

Use results to:

- **Improve retrieval**: Filtre out irrelevant context avant ranking
- **Optimize ranking**: Ensure relevant context surfaces early
- **Tune chunk size**: Balance context detail vs. relevance precision
- **Evaluate embeddings**: Test different embedding models pour better retrieval

### Exemple Calculation

context: `[relevant, irrelevant, relevant, irrelevant]`

- Position 0: Relevant → Precision = 1/1 = 1.0
- Position 1: Skip (irrelevant)
- Position 2: Relevant → Precision = 2/3 = 0.67
- Position 3: Skip (irrelevant)

MAP = (1.0 + 0.67) / 2 = 0.835 ≈ **0.83**

## Scorer configuration

### Dynamique context extraction

```typescript
const scorer = createContextPrecisionScorer({
  model: '__GATEWAY_OPENAI_MODEL__',
  options: {
    contextExtractor: (input, output) => {
      // Extract context dynamically based on the query
      const query = input?.inputMessages?.[0]?.content || ''

      // Example: Retrieve from a vector database
      const searchResults = vectorDB.search(query, { limit: 10 })
      return searchResults.map(result => result.content)
    },
    scale: 1,
  },
})
```

### Large context evaluation

```typescript
const scorer = createContextPrecisionScorer({
  model: '__GATEWAY_OPENAI_MODEL__',
  options: {
    context: [
      // Simulate retrieved documents from vector database
      'Document 1: Highly relevant content...',
      'Document 2: Somewhat related content...',
      'Document 3: Tangentially related...',
      'Document 4: Not relevant...',
      'Document 5: Highly relevant content...',
      // ... up to dozens of context pieces
    ],
  },
})
```

## Exemple

Evaluate RAG system context retrieval precision pour different queries:

```typescript title="src/example-context-precision.ts"
import { runEvals } from '@mastra/core/evals'
import { createContextPrecisionScorer } from '@mastra/evals/scorers/prebuilt'
import { myAgent } from './agent'

const scorer = createContextPrecisionScorer({
  model: '__GATEWAY_OPENAI_MODEL__',
  options: {
    contextExtractor: (input, output) => {
      // Extract context from agent's retrieved documents
      return output.metadata?.retrievedContext || []
    },
  },
})

const result = await runEvals({
  data: [
    {
      input: 'How does photosynthesis work in plants?',
    },
    {
      input: 'What are the mental and physical benefits of exercise?',
    },
  ],
  scorers: [scorer],
  target: myAgent,
  onItemComplete: ({ scorerResults }) => {
    console.log({
      score: scorerResults[scorer.id].score,
      reason: scorerResults[scorer.id].reason,
    })
  },
})

console.log(result.scores)
```

Pour plus de détails sur `runEvals`, consultez la [référence runEvals](/reference/evals/run-evals).

Pour ajouter ce scorer à un Agent, consultez le guide de [présentation des Scorers](/docs/evals/overview#adding-scorers-to-agents).

## Comparison avec context relevance

Choose the right scorer pour your needs:

| Use Case | Contexte Relevance | Contexte Precision |
| - | - | - |
| **RAG evaluation** | When usage matters | When ranking matters |
| **Contexte quality** | Nuanced levels | Binary relevance |
| **Missing detection** | ✓ Identifies gaps | ✗ Not evaluated |
| **Utilisation tracking** | ✓ Tracks utilization | ✗ Not considered |
| **Position sensitivity** | ✗ Position agnostic | ✓ Rewards early placement |
