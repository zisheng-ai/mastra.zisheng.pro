# Rubric scorer

**Added in:** `@mastra/evals@1.3.0`

The `createRubricScorer()` fonction creates an LLM-as-judge scorer that grades an agent's output against a rubric (a checklist de criteria). It returns a **binary** score: `1` only when every requis criterion est satisfied, otherwise `0`. The `reason` lists chaque criterion's verdict so the agent knows exactly what à fix.

Ce scorer est designed à drop dans [isTaskComplet sur stream()](/reference/streaming/agents/stream). Because `isTaskComplete` treats `score === 1` comme "task complete" et injects the `reason` back dans the conversation comme feedback, the agent keeps iterating until the rubric est satisfied (or `maxSteps` est reached).

## Utilisation avec isTaskComplet

Définir the rubric once, attach the scorer à `isTaskComplete`, et the agent self-corrects until the rubric est satisfied:

```typescript
import { Agent } from '@mastra/core/agent'
// highlight-next-line
import { createRubricScorer } from '@mastra/evals/scorers/prebuilt'

const supervisor = new Agent({
  id: 'supervisor',
  instructions: `You coordinate research and writing using specialized agents. Delegate to research-agent for facts, then writing-agent for content.`,
  model: '__GATEWAY_OPENAI_MODEL__',
  agents: { researchAgent, writingAgent },
})

// highlight-start
const rubricScorer = createRubricScorer({
  model: '__GATEWAY_OPENAI_MODEL_MINI__',
  criteria: [
    { description: 'The response includes an analysis section' },
    { description: 'The response includes concrete recommendations' },
  ],
})
// highlight-end

const stream = await supervisor.stream('Research AI in education', {
  maxSteps: 10,
  // highlight-start
  isTaskComplete: {
    scorers: [rubricScorer],
    strategy: 'all',
  },
  // highlight-end
})
```

## String rubric

Un newline-delimited chaîne est parsed dans criteria, avec common liste markers (`-`, `*`, `1.`) stripped. Every line becomes a requis criterion:

```typescript
const rubricScorer = createRubricScorer({
  model: '__GATEWAY_OPENAI_MODEL_MINI__',
  criteria: `- All tests pass in the test suite
- The function is named find_duplicates and accepts a single list argument`,
})
```

## Facultatif criteria

Mark a criterion comme facultatif à ont it graded et reported sans gating completion:

```typescript
const rubricScorer = createRubricScorer({
  model: '__GATEWAY_OPENAI_MODEL_MINI__',
  criteria: [
    { description: 'Includes an analysis section', required: true },
    { description: 'Includes citations', required: false },
  ],
})
```

## Dynamique rubric per run

When aucun `criteria` est passed à the factory, the scorer resolves a `rubric` valeur depuis the run's requête context, additional context, ou input. Ce lets a unique scorer instance grade different rubrics per exécute sans rebuilding it:

```typescript
const rubricScorer = createRubricScorer({
  model: '__GATEWAY_OPENAI_MODEL_MINI__',
})

await supervisor.stream('Write find_duplicates', {
  isTaskComplete: { scorers: [rubricScorer] },
  requestContext: {
    rubric: '- All tests pass\n- The function is named find_duplicates',
  },
})
```

Si aucun rubric resolves, the scorer returns `1` et doesn't gate the loop.

## Scoring details

The scorer runs dans deux phases:

1. **Grade**: The judge modèle evaluates chaque criterion independently et returns a per-criterion verdict (`satisfied` / not) avec reasoning.
1. **Score**: Le résultat est `1` only when every requis criterion est `satisfied`, otherwise `0`. Si aucun criteria sont marked required, tous les criteria sont treated comme required.

The `reason` summarizes the résultat et lists chaque criterion avec its verdict, so a failing grade gives the agent targeted, useful feedback rather than a generic "try again".
