# Summarization scorer

The `createSummarizationScorer()` fonction creates a scorer that evaluates a summary sur deux axes: whether every claim it makes est pris en charge par the source text, et whether it preserves the information the source states. The final score est the lower de the two, so a summary can't transmet par being faithful mais empty, ou thorough mais wrong.

The summary est the agent's dernier message that carries text, et the source text defaults à the premier utilisateur message de the exécute input. Pass `source` ou `sourceExtractor` when the text being summarized lives somewhere else, such comme a Tool result.

## Exemple d’utilisation

Score a summary against the document it condenses.

```typescript title="src/mastra/scorers/summarization.ts"
import { createSummarizationScorer } from '@mastra/evals/scorers/prebuilt'

const scorer = createSummarizationScorer({
  model: '__GATEWAY_OPENAI_MODEL__',
})

const result = await scorer.run({
  input: {
    inputMessages: [{ id: '1', role: 'user', content: sourceDocument }],
  },
  output: [{ id: '2', role: 'assistant', content: summary }],
})

console.log(result.score)
console.log(result.reason)
```

## Summarization evaluation

Utilisez ce scorer when an agent condenses text:

- Document et transcript summarization
- Prendre en charge thread et email digests
- Any step that compresses a long input dans a short output

The axis scores sont derived depuis these verdicts rather than stored: alignment est the share de `alignment` entries avec `supported: true`, et coverage est the share de `questions` whose `coverage` entry possède `answered: true`.

## Scoring details

### Two-axis evaluation

The scorer runs a three-step pipeline:

1. **Source judgement**: the claims the summary makes sont extracted et checked against the source, et closed-ended questions sont drawn depuis the source. Every question est written so the source answers it "yes".
1. **Coverage**: chaque question est answered using the summary alone.
1. **Scoring**: the deux ratios sont computed et the lower un becomes the score.

The coverage step runs comme a separate modèle call that never receives the source text. Un judge that could see the source would answer questions depuis it rather than depuis the summary, which would hide the omissions this axis exists à measure.

### Scoring formula

```
Alignment    = supported_claims / total_claims
Coverage     = answered_questions / total_questions
Summarization = min(Alignment, Coverage) × scale
```

The score est 0 when the summary yields aucun claims ou the source yields aucun questions.

### Score interpretation

Ces ranges assume the par défaut `scale` de 1. Lorsque vous utilisez a personnalisé scale, multiply accordingly.

- **0.9-1.0**: Excellent summary, faithful à the source et covering its main points
- **0.7-0.8**: Good summary avec a small omission ou an unsupported detail
- **0.4-0.6**: Moderate summary, either missing important information ou drifting depuis the source
- **0.1-0.3**: Poor summary, most de the source est lost ou contradicted
- **0.0**: The summary produced nothing à judge, ou it failed à support tout claims. Un summary that answers aucun questions also receives this score

### Reading the deux axes

Both axes leave their verdicts sur the exécute result: the alignment verdicts sur the preprocess step, et the coverage verdicts sur the analyze step. Chaque verdict carries the claim ou question it belongs à et the reason behind it. Un low alignment score possède a different meaning depuis a low coverage score:

- Un low alignment score avec high coverage means the summary invents ou distorts detail
- Un low coverage score avec high alignment means the summary est accurate mais leaves too much out

The reason field names whichever axis produced the score.

### What the score leaves out

Length plays aucun part dans the score. Un summary that repeats the source word pour word supports every claim et answers every question, so it scores 1. Ajouter a length check de your own when compression est part de what you're testing.

### Cost

Chaque evaluation makes three modèle calls. `maxQuestions` bounds the coverage half de the work, which otherwise grows avec source length. Raise it pour long documents where ten questions can't represent the content.

## Scorer configuration

### Summarizing the exécute input

```typescript
const scorer = createSummarizationScorer({
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

### Summarizing a document depuis elsewhere

```typescript
import { extractToolResults } from '@mastra/evals/scorers/utils'

const scorer = createSummarizationScorer({
  model: '__GATEWAY_OPENAI_MODEL__',
  options: {
    sourceExtractor: (input, output) => {
      return extractToolResults(output)
        .filter(({ toolName }) => toolName === 'fetchDocument')
        .map(({ result }) => String(result))
        .join('\n\n')
    },
    maxQuestions: 20,
  },
})
```

## Exemple

Evaluate a summarization agent against a définit de documents:

```typescript title="src/example-summarization.ts"
import { runEvals } from '@mastra/core/evals'
import { createSummarizationScorer } from '@mastra/evals/scorers/prebuilt'
import { summarizerAgent } from './agent'

const scorer = createSummarizationScorer({
  model: '__GATEWAY_OPENAI_MODEL__',
  options: { maxQuestions: 10 },
})

const result = await runEvals({
  target: summarizerAgent,
  scorers: [scorer],
  data: [
    {
      input:
        'The company was founded in 1995 by John Smith. It started with 10 employees and grew to 500 by 2020. The company is based in Seattle.',
    },
  ],
  onItemComplete: ({ scorerResults }) => {
    console.log({
      score: scorerResults[scorer.id].score,
      reason: scorerResults[scorer.id].reason,
    })
  },
})

console.log(result.scores)
```

Pour plus de détails sur `runEvals`, consultez la [référence runEvals](/reference/evals/run-evals).

Pour ajouter ce scorer à un Agent, consultez le guide de [présentation des Scorers](/docs/evals/overview#adding-scorers-to-agents).

## Comparison avec faithfulness

| Use case | Summarization | Faithfulness |
| - | - | - |
| **What it measures** | Prendre en charge et coverage together | Prendre en charge only |
| **Judged against** | The source text being condensed | Retrieved context ou Tool results |
| **Catches omission** | Yes | No |
| **Needs the full source** | Yes | No, context alone est enough |

Use `faithfulness` when the question est whether an answer stays grounded dans retrieved context. Use `summarization` when the output est meant à stand dans pour a longer text.
