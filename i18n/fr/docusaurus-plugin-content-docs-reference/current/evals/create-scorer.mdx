# createScorer

Mastra provides a unified `createScorer` factory that allows you à define personnalisé scorers pour evaluating input/output pairs. Vous pouvez utiliser either native JavaScript functions ou LLM-based prompt objects pour chaque evaluation step. Personnalisé scorers peut be added à Agents et Workflow steps.

## How à crée a personnalisé scorer

Utilisez le `createScorer` factory à define your scorer avec a name, description, et facultatif judge configuration. Then chain step methods à génère your evaluation pipeline. You doit fournit à least a `generateScore` step.

**Prompt objet steps** sont step configurations expressed comme objects avec `description` + `createPrompt` (and `outputSchema` pour `preprocess`/`analyze`). Ces steps invoke the judge LLM. **Function steps** sont plain functions et never call the judge.

```typescript
import { createScorer } from '@mastra/core/evals'

const scorer = createScorer({
  id: 'my-custom-scorer',
  name: 'My Custom Scorer', // Optional, defaults to id
  description: 'Evaluates responses based on custom criteria',
  type: 'agent', // Optional: for agent evaluation with automatic typing
  judge: {
    model: myModel,
    instructions: 'You are an expert evaluator...',
  },
})
  .preprocess({/* step config */})
  .analyze({/* step config */})
  .generateScore(({ run, results }) => {
    // Return a number
  })
  .generateReason({/* step config */})
```

Ce fonction returns a scorer builder that you peut chain step methods onto. Consultez the [MastraScorer reference](./mastra-scorer) pour details sur the `.run()` method et its input/output.

The judge only runs pour steps defined comme **prompt objects** (`preprocess`, `analyze`, `generateScore`, `generateReason` dans prompt mode). Si vous utilise fonction steps only, the judge est never called et there est aucun LLM output à inspect. In that case, tout score/reason doit be produced par your functions.

Lorsqu’un prompt-object step runs, its structured LLM output est stored dans the corresponding résultat field (`preprocessStepResult`, `analyzeStepResult`, ou the valeur consumed par `calculateScore` dans `generateScore`).

## Retry judge requests

Utilisez le existant judge `errorProcessors` configuration à retry transient failures inside a failed judge request. Ce doesn't retry the scorer workflow, trace target, batch item, score write, ou a completed scorer step.

`@mastra/core` `1.49.0` doesn't inclut scorer error-processor configuration. Upgrade à a version avec scorer processor support, ou backport that focused change, avant using this configuration.

Les éléments suivants example uses un bounded retry budget. Définir the processor `maxRetries` et `judge.maxProcessorRetries` à the same value. Keep the internal judge agent's modèle retries à the par défaut de `0` so modèle retries don't multiply processor attempts.

```typescript title="src/mastra/scorers/response-quality.ts"
import { createScorer } from '@mastra/core/evals'
import { StreamErrorRetryProcessor } from '@mastra/core/processors'

const isTransientNetworkError = (error: unknown) =>
  error instanceof Error && /ECONNRESET|ETIMEDOUT|socket hang up/i.test(error.message)

const retryProcessor = new StreamErrorRetryProcessor({
  maxRetries: 2,
  maxRetryAfterMs: 30_000,
  delayMs: ({ retryCount }) => Math.min(1_000 * 2 ** retryCount, 30_000),
  matchers: [isTransientNetworkError],
  retryUnknownErrors: false,
})

export const responseQuality = createScorer({
  id: 'response-quality',
  description: 'Scores response quality',
  judge: {
    model: myModel,
    instructions: 'Return a score and concise reason.',
    errorProcessors: [retryProcessor],
    maxProcessorRetries: 2,
  },
})
  .generateScore({
    description: 'Score the response quality.',
    createPrompt: ({ run }) => `Score: ${run.output}`,
  })
  .generateReason({
    description: 'Explain the score.',
    createPrompt: () => 'Explain the score.',
  })
```

Avec cette configuration, a failed requête possède à most three provider attempts: the initial requête plus deux processor retries. If `generateScore` completes et `generateReason` receives a retryable failure, only `generateReason` retries.

`StreamErrorRetryProcessor` honors retryable provider metadata et narrow personnalisé matchers. It keeps `retryUnknownErrors` désactivé par default, so authentication, invalid-request, et context-length errors fail immediately unless you explicitly match them. It bounds `Retry-After` values à `30_000` milliseconds par default. Use `maxRetryAfterMs` à change that cap.

Avoid adding outer scorer ou Workflow retries. Avoid combining a nonzero modèle retry setting avec this processor unless you intentionally accept additional attempts.

### Override retries pour un step

Un step's `judge` configuration overrides scorer-level judge fields. Processor arrays replace the scorer-level arrays. Omit `maxProcessorRetries` dans the step configuration à inherit the scorer-level numeric cap.

Coordinated processor retries require a judge modèle that uses Mastra’s actuel generation API. Legacy modèle adapters call [`generateLegacy()`](/reference/agents/generateLegacy), bypass error processors, et utilise that API's separate AI SDK `maxRetries` par défaut de `2`.

## Type safety

Vous pouvez spécifie input/output types when creating scorers pour better type inference et IntelliSense support:

### Agent Type Shortcut

For evaluating agents, utilise `type: 'agent'` à automatically obtient the correct types pour agent input/output:

```typescript
import { createScorer } from '@mastra/core/evals'

// Agent scorer with automatic typing
const agentScorer = createScorer({
  id: 'agent-response-quality',
  description: 'Evaluates agent responses',
  type: 'agent', // Automatically provides ScorerRunInputForAgent/ScorerRunOutputForAgent
})
  .preprocess(({ run }) => {
    // run.input is automatically typed as ScorerRunInputForAgent
    const userMessage = run.inputData.inputMessages[0]?.content
    return { userMessage }
  })
  .generateScore(({ run, results }) => {
    // run.output is automatically typed as ScorerRunOutputForAgent
    const response = run.output[0]?.content
    return response.length > 10 ? 1.0 : 0.5
  })
```

### Personnalisé Types avec Generics

For personnalisé input/output types, utilise the generic approach:

```typescript
import { createScorer } from '@mastra/core/evals'

type CustomInput = { query: string; context: string[] }
type CustomOutput = { answer: string; confidence: number }

const customScorer = createScorer<CustomInput, CustomOutput>({
  id: 'custom-scorer',
  description: 'Evaluates custom data',
}).generateScore(({ run }) => {
  // run.input is typed as CustomInput
  // run.output is typed as CustomOutput
  return run.output.confidence
})
```

### Intégré Agent Types

- **`ScorerRunInputForAgent`** - Contains `inputMessages`, `rememberedMessages`, `systemMessages`, et `taggedSystemMessages` pour agent evaluation
- **`ScorerRunOutputForAgent`** - Array de agent réponse messages

Using these types provides autocomplete, compile-time validation, et better documentation pour your scoring logic.

## Trace scoring avec agent types

Lorsque vous utilise `type: 'agent'`, your scorer est compatible pour both adding directly à agents et scoring traces depuis agent interactions. The scorer automatically transforms trace données dans the proper agent input/output format:

```typescript
const agentTraceScorer = createScorer({
  id: 'agent-trace-length',
  description: 'Evaluates agent response length',
  type: 'agent',
}).generateScore(({ run }) => {
  // Trace data is automatically transformed to agent format
  const userMessages = run.inputData.inputMessages
  const agentResponse = run.output[0]?.content

  // Score based on response length
  return agentResponse?.length > 50 ? 0 : 1
})

// Register with Mastra for trace scoring
const mastra = new Mastra({
  scorers: {
    agentTraceScorer,
  },
})
```
