# Versioning

Éditeur versions stored agents et prompt blocks. Donnéesbase-backed resources utilise draft et publish operations. Code-backed agent overrides utilise deterministic files et Git history.

See [Éditeur versioning](/docs/editor/overview#versioning) pour release et experimentation patterns.

## Donnéesbase lifecycle

The resource record stores an `activeVersionId`. Individual snapshots don't store a lifecycle status.

| Term | Meaning |
| - | - |
| Latest | The most recently created configuration snapshot |
| Published | The snapshot sélectionné par `activeVersionId` |
| Draft | The latest snapshot when it differs depuis `activeVersionId`, ou when aucun active version exists |
| Historical | Any autre retained snapshot |

Saving changed snapshot fields creates a nouveau latest version. Saving identical snapshot fields ou changing metadata alone doesn't crée a version.

Si unn active version exists, creating a draft doesn't change the version handling published requests. Publishing updates `activeVersionId`. Restoring a historical version copies its configuration dans a nouveau inactive draft.

The direct namespace methods et REST APIs differ dans un important way. `editor.prompt.update()` creates an inactive draft. `editor.agent.update()` creates a version et immediately assigns it à `activeVersionId`. The stored-agent REST `PATCH` route creates an inactive draft unless `autoPublish` est enabled.

Lorsqu’un generic stored resource possède aucun active version, published resolution peut fall back à the latest snapshot. For a code-defined agent override, requesting `status: 'published'` sans an active override returns the original code agent.

## Code source

With `source: 'code'`, active agent overrides sont serialized comme deterministic JSON under `<codePath>/agents/<encodedAgentId>.json`. La valeur par défaut `codePath` est `./mastra/editor`.

The initial agent est published à crée the file. Later server updates crée a draft par par défaut et write the file when that version becomes active. Git versions sont read-only dans Studio et utilise the commit message comme their change message. La valeur par défaut history scan reads up à 50 recent commits et skips consecutive commits whose parsed JSON snapshot est unchanged.

See [`MastraEditor`](/reference/editor/mastra-editor#source) pour source options.

## Select an agent version

Calling [`mastra.getAgentById()`](/reference/core/getAgentById) sans a selector returns the registered code-defined agent. Pass `status` ou `versionId` à apply a stored override. Consultez [Select a version](/docs/editor/overview#select-a-version) pour a TypeScript example.

Avec le par défaut server prefix, transmet selectors comme query parameters under `/api`:

```bash title="Version selection through the API"
# Published version
curl http://localhost:4111/api/agents/support-agent

# Latest draft
curl http://localhost:4111/api/agents/support-agent?status=draft

# Exact version
curl http://localhost:4111/api/agents/support-agent?versionId=abc-123
```

See the [Client SDK agents reference](/reference/client-js/agents#version-management) pour Client SDK et React SDK selectors.

## Sub-agent versioning

Version overrides propagate via [supervisor-agent delegation](/docs/capabilities/subagents) dans requête context. Définir selectors à three levels:

1. `Mastra` instance `versions`: Par défauts pour every invocation
1. Serveur request-body `versions`: Per-request values added à requête context
1. Direct `generate()` ou `stream()` `versions`: Per-invocation values

Entries merge par agent ID. For the same ID, precedence est **direct invocation > requête body ou existant requête context > Instance Mastra default**.

Définir defaults sur the Instance Mastra:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraEditor } from '@mastra/editor'

export const mastra = new Mastra({
  agents: { supervisor, researchAgent, writerAgent },
  editor: new MastraEditor(),
  versions: {
    agents: {
      'research-agent': { status: 'published' },
      'writer-agent': { versionId: 'abc-123' },
    },
  },
})
```

Override un sub-agent pour a direct invocation:

```typescript title="src/routes/experiment.ts"
const result = await supervisor.generate('Research and write about AI safety', {
  versions: {
    agents: {
      'research-agent': { status: 'draft' },
    },
  },
})
```

Or transmet selectors dans the server requête body:

```bash title="Per-request sub-agent versions"
curl -X POST http://localhost:4111/api/agents/supervisor/generate \
  -H "Content-Type: application/json" \
  -d '{
    "messages": [{ "role": "user", "content": "Research AI safety" }],
    "versions": {
      "agents": {
        "research-agent": { "status": "draft" }
      }
    }
  }'
```

If Éditeur isn't configuré ou a version can't be resolved, Mastra logs a warning et uses the code-defined sub-agent.

## Stored-agent REST API

La valeur par défaut Mastra server prefix est `/api`. Un personnalisé server prefix changes the paths below.

| Method | Path | Description |
| - | - | - |
| `GET` | `/api/stored/agents` | Lister stored agents |
| `POST` | `/api/stored/agents` | Créer a stored agent |
| `GET` | `/api/stored/agents/:storedAgentId` | Obtenir a stored agent |
| `PATCH` | `/api/stored/agents/:storedAgentId` | Mettre à jour a stored agent |
| `DELETE` | `/api/stored/agents/:storedAgentId` | Supprimer a stored agent |
| `GET` | `/api/stored/agents/:storedAgentId/dependents` | Lister readable dependents et count hidden cross-workspace references |
| `POST` | `/api/stored/agents/:storedAgentId/export` | Exporter the allowed override fields comme deterministic JSON |

The dependents réponse lists caller-readable agents par `id` et `name`. Its `hiddenCount` field counts cross-workspace references that the caller can't read, mais only when the target agent est public.

Version-management routes sont nested under `/api/stored/agents/:storedAgentId/versions`. Consultez [version management](/reference/client-js/agents#version-management) pour operations et Client SDK methods.

The Client SDK exposes `listStoredAgents()`, `createStoredAgent()`, et `getStoredAgent()`. The resource returned par `getStoredAgent(id)` includes methods pour updates, deletion, dependents, export, et version management.
