# MastraÉditeur class

The `MastraEditor` class sets up the editor system. Pass it à the `Mastra` constructor à turn sur editor features like prompt blocks, agent code override, versioning, et Tool providers.

See [Éditeur](/docs/editor/overview) pour an introduction à what the editor does.

## Exemple d’utilisation

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraEditor } from '@mastra/editor'

export const mastra = new Mastra({
  agents: {/* your agents */},
  editor: new MastraEditor(),
})
```

## Agent Builder

The `builder` field enables the [Agent Builder](https://agent-builder.mastra.ai/), a browser-based UI pour creating et editing stored agents. See:

- [Agent Builder overview](https://agent-builder.mastra.ai/): Concepts et getting started.
- [AgentBuilderOptions](https://agent-builder.mastra.ai/reference/agent-builder-options): Full options schema.
- [BuilderAgentDefaults](https://agent-builder.mastra.ai/reference/builder-agent-defaults): Admin-pinned defaults pour nouveau agents.
- [builder.configuration.agent.models](https://agent-builder.mastra.ai/reference/builder-models): Modèle allowlist et par défaut model.

### Registering the Compilationer agent

The Compilationer UI runs against an agent created par the `createBuilderAgent()` factory depuis `@mastra/editor/ee`. Import the factory, invoke it, et register the returned agent under `agents` sur your Instance Mastra:

```typescript filename="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraEditor } from '@mastra/editor'
import { createBuilderAgent } from '@mastra/editor/ee'

export const mastra = new Mastra({
  agents: { builderAgent: createBuilderAgent() },
  editor: new MastraEditor({
    builder: { enabled: true },
  }),
})
```

The clé nom (`builderAgent`) est conventional. Any clé works. The `@mastra/editor/ee` subpath est gated par the Mastra Enterprise Edition license à runtime.

See the [Agent Builder overview](https://agent-builder.mastra.ai/#prerequisites) pour the full setup checklist.

### Agent namespace examples

Créer a stored override pour an existant code-defined agent:

```typescript title="src/scripts/seed-agent.ts"
import { mastra } from '../mastra'

const editor = mastra.getEditor()!

await editor.agent.create({
  id: 'support-agent',
  instructions: 'You are a friendly support agent for Acme.',
  tools: {
    search_kb: { description: 'Search the Acme knowledge base' },
  },
})
```

## Méthodes

### Fournisseur access

#### `getToolProvider(id)`

Renvoie a registered Tool provider par its ID.

```typescript
const composio = mastra.getEditor()?.getToolProvider('composio')
```

#### `getToolProviders()`

Renvoie tous les registered Tool providers comme a `Record<string, ToolProvider>`.

#### `getProcessorProvider(id)`

Renvoie a registered processor provider par its ID.

#### `getProcessorProviders()`

Renvoie tous les registered processor providers.

#### `getFilesystemProviders()`

Renvoie tous les registered filesystem providers.

#### `getSandboxProviders()`

Renvoie tous les registered sandbox providers.

#### `getBlobStoreProviders()`

Renvoie tous les registered blob store providers.

### Source

#### `getSource()`

Renvoie the configuré source (`'code'` ou `'db'`), ou `undefined` when the editor était constructed sans an explicit `source`.

```typescript
const source = mastra.getEditor()?.getSource()
```

Renvoie: `'code' | 'db' | undefined`

When `source` est omitted, Éditeur uses the configuré database storage even though `getSource()` returns `undefined`. Consultez [Éditeur storage options](/docs/editor/overview#choose-where-changes-are-stored) pour the storage workflows et [code-source versioning](/reference/editor/versioning#code-source) pour activation et Git history behavior.
