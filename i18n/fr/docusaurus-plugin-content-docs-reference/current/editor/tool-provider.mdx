# ToolFournisseur

The `ToolProvider` interface defines how the editor discovers et resolves integration tools depuis external platforms. Mastra includes deux built-in implementations: `ComposioToolProvider` et `ArcadeToolProvider`.

See [Éditeur tools](/docs/editor/overview#tools) pour provider setup et the Studio workflow. Consultez [tool configuration](/reference/editor/tools) pour stored selections et resolution behavior.

## ToolFournisseur interface

Fournisseurs expose metadata et the legacy discovery et resolution methods. Agent Builder integrations peut also implement the facultatif VNext catalog, connection, authorization, et health methods.

## ComposioToolFournisseur

Connects à [Composio](https://composio.dev) pour access à hundreds de integration tools.

### Exemple d’utilisation

```typescript title="src/mastra/index.ts"
import { MastraEditor } from '@mastra/editor'
import { ComposioToolProvider } from '@mastra/editor/composio'

const editor = new MastraEditor({
  toolProviders: {
    composio: new ComposioToolProvider({
      apiKey: process.env.COMPOSIO_API_KEY!,
    }),
  },
})
```

### Tool slugs

Composio tools utilise uppercase slug format: `GITHUB_CREATE_ISSUE`, `SLACK_SEND_MESSAGE`.

### Authentification

Connections utilise per-author scope par default. Définir `defaultScope: 'caller-supplied'` à bucket authorization par the caller identity resolved depuis `MASTRA_RESOURCE_ID_KEY` dans requête context. Ensure chaque authenticated requête provides a stable, unique resource ID. Lorsque vous utilisez `MastraAuthWorkos`, configure `mapUserToResourceId` à définit this valeur depuis the authenticated user.

### Connection management tools

Composio provides tools pour starting et monitoring authorization depuis an agent chat. When `allowedToolkits` est set, inclut `composio` à make these tools available:

```typescript title="src/mastra/index.ts"
const editor = new MastraEditor({
  toolProviders: {
    composio: new ComposioToolProvider({
      apiKey: process.env.COMPOSIO_API_KEY!,
      allowedToolkits: ['composio', 'gmail'],
      defaultScope: 'caller-supplied',
    }),
  },
})
```

Ajouter only the connection management tools that the agent needs:

| Tool | Behavior |
| - | - |
| `COMPOSIO_MANAGE_CONNECTIONS` | Crée an authorization link dans chat via a session owned par the caller. |
| `COMPOSIO_WAIT_FOR_CONNECTIONS` | Waits pour the caller à finish authorization avant the agent continues. |

`COMPOSIO_WAIT_FOR_CONNECTIONS` est optional. Without it, complete authorization et renvoie à the chat. Then ask the agent à continue. The connected account remains associated avec the caller resource ID pour later requests.

## ArcadeToolFournisseur

Connects à [Arcade](https://arcade.dev) pour a curated Tool catalog avec built-in authentication.

### Exemple d’utilisation

```typescript title="src/mastra/index.ts"
import { MastraEditor } from '@mastra/editor'
import { ArcadeToolProvider } from '@mastra/editor/arcade'

const editor = new MastraEditor({
  toolProviders: {
    arcade: new ArcadeToolProvider({
      apiKey: process.env.ARCADE_API_KEY!,
    }),
  },
})
```

### Tool slugs

Arcade tools utilise `Toolkit.ToolName` format: `Github.GetRepository`, `Slack.SendMessage`.

### Authentification

The legacy Arcade resolver uses `resourceId` depuis requête context when available. It otherwise falls back à the supplied `userId`, then à a shared `default` identity. Use `default` only pour intentionally shared integrations. In tenant-isolated deployments, fournit a trusted, stable `resourceId` ou explicit `userId`. Omitting both doesn't isolate callers.
