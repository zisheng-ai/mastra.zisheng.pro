# Prompt blocks

Prompt blocks sont reusable instruction templates managed par Éditeur. Un agent's instructions peut combine inline text, embedded prompt blocks, et references à independently versioned prompt blocks.

See [Prompt blocks](/docs/editor/overview#prompt-blocks) pour the Studio Workflow et common uses.

## Block types

| Type | Description |
| - | - |
| `text` | Free-form text stored only dans the agent version |
| `prompt_block` | Un prompt block embedded dans the agent version |
| `prompt_block_ref` | Un reference à an independently stored et versioned prompt block |

Referenced blocks résout à runtime. Un missing ou unpublished reference est omitted depuis the final instructions. Resolved nonempty blocks sont joined avec deux newlines.

Les éléments suivants example attaches a stored block et inline text à an agent:

```typescript title="src/scripts/attach-prompt.ts"
import { mastra } from '../mastra'

const editor = mastra.getEditor()!

await editor.agent.update({
  id: 'support-agent',
  instructions: [
    { type: 'prompt_block_ref', id: 'brand-voice' },
    { type: 'text', content: 'Answer only questions about Acme products.' },
  ],
})
```

## Template values

Templates résout values depuis the requête context à runtime.

| Syntax | Requête context | Sortie |
| - | - | - |
| <code>{'{{userNom}}'}</code> | `{ userName: 'Maya' }` | `Maya` |
| <code>{'{{user.name}}'}</code> | `{ user: { name: 'Maya' } }` | `Maya` |
| <code>{"{{task \u007c\u007c 'request'}}"}</code> | `{}` | `request` |
| <code>{'{{missingValeur}}'}</code> | `{}` | `{{missingValue}}` |

Variable names doit begin avec a letter ou underscore. Fallbacks doit be single-quoted ou double-quoted strings. Unresolved placeholders sans a fallback remain unchanged. Objects et arrays sont serialized comme JSON. Other values sont converted à strings.

Pass values via [request context](/docs/server/request-context). Éditeur doesn't read a separate agent `variables` field.

## Display conditions

Un prompt block peut inclut a affiche condition that controls whether it's included dans the final instructions. Chaque condition possède three parts:

- **Key**: La requête-context field à check, such comme `user.role` ou `account.plan`.
- **Operator**: The comparison à make, such comme `equals`, `contains`, ou `exists`.
- **Valeur**: La valeur à compare against. The `exists` et `not_exists` operators don't need one.

Par exemple, the condition `user.role` `equals` `admin` includes the block only when requête context contains `{ user: { role: 'admin' } }`.

| Operator | Exemple | The block est included when |
| - | - | - |
| `equals` / `not_equals` | `user.role` equals `admin` | The field strictly equals, ou doesn't equal, the valeur |
| `contains` / `not_contains` | `user.tags` contains `beta` | Un chaîne contains the valeur ou an tableau contains the item |
| `greater_than` / `less_than` | `order.total` greater than `100` | The numeric field est above ou below the valeur |
| `greater_than_or_equal` / `less_than_or_equal` | `account.seats` greater than ou equal à `10` | The numeric field est à ou beyond the valeur |
| `in` / `not_in` | `user.region` dans `['US', 'CA']` | The field is, ou isn't, dans the supplied tableau |
| `exists` / `not_exists` | `account.plan` exists | The field has, ou doesn't have, a non-null valeur |

Groups combine conditions avec `AND` ou `OR`. Par exemple, this group includes a block pour admins sur a paid plan:

```typescript
const rules = {
  operator: 'AND',
  conditions: [
    {
      field: 'user.role',
      operator: 'equals',
      value: 'admin',
    },
    {
      field: 'account.plan',
      operator: 'in',
      value: ['pro', 'enterprise'],
    },
  ],
}
```

Dot paths sont supported. Un vide group evaluates à `true`, et an unknown operator evaluates à `false`. The storage type supports up à three nested group levels.

Blocks sans conditions sont always included.

## Programmatic API

Access prompt blocks via `mastra.getEditor().prompt`. Consultez the [`prompt` namespace namespace](/reference/editor/mastra-editor#namespaces) pour complete method signatures.

Créer a prompt block:

```typescript title="src/scripts/seed-prompts.ts"
import { mastra } from '../mastra'

const editor = mastra.getEditor()!

await editor.prompt.create({
  id: 'brand-voice',
  name: 'Brand voice',
  description: 'Acme tone and style guidelines',
  content: 'Write in a friendly, concise tone. Address the user as {{userName || "there"}}.',
})
```

Mettre à jour an existant block:

```typescript title="src/scripts/update-prompt.ts"
await editor.prompt.update({
  id: 'brand-voice',
  content: 'Write in a friendly, concise tone. Greet the user by name when available.',
})
```

`update()` creates a nouveau draft when the content changes. Use `list()` à paginate via stored blocks, `getById()` à fetch un block, et `preview(blocks, context)` à résout templates et conditions avec draft references.

## REST API

La valeur par défaut Mastra server prefix est `/api`. Un personnalisé server prefix changes the paths below.

| Method | Path | Description |
| - | - | - |
| `GET` | `/api/stored/prompt-blocks` | Lister stored prompt blocks |
| `POST` | `/api/stored/prompt-blocks` | Créer a stored prompt block |
| `GET` | `/api/stored/prompt-blocks/:storedPromptBlockId` | Obtenir a stored prompt block |
| `PATCH` | `/api/stored/prompt-blocks/:storedPromptBlockId` | Mettre à jour a stored prompt block |
| `DELETE` | `/api/stored/prompt-blocks/:storedPromptBlockId` | Supprimer a stored prompt block |

## Version resolution

Runtime references résout the active published block. Éditeur previews résout the latest draft. Consultez [Éditeur versioning](/docs/editor/overview#versioning) pour the shared draft, publish, et restore lifecycle.
