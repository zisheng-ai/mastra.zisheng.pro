# Configuration des Tools

Editor enregistre les Tools sélectionnés dans une version d’Agent. Une configuration stockée peut ajouter des Tools enregistrés, des Tools provenant de fournisseurs d’intégration et des Tools issus de clients Model Context Protocol (MCP).

Consultez [les Tools d’Editor](/docs/editor/overview#tools) pour découvrir le Workflow dans Studio et les usages courants.

## Sources des Tools {/* #tool-sources */}

| Source | Description |
| - | - |
| Tools enregistrés | Tools enregistrés dans le registre des Tools du runtime Mastra |
| Clients MCP | Tools exposés par des configurations stockées de serveurs MCP locaux ou distants |
| Tools d’intégration | Tools résolus à partir de l’ancienne configuration des fournisseurs d’intégration |
| [Fournisseurs de Tools](/reference/editor/tool-provider) | Tools résolus par les fournisseurs enregistrés dans `MastraEditor`, comme Composio ou Arcade |

Les Agents définis dans le code conservent leurs Tools existants. Le [paramètre de remplacement `editor`](/reference/agents/agent#editor-overrides) détermine si Editor peut ajouter et supprimer des Tools ou seulement modifier leurs descriptions.

## Remplacement des descriptions {/* #description-overrides */}

Chaque Tool sélectionné peut stocker une description propre à l’Agent. Cette description modifie ce que voit le modèle sans changer la définition d’origine du Tool.

En mode de remplacement des descriptions uniquement, Editor applique les remplacements seulement aux Tools qui existent déjà sur l’Agent défini dans le code. Pour les Tools MCP, une description définie au niveau de l’Agent est prioritaire sur celle enregistrée dans le client MCP.

Si deux sources résolvent le même ID de Tool, la source la plus tardive remplace entièrement le Tool précédent, y compris sa description. Consultez l’[ordre de résolution](#resolution-order).

## Ensembles conditionnels de Tools {/* #conditional-tool-sets */}

Editor peut stocker des variantes conditionnelles pour les champs `tools`, `mcpClients`, `integrationTools` et `toolProviders`. Lors de l’exécution, les variantes correspondantes sont fusionnées superficiellement selon les valeurs du contexte de requête.

Le langage de règles utilise les mêmes opérateurs et le même comportement d’imbrication que les [conditions d’affichage des blocs de prompt](/reference/editor/prompt-blocks#display-conditions).

Les conditions s’appliquent à une variante de champ de Tool ou à une référence de client MCP. Le résolveur Editor actuel n’évalue pas les valeurs `rules` propres à chaque Tool dans les entrées stockées.

## Clients MCP stockés {/* #stored-mcp-clients */}

L’espace de noms `editor.mcp` gère des configurations réutilisables de clients MCP. Consultez l’[espace de noms `mcp`](/reference/editor/mastra-editor#namespaces) pour connaître les signatures des méthodes CRUD.

`@mastra/mcp` est une dépendance pair facultative de `@mastra/editor`. Installez-la avant de configurer des clients MCP stockés afin qu’Editor puisse charger leurs Tools lors de l’exécution :

```bash npm2yarn
npm install @mastra/mcp
```

### Transports {/* #transports */}

| Transport | Configuration stockée |
| - | - |
| `stdio` | `command` avec les valeurs facultatives `args`, `env` et `timeout` |
| HTTP | `url` avec la valeur facultative `timeout` |

Les définitions HTTP stockées n’acceptent pas d’en-têtes arbitraires. Lorsque la valeur réservée `mastra__authToken` est présente dans le contexte de requête, Editor la transmet dans un en-tête `Authorization: Bearer`.

### Filtrage {/* #filtering */}

Les Tools MCP peuvent être inscrits sur une liste d’autorisation à deux niveaux :

1. **Niveau du serveur** : la map `tools` du serveur stocké limite les Tools pour chaque Agent qui utilise le client.
1. **Niveau de l’Agent** : la référence de client MCP de l’Agent limite les Tools restants pour cet Agent.

Les noms de Tools au niveau de l’Agent peuvent utiliser des noms avec ou sans espace de noms. Une map `tools` explicitement vide sélectionne tous les Tools. Avec le résolveur actuel, l’omission de `tools` dans une référence MCP au niveau de l’Agent n’en sélectionne aucun.

### Espaces de noms {/* #namespacing */}

Les Tools MCP utilisent des ID au format `serverName_toolName` pour éviter les conflits. Un Tool `search` provenant du serveur `docs` devient `docs_search`.

## Ordre de résolution {/* #resolution-order */}

Editor fusionne les enregistrements de Tools dans l’ordre suivant. Les enregistrements les plus tardifs remplacent ceux qui les précèdent lorsqu’ils possèdent le même ID.

1. Tools définis dans le code
1. Tools enregistrés et stockés
1. Tools MCP
1. Tools des anciennes intégrations
1. Tools des fournisseurs de Tools V1

Les Agents autonomes stockés utilisent le même ordre, sans les Tools définis dans le code. Les remplacements statiques d’Agents définis dans le code s’arrêtent après les Tools des anciennes intégrations.

Utilisez autant que possible des ID de Tool uniques dans toutes les sources. En cas de collision, le Tool précédent est entièrement remplacé au lieu de voir ses champs fusionnés.
