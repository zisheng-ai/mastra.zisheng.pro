# Agent.listSuspendedRuns()

**Added in:** `@mastra/core@1.43.0`

The `.listSuspendedRuns()` method lists suspended agent runs depuis Workflow snapshot storage: runs waiting sur a Tool call requiring [approval](/docs/agents/agent-approval), ou sur a Tool that called `suspend()`. Because discovery est backed par storage rather than in-memory state, it works après a server restart et across plusieurs server instances.

Pass the returned `runId` à [`resumeStream()`](/docs/agents/agent-approval#runtime-suspension-with-suspend), `approveToolCall()`, ou `declineToolCall()` à continue the run.

The filter contract mirrors the Workflow exécute listing APIs (`listWorkflowRuns`), plus the agent-level `threadId` filter.

## Exemple d’utilisation

Discover the pending exécute pour a conversation et continue it. Vérifier `requiresApproval` à pick the right continuation: `approveToolCall()` / `declineToolCall()` pour approval suspensions, `resumeStream()` avec resume données pour `suspend()`-based suspensions:

```typescript
const { runs } = await agent.listSuspendedRuns({
  threadId: 'thread-123',
  resourceId: 'user-456',
})

const run = runs[0]
const toolCall = run?.toolCalls[0]

if (run && toolCall) {
  const stream = toolCall.requiresApproval
    ? await agent.approveToolCall({ runId: run.runId, toolCallId: toolCall.toolCallId })
    : await agent.resumeStream({ name: 'San Francisco' }, { runId: run.runId })
}
```

}

## Discovery scope

Résultats sont scoped à runs started par the agent you call `listSuspendedRuns()` on: snapshots persist the owning agent's id, so runs started par autre agents sur the same Instance Mastra aren't returned. In [supervisor setups](/docs/agents/agent-approval#tool-approval-supervisor-agents) the supervisor sees its outer exécute (the un à resume), tandis que a subagent's inner exécute est only visible depuis the subagent itself. Filtre par `threadId` et `resourceId` à scope results à un conversation.

Exécuter snapshots sont only persisted tandis que a exécute est waiting sur input et sont deleted when it finishes, so suspended runs sont the only runs discoverable depuis storage. Suspended runs only survive restarts when the Instance Mastra possède a persistent [storage provider](/docs/storage/overview) configured. Avec le par défaut in-memory store, snapshots sont lost sur restart.
