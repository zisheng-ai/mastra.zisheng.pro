# create-mastra

Créez un projet Mastra autonome. Par défaut, `create-mastra` installe un starter par défaut et le configure pour le fournisseur de modèles sélectionné.

```bash npm2yarn
npx create-mastra@latest
```

## Modes de création {/* #creation-modes */}

### Starter par défaut {/* #default-starter */}

Le starter par défaut crée un environnement d’agent avec des outils d’espace de travail, de la mémoire, le suivi des tâches, un accès web, des planifications récurrentes, du stockage et de l’observabilité. Sélectionnez OpenAI, Anthropic, Gemini ou xAI comme fournisseur de modèles.

Indiquez le nom du projet et le fournisseur pour créer le projet sans invites. Cet exemple utilise Anthropic ; vous pouvez également passer `openai`, `google` ou `xai` :

```bash npm2yarn
npx create-mastra@latest my-mastra-project --llm anthropic
```

Omettez `--llm` pour sélectionner le fournisseur et, si vous le souhaitez, saisir sa clé API de manière interactive. La configuration interactive propose également de connecter votre projet à la plateforme Mastra. Si vous l’activez, la commande ouvre le flux d’authentification dans le navigateur et crée un projet sur la plateforme portant le même nom que le projet local. Elle écrit ensuite `MASTRA_PLATFORM_ACCESS_TOKEN` et `MASTRA_PROJECT_ID` dans `.env`.

### Modèle {/* #template */}

Utilisez un slug de modèle ou une URL GitHub publique :

```bash npm2yarn
npx create-mastra@latest my-mastra-project --template agent-harness
```

```bash npm2yarn
npx create-mastra@latest my-mastra-project --template https://github.com/mastra-ai/template-agent-harness
```

Laissez la valeur du modèle vide pour sélectionner un modèle de manière interactive :

```bash npm2yarn
npx create-mastra@latest my-mastra-project --template
```

Les auteurs de modèles sont responsables de leurs dépendances, modèles, variables d’environnement et code source. `create-mastra` n’applique pas `--llm` ni `--llm-api-key`.

### Squelette vide {/* #empty-scaffold */}

Utilisez `--empty` pour créer un projet sans fournisseur, agents, exemples, SDK de modèles ni fichiers d’environnement :

```bash npm2yarn
npx create-mastra@latest my-empty-project --empty
```

## Configuration automatique {/* #automatic-setup */}

Après l’installation des dépendances, la commande :

1. Détecte les assistants de programmation pris en charge dans `PATH` et installe les skills Mastra. Si aucun n’est détecté, elle installe les skills universels.
1. Crée un commit Git initial lorsque le répertoire actuel et le projet généré ne se trouvent pas déjà dans des dépôts Git.

Utilisez `--no-skills` ou `--no-git` pour ignorer ces étapes. Les échecs de configuration des skills et de Git produisent des avertissements, mais ne suppriment pas un projet créé avec succès.

## Conflits et validation {/* #conflicts-and-validation */}

- `--empty` et `--template` ne peuvent pas être utilisés ensemble.
- `--llm` et `--llm-api-key` sont valides uniquement pour le projet utilisant le starter par défaut.
- Le nom du projet doit être un nom de répertoire unique, sûr et en minuscules, et la cible ne doit pas déjà exister.

Les entrées non valides sont rejetées avant que les modèles soient récupérés ou que des fichiers soient créés.

## Télémétrie {/* #telemetry */}

Mastra collecte des informations anonymes sur l’utilisation de la CLI, telles que le système d’exploitation, la version de Mastra et la version de Node.js. Vous pouvez consulter le [code source des analyses](https://github.com/mastra-ai/mastra/blob/main/packages/cli/src/analytics/index.ts).

Définissez `MASTRA_TELEMETRY_DISABLED=1` pour désactiver cette collecte :

```bash
MASTRA_TELEMETRY_DISABLED=1 npx create-mastra@latest my-project --empty
```
