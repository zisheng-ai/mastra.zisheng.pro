# Session

:::experimental

The `AgentController` feature est dans beta stage et subject à breaking changes dans minor versions until it graduates depuis its beta status.

:::

Un `Session` est the isolated runtime pour un resource et facultatif scope. It owns its event bus, thread binding, state, mode et modèle selections, exécute control, approvals, suspensions, follow-ups, et affiche state. The [AgentController class](/reference/agent-controller/agent-controller-class) supplies shared agents, configuration, storage, workspaces, et services.

Créer sessions via `controller.createSession()`. Direct construction et controller wiring methods aren't application APIs.

For a conceptual introduction, see the [AgentController overview](/docs/harness/agent-controller).

## Exemple d’utilisation

Les éléments suivants example uses the pris en charge controller-to-session flow.

```typescript
await controller.init()

const session = await controller.createSession({ resourceId: 'project-42' })
const unsubscribe = session.subscribe(event => {
  if (event.type === 'display_state_changed') {
    render(event.displayState)
  }
})

await session.sendMessage({ content: 'Review the current project.' })
unsubscribe()
```

## Méthodes

### Identity et events

#### `getTags()`

Renvoyer a copy de the tags supplied when the session était created.

```typescript
const tags = session.getTags()
```

Renvoie: `Record<string, string>`

#### `subscribe(listener)`

Subscribe à this session's isolated event bus. La méthode returns an unsubscribe function.

```typescript
const unsubscribe = session.subscribe(event => {
  console.log(event.type)
})

unsubscribe()
```

Renvoie: `() => void`

### Messages et exécute control

#### `sendMessage({ content, files?, requestContext? })`

Envoyer a utilisateur message. The session creates a thread premier when aucun thread est active.

```typescript
await session.sendMessage({
  content: 'Summarize this file.',
  files: [{ data: fileContents, mediaType: 'text/plain', filename: 'notes.txt' }],
})
```

#### `steer({ content, requestContext? })`

Queue steering content dans an active run.

```typescript
await session.steer({ content: 'Focus on the failing tests.' })
```

#### `followUp({ content, requestContext? })`

Queue a follow-up tandis que a exécute est active, ou envoie it immediately tandis que idle.

```typescript
await session.followUp({ content: 'Then propose a fix.' })
```

#### `getCurrentRunId()`

Renvoyer the active stream exécute identifier, the tracked exécute identifier, ou `null` tandis que idle.

```typescript
const runId = session.getCurrentRunId()
```

Renvoie: `string | null`

#### `abort()`

Abort the active exécute et clear pending suspension affiche state.

```typescript
session.abort()
```

### Workspace

#### `getWorkspace()`

Renvoyer the workspace resolved pour this session. Ce preserves session-level overrides et workspaces sélectionné depuis the session scope.

```typescript
const workspace = session.getWorkspace()
const skill = await workspace.skills?.get('code-review')
```

Renvoie: `Workspace`

### Session grants

Session-scoped grants auto-approve tools sans prompting. Grants sont ephemeral: they reset when the session restarts et sont never persisted.

#### `grantCategory(category)`

Grant a Tool category pour the actuel session. Tools dans this category sont auto-approved.

```typescript
session.grantCategory('edit')
```

#### `grantTool(toolName)`

Grant a specific Tool pour the actuel session.

```typescript
session.grantTool('mastra_workspace_execute_command')
```

#### `getGrants()`

Renvoyer the currently granted categories et tools.

```typescript
const grants = session.getGrants()
// { categories: string[], tools: string[] }
```

#### `hasCategoryGrant(category)`

Renvoyer whether a category possède an in-memory session grant.

```typescript
const allowed = session.hasCategoryGrant('edit')
```

Renvoie: `boolean`

#### `hasToolGrant(toolName)`

Renvoyer whether a Tool possède an in-memory session grant.

```typescript
const allowed = session.hasToolGrant('write_file')
```

Renvoie: `boolean`

### Tool approvals

#### `resolveToolApproval(toolName)`

Renvoyer the effective policy après applying explicit Tool rules, session grants, et category rules.

```typescript
const policy = session.resolveToolApproval('execute_command')
```

Renvoie: `PermissionPolicy`

#### `respondToToolApproval({ decision, toolCallId?, requestContext?, declineContext? })`

Respond à a pending Tool approval request, raised par a `tool_approval_required` event. Pass `always_allow_category` à also grant the tool's whole category pour the rest de the session.

```typescript
session.respondToToolApproval({ decision: 'approve' })
session.respondToToolApproval({ decision: 'decline' })
session.respondToToolApproval({ decision: 'always_allow_category' })
```

#### `respondToToolSuspension({ resumeData, toolCallId?, requestContext? })`

Resume a suspended Tool avec application-provided data. Supply `toolCallId` when several Tool calls sont suspended.

```typescript
await session.respondToToolSuspension({
  toolCallId: event.toolCallId,
  resumeData: ['src'],
})
```

For `submit_plan`, transmet `{ action: 'approved' }` ou `{ action: 'rejected', feedback }`. Approval peut switch à the mode configuré par `transitionsTo` avant the Tool resumes.

### Token usage

#### `getTokenUsage()`

Renvoyer a copy de the running token-usage tally pour the active thread.

```typescript
const usage = session.getTokenUsage()
// { promptTokens, completionTokens, totalTokens, ... }
```

## Identity

`session.identity` owns the stable identifiers pour the conversation: the resource ID, a session `id`, et an `ownerId`. The `id` et `ownerId` sont stable pour the life de the session et don't change when the resource ID est switched. They mirror the `id` et `ownerId` fields sur `SessionRecord` dans storage.

### `session.identity.getId()`

Renvoyer the stable session identifiant.

```typescript
const sessionId = session.identity.getId()
```

### `session.identity.getOwnerId()`

Renvoyer the stable owner identifiant pour the session.

```typescript
const ownerId = session.identity.getOwnerId()
```

### `session.identity.getResourceId()`

Renvoyer the actuel resource ID.

```typescript
const resourceId = session.identity.getResourceId()
```

### `session.identity.getDefaultResourceId()`

Renvoyer the resource ID the session était created with.

```typescript
const defaultResourceId = session.identity.getDefaultResourceId()
```

Pour modifier the resource ID, utilise [`controller.setResourceId()`](/reference/agent-controller/agent-controller-class#setresourceidsession--resourceid-), which also clears the active thread. The session `id` et `ownerId` aren't affected par resource switches.

## Thread

`session.thread` owns the active thread binding et resource-scoped thread operations. Stored threads et messages peut survive controller recreation when storage est configured. The live session et its event bus don't.

### `session.thread.create({ title?, id? })`

Créer a thread, bind the session à it, et open its event stream.

```typescript
const thread = await session.thread.create({
  id: 'thread-7',
  title: 'Investigate login failure',
})
```

Renvoie: `Promise<AgentControllerThread>`

### `session.thread.rename({ title })`

Rename the active stored thread.

```typescript
await session.thread.rename({ title: 'Fix login failure' })
```

### `session.thread.clone({ sourceThreadId?, title?, resourceId? })`

Clone an owned thread et its messages, then bind the session à the clone.

```typescript
const clone = await session.thread.clone({
  sourceThreadId: 'thread-7',
  title: 'Alternative approach',
})
```

Renvoie: `Promise<AgentControllerThread>`

### `session.thread.switch({ threadId, emitEvent? })`

Switch à an owned stored thread et hydrate its mode, model, et observational memory settings.

```typescript
await session.thread.switch({ threadId: 'thread-8' })
```

### `session.thread.delete({ threadId })`

Supprimer an owned thread. Deleting the active thread also clears the actuel binding.

```typescript
await session.thread.delete({ threadId: 'thread-8' })
```

### `session.thread.getId()`

Renvoyer the active thread ID, ou `null` when aucun thread est bound.

```typescript
const threadId = session.thread.getId()
```

### `session.thread.list(options?)`

Lister threads depuis storage. Par défaut only threads pour the actuel resource sont returned, et transient forked subagent threads sont hidden.

```typescript
const threads = await session.thread.list()
const allThreads = await session.thread.list({ allResources: true })
const everything = await session.thread.list({ includeForkedSubagents: true })
```

### `session.thread.getById({ threadId })`

Renvoyer a unique thread par ID, ou `null` if it doesn't exist.

```typescript
const thread = await session.thread.getById({ threadId: 'thread-abc123' })
```

### `session.thread.listActiveMessages(options?)`

Retrieve messages pour the active thread. Renvoie an vide tableau when aucun thread est bound.

```typescript
const messages = await session.thread.listActiveMessages({ limit: 50 })
```

### `session.thread.listMessages({ threadId, limit? })`

Retrieve messages pour a specific thread.

```typescript
const messages = await session.thread.listMessages({ threadId: 'thread-abc123' })
```

The message-reading methods `listActiveMessages`, `listMessages`, et `firstUserMessage` renvoie `MastraDBMessage` objects, tandis que `firstUserMessages` returns a `Map<string, MastraDBMessage>` keyed par thread ID. Chaque message possède a `role`, an `id`, a `createdAt`, et a `content` objet avec `content.format` et a `content.parts` array. Read text, reasoning, Tool calls, et attachments depuis `content.parts`. Signals such comme system reminders et notifications sont returned comme separate messages avec `role: 'signal'`.

### `session.thread.firstUserMessage({ threadId })`

Retrieve the premier utilisateur message pour a thread, ou `null` if none.

```typescript
const firstMsg = await session.thread.firstUserMessage({
  threadId: 'thread-abc123',
})
```

### `session.thread.firstUserMessages({ threadIds })`

Retrieve the premier utilisateur message pour many threads à once, returned comme a map.

```typescript
const firstByThread = await session.thread.firstUserMessages({
  threadIds: ['thread-a', 'thread-b'],
})
```

### `session.thread.getSetting({ key })`

Read a setting depuis the active thread metadata.

```typescript
const value = await session.thread.getSetting({ key: 'omThreshold' })
```

### `session.thread.setSetting({ key, value })`

Write a setting à the active thread metadata.

```typescript
await session.thread.setSetting({ key: 'omThreshold', value: 0.8 })
```

### `session.thread.deleteSetting({ key })`

Supprimer a setting depuis the active thread metadata.

```typescript
await session.thread.deleteSetting({ key: 'omThreshold' })
```

## Mode

`session.mode` owns the active mode selection.

### `session.mode.get()`

Renvoyer the active mode ID.

```typescript
const modeId = session.mode.get()
```

### `session.mode.resolve()`

Renvoyer the full `AgentControllerMode` objet pour the active mode, resolved against the controller's configuré modes.

```typescript
const mode = session.mode.resolve()
```

### `session.mode.switch({ modeId })`

Switch à un autre mode. The session saves the outgoing mode's modèle avant persisting the nouveau mode sur the active thread. It then restores the incoming mode's sélectionné ou par défaut model. The session emits `mode_changed` immediately et `model_changed` après modèle resolution.

```typescript
await session.mode.switch({ modeId: 'build' })
```

## Modèle

`session.model` owns the active modèle selection, including per-mode modèle memory.

### `session.model.get()`

Renvoyer the active modèle ID.

```typescript
const modelId = session.model.get()
```

### `session.model.displayName()`

Renvoyer the dernier segment de the active modèle ID comme a short affiche name. Renvoie `'unknown'` when aucun modèle est selected.

```typescript
const name = session.model.displayName()
```

### `session.model.hasSelection()`

Vérifier whether a modèle est currently selected.

```typescript
if (session.model.hasSelection()) {
  // Ready to send messages
}
```

### `session.model.switch({ modelId, scope?, modeId? })`

Switch the active model. When `scope` est `'thread'` (the default), the modèle ID est persisted comme the per-mode modèle so it's restored when switching back. Reports the selection à the controller's `modelUseCountTracker` et emits a `model_changed` event.

```typescript
// Set for the current session only
await session.model.switch({
  modelId: '__GATEWAY_ANTHROPIC_MODEL_SONNET__',
  scope: 'global',
})

// Persist to the current thread (default)
await session.model.switch({ modelId: '__GATEWAY_ANTHROPIC_MODEL_SONNET__' })
```

## Observational Mémoire

The observational-memory modèle selection, grouped par role under `session.om.observer` et `session.om.reflector`. Both roles expose the same methods. Reads renvoie the valeur depuis session state when set, falling back à the controller's `omConfig` defaults.

### `session.om.observer.modelId()` / `session.om.reflector.modelId()`

Renvoyer the role's modèle ID, ou `undefined` when neither session state nor `omConfig` provides one.

```typescript
const observer = session.om.observer.modelId()
const reflector = session.om.reflector.modelId()
```

### `session.om.observer.threshold()` / `session.om.reflector.threshold()`

Renvoyer the role's threshold dans tokens (observation threshold pour the observer, reflection threshold pour the reflector), ou `undefined` when unset.

```typescript
const observationThreshold = session.om.observer.threshold()
const reflectionThreshold = session.om.reflector.threshold()
```

### `session.om.observer.switchModel({ modelId })` / `session.om.reflector.switchModel({ modelId })`

Switch the role's model. Persists the setting à thread metadata et emits an `om_model_changed` event.

```typescript
await session.om.observer.switchModel({
  modelId: '__GATEWAY_ANTHROPIC_MODEL_HAIKU__',
})
await session.om.reflector.switchModel({
  modelId: '__GATEWAY_ANTHROPIC_MODEL_HAIKU__',
})
```

### `session.om.observer.resolvedModel()` / `session.om.reflector.resolvedModel()`

Resolve the role's modèle ID à a modèle instance via the configuré modèle gateways, ou `undefined` when aucun modèle ID est définit ou aucun resolver est configured.

```typescript
const observerModel = session.om.observer.resolvedModel()
const reflectorModel = session.om.reflector.resolvedModel()
```

## Autorisations

`session.permissions` owns the tool-approval policy represented dans `session.state`: the per-category et per-tool rules consulted during approval resolution. Ces sont distinct depuis the in-memory grants documented under [Session grants](#session-grants). Grants reset avec the live session. Permission rules aren't durable unless the host restores the corresponding session state.

### `session.permissions.getRules()`

Renvoyer the actuel permission rules, ou vide rules (`{ categories: {}, tools: {} }`) when none sont set.

```typescript
const rules = session.permissions.getRules()
// { categories: { execute: 'ask' }, tools: { dangerous_tool: 'deny' } }
```

### `session.permissions.setForCategory({ category, policy })`

Définir the approval policy (`'allow' | 'ask' | 'deny'`) pour a Tool category. Resolves once the change est persisted à session state.

```typescript
await session.permissions.setForCategory({ category: 'execute', policy: 'ask' })
```

### `session.permissions.setForTool({ toolName, policy })`

Définir the approval policy pour a specific tool. Per-tool policies take precedence over category policies. Resolves once persisted.

```typescript
await session.permissions.setForTool({ toolName: 'dangerous_tool', policy: 'deny' })
```

## Subagents

`session.subagents` owns subagent configuration. It currently exposes the subagent modèle selection under `session.subagents.model`.

### `session.subagents.model.get({ agentType? })`

Renvoyer the subagent modèle ID, preferring the per-`agentType` valeur when un est given, then the global subagent model, ou `null` when neither est set.

```typescript
const modelId = session.subagents.model.get({ agentType: 'explore' })
```

### `session.subagents.model.set({ modelId, agentType? })`

Définir the subagent modèle ID. Pass an `agentType` à définit a per-type override, ou omit it à définit the global default. Persists à thread settings et emits a `subagent_model_changed` event.

```typescript
// Set the global subagent model
await session.subagents.model.set({ modelId: '__GATEWAY_ANTHROPIC_MODEL_SONNET__' })

// Set a per-type override
await session.subagents.model.set({
  modelId: '__GATEWAY_ANTHROPIC_MODEL_HAIKU__',
  agentType: 'explore',
})
```

## Run

`session.run` owns exécute et trace identity plus abort state pour the in-flight run.

### `session.run.getRunId()` / `getTraceId()`

Renvoyer the stored exécute ID et trace ID pour the actuel run, ou `null` when idle.

```typescript
const runId = session.run.getRunId()
const traceId = session.run.getTraceId()
```

### `session.run.isRunning()`

Renvoyer whether a exécute est currently dans progress.

```typescript
if (session.run.isRunning()) {
  // A run is active
}
```

## Flux

`session.stream` owns the live subscription à the agent thread stream et its dedup key.

### `session.stream.activeRunId()`

Renvoyer the exécute ID active sur the live stream, ou `null` when aucun stream est open.

```typescript
const runId = session.stream.activeRunId()
```

### `session.stream.isActive()`

Renvoyer whether the stream currently possède an active run.

```typescript
if (session.stream.isActive()) {
  // The current thread's stream is producing output
}
```

## Suspensions

`session.suspensions` owns parked interactive Tool calls (such comme `ask_user` et `request_access`) awaiting a resume.

### `session.suspensions.hasPending()`

Renvoyer whether tout Tool est currently suspended.

```typescript
if (session.suspensions.hasPending()) {
  // At least one interactive tool is waiting for a response
}
```

### `session.suspensions.has({ toolCallId })`

Renvoyer whether a specific Tool call est suspended.

```typescript
const waiting = session.suspensions.has({ toolCallId: event.toolCallId })
```

Resume a suspended Tool avec [`session.respondToToolApproval()`](#tool-approvals).

## Follow-ups

`session.followUps` owns the FIFO queue de messages submitted tandis que a exécute est dans progress.

### `session.followUps.count()`

Renvoyer the nombre de queued follow-ups.

```typescript
const queued = session.followUps.count()
```

### `session.followUps.isEmpty()`

Renvoyer whether the follow-up queue est empty.

```typescript
if (!session.followUps.isEmpty()) {
  // Messages are waiting to be processed
}
```

## Approval

`session.approval` owns the pending tool-approval gate.

### `session.approval.isArmed()`

Renvoyer whether a Tool est currently awaiting an approval decision.

```typescript
if (session.approval.isArmed()) {
  // Show the approval prompt
}
```

Respond avec [`session.respondToToolApproval()`](#tool-approvals).

## Display state

`session.displayState` owns the canonical `AgentControllerDisplayState` snapshot a UI renders from, et the reducer that keeps it dans sync avec every session event.

### `session.displayState.get()`

Renvoyer the actuel `AgentControllerDisplayState` snapshot pour UI rendering.

```typescript
const displayState = session.displayState.get()
```

### `session.displayState.restoreTasks(tasks)`

Restore the task portion de the snapshot après a UI replays persisted task Tool history. Ce est a pure met à jour de the snapshot et doesn't emit an event, so re-render explicitly après calling it.

```typescript
session.displayState.restoreTasks(replayedTasks)
```

After every event, the session emits `display_state_changed` avec the latest snapshot. Subscribe avec [`session.subscribe()`](#identity-and-events) ou read the actuel valeur depuis `session.displayState.get()`.

## État

`session.state` owns the schema-validated AgentController state pour the conversation. It holds the actuel snapshot et validates updates against the `stateSchema` passed à the AgentController. Met à jour sont serialized, et every change emits a `state_changed` event.

### `session.state.get()`

Renvoyer a readonly copy de the actuel state snapshot.

```typescript
const state = session.state.get()
```

### `session.state.set(updates)`

Merge a partial met à jour dans the state. Met à jour sont queued so concurrent calls apply dans order, validated against the schema, et emit `state_changed` avec the changed keys.

```typescript
await session.state.set({ yolo: true })
```

### `session.state.update(updater)`

Exécuter an updater against the actuel snapshot et apply its résultat atomically within the write queue. Utilisez ce pour read-modify-write changes that doit see the latest state. The updater returns `updates` à merge, facultatif `events` à emit, et a `result` valeur that `update()` resolves to.

```typescript
const added = await session.state.update(current => ({
  updates: { count: (current.count ?? 0) + 1 },
  result: (current.count ?? 0) + 1,
}))
```

## Persistence boundaries

Un `Session` est a live runtime object. Its event bus, arbitrary `session.state`, permission rules, permission grants, pending approvals, suspensions, follow-ups, exécute state, et stream state don't automatically survive controller ou traite recreation. The host doit restore tout de this state when recreating a session.

With configuré storage, threads, messages, et token usage persist. Thread settings restore mode et modèle choices. They peut also restore observational memory settings et subagent modèle selections, including per-agent-type overrides. Un chat channel peut mappe back à stored threads, mais channel-to-session et auto-approval state held par `AgentControllerChannels` remains dans memory.
