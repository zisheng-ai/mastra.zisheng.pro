# Workflows API

The Workflows API provides methods à interact avec et exécute automated workflows dans Mastra.

## Getting tous les workflows

Retrieve a liste de tous les disponible workflows:

```typescript
const workflows = await mastraClient.listWorkflows()
```

## Getting Workflow exécute counts

Retrieve per-workflow counts de `running` et [`suspended`](/docs/workflows/suspend-and-resume) runs dans a unique request. The counts sont computed sur the server et keyed par the workflow's registry clé — the clé used when registering the Workflow dans the Mastra config, which peut differ depuis the workflow's own `id`:

```typescript
const runCounts = await mastraClient.listWorkflowRunCounts()
// { "cityWorkflow": { running: 2, suspended: 1 }, ... }
```

Renvoie: `Record<string, { running: number; suspended: number }>`

The server peut cache the counts pour a few seconds entre requests. Serveurs that predate this endpoint respond avec `404 Not Found` — gère the error when the client peut talk à older deployments.

## Working avec a specific workflow

Obtenir an instance de a specific Workflow par its ID:

```typescript title="src/mastra/workflows/test-workflow.ts"
export const testWorkflow = createWorkflow({
  id: 'city-workflow',
})
```

```typescript
const workflow = mastraClient.getWorkflow('city-workflow')
```

## Workflow methods

### `details()`

Retrieve detailed information concernant a workflow:

```typescript
const details = await workflow.details()
```

### `createRun()`

Créer a nouveau Workflow exécute instance:

```typescript
const run = await workflow.createRun()

// Or with an existing runId
const run = await workflow.createRun({ runId: 'existing-run-id' })

// Or with a resourceId to associate the run with a specific resource
const run = await workflow.createRun({
  runId: 'my-run-id',
  resourceId: 'user-123',
})
```

The `resourceId` paramètre associates the Workflow exécute avec a specific resource (e.g., utilisateur ID, tenant ID). Ce valeur est persisted avec the exécute et peut be used pour filtering et querying runs later.

### `startAsync()`

Démarrer a Workflow exécute et await its completion, returning the full résultat comme the Workflow output.

```typescript
const run = await workflow.createRun()

const result = await run.startAsync({
  inputData: {
    city: 'New York',
  },
})
```

Vous pouvez également transmet `initialState` à définit the starting values pour the workflow's state:

```typescript
const result = await run.startAsync({
  inputData: {
    city: 'New York',
  },
  initialState: {
    count: 0,
    items: [],
  },
})
```

The `initialState` objet doit match the structure defined dans the workflow's `stateSchema`. Consultez [Workflow État](/docs/workflows/workflow-state) pour more details.

To associate a exécute avec a specific resource, transmet `resourceId` à `createRun()`:

```typescript
const run = await workflow.createRun({ resourceId: 'user-123' })

const result = await run.startAsync({
  inputData: {
    city: 'New York',
  },
})
```

### `start()`

Démarrer a Workflow exécute sans waiting pour completion (fire-and-forget). Renvoie immediately avec a success message. Use `runById()` sur the Workflow instance à check results later:

```typescript
const run = await workflow.createRun()

await run.start({
  inputData: {
    city: 'New York',
  },
})

// Poll for results later
const result = await workflow.runById(run.runId)
```

Ce est useful pour long-running workflows where you want à démarre execution et check results later.

### `resumeAsync()`

Resume a suspended Workflow step et await the full result:

```typescript
const run = await workflow.createRun({ runId: prevRunId })

const result = await run.resumeAsync({
  step: 'step-id',
  resumeData: { key: 'value' },
})
```

### `resume()`

Resume a suspended Workflow step sans waiting pour completion:

```typescript
const run = await workflow.createRun({ runId: prevRunId })

await run.resume({
  step: 'step-id',
  resumeData: { key: 'value' },
})
```

Lorsqu’un [`.foreach()`](/reference/workflows/workflow-methods/foreach) step suspends across plusieurs iterations, transmet `forEachIndex` (zero-based. `0` targets the premier iteration) à resume un iteration à a time. Iterations you don't target remain suspended.

```typescript
await run.resume({
  step: 'approve',
  resumeData: { ok: true },
  forEachIndex: 1, // resumes the second iteration
})
```

`forEachIndex` est also pris en charge par `resumeAsync()` et `resumeStream()`.

### `cancel()`

Cancel a running workflow:

```typescript
const run = await workflow.createRun({ runId: existingRunId })

const result = await run.cancel()
// Returns: { message: 'Workflow run canceled' }
```

Ce method stops tout running steps et prevents subsequent steps depuis executing. Steps that check the `abortSignal` paramètre peut respond à cancellation par cleaning up resources (timeouts, network requests, etc.).

See the [Run.cancel()](/reference/workflows/run-methods/cancel) reference pour detailed information concernant how cancellation works et how à write steps that respond à cancellation.

### `stream()`

Flux Workflow execution pour real-time updates:

```typescript
const run = await workflow.createRun()

const stream = await run.stream({
  inputData: {
    city: 'New York',
  },
})

for await (const chunk of stream) {
  console.log(JSON.stringify(chunk, null, 2))
}
```

### `runById()`

Obtenir the execution résultat pour a Workflow run:

```typescript
const result = await workflow.runById(runId)

// Or with options for performance optimization:
const result = await workflow.runById(runId, {
  fields: ['status', 'result'], // Only fetch specific fields
  withNestedWorkflows: false, // Skip expensive nested workflow data
  requestContext: { userId: 'user-123' }, // Optional request context
})
```

## Dynamique workflows

:::experimental

Dynamique workflows sont dans beta. Breaking changes peut occur sans a major version bump until the API est stable.

:::

Dynamique workflows sont Workflow definitions expressed comme JSON. The server persists chaque definition et registers it comme a runnable workflow. Consultez [Dynamique workflows](/docs/workflows/dynamic-workflows) pour the definition format.

### `listDynamicWorkflows()`

Lister dynamic Workflow definitions, optionally filtered par `status` (`'active' | 'archived'`) et `authorId`:

```typescript
const { definitions, total } = await mastraClient.listDynamicWorkflows({
  status: 'active',
})
```

### `upsertDynamicWorkflow()`

Créer ou replace a dynamic Workflow definition. The server validates the definition, persists it, et live-registers it pour execution:

```typescript
const stored = await mastraClient.upsertDynamicWorkflow({
  id: 'greeting-workflow',
  description: 'Returns a greeting for the supplied name',
  inputSchema: {
    type: 'object',
    properties: { name: { type: 'string' } },
    required: ['name'],
  },
  outputSchema: {
    type: 'object',
    properties: { message: { type: 'string' } },
    required: ['message'],
  },
  graph: [
    {
      type: 'mapping',
      id: 'create-greeting',
      mapConfig: JSON.stringify({
        message: { template: 'Hello, ${initData.name}!' },
      }),
    },
  ],
})
```

Lorsque le root definition nests helper workflows that don't exist yet, transmet them dans the same requête via `dependencies`. The server validates et registers the bundle comme a unit et echoes the helper ids back comme `dependencyIds`:

```typescript
const stored = await mastraClient.upsertDynamicWorkflow({
  id: 'root-workflow',
  // ...schemas and graph referencing 'helper-workflow'...
  dependencies: [helperDefinition],
})

console.log(stored.dependencyIds) // ['helper-workflow']
```

### `getDynamicWorkflow()`

Obtenir a dynamic Workflow instance pour definition management. To exécute a dynamic workflow, utilise `getWorkflow(id).createRun()` like tout autre workflow:

```typescript
const dynamicWorkflow = mastraClient.getDynamicWorkflow('greeting-workflow')
```

### `dynamicWorkflow.details()`

Retrieve the persisted definition, including schemas, graph, status, et timestamps:

```typescript
const definition = await dynamicWorkflow.details()
```

### `dynamicWorkflow.delete()`

Supprimer the stored definition et unregister the live workflow:

```typescript
await dynamicWorkflow.delete()
```

### Executing a dynamic workflow

Once registered, a dynamic Workflow runs via the ordinary Workflow API:

```typescript
const workflow = mastraClient.getWorkflow('greeting-workflow')
const run = await workflow.createRun()
const result = await run.startAsync({ inputData: { name: 'Ada' } })
```

## Schedules

Schedules sont declared dans code via the `schedule` field sur `createWorkflow`. The client SDK exposes read et operational methods pour managing Workflow schedules à runtime. Consultez [Scheduled workflows](/docs/workflows/scheduled-workflows).

### `createSchedule()`

Créer a Workflow schedule par passing `workflowId`.

```typescript
const schedule = await mastraClient.createSchedule({
  workflowId: 'daily-report',
  cron: '0 9 * * *',
  inputData: { reportType: 'summary' },
})
```

### `listSchedules()`

Lister Workflow schedules, optionally filtered par Workflow ID ou status.

```typescript
const schedules = await mastraClient.listSchedules({
  workflowId: 'daily-report',
  status: 'active',
})
```

### `getSchedule()`

Fetch a unique Workflow schedule par ID.

```typescript
const schedule = await mastraClient.getSchedule('daily-report')
```

### `updateSchedule()`

Mettre à jour a Workflow schedule.

```typescript
const updated = await mastraClient.updateSchedule('daily-report', {
  cron: '0 10 * * *',
  inputData: { reportType: 'summary' },
})
```

### `deleteSchedule()`

Supprimer a Workflow schedule.

```typescript
await mastraClient.deleteSchedule('daily-report')
```

### `runSchedule()`

Fire a Workflow schedule once immediately sans changing its cron cadence.

```typescript
const run = await mastraClient.runSchedule('daily-report')
```

### `pauseSchedule()`

Pause a schedule so the scheduler stops firing it. Renvoie the updated schedule.

```typescript
await mastraClient.pauseSchedule('daily-report')
```

### `resumeSchedule()`

Resume a paused schedule. The next fire time est recomputed depuis now, so a long-paused schedule doesn't fire a backlog. Renvoie the updated schedule.

```typescript
await mastraClient.resumeSchedule('daily-report')
```

### `listScheduleTriggers()`

Lister the trigger history pour a Workflow schedule, including the joined exécute summary pour chaque fire.

```typescript
const { triggers } = await mastraClient.listScheduleTriggers('daily-report', {
  limit: 50,
})
```
