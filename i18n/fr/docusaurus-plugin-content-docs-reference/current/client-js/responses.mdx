# OpenAI Réponses API

Ce OpenAI-compatible, agent-backed interface lets you utilise Mastra Agents comme a Réponses API. It provides methods à create, retrieve, stream, et supprime responses via Mastra agents.

Ces routes sont agent-backed adapters over Mastra agents, memory, et storage. Use `agent_id` à select the Mastra agent that doit gère the request. Vous pouvez transmet `model` à override the agent's configuré modèle pour a unique request, ou omit it à utilise the modèle already configuré sur the agent.

Stored responses also renvoie `conversation_id`. In Mastra, this est the raw memory `threadId`.

Ce API est currently experimental.

## Exemple d’utilisation

```typescript
import { MastraClient } from '@mastra/client-js'

const client = new MastraClient({
  baseUrl: 'http://localhost:4111',
})

const response = await client.responses.create({
  agent_id: 'support-agent',
  input: 'Summarize this ticket',
  store: true,
})

console.log(response.output_text)
```

## Méthodes

### Lifecycle

#### `create(params)`

Crée a response.

```typescript
const response = await client.responses.create({
  agent_id: 'support-agent',
  input: 'Summarize this ticket',
})
```

**Renvoie:** `Promise<ResponsesResponse>` when `stream` est omitted ou `false`.

When `stream: true`, `create()` returns an async iterable de SSE-style event payloads:

```typescript
const stream = await client.responses.create({
  agent_id: 'support-agent',
  input: 'Summarize this ticket',
  stream: true,
})

for await (const event of stream) {
  if (event.type === 'response.output_text.delta') {
    process.stdout.write(event.delta)
  }
}
```

Fluxing responses peut also inclut Tool events. Tool-call streams utilise `response.output_item.added`, `response.function_call_arguments.delta`, `response.function_call_arguments.done`, et `response.output_item.done` events. Tool results appear comme `function_call_output` items avec `<toolCallId>:output` IDs.

**Renvoie:** `Promise<ResponsesStream>`.

#### `retrieve(responseId, requestContext?)`

Retrieves a stored response.

```typescript
const response = await client.responses.retrieve('msg_123')
```

**Renvoie:** `Promise<ResponsesResponse>`.

#### `delete(responseId, requestContext?)`

Supprime a stored response.

```typescript
const deleted = await client.responses.delete('msg_123')
```

**Renvoie:** `Promise<{ id: string; object: "response"; deleted: true }>`

#### `stream(params)`

Crée a streaming response.

```typescript
const stream = await client.responses.stream({
  agent_id: 'support-agent',
  input: 'Say hello',
})

for await (const event of stream) {
  console.log(event.type)
}
```

**Renvoie:** `Promise<ResponsesStream>`.

## Stored responses et conversations

Stored responses inclut both `response.id` et `conversation_id`.

- `response.id` est the réponse ID. For stored agent-backed responses, this est the persisted assistant message ID.
- `conversation_id` est the raw Mastra thread ID.

Use `previous_response_id` when you want à continue depuis a previous stored response. Use `conversation_id` when you want à target a known thread directly.

```typescript
const first = await client.responses.create({
  agent_id: 'support-agent',
  input: 'Start a support thread',
  store: true,
})

const second = await client.responses.create({
  agent_id: 'support-agent',
  conversation_id: first.conversation_id!,
  input: 'Add a follow-up to the same thread',
  store: true,
})
```

Use [`client.conversations`](/reference/client-js/conversations) when you want à create, retrieve, delete, ou inspect the underlying OpenAI Réponses API conversation directly.

## Function calling (tools)

`response.tools` contains the configuré fonction definitions disponible pour the request.

Si le modèle calls a function, that activity est included dans `response.output` comme `function_call` et `function_call_output` items alongside the final assistant `message`.

When `stream: true`, fonction calls sont also emitted comme Réponses stream events. Read `response.function_call_arguments.delta` events pour partial argument chunks et prefer `response.function_call_arguments.done` pour the finalized arguments payload et Tool name. Read `response.output_item.done` events pour completed `function_call` et `function_call_output` items. Tool output items utilise `<toolCallId>:output` IDs.

## Structured output

Use `text.format` when you want JSON output.

- `json_object` enables JSON mode.
- `json_schema` enables schema-constrained structured output.

Both formats renvoie JSON dans the assistant message content. Use `json_schema` when you need strict schema enforcement. Use `json_object` when you only need valid JSON output.

```typescript
const response = await client.responses.create({
  agent_id: 'support-agent',
  input: 'Return a structured support ticket summary.',
  text: {
    format: {
      type: 'json_schema',
      name: 'ticket_summary',
      schema: {
        type: 'object',
        properties: {
          summary: { type: 'string' },
          priority: { type: 'string' },
        },
        required: ['summary', 'priority'],
        additionalProperties: false,
      },
    },
  },
})
```

## Fournisseur-backed requests

Use `providerOptions` when you need provider-specific options that Mastra doesn't normalize à the Réponses layer.

```typescript
const response = await client.responses.create({
  agent_id: 'support-agent',
  input: 'Continue this exchange',
  providerOptions: {
    openai: {
      previousResponseId: 'resp_123',
    },
  },
})
```

## Réponse shape

La valeur renvoyée réponse objet includes:

- `id`: La réponse ID
- `output`: Sortie items such comme the assistant `message`, `function_call`, et `function_call_output`
- `output_text`: Convenience getter that joins assistant text output
- `tools`: Configured Tool definitions pour the request
- `conversation_id`: The raw thread ID pour stored responses
- `text`: La requêteed text output format, when provided
