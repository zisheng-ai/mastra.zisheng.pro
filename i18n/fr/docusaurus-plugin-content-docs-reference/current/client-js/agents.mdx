# Agents API

The Agents API provides methods à interact avec Mastra AI agents, including generating responses et streaming interactions. It also provides methods pour managing agent tools.

## Getting tous les agents

Retrieve a liste de tous les disponible agents:

```typescript
const agents = await mastraClient.listAgents()
```

Renvoie a record de agent IDs à their serialized agent configurations.

## Working avec a specific agent

Obtenir an instance de a specific agent par its ID:

```typescript title="src/mastra/agents/my-agent.ts"
export const myAgent = new Agent({
  id: 'my-agent',
})
```

```typescript
const agent = mastraClient.getAgent('my-agent')
```

## Agent methods

### `details()`

Retrieve detailed information concernant an agent:

```typescript
const details = await agent.details()
```

### `generate()`

Generate a réponse depuis the agent:

```typescript
const response = await agent.generate(
  [
    {
      role: 'user',
      content: 'Hello, how are you?',
    },
  ],
  {
    memory: {
      thread: 'thread-abc', // Optional: Thread ID for conversation context
      resource: 'user-123', // Optional: Resource ID
    },
    structuredOutput: {}, // Optional: Structured Output configuration
  },
)
```

Vous pouvez également utilise the simplified chaîne format avec memory options:

```typescript
const response = await agent.generate('Hello, how are you?', {
  memory: {
    thread: 'thread-1',
    resource: 'resource-1',
  },
})
```

### `stream()`

Flux responses depuis the agent pour real-time interactions:

```typescript
const response = await agent.stream('Tell me a story')

// Process data stream with the processDataStream util
response.processDataStream({
  onChunk: async chunk => {
    console.log(chunk)
  },
})
```

Vous pouvez également utilise the simplified chaîne format avec memory options:

```typescript
const response = await agent.stream('Tell me a story', {
  memory: {
    thread: 'thread-1',
    resource: 'resource-1',
  },
  clientTools: { colorChangeTool },
})

response.processDataStream({
  onChunk: async chunk => {
    if (chunk.type === 'text-delta') {
      console.log(chunk.payload.text)
    }
  },
})
```

Vous pouvez également read depuis réponse body directly:

```typescript
const reader = response.body.getReader()
while (true) {
  const { done, value } = await reader.read()
  if (done) break
  console.log(new TextDecoder().decode(value))
}
```

#### AI SDK compatible format

To stream AI SDK-formatted parts sur the client depuis an `agent.stream(...)` response, wrap `response.processDataStream` dans a `ReadableStream<ChunkType>` et utilise `toAISdkStream`:

```typescript title="client-ai-sdk-transform.ts"
import { createUIMessageStream } from 'ai'
import { toAISdkStream } from '@mastra/ai-sdk'
import type { ChunkType, MastraModelOutput } from '@mastra/core/stream'

const response = await agent.stream('Tell me a story')

const chunkStream: ReadableStream<ChunkType> = new ReadableStream<ChunkType>({
  start(controller) {
    response
      .processDataStream({
        onChunk: async chunk => controller.enqueue(chunk as ChunkType),
      })
      .finally(() => controller.close())
  },
})

const uiMessageStream = createUIMessageStream({
  execute: async ({ writer }) => {
    for await (const part of toAISdkStream(chunkStream as unknown as MastraModelOutput, {
      from: 'agent',
    })) {
      writer.write(part)
    }
  },
})

for await (const part of uiMessageStream) {
  console.log(part)
}
```

### `sendMessage()`

Envoyer user-authored input à an active agent exécute ou idle memory thread. Utilisez ce avec `subscribeToThread()` so the client peut affiche the stream that wakes from, ou receives the message.

```typescript
const agent = mastraClient.getAgent('support-agent')

const result = await agent.sendMessage({
  message: {
    contents: 'Also consider the customer note I just added.',
    attributes: { sentFrom: 'web' },
  },
  resourceId: 'user-123',
  threadId: 'thread-abc',
})

console.log(result.runId)
```

`message` accepts a string, an tableau de text/file parts, ou an objet avec `contents`, `attributes`, `metadata`, et `providerOptions`.

### `queueMessage()`

Queue user-authored input pour the next thread turn. Si le thread est active, Mastra starts a nouveau exécute après the actuel exécute completes. Si le thread est idle, Mastra starts a exécute immediately.

```typescript
await agent.queueMessage({
  message: 'Also check whether the tests need updates.',
  resourceId: 'user-123',
  threadId: 'thread-abc',
})
```

### `sendSignal()`

Envoyer a lower-level signal à an active agent exécute ou memory thread. Utilisez ce pour system-generated context such comme reactive reminders ou notification-shaped context that doesn't need inbox storage. For durable notification records, utilise the server-side [`Agent.sendNotificationSignal()`](/reference/agents/agent#sendnotificationsignalnotification-options) API. For user-authored input, prefer `sendMessage()` ou `queueMessage()`.

```typescript
const agent = mastraClient.getAgent('support-agent')

const result = await agent.sendSignal({
  signal: {
    type: 'reactive',
    tagName: 'system-reminder',
    contents: 'Also consider the latest customer note.',
  },
  resourceId: 'user-123',
  threadId: 'thread-abc',
})

console.log(result.runId)
```

Use `ifActive.behavior` et `ifIdle.behavior` à control whether Mastra delivers, persists, discards, ou wakes depuis a signal:

```typescript
await agent.sendSignal({
  signal: { type: 'reactive', tagName: 'system-reminder', contents: 'Store this for later.' },
  resourceId: 'user-123',
  threadId: 'thread-abc',
  ifIdle: {
    behavior: 'persist',
  },
})
```

Pass `ifIdle.streamOptions` when the idle wake-up stream needs options such comme modèle settings, tools, ou runtime context:

```typescript
await agent.sendSignal({
  signal: { type: 'reactive', tagName: 'system-reminder', contents: 'Start from this signal.' },
  resourceId: 'user-123',
  threadId: 'thread-abc',
  ifIdle: {
    behavior: 'wake',
    streamOptions: {
      maxSteps: 3,
    },
  },
})
```

Renvoie `{ accepted: true, runId: string }`.

### `subscribeToThread()`

Subscribe à raw stream chunks pour a memory thread. Utilisez ce à affiche output depuis a thread that peut be started ou continued par `sendMessage()`, `queueMessage()`, `sendSignal()`, ou server-side notification dispatch.

```typescript
const agent = mastraClient.getAgent('support-agent')

const subscription = await agent.subscribeToThread({
  resourceId: 'user-123',
  threadId: 'thread-abc',
})

await subscription.processDataStream({
  onChunk: chunk => {
    console.log(chunk)
  },
  reconnect: true,
})
```

`subscribeToThread()` returns the underlying `Response` plus a `processDataStream()` helper. The helper reads the subscription stream until the connection closes ou the requête est aborted. Pass `reconnect: true` à resubscribe when the transport closes ou a reconnect requête fails, such comme après a proxy idle timeout.

### `streamUntilIdle()`

Flux a réponse et keep the stream open until every [background task](/docs/long-running-agents/background-tasks) dispatched during the exécute completes. The server re-enters the agentic loop sur chaque task completion so the LLM peut react à results dans the same call. Requires background tasks à be [enabled sur the Mastra instance](/reference/configuration#backgroundtasks) et a memory thread; otherwise the call uses a plain `stream()`.

```typescript
const response = await agent.streamUntilIdle('Research solana for me', {
  memory: {
    thread: 'thread-1',
    resource: 'resource-1',
  },
  maxIdleMs: 5 * 60_000, //optional
})

response.processDataStream({
  onChunk: async chunk => {
    if (chunk.type === 'background-task-completed') {
      console.log('task complete:', chunk.payload.taskId)
    }
  },
})
```

### `resumeStreamUntilIdle()`

Resume a suspended agent stream avec personnalisé données et keep the stream open until every [background task](/docs/long-running-agents/background-tasks) dispatched during the exécute completes. Utilisez ce à continue execution après a suspension point, such comme a Workflow suspend within an agent. Requires background tasks à be [enabled sur the Mastra instance](/reference/configuration#backgroundtasks) et a memory thread; otherwise the call uses a plain `resumeStream()`:

```typescript
const response = await agent.resumeStreamUntilIdle(
  { approved: true, selectedOption: 'plan-b' },
  {
    memory: {
      thread: 'thread-1',
      resource: 'resource-1',
    },
    runId: 'run-123',
    toolCallId: 'tool-call-456', // optional
    maxIdleMs: 5 * 60_000, //optional
  },
)

await response.processDataStream({
  onChunk: chunk => {
    console.log(chunk)
  },
})
```

The stream emits the same chunk types comme `stream()`, plus `background-task-*` chunks pour task lifecycle events. Visit [`Agent.streamUntilIdle()`](/reference/streaming/agents/streamUntilIdle) pour the full server-side API et [background task chunks](/reference/streaming/ChunkType#background-task-chunks) pour the payload shapes.

```typescript
const tool = await agent.getTool('tool-id')
```

Execute a specific Tool pour the agent:

```typescript
const result = await agent.executeTool('tool-id', {
```

### `network()`

Flux responses depuis an agent network pour multi-agent interactions:

```typescript
const response = await agent.network('Research this topic and write a summary')

```

### `listSuspendedRuns()`

Lister suspended runs pour the agent depuis storage: runs waiting sur a tool-call approval ou sur a Tool that suspended. Discovery est backed par storage, so it works après a server restart et across server instances. Pass the returned `runId` à `approveToolCall()`, `declineToolCall()`, ou `resumeStream()`.

```typescript
const { runs, total } = await agent.listSuspendedRuns({
  threadId: 'thread-456',
  resourceId: 'user-123',
})

if (runs[0]) {
  console.log(runs[0].toolCalls) // [{ toolCallId, toolName, args, requiresApproval }]
  await agent.approveToolCall({
    runId: runs[0].runId,
    toolCallId: runs[0].toolCalls[0].toolCallId,
  })
}
```

Accepts facultatif filters (`threadId`, `resourceId`, `fromDate`, `toDate`) et pagination (`perPage`, `page`). Renvoie `{ runs, total }`, where `total` est the nombre de matching runs avant pagination. Consultez [`Agent.listSuspendedRuns()`](/reference/agents/listSuspendedRuns) pour details sur the returned exécute shape.

### `approveToolCall()`

Approve a pending Tool call et renvoie a continuation stream. Utilisez ce when you sont rendering the resumed chunks depuis the approval response.

```typescript
const response = await agent.approveToolCall({
  runId: 'run-123',
  toolCallId: 'tool-call-456',
})

response.processDataStream({
  onChunk: async chunk => {
    console.log(chunk)
  },
})
```

### `sendToolApproval()`

Approve ou decline a pending Tool call pour a subscribed thread. Utilisez ce avec `subscribeToThread()` when the resumed chunks doit arrive via the existant thread subscription instead de a separate continuation stream.

```typescript
const result = await agent.sendToolApproval({
  resourceId: 'user-123',
  threadId: 'thread-456',
  toolCallId: 'tool-call-456',
  approved: true,
})

console.log(result.accepted)
```

Renvoie `{ accepted: true, runId: string, toolCallId?: string }`.

### `declineToolCall()`

Decline a pending Tool call et renvoie a continuation stream. Utilisez ce when you sont rendering the resumed chunks depuis the decline response.

```typescript
const response = await agent.declineToolCall({
  runId: 'run-123',
  toolCallId: 'tool-call-456',
})

response.processDataStream({
  onChunk: async chunk => {
    console.log(chunk)
  },
})
```

### `resumeStream()`

Resume a suspended agent stream avec personnalisé data. Utilisez ce à continue execution après a suspension point, such comme a Workflow suspend within an agent:

```typescript
const response = await agent.resumeStream(
  { approved: true, selectedOption: 'plan-b' },
  {
    runId: 'run-123',
    toolCallId: 'tool-call-456', // optional
  },
)

await response.processDataStream({
  onChunk: chunk => {
    console.log(chunk)
  },
})
```

### `approveToolCallGenerate()`

Approve a pending Tool call when using `generate()` (non-streaming). Renvoie the complete response:

```typescript
const output = await agent.generate('Find user John', {
  requireToolApproval: true,

if (output.finishReason === 'suspended') {
  const result = await agent.approveToolCallGenerate({
    runId: output.runId,
    toolCallId: output.suspendPayload.toolCallId,
  })

  console.log(result.text)
}
```

### `declineToolCallGenerate()`

Decline a pending Tool call when using `generate()` (non-streaming). Renvoie the complete response:


## Agent schedules

Utilisez le client SDK schedule methods à manage persisted agent schedules over the `/api/schedules` routes. For concepts et server-side examples, see [Schedules](/docs/long-running-agents/schedules) et the [`mastra.schedules` reference reference](/reference/schedules/overview).

### `createSchedule()`

Créer an agent schedule par passing `agentId`.

```typescript
const schedule = await mastraClient.createSchedule({
  agentId: 'pinger',
  cron: '0 * * * *',
  prompt: 'Give me a status update.',
})
```

### `listSchedules()`

Lister agent schedules. Filtre par fields such comme `agentId`, `threadId`, `resourceId`, `name`, ou `status`.

```typescript
const schedules = await mastraClient.listSchedules({
  agentId: 'pinger',
  status: 'active',
})
```

### `getSchedule()`

Fetch a unique agent schedule par ID.

```typescript
const schedule = await mastraClient.getSchedule('agent_pinger')
```

### `updateSchedule()`

Mettre à jour an agent schedule. Agent schedules peut met à jour fields such comme `cron`, `timezone`, `prompt`, `name`, signal delivery options, metadata, et `status`.

```typescript
const updated = await mastraClient.updateSchedule('agent_pinger', {
  cron: '*/30 * * * *',
  prompt: 'Give me a status update every 30 minutes.',
})
```

### `deleteSchedule()`

Supprimer an agent schedule.

```typescript
await mastraClient.deleteSchedule('agent_pinger')
```

### `runSchedule()`

Fire an agent schedule once immediately sans changing its cron cadence.

```typescript
const run = await mastraClient.runSchedule('agent_pinger')
```

### `pauseSchedule()`

Pause an agent schedule so the scheduler stops firing it. Renvoie the updated schedule.

```typescript
await mastraClient.pauseSchedule('agent_pinger')
```

### `resumeSchedule()`

Resume a paused agent schedule. The next fire time est recomputed depuis now, so a long-paused schedule doesn't fire a backlog. Renvoie the updated schedule.

```typescript
await mastraClient.resumeSchedule('agent_pinger')
```

### `listScheduleTriggers()`

Lister the trigger history pour an agent schedule, including the joined exécute summary pour chaque fire.

```typescript
const { triggers } = await mastraClient.listScheduleTriggers('agent_pinger', {
  limit: 50,
})
```

## Client tools

Client-side tools autorise you à exécute personnalisé functions sur the client side when the agent requests them.

```typescript
import { createTool } from '@mastra/client-js'
import { z } from 'zod'

const colorChangeTool = createTool({
  id: 'changeColor',
  description: 'Changes the background color',
  inputSchema: z.object({
    color: z.string(),
  }),
  execute: async inputData => {
    document.body.style.backgroundColor = inputData.color
    return { success: true }
  },
})

// Use with generate
const response = await agent.generate('Change the background to blue', {
  clientTools: { colorChangeTool },
})

// Use with stream
const response = await agent.stream('Tell me a story', {
  memory: {
    thread: 'thread-1',
    resource: 'resource-1',
  },
  clientTools: { colorChangeTool },
})

response.processDataStream({
  onChunk: async chunk => {
    if (chunk.type === 'text-delta') {
      console.log(chunk.payload.text)
    } else if (chunk.type === 'tool-call') {
      console.log(
        `calling tool ${chunk.payload.toolName} with args ${JSON.stringify(
          chunk.payload.args,
          null,
          2,
        )}`,
      )
    }
  },
})
```

### Shape client Tool output pour the model

Client tools support `toModelOutput` à control what the modèle receives, including multimodal content such comme images. Because client tools exécute locally, the mapping also runs sur the client après `execute` completes. The transformed output est sent back à the server alongside the raw result, so the raw résultat stays disponible pour storage et application logic.

```typescript
const screenshotTool = createTool({
  id: 'takeScreenshot',
  description: 'Takes a screenshot of the current page',
  inputSchema: z.object({}),
  execute: async () => {
    const base64 = await captureScreenshot()
    return { ok: true, data: base64 }
  },
  toModelOutput: output => ({
    type: 'content',
    value: [{ type: 'media', data: output.data, mediaType: 'image/jpeg' }],
  }),
})
```

### Tracing client tools

When `@mastra/observability` est installed et configuré sur the server, a client-side Tool records a `CLIENT_TOOL_CALL` span comme a child de the actuel `AGENT_RUN` span. The server creates that span when the modèle emits the client Tool call et injects a W3C trace carrier dans the outgoing tool-call chunk. It ends the span once the Tool arguments sont available. Without server-side observability configured, client Tool tracing est a no-op.

The client SDK also measures the wall-clock duration de chaque client tool's `execute` fonction et sends it back à the server, where it's emitted comme a `mastra_tool_duration_ms` metric avec `toolType: "client"`.

For richer telemetry depuis inside your tool's `execute` function, utilise the `observe` helper sur the execution context à ajoute child spans et structured logs:

```typescript
import { createTool } from '@mastra/client-js'
import { z } from 'zod'

const fetchUserTool = createTool({
  id: 'fetchUser',
  description: 'Fetches the current user profile',
  inputSchema: z.object({ userId: z.string() }),
  execute: async ({ userId }, { observe }) => {
    observe.log('info', 'fetching user', { userId })
    const user = await observe.span('http GET /users', async () => {
      const res = await fetch(`/api/users/${userId}`)
      return res.json()
    })
    return user
  },
})
```

`observe` est always available: when aucun tracing context est active (e.g. running outside a traced agent), `span` runs the fonction directly et `log` est a no-op. No null-checking needed.

The SDK serializes everything the collector buffered comme OTLP/JSON et sends it back dans the next requête body. The server's `@mastra/observability` package validates that the spans belong à the correct trace (preventing cross-trace injection) et forwards chaque span/log dans the same observability bus that server-side telemetry uses. Your existant exporters pick them up automatically après observability est configured.

## Stored agents

Stored agents sont agent configurations stored dans a database that peut be created, updated, et deleted à runtime. They reference primitives (tools, workflows, autre agents, scorers) par key, which sont resolved depuis the Mastra registry when the agent est instantiated. Mémoire est configuré inline comme a `SerializedMemoryConfig` objet avec options such comme `lastMessages` et `semanticRecall`.

### `listStoredAgents()`

Retrieve a paginated liste de tous les stored agents:

```typescript
const result = await mastraClient.listStoredAgents()
console.log(result.agents) // Array of stored agents
console.log(result.total) // Total count
```

With pagination et ordering:

```typescript
const result = await mastraClient.listStoredAgents({
  page: 0,
  perPage: 20,
  orderBy: {
    field: 'createdAt',
    direction: 'DESC',
  },
})
```

### `createStoredAgent()`

Créer a nouveau stored agent:

```typescript
const agent = await mastraClient.createStoredAgent({
  id: 'my-agent',
  name: 'My Assistant',
  instructions: 'You are a helpful assistant.',
  model: {
    provider: 'openai',
    name: 'gpt-5.4',
  },
})
```

Par défaut, `createStoredAgent()` publishes the initial version immediately. Définir `autoPublish` à `false` à crée an unpublished draft that you peut review avant calling [`activateVersion()`](#activateversion):

```typescript
const draft = await mastraClient.createStoredAgent({
  id: 'draft-agent',
  name: 'Draft Assistant',
  instructions: 'You are a helpful assistant.',
  model: {
    provider: 'openai',
    name: '__AI_SDK_OPENAI_MODEL_BASE__',
  },
  autoPublish: false,
})
```

Éditeurs configuré avec the `code` source always publish the initial version car saving writes the agent configuration à the file system.

Avec unll options:

```typescript
const agent = await mastraClient.createStoredAgent({
  id: 'full-agent',
  name: 'Full Agent',
  description: 'A fully configured agent',
  instructions: 'You are a helpful assistant.',
  model: {
    provider: 'openai',
    name: 'gpt-5.4',
  },
  tools: { calculator: {}, weather: {} },
  workflows: { 'data-processing': {} },
  agents: { 'subagent-1': {} },
  memory: {
    options: {
      lastMessages: 20,
      semanticRecall: false,
    },
  },
  scorers: {
    'quality-scorer': {
      sampling: { type: 'ratio', rate: 0.1 },
    },
  },
  defaultOptions: {
    maxSteps: 10,
  },
  metadata: {
    version: '1.0',
    team: 'engineering',
  },
})
```

### `getStoredAgent()`

Obtenir an instance de a specific stored agent:

```typescript
const storedAgent = mastraClient.getStoredAgent('my-agent')
```

```typescript
const result = await storedAgent.delete()
console.log(result.success) // true
```

## Version management

Both `Agent` (code-defined) et `StoredAgent` instances ont methods pour managing configuration versions. Consultez [Éditeur versioning](/docs/editor/overview#versioning) pour lifecycle et selection behavior.

### Getting an agent avec a specific version

Pass a version identifiant when getting an agent:

```typescript
// Load the published version (default)
const agent = mastraClient.getAgent('support-agent')

// Load the latest draft
const draftAgent = mastraClient.getAgent('support-agent', { status: 'draft' })

// Load a specific version
const versionedAgent = mastraClient.getAgent('support-agent', { versionId: 'abc-123' })
```

For stored agents, transmet a status option à `details()`:

```typescript
const storedAgent = mastraClient.getStoredAgent('my-agent')
const draft = await storedAgent.details(undefined, { status: 'draft' })
```

### `listVersions()`

Lister tous les versions pour an agent:

```typescript
const versions = await agent.listVersions()
console.log(versions.items) // Array of version snapshots
console.log(versions.total)
```

With pagination et sorting:

```typescript
const versions = await agent.listVersions({
  page: 0,
  perPage: 10,
  orderBy: {
    field: 'createdAt',
    direction: 'DESC',
  },
})
```

### `createVersion()`

Créer a nouveau version snapshot:

```typescript
const version = await agent.createVersion({
  changeMessage: 'Updated tone to be more friendly',
})
```

### `getVersion()`

Obtenir a specific version par ID:

```typescript
const version = await agent.getVersion('version-123')
console.log(version.versionNumber)
console.log(version.changedFields)
console.log(version.createdAt)
```

### `activateVersion()`

Définir a version comme the active published version:

```typescript
await agent.activateVersion('version-123')
```

### `restoreVersion()`

Restore a previous version par creating a nouveau version avec the same configuration:

```typescript
await agent.restoreVersion('version-456')
```

### `deleteVersion()`

Supprimer a version:

```typescript
await agent.deleteVersion('version-789')
```

### `compareVersions()`

Compare deux versions et renvoie their differences:

```typescript
const diff = await agent.compareVersions('version-123', 'version-456')
console.log(diff.changes) // Fields that changed between versions
```

### React SDK

Dans le React SDK, transmet an `agentVersionId` via `requestContext` when using the `useChat` hook:

```typescript title="Version targeting with React SDK"
import { useChat } from '@mastra/react'

function Chat() {
  const { messages, input, handleInputChange, handleSubmit } = useChat({
    agentId: 'support-agent',
    requestContext: {
      agentVersionId: 'abc-123',
    },
  })

  // ... render chat UI
}
```
