# createACPTool()

The `createACPTool()` fonction creates a Mastra Tool that sends a `task` chaîne à an Agent Client Protocol (ACP)-compatible coding agent et returns the final ACP réponse comme `output`. Use it when a parent agent doit decide when à call the ACP agent comme a tool.

Si vous want à register the ACP agent comme a Mastra subagent instead, utilise the [`AcpAgent` class class](/reference/acp/acp-agent).

## Exemple d’utilisation

Créer a code editing Tool et register it sur a parent agent:

```typescript title="src/mastra/agents/code-supervisor.ts"
import { createACPTool } from '@mastra/acp'
import { Agent } from '@mastra/core/agent'

const codeAgentTool = createACPTool({
  id: 'code-agent',
  description: 'Use an ACP-compatible coding agent to inspect and edit code',
  command: 'acp-agent',
  args: ['--stdio'],
  cwd: process.cwd(),
})

export const codeSupervisor = new Agent({
  id: 'code-supervisor',
  name: 'Code Supervisor',
  instructions: 'Use the code-agent tool when a task requires repository inspection or code edits.',
  model: '__GATEWAY_OPENAI_MODEL__',
  tools: {
    codeAgentTool,
  },
})
```

## Cycle de vie de la session

Chaque Tool execution creates an ACP connection et starts the configuré `command`. It initializes the ACP client et creates an ACP session avant sending the `task` avec ACP `session/prompt`.

Par défaut, `persistSession` est `true` pour the ACP connection created during Tool execution. Définir `persistSession: false` when the ACP traite doit arrête comme soon comme that prompt completes.

Use [`AcpAgent`](/reference/acp/acp-agent#session-lifecycle) when you need a reusable ACP subagent instance avec explicit session lifecycle control across calls.

## Permission handling

ACP agents peut ask the client à choose a permission option avant they continue. Par défaut, `@mastra/acp` selects the premier option returned par the ACP agent, ou cancels when aucun option est available.

Pass `onPermissionRequest` à inspect the requête et renvoie your own permission response:

```typescript title="src/mastra/agents/code-agent.ts"
import { createACPTool } from '@mastra/acp'

export const codeAgentTool = createACPTool({
  id: 'code-agent',
  description: 'Use an ACP-compatible coding agent',
  command: 'acp-agent',
  args: ['--stdio'],
  async onPermissionRequest(request) {
    const allowOption = request.options.find(option => option.name === 'Allow')

    if (!allowOption) {
      return { outcome: { outcome: 'cancelled' } }
    }

    return {
      outcome: {
        outcome: 'selected',
        optionId: allowOption.optionId,
      },
    }
  },
})
```

Utilisez ce rappel à enforce local policy ou inspect the permission title. It peut also route the decision à your own approval flow.

## Extension methods

Some ACP agents call personnalisé extension methods sur the client, outside the standard ACP requête set. La valeur par défaut client rejects unknown methods avec a "Method ne pas found" error, which peut abort the agent's turn.

Pass `createClient` à extend ou replace the par défaut client. The rappel receives the par défaut client et returns the client used pour the connection:

```typescript title="src/mastra/agents/code-agent.ts"
import { createACPTool } from '@mastra/acp'

export const codeAgentTool = createACPTool({
  id: 'code-agent',
  description: 'Use an ACP-compatible coding agent',
  command: 'acp-agent',
  args: ['--stdio'],
  createClient: defaultClient =>
    Object.assign(defaultClient, {
      async extMethod(method: string, params: Record<string, unknown>) {
        return {}
      },
      async extNotification(method: string, params: Record<string, unknown>) {},
    }),
})
```

Renvoyer a fully personnalisé `Client` implementation when you need à change the standard handlers comme well. The `Client` type est re-exported depuis `@mastra/acp`.
