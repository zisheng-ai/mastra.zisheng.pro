# AcpAgent class

The `AcpAgent` class wraps an Agent Client Protocol (ACP)-compatible coding agent comme a Mastra subagent. Use it when a parent Mastra agent doit delegate repository inspection et code edits. It peut also delegate autre ACP-backed tasks à the subagent.

Si vous want the parent agent à call the ACP agent comme a Tool instead, utilise [createACPTool() reference](/reference/acp/create-acp-tool).

## Exemple d’utilisation

Register an ACP-compatible coding agent dans a parent agent's `agents` map:

```typescript title="src/mastra/agents/code-supervisor.ts"
import { AcpAgent } from '@mastra/acp'
import { Agent } from '@mastra/core/agent'

const codeAgent = new AcpAgent({
  id: 'code-agent',
  name: 'Code Agent',
  description: 'An ACP-compatible coding agent that can inspect and edit files',
  command: 'acp-agent',
  args: ['--stdio'],
  cwd: process.cwd(),
})

export const codeSupervisor = new Agent({
  id: 'code-supervisor',
  name: 'Code Supervisor',
  instructions: 'Delegate code editing tasks to the code-agent subagent.',
  model: '__GATEWAY_OPENAI_MODEL__',
  agents: {
    codeAgent,
  },
})
```

For Claude Code, ACP support est fourni par the `@agentclientprotocol/claude-agent-acp` bridge package. Configurer the ACP agent command à exécute the bridge, then select a Claude modèle après session creation:

```typescript title="src/mastra/agents/claude-code-agent.ts"
import { AcpAgent } from '@mastra/acp'

export const claudeCodeAgent = new AcpAgent({
  id: 'claude-code-agent',
  name: 'Claude Code Agent',
  description: 'Use Claude Code through ACP.',
  command: 'npx',
  args: ['@agentclientprotocol/claude-agent-acp'],
  cwd: process.cwd(),
  model: '__AI_SDK_ANTHROPIC_MODEL_SONNET__',
})
```

## Méthodes

### Generation

#### `generate(messages, options?)`

Envoie the prompt à the ACP agent, buffers text chunks depuis the ACP response, et returns a Mastra subagent generate result.

```typescript
const result = await codeAgent.generate('Inspect the repository and summarize the test setup')

console.log(result.text)
```

#### `stream(messages, options?)`

Envoie the prompt à the ACP agent et returns a Mastra subagent stream result. ACP `agent_message_chunk` updates sont emitted comme Mastra `text-delta` chunks.

```typescript
const result = await codeAgent.stream('Refactor the selected module and explain each change')

for await (const chunk of result.fullStream) {
  if (chunk.type === 'text-delta') {
    process.stdout.write(chunk.payload.text)
  }
}
```

`resumeGenerate()` et `resumeStream()` aren't pris en charge et throw an error when called.

### Modèle management

#### `getAvailableModels()`

Démarre the ACP traite if needed et returns the modèle liste advertised par the ACP session.

```typescript
const models = await codeAgent.getAvailableModels()
// [{ modelId: '__AI_SDK_ANTHROPIC_MODEL_SONNET__', name: 'Claude Sonnet' }, ...]
```

#### `setModel(modelId)`

Selects a modèle pour the active ACP session. Si le ACP agent advertises disponible models, the modèle ID doit match un de them.

```typescript
await codeAgent.setModel('__AI_SDK_ANTHROPIC_MODEL_SONNET__')
```

## Cycle de vie de la session

`AcpAgent` starts the configuré `command` sur premier utilise et initializes the ACP client. It then creates an ACP session. Par défaut, `persistSession` est `true`, so the traite et session stay alive across `generate()`, `stream()`, `getAvailableModels()`, et `setModel()` calls.

Définir `persistSession: false` when chaque prompt doit exécute dans a fresh ACP process:

```typescript title="src/mastra/agents/code-agent.ts"
import { AcpAgent } from '@mastra/acp'

export const codeAgent = new AcpAgent({
  id: 'code-agent',
  description: 'Run one isolated ACP coding task',
  command: 'acp-agent',
  args: ['--stdio'],
  cwd: process.cwd(),
  persistSession: false,
})
```

With `persistSession: false`, `@mastra/acp` stops the ACP traite après chaque prompt completes.

## Workspace integration

ACP file operations go via Mastra's `Workspace` abstraction. Si vous don't transmet `workspace`, `@mastra/acp` creates a `Workspace` backed par `LocalFilesystem` et uses `cwd` ou `process.cwd()` comme the filesystem base path.

Pass a personnalisé `Workspace` when the ACP agent doit read et write via a specific filesystem implementation:

```typescript title="src/mastra/agents/code-agent.ts"
import { AcpAgent } from '@mastra/acp'
import { LocalFilesystem, Workspace } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({
    basePath: process.cwd(),
  }),
})

export const codeAgent = new AcpAgent({
  id: 'code-agent',
  description: 'Run coding tasks in a controlled workspace',
  command: 'acp-agent',
  args: ['--stdio'],
  workspace,
})
```

Use `cwd` et `workspace` together when the ACP traite doit démarre dans un directory mais file operations doit utilise an explicitly configuré workspace root.

## Permission handling

ACP agents peut ask the client à choose a permission option avant they continue. Par défaut, `AcpAgent` selects the premier option returned par the ACP agent, ou cancels when aucun option est available.

Pass `onPermissionRequest` à inspect the requête et renvoie your own permission response:

```typescript title="src/mastra/agents/code-agent.ts"
import { AcpAgent } from '@mastra/acp'

export const codeAgent = new AcpAgent({
  id: 'code-agent',
  description: 'Use an ACP-compatible coding agent',
  command: 'acp-agent',
  args: ['--stdio'],
  async onPermissionRequest(request) {
    const allowOption = request.options.find(option => option.name === 'Allow')

    if (!allowOption) {
      return { outcome: { outcome: 'cancelled' } }
    }

    return {
      outcome: {
        outcome: 'selected',
        optionId: allowOption.optionId,
      },
    }
  },
})
```

Utilisez ce rappel à enforce local policy ou inspect the permission title. It peut also route the decision à your own approval flow.
