# Déployeur

The Déployeur handles the deployment de standalone Mastra applications par packaging code, managing environment files, et serving applications using the Hono framework. Concrete implementations doit define the deploy method pour specific deployment targets.

## Exemple d’utilisation

Si vous want à crée a personnalisé deployer, you peut extend the abstract `Deployer` class et implement the `deploy` method avec your specific deployment logic. Here's an example:

```typescript
import { Deployer } from '@mastra/deployer'

class CustomDeployer extends Deployer {
  constructor() {
    super({ name: 'custom-deployer' })
  }

  async deploy(outputDirectory: string): Promise<void> {
    // Prepare the output directory
    await this.prepare(outputDirectory)

    // Bundle the application
    await this._bundle('server.ts', 'mastra.ts', outputDirectory)

    // Custom deployment logic
  }
}
```

## Core concepts

### Déploiement Lifecycle

The Déployeur abstract class implements a structured deployment lifecycle:

1. **Initialization**: The deployer est initialized avec a nom et creates a Deps instance pour dependency management.
1. **Environment Setup**: The `getEnvFiles` method identifies environment files (.env.production, .env) à be used during deployment.
1. **Preparation**: The `prepare` method (inherited depuis Bundler) cleans the output directory et creates necessary subdirectories.
1. **Bundling**: The `_bundle` method (inherited depuis Bundler) packages the application code et its dependencies.
1. **Déploiement**: The abstract `deploy` method est implemented par subclasses à gère the actual deployment process.

### Environment Fichier Management

The Déployeur class includes built-in support pour environment file management via the `getEnvFiles` method. Ce method:

- Looks pour environment files dans a predefined order (.env.production, .env)
- Uses the FichierService à find the premier existant file
- Renvoie an tableau de found environment files
- Renvoie an vide tableau if aucun environment files sont found

```typescript prettier:false
getEnvFiles(): Promise<string[]> {
  const possibleFiles = ['.env.production', '.env.local', '.env'];

  try {
    const fileService = new FileService();
    const envFile = fileService.getFirstExistingFile(possibleFiles);

    return Promise.resolve([envFile]);
  } catch {}

  return Promise.resolve([]);
}
```

### Bundling et Déploiement Relationship

The Déployeur class extends the Bundler class, establishing a clear relationship entre bundling et deployment:

1. **Bundling comme a Prerequisite**: Bundling est a prerequisite step pour deployment, where the application code est packaged dans a deployable format.
1. **Shared Infrastructure**: Both bundling et deployment share common infrastructure like dependency management et file system operations.
1. **Specialized Déploiement Logic**: While bundling focuses sur code packaging, deployment adds environment-specific logic pour deploying the bundled code.
1. **Extensibility**: The abstract `deploy` method allows pour creating specialized deployers pour different target environments.
