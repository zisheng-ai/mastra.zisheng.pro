# Deployer

Le Deployer gère le déploiement des applications Mastra autonomes en regroupant le code, en gérant les fichiers d’environnement et en servant les applications au moyen du framework Hono. Les implémentations concrètes doivent définir la méthode deploy pour des cibles de déploiement précises.

## Exemple d’utilisation {/* #usage-example */}

Pour créer un Deployer personnalisé, étendez la classe abstraite `Deployer` et implémentez la méthode `deploy` avec votre propre logique de déploiement. Exemple :

```typescript
import { Deployer } from '@mastra/deployer'

class CustomDeployer extends Deployer {
  constructor() {
    super({ name: 'custom-deployer' })
  }

  async deploy(outputDirectory: string): Promise<void> {
    // Prepare the output directory
    await this.prepare(outputDirectory)

    // Bundle the application
    await this._bundle('server.ts', 'mastra.ts', outputDirectory)

    // Custom deployment logic
  }
}
```

## Concepts fondamentaux {/* #core-concepts */}

### Cycle de vie du déploiement {/* #deployment-lifecycle */}

La classe abstraite Deployer implémente un cycle de vie de déploiement structuré :

1. **Initialisation :** le Deployer est initialisé avec un nom et crée une instance de Deps pour gérer les dépendances.
1. **Configuration de l’environnement :** la méthode `getEnvFiles` identifie les fichiers d’environnement (.env.production, .env) à utiliser pendant le déploiement.
1. **Préparation :** la méthode `prepare`, héritée de Bundler, nettoie le répertoire de sortie et crée les sous-répertoires nécessaires.
1. **Regroupement :** la méthode `_bundle`, héritée de Bundler, regroupe le code de l’application et ses dépendances.
1. **Déploiement :** les sous-classes implémentent la méthode abstraite `deploy` afin de gérer le processus de déploiement réel.

### Gestion des fichiers d’environnement {/* #environment-file-management */}

La classe Deployer prend nativement en charge la gestion des fichiers d’environnement au moyen de la méthode `getEnvFiles`. Cette méthode :

- Recherche les fichiers d’environnement dans un ordre prédéfini (.env.production, .env)
- Utilise FileService pour trouver le premier fichier existant
- Renvoie un tableau des fichiers d’environnement trouvés
- Renvoie un tableau vide si aucun fichier d’environnement n’est trouvé

```typescript prettier:false
getEnvFiles(): Promise<string[]> {
  const possibleFiles = ['.env.production', '.env.local', '.env'];

  try {
    const fileService = new FileService();
    const envFile = fileService.getFirstExistingFile(possibleFiles);

    return Promise.resolve([envFile]);
  } catch {}

  return Promise.resolve([]);
}
```

### Relation entre le regroupement et le déploiement {/* #bundling-and-deployment-relationship */}

La classe Deployer étend la classe Bundler, établissant une relation claire entre le regroupement et le déploiement :

1. **Regroupement comme prérequis :** le regroupement est une étape préalable au déploiement, durant laquelle le code de l’application est conditionné dans un format déployable.
1. **Infrastructure partagée :** le regroupement et le déploiement partagent une infrastructure commune, comme la gestion des dépendances et les opérations sur le système de fichiers.
1. **Logique de déploiement spécialisée :** le regroupement se concentre sur le packaging du code, tandis que le déploiement ajoute une logique propre à l’environnement pour déployer le code regroupé.
1. **Extensibilité :** la méthode abstraite `deploy` permet de créer des Deployers spécialisés pour différentes cibles d’environnement.
