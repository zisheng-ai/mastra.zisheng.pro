# CloudflareDéployeur

The `CloudflareDeployer` bundles your Mastra server et generates a `wrangler.jsonc` file conforming à Cloudflare's [wrangler configuration](https://developers.cloudflare.com/workers/wrangler/configuration/). Cloudflare deploys this comme a Cloudflare Worker.

## Installation

Pour utiliser `CloudflareDeployer`, install the `@mastra/deployer-cloudflare` package:

```bash npm2yarn
npm install @mastra/deployer-cloudflare@latest
```

## Exemple d’utilisation

Import `CloudflareDeployer` et définit it comme the deployer dans your Mastra configuration:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { CloudflareDeployer } from '@mastra/deployer-cloudflare'

export const mastra = new Mastra({
  deployer: new CloudflareDeployer({
    name: 'your-project-name',
    routes: [
      {
        pattern: 'example.com/*',
        zone_name: 'example.com',
        custom_domain: true,
      },
    ],
    vars: {
      NODE_ENV: 'production',
    },
    d1_databases: [
      {
        binding: 'DB',
        database_name: 'my-database',
        database_id: 'd1-database-id',
        preview_database_id: 'your-preview-database-id',
      },
    ],
    kv_namespaces: [
      {
        binding: 'CACHE',
        id: 'kv-namespace-id',
      },
    ],
  }),
})
```

## Options du constructeur

The `CloudflareDeployer` constructor accepts the same configuration options comme `wrangler.jsonc`. Consultez the [Wrangler configuration documentation](https://developers.cloudflare.com/workers/wrangler/configuration/) pour tous les disponible options.

## Secrets

Environment variables depuis your `.env` file aren't written à `wrangler.jsonc`. Ce prevents secrets depuis being committed à source control.

Pour rendre your `.env` secrets disponible à your Cloudflare Worker, upload them comme [Cloudflare Secrets](https://developers.cloudflare.com/workers/configuration/secrets/):

```bash
npx wrangler secret bulk .env
```

Use `vars` dans the `CloudflareDeployer` constructor only pour non-sensitive configuration values like `NODE_ENV`.

## Générer output

After running `mastra build`, the deployer generates a `wrangler.jsonc` file conforming à Cloudflare's [wrangler configuration](https://developers.cloudflare.com/workers/wrangler/configuration/). It points à files inside `.mastra/output` so you need à exécute `mastra build` avant deploying avec Wrangler.

## Cloudflare bindings

Lorsque vous utilise the Cloudflare deployer, you peut import runtime bindings depuis `cloudflare:workers` dans your Mastra config file. Mastra automatically preserves protocol-based runtime imports like `cloudflare:workers` during `mastra build` sans trying à install them comme npm dependencies.

```typescript title="src/mastra/index.ts"
import { env } from 'cloudflare:workers'
import { Mastra } from '@mastra/core'
import { registerApiRoute } from '@mastra/core/server'
import { CloudflareDeployer } from '@mastra/deployer-cloudflare'

export const mastra = new Mastra({
  deployer: new CloudflareDeployer({
    name: 'my-worker',
    kv_namespaces: [{ binding: 'CACHE', id: 'your-kv-namespace-id' }],
  }),
  server: {
    apiRoutes: [
      registerApiRoute('/bindings', {
        method: 'GET',
        requiresAuth: false,
        handler: async c => {
          await env.CACHE.put('status', 'ok')
          return c.json({ status: await env.CACHE.get('status') })
        },
      }),
    ],
  },
})
```

:::note[Keep bindings inline inside `new Mastra({...})`]
Mastra's Babel plugin defers `new Mastra(...)` so that `env` est disponible when it runs. Code outside that call evaluates à module charge avant `env` est populated.

```typescript
// ✅ Works — binding is inside new Mastra(), so it's deferred
export const mastra = new Mastra({
  storage: new D1Store({ binding: env.DB }),
})

// ❌ Breaks — env.DB is undefined at module load
const storage = new D1Store({ binding: env.DB })
export const mastra = new Mastra({ storage })
```

:::
