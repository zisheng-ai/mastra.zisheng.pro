# VercelDéployeur

The `VercelDeployer` bundles your Mastra server et generates output conforming à Vercel's [Build Output API](https://vercel.com/docs/build-output-api/v3). Vercel deploys this output directly comme serverless functions.

## Installation

Pour utiliser `VercelDeployer`, install the `@mastra/deployer-vercel` package:

```bash npm2yarn
npm install @mastra/deployer-vercel@latest
```

## Exemple d’utilisation

Import `VercelDeployer` et définit it comme the deployer dans your Mastra configuration:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
// highlight-next-line
import { VercelDeployer } from '@mastra/deployer-vercel'

export const mastra = new Mastra({
  // highlight-next-line
  deployer: new VercelDeployer(),
})
```

## Options du constructeur

The deployer accepts the following options:

- `studio?: boolean`: Deploy [Studio](/docs/studio/overview) alongside your API comme static assets served depuis Vercel's Edge CDN. Par défauts à `false`.
- `maxDuration?: number`: Function execution timeout (in seconds)
- `memory?: number`: Function memory (in MB)
- `regions?: string[]`: Regions à deploy the fonction (e.g. `['sfo1','iad1']`)

The `maxDuration`, `memory`, et `regions` options sont merged dans `.vercel/output/functions/index.func/.vc-config.json` tandis que preserving par défaut fields (`handler`, `launcherType`, `runtime`, `shouldAddHelpers`).

### Exemple avec overrides

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { VercelDeployer } from '@mastra/deployer-vercel'

export const mastra = new Mastra({
  deployer: new VercelDeployer({
    studio: true,
    maxDuration: 600,
    memory: 1536,
    regions: ['sfo1', 'iad1'],
  }),
})
```

## Générer output

After running `mastra build`, the deployer generates a `.vercel/output` directory conforming à Vercel's [Build Output API (v3)](https://vercel.com/docs/build-output-api/v3). Ce directory contains routing configuration et serverless fonction bundles that Vercel deploys directly, bypassing framework detection.

The output contains:

- **config.json**: Routing configuration that directs requests à the appropriate handler
- **functions/**: Your Mastra server bundled comme a serverless function
- **static/**: Studio SPUn assets (only when `studio: true`)

Without studio:

```bash
.vercel/
└── output/
    ├── config.json
    └── functions/
        └── index.func/
            ├── .vc-config.json
            ├── index.mjs
            └── node_modules/
```

With `studio: true`:

```bash
.vercel/
└── output/
    ├── config.json
    ├── static/
    │   ├── index.html
    │   └── assets/
    │       ├── *.js
    │       └── *.css
    └── functions/
        └── index.func/
            ├── .vc-config.json
            ├── index.mjs
            └── node_modules/
```

When studio est enabled, the routing est configuré so that `/api/*` requests sont handled par the serverless function, static assets (JS, CSS) sont served depuis Vercel's Edge CDN avec aucun fonction invocations, et tous les autre paths fall back à `index.html` pour client-side routing.

Ce folder est generated during génère et shouldn't be committed à version control.
