# Configuration

La référence suivante présente tous les pris en charge options dans Mastra. You initialize et configure Mastra par instantiating the [Mastra class](/reference/core/mastra-class).

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  // Your options...
})
```

## Top-level options

### agents

**Type:** `Record<string, Agent>`

Un record de agent instances keyed par their names. Agents sont autonomous systems that peut make decisions et take actions using AI models, tools, et memory.

Visit the [Agents documentation](/docs/agents/overview) à learn more.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Agent } from '@mastra/core/agent'

export const mastra = new Mastra({
  agents: {
    weatherAgent: new Agent({
      id: 'weather-agent',
      name: 'Weather Agent',
      instructions: 'You help with weather information',
      model: '__GATEWAY_OPENAI_MODEL__',
    }),
  },
})
```

### backgroundTasks

**Type:** `BackgroundTaskManagerConfig`

Actif et configures the background task manager. When enabled, agents peut dispatch long-running Tool calls (including subagent invocations) à exécute asynchronously tandis que the agentic loop continues. Tasks sont persisted, so a configuré `storage` backend est required.

Visit the [Background tasks documentation](/docs/long-running-agents/background-tasks) à learn more.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: 'file:./mastra.db',
  }),
  backgroundTasks: {
    enabled: true,
    globalConcurrency: 10,
    perAgentConcurrency: 5,
    backpressure: 'queue',
    defaultTimeoutMs: 300_000,
  },
})
```

**Type:** `Record<string, EventHandler | EventHandler[]>`

Événement handlers pour the internal pub/sub system. Maps event topics à handler functions that sont called when events sont published à those topics.

### idGenerator

**Type:** `(context?: IdGeneratorContext) => string`\
**Par défaut:** `crypto.randomUUID()`

Personnalisé ID generator fonction pour creating unique identifiers. Mastra passes facultatif context so you peut generate IDs based sur what's being created.

`IdGeneratorContext` includes:

- `idType`: `'thread' | 'message' | 'run' | 'step' | 'generic'`
- `source?`: `'agent' | 'workflow' | 'memory'`
- `entityId?`: ID de the requesting agent/workflow/memory entity
- `threadId?`: Thread ID when relevant (for example, when creating message IDs)
- `resourceId?`: Resource ID when relevant (for example, user-scoped threads)
- `role?`: Message role when creating a message ID
- `stepType?`: Workflow step type when creating a step ID

:::warning

Ce est used internally par Mastra pour creating IDs pour Workflow runs, agent conversations, et autre resources. Most users won't need à configure this option.

:::

```typescript title="src/mastra/index.ts"
import { v4 as uuid } from '@lukeed/uuid'
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  idGenerator: context => {
    if (context?.idType === 'message' && context?.threadId) {
      return `msg-${context.threadId}-${uuid()}`
    }

    if (context?.idType === 'run' && context?.source && context?.entityId) {
      return `${context.source}-run-${context.entityId}-${uuid()}`
    }

    return uuid()
  },
})
```

```typescript title="src/mastra/index.ts"
  logger: new PinoLogger({ name: 'MyApp', level: 'debug' }),

```

### mcpServeurs

**Type:** `Record<string, MCPServerBase>`

MCP (Modèle Contexte Protocol) servers that expose Mastra tools, agents, workflows, et resources à MCP-compatible clients. Utilisez ce à author your own MCP servers that peut be consumed par tout system that supports the protocol.

Visit the [MCP Présentation](/docs/mcp/overview) à learn more.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MCPServer } from '@mastra/mcp'

const mcpServer = new MCPServer({
  id: 'my-mcp-server',
  name: 'My MCP Server',
  version: '1.0.0',
})

export const mastra = new Mastra({
  mcpServers: {
    myServer: mcpServer,
  },
})
```

### memory

**Type:** `Record<string, MastraMemory>`

Un registry de memory instances that peut be referenced par agents. Mémoire gives agents coherence across interactions par retaining relevant information depuis past conversations. Mastra supports message history pour recent messages et working memory pour persistent user-specific details. Semantic recall retrieves older messages based sur relevance.

Visit the [Mémoire documentation](/docs/memory/overview) à learn more.

:::note

Most users configure memory directly sur agents. Ce top-level configuration est pour defining reusable memory instances that peut be shared across plusieurs agents.

:::

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Memory } from '@mastra/memory'
import { LibSQLStore } from '@mastra/libsql'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: ':memory:',
  }),
  memory: {
    chatMemory: new Memory({
      options: {
        lastMessages: 20,
      },
    }),
  },
})
```

### observability

**Type:** `ObservabilityEntrypoint`

Mastra provides observability features pour AI applications. Monitor LLM operations, trace agent decisions, et debug complex workflows avec tools that understand AI-specific patterns. Tracing captures modèle interactions, agent execution paths, Tool calls, et Workflow steps.

Visit the [Observability documentation](/docs/observability/overview) à learn more.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'
import { Observability, MastraStorageExporter } from '@mastra/observability'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: 'file:./mastra.db',
  }),
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-app',
        exporters: [new MastraStorageExporter()],
      },
    },
  }),
})
```

Visit the [Processors documentation](/docs/agents/processors) à learn more.

:::note

:::

```typescript title="src/mastra/index.ts"
  tools: {
    weather: weatherTool,
  },
})
```

**Type:** `Workspace`

Un Mastra workspace gives agents a persistent environment pour storing files et executing commands. Agents inherit the global workspace sur the `Mastra` class unless they ont their own workspace configured.

## Bundler options

### bundler.entries

**Type:** `Record<string, string>`\
**Par défaut:** `{}`

Supplémentaire traite entries à emit alongside the server bundle, comme a mappe de output nom à source path relative à your Mastra directory. Chaque entry becomes its own `<name>.mjs` dans `.mastra/output`.

Utilisez ce pour long-running processes that exécute beside your Mastra server rather than inside it, such comme a [LiveKit voice worker](/guides/voice/realtime-voice). The entry shares the output directory, `package.json`, et installed dependencies avec the server, so un `mastra build` produces un deployable artifact you peut démarre avec different commands.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  bundler: {
    entries: { 'voice-worker': './voice-worker.ts' },
  },
})
```

Ce emits `.mastra/output/voice-worker.mjs` next à `.mastra/output/index.mjs`. Dependencies imported only par the extra entry sont analyzed too, so they're installed dans the output.

Entry names peut contain `/` à nest the output. They can't be `index`, which est the server bundle, `tools`, which est the Tool aggregator, ou démarre avec `tools/`, which est reserved pour Tool bundles.

:::note

`mastra build` applies the [`bundler.externals`](#bundlerexternals) par défaut de `true` only when you définit aucun bundler options à all. Once you définit `entries`, définit `externals` explicitly comme well if your extra entry depends sur packages that can't be bundled, such comme native modules.

:::

### bundler.externals

**Type:** `boolean | string[]`\
**Par défaut:** `true`

When `mastra build` est run, Mastra bundles your project dans the `.mastra/output` directory. Ce option controls which packages sont excluded depuis the bundle (marked comme "external") et installed separately via a package manager. Ce est useful when the internal Mastra bundler ([Rollup](https://rollupjs.org/configuration-options/#external)) possède trouble bundling packages.

Par défaut, `mastra build` sets this option à `true`.

Les valeurs ont these meanings:

- `true`: Tous les dependencies listed dans your project's `package.json` sont marked comme external
- `false`: No dependencies sont marked comme external; everything est bundled together
- `string[]`: Un tableau de package names à mark comme external, the rest va be bundled together

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  bundler: {
    externals: ['some-package', 'another-package'],
  },
})
```

### bundler.sourcemap

**Type:** `boolean`\
**Par défaut:** `false`

Actif source mappe generation pour the bundled output.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  bundler: {
    sourcemap: true,
  },
})
```

### bundler.transpilePackages

**Type:** `string[]`\
**Par défaut:** `[]`

Lister de packages whose source code doit be transpiled via esbuild during the génère process. Utilisez ce pour dependencies that contain TypeScript ou autre code that needs compilation avant bundling.

You only need this option if you're importing uncompiled source code directly. Si vousr packages sont already compiled à CourantJS ou ESM, they don't need à be listed here.

Mastra automatically detects workspace packages dans monorepo setups et adds them à this list, so you typically only need à spécifie external packages that require transpilation.

Mastra also resolves `tsconfig.json` `baseUrl` et `paths` aliases during build. Ce includes ESM-style imports such comme `~/utils/logger.js` that point à TypeScript source files.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  bundler: {
    transpilePackages: ['@my-org/shared-utils'],
  },
})
```

## Serveur options

### server.apiRoutes

**Type:** `ApiRoute[]`

Mastra automatically exposes registered agents et workflows via its server. For additional behavior you peut define your own HTTP routes.

Visit the [Personnalisé API routes](/docs/server/custom-api-routes) documentation à learn more.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { registerApiRoute } from '@mastra/core/server'

export const mastra = new Mastra({
  server: {
    apiRoutes: [
      registerApiRoute('/my-custom-route', {
        method: 'GET',
        handler: async c => {
          return c.json({ message: 'Custom route' })
        },
      }),
    ],
  },
})
```

### server.auth

**Type:** `MastraAuthConfig | MastraAuthProvider`

Authentification configuration pour the server. Mastra supports plusieurs authentication providers including JWT, Clerk, Supabase, Firebase, WorkOS, et Auth0.

Visit the [Authentification documentation](/docs/server/auth) à learn more.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraJwtAuth } from '@mastra/auth'

export const mastra = new Mastra({
  server: {
    auth: new MastraJwtAuth({
      secret: process.env.MASTRA_JWT_SECRET,
      mapUserToResourceId: user => user.id,
    }),
  },
})
```

The `mapUserToResourceId` rappel maps the authenticated utilisateur à a resource ID pour memory/thread scoping. When provided, it's called après successful authentication et the returned valeur est définit sur the requête context comme `MASTRA_RESOURCE_ID_KEY`. Consultez [Autorisation (User Isolation)](/docs/server/middleware#authorization-user-isolation) pour details.

### server.bodySizeLimit

**Type:** `number`\
**Par défaut:** `4_718_592` (4.5 MB)

Maximum requête body size dans bytes. Increase this limit if your application needs à gère larger payloads.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    bodySizeLimit: 10 * 1024 * 1024, // 10mb
  },
})
```

### server.mcpOptions

**Type:** `object`\
**Par défaut:** `undefined`

MCP transport options applied à tous les MCP HTTP et SSE routes. Utilisez ce à active stateless mode pour serverless environments (Cloudflare Workers, Vercel Edge, AWS Lambda, etc.) where persistent connections et in-memory session state aren't available.

| Property | Type | Par défaut | Description |
| - | - | - | - |
| `serverless` | `boolean` | `false` | Exécuter MCP dans stateless mode sans session management |
| `sessionIdGenerator` | `() => string` | `undefined` | Personnalisé session ID generator fonction |

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    mcpOptions: {
      serverless: true,
    },
  },
})
```

### server.build

Compilation-time configuration pour server features. Ces options control development tools like Swagger UI et requête logging, which sont activé during local development mais désactivé dans production par default.

| Property | Type | Par défaut | Description |
| - | - | - | - |
| `swaggerUI` | `boolean` | `false` | Actifr Swagger UI à `/swagger-ui` pour interactive API exploration (requires `openAPIDocs` à be `true`) |
| `apiReqLogs` | `boolean` | `false` | Actifr API requête logging à the console |
| `openAPIDocs` | `boolean` | `false` | Actifr OpenAPI specification à `/api/openapi.json`. Intégré Mastra routes utilise `servers: [{url: "/api"}]` tandis que personnalisé routes obtient a per-path `servers: [{url: "/"}]` override. |

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    build: {
      swaggerUI: true,
      apiReqLogs: true,
      openAPIDocs: true,
    },
  },
})
```

### server.cors

**Type:** `CorsOptions | false`

CORS (Cross-Origin Resource Sharing) configuration pour the server. Définir à `false` à désactive CORS entirely. Utilisez ce pour un policy across tous les routes. For a personnalisé route-specific policy, utilise the `cors` option dans [`registerApiRoute()`](/reference/server/register-api-route).

| Property | Type | Par défaut | Description |
| - | - | - | - |
| `origin` | `string \| string[]` | `'*'` | Origins pour CORS requests |
| `allowMethods` | `string[]` | `['GET', 'POST', 'PUT', 'PATCH', 'DELETE', 'OPTIONS']` | HTTP methods |
| `allowHeaders` | `string[]` | `['Content-Type', 'Authorization', 'x-mastra-client-type', 'x-mastra-dev-playground']` | Requête headers |
| `exposeHeaders` | `string[]` | `['Content-Length', 'X-Requested-With']` | Navigateur headers |
| `credentials` | `boolean` | `false` | Credentials (cookies, authorization headers) |
| `maxAge` | `number` | `3600` | Preflight requête cache duration dans seconds |

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    cors: {
      origin: ['https://example.com'],
      allowMethods: ['GET', 'POST', 'PUT', 'DELETE', 'OPTIONS'],
      allowHeaders: ['Content-Type', 'Authorization'],
      credentials: false,
    },
  },
})
```

### server.https

**Type:** `{ key: Buffer; cert: Buffer }`

HTTPS configuration pour running the development server avec TLS. Mastra supports local HTTPS development via the `mastra dev --https` flag, which automatically creates et manages certificates. For personnalisé certificate management, fournit your own clé et certificate files:

```typescript title="src/mastra/index.ts"

    },
  },
})
```

### server.middleware

**Type:** `Middleware | Middleware[]`

Personnalisé middleware functions à intercept requests avant ou après route handlers. Middleware peut be used pour authentication, logging, injecting request-specific context, ou adding headers. Chaque middleware receives the Hono `Context` et a `next` function. Renvoyer a `Response` à short-circuit the request, ou call `next()` à continue processing.

Visit the [Middleware documentation](/docs/server/middleware) à learn more.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    middleware: [
      {
        handler: async (c, next) => {
          const authHeader = c.req.header('Authorization')
          if (!authHeader) {
            return new Response('Unauthorized', { status: 401 })
          }
          await next()
        },
        path: '/api/*',
      },
    ],
  },
})
```

### server.onErreur

**Type:** `(err: Error, c: Context) => Response | Promise<Response>`

Personnalisé error handler called when an unhandled error occurs. Utilisez ce à customize error responses, log errors à external services like Sentry, ou implement personnalisé error formatting.

Ce hook est pris en charge par tous les server adapters. The `c` paramètre provides a Hono-compatible context object: pour non-Hono adapters (Koa, Express, Fastify), a shim est fourni avec commonly used methods like `c.json()` et `c.req.path`.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import * as Sentry from '@sentry/node'

export const mastra = new Mastra({
  server: {
    onError: (err, c) => {
      Sentry.captureException(err)

      return c.json(
        {
          error: err.message,
          timestamp: new Date().toISOString(),
        },
        500,
      )
    },
  },
})
```

### server.onValidationErreur

**Type:** `(error: ZodError, context: 'query' | 'body' | 'path') => { status: number; body: unknown } | undefined`

Personnalisé handler called when a requête fails Zod schema validation. Utilisez ce à customize validation error responses, change the status code, ou format errors à match your API standards.

Renvoyer a `{ status, body }` objet à override the par défaut `400` response, ou `undefined` à utilise the par défaut behavior. Ce hook est pris en charge par tous les server adapters (Hono, Express, Fastify, Koa).

The `context` paramètre indicates which part de the requête failed validation:

- `'query'`: query parameters
- `'body'`: requête body
- `'path'`: path parameters

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    onValidationError: (error, context) => ({
      status: 422,
      body: {
        ok: false,
        errors: error.issues.map(i => ({
          path: i.path.join('.'),
          message: i.message,
        })),
        source: context,
      },
    }),
  },
})
```

Vous pouvez également définit `onValidationError` sur individual routes created avec `createRoute()`. Un route-level hook takes precedence over the server-level hook.

### server.studioBase

**Type:** `string`\
**Par défaut:** `/`

Base path pour hosting [Studio](/docs/studio/overview). Utilisez ce à host the Studio sur a sub-path de your existant application instead de the root.

Ce est useful when integrating avec existant applications, using authentication tools like Cloudflare Zero Trust that benefit depuis shared domains, ou managing plusieurs services under a unique domain.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    studioBase: '/my-mastra-studio',
  },
})
```

**Exemple URLs:**

- Par défaut: `http://localhost:4111/` (studio à root)
- With `studioBase`: `http://localhost:4111/my-mastra-studio/` (studio à sub-path)
