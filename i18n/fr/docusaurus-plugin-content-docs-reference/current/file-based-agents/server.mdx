# Serveur

Mastra configure son [serveur](/docs/server/mastra-server) HTTP à partir d’un fichier `server.ts` placé directement dans `src/mastra/`. Le serveur expose les Agents, les Workflows et les autres éléments enregistrés en tant que points de terminaison REST, et le fichier exporte par défaut la même forme `ServerConfig` que celle transmise à [`new Mastra()`](/reference/core/mastra-class).

Utilisez cette page pour la convention basée sur les fichiers. Pour les fonctionnalités du serveur, les middlewares, les routes personnalisées, la documentation d’API générée et le comportement de déploiement, consultez la [présentation du serveur](/docs/server/mastra-server).

## Démarrage rapide {/* #quickstart */}

Créez `src/mastra/server.ts` et exportez par défaut un objet `ServerConfig` :

```typescript title="src/mastra/server.ts"
import type { ServerConfig } from '@mastra/core/server'

export default {
  port: 4111,
  host: '0.0.0.0',
} satisfies ServerConfig
```

## Configurations courantes {/* #common-configurations */}

`server.ts` peut configurer les mêmes options de serveur que l’enregistrement dans le code :

| Besoin | Utiliser |
| - | - |
| Se lier à l’adresse d’une plateforme de déploiement | `host` et `port` |
| Restreindre l’accès depuis le navigateur | `cors` |
| Ajouter des webhooks ou des contrôles d’intégrité | `apiRoutes` |
| Activer la documentation d’API générée | `build.openAPIDocs` et `build.swaggerUI` |

Consultez [serveur Mastra](/docs/server/mastra-server), [middlewares](/docs/server/middleware) et [routes d’API personnalisées](/docs/server/custom-api-routes) pour des exemples.

## Priorité du code {/* #precedence-with-code */}

La configuration de serveur enregistrée dans le code est prioritaire sur `server.ts`. Les routes ajoutées au démarrage, telles que les webhooks de canal, sont conservées lors de l’application de la configuration de serveur basée sur les fichiers.
