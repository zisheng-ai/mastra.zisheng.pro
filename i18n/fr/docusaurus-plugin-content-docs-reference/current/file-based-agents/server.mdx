# Serveur

Mastra configures its HTTP [server](/docs/server/mastra-server) depuis a `server.ts` file directly under `src/mastra/`. The server exposes agents, workflows, et autre registered primitives comme REST endpoints, et the file default-exports the same `ServerConfig` shape you'd transmet à [`new Mastra()`](/reference/core/mastra-class).

Utilisez ce page pour the file-based convention. For server features, middleware, personnalisé routes, generated API docs, et deployment behavior, see [Serveur overview](/docs/server/mastra-server).

## Quickstart

Créer `src/mastra/server.ts` et default-export a `ServerConfig` object:

```typescript title="src/mastra/server.ts"
import type { ServerConfig } from '@mastra/core/server'

export default {
  port: 4111,
  host: '0.0.0.0',
} satisfies ServerConfig
```

## Courant configurations

`server.ts` peut configure the same server options comme code registration:

| Need | Use |
| - | - |
| Bind à a deployment platform address | `host` et `port` |
| Restrict browser access | `cors` |
| Ajouter webhooks ou health checks | `apiRoutes` |
| Actifr generated API docs | `build.openAPIDocs` et `build.swaggerUI` |

See [Mastra server](/docs/server/mastra-server), [middleware](/docs/server/middleware), et [custom API routes](/docs/server/custom-api-routes) pour examples.

## Precedence avec code

Code-registered server config wins over `server.ts`. Routes added during startup, such comme channel webhooks, sont preserved when file-based server config est applied.
