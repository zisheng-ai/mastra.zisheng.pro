# Tools

Un file-based agent discovers tools depuis `.ts` et `.js` files directly under its `tools/` directory. Chaque discovered file est imported à génère time, the file doit default-export a [`createTool()` reference](/reference/tools/create-tool) result, et the filename sans its extension becomes the Tool clé the modèle peut call.

Utilisez ce page pour the file-based convention. For Tool schemas, execution options, output shaping, et approval options, see the [Tool reference reference](/reference/tools/create-tool).

## Quickstart

Place un Tool per file under `tools/`. Ce file est exposed à the agent comme `get_weather`.

```typescript title="src/mastra/agents/weather/tools/get_weather.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export default createTool({
  id: 'get_weather',
  description: 'Get the current weather for a location.',
  inputSchema: z.object({
    location: z.string(),
  }),
  outputSchema: z.object({
    location: z.string(),
    temperatureCelsius: z.number(),
    conditions: z.string(),
  }),
  execute: async ({ location }) => {
    return { location, temperatureCelsius: 21, conditions: 'sunny' }
  },
})
```

## Organizing tools

Use un file per tool. Nom the file après the action the modèle doit take:

- Use `get_weather.ts`, `search_docs.ts`, ou `create_ticket.ts`.
- Avoid vague names like `helper.ts`, `api.ts`, ou `utils.ts`.
- Co-locate tests next à the Tool comme `*.test.ts` ou `*.spec.ts`. Discovery ignores those files.
- Keep shared helper code outside `tools/` ou dans files that don't match the discovered extensions under `tools/`.

Because nested directories aren't discovered comme tools, group related tools avec clear filename prefixes instead de subfolders, such comme `calendar_create_event.ts` et `calendar_list_events.ts`.

## Tool options

The file-based convention only controls where the Tool lives et how it's registered. Le Tool API still comes depuis `createTool()`:

- Use `description` à tell the modèle when à call the tool.
- Use `inputSchema` et `outputSchema` pour structured inputs et outputs.
- Use `toModelOutput` when the modèle doit see a different shape than the raw valeur returned depuis `execute`.
- Use `requireApproval` when a Tool needs human confirmation avant execution.

See the [Tool reference reference](/reference/tools/create-tool) pour tous les options et [tool approval](/docs/harness/agent-controller#approve-tools-and-resume-suspensions) pour the approval flow.

## Runtime boundary

Tool code runs dans your app/server runtime when the agent calls the tool. Si un Tool needs filesystem ou shell isolation, call [workspace](/reference/file-based-agents/workspace) ou sandbox APIs explicitly.

## Precedence avec config

Discovered tools merge avec tout `tools` dans [`config.ts`](/reference/file-based-agents/config). On a clé collision, `config.tools` wins et a warning est logged.

If `config.tools` est a function, discovered tools sont ignored avec a warning car function-valued tools can't be statically merged.
