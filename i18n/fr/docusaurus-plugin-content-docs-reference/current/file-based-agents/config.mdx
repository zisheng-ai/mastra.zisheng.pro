# config.ts

Un agent's `config.ts` sets its modèle et runtime options. Use it pour options that belong à the [`Agent`](/reference/agents/agent) itself, tandis que sibling files fournit instructions, tools, skills, et cetera.

## What belongs dans `config.ts`

`config.ts` est the requis entry point pour a file-based agent's modèle et runtime options. Put agent-level settings here when they don't need their own file, such comme the model, description, par défaut execution options, retry behavior, scorers, et affiche identity.

Keep adjacent concerns dans sibling files when you want file-based routing à merge them dans the agent. Par exemple, utilise `instructions.md` pour the always-on prompt et `tools/` pour model-callable actions.

## Quickstart

Les éléments suivants `config.ts` plus an `instructions.md` file creates a working file-based agent:

```typescript title="src/mastra/agents/weather/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

```markdown title="src/mastra/agents/weather/instructions.md"
You are a helpful weather assistant. Answer questions about current conditions and forecasts.
```

Mastra uses the `weather` directory nom comme the par défaut agent `id` et `name`. The sibling `instructions.md` supplies the requis instructions.

## Définir the model

The `model` field est the only requis field dans `agentConfig()`. The génère fails when an agent directory doesn't fournit a model. Other capabilities either come depuis sibling files ou ont defaults.

```typescript title="src/mastra/agents/weather/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

## Identity depuis the directory

Un file-based agent's `id` et `name` par défaut à the directory name. For `src/mastra/agents/weather/`, Mastra registers the agent comme `weather` unless you override those fields.

Override `id` ou `name` when the stable routing clé et the affiche nom doit differ.

```typescript title="src/mastra/agents/weather/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  id: 'weather-assistant',
  name: 'Weather Assistant',
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

## Définir runtime options

`agentConfig()` accepts [`Agent` constructor options constructor options](/reference/agents/agent#constructor-parameters), except that `id`, `name`, et sibling-file fields peut be supplied par the file-based convention. Utilisez le Agent reference pour the full option list.

Please note:

- Fichier-based subagents require a non-empty `description` car the parent modèle uses it pour delegation routing.
- `defaultOptions`, `maxRetries`, `scorers`, et autre Agent options peut live dans `config.ts` when they don't need their own file.

## Where adjacent settings live

Keep `config.ts` focused sur runtime options. Use sibling files pour concerns that benefit depuis their own location.

| Setting | Fichier ou folder | Why it lives there |
| - | - | - |
| Instructions | [`instructions.md` ou `instructions.ts`](/reference/file-based-agents/instructions) | Keeps the always-on prompt readable comme markdown, ou computed dans TypeScript |
| Tools | [`tools/`](/reference/file-based-agents/tools) | Gives chaque callable action its own typed module |
| Skills | [`skills/`](/reference/file-based-agents/skills) | Keeps load-on-demand procedures separate depuis always-on instructions |
| Mémoire | [`memory.ts`](/reference/file-based-agents/memory) | Configurer persistent memory sans crowding runtime options |
| Workspace | [`workspace.ts`](/reference/file-based-agents/workspace) | Configurer files et sandbox behavior separately depuis modèle settings |
| Processors | [`processors/`](/reference/file-based-agents/processors) | Separates input et output processing pipelines |
| Subagents | [`subagents/`](/reference/file-based-agents/subagents) | Gives chaque specialist child agent its own directory |

## Precedence

`config.ts` merges avec the agent's autre files according à these rules:

| Domain | Source Un | Source B | Winner |
| - | - | - | - |
| Instructions | Dynamique `config.instructions` | [`instructions.ts` ou `instructions.md`](/reference/file-based-agents/instructions) | Dynamique `config.instructions` |
| Instructions | Statique `config.instructions` | [`instructions.ts` ou `instructions.md`](/reference/file-based-agents/instructions) | The instructions file |
| Instructions | [`instructions.md`](/reference/file-based-agents/instructions) | [`instructions.md`](/reference/file-based-agents/instructions) | `instructions.ts` |
| Tools | `config.tools` | [`tools/`](/reference/file-based-agents/tools) | Both merge; `config.tools` wins sur clé collisions |
| Tools | Function `config.tools` | [`tools/`](/reference/file-based-agents/tools) | Function `config.tools`; discovered tools sont ignored |
| Skills | `config.skills` | [`skills/`](/reference/file-based-agents/skills) | Both merge; `config.skills` wins sur nom collisions |
| Skills | Function `config.skills` | [`skills/`](/reference/file-based-agents/skills) | Function `config.skills`; discovered skills sont ignored |
| Mémoire | `config.memory` | [`memory.ts`](/reference/file-based-agents/memory) | `config.memory` |
| Workspace | `config.workspace` | [`workspace.ts`](/reference/file-based-agents/workspace) | `config.workspace` |

Missing `instructions.md`, `instructions.ts`, et `config.instructions` fails the build. Missing both `config.memory` et `memory.ts` leaves the agent sans memory.

## Discovery lifecycle

Fichier-based primitives sont discovered par the Mastra bundler under `mastra dev` et `mastra build`. During discovery, Mastra reads pris en charge files under `src/mastra/`, imports TypeScript et JavaScript modules, reads markdown instructions et skills, copies workspace seed files, et registers the assembled primitives avec your Mastra app.

After discovery, a file-based agent runs comme a normal [`Agent`](/reference/agents/agent). Calling it depuis the Agent API, Studio, workflows, ou your application code uses the same runtime comme a code-defined agent.

Discovery est source-based et conservative.

It skips symlinks, test files, et directories that aren't agent directories. Workflows et singleton project files sont file-routed only when they ont a par défaut export.

Démarrer your app via the Mastra CLI so discovery runs:

```bash npm2yarn
npx mastra dev
```

Si vous import your `mastra` instance directly, `agents/<name>/` directories et the autre conventions aren't discovered. Lorsque vous consume Mastra comme a library, register those primitives dans code instead.
