# Studio

Mastra configure [Studio](/docs/studio/overview) à partir d’un fichier `studio.ts` directement sous `src/mastra/`. Le fichier exporte par défaut un objet `StudioConfig` pour l’authentification et l’autorisation de Studio : qui peut accéder à Studio et ce que les utilisateurs authentifiés peuvent faire.

Utilisez cette page pour la convention basée sur des fichiers. Pour les fournisseurs d’authentification, le contrôle d’accès basé sur les rôles (RBAC) et l’autorisation à grain fin (FGA), consultez [l’authentification de Studio](/docs/studio/auth).

## Démarrage rapide

Pour le développement local, vous n’avez pas besoin de `studio.ts`. Démarrez le serveur de développement et ouvrez Studio :

```bash npm2yarn
npm run dev
```

Studio s’ouvre sans authentification en développement local. Ajoutez `studio.ts` lorsque vous êtes prêt à sécuriser un déploiement partagé ou de production.

## Ajouter l’authentification

Utilisez un fournisseur d’authentification pour exiger une connexion avant que les utilisateurs puissent accéder à Studio. Cet exemple utilise [WorkOS](/docs/server/auth/workos) :

```typescript title="src/mastra/studio.ts"
import { MastraAuthWorkos } from '@mastra/auth-workos'
import type { StudioConfig } from '@mastra/core/server'

export default {
  auth: new MastraAuthWorkos(),
} satisfies StudioConfig
```

Le fournisseur d’authentification détermine l’identité de l’utilisateur. Pour définir ce que l’utilisateur peut faire après la connexion, ajoutez RBAC ou FGUn dans la même configuration. Consultez [l’authentification de Studio](/docs/studio/auth) pour des exemples complets.

## Priorité du code

La configuration Studio enregistrée dans le code est prioritaire sur `studio.ts`. Utilisez `studio.ts` lorsqu’une seule configuration Studio pour l’ensemble du projet suffit. Utilisez l’enregistrement dans le code lorsque l’authentification dépend d’un câblage à l’exécution dans `src/mastra/index.ts`.
