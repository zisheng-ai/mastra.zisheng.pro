# Logger

Mastra configure le [logger](/docs/observability/logging) du projet à partir d’un fichier `logger.ts` placé directement dans `src/mastra/`. Le fichier exporte par défaut un logger, qui remplace le `ConsoleLogger` intégré utilisé par les agents, les Workflows et les autres composants.

Utilisez cette page pour la convention basée sur les fichiers. Pour les niveaux de journalisation, les transports et les détails des Providers, consultez la page [journalisation](/docs/observability/logging).

## Démarrage rapide

Créez `src/mastra/logger.ts` et exportez par défaut un logger, tel que [`PinoLogger`](/reference/logging/pino-logger) :

```typescript title="src/mastra/logger.ts"
import { PinoLogger } from '@mastra/loggers'

export default new PinoLogger({
  name: 'Mastra',
  level: 'info',
})
```

Mastra enregistre le logger avant le stockage, l’observabilité et les agents basés sur des fichiers, afin que ces éléments l’utilisent lorsqu’ils sont configurés.

## Priorité du code

La journalisation enregistrée dans le code est prioritaire sur `logger.ts`. Si vous transmettez `logger` à `new Mastra({ logger })` dans `src/mastra/index.ts` (ou définissez `logger: false` pour désactiver la journalisation), `logger.ts` est ignoré avec un avertissement. Utilisez `logger.ts` lorsqu’un seul logger à l’échelle du projet suffit. Utilisez l’enregistrement dans le code lorsque la configuration dépend du câblage au moment de l’exécution.
