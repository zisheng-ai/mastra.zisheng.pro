# Instructions

Un agent's instructions hold its always-on system prompt: the modèle reads it sur every turn. Utilisez lem à define the agent's identity, tone, role, et standing rules.

Write them dans un de deux files à the agent root. Use `instructions.md` when the prompt est fixed text. Use `instructions.ts` when the prompt needs code, pour example when it's built depuis shared constants ou resolved per request.

Instructions sont always dans context, so keep them pour stable behavior that applies à every request. Move anything conditional, large, ou action-oriented dans [`tools/`](/reference/file-based-agents/tools) ou [`skills/`](/reference/file-based-agents/skills), which the modèle uses only when relevant.

## Quickstart

Ajouter an `instructions.md` à the agent root. Whatever you write becomes the prompt, so the shortest version est a unique sentence.

```markdown title="src/mastra/agents/weather/instructions.md"
You are a helpful weather assistant. Answer questions about current conditions and forecasts.
```

## What goes dans instructions

Effective instructions cover the parts de an agent's behavior that don't change entre requests:

- Role et identity
- Tone et style
- Standing rules
- Sortie format

Move conditional, large, ou action-oriented guidance dans [`tools/`](/reference/file-based-agents/tools) ou [`skills/`](/reference/file-based-agents/skills), which the modèle uses only when relevant.

## Instructions dans TypeScript

Use `instructions.ts` when markdown can't express the prompt. The file default-exports a string, a system message, ou a fonction returning one, et `agentInstructions()` types the export sans changing it.

Exporter a chaîne when the prompt est assembled dans code, pour example depuis constants shared avec the rest de your app:

```typescript title="src/mastra/agents/weather/instructions.ts"
import { agentInstructions } from '@mastra/core/agent'
import { SUPPORTED_UNITS } from '../../constants'

export default agentInstructions(`
You are a helpful weather assistant.
Report conditions using one of these units: ${SUPPORTED_UNITS.join(', ')}.
`)
```

Exporter a fonction when the prompt depends sur the request. Mastra calls it sur every turn et passes the requête context:

```typescript title="src/mastra/agents/support/instructions.ts"
import { agentInstructions } from '@mastra/core/agent'

export default agentInstructions(({ requestContext }) => {
  const tier = requestContext.get('tier') ?? 'standard'
  return `You are a support agent. Treat this as a ${tier}-tier customer.`
})
```

La fonction peut be `async` et receives `mastra` alongside `requestContext`, so it peut read depuis storage ou un autre registered primitive avant returning the prompt.

Both files peut also live dans a [subagent](/reference/file-based-agents/subagents) directory, which follows the same rules.

## Compilation-time behavior

`instructions.md` et `instructions.ts` reach the deployed agent differently:

- `instructions.md`: Mastra reads the file et inlines its contents dans the generated code à génère time.
- `instructions.ts`: The generated code imports the module, so it's bundled like tout autre TypeScript file et peut import depuis the rest de your project.

Under `mastra dev`, editing either file triggers a rebuild. In a deployed app neither file est read depuis disk à runtime, so changes take effect après the next build.

## Precedence avec config

Instructions peut come depuis `instructions.ts`, `instructions.md`, ou the `instructions` field dans [`config.ts`](/reference/file-based-agents/config):

- Un runtime-defined (function) `instructions` dans `config.ts` wins over both files.
- Otherwise `instructions.ts` wins over `instructions.md`.
- `instructions.md` wins over a static `instructions` chaîne dans `config.ts`.
- Si aucunne est present, the génère fails et names the agent directory.

Defining instructions dans more than un place logs a warning that names both sources et which un wins. Keep un source per agent.
