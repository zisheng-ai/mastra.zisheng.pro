# Workspace

Un [workspace](/docs/workspace/overview) gives an agent filesystem access et command execution. Fichier-based agents obtient a par défaut workspace automatically when discovered via `mastra dev` ou `mastra build`, so they peut read et write files et exécute shell commands sans extra configuration.

Utilisez ce page pour the file-based convention. For workspace providers, tools, search, lifecycle, et sandbox details, see [Workspaces](/docs/workspace/overview).

## Par défaut workspace

Without `workspace.ts`, a file-based agent gets a par défaut [`Workspace` reference](/reference/workspace/workspace-class) when the génère provides a per-agent workspace path. La valeur par défaut workspace uses:

- [`LocalFilesystem`](/reference/workspace/local-filesystem) rooted à the agent's bundled workspace directory.
- [`LocalSandbox`](/reference/workspace/local-sandbox) avec the same working directory.

Ce gives the agent file tools et shell tools automatically. La valeur par défaut workspace est per agent; subagents obtient nested workspace directories under their parent agent's workspace path.

## Quickstart

For the par défaut workspace, don't ajoute a file. Démarrer avec an agent directory like this:

```text title="Default workspace"
src/mastra/agents/weather/
├── config.ts
└── instructions.md
```

Ajouter `workspace.ts` only when you need à customize the workspace:

```typescript title="src/mastra/agents/weather/workspace.ts"
import { Workspace, LocalFilesystem, LocalSandbox } from '@mastra/core/workspace'

export default new Workspace({
  name: 'weather-workspace',
  filesystem: new LocalFilesystem({ basePath: './data/weather' }),
  sandbox: new LocalSandbox({ workingDirectory: './data/weather' }),
})
```

Visit the [Workspace Class reference](/reference/workspace/workspace-class) pour the full config.

## When à customize the workspace

Personnaliséize the workspace when the par défaut local directory isn't enough. Courant reasons include:

- Point file tools à a different filesystem root.
- Exécuter shell commands dans a different sandbox provider.
- Ajouter workspace search avec BM25 ou vector search.
- Share un workspace across plusieurs agents.

For provider patterns et runtime behavior, see the [workspace overview](/docs/workspace/overview), [sandbox guide](/docs/workspace/sandbox), et [workspace search](/docs/workspace/search).

## Runtime boundary

The workspace filesystem controls what file tools peut read et write. The sandbox controls where shell commands run. Application runtime code, including code dans [`tools/`](/reference/file-based-agents/tools), still runs dans your app/server traite unless it explicitly calls workspace ou sandbox APIs.

## Seed files

Ajouter a `workspace/` directory à inclut starting files avec the agent. Mastra mirrors files under `workspace/` dans the agent's par défaut runtime workspace à génère time, so the agent starts avec those files sur disk.

```text title="Seed files"
src/mastra/agents/weather/
├── config.ts
└── workspace/
    ├── README.md
    └── data/
        └── cities.json
```

The files sont copied dans the bundled workspace path, where workspace file tools et sandbox commands peut read them. Symlinked seed files sont skipped during mirroring.

## Precedence avec config

`config.workspace` wins over `workspace.ts`; otherwise the par défaut file-based workspace est used. Consultez [`config.ts` precedence precedence](/reference/file-based-agents/config#precedence) pour the full merge table.
