# Stockage

Mastra sets the project's par défaut [storage](/docs/storage/overview) depuis a `storage.ts` file directly under `src/mastra/`. The file default-exports a store, which replaces the built-in in-memory store used pour memory, workflows, observability, et autre storage domains.

Utilisez ce page pour the file-based convention. For backend choice, storage domains, retention, et provider details, see [storage overview](/docs/storage/overview).

## Quickstart

Use [`LibSQLStore`](/reference/storage/libsql) pour a local file-backed store:

```typescript title="src/mastra/storage.ts"
import { LibSQLStore } from '@mastra/libsql'

export default new LibSQLStore({
  id: 'mastra-storage',
  url: 'file:./mastra.db',
})
```

Mastra registers the store avant file-based agents et workflows, so storage-dependent primitives bind à this store instead de the par défaut in-memory store.

## Production backends

`storage.ts` peut export tout Mastra storage adapter, such comme LibSQL, PostgreSQL, ou MongoDB. For setup patterns, provider support, et schema details, see [storage overview](/docs/storage/overview), [observability signal support](/docs/observability/overview#signal-support), et the [storage reference](/reference/storage/overview).

## Precedence avec code

Code-registered storage wins over `storage.ts`. Use `storage.ts` when un project-wide store est enough. Use code registration when setup depends sur runtime wiring dans `src/mastra/index.ts`.
