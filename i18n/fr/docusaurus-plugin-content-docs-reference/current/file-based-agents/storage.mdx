# Storage

Mastra configure le [stockage](/docs/storage/overview) par défaut du projet à partir d’un fichier `storage.ts` placé directement dans `src/mastra/`. Le fichier exporte par défaut un magasin, qui remplace le magasin en mémoire intégré utilisé pour la mémoire, les Workflows, l’observabilité et les autres domaines de stockage.

Utilisez cette page pour la convention basée sur les fichiers. Pour le choix du backend, les domaines de stockage, la rétention et les détails des Providers, consultez la [présentation du stockage](/docs/storage/overview).

## Démarrage rapide {/* #quickstart */}

Utilisez [`LibSQLStore`](/reference/storage/libsql) pour un magasin local adossé à un fichier :

```typescript title="src/mastra/storage.ts"
import { LibSQLStore } from '@mastra/libsql'

export default new LibSQLStore({
  id: 'mastra-storage',
  url: 'file:./mastra.db',
})
```

Mastra enregistre le magasin avant les agents basés sur des fichiers et les Workflows, afin que les éléments qui dépendent du stockage utilisent ce magasin plutôt que le magasin en mémoire par défaut.

## Backends de production {/* #production-backends */}

`storage.ts` peut exporter n’importe quel adaptateur de stockage Mastra, tel que LibSQL, PostgreSQL ou MongoDB. Pour les modèles de configuration, la prise en charge des Providers et les détails de schéma, consultez la [présentation du stockage](/docs/storage/overview), la [prise en charge des signaux d’observabilité](/docs/observability/overview#signal-support) et la [référence du stockage](/reference/storage/overview).

## Priorité du code {/* #precedence-with-code */}

Le stockage enregistré dans le code est prioritaire sur `storage.ts`. Utilisez `storage.ts` lorsqu’un seul magasin à l’échelle du projet suffit. Utilisez l’enregistrement dans le code lorsque la configuration dépend du câblage au moment de l’exécution dans `src/mastra/index.ts`.
