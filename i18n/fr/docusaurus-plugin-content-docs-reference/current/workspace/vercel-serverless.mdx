# VercelServerlessSandbox

Exécute des commandes sous forme de fonctions serverless [Vercel](https://vercel.com). Fournit une exécution distribuée à l’échelle mondiale, sans infrastructure et avec mise à l’échelle automatique. Pour en savoir plus sur l’interface, consultez l’[interface WorkspaceSandbox](/reference/workspace/sandbox).

:::warning

VercelServerlessSandbox est sans état. Il ne fournit ni système de fichiers persistant, ni shell interactif, ni processus d’arrière-plan de longue durée. Seul `/tmp` est accessible en écriture et son contenu est éphémère entre les appels.

:::

:::note

Pour disposer d’une MicroVM Linux complète avec un système de fichiers persistant, un accès `sudo`, des ports exposés et des processus d’arrière-plan, utilisez [`VercelSandbox`](/reference/workspace/vercel-sandbox), qui repose sur le produit [Vercel Sandbox](https://vercel.com/docs/vercel-sandbox).

:::

## Installation {/* #installation */}

```bash npm2yarn
npm install @mastra/vercel
```

## Utilisation {/* #usage */}

Ajoutez un `VercelServerlessSandbox` à un Workspace et attribuez-le à un Agent :

```typescript
import { Agent } from '@mastra/core/agent'
import { Workspace } from '@mastra/core/workspace'
import { VercelServerlessSandbox } from '@mastra/vercel'

const workspace = new Workspace({
  sandbox: new VercelServerlessSandbox({
    token: process.env.VERCEL_TOKEN,
  }),
})

const agent = new Agent({
  id: 'dev-agent',
  name: 'dev-agent',
  instructions: 'You are a coding assistant working in this workspace.',
  model: '__GATEWAY_ANTHROPIC_MODEL_SONNET__',
  workspace,
})
```

### Déploiement limité à une équipe avec des ressources personnalisées {/* #team-scoped-deployment-with-custom-resources */}

```typescript
const workspace = new Workspace({
  sandbox: new VercelServerlessSandbox({
    token: process.env.VERCEL_TOKEN,
    teamId: 'team_abc123',
    regions: ['iad1', 'sfo1'],
    maxDuration: 120,
    memory: 3008,
    env: {
      NODE_ENV: 'production',
    },
  }),
})
```

## Limites {/* #limitations */}

VercelServerlessSandbox utilise des fonctions serverless en interne, ce qui implique les limites suivantes :

- **Aucun système de fichiers persistant** : les fichiers écrits dans `/tmp` sont éphémères et supprimés entre les appels.
- **Aucun shell interactif** : les commandes sont exécutées au moyen de `/bin/sh -c`, sans streaming de stdin.
- **Aucun processus d’arrière-plan** : aucun gestionnaire de processus, PID ou tâche de longue durée.
- **Aucun montage** : le montage de stockages cloud (S3, GCS) n’est pas pris en charge.
- **Limites de délai d’expiration** : la durée maximale d’exécution est limitée par `maxDuration` (60 s par défaut).
