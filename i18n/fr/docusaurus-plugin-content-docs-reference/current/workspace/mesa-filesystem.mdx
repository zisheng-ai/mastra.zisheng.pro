# MesaFilesystem

Stocke les fichiers du Workspace dans des dépôts [Mesa](https://docs.mesa.dev/content/getting-started/introduction) au moyen de l’interface Mastra standard `WorkspaceFilesystem`.

Utilisez `MesaFilesystem` lorsque des Agents ont besoin d’un stockage de fichiers versionné. Pour un répertoire local, utilisez [`LocalFilesystem`](/reference/workspace/local-filesystem). Pour le stockage d’objets, utilisez [`S3Filesystem`](/reference/workspace/s3-filesystem), [`GCSFilesystem`](/reference/workspace/gcs-filesystem) ou [`AzureBlobFilesystem`](/reference/workspace/azure-blob-filesystem).

:::info

`MesaFilesystem` s’exécute dans le processus Mastra.

Le [montage POSIX de Mesa](https://docs.mesa.dev/content/mesafs/posix-mount) (permettant d’utiliser un système de fichiers Mesa dans un Sandbox) ne fait pas encore partie du package `@mastra/mesa`. Sa prise en charge sera bientôt disponible.

:::

## Installation {/* #installation */}

```bash npm2yarn
npm install @mastra/mesa
```

## Exemple d’utilisation {/* #usage-example */}

Montez un dépôt Mesa et transmettez le système de fichiers à un Workspace :

```typescript title="src/mastra/workspace.ts"
import { Agent } from '@mastra/core/agent'
import { Workspace } from '@mastra/core/workspace'
import { MesaFilesystem } from '@mastra/mesa'

const workspace = new Workspace({
  filesystem: new MesaFilesystem({
    apiKey: process.env.MESA_API_KEY,
    org: 'acme',
    repos: [{ name: 'docs', bookmark: 'main' }],
  }),
})

const agent = new Agent({
  id: 'file-agent',
  name: 'file-agent',
  model: '__GATEWAY_ANTHROPIC_MODEL_OPUS__',
  workspace,
})
```

Lorsque `apiKey` est omis, `MESA_API_KEY` est utilisée comme valeur de repli.

## Méthodes {/* #methods */}

`MesaFilesystem` implémente l’[interface WorkspaceFilesystem](/reference/workspace/filesystem).

### Opérations sur les fichiers {/* #file-operations */}

#### `readFile(path, options?)` {/* #readfilepath-options */}

Lit un fichier depuis Mesa.

```typescript
const content = await filesystem.readFile('/acme/docs/README.md', {
  encoding: 'utf-8',
})
```

Renvoie : `Promise<string | Buffer>`

#### `writeFile(path, content, options?)` {/* #writefilepath-content-options */}

Écrit un fichier dans Mesa.

```typescript
await filesystem.writeFile('/acme/docs/report.md', '# Report')
```

Renvoie : `Promise<void>`

#### `appendFile(path, content)` {/* #appendfilepath-content */}

Ajoute du contenu à la fin d’un fichier.

```typescript
await filesystem.appendFile('/acme/docs/log.txt', 'new line\n')
```

Renvoie : `Promise<void>`

#### `deleteFile(path, options?)` {/* #deletefilepath-options */}

Supprime un fichier.

```typescript
await filesystem.deleteFile('/acme/docs/old-report.md')
```

Renvoie : `Promise<void>`

#### `copyFile(src, dest, options?)` {/* #copyfilesrc-dest-options */}

Copie un fichier.

```typescript
await filesystem.copyFile('/acme/docs/report.md', '/acme/docs/archive/report.md')
```

Renvoie : `Promise<void>`

#### `moveFile(src, dest, options?)` {/* #movefilesrc-dest-options */}

Déplace ou renomme un fichier.

```typescript
await filesystem.moveFile('/acme/docs/draft.md', '/acme/docs/final.md')
```

Renvoie : `Promise<void>`

### Opérations sur les répertoires {/* #directory-operations */}

#### `mkdir(path, options?)` {/* #mkdirpath-options */}

Crée un répertoire.

```typescript
await filesystem.mkdir('/acme/docs/reports', { recursive: true })
```

Renvoie : `Promise<void>`

#### `rmdir(path, options?)` {/* #rmdirpath-options */}

Supprime un répertoire.

```typescript
await filesystem.rmdir('/acme/docs/reports', { recursive: true })
```

Renvoie : `Promise<void>`

#### `readdir(path, options?)` {/* #readdirpath-options */}

Répertorie les entrées d’un répertoire.

```typescript
const entries = await filesystem.readdir('/acme/docs', {
  recursive: true,
  extension: '.md',
})
```

Renvoie : `Promise<FileEntry[]>`

### Opérations sur les chemins {/* #path-operations */}

#### `exists(path)` {/* #existspath */}

Vérifie si un chemin existe.

```typescript
const exists = await filesystem.exists('/acme/docs/README.md')
```

Renvoie : `Promise<boolean>`

#### `stat(path)` {/* #statpath */}

Renvoie les métadonnées d’un fichier ou d’un répertoire.

```typescript
const stat = await filesystem.stat('/acme/docs/README.md')
```

Renvoie : `Promise<FileStat>`

#### `realpath(path)` {/* #realpathpath */}

Renvoie le chemin canonique fourni par Mesa.

```typescript
const realPath = await filesystem.realpath('/acme/docs/README.md')
```

Renvoie : `Promise<string>`

### Opérations Mesa {/* #mesa-operations */}

#### `bash(options?)` {/* #bashoptions */}

Crée un environnement d’exécution Bash reposant sur Mesa pour ce système de fichiers.

```typescript
const bash = await filesystem.bash({
  cwd: '/acme/docs',
})
```

Renvoie : `Promise<Bash>`

## Sémantique des chemins {/* #path-semantics */}

Les méthodes attendent des chemins absolus. Pour `MesaFilesystem`, les chemins ont pour racine le montage Mesa et doivent inclure le slug de l’organisation ainsi que le nom du dépôt :

```typescript
await filesystem.readFile('/acme/docs/README.md')
```

N’omettez pas la barre oblique initiale :

```typescript
await filesystem.readFile('acme/docs/README.md') // Incorrect
await filesystem.readFile('/acme/docs/README.md') // Correct
```

L’organisation provient de `org` dans le constructeur ou, lorsque `org` est omis, de l’inférence de l’organisation par défaut du SDK Mesa. Elle reste le premier segment du chemin.

Lorsque vous montez plusieurs dépôts, chacun d’eux est disponible sous le segment de l’organisation :

```typescript
const filesystem = new MesaFilesystem({
  org: 'acme',
  repos: [
    { name: 'docs', bookmark: 'main' },
    { name: 'website', bookmark: 'main' },
  ],
})

await filesystem.readFile('/acme/docs/README.md')
await filesystem.readFile('/acme/website/package.json')
```

## API de versionnement Mesa {/* #mesa-versioning-apis */}

Accédez au système de fichiers Mesa sous-jacent pour effectuer les opérations de changement et de signet propres à Mesa :

```typescript
await filesystem.writeFile('/acme/docs/draft.md', 'Draft')

const current = await filesystem.change.current({
  repo: 'docs',
})

await filesystem.bookmark.move({
  repo: 'docs',
  name: 'main',
  changeId: current.changeId,
})
```

Pour en savoir plus sur la sémantique du versionnement, consultez la [documentation de Mesa](https://docs.mesa.dev/content/concepts/versioning).

## Mode lecture seule {/* #read-only-mode */}

Définissez `readOnly: true` pour bloquer les opérations d’écriture via Mastra :

```typescript
const filesystem = new MesaFilesystem({
  repos: [{ name: 'docs', bookmark: 'main' }],
  readOnly: true,
})
```

Les opérations de lecture continuent de fonctionner. Les opérations d’écriture déclenchent `WorkspaceReadOnlyError`.

## Accès concurrent {/* #concurrency */}

`overwrite: false` et `expectedMtime` utilisent des vérifications préalables avant l’écriture. Ces vérifications ne sont pas atomiques, sauf si Mesa ajoute des écritures conditionnelles natives pour les montages d’application.
