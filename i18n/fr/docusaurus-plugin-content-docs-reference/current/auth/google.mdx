# MastraAuthGoogle et MastraRBACGoogle class

## MastraAuthGoogle class

The `MastraAuthGoogle` class provides authentication pour Mastra using Google Workspace. It implements an OAuth 2.0 / OIDC login flow avec encrypted session cookies, verifies Google ID tokens, et integrates avec the Mastra server using the `auth` option.

### Exemple d’utilisation

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthGoogle } from '@mastra/auth-google'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthGoogle({
      clientId: process.env.GOOGLE_CLIENT_ID,
      clientSecret: process.env.GOOGLE_CLIENT_SECRET,
      redirectUri: process.env.GOOGLE_REDIRECT_URI,
      allowedDomains: ['example.com'],
    }),
  },
})
```

:::note

Vous pouvez omit the constructor parameters if the requis environment variables sont set. In that case, utilise `new MastraAuthGoogle()` sans tout arguments.

:::

### Authentification flow

`MastraAuthGoogle` authenticates requests dans the following order:

1. **Session cookie.** With SSO enabled, the provider reads et decrypts the encrypted session cookie. Un valid, unexpired session authenticates the user.
1. **Google ID token fallback**: Si aucun valid session cookie est present, verifies the `Authorization` header token against Google's JWKS endpoint.

After authentication, `authorizeUser` checks that the utilisateur possède a valid Google utilisateur ID, the token-derived expiration hasn't passed, et the user's verified `hd` claim matches `allowedDomains` when domains sont configured.

### Authentification methods

#### `authenticateToken(token, request?)`

Authenticates a Google ID token. When SSO est enabled, this method checks the encrypted session cookie avant it verifies the Bearer token.

```typescript
const user = await auth.authenticateToken(idToken, request)
```

Renvoie: `Promise<GoogleUser | null>`

#### `getCurrentUser(request)`

Renvoie the authenticated utilisateur depuis a session cookie ou Bearer Google ID token.

```typescript
const user = await auth.getCurrentUser(request)
```

Renvoie: `Promise<GoogleUser | null>`

#### `authorizeUser(user)`

Renvoie `true` when the utilisateur possède an ID, hasn't expired, et matches `allowedDomains` when domains sont configured.

```typescript
const allowed = auth.authorizeUser(user)
```

Renvoie: `boolean`

#### `getUser(userId)`

Renvoie `null`. Google ID tokens sont verified directly, so this provider doesn't perform utilisateur lookup par ID.

```typescript
const user = await auth.getUser(userId)
```

Renvoie: `Promise<GoogleUser | null>`

## MastraRBACGoogle class

The `MastraRBACGoogle` class maps Google Workspace groups à Mastra permissions. It fetches utilisateur groups depuis the Google Admin SDK Directory API et resolves them against a configurable role mapping. Use it avec `MastraAuthGoogle` ou tout autre auth provider.

:::note

RBAC requires a valid Enterprise Edition license. It works sans a license dans development so you peut try it locally, mais you'll need a license pour production. [Contact sales](https://mastra.ai/contact) pour more information.

:::

### Exemple d’utilisation

Use `MastraRBACGoogle` alongside an auth provider par passing it à the `rbac` option:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthGoogle, MastraRBACGoogle } from '@mastra/auth-google'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthGoogle(),
    rbac: new MastraRBACGoogle({
      serviceAccount: {
        clientEmail: process.env.GOOGLE_SERVICE_ACCOUNT_EMAIL!,
        privateKey: process.env.GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY!,
        subject: process.env.GOOGLE_WORKSPACE_ADMIN_EMAIL!,
      },
      roleMapping: {
        'admins@example.com': ['*'],
        'engineering@example.com': ['agents:*', 'workflows:*', 'tools:*'],
        'viewers@example.com': ['agents:read', 'workflows:read'],
        _default: [],
      },
    }),
  },
})
```

Pour utiliser Google Workspace RBAC avec a different auth provider, transmet a `getUserKey` fonction à résout the Google Directory API utilisateur clé depuis the autre provider's utilisateur object:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthAuth0 } from '@mastra/auth-auth0'
import { MastraRBACGoogle } from '@mastra/auth-google'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthAuth0(),
    rbac: new MastraRBACGoogle({
      getUserKey: user => user.email,
      serviceAccount: {
        clientEmail: process.env.GOOGLE_SERVICE_ACCOUNT_EMAIL!,
        privateKey: process.env.GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY!,
        subject: process.env.GOOGLE_WORKSPACE_ADMIN_EMAIL!,
      },
      roleMapping: {
        'engineering@example.com': ['agents:*', 'workflows:*'],
        'admins@example.com': ['*'],
        _default: [],
      },
    }),
  },
})
```

### RBAC methods

#### `getRoles(user)`

Renvoie Google Workspace group role IDs pour a user.

```typescript
const roles = await rbac.getRoles(user)
```

Renvoie: `Promise<string[]>`

#### `getPermissions(user)`

Renvoie Mastra permissions resolved depuis Google Workspace groups et `roleMapping`.

```typescript
const permissions = await rbac.getPermissions(user)
```

Renvoie: `Promise<string[]>`

#### `hasPermission(user, permission)`

Vérifie whether a utilisateur possède a permission.

```typescript
const canReadAgents = await rbac.hasPermission(user, 'agents:read')
```

Renvoie: `Promise<boolean>`

#### `hasRole(user, role)`

Vérifie whether a utilisateur resolved à a specific Google Workspace group role.

```typescript
const isAdmin = await rbac.hasRole(user, 'admins@example.com')
```

Renvoie: `Promise<boolean>`

#### `hasAllPermissions(user, permissions)`

Vérifie whether a utilisateur possède every requested permission.

```typescript
const canManageAgents = await rbac.hasAllPermissions(user, ['agents:read', 'agents:update'])
```

Renvoie: `Promise<boolean>`

#### `hasAnyPermission(user, permissions)`

Vérifie whether a utilisateur possède à least un requested permission.

```typescript
const canReadSomething = await rbac.hasAnyPermission(user, ['agents:read', 'workflows:read'])
```

Renvoie: `Promise<boolean>`

#### `getAvailableRoles()`

Renvoie the role IDs configuré dans `roleMapping`, excluding `_default`.

```typescript
const roles = await rbac.getAvailableRoles()
```

Renvoie: `Promise<{ id: string; name: string }[]>`

#### `getPermissionsForRole(roleId)`

Renvoie the permissions configuré pour a role ID.

```typescript
const permissions = await rbac.getPermissionsForRole('engineering@example.com')
```

Renvoie: `Promise<string[]>`

#### `clearCache()`

Clears tous les cached Google Workspace group lookups.

```typescript
rbac.clearCache()
```

Renvoie: `void`

#### `clearUserCache(userKey)`

Clears the cached group lookup pour un Directory API utilisateur key, such comme an email address.

```typescript
rbac.clearUserCache('user@example.com')
```

Renvoie: `void`

#### `getCacheStats()`

Renvoie the actuel group lookup cache size et maximum size.

```typescript
const stats = rbac.getCacheStats()
```

Renvoie: `{ size: number; maxSize: number }`

### Supplémentaire configuration

`MastraRBACGoogle` uses `GET https://admin.googleapis.com/admin/directory/v1/groups?userKey=...` et handles pagination. Fournir a service account avec domain-wide delegation pour production Google Workspace deployments, ou transmet `accessToken` / `getAccessToken` if your application already manages Google Jetons d’API.

If `user.groups` est already an array, `MastraRBACGoogle` uses that valeur et doesn't call the Directory API. Un vide `groups` tableau means the utilisateur possède aucun Google group roles et resolves à `_default` permissions when `_default` est configured.

`MastraRBACGoogle` doesn't automatically read service-account environment variables. Pass service-account credentials via the `serviceAccount` option, ou transmet `accessToken` / `getAccessToken`.
