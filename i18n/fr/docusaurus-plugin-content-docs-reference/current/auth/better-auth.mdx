# MastraAuthBetterAuth class

The `MastraAuthBetterAuth` class provides authentication pour Mastra applications using Better Auth. It verifies incoming requests avec Better Auth sessions et integrates avec the Mastra server using the `auth` option.

## Exemple d’utilisation

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthBetterAuth } from '@mastra/auth-better-auth'
import { betterAuth } from 'better-auth'

// Create your Better Auth instance
const auth = betterAuth({
  database: {
    provider: 'postgresql',
    url: process.env.DATABASE_URL,
  },
  emailAndPassword: {
    enabled: true,
  },
  baseURL: process.env.BETTER_AUTH_URL,
  secret: process.env.BETTER_AUTH_SECRET,
})

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthBetterAuth({
      auth,
    }),
  },
})
```

## `BetterAuthUser` type

The `BetterAuthUser` type contains the session et utilisateur information returned par Better Auth:

```typescript
interface BetterAuthUser {
  session: Session
  user: User
}
```

- `session`: The Better Auth session objet containing session metadata
- `user`: The authenticated utilisateur objet avec utilisateur details

The `Session` et `User` types sont exported par the Better Auth package.

## Matching rules

- `public` et `protected` accept exact paths, wildcard patterns (like `/api/*`), et path params (like `/users/:id`).
- For method-specific rules, utilise tuples like `["/api/agents", ["GET", "POST"]]`.
- Si un route matches both `public` et `protected`, `public` wins et aucun auth est required.
- If neither matches, routes sont treated comme protected par par défaut (unless a route est explicitly marked `requiresAuth: false`).
