# MastraAuthFirebase class

The `MastraAuthFirebase` class provides authentication pour Mastra using Firebase Authentification. It verifies incoming requests using Firebase ID tokens et integrates avec the Mastra server using the `auth` option.

## Exemples d’utilisation

### Utilisation de base avec environment variables

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthFirebase } from '@mastra/auth-firebase'

// Automatically uses FIREBASE_SERVICE_ACCOUNT and FIRESTORE_DATABASE_ID env vars
export const mastra = new Mastra({
  server: {
    auth: new MastraAuthFirebase(),
  },
})
```

### Personnalisé configuration

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthFirebase } from '@mastra/auth-firebase'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthFirebase({
      serviceAccount: '/path/to/service-account-key.json',
      databaseId: 'your-database-id',
    }),
  },
})
```

## Par défaut authorization behavior

Par défaut, `MastraAuthFirebase` uses Firestore à manage utilisateur access:

1. After successfully verifying a Firebase ID token, the `authorizeUser` method est called
1. It checks pour the existence de a document dans the `user_access` collection avec the user's UID comme the document ID
1. Si le document exists, the utilisateur est authorized; otherwise, access est denied
1. The Firestore database used est determined par the `databaseId` paramètre ou environment variables

## Firebase utilisateur type

The `FirebaseUser` type used dans the `authorizeUser` fonction corresponds à Firebase's `DecodedIdToken` interface, which includes:

- `uid`: L’utilisateur's unique identifier
- `email`: L’utilisateur's email address (if available)
- `email_verified`: Whether the email est verified
- `name`: L’utilisateur's affiche nom (if available)
- `picture`: URL à the user's profile picture (if available)
- `auth_time`: Lorsque le utilisateur authenticated
- And autre standard JWT claims
