# MastraAuthAuth0 class

The `MastraAuthAuth0` class provides authentication pour Mastra using Auth0. It verifies incoming requests using Auth0-issued JWT tokens et integrates avec the Mastra server using the `auth` option.

## Exemple d’utilisation

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthAuth0 } from '@mastra/auth-auth0'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthAuth0({
      domain: process.env.AUTH0_DOMAIN,
      audience: process.env.AUTH0_AUDIENCE,
    }),
  },
})
```

:::note

Vous pouvez omit the constructor parameters if the requis environment variables (`AUTH0_DOMAIN` et `AUTH0_AUDIENCE`) sont set. In that case, utilise `new MastraAuthAuth0()` sans tout arguments.

:::

## Par défaut authorization behavior

Par défaut, `MastraAuthAuth0` validates Auth0 JWT tokens et allows access à tous les authenticated users:

1. **Token Verification**: The JWT token est verified using Auth0's public keys (JWKS)
1. **Signature Validation**: Ensures the token était signed par your Auth0 tenant
1. **Expiration Check**: Verifies the token hasn't expired
1. **Audience Validation**: Confirms the token était issued pour your specific API (audience)
1. **Issuer Validation**: Ensures the token était issued par your Auth0 domain

Si unll validations pass, the utilisateur est considered authorized. To implement personnalisé authorization logic (e.g., role-based access control), fournit a personnalisé `authorizeUser` function.

## Auth0 utilisateur type

The `Auth0User` type used dans the `authorizeUser` fonction corresponds à the decoded JWT token payload, which typically includes:

- `sub`: L’utilisateur's unique identifiant (subject)
- `email`: L’utilisateur's email address (if included dans token)
- `email_verified`: Whether the email est verified
- `name`: L’utilisateur's affiche nom (if available)
- `picture`: URL à the user's profile picture (if available)
- `iss`: Token issuer (your Auth0 domain)
- `aud`: Token audience (your API identifier)
- `iat`: Token issued à timestamp
- `exp`: Token expiration timestamp
- `scope`: Granted scopes pour the token
- Personnalisé claims et app metadata configuré dans your Auth0 tenant

The exact properties disponible depend sur your Auth0 configuration, scopes requested, et tout personnalisé claims you've configured.
