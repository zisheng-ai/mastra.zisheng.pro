# Deployment

Le point de terminaison de spécification OpenAPI a été déplacé vers `/api/openapi.json` et la configuration de `CloudflareDeployer` a été mise à jour pour utiliser les noms de propriétés standard de `wrangler.json`.

## Modifié {/* #changed */}

### Point de terminaison OpenAPI déplacé vers `/api/openapi.json` {/* #openapi-spec-endpoint-moved-to-apiopenapijson */}

Le point de terminaison de spécification OpenAPI a été déplacé de `/openapi.json` vers `/api/openapi.json` afin de s’aligner sur le préfixe `/api` utilisé par toutes les routes Mastra intégrées.

Si vous avez des scripts ou Tools qui consomment la spécification OpenAPI, mettez l’URL à jour :

```diff
- GET /openapi.json
+ GET /api/openapi.json
```

### `CloudflareDeployer` utilise les noms de propriétés standard de `wrangler.json` {/* #cloudflaredeployer-uses-standard-wranglerjson-property-names */}

Le constructeur `CloudflareDeployer` accepte désormais les noms de propriétés standard de `wrangler.json` au lieu de variantes personnalisées en camelCase. Ce changement aligne le déployeur sur le format de configuration officiel de Cloudflare et donne accès à toutes les options de configuration wrangler.

Les champs obsolètes sont automatiquement migrés à l’exécution avec des avertissements dans la console, mais vous devez mettre votre code à jour pour utiliser les nouveaux noms de champs.

```diff
  const deployer = new CloudflareDeployer({
-   projectName: 'my-worker',
+   name: 'my-worker',
-   d1Databases: [
+   d1_databases: [
      {
        binding: 'DB',
        database_name: 'my-db',
        database_id: 'xxx',
      },
    ],
-   kvNamespaces: [
+   kv_namespaces: [
      {
        binding: 'KV',
        id: 'yyy',
      },
    ],
  });
```

Le champ `workerNamespace` a été supprimé car il n’est plus utilisé.

Pour toutes les options de configuration disponibles, consultez la [documentation de configuration Wrangler](https://developers.cloudflare.com/workers/wrangler/configuration/).
