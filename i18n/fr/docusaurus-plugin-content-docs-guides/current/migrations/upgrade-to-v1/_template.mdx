Ce modèle est un guide de style expliquant comment remplir les guides de migration individuels. Utilisez-le pour structurer les fichiers de ce répertoire. Vous ne devez pas déroger à cette structure.

Suivez les instructions de `.cursor/rules/writing-documentation.mdc` pour rédiger le contenu explicatif.

Après avoir identifié tous les changements à documenter, regroupez-les en deux grandes catégories : « Modifié » et « Supprimé ».

Example:

```md
## Changed

## Removed
```

Tous les changements DOIVENT figurer sous ces deux sections.

Chaque changement, qu’il soit modifié ou supprimé, doit être un titre h3. Vous devez respecter exactement ce format.

Example:

```md
## Changed

### `oldFunction` to `newFunction`
```

Maintenant que les titres sont en place, vous devez suivre une structure EXACTE pour chaque changement. Vous ne devez pas déroger à cette structure.

Donnez une brève description du changement en une ou deux phrases. Expliquez ensuite en une phrase pourquoi il a été effectué.

Le troisième élément de chaque changement doit expliquer comment migrer le code existant vers la nouvelle version. Restez concis mais clair, sans omettre trop d’informations. Ajoutez ensuite OBLIGATOIREMENT un bloc de code utilisant la syntaxe « diff ». Dans ce bloc, montrez un exemple « avant » et « après » du code à modifier avec cette syntaxe.

Example:

````md
## Changed

### `oldFunction` to `newFunction`

The `oldFunction` has been renamed to `newFunction`. This change improves clarity and consistency across the API.

To migrate, replace all instances of `oldFunction` with `newFunction` in your codebase.

```diff
- const result = oldFunction(args);
+ const result = newFunction(args);
```
````

Si la migration demande davantage qu’une recherche et un remplacement, vous pouvez ajouter des explications avant le bloc de code. Si elle comporte plusieurs étapes, utilisez une liste numérotée pour les expliquer clairement.
