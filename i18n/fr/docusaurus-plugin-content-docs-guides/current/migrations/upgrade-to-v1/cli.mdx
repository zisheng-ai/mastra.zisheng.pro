# CLI

La CLI a été simplifiée en supprimant les commandes de déploiement, les flags de configuration et les fichiers de démarrage. Une nouvelle commande de migration a été ajoutée pour faciliter les mises à niveau de schéma de base de données.

## Ajouté {/* #added */}

### `mastra migrate` command {/* #mastra-migrate-command */}

Une nouvelle commande `mastra migrate` aide à exécuter les migrations de base de données lors de la mise à niveau des versions de Mastra. Elle est particulièrement utile lors de la mise à niveau depuis d’anciennes versions pouvant présenter des incompatibilités de données.

```bash
npx mastra migrate
```

La commande regroupe votre projet et se connecte au stockage configuré avant d’exécuter les migrations nécessaires. Elle prend actuellement en charge la migration des entrées de span dupliquées qui peuvent empêcher la création de contraintes uniques.

Consultez le [guide de migration du Storage](/guides/migrations/upgrade-to-v1/storage#duplicate-spans-migration) pour savoir quand cette migration est nécessaire.

## Supprimé {/* #removed */}

### `mastra deploy` command {/* #mastra-deploy-command */}

La commande `mastra deploy` a été supprimée de la CLI. Ce changement simplifie la CLI en supprimant la logique de déploiement propre à un fournisseur.

Pour migrer, choisissez l’une des [plateformes de déploiement](/docs/deployment/overview) de votre choix.

### `--env` flag from `mastra build` {/* #--env-flag-from-mastra-build */}

Le flag `--env` a été supprimé de la commande `mastra build`. Ce changement simplifie la commande de build.

Pour migrer, utilisez `mastra start --env <env>` pour démarrer la sortie de build avec un environnement personnalisé.

```diff
- mastra build --env production
+ mastra build
+ mastra start --env production
```

### `--port` flag from `mastra dev` {/* #--port-flag-from-mastra-dev */}

Le flag `--port` a été supprimé de la commande `mastra dev`. La configuration du port est désormais gérée par la configuration de l’instance Mastra. Ce changement centralise la configuration du port.

Pour migrer, utilisez `server.port` sur l’instance Mastra au lieu du flag de CLI.

```ts
const mastra = new Mastra({
  server: {
    port: 3001,
  },
})
```

### Telemetry options from CLI {/* #telemetry-options-from-cli */}

L’option `telemetry` a été supprimée des commandes de CLI, y compris le flag `--no-telemetry` / `-nt`. La configuration de la télémétrie a été supprimée de la CLI. Ce changement reflète le déplacement des fonctionnalités de télémétrie vers le package d’observabilité.

Pour migrer, supprimez les flags de télémétrie des commandes de CLI. Utilisez `@mastra/observability` pour les fonctionnalités de tracing.
