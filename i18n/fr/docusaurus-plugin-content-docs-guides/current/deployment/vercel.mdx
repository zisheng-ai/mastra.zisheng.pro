# Déployer Mastra sur Vercel

Utilisez `@mastra/deployer-vercel` pour déployer votre serveur Mastra sous forme de fonctions serverless sur Vercel. Le Deployer regroupe votre code et génère un répertoire `.vercel/output` conforme à la [Build Output API](https://vercel.com/docs/build-output-api/v3) de Vercel, prêt à être déployé sans configuration supplémentaire.

:::info
Ce guide traite du déploiement du [serveur Mastra](/docs/server/mastra-server). Si vous utilisez un [adaptateur de serveur](/docs/server/server-adapters) ou un [framework web](/docs/deployment/web-framework), procédez au déploiement comme vous le feriez habituellement pour ce framework.
:::

## Avant de commencer {/* #before-you-begin */}

Vous aurez besoin d’une [application Mastra](/guides/getting-started/quickstart) et d’un compte [Vercel](https://vercel.com/).

:::warning
Les fonctions Vercel utilisent un système de fichiers éphémère. Tout stockage configuré, y compris celui de l’observabilité, doit donc être hébergé en externe. Si vous utilisez [LibSQLStore](/reference/storage/libsql) avec une URL de fichier, adoptez une base de données hébergée à distance.
:::

## Installation {/* #installation */}

Ajoutez le package `@mastra/deployer-vercel` à votre projet :

```bash npm2yarn
npm install @mastra/deployer-vercel@latest
```

Importez [`VercelDeployer`](/reference/deployer/vercel) et définissez-le comme Deployer dans votre configuration Mastra :

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
// highlight-next-line
import { VercelDeployer } from '@mastra/deployer-vercel'

export const mastra = new Mastra({
  // highlight-next-line
  deployer: new VercelDeployer(),
})
```

## Déployer {/* #deploy */}

<Steps>
  <StepItem>
    Envoyez votre projet vers un Provider Git distant, par exemple GitHub, puis connectez votre dépôt à Vercel.

    Par défaut, Vercel exécute `npm run build`, qui déclenche `mastra build`. Si vous n’avez pas de script de build, ajoutez `"build": "mastra build"` à votre `package.json`.

    :::note

    Pensez à définir les variables d’environnement nécessaires à l’exécution de votre application, par exemple la clé d’API de votre [Provider de modèle](/models/providers).

    :::
  </StepItem>

  <StepItem>
    Lorsque vous êtes prêt, cliquez sur **Deploy** et attendez la fin du premier déploiement.
  </StepItem>

  <StepItem>
    Vérifiez votre déploiement à l’adresse `https://<your-project>.vercel.app/api/agents`, qui doit renvoyer une liste JSON de vos Agents.

    Comme le serveur Mastra préfixe chaque endpoint avec `/api`, vous devez l’ajouter à vos URL lorsque vous effectuez des requêtes.
  </StepItem>

  <StepItem>
    Vous pouvez maintenant appeler vos endpoints Mastra via HTTP.

    :::warning
    Configurez l’[authentification](/docs/server/auth) avant d’exposer publiquement vos endpoints.
    :::
  </StepItem>
</Steps>

## Studio {/* #studio */}

Vous pouvez déployer [Studio](/docs/studio/overview) avec votre API en activant l’option `studio`. Studio est déployé sous forme de ressources statiques servies depuis l’Edge CDN de Vercel et ne consomme donc aucune invocation de fonction.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { VercelDeployer } from '@mastra/deployer-vercel'

export const mastra = new Mastra({
  deployer: new VercelDeployer({
    // highlight-next-line
    studio: true,
  }),
})
```

Après le déploiement, Studio est disponible à l’URL racine (`https://<your-project>.vercel.app/`) et l’API reste accessible sous `/api/*`. Studio se connecte automatiquement à l’API de la même origine ; aucune variable d’environnement supplémentaire n’est donc nécessaire.

Studio sert ses propres pages depuis le CDN, tandis que tous les autres chemins sont dirigés vers votre serveur. Les routes ajoutées avec [`registerApiRoute()`](/docs/server/custom-api-routes) restent ainsi accessibles à leurs propres chemins. Évitez d’attribuer à une route personnalisée un chemin déjà utilisé par Studio, comme `/agents` ou `/workflows`, car Studio les réserve en priorité.

:::warning
Une fois Studio connecté à votre serveur Mastra, il dispose d’un accès complet à vos Agents, Workflows et Tools. Veillez à le sécuriser correctement en production, par exemple derrière une authentification ou un VPN, afin d’empêcher tout accès non autorisé.
:::

## Remplacements facultatifs {/* #optional-overrides */}

Le Deployer Vercel prend en charge des options de configuration écrites dans la configuration de fonction de la Vercel Output API. Consultez la [référence de `VercelDeployer`](/reference/deployer/vercel#constructor-options) pour découvrir les options disponibles, telles que `maxDuration`, `memory` et `regions`.

## Observabilité {/* #observability */}

Les fonctions serverless peuvent s’arrêter immédiatement après avoir renvoyé une réponse. Tout traitement asynchrone en attente, comme l’envoi de télémétrie, peut être interrompu avant son terme. Attendre `flush()` garantit l’envoi de toutes les traces avant l’arrêt de la fonction.

```typescript title="api/chat.ts"
import type { VercelRequest, VercelResponse } from '@vercel/node'
import { mastra } from '../src/mastra'

export default async function handler(req: VercelRequest, res: VercelResponse) {
  const { message } = req.body
  const agent = mastra.getAgent('myAgent')
  const result = await agent.generate([{ role: 'user', content: message }])

  await mastra.observability.flush()

  return res.json(result)
}
```

:::warning
Le Deployer Vercel n’inclut aucun appel à `flush`. Si vous en avez besoin, vous devez encapsuler vous-même le Handler afin d’ajouter cette logique avant de renvoyer la réponse. Vous pouvez également déployer l’application sur un serveur de longue durée, tel qu’une [machine virtuelle](/guides/deployment/digital-ocean), où ce problème ne se pose pas.
:::
