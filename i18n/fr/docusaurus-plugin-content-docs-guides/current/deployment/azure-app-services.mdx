# Déployer Mastra sur Azure App Services

Déployez vos applications Mastra sur Azure App Services.

:::info
Ce guide explique comment déployer le [serveur Mastra](/docs/server/mastra-server). Si vous utilisez un [adaptateur de serveur](/docs/server/server-adapters) ou un [framework web](/docs/deployment/web-framework), suivez la procédure de déploiement habituelle de ce framework.
:::

## Avant de commencer {/* #before-you-begin */}

Vous aurez besoin des éléments suivants :

- Une [application Mastra](/guides/getting-started/quickstart)
- Un [compte Azure](https://azure.microsoft.com/) avec un abonnement actif
- Un [dépôt GitHub](https://github.com/) contenant votre application Mastra

:::warning
Sur Azure App Services, le système de fichiers est éphémère avec certains niveaux tarifaires : tout fichier de base de données local sera donc perdu entre deux déploiements. Si vous utilisez [LibSQLStore](/reference/storage/libsql) avec un fichier local, configurez-le plutôt pour employer une base de données distante compatible avec LibSQL, comme [Turso](https://turso.tech/).
:::

## Créer un nouvel App Service {/* #create-a-new-app-service */}

Les étapes suivantes vous montrent comment créer un nouvel Azure App Service pour héberger votre application Mastra. Elles mettent en place l'infrastructure et l'environnement nécessaires à son exécution.

<Steps>
  <StepItem>
    Connectez-vous au [portail Azure](https://portal.azure.com), puis accédez à **[App Services](https://docs.microsoft.com/en-us/azure/app-service/)** ou recherchez ce service dans la barre de recherche supérieure. Sélectionnez **Create** (« Créer ») pour créer un nouvel App Service, puis choisissez **Web App** (« Application web ») dans le menu déroulant.
  </StepItem>

  <StepItem>
    Configurez les paramètres de l'App Service :

    - **Subscription** (« Abonnement ») : sélectionnez votre abonnement Azure
    - **Resource Group** (« Groupe de ressources ») : créez un groupe de ressources ou sélectionnez-en un qui existe déjà
    - **Instance name** (« Nom de l'instance ») : saisissez un nom unique pour votre application ; il fera partie de son URL
    - **Publish** (« Publier ») : sélectionnez **Code**
    - **Runtime stack** (« Pile d'exécution ») : sélectionnez **Node 22 LTS**
    - **Operating System** (« Système d'exploitation ») : sélectionnez **Linux**
    - **Region** (« Région ») : choisissez une région proche de vos utilisateurs
    - **Linux Plan** (« Plan Linux ») : selon la région choisie, vous pourrez éventuellement sélectionner un plan ; choisissez celui qui correspond à vos besoins.
    - Sélectionnez **Review + Create** (« Vérifier + créer ») et attendez la fin de la validation, puis sélectionnez **Create** (« Créer »).
  </StepItem>

  <StepItem>
    Un nouveau déploiement a été lancé. Attendez qu'il se termine, puis sélectionnez **Go to resource** (« Accéder à la ressource ») dans la section consacrée aux étapes suivantes.
  </StepItem>

  <StepItem>
    Avant de configurer le déploiement GitHub, définissez vos variables d'environnement. Dans la barre latérale gauche, accédez à **Settings** (« Paramètres ») > **Environment variables** (« Variables d'environnement »). Ajoutez les variables d'environnement requises, notamment :

    - Les clés d'API des fournisseurs de modèles (par exemple, `OPENAI_API_KEY`)
    - Les chaînes de connexion aux bases de données
    - Toute autre valeur de configuration requise par votre application Mastra

    Sélectionnez **Apply** (« Appliquer ») pour enregistrer les modifications.
  </StepItem>
</Steps>

## Déploiement avec GitHub {/* #github-deployment */}

Au cours des étapes suivantes, vous allez connecter votre Azure App Service à votre dépôt GitHub afin d'activer le déploiement continu. Ainsi, chaque fois que vous enverrez des modifications vers votre dépôt, Azure compilera et déploiera automatiquement votre application.

<Steps>
  <StepItem>
    Dans la barre latérale gauche, accédez à **Deployment Center** (« Centre de déploiement »), puis sélectionnez **GitHub** comme source. Connectez-vous à GitHub si vous ne vous êtes pas déjà authentifié auprès d'Azure.

    Dans cet exemple, conservez [GitHub Actions](https://docs.github.com/en/actions) comme fournisseur. Sélectionnez votre organisation, votre dépôt et votre branche.

    Azure va générer un fichier de Workflow GitHub que vous pourrez prévisualiser avant de continuer. Sélectionnez **Save** (« Enregistrer ») ; ce bouton se trouve en haut de la page.
  </StepItem>

  <StepItem>
    Une fois le Workflow créé par Azure, une exécution GitHub Actions sera déclenchée et le fichier de Workflow sera fusionné dans votre branche. **Annulez cette première exécution**, car elle échouera tant que les modifications nécessaires n'auront pas été apportées.

    :::warning
    Le Workflow par défaut généré par Azure échouera avec les applications Mastra et doit être modifié.
    :::

    Récupérez les dernières modifications dans votre dépôt local, puis modifiez le fichier de Workflow généré (`.github/workflows/main_<your-app-name>.yml`) :
  </StepItem>

  <StepItem>
    Repérez l'étape intitulée "npm install, build, and test", puis :

    - Renommez l'étape "npm install and build"
    - Si vous n'avez pas configuré de tests adaptés dans votre application Mastra, supprimez la commande `npm test` de la section d'exécution, car le script de test par défaut échouera et interrompra le déploiement. Si vos tests fonctionnent, vous pouvez conserver la commande de test.
  </StepItem>

  <StepItem>
    Repérez l'étape "Zip artifact for deployment", puis remplacez la commande zip par :

    ```yaml
    run: (cd .mastra/output && zip ../../release.zip -r .)
    ```

    Le package de déploiement ne contiendra alors que les sorties de compilation provenant de `.mastra/output`.
  </StepItem>

  <StepItem>
    Commitez et envoyez les modifications apportées au Workflow. La compilation sera automatiquement déclenchée dans le **Deployment Center** (« Centre de déploiement ») de votre tableau de bord Azure. Suivez la progression du déploiement jusqu'à ce qu'il se termine correctement.
  </StepItem>
</Steps>

## Vérifier le déploiement {/* #verify-your-deployment */}

Une fois la compilation réussie, attendez quelques instants que l'application démarre. Vous pouvez accéder à l'application déployée à l'aide de l'URL par défaut indiquée dans l'onglet **Overview** (« Vue d'ensemble ») du portail Azure. Votre application sera disponible à l'adresse `https://<your-app-name>.azurewebsites.net`.

Copiez l'URL depuis le portail Azure, puis ouvrez `https://<your-app-name>.azurewebsites.net/api/agents` dans votre navigateur. Une liste JSON de vos agents devrait s'afficher.

Vous pouvez maintenant appeler vos endpoints Mastra via HTTP.

:::warning
Configurez l'[authentification](/docs/server/auth) avant d'exposer publiquement vos endpoints.
:::
