# Déployer Mastra sur Amazon EC2

Déployez votre serveur Mastra sur Amazon EC2. Le serveur s’exécute sur une infrastructure que vous gérez et peut prendre en charge des agents et des workflows de longue durée.

:::info
Ce guide explique comment déployer le [serveur Mastra](/docs/server/mastra-server). Si vous utilisez un [adaptateur de serveur](/docs/server/server-adapters) ou un [framework web](/docs/deployment/web-framework), procédez comme vous le feriez habituellement pour ce framework.
:::

## Avant de commencer {/* #before-you-begin */}

Vous aurez besoin des éléments suivants :

- Une [application Mastra](/guides/getting-started/quickstart)
- Une instance [EC2](https://aws.amazon.com/ec2/) (Ubuntu ou Amazon Linux) sur laquelle Git et Node.js 22.13.0 ou version ultérieure sont installés

Pour la production, vous aurez également besoin des éléments suivants :

- Un nom de domaine pointant vers votre instance (nécessaire pour les certificats SSL)
- Un certificat SSL pour votre domaine (par exemple, en utilisant [Certbot](https://certbot.eff.org/) avec Let’s Encrypt)
- Un proxy inverse (par exemple, [nginx](https://nginx.org/)) pour transférer le trafic vers votre application

## Déployer {/* #deploy */}

<Steps>
  <StepItem>
    Connectez-vous à votre instance EC2 et clonez votre dépôt :

    <Tabs>
      <TabItem value="public" label="Dépôt public">
        ```bash
        git clone https://github.com/<your-username>/<your-repository>.git
        ```
      </TabItem>

      <TabItem value="private" label="Dépôt privé">
        ```bash
        git clone git@github.com:<your-username>/<your-repository>.git
        ```
      </TabItem>
    </Tabs>

    Accédez au répertoire du dépôt :

    ```bash
    cd "<your-repository>"
    ```
  </StepItem>

  <StepItem>
    Installez les dépendances :

    ```bash npm2yarn
    npm install
    ```
  </StepItem>

  <StepItem>
    Créez un fichier `.env` et ajoutez-y vos variables d’environnement :

    ```bash
    touch .env
    ```

    Pensez à définir les variables d’environnement nécessaires à l’exécution de votre application (par exemple, la clé API de votre fournisseur de modèles) :

    ```bash
    OPENAI_API_KEY=<your-openai-api-key>
    # Add other required environment variables
    ```
  </StepItem>

  <StepItem>
    Générez l’application :

    ```bash npm2yarn
    npm run build
    ```
  </StepItem>

  <StepItem>
    Exécutez l’application :

    ```bash
    node --env-file=".env" .mastra/output/index.mjs
    ```

    Il s’agit d’un exemple de base. En production, utilisez un gestionnaire de processus tel que [PM2](https://pm2.keymetrics.io/) ou [systemd](https://systemd.io/) pour maintenir votre application en cours d’exécution et gérer les redémarrages.

    :::warning
    Configurez l’[authentification](/docs/server/auth) avant d’exposer publiquement vos points de terminaison.
    :::
  </StepItem>

  <StepItem>
    Votre serveur Mastra s’exécute désormais sur le port 4111, mais il n’est accessible que localement.

    Vous pouvez ouvrir le port 4111 dans votre groupe de sécurité EC2 pour permettre un accès direct, ou configurer un proxy inverse (tel que nginx) afin qu’il écoute sur les ports 80 et 443 et transfère les requêtes vers `http://localhost:4111`.

    En production, vous devriez utiliser un proxy inverse afin de pouvoir configurer HTTPS. HTTPS chiffre le trafic et est requis par la plupart des intégrations de webhooks et des services externes avec lesquels vos agents interagissent.
  </StepItem>

  <StepItem>
    Vérifiez votre déploiement à l’adresse `https://<your-ec2-address>/api/agents`, qui devrait renvoyer une liste JSON de vos agents.
  </StepItem>

  <StepItem>
    Vous pouvez maintenant appeler vos points de terminaison Mastra via HTTP.
  </StepItem>
</Steps>
