# createCodingAgent()

`createCodingAgent()` は、Coding Agent に常に必要となる要素（ローカル Workspace、タスクリストの Signal Provider、ネットワークリトライ用のエラー Processor、Goal Judge プロンプト）に移植可能なデフォルトを適用した Coding [`Agent`](/reference/agents/agent) を構築します。動作する Agent を得るには `model`、`instructions`、`tools` だけを指定します。どのデフォルトもオーバーライドできます。

戻り値は標準の `Agent` であるため、`Agent` を使用できる場所ならどこでも使用できます。たとえば、[`AgentController`](/reference/agent-controller/agent-controller-class) に渡す Agent として利用できます。

## 使用例

モデル、指示、Tool を渡します。ファクトリーが Workspace、タスクシグナル、エラー Processor、Goal プロンプトを補完します。

```typescript title="src/mastra/coding-agent.ts"
import { createCodingAgent } from '@mastra/core/coding-agent'

const agent = createCodingAgent({
  id: 'my-coding-agent',
  name: 'My Coding Agent',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  instructions: 'You are a helpful coding assistant.',
  tools: {},
})
```

## デフォルト

ファクトリーがデフォルトを補完するのは、対応するフィールドを指定しなかった場合だけです。呼び出し元が指定した値が常に優先されます。

| フィールド | 省略時のデフォルト |
| - | - |
| `workspace` | ベースパスをルートとする `LocalFilesystem` と `LocalSandbox` を利用した [`Workspace`](/reference/workspace/workspace-class)。 |
| `signals` | 単一の [`TaskSignalProvider`](/reference/signals/task-signal-provider)。 |
| `errorProcessors` | 不明なストリームエラーのリトライに、ECONNRESET と Bad Request 専用のポリシー、`PrefillErrorHandler`、`ProviderHistoryCompat` を加えた構成。 |
| `goal.prompt` | `DEFAULT_GOAL_JUDGE_PROMPT`（`goal` が設定されている場合のみ）。 |

### Workspace

`workspace` キーを省略すると、ファクトリーは `basePath`（デフォルトは `process.cwd()`）をルートとするローカル Workspace を構築します。

```typescript
import { Workspace, LocalFilesystem, LocalSandbox } from '@mastra/core/workspace'

new Workspace({
  filesystem: new LocalFilesystem({ basePath }),
  sandbox: new LocalSandbox({ workingDirectory: basePath }),
})
```

オプトアウトするには（たとえば、[`AgentController`](/reference/agent-controller/agent-controller-class) レベルで Workspace を注入する場合）、`workspace: undefined` を明示的に渡します。

```typescript
const agent = createCodingAgent({
  id: 'my-coding-agent',
  name: 'My Coding Agent',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  instructions: 'You are a helpful coding assistant.',
  tools: {},
  workspace: undefined, // opt out of the default workspace
})
```

### エラー Processor

デフォルトの [`StreamErrorRetryProcessor`](/reference/processors/stream-error-retry-processor) は、次のリトライポリシーを適用します。

- Provider のメタデータや特定の Matcher に一致しない不明なエラーは、`3000ms` の遅延で最大 2 回リトライします。既知の認証エラーは直ちに返されます。
- ネットワークのリセット（`ECONNRESET` / `socket hang up`）は、指数バックオフ（`1000ms * 2^retryCount`、上限 `30000ms`）で最大 2 回リトライします。
- Bad Request エラーは `2000ms` 後に 1 回リトライします。

ネットワークリセットと Bad Request 専用のポリシーは、不明なエラーのポリシーより優先されます。`errorProcessors` を渡すと、デフォルトの Processor スタックが置き換えられます。Provider の互換性を確保するために `PrefillErrorHandler` と `ProviderHistoryCompat` も含まれています。
