# MastraEditor クラス

`MastraEditor` クラスは Editor システムをセットアップします。`Mastra` コンストラクターに渡すと、Prompt Block、Agent コードのオーバーライド、バージョニング、Tool Provider などの Editor 機能が有効になります。

Editor の概要については、[Editor](/docs/editor/overview) を参照してください。

## 使用例

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraEditor } from '@mastra/editor'

export const mastra = new Mastra({
  agents: {/* your agents */},
  editor: new MastraEditor(),
})
```

## Agent Builder

`builder` フィールドは、保存済み Agent を作成・編集するためのブラウザーベース UI、[Agent Builder](https://agent-builder.mastra.ai/) を有効にします。以下を参照してください。

- [Agent Builder の概要](https://agent-builder.mastra.ai/): 概念と導入方法。
- [AgentBuilderOptions](https://agent-builder.mastra.ai/reference/agent-builder-options): 完全なオプションスキーマ。
- [BuilderAgentDefaults](https://agent-builder.mastra.ai/reference/builder-agent-defaults): 新しい Agent に対して管理者が固定するデフォルト値。
- [builder.configuration.agent.models](https://agent-builder.mastra.ai/reference/builder-models): Model の許可リストとデフォルト Model。

### Builder Agent の登録

Builder UI は、`createBuilderAgent()` ファクトリーによって作成された Agent に対して動作します。このファクトリーは `@mastra/editor/ee` から提供されます。ファクトリーをインポートして呼び出し、返された Agent を Mastra インスタンスの `agents` に登録します。

```typescript filename="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraEditor } from '@mastra/editor'
import { createBuilderAgent } from '@mastra/editor/ee'

export const mastra = new Mastra({
  agents: { builderAgent: createBuilderAgent() },
  editor: new MastraEditor({
    builder: { enabled: true },
  }),
})
```

キー名（`builderAgent`）は慣例的なものです。任意のキーを使用できます。`@mastra/editor/ee` サブパスは、実行時に Mastra Enterprise Edition ライセンスによって制限されます。

セットアップの完全なチェックリストについては、[Agent Builder の概要](https://agent-builder.mastra.ai/#prerequisites)を参照してください。

## Namespace

Editor は、さまざまなエンティティ型を管理する Namespace を公開します。任意の Mastra インスタンスから `mastra.getEditor()` でアクセスし、アプリケーションコードで CRUD メソッドを直接呼び出すか、内部でそれらを使用する Mastra サーバールートを利用します。

すべての Namespace は共通の CRUD 基底クラスを拡張しているため、同じ `create`、`getById`、`update`、`delete`、`list`、`listResolved`、`clearCache` メソッドを公開します。以下の Namespace 固有のプロパティテーブルには、追加のメソッドも記載されています。

### Agent Namespace の例

既存のコード定義 Agent に対する保存済みオーバーライドを作成します。

```typescript title="src/scripts/seed-agent.ts"
import { mastra } from '../mastra'

const editor = mastra.getEditor()!

await editor.agent.create({
  id: 'support-agent',
  instructions: 'You are a friendly support agent for Acme.',
  tools: {
    search_kb: { description: 'Search the Acme knowledge base' },
  },
})
```

## メソッド

### Provider へのアクセス

#### `getToolProvider(id)`

登録済みの Tool Provider を ID で返します。

```typescript
const composio = mastra.getEditor()?.getToolProvider('composio')
```

#### `getToolProviders()`

登録済みのすべての Tool Provider を `Record<string, ToolProvider>` として返します。

#### `getProcessorProvider(id)`

登録済みの Processor Provider を ID で返します。

#### `getProcessorProviders()`

登録済みのすべての Processor Provider を返します。

#### `getFilesystemProviders()`

登録済みのすべての Filesystem Provider を返します。

#### `getSandboxProviders()`

登録済みのすべての Sandbox Provider を返します。

#### `getBlobStoreProviders()`

登録済みのすべての Blob Store Provider を返します。

### Source

#### `getSource()`

構成済みの source（`'code'` または `'db'`）を返します。Editor を明示的な source なしで構築した場合は `undefined` を返します。明示的な source は `source` で指定します。

```typescript
const source = mastra.getEditor()?.getSource()
```

戻り値: `'code' | 'db' | undefined`

`source` を省略した場合、`getSource()` が `undefined` を返しても、Editor は構成済みのデータベースストレージを使用します。ストレージのワークフローについては [Editor のストレージオプション](/docs/editor/overview#choose-where-changes-are-stored)、有効化と Git 履歴の動作については [code source のバージョニング](/reference/editor/versioning#code-source)を参照してください。
