# S3Filesystem

Amazon S3、または Cloudflare R2、MinIO、DigitalOcean Spaces、Tigris などの S3 互換ストレージサービスにファイルを保存します。インターフェースの詳細は、[WorkspaceFilesystem インターフェース](/reference/workspace/filesystem)を参照してください。

## インストール

```bash npm2yarn
npm install @mastra/s3
```

## 使用方法

Workspace に `S3Filesystem` を追加して Agent に割り当てます。

```typescript
import { Agent } from '@mastra/core/agent'
import { Workspace } from '@mastra/core/workspace'
import { S3Filesystem } from '@mastra/s3'

const workspace = new Workspace({
  filesystem: new S3Filesystem({
    bucket: 'my-bucket',
    region: 'us-east-1',
    accessKeyId: process.env.AWS_ACCESS_KEY_ID,
    secretAccessKey: process.env.AWS_SECRET_ACCESS_KEY,
  }),
})

const agent = new Agent({
  id: 'file-agent',
  name: 'file-agent',
  model: '__GATEWAY_ANTHROPIC_MODEL_OPUS__',
  workspace,
})
```

### AWS 認証情報 Provider チェーン

認証情報を指定しない場合、`S3Filesystem` は AWS SDK のデフォルト認証情報 Provider チェーンを使用します。環境変数、`~/.aws` 設定ファイル、ECS コンテナ認証情報、EC2 インスタンスプロファイル、その他の標準ソースから認証情報を自動検出します。

```typescript
import { S3Filesystem } from '@mastra/s3'

// SDK discovers credentials from the environment automatically
const filesystem = new S3Filesystem({
  bucket: 'my-bucket',
  region: 'us-east-1',
})
```

認証情報を自動更新するには、認証情報 Provider 関数を渡します。ECS や Lambda へのデプロイ、または有効期限のある一時認証情報を更新する必要がある SSO / AssumeRole の使用時に便利です。

`fromNodeProviderChain()` を直接呼び出す場合は、AWS SDK の認証情報 Provider パッケージをインストールします。

```bash npm2yarn
npm install @aws-sdk/credential-providers
```

```typescript
import { S3Filesystem } from '@mastra/s3'
import { fromNodeProviderChain } from '@aws-sdk/credential-providers'

const filesystem = new S3Filesystem({
  bucket: 'my-bucket',
  region: 'us-east-1',
  credentials: fromNodeProviderChain(),
})
```

Provider 関数は `S3Filesystem` API の呼び出しにのみ適用されます。Filesystem を E2B Sandbox にマウントする場合、マウント設定は静的な `accessKeyId`、`secretAccessKey`、`sessionToken` の値にしか対応しないため、認証情報の更新はマウントの外部で処理する必要があります。

### Cloudflare R2

```typescript
import { S3Filesystem } from '@mastra/s3'

const filesystem = new S3Filesystem({
  bucket: 'my-r2-bucket',
  region: 'auto',
  endpoint: `https://${process.env.R2_ACCOUNT_ID}.r2.cloudflarestorage.com`,
  accessKeyId: process.env.R2_ACCESS_KEY_ID,
  secretAccessKey: process.env.R2_SECRET_ACCESS_KEY,
})
```

### MinIO

```typescript
import { S3Filesystem } from '@mastra/s3'

const filesystem = new S3Filesystem({
  bucket: 'my-bucket',
  region: 'us-east-1',
  endpoint: 'http://localhost:9000',
  accessKeyId: 'minioadmin',
  secretAccessKey: 'minioadmin',
})
```

### Tigris

```typescript
import { S3Filesystem } from '@mastra/s3'

const filesystem = new S3Filesystem({
  bucket: 'my-bucket',
  region: 'auto',
  endpoint: 'https://t3.storage.dev',
  accessKeyId: process.env.TIGRIS_ACCESS_KEY_ID,
  secretAccessKey: process.env.TIGRIS_SECRET_ACCESS_KEY,
  forcePathStyle: false,
})
```

Tigris は仮想ホスト形式のアドレス指定を使用するため、`forcePathStyle` を `false` に設定する必要があります（カスタムエンドポイントを指定した場合のデフォルトは `true`）。認証情報は [Tigris ダッシュボード](https://console.tigris.dev/)で作成します。アクセスキーには `tid_`、シークレットには `tsec_` の接頭辞が付きます。

## メソッド

S3Filesystem は [WorkspaceFilesystem インターフェース](/reference/workspace/filesystem)を実装し、標準の Filesystem メソッドをすべて提供します。

- `readFile(path, options?)` - ファイルの内容を読み取ります
- `writeFile(path, content, options?)` - ファイルに内容を書き込みます
- `appendFile(path, content)` - ファイルに内容を追記します
- `deleteFile(path, options?)` - ファイルを削除します
- `copyFile(src, dest, options?)` - ファイルをコピーします
- `moveFile(src, dest, options?)` - ファイルを移動または名前変更します
- `mkdir(path, options?)` - ディレクトリを作成します
- `rmdir(path, options?)` - ディレクトリを削除します
- `readdir(path, options?)` - ディレクトリの内容を一覧表示します
- `exists(path)` - パスが存在するか確認します
- `stat(path)` - ファイルまたはディレクトリのメタデータを取得します

### `init()`

Filesystem を初期化し、バケットへのアクセスと認証情報を検証します。

```typescript
await filesystem.init()
```

### `getInfo()`

この Filesystem インスタンスのメタデータを返します。

```typescript
const info = filesystem.getInfo()
// { id: '...', name: 'S3Filesystem', provider: 's3', status: 'ready' }
```

### `getMountConfig()`

この種類の Filesystem のマウントに対応する Sandbox 向けに、マウント設定を返します。

```typescript
const config = filesystem.getMountConfig()
// { type: 's3', bucket: 'my-bucket', region: 'us-east-1', ... }
```

## E2B Sandbox にマウントする

S3Filesystem を E2B Sandbox にマウントすると、バケットへローカルディレクトリとしてアクセスできます。

```typescript
import { Workspace } from '@mastra/core/workspace'
import { S3Filesystem } from '@mastra/s3'
import { E2BSandbox } from '@mastra/e2b'

const workspace = new Workspace({
  mounts: {
    '/data': new S3Filesystem({
      bucket: 'my-bucket',
      region: 'us-east-1',
      accessKeyId: process.env.AWS_ACCESS_KEY_ID,
      secretAccessKey: process.env.AWS_SECRET_ACCESS_KEY,
    }),
  },
  sandbox: new E2BSandbox({ id: 'dev-sandbox' }),
})
```

マウントの詳細は、[E2BSandbox リファレンス](/reference/workspace/e2b-sandbox)を参照してください。
