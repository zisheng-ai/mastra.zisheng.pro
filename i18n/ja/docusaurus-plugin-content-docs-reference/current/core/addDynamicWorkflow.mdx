# Mastra.addDynamicWorkflow()

:::experimental

動的 Workflow はベータ版です。API が安定するまでは、メジャーバージョンを上げずに破壊的変更が加わる場合があります。

:::

`.addDynamicWorkflow()` メソッドは動的 Workflow 定義を検証し、インスタンス上で実行可能な Workflow として登録するとともに、`workflowDefinitions` Storage ドメインに永続化します。登録後は、ほかの Workflow と同様に [`getWorkflow()`](/reference/core/getWorkflow) から実行できます。

完全なセットアップ例は[動的 Workflow](/docs/workflows/dynamic-workflows)、使用できるフィールドとグラフエントリは[動的 Workflow 定義リファレンス](/reference/workflows/dynamic-workflow-definition)を参照してください。

## 使用例 {/* #usage-example */}

```typescript
await mastra.addDynamicWorkflow({
  id: 'greeting-workflow',
  description: 'Returns a greeting for the supplied name',
  inputSchema: {
    type: 'object',
    properties: { name: { type: 'string' } },
    required: ['name'],
  },
  outputSchema: {
    type: 'object',
    properties: { message: { type: 'string' } },
    required: ['message'],
  },
  graph: [
    {
      type: 'mapping',
      id: 'create-greeting',
      mapConfig: JSON.stringify({
        message: { template: 'Hello, ${initData.name}!' },
      }),
    },
  ],
})

const run = await mastra.getWorkflow('greeting-workflow').createRun()
const result = await run.start({ inputData: { name: 'Ada' } })
```

## 戻り値 {/* #returns */}

定義の検証、登録、永続化が完了すると解決される Promise。

## 動作 {/* #behavior */}

- 何らかの状態を変更する前に、定義全体（構造、参照、スキーマの流れ）を検証します。グラフが参照する Agent、Tool、Workflow は、あらかじめインスタンスに登録されている必要があります。
- 既存の ID と同じ定義を追加すると、保存済みの定義と実行中インスタンスの登録がどちらも置き換えられます。実行中の Run は、開始時のグラフを引き続き使用します。
- `workflowDefinitions` ドメイン対応の Storage アダプターがなくても、Workflow は検証され、メモリ内に登録されます。ただし、再起動すると定義は失われます。
- ルート Workflow と、その内部で使用する補助 Workflow をまとめて追加するには、[`addDynamicWorkflows()`](/reference/core/addDynamicWorkflows) を使用します。
