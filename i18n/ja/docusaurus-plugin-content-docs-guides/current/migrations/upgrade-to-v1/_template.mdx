このテンプレートは、このディレクトリにある各移行ガイドを作成するためのスタイルガイドです。このディレクトリのファイル構成を決める際の指針として使用してください。この構成から逸脱することはできません。

文章の書き方については、`.cursor/rules/writing-documentation.mdc` の指示に従ってください。

ドキュメント化が必要な変更をすべて特定したら、「変更」と「削除」の 2 つの大きなグループに分類してください。

例：

```md
## Changed

## Removed
```

すべての変更は、必ずこの 2 つのセクションのいずれかに含めてください。

個々の変更（「変更」「削除」のどちらでも）は、h3 見出しにしてください。この形式に厳密に従う必要があります。

例：

```md
## Changed

### `oldFunction` to `newFunction`
```

見出しを作成したら、各変更について以下の構成に厳密に従ってください。この構成から逸脱することはできません。

まず、変更内容を 1〜2 文で簡潔に説明します。次に、変更理由を 1 文で説明します。

各変更の 3 番目の要素では、既存コードを新しいバージョンへ移行する方法を説明します。簡潔かつ明確に記述し、必要な情報を削りすぎないようにしてください。その後に、必ず「diff」構文のコードブロックを配置します。コードブロック内では、変更が必要なコードの「変更前」と「変更後」の例を diff 構文で示してください。

例：

````md
## Changed

### `oldFunction` to `newFunction`

The `oldFunction` has been renamed to `newFunction`. This change improves clarity and consistency across the API.

To migrate, replace all instances of `oldFunction` with `newFunction` in your codebase.

```diff
- const result = oldFunction(args);
+ const result = newFunction(args);
```
````

単純な検索と置換では移行できない場合は、コードブロックの前に補足説明を追加できます。複数の手順が必要な場合は、番号付きリストで各手順を明確に説明してください。
