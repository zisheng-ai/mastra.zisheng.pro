# デプロイの概要

Mastra アプリケーションは、Node.js と互換性のある任意の環境にデプロイできます。Mastra サーバーをデプロイする、既存の Web フレームワークと統合する、クラウド Provider にデプロイする、または可観測性、Studio、サーバーデプロイのために [Mastra platform](/docs/mastra-platform/overview) を利用できます。

## Runtime のサポート {/* #runtime-support */}

Mastra は次の Runtime 環境で動作します。

- Node.js `v22.13.0` 以降
- Bun
- Deno
- Cloudflare

## デプロイ方法 {/* #deployment-options */}

### Mastra サーバー {/* #mastra-server */}

Mastra は、単独でデプロイできる Hono ベースの[サーバー](/docs/server/mastra-server)を提供します。`mastra build` コマンドでアプリケーションをビルドし、その出力を任意の VM、コンテナ、PaaS プラットフォームにデプロイします。

インフラストラクチャを完全に制御する必要がある場合、長時間実行するプロセスが必要な場合、または WebSocket 接続を使用する場合は、この方法を選択してください。詳しくは、[Mastra サーバーデプロイガイド](/docs/deployment/mastra-server)を参照してください。

### Monorepo {/* #monorepo */}

スタンドアロンでのデプロイと同じ方法で、monorepo 構成の一部として Mastra サーバーをデプロイします。

詳しくは、[monorepo でのデプロイ](/docs/deployment/monorepo)を参照してください。

### Mastra platform {/* #mastra-platform */}

[Mastra platform](/docs/mastra-platform/overview) は、Mastra フレームワークで構築した AI アプリケーションをデプロイ、監視、管理するための3つの製品を提供します。

- [**Observability**](/docs/mastra-platform/observability): Mastra のプロジェクトやデプロイ全体の Trace、ログ、メトリクスを検索できる、独立したホステッド製品
- [**Studio**](/docs/mastra-platform/studio): Agent のテスト、Workflow の実行、Trace の調査を行える、ホステッド型のビジュアル環境
- [**Server**](/docs/mastra-platform/server): Mastra アプリケーションを API サーバーとして実行する本番環境向けデプロイ先

詳しくは、[Mastra platform の概要](/docs/mastra-platform/overview)を参照してください。

### クラウド Provider {/* #cloud-providers */}

Mastra アプリケーションは、クラウド Provider やサーバーレスプラットフォームにデプロイできます。Mastra には、ビルドとデプロイのプロセスを自動化するための Vercel、Netlify、Cloudflare 向け組み込み Deployer がオプションで用意されています。

自動スケーリングを利用したい場合、インフラストラクチャの管理を最小限に抑えたい場合、またはこれらのプラットフォームのいずれかをすでに使用している場合は、この方法を選択してください。

- [Amazon EC2](/guides/deployment/amazon-ec2)
- [AWS Lambda](/guides/deployment/aws-lambda)
- [Azure App Services](/guides/deployment/azure-app-services)
- [Cloudflare](/guides/deployment/cloudflare)
- [Digital Ocean](/guides/deployment/digital-ocean)
- [Kubernetes](/guides/deployment/kubernetes)
- [Netlify](/guides/deployment/netlify)
- [Vercel](/guides/deployment/vercel)

### Sandbox {/* #sandbox */}

Mastra サーバーを一時的な Workspace Sandbox（Vercel Sandbox や E2B など）にデプロイし、数秒で公開 URL を取得できます。

即時プレビュー、CI パイプラインからのデプロイ、Agent が構築したアプリの検証、ユーザーごとの信頼できないインスタンスの実行には、この方法を使用します。詳しくは、[Sandbox デプロイガイド](/docs/deployment/sandbox)を参照してください。

### Web フレームワーク {/* #web-framework */}

Mastra を Web フレームワークと統合すると、そのフレームワークの標準的なデプロイプロセスを使用して、アプリケーションと一緒にデプロイされます。以下のガイドでは、デプロイ時に必要となるフレームワーク固有の設定について説明します。

既存の Next.js または Astro アプリケーションに Mastra を追加する場合は、次のガイドを使用してください。

- [Vercel 上の Next.js との統合](/docs/deployment/web-framework#with-nextjs-on-vercel)
- [Vercel 上の Astro との統合](/docs/deployment/web-framework#with-astro-on-vercel)
- [Netlify 上の Astro との統合](/docs/deployment/web-framework#with-astro-on-netlify)

## Workflow runner {/* #workflow-runners */}

Mastra Workflow は、デフォルトでは組み込みの実行エンジンを使用して実行されます。マネージドインフラストラクチャを必要とする本番ワークロードでは、Workflow を [Inngest](https://www.inngest.com) のような専用プラットフォームにデプロイすることもできます。このようなプラットフォームは、ステップのメモ化、自動再試行、リアルタイム監視を提供します。

実行方法については [Workflow runner ガイド](/docs/deployment/workflow-runners)を、セットアップ手順については [Inngest デプロイガイド](/guides/deployment/inngest)を参照してください。

## Worker {/* #workers */}

本番環境へのデプロイでは、Mastra は Workflow のオーケストレーション、cron スケジューリング、バックグラウンドでの Tool 実行を、API サーバーとは別の専用 Worker プロセスで実行できます。これにより、それぞれを個別にスケールし、障害を分離できます。詳しくは、[Worker](/docs/deployment/workers)を参照してください。
