# MastraAuthBetterAuth 클래스

그만큼`MastraAuthBetterAuth`클래스는 Better Auth를 사용하여 Mastra 애플리케이션에 대한 인증을 제공합니다. Better Auth 세션으로 들어오는 요청을 확인하고 다음을 사용하여 Mastra 서버와 통합합니다.`auth`옵션.

## 사용예 {/* #usage-example */}

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthBetterAuth } from '@mastra/auth-better-auth'
import { betterAuth } from 'better-auth'

// Create your Better Auth instance
const auth = betterAuth({
  database: {
    provider: 'postgresql',
    url: process.env.DATABASE_URL,
  },
  emailAndPassword: {
    enabled: true,
  },
  baseURL: process.env.BETTER_AUTH_URL,
  secret: process.env.BETTER_AUTH_SECRET,
})

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthBetterAuth({
      auth,
    }),
  },
})
```

## `BetterAuthUser`유형 {/* #betterauthuser-type */}

그만큼`BetterAuthUser` type contains the session and user information returned by Better Auth:

```typescript
interface BetterAuthUser {
  session: Session
  user: User
}
```

* `session`: 세션 메타데이터를 포함하는 Better Auth 세션 객체
* `user`: 사용자 세부정보가 포함된 인증된 사용자 개체

그만큼`Session` and `User` types are exported by the Better Auth package.

## 일치 규칙 {/* #matching-rules */}

* `public`그리고`protected` accept exact paths, wildcard patterns (like `/api/*`), and path params (like `/users/:id`).
* 메소드별 규칙의 경우 다음과 같은 튜플을 사용하세요.`["/api/agents", ["GET", "POST"]]`.
* 경로가 둘 다 일치하는 경우`public` and `protected`, `public` wins and no auth is required.
* 둘 다 일치하지 않으면 경로는 기본적으로 보호되는 것으로 간주됩니다(경로가 명시적으로 표시되지 않는 한).`requiresAuth: false`).
