# 메시지 기록

그만큼`MessageHistory`는**하이브리드 프로세서**메시지 기록의 검색과 지속성을 모두 처리합니다. 입력 시 스토리지에서 기록 메시지를 가져와서 대화 앞에 추가합니다. 출력 시 새 메시지를 스토리지에 유지합니다.

## 사용예 {/* #usage-example */}

```typescript
import { MessageHistory } from '@mastra/core/processors'

const processor = new MessageHistory({
  storage: memoryStorage,
  lastMessages: 50,
})
```

## 확장된 사용 예 {/* #extended-usage-example */}

```typescript title="src/mastra/agents/memory-agent.ts"
import { Agent } from '@mastra/core/agent'
import { MessageHistory } from '@mastra/core/processors'
import { PostgresStorage } from '@mastra/pg'

const storage = new PostgresStorage({
  connectionString: process.env.DATABASE_URL,
})

export const agent = new Agent({
  id: 'memory-agent',
  name: 'memory-agent',
  instructions: 'You are a helpful assistant with conversation memory',
  model: '__GATEWAY_OPENAI_MODEL__',
  inputProcessors: [
    new MessageHistory({
      storage,
      lastMessages: 100,
    }),
  ],
  outputProcessors: [
    new MessageHistory({
      storage,
    }),
  ],
})
```

## 행동 {/* #behavior */}

### 입력 처리 {/* #input-processing */}

1. 요청 컨텍스트에서 `threadId`를 가져옵니다.
2. 스토리지에서 기록 메시지를 가져옵니다(생성 날짜 기준 내림차순).
3. 시스템 메시지를 필터링합니다(데이터베이스에 저장하면 안 됨).
4. ID별 중복을 방지하면서 기록 메시지를 수신 메시지와 병합합니다.
5. 기록 메시지에 `source: 'memory'` 태그를 추가합니다.
### 출력 처리 {/* #output-processing */}

1. 요청 컨텍스트에서 `threadId`를 가져옵니다.
2. Memory 구성에 `readOnly`가 설정되어 있으면 유지를 건너뜁니다.
3. 메시지에서 불완전한 Tool 호출을 필터링합니다.
4. 새 사용자 입력 및 어시스턴트 응답 메시지를 스토리지에 유지합니다.
5. 스레드의 `updatedAt` 타임스탬프를 업데이트합니다.
