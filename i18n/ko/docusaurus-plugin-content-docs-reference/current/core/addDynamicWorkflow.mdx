# Mastra.addDynamicWorkflow()

:::실험적

동적 Workflow는 베타 버전입니다. API가 안정될 때까지 주요 버전 변경 없이 주요 변경 사항이 발생할 수 있습니다.

:::

`.addDynamicWorkflow()` 메서드는 동적 Workflow 정의를 검증하고 인스턴스에 실제 Workflow로 등록하며, `workflowDefinitions` 스토리지 도메인을 통해 유지합니다. 등록된 Workflow는 [`getWorkflow()`](/reference/core/getWorkflow)를 통해 다른 Workflow와 동일하게 실행됩니다.
전체 설정 예시는 [동적 Workflow](/docs/workflows/dynamic-workflows)를, 허용되는 필드와 그래프 엔트리는 [동적 Workflow 정의 레퍼런스](/reference/workflows/dynamic-workflow-definition)를 참조하세요.
## 사용예 {/* #usage-example */}

```typescript
await mastra.addDynamicWorkflow({
  id: 'greeting-workflow',
  description: 'Returns a greeting for the supplied name',
  inputSchema: {
    type: 'object',
    properties: { name: { type: 'string' } },
    required: ['name'],
  },
  outputSchema: {
    type: 'object',
    properties: { message: { type: 'string' } },
    required: ['message'],
  },
  graph: [
    {
      type: 'mapping',
      id: 'create-greeting',
      mapConfig: JSON.stringify({
        message: { template: 'Hello, ${initData.name}!' },
      }),
    },
  ],
})

const run = await mastra.getWorkflow('greeting-workflow').createRun()
const result = await run.start({ inputData: { name: 'Ada' } })
```

## 행동 {/* #behavior */}

* 정의는 변경되기 전에 완전히 검증됩니다(구조, 참조, 스키마 흐름). 그래프에서 참조하는 Agent, Tool 및 Workflow는 이미 인스턴스에 등록되어 있어야 합니다.
* 기존 ID로 정의를 추가하면 저장된 정의와 실시간 등록이 모두 대체됩니다. 실행 중인 작업은 시작할 때 사용한 그래프를 유지합니다.
* `workflowDefinitions` 도메인을 지원하는 스토리지 어댑터가 없는 경우에도 Workflow는 검증되어 Memory에 등록되지만, 재시작하면 정의가 손실됩니다.
* 중첩된 도우미 Workflow와 함께 루트 Workflow를 추가하려면 [`addDynamicWorkflows()`](/reference/core/addDynamicWorkflows)를 사용합니다.
