# Mastra.addDynamicWorkflow()

:::실험적

동적 Workflow는 베타 버전입니다. API가 안정될 때까지 주요 버전 변경 없이 주요 변경 사항이 발생할 수 있습니다.

:::

그만큼`.addDynamicWorkflow()` method validates a dynamic workflow definition and registers it as a live workflow on the instance, persisting it through the `workflowDefinitions` storage domain. Once registered, the workflow runs like any other workflow via [`getWorkflow()`](/reference/core/getWorkflow).

보다[Dynamic workflows](/docs/workflows/dynamic-workflows) for a complete setup example and the [dynamic workflow definition reference](/reference/workflows/dynamic-workflow-definition) for the accepted fields and graph entries.

## 사용예 {/* #usage-example */}

```typescript
await mastra.addDynamicWorkflow({
  id: 'greeting-workflow',
  description: 'Returns a greeting for the supplied name',
  inputSchema: {
    type: 'object',
    properties: { name: { type: 'string' } },
    required: ['name'],
  },
  outputSchema: {
    type: 'object',
    properties: { message: { type: 'string' } },
    required: ['message'],
  },
  graph: [
    {
      type: 'mapping',
      id: 'create-greeting',
      mapConfig: JSON.stringify({
        message: { template: 'Hello, ${initData.name}!' },
      }),
    },
  ],
})

const run = await mastra.getWorkflow('greeting-workflow').createRun()
const result = await run.start({ inputData: { name: 'Ada' } })
```

## 행동 {/* #behavior */}

* 정의는 변경되기 전에 완전히 검증됩니다(구조, 참조, 스키마 흐름). 그래프에서 참조하는 Agent, Tool 및 Workflow는 이미 인스턴스에 등록되어 있어야 합니다.
* 기존 ID로 정의를 추가하면 저장된 정의와 실시간 등록이 모두 대체됩니다. 비행 중 실행은 시작된 그래프를 유지합니다.
* 지원하는 스토리지 어댑터가 없는 경우`workflowDefinitions` domain, the workflow is still validated and registered in memory, but the definition is lost on restart.
* 중첩된 도우미 Workflow와 함께 루트 Workflow를 추가하려면 다음을 사용합니다.[`addDynamicWorkflows()`](/reference/core/addDynamicWorkflows).
