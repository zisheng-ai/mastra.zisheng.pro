# Mastra.addDynamicWorkflows()

:::실험적

동적 Workflow는 베타 버전입니다. API가 안정될 때까지 주요 버전 변경 없이 주요 변경 사항이 발생할 수 있습니다.

:::

`.addDynamicWorkflows()` 메서드는 서로 참조할 수 있는 동적 Workflow 정의 묶음을 추가합니다. 일반적인 사용 사례는 아직 존재하지 않는 루트 Workflow와 그 안에 중첩되는 도우미 Workflow를 함께 추가하는 것입니다.
전체 번들은 미리 검증됩니다. 그런 다음 멤버는 종속성 순서에 따라 등록되므로 도우미는 이를 중첩하는 Workflow 앞에 항상 배치됩니다.

[`addDynamicWorkflow()`](/reference/core/addDynamicWorkflow)단일 회원의 경우입니다.

## 사용예 {/* #usage-example */}

```typescript
await mastra.addDynamicWorkflows([
  helperDefinition, // nested by the root — order in the array doesn't matter
  rootDefinition, // graph contains { type: 'workflow', workflowId: helperDefinition.id }
])
```

## 행동 {/* #behavior */}

* 참조는 인스턴스의 레지스트리 통합 번들의 자체 ID에 대해 확인되므로 루트는 동일한 호출에 도입된 도우미를 중첩할 수 있습니다. 등록 순서는 배열 순서가 아닌 종속성 그래프에서 파생됩니다.
* 거부된 번들은 아무것도 등록하지 않습니다. 중복된 ID, 유효하지 않은 멤버 및 종속성 주기는 변경되기 전에 감지되며, 등록 또는 지속성이 중간에 실패하면 Memory 내 레지스트리가 이전 상태로 복원됩니다.
* 스토리지 쓰기는 마지막에 발생합니다. 번들 중간에 스토리지 수준 오류가 발생하면 일부 행이 기록된 상태로 남을 수 있지만 레지스트리는 여전히 롤백되고 고아 행은 다음 부팅까지 비활성 상태입니다.
