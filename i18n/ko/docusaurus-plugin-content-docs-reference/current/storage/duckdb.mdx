# DuckDB 스토리지

[덕DB](https://duckdb.org/)내장된 프로세스 내 분석 데이터베이스입니다. 그만큼`@mastra/duckdb`패키지는 외부 서비스를 실행하지 않고도 추적, 로그, 메트릭, 점수 및 피드백에 적합한 로컬 개발을 위한 OLAP 지원 관찰 저장소를 제공합니다.

벡터 검색에 대해서는 다음을 참조하세요.[DuckDB vector store reference](/reference/vectors/duckdb), which is a separate API in the same package.

## DuckDB를 사용하는 경우 {/* #when-to-use-duckdb */}

Observability 기능의 로컬 개발. DuckDB는 내장형이며 파일 기반이므로 서버가 필요하지 않고 즉시 시작됩니다. ClickHouse와 동일한 Observability 신호를 지원하므로 프로덕션 백엔드에 배포하기 전에 대시보드를 테스트하고 탐색을 추적하는 데 유용합니다.

DuckDB는 현재 다음만 구현합니다.`observability` domain. Pair it with another storage adapter (such as [LibSQL](/reference/storage/libsql)) for `memory` and `workflows`에[복합 스토리지](/reference/storage/composite)설정.

:::경고
DuckDB는 개발용이므로 프로덕션용으로는 권장되지 않습니다. 프로세스 내에서 실행되고 단일 로컬 파일에 유지되며 임시 파일 시스템(예: Railway, Fly.io, Render, Heroku 또는 서버리스 컨테이너)이 있는 플랫폼에서는 작동하지 않습니다. 프로덕션 관찰성을 위해서는 다음을 사용하세요.[ClickHouse](/reference/storage/clickhouse).
:::

## 용법 {/* #usage */}

### 복합 저장소의 Observability 도메인 {/* #as-the-observability-domain-in-a-composite-store */}

이는 표준 로컬 개발 설정입니다. LibSQL은 다른 도메인을 처리하고 DuckDB는 Observability을 처리합니다.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraCompositeStore } from '@mastra/core/storage'
import { LibSQLStore } from '@mastra/libsql'
import { DuckDBStore } from '@mastra/duckdb'
import { Observability, MastraStorageExporter } from '@mastra/observability'

export const mastra = new Mastra({
  storage: new MastraCompositeStore({
    id: 'composite-storage',
    default: new LibSQLStore({
      id: 'mastra-storage',
      url: 'file:./mastra.db',
    }),
    domains: {
      observability: new DuckDBStore().observability,
    },
  }),
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'mastra',
        exporters: [new MastraStorageExporter()],
      },
    },
  }),
})
```

그만큼`.observability` accessor returns the observability domain store directly. The equivalent generic form uses `getStore()`, which works for any composite-style storage adapter:

```typescript
const observability = await new DuckDBStore().getStore('observability')
```

### 독립형 {/* #standalone */}

외부에 관찰성 저장소만 필요한 경우`Mastra` composite, instantiate `DuckDBStore` directly and access the observability domain:

```typescript
import { DuckDBStore } from '@mastra/duckdb'

const duckdb = new DuckDBStore({ path: './traces.duckdb' })
const observability = duckdb.observability

await observability.init()
```

### 인Memory 데이터베이스 {/* #in-memory-database */}

통과하다`:memory:` to use an ephemeral DuckDB instance. Data is lost when the process exits, which is appropriate for unit tests and short-lived scripts.

```typescript
const duckdb = new DuckDBStore({ path: ':memory:' })
```

## 지원되는 도메인 {/* #supported-domains */}

DuckDB는 현재 하나의 스토리지 도메인을 구현합니다.

| 도메인 | 지원됨 |
| - | - |
|`observability` | Yes |
| `memory` | No |
| `workflows` | No |
| `scores` | No |
| `agents` | No |

전체 스토리지 솔루션을 위해서는 다음을 구성하세요.`DuckDBStore` with an adapter that covers the missing domains (most commonly [LibSQL](/reference/storage/libsql) for local development).

## 초기화 {/* #initialization */}

전달될 때`Mastra` through `MastraCompositeStore`, the observability domain initializes itself on first use. To run initialization explicitly outside of `Mastra`, call `init()` on the observability store:

```typescript
import { DuckDBStore } from '@mastra/duckdb'

const duckdb = new DuckDBStore({ path: './traces.duckdb' })
await duckdb.observability.init()
```

## Observability 전략 {/* #observability-strategy */}

DuckDB는 다음을 지원합니다.`event-sourced` strategy used by `MastraStorageExporter`, which buffers spans in memory and writes completed events in batches. This is appropriate for development-scale traffic. For high-volume production workloads, see [`MastraStorageExporter` storage provider support](/docs/observability/integrations/exporters/mastra-storage#storage-provider-support).
