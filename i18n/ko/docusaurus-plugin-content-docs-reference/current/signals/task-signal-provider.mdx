# TaskSignalProvider

내장된 작업 Tool를 번들로 제공합니다(`task_write`, `task_update`, `task_complete`, `task_check`) 그리고`TaskStateProcessor`단일 Agent 등록 뒤에. Tool와 프로세서를 별도로 연결하지 않고도 구조화되고 내구성 있는 작업 목록을 Agent에 추가하는 데 사용됩니다.

확장[`SignalProvider`](/reference/signals/signal-provider). The task list is stored in the thread-scoped `tasks` storage domain (the source of truth) and projected onto the agent state-signal lane by the processor, so it survives observational-memory truncation without invalidating the prompt cache.

## 사용예 {/* #usage-example */}

다음과 같은 Agent에 공급자를 등록하세요.`Memory` and a Mastra `storage`:

```typescript title="src/mastra/index.ts"
import { Agent } from '@mastra/core/agent'
import { TaskSignalProvider } from '@mastra/core/signals'

const agent = new Agent({
  id: 'coder',
  name: 'coder',
  instructions: '...',
  model,
  memory,
  signals: [new TaskSignalProvider()],
})
```

Agent는 자동으로 네 가지 작업 Tool를 Tool 세트에 병합하고 입력 프로세서 체인에 프로세서를 등록합니다. 다른 배선은 필요하지 않습니다.

작업 추적에는 Memory 지원 스레드가 필요합니다(`threadId` + `resourceId`). Without memory the task tools no-op and return a result explaining that task tracking requires agent memory. The `tasks` storage domain is wired in-memory by default, so task tracking works without configuring a storage backend.

## 행동 양식 {/* #methods */}

### Agent 통합 {/* #agent-integration */}

이러한 메소드는 공급자가 전달될 때 Agent에 의해 자동으로 호출됩니다.`signals`. You normally don't call them directly.

#### `getTools()` {/* #gettools */}

Tool ID로 입력된 4개의 작업 Tool를 반환합니다(`task_write`, `task_update`, `task_complete`, `task_check`). The Agent merges these into its toolset.

```typescript
const tools = new TaskSignalProvider().getTools()
// { task_write, task_update, task_complete, task_check }
```

보고:`Record<string, Tool>`

#### `getInputProcessors()` {/* #getinputprocessors */}

공급자의 정보를 반환합니다.`TaskStateProcessor` instance. The Agent registers it on the input-processor chain, which propagates the Mastra instance so the processor can resolve the `tasks` store.

```typescript
const [processor] = new TaskSignalProvider().getInputProcessors()
// processor instanceof TaskStateProcessor
```

보고:`InputProcessorOrWorkflow[]`
