# Tool 구성

편집기는 Tool 선택 사항을 Agent 버전의 일부로 저장합니다. 저장된 구성은 등록된 Tool, 통합 공급자의 Tool 및 MCP(Model Context Protocol) 클라이언트의 Tool을 추가할 수 있습니다.

Studio Workflow와 일반적인 사용 사례는 [Editor Tool](/docs/editor/overview#tools)을 참조하세요.
## Tool 소스 {/* #tool-sources */}

| 소스 | 설명 |
| - | - |
| 등록된 Tool | Mastra 런타임 Tool 레지스트리에 등록된 Tool |
| MCP 클라이언트 | 저장된 로컬 또는 원격 MCP 서버 구성에 의해 노출되는 Tool |
| 통합 Tool | 레거시 통합 Provider 구성으로 해석된 Tool |
|[Tool Provider](/reference/editor/tool-provider) | Composio 또는 Arcade와 같이 `MastraEditor`에 등록된 Provider가 해석한 Tool |
코드 정의 Agent는 기존 Tool을 유지합니다. [`editor` 재정의 설정](/reference/agents/agent#editor-overrides)은 Editor가 Tool을 추가 및 제거할 수 있는지, 아니면 설명만 변경할 수 있는지를 제어합니다.
## 설명 재정의 {/* #description-overrides */}

선택한 각 Tool은 Agent별 설명을 저장할 수 있습니다. 설명은 원래 Tool 정의를 수정하지 않고 Model에 표시되는 내용을 변경합니다.

설명 전용 모드에서 편집기는 코드 정의 Agent에 이미 존재하는 Tool에만 재정의를 적용합니다. MCP Tool의 경우 Agent 수준 설명이 MCP 클라이언트에 저장된 설명보다 우선합니다.

두 소스가 동일한 Tool ID를 확인하는 경우 최신 소스가 해당 설명을 포함하여 이전 Tool 전체를 대체합니다. 보다[Resolution order](#resolution-order).

## 조건부 Tool 세트 {/* #conditional-tool-sets */}

Editor는 `tools`, `mcpClients`, `integrationTools`, `toolProviders` 필드의 조건부 변형을 저장할 수 있습니다. 런타임에는 요청 컨텍스트 값에 따라 일치하는 변형이 얕게 병합됩니다.
규칙 언어는 다음과 동일한 연산자 및 중첩 동작을 사용합니다.[prompt block display conditions](/reference/editor/prompt-blocks#display-conditions).

조건은 Tool 필드 변형 또는 MCP 클라이언트 참조에 적용됩니다. 현재 Editor 리졸버는 저장된 Tool 항목에 있는 Tool별 `rules` 값을 평가하지 않습니다.
## 저장된 MCP 클라이언트 {/* #stored-mcp-clients */}

`editor.mcp` 네임스페이스는 재사용 가능한 MCP 클라이언트 구성을 관리합니다. CRUD 메서드 시그니처는 [`mcp` 네임스페이스](/reference/editor/mastra-editor#namespaces)를 참조하세요.
`@mastra/mcp`는 `@mastra/editor`의 선택적 피어 종속성입니다. Editor가 런타임에 저장된 MCP 클라이언트의 Tool을 로드할 수 있도록 MCP 클라이언트를 구성하기 전에 설치하세요.
```bash npm2yarn
npm install @mastra/mcp
```

### 교통수단 {/* #transports */}

| 전송 방식 | 저장된 구성 |
| - | - |
|`stdio` | 선택적 `args`, `env`, `timeout`과 함께 사용하는 `command` |
| HTTP | 선택적 `timeout`과 함께 사용하는 `url` |
저장된 HTTP 정의에서는 임의의 헤더를 사용할 수 없습니다. 예약된 `mastra__authToken` 값이 요청 컨텍스트에 있으면 Editor가 이를 `Authorization: Bearer` 헤더로 전달합니다.
### 필터링 {/* #filtering */}

MCP Tool은 두 가지 수준으로 허용 목록에 추가될 수 있습니다.

1. **서버 수준**: 저장된 서버의 `tools` 맵은 해당 클라이언트를 사용하는 모든 Agent의 Tool을 제한합니다.
2. **Agent 수준**: Agent의 MCP 클라이언트 참조는 해당 Agent에 대해 남아 있는 Tool을 제한합니다.
Agent 수준 Tool 이름에는 네임스페이스가 포함된 이름 또는 기본 이름을 사용할 수 있습니다. 명시적으로 비어 있는 `tools` 맵은 모든 Tool을 선택합니다. 현재 리졸버에서는 Agent 수준 MCP 참조에서 `tools`를 생략하면 아무 Tool도 선택되지 않습니다.
### 네임스페이스 {/* #namespacing */}

MCP Tool은 충돌을 방지하기 위해 `serverName_toolName` ID를 사용합니다. `docs` 서버의 `search` Tool은 `docs_search`가 됩니다.
## 해결 순서 {/* #resolution-order */}

편집기는 다음 순서로 Tool 기록을 병합합니다. 이후 레코드는 이전 레코드를 동일한 ID로 대체합니다.

1. 코드 정의 Tool
2. 등록된 저장 Tool
3. MCP Tool
4. 레거시 통합 Tool
5. V1 Tool 제공자 Tool

독립형 저장 Agent는 코드 정의 Tool 없이 동일한 순서를 사용합니다. 레거시 통합 Tool 이후 정적 코드 Agent 재정의가 중지됩니다.

가능하면 소스 전반에 걸쳐 고유한 Tool ID를 사용하십시오. 충돌은 해당 필드를 병합하는 대신 전체 이전 Tool을 대체합니다.
