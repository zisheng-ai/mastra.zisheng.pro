# 배포자

Deployer는 Hono 프레임워크를 사용하여 코드를 패키징하고, 환경 파일을 관리하고, 애플리케이션을 제공함으로써 독립형 Mastra 애플리케이션의 배포를 처리합니다. 구체적인 구현에서는 특정 배포 대상에 대한 배포 방법을 정의해야 합니다.

## 사용예 {/* #usage-example */}

사용자 정의 배포자를 생성하려면 추상을 확장할 수 있습니다.`Deployer` class and implement the `deploy`특정 배포 논리를 사용하는 메서드입니다. 예는 다음과 같습니다.

```typescript
import { Deployer } from '@mastra/deployer'

class CustomDeployer extends Deployer {
  constructor() {
    super({ name: 'custom-deployer' })
  }

  async deploy(outputDirectory: string): Promise<void> {
    // Prepare the output directory
    await this.prepare(outputDirectory)

    // Bundle the application
    await this._bundle('server.ts', 'mastra.ts', outputDirectory)

    // Custom deployment logic
  }
}
```

## 핵심 개념 {/* #core-concepts */}

### 배포 수명주기 {/* #deployment-lifecycle */}

Deployer 추상 클래스는 구조화된 배포 수명 주기를 구현합니다.

1. **초기화**: 배포자는 이름으로 초기화되고 종속성 관리를 위한 Deps 인스턴스를 생성합니다.
2. **환경설정**:`getEnvFiles` method identifies environment files (.env.production, .env) to be used during deployment.
3. **준비**:`prepare` method (inherited from Bundler) cleans the output directory and creates necessary subdirectories.
4. **동고**:`_bundle` method (inherited from Bundler) packages the application code and its dependencies.
5. **전개**: 초록`deploy` method is implemented by subclasses to handle the actual deployment process.

### 환경 파일 관리 {/* #environment-file-management */}

Deployer 클래스에는 다음을 통한 환경 파일 관리 지원이 내장되어 있습니다.`getEnvFiles` method. This method:

* 사전 정의된 순서(.env.production, .env)로 환경 파일을 찾습니다.
* FileService를 사용하여 첫 번째 기존 파일을 찾습니다.
* 발견된 환경 파일의 배열을 반환합니다.
* 환경 파일이 없으면 빈 배열을 반환합니다.

```typescript prettier:false
getEnvFiles(): Promise<string[]> {
  const possibleFiles = ['.env.production', '.env.local', '.env'];

  try {
    const fileService = new FileService();
    const envFile = fileService.getFirstExistingFile(possibleFiles);

    return Promise.resolve([envFile]);
  } catch {}

  return Promise.resolve([]);
}
```

### 번들링 및 배포 관계 {/* #bundling-and-deployment-relationship */}

Deployer 클래스는 Bundler 클래스를 확장하여 번들링과 배포 간의 명확한 관계를 설정합니다.

1. **전제 조건으로 번들링**: 번들링은 애플리케이션 코드를 배포 가능한 형식으로 패키징하는 배포의 필수 단계입니다.
2. **공유 인프라**: 번들링과 배포 모두 종속성 관리 및 파일 시스템 작업과 같은 공통 인프라를 공유합니다.
3. **특화된 배포 로직**: 번들링은 코드 패키징에 중점을 두는 반면, 배포는 번들 코드 배포를 위한 환경별 로직을 추가합니다.
4. **확장성**: 초록`deploy` method allows for creating specialized deployers for different target environments.
