# Agent.listSuspendedRuns()

**추가된 항목:** `@mastra/core@1.43.0`

그만큼`.listSuspendedRuns()` method lists suspended agent runs from workflow snapshot storage: runs waiting on a tool call requiring [approval](/docs/agents/agent-approval)또는 다음을 호출한 Tool에서`suspend()`. 검색은 Memory 내 상태가 아닌 스토리지에 의해 지원되므로 서버를 다시 시작한 후 여러 서버 인스턴스에서 작동합니다.

반환 된 통과`runId` to [`resumeStream()`](/docs/agents/agent-approval#runtime-suspension-with-suspend), `approveToolCall()`, or `declineToolCall()`계속 달리기 위해.

필터 계약은 API를 나열하는 Workflow 실행을 미러링합니다(`listWorkflowRuns`), plus the agent-level `threadId` filter.

## 사용예 {/* #usage-example */}

대화에 대해 보류 중인 실행을 검색하고 계속합니다. 확인하다`requiresApproval` to pick the right continuation: `approveToolCall()` / `declineToolCall()` for approval suspensions, `resumeStream()` with resume data for `suspend()`-based suspensions:

```typescript
const { runs } = await agent.listSuspendedRuns({
  threadId: 'thread-123',
  resourceId: 'user-456',
})

const run = runs[0]
const toolCall = run?.toolCalls[0]

if (run && toolCall) {
  const stream = toolCall.requiresApproval
    ? await agent.approveToolCall({ runId: run.runId, toolCallId: toolCall.toolCallId })
    : await agent.resumeStream({ name: 'San Francisco' }, { runId: run.runId })
}
```

## 발견 범위 {/* #discovery-scope */}

결과는 호출한 Agent가 시작한 실행으로 범위가 지정됩니다.`listSuspendedRuns()` on: snapshots persist the owning agent's id, so runs started by other agents on the same Mastra instance aren't returned. In [supervisor setups](/docs/agents/agent-approval#tool-approval-supervisor-agents) the supervisor sees its outer run (the one to resume), while a subagent's inner run is only visible from the subagent itself. Filter by `threadId` and `resourceId` to scope results to one conversation.

실행 스냅샷은 실행이 입력을 기다리는 동안에만 유지되고 완료되면 삭제됩니다. 따라서 일시 중단된 실행은 스토리지에서 검색할 수 있는 유일한 실행입니다. 일시 중단된 실행은 Mastra 인스턴스에 영구 인스턴스가 있는 경우에만 다시 시작해도 유지됩니다.[storage provider](/docs/storage/overview) configured. With the default in-memory store, snapshots are lost on restart.
