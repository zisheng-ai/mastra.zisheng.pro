# Workflow우.tool()

그만큼`.tool()`메서드는 Tool를 선언적 단계로 추가합니다. Tool 자체의 입력 및 출력 스키마가 적용되므로 이전 단계의 출력은 Tool의 입력 스키마를 충족해야 합니다. 사용`.map()`일치하지 않는 경우 데이터를 변환합니다.

Tool를 감싸는 것과는 달리`createStep()`, `.tool()` records a declarative entry in the workflow graph. This makes the workflow portable: the same graph can be serialized and persisted as a [dynamic workflow](/docs/workflows/dynamic-workflows).

## 사용예 {/* #usage-example */}

```typescript filename="src/mastra/workflows/test-workflow.ts" prettier:false
workflow.tool(testTool).commit();
```

## ID로 Tool 참조 {/* #referencing-a-tool-by-id */}

등록된 Tool를 가져오지 않고 참조하려면 문자열을 전달하세요. Workflow우가 실행될 때 Tool는 Mastra 인스턴스에 등록되어야 합니다.

```typescript filename="src/mastra/workflows/test-workflow.ts" prettier:false
workflow.tool("lookup-customer", { retries: 2 }).commit();
```

## 지속적인 Tool 단계 {/* #persisting-tool-steps */}

다음으로 구축된 Workflow`.tool()` serialize to the same declarative entries that [dynamic workflows](/docs/workflows/dynamic-workflows) use. Only `retries` and `metadata` round-trip through storage. A function-valued `scorers` option throws an error when the workflow is stored.
