# 도커샌드박스

로컬 머신의 Docker 컨테이너 내에서 명령을 실행합니다. 다음과 같은 수명이 긴 컨테이너를 사용합니다.`docker exec`명령 실행을 위해. 클라우드 샌드박스가 불필요한 로컬 개발, CI/CD, 에어 갭 배포 및 비용에 민감한 시나리오를 대상으로 합니다. 인터페이스에 대한 자세한 내용은 다음을 참조하세요.[WorkspaceSandbox 인터페이스](/reference/workspace/sandbox).

## 설치 {/* #installation */}

```bash npm2yarn
npm install @mastra/docker
```

필요하다[Docker Engine](https://docs.docker.com/engine/install/) running on the host machine.

## 용법 {/* #usage */}

추가`DockerSandbox` to a workspace and assign it to an agent:

```typescript
import { Agent } from '@mastra/core/agent'
import { Workspace } from '@mastra/core/workspace'
import { DockerSandbox } from '@mastra/docker'

const workspace = new Workspace({
  sandbox: new DockerSandbox({
    image: 'node:22-slim',
  }),
})

const agent = new Agent({
  id: 'dev-agent',
  name: 'dev-agent',
  model: '__GATEWAY_ANTHROPIC_MODEL_OPUS__',
  workspace,
})
```

## 백그라운드 프로세스 {/* #background-processes */}

`DockerSandbox`백그라운드 프로세스 생성 및 관리를 위한 내장 프로세스 관리자가 포함되어 있습니다. 프로세스는 다음을 사용하여 컨테이너 내부에서 실행됩니다.`docker exec`.

```typescript
const sandbox = new DockerSandbox({ id: 'dev-sandbox' })
await sandbox._start()

// Spawn a background process
const handle = await sandbox.processes.spawn('node server.js', {
  env: { PORT: '3000' },
  onStdout: data => console.log(data),
})

// Interact with the process
console.log(handle.stdout)
await handle.sendStdin('input\n')
await handle.kill()
```

보다[`SandboxProcessManager` reference](/reference/workspace/process-manager) for the full API.

## 환경변수 {/* #environment-variables */}

다음을 사용하여 컨테이너 수준에서 환경 변수를 설정합니다.`env`. Per-command environment variables can also be passed when spawning processes:

```typescript
const sandbox = new DockerSandbox({
  image: 'node:22-slim',
  env: {
    NODE_ENV: 'production',
    DATABASE_URL: 'postgres://localhost:5432/mydb',
  },
})
```

## 바인드 마운트 {/* #bind-mounts */}

다음을 사용하여 호스트 디렉터리를 컨테이너에 마운트합니다.`volumes` option:

```typescript
const sandbox = new DockerSandbox({
  image: 'node:22-slim',
  volumes: {
    '/my/project': '/workspace/project',
    '/shared/data': '/data',
  },
})
```

바인드 마운트는 컨테이너 생성 시 적용됩니다. 샌드박스가 시작되기 전에 호스트 경로가 존재해야 합니다.

## 경화 {/* #hardening */}

Docker 특정 리소스 및 강화 옵션을 사용하여 샌드박스 컨테이너를 제한합니다. 다음 예에서는 CPU를 일치하는 단일 코어로 제한하면서 Memory와 프로세스 수를 제한합니다.`cpuPeriod` and `cpuQuota` values. It drops Linux capabilities and makes the root filesystem read-only, with `/tmp` mounted as writable scratch space:

```typescript
const sandbox = new DockerSandbox({
  image: 'node:22-slim',
  memory: 512 * 1024 * 1024,
  memorySwap: 512 * 1024 * 1024,
  cpuPeriod: 100_000,
  cpuQuota: 100_000,
  pidsLimit: 256,
  readonlyRootfs: true,
  capDrop: ['ALL'],
  capAdd: ['NET_BIND_SERVICE'],
  securityOpt: ['no-new-privileges:true'],
  ulimits: [{ name: 'nofile', soft: 1024, hard: 2048 }],
  tmpfs: {
    '/tmp': 'rw,noexec,nosuid,size=64m',
  },
})
```

이러한 옵션은 Docker에 직접 매핑됩니다.`HostConfig` fields and aren't set unless you pass them.

강화를 활성화하기 전에 다음 장단점을 검토하세요.

* `readonlyRootfs`: 탑재된 경로 외부에 쓰는 컨테이너 내 패키지 설치 및 Tool가 실패할 수 있습니다. 추가하다`tmpfs` entries for writable scratch paths such as `/tmp`, and mount tmpfs or volumes for package-manager caches such as `~/.npm` when needed.
* `capDrop`: 모든 기능을 삭제하면 다음을 포함하여 Linux 기능이 필요한 명령이 비활성화됩니다.`ping` and mount operations. FUSE-backed tools are also disabled. Add back only the capabilities your workload needs.
* `memory`: Docker가 처리합니다.`0` as unlimited. Omit `memory` or pass `0` only when you don't want a memory cap.
* `memorySwap`: Docker Memory 및 스왑 동작은 호스트 및 Docker 데몬 구성에 따라 다릅니다. 설정할 때`memory` without `memorySwap`, Docker allows swap up to twice the memory limit by default. Set `memorySwap` equal to `memory` when you want to disable swap for the container; Docker also accepts `-1` for unlimited swap.
* `pidsLimit`: 매우 낮은 값은 깨질 수 있습니다.`docker exec` workloads because each command starts additional processes inside the long-lived container.
* `privileged`: 권한 있는 컨테이너는 기능 및 보안 옵션 제어를 우회합니다. 결합하지 마십시오`privileged: true` with capability or security options unless the workload requires it.
* 재연결:`DockerSandbox` reuses an existing container when the sandbox ID matches and warns if inspected `HostConfig` hardening values differ. Destroy and recreate the sandbox to apply changed hardening options. Docker can normalize inspected values, and changing `memorySwap` on reconnect can trigger a warning if the original container used Docker's default swap behavior.
* Docker Desktop: 리소스 제한은 macOS 및 Windows의 Docker Desktop 가상 머신 내부에 적용되므로 VM에 할당된 리소스에 따라 컨테이너가 수신하는 리소스가 제한될 수 있습니다.

## 재연결 {/* #reconnection */}

`DockerSandbox`레이블을 일치시켜 기존 컨테이너에 다시 연결할 수 있습니다. 언제`start()` is called, it checks for a container with the `mastra.sandbox.id` label matching the sandbox ID. If found:

* 실행 중인 컨테이너는 직접 재사용됩니다.
* 중지된 컨테이너가 다시 시작됩니다.

```typescript
// First run — creates a new container
const sandbox = new DockerSandbox({ id: 'persistent-sandbox' })
await sandbox._start()

// Later — reconnects to the existing container
const sandbox2 = new DockerSandbox({ id: 'persistent-sandbox' })
await sandbox2._start()
```

## 도커 연결 옵션 {/* #docker-connection-options */}

원격 Docker 호스트에 연결하거나 다음을 통해 사용자 정의 소켓 경로를 사용하십시오.`dockerOptions`:

```typescript
// Remote Docker host
const sandbox = new DockerSandbox({
  dockerOptions: {
    host: '192.168.1.100',
    port: 2376,
    ca: fs.readFileSync('ca.pem'),
    cert: fs.readFileSync('cert.pem'),
    key: fs.readFileSync('key.pem'),
  },
})

// Custom socket path
const sandbox = new DockerSandbox({
  dockerOptions: {
    socketPath: '/var/run/docker.sock',
  },
})
```
