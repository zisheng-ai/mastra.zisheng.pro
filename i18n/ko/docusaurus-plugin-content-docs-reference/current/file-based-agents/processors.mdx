# 프로세서

파일 기반 Agent가 검색합니다.[processors](/docs/agents/processors)그로부터`processors/`예배 규칙서. 파일 기반 규칙을 보려면 이 페이지를 사용하십시오. 내장 프로세서, 맞춤형 프로세서, 스트리밍 동작 및 고급 패턴에 대한 프로세서 가이드를 사용하세요.

`processors/input/` 아래의 파일은 메시지가 Model에 도달하기 전에 실행됩니다. `processors/output/` 아래의 파일은 Model이 응답한 후 실행됩니다. 각 파일은 하나의 [`Processor`](/reference/processors/processor-interface)를 기본 내보내기하며, 파일 이름이 검색 키가 됩니다.
## 빠른 시작 {/* #quickstart */}

아래에 프로세서 파일을 배치하여 입력 프로세서를 추가합니다.`processors/input/`:

```typescript title="src/mastra/agents/weather/processors/input/pii.ts"
import { PIIDetector } from '@mastra/core/processors'

export default new PIIDetector({
  strategy: 'block',
})
```

이 프로세서는 사용자 메시지가 Model에 도달하기 전에 실행됩니다.

## 출력 프로세서 추가 {/* #add-an-output-processor */}

출력 프로세서는 Model 응답이 반환되기 전에 필터링하거나 변환하는 데 적합합니다. 이 예에서는 최종 응답에서 PII를 수정합니다.

```typescript title="src/mastra/agents/weather/processors/output/redact.ts"
import { PIIDetector } from '@mastra/core/processors'

export default new PIIDetector({
  strategy: 'redact',
})
```

## 주문 {/* #ordering */}

검색된 프로세서는 [`config.ts`](/reference/file-based-agents/config)에 정의된 프로세서 뒤에 추가됩니다. 따라서 구성 프로세서가 먼저 실행됩니다.
```text title="Ordering"
config.inputProcessors → processors/input/* → model
model → config.outputProcessors → processors/output/* → response
```

`config.inputProcessors` 또는 `config.outputProcessors`가 함수이면 함수형 프로세서를 정적으로 병합할 수 없으므로, 경고와 함께 해당 유형의 검색된 프로세서가 무시됩니다.
## 구성 우선순위 {/* #precedence-with-config */}

런타임에 생성하거나 여러 Agent에서 공유해야 하는 프로세서에는 `config.ts`를 사용하세요. Agent와 함께 검토할 정적인 Agent별 프로세서에는 파일 기반 프로세서를 사용하세요.
우선순위는 다음과 같습니다.

1. 함수 값 `config.inputProcessors` 또는 `config.outputProcessors`
2. 배열 값 `config.inputProcessors` 또는 `config.outputProcessors`
3. `processors/input/` 또는 `processors/output/`에서 검색된 파일
전체 인터페이스는 [`Processor` 참조](/reference/processors/processor-interface)를 확인하세요.
