# config.ts

대리인의`config.ts`Model 및 런타임 옵션을 설정합니다. 다음에 속하는 옵션에 사용합니다.[`Agent`](/reference/agents/agent)형제 파일은 지침, Tool, 기술 등을 제공합니다.

## 에 속하는 것`config.ts` {/* #what-belongs-in-configts */}

`config.ts`파일 기반 Agent의 Model 및 런타임 옵션에 대한 필수 진입점입니다. Model, 설명, 기본 실행 옵션, 재시도 동작, 채점자, 표시 ID 등 자체 파일이 필요하지 않은 경우 Agent 수준 설정을 여기에 입력하세요.

파일 기반 라우팅을 통해 형제 파일을 Agent에 병합하려는 경우 형제 파일의 인접한 문제를 유지하세요. 예를 들어`instructions.md` for the always-on prompt and `tools/` for model-callable actions.

## 빠른 시작 {/* #quickstart */}

다음`config.ts` plus an `instructions.md` file creates a working file-based agent:

```typescript title="src/mastra/agents/weather/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

```markdown title="src/mastra/agents/weather/instructions.md"
You are a helpful weather assistant. Answer questions about current conditions and forecasts.
```

마스트라는`weather` directory name as the default agent `id` and `name`. The sibling `instructions.md` supplies the required instructions.

## Model 설정 {/* #set-the-model */}

그만큼`model` field is the only required field in `agentConfig()`. The build fails when an agent directory doesn't provide a model. Other capabilities either come from sibling files or have defaults.

```typescript title="src/mastra/agents/weather/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

## 디렉토리의 신원 {/* #identity-from-the-directory */}

파일 기반 Agent의`id` and `name` default to the directory name. For `src/mastra/agents/weather/`, Mastra registers the agent as `weather` unless you override those fields.

보수`id` or `name` when the stable routing key and the display name should differ.

```typescript title="src/mastra/agents/weather/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  id: 'weather-assistant',
  name: 'Weather Assistant',
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

## 런타임 옵션 설정 {/* #set-runtime-options */}

`agentConfig()`받아들인다[`Agent` constructor options](/reference/agents/agent#constructor-parameters), except that `id`, `name`, and sibling-file fields can be supplied by the file-based convention. Use the Agent reference for the full option list.

참고:

* 파일 기반 하위 Agent에는 비어 있지 않은 값이 필요합니다.`description` because the parent model uses it for delegation routing.
* `defaultOptions`, `maxRetries`, `scorers`, and other Agent options can live in `config.ts` when they don't need their own file.

## 인접한 환경이 살고 있는 곳 {/* #where-adjacent-settings-live */}

유지하다`config.ts` focused on runtime options. Use sibling files for concerns that benefit from their own location.

| 설정 | 파일 또는 폴더 | 왜 거기에 사는가 |
| - | - | - |
| 지침 |[`instructions.md` or `instructions.ts`](/reference/file-based-agents/instructions) | Keeps the always-on prompt readable as markdown, or computed in TypeScript |
| Tools | [`tools/`](/reference/file-based-agents/tools) | Gives each callable action its own typed module |
| Skills | [`skills/`](/reference/file-based-agents/skills) | Keeps load-on-demand procedures separate from always-on instructions |
| Memory | [`memory.ts`](/reference/file-based-agents/memory) | Configures persistent memory without crowding runtime options |
| Workspace | [`workspace.ts`](/reference/file-based-agents/workspace) | Configures files and sandbox behavior separately from model settings |
| Processors | [`processors/`](/reference/file-based-agents/processors) | Separates input and output processing pipelines |
| Subagents | [`subagents/`](/reference/file-based-agents/subagents) | Gives each specialist child agent its own directory |

## 상위 {/* #precedence */}

`config.ts`다음 규칙에 따라 Agent의 다른 파일과 병합됩니다.

| 도메인 | 소스 A | 소스 B | 우승자 |
| - | - | - | - |
| 지침 | 동적`config.instructions` | [`instructions.ts` or `instructions.md`](/reference/file-based-agents/instructions) | Dynamic `config.instructions` |
| Instructions | Static `config.instructions` | [`instructions.ts` or `instructions.md`](/reference/file-based-agents/instructions) | The instructions file |
| Instructions | [`instructions.ts`](/reference/file-based-agents/instructions) | [`instructions.md`](/reference/file-based-agents/instructions) | `instructions.ts` |
| Tools | `config.tools` | [`tools/`](/reference/file-based-agents/tools) | Both merge; `config.tools` wins on key collisions |
| Tools | Function `config.tools` | [`tools/`](/reference/file-based-agents/tools) | Function `config.tools`; 발견된 Tool는 무시됩니다 |
| 기술 |`config.skills` | [`skills/`](/reference/file-based-agents/skills)| 둘 다 병합됩니다.`config.skills`이름 충돌로 승리 |
| 기술 | 기능`config.skills` | [`skills/`](/reference/file-based-agents/skills)| 기능`config.skills`; 발견된 스킬은 무시됩니다 |
| Memory |`config.memory` | [`memory.ts`](/reference/file-based-agents/memory) | `config.memory`|
| 작업공간 |`config.workspace` | [`workspace.ts`](/reference/file-based-agents/workspace) | `config.workspace` |

없어진`instructions.md`, `instructions.ts`, and `config.instructions` fails the build. Missing both `config.memory` and `memory.ts` leaves the agent without memory.

## 검색 수명주기 {/* #discovery-lifecycle */}

파일 기반 프리미티브는 Mastra 번들러에 의해 발견됩니다.`mastra dev` and `mastra build`. During discovery, Mastra reads supported files under `src/mastra/`, imports TypeScript and JavaScript modules, reads markdown instructions and skills, copies workspace seed files, and registers the assembled primitives with your Mastra app.

검색 후 파일 기반 Agent는 정상적으로 실행됩니다.[`Agent`](/reference/agents/agent). Calling it from the Agent API, Studio, workflows, or your application code uses the same runtime as a code-defined agent.

발견은 소스 기반이며 보수적입니다.

심볼릭 링크, 테스트 파일 및 Agent 디렉터리가 아닌 디렉터리를 건너뜁니다. Workflow 및 싱글톤 프로젝트 파일은 기본 내보내기가 있는 경우에만 파일 라우팅됩니다.

검색이 실행되도록 Mastra CLI를 통해 앱을 시작하세요.

```bash npm2yarn
npx mastra dev
```

수입하는 경우`mastra` instance directly, `agents/<name>/` directories and the other conventions aren't discovered. When you consume Mastra as a library, register those primitives in code instead.
