# 하위 Agent

파일 기반 Agent는 다음을 선언할 수 있습니다.**subagents**, 전문 아동 대리인에게 위임합니다. 상위 Model은 각 하위 Agent를 하위 Agent 디렉터리 이름을 딴 위임 Tool로 보고 해당 Tool를 호출하여 작업을 전달합니다. 하위 Agent의 결과는 상위 대화로 반환됩니다.

파일 기반 규칙에 대해서는 이 페이지를 사용하십시오. 더 광범위한 위임 패턴, 후크, Memory 격리, Tool 승인 전파 및 채점에 대해서는 다음을 참조하세요.[Supervisor agents](/docs/capabilities/subagents).

## 빠른 시작 {/* #quickstart */}

하위 Agent당 하나의 디렉터리를 선언합니다.`subagents/`:

```text title="Subagent layout"
src/mastra/agents/
└── supervisor/
    ├── config.ts
    ├── instructions.md
    └── subagents/
        └── researcher/
            ├── config.ts
            ├── instructions.md
            └── tools/
                └── search.ts
```

마스트라 조립`researcher` as its own agent and wires it into the supervisor's `agents` map. The parent model can delegate to it by using the generated `researcher` delegation tool.

하위 대리인의`config.ts` must set a non-empty `description`. The parent model reads this when deciding whether to delegate.

```typescript title="src/mastra/agents/supervisor/subagents/researcher/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  model: '__GATEWAY_OPENAI_MODEL__',
  description: 'Researches a topic and returns cited findings.',
})
```

## Model이 위임하는 방법 {/* #how-the-model-delegates */}

하위 대리인의`description` is routing text for the parent model. Write it like a [tool description](/reference/file-based-agents/tools#tool-options): explain what the subagent does and when to delegate to it.

검색된 하위 Agent가 비어 있지 않은 설명을 제공하지 않으면 빌드가 실패합니다.

## 격리 {/* #isolation */}

하위 Agent는 격리됩니다. 하위 Agent는 상위 Agent의 Tool, 기술, 작업 영역, Memory, 프로세서 또는 하위 Agent를 상속하지 않습니다. 각 하위 항목은 자체 디렉토리가 있는 독립형 Agent입니다.

여러 Agent가 동일한 종속성을 공유해야 하는 경우 이를 코드에서 정의하고 각 Agent의 구성을 통해 할당하세요.

## 중첩 {/* #nesting */}

하위 Agent는 자신의 것을 선언할 수 있습니다.`subagents/` directories, nesting up to three levels below the top-level agent. A `subagents/` directory nested deeper is ignored with a warning.

```text title="Nested subagents"
src/mastra/agents/
└── supervisor/            # depth 0
    └── subagents/
        └── researcher/    # depth 1
            └── subagents/
                └── summarizer/ # depth 2
```

## 명명 규칙 {/* #naming-rules */}

* 상위 Tool 키 중 하나와 충돌하는 하위 Agent ID는 빌드 오류입니다.
* 동일한 상위 아래 중복된 하위 Agent ID는 빌드 오류입니다.
* 하위 Agent ID가 상위 Agent에도 존재하는 경우`config.agents`, the `config.agents` entry wins and logs a warning.
* 만약에`config.agents` is a function, discovered subagents are ignored with a warning because they can't be statically merged.

## 예 {/* #example */}

이 감독자는 연구 및 글쓰기 흐름을 조정합니다. 그만큼`researcher` subagent owns search tools, while the `writer` subagent owns a workspace for drafting files.

```text title="Research supervisor"
src/mastra/agents/
└── research-supervisor/
    ├── config.ts
    ├── instructions.md
    └── subagents/
        ├── researcher/
        │   ├── config.ts
        │   ├── instructions.md
        │   └── tools/
        │       └── search_web.ts
        └── writer/
            ├── config.ts
            ├── instructions.md
            └── workspace/
                └── draft-template.md
```

```typescript title="src/mastra/agents/research-supervisor/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

```markdown title="src/mastra/agents/research-supervisor/instructions.md"
You coordinate research and writing.

Delegate fact gathering to `researcher`. Delegate final drafting to `writer`.
```

```typescript title="src/mastra/agents/research-supervisor/subagents/researcher/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  model: '__GATEWAY_OPENAI_MODEL_MINI__',
  description: 'Use to gather facts, sources, and concise research notes for a topic.',
})
```

```typescript title="src/mastra/agents/research-supervisor/subagents/writer/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  model: '__GATEWAY_OPENAI_MODEL__',
  description: 'Use to turn research notes into a structured draft.',
})
```
