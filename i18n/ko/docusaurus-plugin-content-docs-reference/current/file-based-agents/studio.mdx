# 사진관

마스트라 구성[Studio](/docs/studio/overview)에서`studio.ts`바로 아래 파일`src/mastra/`. 파일은 기본적으로`StudioConfig`Studio 인증 및 승인을 위한 개체: Studio에 액세스할 수 있는 사람과 인증된 사용자가 수행할 수 있는 작업.

파일 기반 규칙에 대해서는 이 페이지를 사용하십시오. 인증 공급자, 역할 기반 액세스 제어(RBAC) 및 세분화된 권한 부여(FGA)의 경우 다음을 참조하세요.[Studio auth](/docs/studio/auth).

## 빠른 시작 {/* #quickstart */}

지역 발전을 위해서는 필요하지 않습니다`studio.ts`. Start the dev server and open Studio:

```bash npm2yarn
npm run dev
```

Studio는 로컬 개발 시 인증 없이 열립니다. 추가하다`studio.ts` when you're ready to secure a shared or production deployment.

## 인증 추가 {/* #add-authentication */}

사용자가 Studio에 액세스하기 전에 로그인을 요구하려면 인증 공급자를 사용하세요. 이 예제에서는[WorkOS](/docs/server/auth/workos):

```typescript title="src/mastra/studio.ts"
import { MastraAuthWorkos } from '@mastra/auth-workos'
import type { StudioConfig } from '@mastra/core/server'

export default {
  auth: new MastraAuthWorkos(),
} satisfies StudioConfig
```

인증 공급자는 사용자가 누구인지 처리합니다. 사용자가 로그인 후 수행할 수 있는 작업을 확인하려면 동일한 구성에 RBAC 또는 FGA를 추가하세요. 보다[Studio auth](/docs/studio/auth) for full examples.

## 코드 우선순위 {/* #precedence-with-code */}

코드 등록된 Studio 구성이 승리합니다.`studio.ts`. Use `studio.ts` when one project-wide Studio config is enough. Use code registration when auth depends on runtime wiring in `src/mastra/index.ts`.
