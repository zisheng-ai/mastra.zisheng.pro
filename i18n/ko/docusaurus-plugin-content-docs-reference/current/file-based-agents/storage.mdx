# 저장

Mastra는 프로젝트의 기본값을 설정합니다.[storage](/docs/storage/overview)에서`storage.ts`바로 아래 파일`src/mastra/`. 파일은 기본적으로 Memory, Workflow, Observability 및 기타 스토리지 도메인에 사용되는 내장 Memory 저장소를 대체하는 저장소를 내보냅니다.

파일 기반 규칙에 대해서는 이 페이지를 사용하십시오. 백엔드 선택, 스토리지 도메인, 보존 및 공급자 세부 정보는 다음을 참조하세요.[storage overview](/docs/storage/overview).

## 빠른 시작 {/* #quickstart */}

사용[`LibSQLStore`](/reference/storage/libsql) for a local file-backed store:

```typescript title="src/mastra/storage.ts"
import { LibSQLStore } from '@mastra/libsql'

export default new LibSQLStore({
  id: 'mastra-storage',
  url: 'file:./mastra.db',
})
```

Mastra는 파일 기반 Agent 및 Workflow보다 먼저 저장소를 등록하므로 저장소 종속 기본 요소는 기본 Memory 내 저장소 대신 이 저장소에 바인딩됩니다.

## 프로덕션 백엔드 {/* #production-backends */}

`storage.ts`LibSQL, PostgreSQL 또는 MongoDB와 같은 Mastra 스토리지 어댑터를 내보낼 수 있습니다. 설정 패턴, 공급자 지원, 스키마 세부정보는 다음을 참조하세요.[storage overview](/docs/storage/overview), [observability signal support](/docs/observability/overview#signal-support), and the [storage reference](/reference/storage/overview).

## 코드 우선순위 {/* #precedence-with-code */}

코드 등록 스토리지가 승리합니다`storage.ts`. Use `storage.ts` when one project-wide store is enough. Use code registration when setup depends on runtime wiring in `src/mastra/index.ts`.
