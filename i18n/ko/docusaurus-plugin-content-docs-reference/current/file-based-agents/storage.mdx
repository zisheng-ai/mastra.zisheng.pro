# 저장

Mastra는 프로젝트의 기본값을 설정합니다.[storage](/docs/storage/overview)에서`storage.ts`바로 아래 파일`src/mastra/`. 파일은 기본적으로 Memory, Workflow, Observability 및 기타 스토리지 도메인에 사용되는 내장 Memory 저장소를 대체하는 저장소를 내보냅니다.

파일 기반 규칙에 대해서는 이 페이지를 사용하십시오. 백엔드 선택, 스토리지 도메인, 보존 및 공급자 세부 정보는 다음을 참조하세요.[storage overview](/docs/storage/overview).

## 빠른 시작 {/* #quickstart */}

로컬 파일 기반 스토어에는 [`LibSQLStore`](/reference/storage/libsql)를 사용하세요.
```typescript title="src/mastra/storage.ts"
import { LibSQLStore } from '@mastra/libsql'

export default new LibSQLStore({
  id: 'mastra-storage',
  url: 'file:./mastra.db',
})
```

Mastra는 파일 기반 Agent 및 Workflow보다 먼저 저장소를 등록하므로 저장소 종속 기본 요소는 기본 Memory 내 저장소 대신 이 저장소에 바인딩됩니다.

## 프로덕션 백엔드 {/* #production-backends */}

`storage.ts`는 LibSQL, PostgreSQL 또는 MongoDB와 같은 Mastra 스토리지 어댑터를 내보낼 수 있습니다. 구성 패턴, Provider 지원 및 스키마 세부 정보는 [스토리지 개요](/docs/storage/overview), [Observability 신호 지원](/docs/observability/overview#signal-support), [스토리지 참조](/reference/storage/overview)를 확인하세요.
## 코드 우선순위 {/* #precedence-with-code */}

코드로 등록한 스토리지가 `storage.ts`보다 우선합니다. 프로젝트 전체에서 하나의 스토어로 충분하면 `storage.ts`를 사용하세요. 설정이 `src/mastra/index.ts`의 런타임 연결에 따라 달라지면 코드 등록을 사용하세요.
