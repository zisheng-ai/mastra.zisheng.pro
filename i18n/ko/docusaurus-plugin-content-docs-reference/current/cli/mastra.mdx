# CLI 명령

Mastra에서 제공하는 명령줄 인터페이스(CLI)를 사용하여 Mastra 프로젝트를 개발, 빌드 및 시작할 수 있습니다.

## `mastra dev` {/* #mastra-dev */}

노출하는 서버를 시작합니다.[Studio](/docs/studio/overview) and REST endpoints for your agents, tools, and workflows. You can visit [http://localhost:4111/swagger-ui](http://localhost:4111/swagger-ui)사용 가능한 모든 엔드포인트에 대한 개요를 한 번에 확인하세요.`mastra dev`실행 중입니다.

당신은 또한 할 수 있습니다[configure the server](/reference/configuration#server-options).

### 플래그 {/* #flags */}

명령이 수락됩니다.[common flags][common-flags] and the following additional flags:

#### `--https` {/* #--https */}

로컬 HTTPS 지원을 활성화합니다.[Learn more](/reference/configuration#serverhttps).

#### `--inspect` {/* #--inspect */}

디버깅에 도움이 되는 검사 모드에서 개발 서버를 시작합니다. 선택적으로 맞춤 호스트와 포트를 지정합니다(예:`--inspect=0.0.0.0:9229` for Docker). This can't be used together with `--inspect-brk`.

#### `--inspect-brk` {/* #--inspect-brk */}

검사 모드에서 개발 서버를 시작하고 스크립트 시작 부분에서 중단합니다. 선택적으로 맞춤 호스트와 포트를 지정합니다(예:`--inspect-brk=0.0.0.0:9229`). This can't be used together with `--inspect`.

#### `--custom-args` {/* #--custom-args */}

Node.js 프로세스에 전달할 사용자 정의 인수의 쉼표로 구분된 목록입니다.`--require=newrelic` or `--experimental-transform-types`.

#### `--request-context-presets` {/* #--request-context-presets */}

다음을 포함하는 JSON 파일의 경로[request context](/docs/server/request-context) presets. When provided, a dropdown displays in Studio's request context editor, letting you quickly switch between preset configurations.

```bash
mastra dev --request-context-presets ./presets.json
```

파일은 각 키가 사전 설정된 이름이고 각 값이 객체인 JSON 객체여야 합니다.

```json
{
  "development": { "userId": "dev-user", "env": "development" },
  "production": { "userId": "prod-user", "env": "production" }
}
```

### 구성 {/* #configs */}

환경 변수를 설정하여 동작을 수정할 수 있습니다.`mastra dev`.

#### 피어 종속성 검사 건너뛰기 {/* #skip-peer-dependency-check */}

세트`MASTRA_SKIP_PEERDEP_CHECK=1` to skip the peer dependency version mismatch check at startup:

```bash
MASTRA_SKIP_PEERDEP_CHECK=1 mastra dev
```

이는 피어 종속성이 충돌할 수 있지만 패키지가 아직 게시되지 않은 단일 저장소 개발 중에 유용합니다.

#### 빌드 캐싱 비활성화 {/* #disable-build-caching */}

세트`MASTRA_DEV_NO_CACHE=1` to force a full rebuild rather than using the cached assets under `.mastra/`:

```bash
MASTRA_DEV_NO_CACHE=1 mastra dev
```

이는 번들러 플러그인을 디버깅하거나 오래된 출력이 의심되는 경우에 도움이 됩니다.

#### 병렬성 제한 {/* #limit-parallelism */}

`MASTRA_CONCURRENCY`병렬로 실행되는 비용이 많이 드는 작업 수를 제한합니다(주로 빌드 및 평가 단계). 예를 들어:

```bash
MASTRA_CONCURRENCY=4 mastra dev
```

CLI가 시스템에 적합한 기본값을 선택하도록 하려면 설정하지 않은 채로 두십시오.

#### 맞춤형 제공자 엔드포인트 {/* #custom-provider-endpoints */}

Vercel AI SDK에서 지원하는 공급자를 사용하는 경우 기본 URL을 설정하여 프록시 또는 내부 게이트웨이를 통해 요청을 리디렉션할 수 있습니다. OpenAI의 경우:

```bash
OPENAI_API_KEY=<your-api-key> \
OPENAI_BASE_URL=https://openrouter.example/v1 \
mastra dev
```

인류를 위한:

```bash
ANTHROPIC_API_KEY=<your-api-key> \
ANTHROPIC_BASE_URL=https://anthropic.internal \
mastra dev
```

이는 Mastra Model 라우터로 전달되며 모든 라우터에서 작동합니다.`"openai/..."`
or `"anthropic/..."` model selections.

## `mastra factory dev` {/* #mastra-factory-dev */}

개발 서버를 시작합니다.[Agent Builder](https://agent-builder.mastra.ai/) development. It uses the same dev runtime and flags as [`mastra dev`](#mastra-dev) and writes to the same `.mastra/output` directory.

```bash
npx mastra factory dev
```

두 명령 모두 동일한 개발 잠금을 공유하므로`mastra dev` and `mastra factory dev` can't run simultaneously in the same project. If one is already running, the other exits with a duplicate development server error.

사용`mastra factory dev` when developing Agent Builder features. It accepts the same flags as [`mastra dev`](#mastra-dev), including `--https`, `--inspect`, `--inspect-brk`, `--custom-args`, and `--request-context-presets`.

## `mastra build` {/* #mastra-build */}

그만큼`mastra build` command bundles your Mastra project into a production-ready Hono server. [Hono](https://hono.dev/) is a lightweight, type-safe web framework that makes it straightforward to deploy Mastra agents as HTTP endpoints with middleware support.

내부적으로 Mastra의 롤업 서버는 Mastra 항목 파일을 찾아 이를 프로덕션용 Hono 서버에 번들로 묶습니다. 번들링하는 동안 코드를 트리 셰이크하고 디버깅을 위한 소스 맵을 생성합니다.

출력은`.mastra` can be deployed to any cloud server using [`mastra start`](#mastra-start).

다음에 배포하는 경우[serverless platform](/docs/deployment/cloud-providers) you need to install the correct deployer to receive the correct output in `.mastra`.

그것은 받아들인다[common flags][common-flags].

## `mastra experiment build` {/* #mastra-experiment-build */}

HTTP 서버를 노출하지 않고 실험을 실행하는 독립 실행형 도우미 작업자를 빌드합니다. 작업자가 내보낸 파일을 로드합니다.`Mastra` instance and accepts versioned newline-delimited JSON (NDJSON) protocol messages on standard input. It writes protocol events to standard output.

```bash
mastra experiment build [options]
```

이 명령은 작업자에게 다음 위치에 기록합니다.`.mastra/experiment-worker` by default. The directory contains the executable entry point, production dependencies, and `experiment-worker-manifest.json`. Treat standard output as protocol-only output. Worker diagnostics are written to standard error.

### 유물계약 {/* #artifact-contract */}

`experiment-worker-manifest.json`아티팩트를 다음과 같이 식별합니다.`mastra-experiment-worker` version `1` and provides:

* 실행 파일에 포함된 CLI 버전, 생성 시간 및 고유 빌드 ID입니다.
* 지원되는 프로토콜 및 데이터 세트 정규화 버전.
* 작업자를 시작하는 데 필요한 실행 파일, 인수 및 작업 디렉터리입니다.
* 종속성 매니페스트 및 생성된 잠금 파일 경로.
* 각 아티팩트 파일에 대한 정렬된 SHA-256 다이제스트입니다.
* 해당 파일 경로 및 다이제스트에서 파생된 SHA-256 콘텐츠 다이제스트입니다.

콘텐츠 다이제스트는 제외됩니다.`experiment-worker-manifest.json` to avoid a self-referential digest. Package the manifest with the rest of the directory. Use an outer package digest when the manifest itself must be attested.

### 프로토콜 계약 {/* #protocol-contract */}

작업자는 고정된 실험 동료 작업자 프로토콜 버전을 구현합니다.`1`. It reads strict UTF-8 NDJSON frames from standard input and requires every frame, including the last one, to end with a newline. Frames larger than 1 MiB, malformed or truncated frames, unsupported protocol or canonicalization versions, and messages that don't match the active experiment correlation are rejected as protocol failures.

실행 요청은 아티팩트에 포함된 빌드 ID와 일치해야 하며 정렬된 데이터 세트 항목 수 및 SHA-256 증명을 포함해야 합니다. 작업자는 다음에서 시작하여 연속된 시퀀스 번호를 내보냅니다.`0`, timer-driven heartbeats, awaited experiment lifecycle events, and exactly one terminal event. Cancellation must match the active protocol version, experiment ID, job ID, attempt, and idempotency key.

프로토콜 종료 코드는 다음과 같습니다.

| 코드 | 의미 |
| - | - |
|`0` | Completed |
| `10` | Completed with item errors |
| `20` | Fatal failure |
| `21` | Retryable failure |
| `30` | Cancelled |
| `31` | Timed out |
| `70` | Protocol failure |

### 패킷 필드 처리 {/* #packet-field-handling */}

작업자는 대상 ID, 정렬된 인라인 데이터 세트 항목, 채점자 ID, 동시성, 시간 초과, 실험 메타데이터, 요청 컨텍스트, Tool 모의 및 취소를 전달합니다.`runExperiment`. Scorer versions and artifact provenance are retained as experiment metadata. Scorer code provenance is enforced by artifact admission rather than runtime scorer lookup.

버전`1` uses deterministic undeclared-tool denial. Non-empty network allowlists and secret references are rejected with a policy failure because network enforcement and secret materialization belong to the process sandbox. Dataset item source and expected-trajectory fields are preserved as item metadata when passed to `runExperiment`.

## `mastra deploy` {/* #mastra-deploy */}

선택한 Mastra 플랫폼 환경에 프로젝트를 빌드하고 배포합니다.`--env`. This is the recommended command for all new deploys and replaces both [`mastra studio deploy`](#mastra-studio-deploy) and [`mastra server deploy`](#mastra-server-deploy), which continue to work but should no longer be used for new setups.

다음을 통한 인증이 필요합니다.[`mastra auth login`](#mastra-auth-login) or a `MASTRA_API_TOKEN` environment variable.

```bash
mastra deploy
mastra deploy --env staging
mastra deploy --env production --region eu
```

명령이 실행됩니다.`mastra build` and zips the output before uploading it to the selected environment. It then polls the deploy status while streaming build logs until the deploy reaches a terminal state.

조직, 프로젝트, 환경은 다음 순서대로 해결됩니다. 환경 변수(`MASTRA_ORG_ID`, `MASTRA_PROJECT_ID`), CLI flag (`--org`, `--project`, `--env`), `.mastra-project.json` config file, current org from credentials, and lastly interactive prompt. On first deploy, the CLI saves the resolved org and project IDs to `.mastra-project.json` so subsequent deploys skip the prompts.

프로젝트가 아직 존재하지 않으면 CLI가 다음에서 프로젝트를 생성합니다.`package.json` `name` field after confirmation. If the target environment doesn't exist, the CLI creates it (defaulting to `type: staging` for anything other than `production`) after confirmation. Combined with `--yes`, this creates and deploys everything in one non-interactive command:

```bash
mastra deploy --env staging --yes
```

언제`--env <name>` is set and `--env-file` isn't, the CLI auto-selects `.env.<name>` from the project directory if present (for example `.env.staging`). The `<name>` value is validated against a strict allowlist before being interpolated into a file path.

### 인수 {/* #arguments */}

#### `[dir]` {/* #dir */}

프로젝트 디렉토리. 기본값은 현재 디렉터리입니다.

### 플래그 {/* #flags-7 */}

#### `--env` {/* #--env-1 */}

대상 환경 이름. 기본값은`production`. Auto-selects `.env.<name>` from the project directory when `--env-file` isn't set. If the environment doesn't exist, the CLI creates it after confirmation.

#### `--org` {/* #--org */}

조직 ID. 다음을 통해서도 설정할 수 있습니다.`MASTRA_ORG_ID` environment variable.

#### `--project` {/* #--project */}

프로젝트 ID, 슬러그 또는 이름. 다음을 통해서도 설정할 수 있습니다.`MASTRA_PROJECT_ID` environment variable. If no project matches, the value is used as the name of a new project to create on deploy.

#### `-y, --yes` {/* #-y---yes */}

프로젝트 및 환경 생성을 포함하여 확인 메시지 없이 기본값을 자동으로 수락합니다.

#### `-c, --config` {/* #-c---config */}

프로젝트 구성 파일의 경로입니다. 기본값은`.mastra-project.json`.

#### `--env-file` {/* #--env-file */}

배포와 함께 번들링할 env 파일의 경로입니다(프로젝트 디렉터리 기준). 설정되면 비활성화됩니다.`.env.<name>` auto-selection based on `--env`.

```bash
mastra deploy --env staging --env-file .env.staging.local
```

#### `--region` {/* #--region */}

새로 생성된 환경의 지역(예:`eu`). Applied only when the CLI creates the environment.

#### `--skip-build` {/* #--skip-build */}

빌드 단계를 건너뛰고 기존 배포`.mastra/output` directory. The CLI warns if the existing build is stale relative to the current source.

#### `--skip-preflight` {/* #--skip-preflight */}

## `mastra env` {/* #mastra-env */}

모든 하위 명령은 고정된 순서로 프로젝트를 해결합니다. 먼저 다음을 확인합니다.`MASTRA_PROJECT_ID` environment variable and the `--project <name|slug|id>` flag. It then reads the `.mastra-project.json` file written by [`mastra deploy`](#mastra-deploy) in the current directory. Run from your project directory and you never need to name the project.

### `mastra env list` {/* #mastra-env-list */}

```

#### `--json` {/* #--json */}

```

#### `-t, --type` {/* #-t---type */}

### `mastra env delete` {/* #mastra-env-delete */}

```

`<env>`환경 이름, 슬러그 또는 ID일 수 있습니다. 다음을 제외하면 CLI에서 확인 메시지를 표시합니다.`--yes` is passed.

#### `-y, --yes` {/* #-y---yes-1 */}

확인 메시지를 건너뜁니다.

`<env>`환경 이름, 슬러그 또는 ID일 수 있습니다. 환경이 배포된 적이 없는 경우 충돌 오류로 인해 실패합니다.

### `mastra env vars pull` {/* #mastra-env-vars-pull */}

환경의 env 변수를 로컬 env 파일로 가져옵니다(기본값:`.env`). The file contains the merged set used by a deploy. ```bash

```

`<env>`환경 이름, 슬러그 또는 ID일 수 있으며 프로젝트에 환경이 정확히 하나만 있는 경우 생략할 수 있습니다. 파일은 다음과 같이 작성됩니다.`0600` permissions. The command stops if the output file already exists. Pass `--force` to replace it.

#### `-o, --output` {/* #-o---output */}

쓸 파일입니다. 기본값은`.env`.

#### `-f, --force` {/* #-f---force */}

### `mastra env db` {/* #mastra-env-db */}

Mastra 플랫폼의 프로젝트에 연결된 데이터베이스를 관리합니다. 데이터베이스는 관리형 공급자(예: Turso 또는 Neon)에서 프로비저닝되고 해당 연결 환경 변수를 배포에 자동으로 삽입합니다.

데이터베이스는 다음 중 하나입니다.**environment-scoped** (its env vars only go to one environment) or **shared** (project-scoped: its env vars go to all environments). Environment-scoped is the default for `mastra env db create`: pass an environment argument, or let the CLI pick or prompt for one. Pass `--shared` on create to attach a shared database instead. For other subcommands (`list`, `delete`, `keys`), pass the environment argument to work with environment-scoped databases and omit it for shared databases.

데이터베이스를 생성하고 삭제하려면 다음이 필요합니다.`admin` role in the organization.

### `mastra env db list` {/* #mastra-env-db-list */}

공급자, 프로비저닝 상태, 범위(각 데이터베이스가 제공하는 환경) 및 각 데이터베이스가 삽입하는 환경 변수 이름을 포함하여 프로젝트에 연결된 데이터베이스를 나열합니다. 해당 환경(환경 범위 및 공유)을 제공하는 데이터베이스만 표시하려면 환경을 전달합니다.

```bash
mastra env db list
mastra env db list <env>
```

#### `--json` {/* #--json-2 */}

기계가 읽을 수 있는 JSON을 내보냅니다.

### `mastra env db create` {/* #mastra-env-db-create */}

관리형 데이터베이스를 프로비저닝하고 연결한 다음 준비될 때까지 폴링합니다. 프로비저닝 오류는 공급자의 오류 세부정보와 함께 인쇄됩니다.

기본적으로 데이터베이스는 단일 환경으로 범위가 지정됩니다. 이를 선택하려면 환경 인수를 전달하고, CLI가 자동으로 선택하도록 하려면 인수를 생략하세요. 프로젝트에 하나의 환경이 있으면 해당 환경이 사용됩니다. 여러 개가 있는 경우 CLI는 대화형으로 하나를 선택하라는 메시지를 표시합니다. 비대화형 컨텍스트(CI,`--json`) an environment argument is required. Pass `--shared` to attach a project-scoped database that's shared by every environment instead.

환경 범위 데이터베이스는 환경에서 공급자 지역을 상속합니다. 공유 데이터베이스 허용`--region`.

```bash
mastra env db create --kind turso                                    # picks or prompts for an environment
mastra env db create staging --kind turso                            # scoped to the "staging" environment
mastra env db create --kind turso --shared                           # shared by all environments
mastra env db create --kind neon --name my-app-db --region aws-us-east-1 --shared
```

#### `--kind` {/* #--kind */}

데이터베이스 공급자(필수) 다음 중 하나`turso` or `neon`.

#### `--name` {/* #--name */}

데이터베이스 이름. 기본값은 프로젝트 슬러그에서 파생된 이름입니다(예:`my-app-db`).

#### `--region` {/* #--region-1 */}

공유 데이터베이스의 공급자 지역 ID입니다. 환경 범위 데이터베이스의 경우 무시됩니다.

#### `--shared` {/* #--shared */}

모든 환경에서 공유되는 프로젝트 범위 데이터베이스로 연결합니다. 환경 인수와 결합할 수 없습니다.

#### `--no-wait` {/* #--no-wait */}

데이터베이스가 준비될 때까지 폴링하는 대신 연결이 대기열에 추가된 후 즉시 반환합니다. 나중에 진행 상황을 확인하세요.`mastra env db show`.

#### `--json` {/* #--json-3 */}

기계가 읽을 수 있는 JSON을 내보냅니다. 이 모드에서는 환경 인수 또는`--shared` is required when the project has more than one environment (no interactive prompt).

### `mastra env db show` {/* #mastra-env-db-show */}

데이터베이스 세부 정보를 표시하고, 데이터베이스가 준비되면 해당 연결 환경 변수를 표시합니다. 비밀 값은 기본적으로 마스크되어 있습니다.

### `mastra env db delete` {/* #mastra-env-db-delete */}

모든 데이터를 포함하여 공급자가 있는 데이터베이스를 영구적으로 삭제합니다. 이 작업은 취소할 수 없습니다. 다음을 제외하면 CLI에서 확인 메시지를 표시합니다.`--yes` is passed. After deletion, deploys no longer receive the database's env vars.

## `mastra studio deploy` {/* #mastra-studio-deploy */}

:::정보

`mastra studio deploy`계속 작동하지만 다음으로 대체되었습니다.[`mastra deploy`](#mastra-deploy), which supports environments (`--env staging`, `--env production`) on a single project. New setups should use `mastra deploy`.

:::

Mastra 플랫폼에 프로젝트를 빌드하고 배포합니다. 다음을 통한 인증이 필요합니다.[`mastra auth login`](#mastra-auth-login) or a `MASTRA_API_TOKEN` environment variable.

```bash
mastra studio deploy
```

명령이 실행됩니다.`mastra build` and zips the output. It reads an env file from the project directory before uploading everything to the platform. After uploading, it polls the deploy status and streams build logs until the deploy reaches a terminal state.

배포 명령은 프로젝트의`.env` file. If `MASTRA_PROJECT_ID` points to a project that was provisioned for Observability, the deploy links to that project instead of creating a new one. Deploying Studio to an observability-only project converts it into a Studio project on the platform side.

CLI에는 하나 이상이 필요합니다.`.env` or `.env.*` file (excluding `.env.example`) in the project directory and fails with `Error: No env file found for deploy.` if none exists. When multiple env files are present, the CLI prompts you to pick one (defaulting to `.env.production`). Pass `--env-file` to choose explicitly. With `--yes` and multiple env files, you must pass `--env-file` or the deploy errors.

조직과 프로젝트는 환경 변수 플래그,`.mastra-project.json` config file, current org from credentials, and lastly interactive prompt. On first deploy, the CLI saves the resolved IDs to `.mastra-project.json` so subsequent deploys skip the prompts.

만약에`--project <value>` doesn't match an existing project (by ID or slug), the CLI treats `<value>` as a new project name and creates it after confirmation. Combined with `--yes`, this creates and deploys a new project in one non-interactive command:

```bash
mastra studio deploy --project "my-new-project" --yes
```

확인 메시지 없이 기본값을 자동으로 수락합니다.

#### `-c, --config` {/* #-c---config-1 */}

프로젝트 구성 파일의 경로입니다. 기본값은`.mastra-project.json`.

### 목표 해상도 {/* #target-resolution */}

런타임 명령의 경우 명령은 다음 순서로 대상 서버를 확인합니다.

1. `--url <url>`명시적인 원격 또는 자체 호스팅 서버의 경우.
2. `http://localhost:4111`현지인을 위해`mastra dev` server.
3. `.mastra-project.json`Mastra 플랫폼 프로젝트를 위해.

자동 플랫폼 인증은 CLI가 Mastra 플랫폼 대상을 확인할 때만 사용됩니다.`.mastra-project.json`. Localhost targets and explicit `--url` targets don't receive automatic credentials. Headers passed with `--header` are sent to any target, including localhost.

Observability 명령의 경우(`trace`, `log`, `score`, and `metric`), the CLI targets `https://observability.mastra.ai` by default instead of a project deployment URL. Trace Intelligence commands (`learning`) work the same way but target `https://output.signals.mastra.ai`. Both resolve credentials in this order:

1. 명백한`Authorization` and `X-Mastra-Project-Id` headers passed with `--header`.
2. `MASTRA_PLATFORM_ACCESS_TOKEN`그리고`MASTRA_PROJECT_ID` from your environment.
3. 프로젝트 메타데이터`.mastra-project.json` for the project ID.
4. 인증 대체 수단으로 사용되는 Mastra CLI 로그인 토큰.

학습 명령도 전송됩니다.`X-Mastra-Organization-Id`, resolved from an explicit `--header`, `MASTRA_ORGANIZATION_ID` in your environment, or `.mastra-project.json`, in that order.

사용`--url` and `--header` when you need to override the default hosted observability target or credentials.

### 플래그 {/* #flags-13 */}

#### `--url <url>` {/* #--url-url */}

## 공통 플래그 {/* #common-flags */}

### `--dir` {/* #--dir-5 */}

**사용 가능 국가:** `dev`, `build`, `lint`, `migrate`

Mastra 폴더의 경로입니다. 기본값은`src/mastra`.

### `--debug` {/* #--debug-5 */}

**사용 가능 국가:** `dev`, `build`, `migrate`

Mastra 내부에 대한 자세한 로깅을 활성화합니다. 기본값은`false`.

### `--env` {/* #--env-2 */}

**사용 가능 국가:** `dev`, `start`, `studio`, `migrate`

포함할 사용자 정의 환경 변수 파일입니다. 기본적으로 다음이 포함됩니다.`.env.development`, `.env.local`, and `.env`.

### `--root` {/* #--root-2 */}

**사용 가능 국가:** `dev`, `build`, `lint`, `migrate`

루트 폴더의 경로입니다. 기본값은`process.cwd()`.

### `--tools` {/* #--tools-1 */}

**사용 가능 국가:** `dev`, `build`, `lint`

포함할 Tool 경로의 쉼표로 구분된 목록입니다. 기본값은`src/mastra/tools`.

## 원격 측정 {/* #telemetry */}

기본적으로 Mastra는 OS, Mastra 버전 또는 Node.js 버전과 같은 프로젝트에 대한 익명 정보를 수집합니다. 당신은 읽을 수 있습니다[source code](https://github.com/mastra-ai/mastra/blob/main/packages/cli/src/analytics/index.ts) to check what's collected.

서버가 다음으로 시작되었을 때`mastra dev` or `mastra start` has observability metrics enabled, Mastra also sends anonymous, aggregated model usage at startup: input and output token counts per provider and model, plus the command (`dev` or `start`) and `NODE_ENV`. No prompts, responses, or other message content is ever sent. You can read the [source code](https://github.com/mastra-ai/mastra/blob/main/packages/core/src/telemetry/usage-telemetry.ts) to check what's collected.

서버 시작 시 Mastra는 등록된 Agent, Agent 컨트롤러, Workflow, Tool, 프로세서, 벡터 저장소, 채점자, 작업 공간, MCP 서버, 게이트웨이 및 채널 수와 Memory, 음성, 편집기 및 Observability 사용에 대한 부울과 대략적인 스토리지 백엔드 범주 등 익명의 프로젝트 표면 스냅샷도 보냅니다. 이름이나 식별자는 보내지 않습니다. 당신은 읽을 수 있습니다[source code](https://github.com/mastra-ai/mastra/blob/main/packages/core/src/telemetry/feature-telemetry.ts) to check what's collected.

환경 변수를 설정하여 모든 CLI 및 사용량 분석을 옵트아웃할 수 있습니다.

```bash
MASTRA_TELEMETRY_DISABLED=1
```

다른 것을 사용하는 동안에도 이를 설정할 수 있습니다.`mastra` commands:

```bash
MASTRA_TELEMETRY_DISABLED=1 mastra dev
```
