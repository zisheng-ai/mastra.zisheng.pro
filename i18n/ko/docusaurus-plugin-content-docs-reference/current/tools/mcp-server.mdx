# MCP서버

그만큼`MCPServer`클래스는 기존 Mastra Tool 및 Agent를 MCP(Model Context Protocol) 서버로 노출하는 기능을 제공합니다. 이를 통해 모든 MCP 클라이언트(예: Cursor, Windsurf 또는 Claude Desktop)가 이러한 기능에 연결하여 Agent가 사용할 수 있도록 할 수 있습니다.

Mastra 애플리케이션 내에서 직접 Tool나 Agent만 사용해야 하는 경우 반드시 MCP 서버를 만들 필요는 없습니다. 이 API는 특히 Mastra Tool 및 Agent를 노출하기 위한 것입니다.*external* MCP clients.

[stdio(하위 프로세스) 및 SSE(HTTP) MCP 전송](https://modelcontextprotocol.io/docs/concepts/transports)을 모두 지원합니다.
## 건설자 {/* #constructor */}

새 `MCPServer`를 생성하려면 서버에 관한 기본 정보, 서버가 제공할 Tool, 그리고 선택적으로 Tool로 노출할 Agent를 제공해야 합니다.
```typescript
import { Agent } from '@mastra/core/agent'
import { createTool } from '@mastra/core/tools'
import { MCPServer } from '@mastra/mcp'
import { z } from 'zod'
import { dataProcessingWorkflow } from '../workflows/dataProcessingWorkflow'

const myAgent = new Agent({
  id: 'my-example-agent',
  name: 'MyExampleAgent',
  description: 'A generalist to help with basic questions.',
  instructions: 'You are a helpful assistant.',
  model: '__GATEWAY_OPENAI_MODEL__',
})

const weatherTool = createTool({
  id: 'getWeather',
  description: 'Gets the current weather for a location.',
  inputSchema: z.object({ location: z.string() }),
  execute: async inputData => `Weather in ${inputData.location} is sunny.`,
})

const server = new MCPServer({
  id: 'my-custom-server',
  name: 'My Custom Server',
  version: '1.0.0',
  description: 'A server that provides weather data and agent capabilities',
  instructions:
    'Use the available tools to help users with weather information and data processing tasks.',
  tools: { weatherTool },
  agents: { myAgent }, // this agent will become tool "ask_myAgent"
  workflows: {
    dataProcessingWorkflow, // this workflow will become tool "run_dataProcessingWorkflow"
  },
})
```

## Agent를 Tool로 노출 {/* #exposing-agents-as-tools */}

`MCPServer`의 강력한 기능 중 하나는 Mastra Agent를 호출 가능한 Tool로 자동 노출하는 것입니다. 구성의 `agents` 속성에 Agent를 제공하면 다음과 같이 동작합니다.
* **Tool 명명**: 각 Agent는 `ask_<agentKey>`라는 Tool로 변환됩니다. 여기서 `<agentKey>`는 `agents` 객체에서 해당 Agent에 사용한 키입니다. 예를 들어 `agents: { myAgentKey: myAgentInstance }`로 구성하면 이름이 `ask_myAgentKey`인 Tool이 생성됩니다.
* **Tool 기능**:
  * **설명**: 생성된 Tool의 설명은 "Agent `<AgentName>`에게 질문합니다. 원래 Agent 지침: `<agent description>`" 형식입니다.
  * **입력**: Tool은 `message` 속성(문자열)이 있는 단일 객체 인수 `{ message: "Your question for the agent" }`를 받습니다.
  * **실행**: 이 Tool을 호출하면 제공된 `query`로 해당 Agent의 `generate()` 메서드를 호출합니다.
  * **출력**: Agent의 `generate()` 메서드가 반환한 결과를 Tool의 출력으로 그대로 반환합니다.
* **이름 충돌.** `tools` 구성에 명시적으로 정의된 Tool의 이름이 Agent에서 파생된 Tool의 이름과 같으면(예: 키가 `myAgentKey`인 Agent와 이름이 `ask_myAgentKey`인 Tool을 함께 구성한 경우), *명시적으로 정의된 Tool이 우선합니다*. 충돌이 발생한 Agent는 Tool로 변환되지 않으며 경고가 기록됩니다.
이를 통해 MCP 클라이언트가 다른 Tool와 마찬가지로 자연어 쿼리를 사용하여 Agent와 상호 작용할 수 있도록 하는 것이 간단해졌습니다.

### Agent에서 Tool로의 변환 {/* #agent-to-tool-conversion */}

`agents` 구성 속성에 Agent를 제공하면 `MCPServer`가 각 Agent에 대응하는 Tool을 자동으로 생성합니다. Tool의 이름은 `ask_<agentIdentifier>`이며, 여기서 `<agentIdentifier>`는 `agents` 객체에 사용한 키입니다.
생성된 Tool의 설명은 "Agent `<agent.name>`에게 질문합니다. Agent 설명: `<agent.description>`" 형식입니다.
Tool로 변환할 Agent는 인스턴스 생성 시 구성에 비어 있지 않은 `description` 문자열 속성이 **반드시** 설정되어 있어야 합니다(예: `new Agent({ id: 'my-agent', name: 'myAgent', description: 'This agent does X.', ... })`). `description`이 없거나 비어 있는 Agent를 `MCPServer`에 전달하면 `MCPServer` 인스턴스 생성 시 오류가 발생하고 서버 설정에 실패합니다.
이를 통해 MCP를 통해 Agent의 생성 기능을 신속하게 노출할 수 있으므로 클라이언트가 Agent에 직접 질문할 수 있습니다.

### Tool에서 MCP 컨텍스트에 액세스 {/* #accessing-mcp-context-in-tools */}

`MCPServer`를 통해 노출된 Tool은 호출 방식에 따라 서로 다른 두 속성을 통해 MCP 요청 컨텍스트(인증, 세션 ID 등)에 액세스할 수 있습니다.
| 통화 패턴 | 접근방법 |
| - | - |
| 직접 Tool 호출 |`context?.mcp?.extra` |
| Agent tool call | `context?.requestContext?.get("mcp.extra")` |

**유니버설 패턴**(두 가지 상황 모두에서 작동):

```typescript
const mcpExtra = context?.mcp?.extra ?? context?.requestContext?.get('mcp.extra')
const authInfo = mcpExtra?.authInfo
```

#### 예: 두 컨텍스트 모두에서 작동하는 Tool {/* #example-tool-that-works-in-both-contexts */}

```typescript
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

const fetchUserData = createTool({
  id: 'fetchUserData',
  description: 'Fetches user data using authentication from MCP context',
  inputSchema: z.object({
    userId: z.string().describe('The ID of the user to fetch'),
  }),
  execute: async (inputData, context) => {
    // Access MCP authentication context
    // When called directly via MCP: context.mcp.extra
    // When called via agent: context.requestContext.get('mcp.extra')
    const mcpExtra = context?.mcp?.extra || context?.requestContext?.get('mcp.extra')
    const authInfo = mcpExtra?.authInfo

    if (!authInfo?.token) {
      throw new Error('Authentication required')
    }

    const response = await fetch(`https://api.example.com/users/${inputData.userId}`, {
      headers: {
        Authorization: `Bearer ${authInfo.token}`,
      },
    })

    return response.json()
  },
})
```

## 행동 양식 {/* #methods */}

다음은 동작을 제어하고 정보를 가져오기 위해 `MCPServer` 인스턴스에서 호출할 수 있는 함수입니다.
### `startStdio()` {/* #startstdio */}

표준 입력 및 출력(stdio)을 사용하여 통신하도록 서버를 시작하려면 이 방법을 사용합니다. 이는 서버를 명령줄 프로그램으로 실행할 때 일반적입니다.

```typescript prettier:false
async startStdio(): Promise<void>
```

stdio를 사용하여 서버를 시작하는 방법은 다음과 같습니다.

```typescript
const server = new MCPServer({
  id: 'my-server',
  name: 'My Server',
  version: '1.0.0',
  tools: {/* ... */},
})
await server.startStdio()
```

### `startSSE()` {/* #startsse */}

이 방법을 사용하면 MCP 서버를 기존 웹 서버와 통합하여 통신에 SSE(Server-Sent Events)를 사용할 수 있습니다. SSE 또는 메시지 경로에 대한 요청을 수신하면 웹 서버 코드에서 이를 호출합니다.

```typescript prettier:false
async startSSE({
  url,
  ssePath,
  messagePath,
  req,
  res,
}: {
  url: URL;
  ssePath: string;
  messagePath: string;
  req: any;
  res: any;
}): Promise<void>
```

다음은 HTTP 서버 요청 핸들러 내에서 `startSSE`를 사용하는 예입니다. 이 예에서 MCP 클라이언트는 `http://localhost:1234/sse`의 MCP 서버에 연결할 수 있습니다.
```typescript
import http from 'http'

const httpServer = http.createServer(async (req, res) => {
  await server.startSSE({
    url: new URL(req.url || '', `http://localhost:1234`),
    ssePath: '/sse',
    messagePath: '/message',
    req,
    res,
  })
})

httpServer.listen(PORT, () => {
  console.log(`HTTP server listening on port ${PORT}`)
})
```

### `startHTTP()` {/* #starthttp */}

이 방법을 사용하면 MCP 서버를 기존 웹 서버와 통합하여 스트리밍 가능한 HTTP를 사용하여 통신할 수 있습니다. HTTP 요청을 받을 때 웹 서버의 코드에서 이를 호출합니다.

```typescript prettier:false
async startHTTP({
  url,
  httpPath,
  req,
  res,
  options = { sessionIdGenerator: () => randomUUID() },
}: {
  url: URL;
  httpPath: string;
  req: http.IncomingMessage;
  res: http.ServerResponse<http.IncomingMessage>;
  options?: StreamableHTTPServerTransportOptions;
}): Promise<void>
```

다음은 HTTP 서버 요청 핸들러 내에서 `startHTTP`를 사용하는 예입니다. 이 예에서 MCP 클라이언트는 `http://localhost:1234/http`의 MCP 서버에 연결할 수 있습니다.
```typescript
import http from 'http'

const httpServer = http.createServer(async (req, res) => {
  await server.startHTTP({
    url: new URL(req.url || '', 'http://localhost:1234'),
    httpPath: `/mcp`,
    req,
    res,
    options: {
      sessionIdGenerator: () => randomUUID(),
    },
  })
})

httpServer.listen(PORT, () => {
  console.log(`HTTP server listening on port ${PORT}`)
})
```

**서버리스 환경**(Supabase Edge Functions, Cloudflare Workers, Vercel Edge 등)에서는 `serverless: true`를 사용하여 무상태 작동을 활성화하세요.
```typescript
// Supabase Edge Function example
import { serve } from 'https://deno.land/std@0.168.0/http/server.ts'
import { MCPServer } from '@mastra/mcp'
// Note: You will need to convert req/res format from Deno to Node
import { toReqRes, toFetchResponse } from 'fetch-to-node'

const server = new MCPServer({
  id: 'my-serverless-mcp',
  name: 'My Serverless MCP',
  version: '1.0.0',
  tools: {/* your tools */},
})

serve(async req => {
  const url = new URL(req.url)

  if (url.pathname === '/mcp') {
    // Convert Deno Request to Node.js-compatible format
    const { req: nodeReq, res: nodeRes } = toReqRes(req)

    await server.startHTTP({
      url,
      httpPath: '/mcp',
      req: nodeReq,
      res: nodeRes,
      options: {
        serverless: true, // ← Enable stateless mode for serverless
      },
    })

    return toFetchResponse(nodeRes)
  }

  return new Response('Not found', { status: 404 })
})
```

:::info\[서버리스를 사용하는 경우: true]

각 요청이 새로운 무상태 실행 컨텍스트에서 실행되는 환경에 배포할 때는 `serverless: true`를 사용하세요.
* Supabase Edge 함수
* Cloudflare 작업자
* Vercel 엣지 기능
* Netlify 엣지 기능
* AWS 람다
* 데노 배포

다음의 경우 기본 세션 기반 모드(`serverless: true`)를 사용합니다.
* 수명이 긴 Node.js 서버
* 도커 컨테이너
* 기존 호스팅(VPS, 전용 서버)

서버리스 모드는 세션 관리를 비활성화하고 요청마다 새로운 서버 인스턴스를 생성합니다. 이는 호출 간에 Memory가 유지되지 않는 상태 비저장 환경에 필요합니다.

기본적으로 서버리스 모드는 각 요청을 하나의 JSON 응답으로 버퍼링하므로 Tool이 보낸 `notifications/progress`가 클라이언트에 도달하지 않습니다. 대신 요청 범위 SSE 스트리밍으로 요청을 처리하려면 `serverlessStreaming: true`를 설정하세요. 그러면 최종 결과보다 먼저 진행률 알림이 전달됩니다.
```typescript
await server.startHTTP({
  url,
  httpPath: '/mcp',
  req: nodeReq,
  res: nodeRes,
  options: {
    serverless: true,
    serverlessStreaming: true, // ← Stream request-scoped notifications/progress
  },
})
```

이 방식도 무상태입니다. `mcp-session-id`는 필요하지 않으며 유지되지도 않습니다. 현재 요청 범위의 알림(예: 진행률)만 활성화합니다. 아래의 세션 종속 기능은 계속 사용할 수 없습니다.
다음 MCP 기능은 세션 상태 또는 지속적인 연결이 필요하므로 서버리스 모드(`serverlessStreaming: true` 포함)에서 **작동하지 않습니다**.
* **사용자 입력 요청** - Tool 실행 중 대화형 사용자 입력 요청에는 응답을 올바른 클라이언트로 다시 라우팅하기 위한 세션 관리가 필요합니다.
* **리소스 구독** - `resources/subscribe` 및 `resources/unsubscribe`에는 구독 상태를 유지하기 위한 지속적인 연결이 필요합니다.
* **리소스 업데이트 알림** - `resources.notifyUpdated()`가 클라이언트에 알림을 보내려면 활성 구독과 지속적인 연결이 필요합니다.
* **Prompt 목록 변경 알림** - `prompts.notifyListChanged()`가 클라이언트에 업데이트를 푸시하려면 지속적인 연결이 필요합니다.
* **Tool 목록 변경 알림** - `toolActions.notifyListChanged()`가 클라이언트에 업데이트를 푸시하려면 지속적인 연결이 필요합니다.
* **서버 로그 알림** - `sendLoggingMessage()`가 클라이언트에 로그 메시지를 푸시하려면 지속적인 연결이 필요합니다.
이러한 기능은 일반적으로 수명이 긴 서버 환경(Node.js 서버, Docker 컨테이너 등)에서 작동합니다.

## 자원 처리 {/* #resource-handling */}

### MCP 리소스란 무엇입니까? {/* #what-are-mcp-resources */}

리소스는 서버가 클라이언트가 읽을 수 있고 LLM 상호 작용을 위한 컨텍스트로 사용할 수 있는 데이터와 콘텐츠를 노출할 수 있도록 하는 MCP(Model 컨텍스트 프로토콜)의 핵심 기본 요소입니다. 이는 MCP 서버가 다음과 같이 사용 가능하게 하려는 모든 종류의 데이터를 나타냅니다.

* 파일 내용
* 데이터베이스 기록
* API 응답
* 라이브 시스템 데이터
* 스크린샷 및 이미지
* 로그 파일

리소스는 고유한 URI(예: `file:///home/user/documents/report.pdf`, `postgres://database/customers/schema`)로 식별되며 텍스트(UTF-8 인코딩) 또는 바이너리 데이터(base64 인코딩)를 포함할 수 있습니다.
클라이언트는 다음을 통해 리소스를 검색할 수 있습니다.

1. **직접적인 자원**: 서버는 다음을 통해 구체적인 리소스 목록을 노출합니다.`resources/list` endpoint.
2. **리소스 템플릿**: 런타임 정의 리소스의 경우 서버는 클라이언트가 리소스 URI를 구성하는 데 사용하는 URI 템플릿(RFC 6570)을 노출할 수 있습니다.

리소스를 읽으려면 클라이언트가 URI와 함께 `resources/read` 요청을 보냅니다. 클라이언트가 해당 리소스를 구독한 경우 서버는 리소스 목록 변경(`notifications/resources/list_changed`)이나 특정 리소스 콘텐츠 업데이트(`notifications/resources/updated`)도 클라이언트에 알릴 수 있습니다.
자세한 내용은 [리소스에 관한 공식 MCP 문서](https://modelcontextprotocol.io/docs/concepts/resources)를 참조하세요.
### `MCPServerResources`유형 {/* #mcpserverresources-type */}

`resources` 옵션은 `MCPServerResources` 유형의 객체를 받습니다. 이 유형은 서버가 리소스 요청을 처리하는 데 사용할 콜백을 정의합니다.
```typescript
export type MCPServerResources = {
  // Callback to list available resources
  listResources: () => Promise<Resource[]>

  // Callback to get the content of a specific resource
  getResourceContent: ({
    uri,
  }: {
    uri: string
  }) => Promise<MCPServerResourceContent | MCPServerResourceContent[]>

  // Optional callback to list available resource templates
  resourceTemplates?: () => Promise<ResourceTemplate[]>
}

export type MCPServerResourceContent = { text?: string } | { blob?: string }
```

예:

```typescript
import { MCPServer } from '@mastra/mcp'
import type { MCPServerResourceContent, Resource, ResourceTemplate } from '@mastra/mcp'

// Resources/resource templates will generally be dynamically fetched.
const myResources: Resource[] = [
  { uri: 'file://data/123.txt', name: 'Data File', mimeType: 'text/plain' },
]

const myResourceContents: Record<string, MCPServerResourceContent> = {
  'file://data.txt/123': { text: 'This is the content of the data file.' },
}

const myResourceTemplates: ResourceTemplate[] = [
  {
    uriTemplate: 'file://data/{id}',
    name: 'Data File',
    description: 'A file containing data.',
    mimeType: 'text/plain',
  },
]

const myResourceHandlers: MCPServerResources = {
  listResources: async () => myResources,
  getResourceContent: async ({ uri }) => {
    if (myResourceContents[uri]) {
      return myResourceContents[uri]
    }
    throw new Error(`Resource content not found for ${uri}`)
  },
  resourceTemplates: async () => myResourceTemplates,
}

const serverWithResources = new MCPServer({
  id: 'resourceful-server',
  name: 'Resourceful Server',
  version: '1.0.0',
  tools: {/* ... your tools ... */},
  resources: myResourceHandlers,
})
```

### 클라이언트에게 리소스 변경 사항 알리기 {/* #notifying-clients-of-resource-changes */}

사용 가능한 리소스나 콘텐츠가 변경되면 서버는 특정 리소스를 구독하는 연결된 클라이언트에게 알릴 수 있습니다.

#### `server.resources.notifyUpdated({ uri: string })` {/* #serverresourcesnotifyupdated-uri-string- */}

특정 리소스의 콘텐츠(`uri`)가 업데이트되었습니다. 이 URI를 구독 중인 클라이언트가 있으면 `notifications/resources/updated` 메시지를 받습니다.
```typescript prettier:false
async server.resources.notifyUpdated({ uri: string }): Promise<void>
```

예:

```typescript
// After updating the content of 'file://data.txt'
await serverWithResources.resources.notifyUpdated({ uri: 'file://data.txt' })
```

#### `server.resources.notifyListChanged()` {/* #serverresourcesnotifylistchanged */}

사용 가능한 리소스 목록이 변경된 경우(예: 리소스가 추가되거나 제거된 경우) 이 메서드를 호출하세요. 그러면 클라이언트에 `notifications/resources/list_changed` 메시지가 전송되어 리소스 목록을 다시 가져오도록 안내합니다.
```typescript prettier:false
async server.resources.notifyListChanged(): Promise<void>
```

예:

```typescript
// After adding a new resource to the list managed by 'myResourceHandlers.listResources'
await serverWithResources.resources.notifyListChanged()
```

## 신속한 처리 {/* #prompt-handling */}

### MCP Prompt란 무엇입니까? {/* #what-are-mcp-prompts */}

Prompt는 MCP 서버가 클라이언트에 노출하는 재사용 가능한 템플릿 또는 Workflow입니다. 인수를 허용하고 리소스 컨텍스트를 포함할 수 있습니다. 또한 버전 관리를 지원하고 LLM 상호 작용을 표준화합니다.

Prompt는 고유한 이름(및 선택적 버전)으로 식별되며 런타임에 정의되거나 정적일 수 있습니다.

### `MCPServerPrompts`유형 {/* #mcpserverprompts-type */}

`prompts` 옵션은 `MCPServerPrompts` 유형의 객체를 받습니다. 이 유형은 서버가 Prompt 요청을 처리하는 데 사용할 콜백을 정의합니다.
```typescript
export type MCPServerPrompts = {
  // Callback to list available prompts
  listPrompts: () => Promise<Prompt[]>

  // Callback to get the messages/content for a specific prompt
  getPromptMessages?: ({
    name,
    version,
    args,
  }: {
    name: string
    version?: string
    args?: any
  }) => Promise<{ prompt: Prompt; messages: PromptMessage[] }>
}
```

예:

```typescript
import { MCPServer } from '@mastra/mcp'
import type { Prompt, PromptMessage, MCPServerPrompts } from '@mastra/mcp'

const prompts: Prompt[] = [
  {
    name: 'analyze-code',
    description: 'Analyze code for improvements',
    version: 'v1',
  },
  {
    name: 'analyze-code',
    description: 'Analyze code for improvements (new logic)',
    version: 'v2',
  },
]

const myPromptHandlers: MCPServerPrompts = {
  listPrompts: async () => prompts,
  getPromptMessages: async ({ name, version, args }) => {
    if (name === 'analyze-code') {
      if (version === 'v2') {
        const prompt = prompts.find(p => p.name === name && p.version === 'v2')
        if (!prompt) throw new Error('Prompt version not found')
        return {
          prompt,
          messages: [
            {
              role: 'user',
              content: {
                type: 'text',
                text: `Analyze this code with the new logic: ${args.code}`,
              },
            },
          ],
        }
      }
      // Default or v1
      const prompt = prompts.find(p => p.name === name && p.version === 'v1')
      if (!prompt) throw new Error('Prompt version not found')
      return {
        prompt,
        messages: [
          {
            role: 'user',
            content: { type: 'text', text: `Analyze this code: ${args.code}` },
          },
        ],
      }
    }
    throw new Error('Prompt not found')
  },
}

const serverWithPrompts = new MCPServer({
  id: 'promptful-server',
  name: 'Promptful Server',
  version: '1.0.0',
  tools: {/* ... */},
  prompts: myPromptHandlers,
})
```

### 즉각적인 변경 사항을 고객에게 알리기 {/* #notifying-clients-of-prompt-changes */}

사용 가능한 Prompt가 변경되면 서버는 연결된 클라이언트에 알릴 수 있습니다.

#### `server.prompts.notifyListChanged()` {/* #serverpromptsnotifylistchanged */}

사용 가능한 Prompt 목록이 변경된 경우(예: Prompt가 추가되거나 제거된 경우) 이 메서드를 호출하세요. 그러면 클라이언트에 `notifications/prompts/list_changed` 메시지가 전송되어 Prompt 목록을 다시 가져오도록 안내합니다.
```typescript
await serverWithPrompts.prompts.notifyListChanged()
```

### 신속한 처리 모범 사례 {/* #best-practices-for-prompt-handling */}

* 명확하고 설명적인 Prompt 이름과 설명을 사용하세요.
* `getPromptMessages`에서 모든 필수 인수의 유효성을 검사하세요.
* 호환성을 깨는 변경이 예상된다면 `version` 필드를 포함하세요.
* `version` 매개변수를 사용하여 올바른 Prompt 로직을 선택하세요.
* Prompt 목록이 변경되면 클라이언트에 알리세요.
* 유용한 정보를 제공하는 메시지로 오류를 처리하세요.
* 예상 인수와 사용 가능한 버전을 문서화하세요.
## 동적 Tool 관리 {/* #dynamic-tool-management */}

Tool은 일반적으로 `MCPServer`를 구성할 때 제공하지만 서버가 실행되는 동안 추가하거나 제거할 수도 있습니다. 서버는 `toolActions` 속성을 통해 이러한 작업을 노출합니다. Tool 목록이 변경되면 연결된 클라이언트가 `notifications/tools/list_changed` 메시지를 받아 Tool 목록을 다시 가져옵니다.
등록된 Tool 레지스트리를 반환하는 메서드가 `tools()`이므로 이 속성의 이름은 `toolActions`입니다.
### `toolActions.add(tools)` {/* #toolactionsaddtools */}

실행중인 서버에 새로운 Tool를 등록하고 연결된 클라이언트에게 알려줍니다. Tool는 생성자에 전달된 Tool와 마찬가지로 레코드 키로 키가 지정됩니다. 기존 키 아래에 Tool를 추가하면 해당 키가 대체됩니다.

```typescript prettier:false
async server.toolActions.add(tools: ToolsInput): Promise<void>
```

예:

```typescript
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

const searchTool = createTool({
  id: 'search',
  description: 'Searches the knowledge base.',
  inputSchema: z.object({ query: z.string() }),
  execute: async ({ query }) => ({ results: [] }),
})

await server.toolActions.add({ searchTool })
```

### `toolActions.remove(toolIds)` {/* #toolactionsremovetoolids */}

Tool ID별로 실행 중인 서버에서 Tool를 제거하고 연결된 클라이언트에게 알립니다. 알 수 없는 Tool ID는 무시됩니다. 하나 이상의 Tool가 제거된 경우에만 알림이 전송됩니다.

```typescript prettier:false
async server.toolActions.remove(toolIds: string[]): Promise<void>
```

예:

```typescript
await server.toolActions.remove(['searchTool'])
```

### `toolActions.notifyListChanged()` {/* #toolactionsnotifylistchanged */}

Tool 레지스트리를 수정하지 않고 연결된 클라이언트에 `notifications/tools/list_changed` 메시지를 보냅니다. 다른 수단으로 Tool의 가용성이 변경된 경우(예: 권한 부여 변경) 이 메서드를 호출하세요.
```typescript prettier:false
async server.toolActions.notifyListChanged(): Promise<void>
```

### 마스트라 레지스트리 동기화 {/* #mastra-registry-synchronization */}

서버가 Mastra 인스턴스에 등록되어 있으면 `toolActions.add()`와 `toolActions.remove()`가 시작 시 수행되는 자동 Tool 등록과 동일하게 Mastra 인스턴스의 Tool 레지스트리도 업데이트합니다. 추가된 Tool은 `mastra.listTools()`를 통해 사용할 수 있으며(고유 `id`가 있으면 이를 키로 사용), 제거된 Tool은 레지스트리에서 삭제됩니다.
## 벌채 반출 {/* #logging */}

MCP 서버는 `notifications/message`를 사용하여 구조화된 로그 메시지를 클라이언트에 보낼 수 있습니다. 클라이언트는 `logging/setLevel` 요청을 보내 상세 수준을 제어합니다. 서버는 요청된 최소 수준보다 낮은 메시지를 삭제합니다(RFC 5424 심각도 순서 준수). 수준은 세션별로 추적되므로 클라이언트마다 서로 다른 상세 수준을 요청할 수 있습니다.
### `sendLoggingMessage()` {/* #sendloggingmessage */}

각 클라이언트의 최소 로깅 수준을 준수하여 연결된 모든 클라이언트에 로그 알림을 보냅니다.

```typescript prettier:false
async server.sendLoggingMessage(params: {
  level: LoggingLevel;
  data: unknown;
  logger?: string;
}): Promise<void>
```

예:

```typescript
await server.sendLoggingMessage({
  level: 'info',
  data: { message: 'Sync completed', itemsProcessed: 42 },
})
```

### `context.mcp.log()` {/* #contextmcplog */}

Tool의 `execute` 함수 내에서 `context.mcp.log()`를 사용하여 Tool을 호출한 클라이언트에 로그 메시지를 보내세요.
```typescript prettier:false
async context.mcp.log(
  level: LoggingLevel,
  message: string,
  data?: Record<string, unknown>
): Promise<void>
```

예:

```typescript
execute: async ({ location }, context) => {
  await context.mcp.log('debug', 'Fetching weather', { location })
  const weather = await fetchWeather(location)
  await context.mcp.log('info', 'Weather fetched')
  return weather
}
```

## 진행상황 알림 {/* #progress-notifications */}

장기 실행 Tool은 `notifications/progress`를 사용하여 호출한 클라이언트에 진행 상황을 보고할 수 있습니다. 진행률은 호출자가 요청에 `progressToken`을 포함하여 진행률 추적을 요청한 경우에만 전송됩니다(Mastra `MCPClient`는 `enableProgressTracking`이 설정되면 이를 수행합니다). 토큰이 전송되지 않았다면 `context.mcp.progress()`는 아무 작업도 수행하지 않습니다.
### `context.mcp.progress()` {/* #contextmcpprogress */}

```typescript prettier:false
async context.mcp.progress(params: {
  progress: number;
  total?: number;
  message?: string;
}): Promise<void>
```

예:

```typescript
execute: async ({ items }, context) => {
  for (const [index, item] of items.entries()) {
    await processItem(item)
    await context.mcp.progress({
      progress: index + 1,
      total: items.length,
      message: `Processed ${item.name}`,
    })
  }
  return { done: true }
}
```

## 알림 전달 {/* #notification-delivery */}

알림 메서드(`resources.notifyListChanged()`, `prompts.notifyListChanged()`, `toolActions.notifyListChanged()`, `sendLoggingMessage()`)는 stdio/SSE 연결 및 각 Streamable HTTP 세션을 포함한 모든 전송의 연결된 모든 클라이언트에 브로드캐스트합니다. `resources.notifyUpdated()`는 예외로, `resources/subscribe`를 통해 리소스 URI를 구독한 클라이언트에만 알립니다. Streamable HTTP 클라이언트의 구독은 세션별로 추적됩니다. 레거시 SSE 클라이언트는 기본 서버 인스턴스를 공유하므로 하나의 구독 집합도 공유합니다. 무상태 서버리스 모드를 사용하는 클라이언트는 각 요청에서 일시적인 서버 인스턴스를 사용하므로 알림을 받을 수 없습니다.

## 이끌어 냄 {/* #elicitation */}

### 추출이란 무엇입니까? {/* #whats-elicitation */}

추출은 서버가 사용자에게 구조화된 정보를 요청할 수 있도록 하는 MCP(Model Context Protocol)의 기능입니다. 서버가 런타임 시 추가 데이터를 수집할 수 있는 대화형 Workflow를 지원합니다.

`MCPServer` 클래스에는 사용자 입력 요청 기능이 자동으로 포함됩니다. Tool은 `execute` 함수에서 사용자 입력을 요청하는 `elicitation.sendRequest()` 메서드가 포함된 `context.mcp` 객체를 받습니다.
### Tool 실행 서명 {/* #tool-execution-signature */}

Tool가 MCP 서버 컨텍스트 내에서 실행되면 다음을 통해 MCP 관련 기능을 받습니다.`context.mcp` object:

```typescript
execute: async (inputData, context) => {
  // input contains the tool's inputData parameters
  // context.mcp contains server capabilities like elicitation and authentication info

  // Access authentication information (when available)
  if (context.mcp?.extra?.authInfo) {
    console.log('Authenticated request from:', context.mcp.extra.authInfo.clientId)
  }

  // Use elicitation capabilities
  const result = await context.mcp.elicitation.sendRequest({
    message: 'Please provide information',
    requestedSchema: {/* schema */},
  })

  return result
}
```

### 추출 작동 방식 {/* #how-elicitation-works */}

일반적인 사용 사례는 Tool 실행 중입니다. Tool에 사용자 입력이 필요한 경우 컨텍스트 매개변수를 통해 제공되는 추출 기능을 사용할 수 있습니다.

1. Tool이 메시지 및 스키마와 함께 `context.mcp.elicitation.sendRequest()`를 호출합니다.
2. 요청이 연결된 MCP 클라이언트로 전송됩니다.
3. 클라이언트가 UI, 명령줄 등을 통해 사용자에게 요청을 표시합니다.
4. 사용자가 요청에 입력하거나 거부하거나 취소합니다.
5. 클라이언트가 응답을 서버로 다시 보냅니다.
6. Tool이 응답을 수신하고 실행을 계속합니다.
### Tool에서 추출 사용 {/* #using-elicitation-in-tools */}

다음은 추출을 사용하여 사용자 연락처 정보를 수집하는 Tool의 예입니다.

```typescript
import { MCPServer } from '@mastra/mcp'
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

const server = new MCPServer({
  id: 'interactive-server',
  name: 'Interactive Server',
  version: '1.0.0',
  tools: {
    collectContactInfo: createTool({
      id: 'collectContactInfo',
      description: 'Collects user contact information through elicitation',
      inputSchema: z.object({
        reason: z.string().optional().describe('Reason for collecting contact info'),
      }),
      execute: async (inputData, context) => {
        const { reason } = inputData

        // Log session info if available
        console.log('Request from session:', context.mcp?.extra?.sessionId)

        try {
          // Request user input via elicitation
          const result = await context.mcp.elicitation.sendRequest({
            message: reason
              ? `Please provide your contact information. ${reason}`
              : 'Please provide your contact information',
            requestedSchema: {
              type: 'object',
              properties: {
                name: {
                  type: 'string',
                  title: 'Full Name',
                  description: 'Your full name',
                },
                email: {
                  type: 'string',
                  title: 'Email Address',
                  description: 'Your email address',
                  format: 'email',
                },
                phone: {
                  type: 'string',
                  title: 'Phone Number',
                  description: 'Your phone number (optional)',
                },
              },
              required: ['name', 'email'],
            },
          })

          // Handle the user's response
          if (result.action === 'accept') {
            return `Contact information collected: ${JSON.stringify(result.content, null, 2)}`
          } else if (result.action === 'decline') {
            return 'Contact information collection was declined by the user.'
          } else {
            return 'Contact information collection was cancelled by the user.'
          }
        } catch (error) {
          return `Error collecting contact information: ${error}`
        }
      },
    }),
  },
})
```

### 모집 요청 스키마 {/* #elicitation-request-schema */}

`requestedSchema`는 기본 속성만 포함하는 평면 객체여야 합니다. 지원되는 유형은 다음과 같습니다.
* **끈**: `{ type: 'string', title: 'Display Name', description: 'Help text' }`
* **숫자**: `{ type: 'number', minimum: 0, maximum: 100 }`
* **부울**: `{ type: 'boolean', default: false }`
* **열거형**: `{ type: 'string', enum: ['option1', 'option2'] }`

예제 스키마:

```typescript prettier:false
{
  type: 'object',
  properties: {
    name: {
      type: 'string',
      title: 'Full Name',
      description: 'Your complete name',
    },
    age: {
      type: 'number',
      title: 'Age',
      minimum: 18,
      maximum: 120,
    },
    newsletter: {
      type: 'boolean',
      title: 'Subscribe to Newsletter',
      default: false,
    },
  },
  required: ['name'],
}
```

### 대응 조치 {/* #response-actions */}

사용자는 다음 세 가지 방법으로 유도 요청에 응답할 수 있습니다.

1. **수락** (`action: 'accept'`): 사용자가 데이터를 제공하고 제출을 확인했습니다.
   * 제출된 데이터가 포함된 `content` 필드가 있습니다.
2. **거부** (`action: 'decline'`): 사용자가 정보 제공을 명시적으로 거부했습니다.
   * 콘텐츠 필드가 없습니다.
3. **취소** (`action: 'cancel'`): 사용자가 결정하지 않고 요청을 닫았습니다.
   * 콘텐츠 필드가 없습니다.
Tool는 세 가지 응답 유형을 모두 적절하게 처리해야 합니다.

### 보안 고려 사항 {/* #security-considerations */}

* **민감한 정보는 절대 요청하지 마세요**비밀번호, SSN, 신용카드 번호 등
* 제공된 스키마에 대해 모든 사용자 입력의 유효성을 검사합니다.
* 거부 및 취소를 적절하게 처리
* 데이터 수집에 대한 명확한 이유 제공
* 사용자 개인 정보 보호 및 선호도 존중

### Tool 실행 API {/* #tool-execution-api */}

사용자 입력 요청 기능은 Tool 실행의 `options` 매개변수를 통해 사용할 수 있습니다.
```typescript prettier:false
// Within a tool's execute function
execute: async (inputData, context) => {
  // Use elicitation for user input
  const result = await context.mcp.elicitation.sendRequest({
    message: string,           // Message to display to user
    requestedSchema: object    // JSON schema defining expected response structure
  }): Promise<ElicitResult>

  // Access authentication info if needed
  if (context.mcp?.extra?.authInfo) {
    // Use context.mcp.extra.authInfo.token, etc.
  }
}
```

HTTP 기반 전송(SSE 또는 HTTP)을 사용할 때 사용자 입력 요청은 **세션을 인식합니다**. 여러 클라이언트가 같은 서버에 연결되어 있으면 사용자 입력 요청이 Tool 실행을 시작한 클라이언트 세션으로 라우팅됩니다.
그만큼`ElicitResult` type:

```typescript
type ElicitResult = {
  action: 'accept' | 'decline' | 'cancel'
  content?: any // Only present when action is 'accept'
}
```

## OAuth 보호 {/* #oauth-protection */}

[MCP 인증 명세](https://modelcontextprotocol.io/specification/2025-06-18/basic/authorization)에 따라 OAuth 인증으로 MCP 서버를 보호하려면 `createOAuthMiddleware` 함수를 사용하세요.
```typescript
import http from 'node:http'
import { MCPServer, createOAuthMiddleware, createStaticTokenValidator } from '@mastra/mcp'

const mcpServer = new MCPServer({
  id: 'protected-server',
  name: 'Protected MCP Server',
  version: '1.0.0',
  tools: {/* your tools */},
})

// Create OAuth middleware
const oauthMiddleware = createOAuthMiddleware({
  oauth: {
    resource: 'https://mcp.example.com/mcp',
    authorizationServers: ['https://auth.example.com'],
    scopesSupported: ['mcp:read', 'mcp:write'],
    resourceName: 'My Protected MCP Server',
    validateToken: createStaticTokenValidator(['allowed-token-1']),
  },
  mcpPath: '/mcp',
})

// Create HTTP server with OAuth protection
const httpServer = http.createServer(async (req, res) => {
  const url = new URL(req.url || '', 'https://mcp.example.com')

  // Apply OAuth middleware first
  const result = await oauthMiddleware(req, res, url)
  if (!result.proceed) return // Middleware handled response (401, metadata, etc.)

  // Token is valid, proceed to MCP handler
  await mcpServer.startHTTP({ url, httpPath: '/mcp', req, res })
})

httpServer.listen(3000)
```

미들웨어는 자동으로 다음을 수행합니다.

* `/.well-known/oauth-protected-resource`에서 **보호된 리소스 메타데이터**를 제공합니다(RFC 9728).
* 인증이 필요할 때 적절한 `WWW-Authenticate` 헤더와 함께 `401 Unauthorized`를 반환합니다.
* 제공된 검증기를 사용하여 전달자 토큰의 유효성을 검사합니다.
### 토큰 검증 {/* #token-validation */}

프로덕션의 경우 적절한 토큰 유효성 검사를 사용하세요.

```typescript

// Option 1: Token introspection (RFC 7662)
const middleware = createOAuthMiddleware({
  oauth: {
    resource: 'https://mcp.example.com/mcp',
    authorizationServers: ['https://auth.example.com'],
    validateToken: createIntrospectionValidator('https://auth.example.com/oauth/introspect', {
      clientId: 'mcp-server',
      clientSecret: 'secret',
    }),
  },
})

// Option 2: Custom validation (JWT, database lookup, etc.)
const customMiddleware = createOAuthMiddleware({
  oauth: {
    resource: 'https://mcp.example.com/mcp',
    authorizationServers: ['https://auth.example.com'],
    validateToken: async (token, resource) => {
      const decoded = await verifyJWT(token)
      if (!decoded) {
        return { valid: false, error: 'invalid_token' }
      }
      return {
        valid: true,
        scopes: decoded.scope?.split(' ') || [],

## 인증 컨텍스트 {/* #authentication-context */}

HTTP 기반 전송을 사용할 때 Tool은 `context.mcp.extra`를 통해 요청 메타데이터에 액세스할 수 있습니다. 이를 사용하면 HTTP 미들웨어에서 MCP Tool로 인증 정보, 사용자 컨텍스트 또는 사용자 정의 데이터를 전달할 수 있습니다.
### 작동 원리 {/* #how-it-works */}

HTTP 미들웨어에서 `req.auth`에 설정한 모든 값은 Tool에서 `context.mcp.extra.authInfo`로 사용할 수 있습니다.
```
req.auth = { ... }  →  context?.mcp?.extra?.authInfo.extra = { ... }
```

### FGA용 인증 데이터 매핑 {/* #map-auth-data-for-fga */}

`MCPServer`가 세분화된 권한 부여(FGA) Provider가 있는 Mastra 인스턴스에 등록되면 Mastra는 Tool을 나열하거나 호출하기 전에 `requestContext.get('user')`를 검사합니다. HTTP MCP 전송은 인증된 데이터를 `extra.authInfo`로 전달하므로 `mapAuthInfoToUser`를 사용하여 FGA Provider가 예상하는 사용자 형태를 설정하세요.
```typescript
const server = new MCPServer({
  id: 'my-server',
  name: 'My Server',
  version: '1.0.0',
  tools: { getUserData },
  mapAuthInfoToUser: ({ authInfo }) => {
    const user = authInfo as {
      extra?: {
        userId?: string
        organizationMembershipId?: string
      }
    }

    if (!user.extra?.userId) {
      return null
    }

    return {
      id: user.extra.userId,
      organizationMembershipId: user.extra.organizationMembershipId,
    }
  },
})
```

### 범위 MCP Tool FGA 별도 {/* #scope-mcp-tool-fga-separately */}

MCP 클라이언트에 내부 Agent 또는 Workflow Tool 실행과 다른 권한 부여 범위가 필요한 경우 `fga.resourceMapping`과 `fga.permissionMapping`을 사용하세요. 재정의는 이 MCP 서버의 `tools/list` 및 `tools/call` 검사에만 적용됩니다.
```typescript
import { MastraFGAPermissions } from '@mastra/core/auth/ee'

const server = new MCPServer({
  id: 'my-server',
  name: 'My Server',
  version: '1.0.0',
  tools: { getUserData },
  mapAuthInfoToUser: ({ authInfo }) => {
    const user = authInfo as {
      extra?: {
        userId?: string
        organizationMembershipId?: string
      }
    }

    if (!user.extra?.userId) {
      return null
    }

    return {
      id: user.extra.userId,
      organizationMembershipId: user.extra.organizationMembershipId,
    }
  },
  fga: {
    resourceMapping: {
      tool: {
        fgaResourceType: 'user',
        deriveId: ({ user }) => (user as { id: string }).id,
      },
    },
    permissionMapping: {
      [MastraFGAPermissions.TOOLS_EXECUTE]: 'read',
    },
  },
})
```

### 인증 미들웨어 설정 {/* #setting-up-authentication-middleware */}

Tool에 데이터를 전달하려면 HTTP 서버 미들웨어에서 `server.startHTTP()`를 호출하기 전에 Node.js 요청 객체의 `req.auth`를 설정하세요.
```typescript
import express from 'express'

type MCPAuthenticatedRequest = express.Request & {
  auth?: {
    token: string
    clientId: string
    scopes: string[]
    expiresAt?: number
    extra?: Record<string, unknown>
  }
}

const app = express()

// Auth middleware - set req.auth before the MCP handler
app.use('/mcp', async (req, res, next) => {
  const authorization = req.headers.authorization

  if (!authorization?.startsWith('Bearer ')) {
    res.status(401).json({ error: 'Missing bearer token' })
    return
  }

  const token = authorization.slice('Bearer '.length)

  try {
    const user = await verifyToken(token)

    // This entire object becomes context.mcp.extra.authInfo
    const authenticatedRequest = req as MCPAuthenticatedRequest
    authenticatedRequest.auth = {
      token,
      clientId: user.clientId,
      scopes: user.scopes,
      expiresAt: user.expiresAt,
      extra: {
        userId: user.userId,
        email: user.email,
      },
    }
    next()
  } catch {
    res.status(401).json({ error: 'Invalid or expired token' })
  }
})

app.all('/mcp', async (req, res) => {
  const url = new URL(req.url, `http://${req.headers.host}`)
  await server.startHTTP({ url, httpPath: '/mcp', req, res })
})
```

### Tool에서 인증 데이터에 액세스 {/* #accessing-auth-data-in-tools */}

`req.auth` 객체는 Tool의 execute 함수에서 `context.mcp.extra.authInfo`로 사용할 수 있습니다.
```typescript
execute: async (inputData, context) => {
  // Access the auth data you set in middleware
  const authInfo = context?.mcp?.extra?.authInfo

  if (!authInfo?.extra?.userId) {
    return { error: 'Authentication required' }
  }

  // Use the auth data
  console.log('User ID:', authInfo.extra.userId)
  console.log('Email:', authInfo.extra.email)

  const response = await fetch('/api/data', {
    headers: { Authorization: `Bearer ${authInfo.token}` },
    signal: context?.mcp?.extra?.signal,
  })

  return response.json()
}
```

### `RequestContext`를 Agent로 전달하기 {/* #passing-requestcontext-through-to-agent */}
```typescript
execute: async (inputData, context) => {
  // Access the auth data you set in middleware
  const authInfo = context?.mcp?.extra?.authInfo

  const requestContext = context.requestContext || new RequestContext().set('someKey', authInfo)

  if (!agent) {

  const response = await agent.generate(prompt, { requestContext })

  return response.text
}

### 완전한 예 {/* #complete-example */}

[`jose`](https://github.com/panva/jose)를 설치하여 ID Provider의 JSON Web Key Set(JWKS)을 기준으로 JSON Web Token(JWT)을 검증하세요.```shell npm2yarn
npm install jose
```

다음 예에서는 사용자 데이터를 Tool에 전달하기 전에 토큰의 서명, 발급자, 대상, 알고리즘, 만료 및 필수 클레임을 검증합니다.

```typescript
import express from 'express'
import { createRemoteJWKSet, jwtVerify } from 'jose'
import { MCPServer } from '@mastra/mcp'
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

type MCPAuthenticatedRequest = express.Request & {
  auth?: {
    token: string
    clientId: string
    scopes: string[]
    expiresAt?: number
    extra?: Record<string, unknown>
  }
}

const issuer = process.env.JWT_ISSUER
const audience = process.env.JWT_AUDIENCE
const jwksUri = process.env.JWT_JWKS_URI

if (!issuer || !audience || !jwksUri) {
  throw new Error('JWT_ISSUER, JWT_AUDIENCE, and JWT_JWKS_URI are required')
}

const jwks = createRemoteJWKSet(new URL(jwksUri))

const verifyToken = async (token: string) => {
  const { payload } = await jwtVerify(token, jwks, {
    issuer,
    audience,
    algorithms: ['RS256'],
    requiredClaims: ['exp'],
  })

  const clientId =
    typeof payload.client_id === 'string'
      ? payload.client_id
      : typeof payload.azp === 'string'
        ? payload.azp
        : undefined

  if (!payload.sub || typeof payload.email !== 'string' || !clientId || !payload.exp) {
    throw new Error('Token must contain sub, email, exp, and client_id or azp claims')
  }

  return {
    userId: payload.sub,
    clientId,
    email: payload.email,
    expiresAt: payload.exp,
    scopes: typeof payload.scope === 'string' ? payload.scope.split(' ') : [],
  }
}

// 1. Define your tool that uses auth context
const getUserData = createTool({
  id: 'get-user-data',
  description: 'Fetches data for the authenticated user',
  inputSchema: z.object({}),
  execute: async (inputData, context) => {
    const authInfo = context?.mcp?.extra?.authInfo

    if (!authInfo?.extra?.userId) {
      return { error: 'Authentication required' }
    }

    // Access the data you set in middleware
    return {
      userId: authInfo.extra.userId,
      email: authInfo.extra.email,
    }
  },
})

// 2. Create the MCP server with your tools
const server = new MCPServer({
  id: 'my-server',
  name: 'My Server',
  version: '1.0.0',
  tools: { getUserData },
})

// 3. Set up Express with auth middleware
const app = express()

app.use('/mcp', async (req, res, next) => {
  const authorization = req.headers.authorization

  if (!authorization?.startsWith('Bearer ')) {
    res.status(401).json({ error: 'Missing bearer token' })
    return
  }

  const token = authorization.slice('Bearer '.length)

  try {
    const user = await verifyToken(token)

    // This entire object becomes context.mcp.extra.authInfo
    const authenticatedRequest = req as MCPAuthenticatedRequest
    authenticatedRequest.auth = {
      token,
      clientId: user.clientId,
      scopes: user.scopes,
      expiresAt: user.expiresAt,
      extra: {
        userId: user.userId,
        email: user.email,
      },
    }
    next()
  } catch {
    res.status(401).json({ error: 'Invalid or expired token' })
  }
})

app.all('/mcp', async (req, res) => {
  const url = new URL(req.url, `http://${req.headers.host}`)
  await server.startHTTP({ url, httpPath: '/mcp', req, res })
})

app.listen(3000)
```

### 예 {/* #example */}

```typescript
import { MCPServer } from '@mastra/mcp'
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

const calculatorTool = createTool({
  id: 'calculatorWithUI',
  description: 'An interactive calculator',
  inputSchema: z.object({
    num1: z.number(),
    num2: z.number(),
    operation: z.enum(['add', 'subtract']),
  }),
  execute: async ({ num1, num2, operation }) => {
    const result = operation === 'add' ? num1 + num2 : num1 - num2
    return {
      content: [{ type: 'text', text: 'An interactive calculator is displayed.' }],
      structuredContent: { result },
    }
  },
})

const server = new MCPServer({
  id: 'app-server',
  name: 'App Server',
  version: '1.0.0',
  tools: { calculatorTool },
  appResources: {
    'ui://calculator/main': {
      name: 'Interactive Calculator',
      html: '<html><body><h2>Calculator</h2>...</body></html>',
    },
  },
})
```
