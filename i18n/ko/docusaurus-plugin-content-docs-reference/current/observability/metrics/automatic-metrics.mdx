# 자동 측정항목 참조

Mastra는 추적된 실행에서 성능 및 사용량 측정항목을 자동으로 추출합니다. 이 페이지는 Mastra가 내보내는 모든 지표 이름, 레이블 및 컨텍스트 필드에 대한 완전한 참조입니다.

설정 지침은 다음을 참조하세요.[Metrics overview](/docs/observability/metrics/overview).

## Mastra가 자동 측정항목을 내보내는 경우 {/* #when-mastra-emits-automatic-metrics */}

측정항목은 종료되면 범위에서 추출됩니다. 관측 가능성 계층은 완료된 각 범위를 검사하고 기간을 계산하며 (Model 생성 범위의 경우) 토큰 사용 데이터를 읽습니다. 수동 계측이 필요하지 않습니다.

### 측정항목 사용 가능 여부에 영향을 미치는 요소 {/* #what-affects-whether-a-metric-is-available */}

다음과 같은 경우 측정항목이 저장소에 도달합니다.

1. `MastraStorageExporter`내보내기로 구성되었습니다.
2. 스토리지 백엔드는 측정항목(Observability 도메인이 활성화된 ClickHouse, DuckDB 또는 Postgres v-next)을 지원합니다.

측정항목을 사용할 수 없는 경우 다음을 참조하세요.[troubleshooting](#troubleshooting).

## 기간 측정항목 {/* #duration-metrics */}

기간 측정항목은 범위의 시작 및 종료 타임스탬프에서 계산된 실행 시간을 밀리초 단위로 기록합니다. 각 기간 측정항목에는 다음이 포함됩니다.`status` label set to `ok` or `error`, derived from the span's status.

| 측정항목 이름 | 스팬 유형 | 설명 |
| - | - | - |
|`mastra_agent_duration_ms` | `AGENT_RUN` | Execution time of an agent run |
| `mastra_tool_duration_ms` | `TOOL_CALL`, `MCP_TOOL_CALL`, `PROVIDER_TOOL_CALL` | Execution time of a tool call, including MCP and provider-executed tool calls |
| `mastra_workflow_duration_ms` | `WORKFLOW_RUN`| Workflow 실행 실행 시간 |
|`mastra_model_duration_ms` | `MODEL_GENERATION`| Model 생성 실행 시간 |
|`mastra_processor_duration_ms` | `PROCESSOR_RUN`| 프로세서 실행의 실행 시간 |

## 토큰 사용 지표 {/* #token-usage-metrics */}

토큰 지표는 다음에서만 방출됩니다.`MODEL_GENERATION` spans that include `usage` data. Token metrics require usage data from the provider.

### 입력 토큰 측정항목 {/* #input-token-metrics */}

| 측정항목 이름 | 설명 |
| - | - |
|`mastra_model_total_input_tokens` | Total input tokens |
| `mastra_model_input_text_tokens` | Text tokens in the input prompt |
| `mastra_model_input_cache_read_tokens` | Tokens read from prompt cache (e.g. Anthropic) |
| `mastra_model_input_cache_write_tokens` | Tokens written to prompt cache |
| `mastra_model_input_audio_tokens` | Audio tokens in the input (multimodal models) |
| `mastra_model_input_image_tokens` | Image tokens in the input (vision models) |

### 출력 토큰 측정항목 {/* #output-token-metrics */}

| 측정항목 이름 | 설명 |
| - | - |
|`mastra_model_total_output_tokens` | Total output tokens |
| `mastra_model_output_text_tokens` | Text tokens in the model's output |
| `mastra_model_output_reasoning_tokens` | Reasoning / chain-of-thought tokens (e.g. OpenAI o-series) |
| `mastra_model_output_audio_tokens` | Audio tokens in the model's output |
| `mastra_model_output_image_tokens` | Output image tokens |

### 공급자가 보고한 세부 토큰 카테고리 {/* #provider-reported-detailed-token-categories */}

자세한 분석 측정항목(다음을 제외한 모든 항목)`total_input` and `total_output`) are only emitted when the provider reports them. If a category has zero tokens, the metric is skipped for that span. Different providers report different levels of detail. For example, not all providers report cache or audio tokens.

## 비용 관련 컨텍스트 {/* #cost-related-context */}

### 비용 컨텍스트가 첨부된 경우 {/* #when-cost-context-is-attached */}

공급자가 완료된 모든 Model 단계에 대해 유효한 비용을 보고하거나 내장된 가격 책정 레지스트리에 공급자와 Model에 대해 일치하는 항목이 있는 경우 비용 컨텍스트가 토큰 지표에 첨부됩니다. Mastra는 단계당 공급자 비용을 하나의 쿼리 합계로 합산합니다. 완료된 단계에 보고된 유효한 비용이 부족한 경우 Mastra는 부분 합계를 보고하는 대신 가격 책정 레지스트리를 사용합니다. 두 소스를 모두 사용할 수 없는 경우 비용 필드 없이 토큰 지표가 계속 방출됩니다.

발신자 제공`costContext` takes precedence over provider-reported costs and pricing registry estimates. Provider-reported totals use `costMetadata.source: 'provider_reported'`, `costMetadata.scope: 'query_total'`, and `costMetadata.reportedStepCount` to identify the source, scope, and number of completed steps included in the total.

### 포함될 수 있는 비용 필드 {/* #what-cost-fields-may-be-included */}

| 필드 | 설명 |
| - | - |
|`provider` | Provider name (e.g. `openai`, `anthropic`) |
| `model` | Model identifier (e.g. `gpt-4o`, `claude-sonnet-4-20250514`) |
| `estimatedCost` | Estimated cost from token count and pricing tier, or a total reported by the provider |
| `costUnit` | Currency unit (e.g. `USD`) |
| `costMetadata` | Additional pricing context, including tier information, error details, and provider-reported cost source and scope |

## 추적과의 상관관계 {/* #correlation-with-traces */}

### 측정항목이 범위 및 추적 컨텍스트와 관련되는 방식 {/* #how-metrics-relate-to-spans-and-trace-context */}

각 지표에는`CorrelationContext` snapshot from the span that produced it. This context is stored alongside the metric value and links a metric to the exact span and trace.

상관 필드는 다음 범주를 사용합니다.

**추적 상관관계**

* `traceId`: 추적 식별자
* `spanId`: 스팬 식별자
* `tags`: 범위의 태그

**엔터티 계층 구조**

* `entityType`, `entityId`, `entityName`: The entity that produced the metric (e.g. agent, workflow)
* `parentEntityType`, `parentEntityId`, `parentEntityName`: The parent entity
* `rootEntityType`, `rootEntityId`, `rootEntityName`: The root entity in the call chain

**신원**

* `userId`, `organizationId`, `resourceId`: Identity context from the request
* `runId`, `sessionId`, `threadId`, `requestId`: Correlation IDs

**전개**

* `environment`: 배포 환경(예:`production`, `staging`)
* `source`: 소스 식별자
* `serviceName`: 관측 가능성 구성의 서비스 이름
* `experimentId`: 실험 식별자(해당하는 경우)

### 상관관계가 디버깅에 도움이 되는 이유 {/* #why-correlation-helps-with-debugging */}

지표 대시보드에서 지연 시간이나 토큰 사용량의 급증을 발견하면 상관 관계 컨텍스트를 통해 지표를 생성한 추적을 직접 살펴볼 수 있습니다. 여기에서 개별 범위를 검사할 수 있습니다. 근본 원인은 느린 Tool 호출이나 큰 Prompt일 수 있습니다. 예상치 못한 오류일 수도 있습니다.

## 문제 해결 {/* #troubleshooting */}

### 측정항목이 없습니다. {/* #no-metrics-are-available */}

* **관측 가능성이 구성되었습니다.**: 귀하의`Mastra` instance has an `observability` config with at least one exporter.
* **`MastraStorageExporter`또는`MastraPlatformExporter` is present**: 다른 수출업체(Datadog, Langfuse 등)는 Mastra에 측정항목을 표시하지 않습니다.`MastraStorageExporter` is required for the local Studio dashboard, and `MastraPlatformExporter` is required to view metrics in Mastra platform.
* **스토리지는 측정항목을 지원합니다.**: 지표에는 분석 가능 저장소(Observability 도메인이 활성화된 ClickHouse, DuckDB 또는 Postgres v-next)가 필요합니다. 다른 행 기반 데이터베이스(LibSQL, MSSQL) 및 문서 저장소(MongoDB)는 메트릭에 지원되지 않습니다.
* **샘플링이 0%가 아닙니다.**: 샘플링 확률이`0` or strategy is `never`, all spans become no-ops and no metrics are extracted.

### 기간 측정항목이 누락되었습니다. {/* #duration-metrics-are-missing */}

* **Span에는 타임스탬프가 있습니다.**: 기간은 다음에서 계산됩니다.`startTime` and `endTime`. If either is missing, the metric is skipped.
* **범위 유형은 측정항목에 매핑됩니다.**: 오직`AGENT_RUN`, `TOOL_CALL`, `MCP_TOOL_CALL`, `PROVIDER_TOOL_CALL`, `WORKFLOW_RUN`, `MODEL_GENERATION`, and `PROCESSOR_RUN` spans produce duration metrics.

### 토큰 측정항목이 누락되었습니다. {/* #token-metrics-are-missing */}

* **Span은 Model 생성입니다.**: 토큰 지표는 다음에서만 방출됩니다.`MODEL_GENERATION` spans.
* **공급자 보고서 사용량**: Model 제공자는 다음을 포함해야 합니다.`usage` data in its response. Usage data is required to emit token metrics.
