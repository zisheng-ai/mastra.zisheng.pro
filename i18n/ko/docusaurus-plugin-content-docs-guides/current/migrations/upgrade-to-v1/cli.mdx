# CLI

배포 명령, 구성 플래그 및 시작 파일을 제거하여 CLI가 단순화되었습니다. 데이터베이스 스키마 업그레이드를 돕기 위해 새로운 마이그레이션 명령이 추가되었습니다.

## 추가됨 {/* #added */}

### `mastra migrate`명령 {/* #mastra-migrate-command */}

새로운 `mastra migrate` 명령은 Mastra 버전을 업그레이드할 때 데이터베이스 마이그레이션을 실행하는 데 도움이 됩니다. 데이터가 호환되지 않을 수 있는 이전 버전에서 업그레이드할 때 특히 유용합니다.
```bash
npx mastra migrate
```

이 명령은 필요한 마이그레이션을 실행하기 전에 프로젝트를 번들로 묶고 구성된 스토리지에 연결합니다. 현재 고유 제약 조건 생성을 방지할 수 있는 중복 범위 항목 마이그레이션을 지원합니다.

이 마이그레이션이 필요한 경우에 관한 자세한 내용은 [스토리지 마이그레이션 가이드](/guides/migrations/upgrade-to-v1/storage#duplicate-spans-migration)를 참조하세요.
## 제거됨 {/* #removed */}

### `mastra deploy`명령 {/* #mastra-deploy-command */}

CLI에서 `mastra deploy` 명령이 제거되었습니다. 이 변경은 공급업체별 배포 로직을 제거하여 CLI를 단순화합니다.
마이그레이션하려면 원하는 [배포 플랫폼](/docs/deployment/overview)을 선택하세요.
### `--env`에서 플래그`mastra build` {/* #--env-flag-from-mastra-build */}

`mastra build` 명령에서 `--env` 플래그가 제거되었습니다. 이 변경으로 빌드 명령이 단순해집니다.
마이그레이션하려면 사용자 지정 환경으로 빌드 출력을 시작할 때 `mastra start --env <env>`를 사용하세요.
```diff
- mastra build --env production
+ mastra build
+ mastra start --env production
```

### `--port`에서 플래그`mastra dev` {/* #--port-flag-from-mastra-dev */}

`mastra dev` 명령에서 `--port` 플래그가 제거되었습니다. 이제 포트는 Mastra 인스턴스 구성을 통해 설정합니다. 이 변경으로 포트 구성이 중앙화됩니다.
마이그레이션하려면 CLI 플래그 대신 Mastra 인스턴스의 `server.port`를 사용하세요.
```ts
const mastra = new Mastra({
  server: {
    port: 3001,
  },
})
```

### CLI의 원격 측정 옵션 {/* #telemetry-options-from-cli */}

`--no-telemetry` / `-nt` 플래그를 포함한 CLI 명령의 `telemetry` 옵션이 제거되었습니다. 원격 측정 구성은 CLI에서 제거되었습니다. 이 변경은 원격 측정 기능이 Observability 패키지로 이동한 것을 반영합니다.
마이그레이션하려면 CLI 명령에서 원격 측정 플래그를 제거하세요. 추적 기능에는 `@mastra/observability`를 사용하세요.
