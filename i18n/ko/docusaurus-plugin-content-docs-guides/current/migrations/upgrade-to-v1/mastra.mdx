# 마스트라 수업

최상위 수준 가져오기를 제한하고 직접 속성 액세스를 getter 메서드로 대체하도록 Mastra 클래스가 재구성되었습니다.

## 변경됨 {/* #changed */}

### 하위 경로 가져오기로의 최상위 가져오기 {/* #top-level-imports-to-subpath-imports */}

주요`@mastra/core` index file now only exports `Mastra` and `Config`. 다른 모든 내보내기는 하위 경로 가져오기로 이동되었습니다. 이 변경으로 인해 번들러가 사용되지 않는 코드를 제거할 수 있게 되어 트리 쉐이킹이 개선되고 번들 크기가 줄어듭니다.

마이그레이션하려면 다음에서 모든 가져오기를 업데이트하세요.`@mastra/core` to use the appropriate subpath.

```diff
- import { Mastra, Agent, Workflow, createTool } from '@mastra/core';
+ import { Mastra, type Config } from '@mastra/core';
+ import { Agent } from '@mastra/core/agent';
+ import { Workflow } from '@mastra/core/workflows';
+ import { createTool } from '@mastra/core/tools';
```

:::팁\[코드모드]

Mastra의 codemod CLI를 사용하여 코드를 자동으로 업데이트할 수 있습니다.

```bash
npx @mastra/codemod@latest v1/mastra-core-imports .
```

:::

### `experimental_auth`에게`auth` {/* #experimental_auth-to-auth */}

실험적 인증 구성이 안정 구성으로 승격되었습니다. 이 변경 사항은 인증 API가 이제 안정적이고 프로덕션 준비가 되었음을 반영합니다.

마이그레이션하려면 이름을 바꾸세요.`experimental_auth` key to `auth` in your Mastra configuration.

```diff
  const mastra = new Mastra({
-   experimental_auth: {
+   auth: {
      provider: workos,
    },
  });
```

:::팁\[코드모드]

Mastra의 codemod CLI를 사용하여 코드를 자동으로 업데이트할 수 있습니다.

```bash
npx @mastra/codemod@latest v1/experimental-auth .
```

:::

### 필수의`id` parameter for all mastra primitives {/* #required-id-parameter-for-all-mastra-primitives */}

이제 모든 스토리지, 벡터 저장소, Agent, Workflow, mcpServer, 프로세서, 채점자 및 Tool에는`id` parameter during initialization. This enables the standardized Mastra API and prevents ID conflicts.

이 모든 기본 요소도 이제`get`, `list`, and `add` functions.

마이그레이션하려면 다음을 추가하세요.`id` parameter to all storage and vector store instantiations. When using the same storage/vector class multiple times, ensure each instance has a unique ID.

```diff
- const storage = new LibSQLStore({
-   url: ':memory:',
- });
+ const storage = new LibSQLStore({
+   id: 'my-app-storage',
+   url: ':memory:',
+ });

- const vector = new PgVector({
-   connectionString: process.env.DATABASE_URL,
- });
+ const vector = new PgVector({
+   id: 'my-app-vector',
+   connectionString: process.env.DATABASE_URL,
+ });
```

다양한 목적으로 별도의 인스턴스를 사용하는 경우 설명이 포함된 고유 ID를 사용하세요.

```diff
  const agentMemory = new Memory({
    storage: new LibSQLStore({
-     url: 'file:./agent.db',
+     id: 'weather-agent-memory-storage',
+     url: 'file:./agent.db',
    }),
  });

  const mastra = new Mastra({
    storage: new LibSQLStore({
+     id: 'mastra-storage',
      url: ':memory:',
    }),
  });
```

### 원시 복수형 API가 다음에서 변경되었습니다.`get<primitives>` to `list<primitive>` {/* #primitive-plural-apis-changes-from-getprimitives-to-listprimitive */}

`get*`기본 요소의 모든 인스턴스를 반환하는 함수의 이름이 다음으로 변경되었습니다.`list*` to better reflect their purpose.

```diff
- const agents = mastra.getAgents();
+ const agents = mastra.listAgents();
- const vectors = mastra.getVectors();
+ const vectors = mastra.listVectors();
- const workflows = mastra.getWorkflows();
+ const workflows = mastra.listWorkflows();
- const scorers = mastra.getScorers();
+ const scorers = mastra.listScorers();
- const mcpServers = mastra.getMCPServers();
+ const mcpServers = mastra.listMCPServers();
- const logsByRunId = await mastra.getLogsByRunId({ runId: 'id', transportId: 'id' });
+ const logsByRunId = await mastra.listLogsByRunId({ runId: 'id', transportId: 'id' });
- const logs = await mastra.getLogs('transportId');
+ const logs = await mastra.listLogs('transportId');
```

```bash
npx @mastra/codemod@latest v1/mastra-plural-apis .
```

:::

### 각 기본 요소에는`getById` and a `get` function {/* #each-primitive-has-a-getbyid-and-a-get-function */}

```typescript
mastra.getMCPServer('myServer') // Works (registry key)
mastra.getMCPServerById('my-mcp-server') // Works (intrinsic ID)
```

### Tool 등록은 이제 고유 ID를 사용합니다. {/* #tool-registration-now-uses-intrinsic-ids */}

Tool가 Agent 또는 MCP 서버에서 Mastra 인스턴스로 자동 등록되면 이제 Tool의 고유 기능을 사용합니다.`id` instead of the configuration object key. This prevents collisions when multiple agents/MCP servers have tools with the same configuration key.

마이그레이션하려면 구성 키로 Tool를 참조하는 코드를 업데이트하여 대신 Tool의 고유 ID를 사용하세요.

```diff
  const agent = new Agent({
    id: 'agent1',
    tools: {
      searchTool: weatherSearchTool,
    },
  });

- mastra.getTool('searchTool');
+ mastra.getTool(weatherSearchTool.id);
```
