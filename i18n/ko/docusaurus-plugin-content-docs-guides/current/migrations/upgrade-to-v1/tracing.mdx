# 트레이싱

관측 가능성 시스템은 v1에서 전용으로 재구성되었습니다.`@mastra/observability`패키지. 이 가이드에서는 업그레이드하려는 버전에 따라 두 가지 마이그레이션 경로를 다룹니다.

:::경고\[업그레이드 시 Observability 데이터 흐름이 중지됨]
마이그레이션하지 않고 Mastra 패키지를 v1로 업그레이드하는 경우`telemetry:` config to `observability:`, 이전 구성은 런타임 시 무시됩니다. 서비스는 오류 없이 깔끔하게 시작되지만**추적, 로그 또는 측정항목은 어디에도 전송되지 않습니다.**. Mastra Cloud로 데이터를 전송하는 경우 대시보드가 ​​비어 있게 됩니다.

Mastra 패키지와 동일한 변경으로 이 마이그레이션을 완료하고 추적이 나타나는지 확인하세요.[Mastra Studio](/docs/studio/observability) before considering the upgrade complete. If you previously hosted on Mastra Cloud, also follow the [Mastra Cloud migration guide](/guides/migrations/mastra-cloud). The new platform requires a new access token and a Studio project before `MastraPlatformExporter` can route data to it.
:::

:::note\[내보내기 이름 변경]

`MastraPlatformExporter`(Mastra 플랫폼으로 데이터 전송)은 이전을 대체합니다.`CloudExporter`, and `MastraStorageExporter` (persists data to Mastra Storage) replaces the previous `DefaultExporter`. The original classes remain available from `@mastra/observability` and behave identically, but they're deprecated. New code should use `MastraPlatformExporter`그리고`MastraStorageExporter`. 기존 수입품`CloudExporter`또는`DefaultExporter`향후 주요 버전에서 제거될 때까지 계속 작동합니다.

:::

## 마이그레이션 경로 {/* #migration-paths */}

### OTEL 기반 원격 측정(0.x)에서 {/* #from-otel-based-telemetry-0x */}

오래된 것을 사용하고 있다면`telemetry:` configuration in Mastra, the system has been completely redesigned.

**이전(OTEL 원격 측정을 사용하는 0.x):**

```typescript
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  telemetry: {
    serviceName: 'my-app',
    enabled: true,
    sampling: {
      type: 'always_on',
    },
    export: {
      type: 'otlp',
      endpoint: 'http://localhost:4318',
    },
  },
})
```

**이후(관측 가능성이 있는 v1):**

```typescript
import { Mastra } from '@mastra/core'
import {
  Observability,
  MastraStorageExporter,
  MastraPlatformExporter,
  SensitiveDataFilter,
} from '@mastra/observability'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'mastra',
        exporters: [
          new MastraStorageExporter(), // Persists observability events to Mastra Storage
          new MastraPlatformExporter(), // Sends observability events to Mastra platform (if MASTRA_PLATFORM_ACCESS_TOKEN is set)
        ],
        spanOutputProcessors: [
          new SensitiveDataFilter(), // Redacts sensitive data like passwords, tokens, keys
        ],
      },
    },
  }),
})
```

이 구성에는 다음이 포함됩니다.`MastraStorageExporter`, `MastraPlatformExporter`, and `SensitiveDataFilter` processor. See the [observability tracing documentation](/docs/observability/tracing/overview) for full configuration options.

#### 이후(맞춤 구성이 포함된 v1) {/* #after-v1-with-custom-configuration */}

특정 내보내기(예: OTLP)를 구성해야 하는 경우 내보내기 패키지를 설치하고 구성합니다.

```bash npm2yarn
npm install @mastra/otel-exporter@latest @opentelemetry/exporter-trace-otlp-proto
```

```typescript
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { OtelExporter } from '@mastra/otel-exporter'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      production: {
        serviceName: 'my-app',
        sampling: { type: 'always' },
        exporters: [
          new OtelExporter({
            provider: {
              custom: {
                endpoint: 'http://localhost:4318/v1/traces',
                protocol: 'http/protobuf',
              },
            },
          }),
        ],
      },
    },
  }),
})
```

주요 변경 사항:

1. 설치하다`@mastra/observability` package
2. 바꾸다`telemetry:` with `observability: new Observability()`
3. 명시적 사용`configs:` with `MastraStorageExporter`, `MastraPlatformExporter`, and `SensitiveDataFilter`
4. 내보내기 유형이 문자열 리터럴에서 변경됩니다(`'otlp'`) to exporter class instances (`new OtelExporter()`)

참조[exporters documentation](/docs/observability/integrations/overview#exporters) for all available exporters.

### AI 추적에서 {/* #from-ai-tracing */}

이미 AI 추적(중간 시스템)으로 업그레이드한 경우 새 패키지를 설치하고 명시적 구성을 사용해야 합니다.

**이전(AI 추적):**

```typescript
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  observability: {
    default: { enabled: true },
  },
})
```

**이후(v1 Observability):**

```typescript
import { Mastra } from '@mastra/core'
import {
  Observability,
  MastraStorageExporter,
  MastraPlatformExporter,
  SensitiveDataFilter,
} from '@mastra/observability'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'mastra',
        exporters: [new MastraStorageExporter(), new MastraPlatformExporter()],
        spanOutputProcessors: [new SensitiveDataFilter()],
      },
    },
  }),
})
```

주요 변경 사항:

1. 설치하다`@mastra/observability` package
2. 수입`Observability`, exporters, and processors from `@mastra/observability`
3. 명시적 사용`configs` with `MastraStorageExporter`, `MastraPlatformExporter`, and `SensitiveDataFilter`

## 변경됨 {/* #changed */}

### 패키지 가져오기 경로 {/* #package-import-path */}

Observability 기능이 전용으로 이동되었습니다.`@mastra/observability` package.

마이그레이션하려면 패키지를 설치하고 가져오기 문을 업데이트하세요.

```bash npm2yarn
npm install @mastra/observability@latest
```

```diff
- import { Tracing } from '@mastra/core/observability';
+ import { Observability } from '@mastra/observability';
```

### 레지스트리 구성 {/* #registry-configuration */}

관측 가능성 레지스트리는 이제 다음을 사용하여 구성됩니다.`Observability` class instance with explicit configs instead of a plain object.

마이그레이션하려면 다음을 사용하십시오.`new Observability()` with explicit exporters and processors.

```diff
+ import {
+   Observability,
+   MastraStorageExporter,
+   MastraPlatformExporter,
+   SensitiveDataFilter,
+ } from '@mastra/observability';

  export const mastra = new Mastra({
-   observability: {
-     default: { enabled: true },
-   },
+   observability: new Observability({
+     configs: {
+       default: {
+         serviceName: 'mastra',
+         exporters: [new MastraStorageExporter(), new MastraPlatformExporter()],
+         spanOutputProcessors: [new SensitiveDataFilter()],
+       },
+     },
+   }),
  });
```

### 구성 속성`processors` to `spanOutputProcessors` {/* #configuration-property-processors-to-spanoutputprocessors */}

스팬 프로세서의 구성 속성 이름이 다음에서 변경되었습니다.`processors` to `spanOutputProcessors`.

마이그레이션하려면 구성 개체의 속성 이름을 바꾸세요.

```diff
+ import { SensitiveDataFilter } from '@mastra/observability';

  export const mastra = new Mastra({
    observability: new Observability({
      configs: {
        production: {
          serviceName: 'my-app',
-         processors: [new SensitiveDataFilter()],
+         spanOutputProcessors: [new SensitiveDataFilter()],
          exporters: [...],
        },
      },
    }),
  });
```

### 수출업자 방법`exportEvent` to `exportTracingEvent` {/* #exporter-method-exportevent-to-exporttracingevent */}

사용자 지정 내보내기 Tool를 만든 경우 내보내기 방법의 이름이 다음에서 변경되었습니다.`exportEvent` to `exportTracingEvent`.

마이그레이션하려면 사용자 정의 내보내기에서 메서드 구현을 업데이트하세요.

```diff
  export class MyExporter implements ObservabilityExporter {
-   exportEvent(event: TracingEvent): void {
+   exportTracingEvent(event: TracingEvent): void {
      // export logic
    }
  }
```

## 제거됨 {/* #removed */}

### OTEL 기반`telemetry` configuration {/* #otel-based-telemetry-configuration */}

OTEL 기반`telemetry` configuration from 0.x has been removed. The old system with `serviceName`, `sampling.type`, and `export.type` properties is no longer supported.

마이그레이션하려면 위의 "OTEL 기반 원격 측정에서" 섹션을 따르세요. 자세한 구성 옵션은 다음을 참조하세요.[observability tracing documentation](/docs/observability/tracing/overview).

### 사용자 정의 계측 파일 {/* #custom-instrumentation-files */}

계측 파일 자동 감지`/mastra` (with `.ts`, `.js`, or `.mjs` extensions) has been removed. Custom instrumentation is no longer supported through separate files.

마이그레이션하려면 내장된 내보내기 시스템을 사용하거나`ObservabilityExporter` interface. See the [exporters documentation](/docs/observability/integrations/overview#exporters) for details.

### `instrumentation.mjs`파일 {/* #instrumentationmjs-files */}

사용하고 있었다면`instrumentation.mjs` files to initialize OpenTelemetry instrumentation (common in deployment setups like AWS Lambda), these are no longer needed. The new observability system is configured directly in your Mastra instance.

#### 이전(0.x) {/* #before-0x */}

계측 파일이 필요했습니다.

```javascript
// instrumentation.mjs
import { NodeSDK } from '@opentelemetry/sdk-node'
// ... OTEL setup
```

프로세스를 시작할 때 이를 가져와야 했습니다.

```bash
node --import=./.mastra/output/instrumentation.mjs --env-file=".env" .mastra/output/index.mjs
```

#### 이후(v1) {/* #after-v1 */}

간단히 제거`instrumentation.mjs` file and configure observability in your Mastra instance:

```typescript
// src/mastra/index.ts
import {
  Observability,
  MastraStorageExporter,
  MastraPlatformExporter,
  SensitiveDataFilter,
} from '@mastra/observability'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'mastra',
        exporters: [new MastraStorageExporter(), new MastraPlatformExporter()],
        spanOutputProcessors: [new SensitiveDataFilter()],
      },
    },
  }),
})
```

없이 프로세스를 정상적으로 시작하십시오.`--import` flag:

```bash
node --env-file=".env" .mastra/output/index.mjs
```

별도의 계측 파일이나 특수 시작 플래그가 필요하지 않습니다.

### 설치 {/* #installation */}

**전용 수출업체**(Arize, Braintrust, Langfuse, LangSmith):

```bash npm2yarn
npm install @mastra/[exporter-name]-exporter
```

**OpenTelemetry 내보내기**(Dash0, Laminar, New Relic, SigNoz, Traceloop):

```bash npm2yarn
npm install @mastra/otel-exporter@latest
```

또한 Provider에 필요한 프로토콜 패키지(참조:[OTEL guide](/docs/observability/integrations/exporters/otel#installation)).
