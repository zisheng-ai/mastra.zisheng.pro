이 템플릿은 개별 마이그레이션 가이드를 작성하는 방법에 대한 스타일 가이드입니다. 이 디렉터리의 파일 구조를 구성할 때 참고하세요. 이 구조에서 벗어나서는 안 됩니다.

Follow the `.cursor/rules/writing-documentation.mdc` 본문 콘텐츠 작성 방법에 대한 지침입니다.

문서화해야 할 변경 사항을 모두 찾은 후에는 "Changed"와 "Removed"라는 두 개의 큰 그룹으로 분류해야 합니다.

Example:

```md
## Changed

## Removed
```

모든 변경 사항은 반드시 이 두 섹션 아래에 배치해야 합니다.

각 변경 사항("Changed" 또는 "Removed")은 h3 제목이어야 합니다. 이 형식을 정확히 따라야 합니다.

Example:

```md
## Changed

### `oldFunction` to `newFunction`
```

이제 제목을 배치했으므로 각 변경 사항에 대해 정해진 구조를 정확히 따라야 합니다. 이 구조에서 벗어나서는 안 됩니다.

변경 사항을 한두 문장으로 간략히 설명하세요. 그런 다음 변경한 이유를 한 문장으로 설명하세요.

각 변경 사항의 세 번째 요소는 기존 코드를 새 버전으로 마이그레이션하는 방법에 대한 설명이어야 합니다. 간결하면서도 명확하게 작성하되, 정보를 지나치게 생략하지 마세요. 그다음에는 반드시 "diff" 구문을 사용하는 코드 블록을 제공해야 합니다. 코드 블록 안에서는 해당 diff 구문을 사용하여 변경해야 하는 코드의 "이전" 및 "이후" 예시를 보여 주어야 합니다.

Example:

````md
## Changed

### `oldFunction` to `newFunction`

The `oldFunction` has been renamed to `newFunction`. This change improves clarity and consistency across the API.

To migrate, replace all instances of `oldFunction` with `newFunction` in your codebase.

```diff
- const result = oldFunction(args);
+ const result = newFunction(args);
```
````

마이그레이션에 단순한 찾아 바꾸기보다 더 많은 단계가 필요한 경우 코드 블록 앞에 추가 설명을 넣을 수 있습니다. 여러 단계가 필요하다면 번호 매기기 목록을 사용하여 각 단계를 명확하게 설명하세요.
