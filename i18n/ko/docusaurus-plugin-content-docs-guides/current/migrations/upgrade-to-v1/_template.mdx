이 템플릿은 개별 마이그레이션 가이드를 채우는 방법에 대한 스타일 가이드입니다. 이 디렉터리에서 파일을 구성하는 방법에 대한 지침으로 이를 사용하세요. 이 구조에서 벗어나면 안 됩니다.

따라가다`.cursor/rules/writing-documentation.mdc`산문 내용을 작성하는 방법에 대한 지침.

문서화해야 할 모든 변경 사항을 찾은 후에는 이를 "변경됨"과 "제거됨"이라는 두 개의 큰 그룹으로 그룹화해야 합니다.

예:

```md
## Changed

## Removed
```

모든 변경 사항은 반드시 이 두 섹션 아래에 있어야 합니다.

각 변경 사항("변경" 또는 "제거")은 h3 제목이어야 합니다. 해당 형식을 정확하게 따라야 합니다.

예:

```md
## Changed

### `oldFunction` to `newFunction`
```

이제 제목이 지정되었으므로 각 변경 사항에 대해 정확한 구조를 따라야 합니다. 이 구조에서 벗어나면 안 됩니다.

변경사항에 대해 한두 문장으로 간략하게 설명하세요. 다음으로 왜 변경되었는지 한 문장으로 설명해 보세요.

각 변경 사항의 세 번째 요소는 기존 코드를 새 버전으로 마이그레이션하는 방법에 대한 설명입니다. 간결하면서도 명확하게 유지하고, 너무 많은 정보를 생략하지 마십시오. 이후에는 "diff" 구문을 사용하여 코드 블록을 제공해야 합니다. 코드 블록 내에서 해당 diff 구문으로 변경해야 하는 코드의 "이전" 및 "이후" 예를 표시해야 합니다.

예:

````md
## Changed

### `oldFunction` to `newFunction`

The `oldFunction` has been renamed to `newFunction`. This change improves clarity and consistency across the API.

To migrate, replace all instances of `oldFunction` with `newFunction` in your codebase.

```diff
- const result = oldFunction(args);
+ const result = newFunction(args);```
````

마이그레이션에 찾기 및 바꾸기보다 더 많은 단계가 필요한 경우 코드 블록 앞에 추가 설명을 추가할 수 있습니다. 여러 단계가 필요한 경우 번호가 매겨진 목록을 사용하여 각 단계를 명확하게 설명하세요.
