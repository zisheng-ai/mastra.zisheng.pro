# CopilotKit 채널

인앱 부조종사를 지원하는 동일한 Mastra Agent가 메시징 플랫폼에서 봇으로 실행될 수도 있습니다. CopilotKit의 채널 SDK는 채널에서 기본적으로 처리되는 스레드, Tool 호출, 풍부한 대화형 메시지 및 인간 참여형 승인을 통해 Agent를 Slack 및 기타 메시징 플랫폼에 연결합니다.

:::info

전체 플랫폼 설정은 [CopilotKit Channels 문서](https://docs.copilotkit.ai/slack/mastra)를 참조하세요. 이 페이지에서는 Channels가 Mastra Agent와 함께 작동하는 방식을 설명합니다.
:::

## 어떻게 어울리는지 {/* #how-it-fits-together */}

Mastra Agent는 배포된 위치에서 계속 실행되며 `registerCopilotKit()`을 통해 AG-UI로 노출됩니다([CopilotKit 개요](/guides/build-your-ui/copilotkit/overview) 참조). 채널은 `@copilotkit/channels`로 구축한 별도의 장기 실행 프로세스입니다. 하나 이상의 플랫폼 어댑터를 연결하고 채널이 Agent를 가리키도록 설정합니다. `createChannel`은 어댑터 배열을 사용하므로 단일 프로세스가 여러 플랫폼을 동시에 지원할 수 있습니다.
SDK 설치(배터리 포함, 모든 어댑터):

```bash npm2yarn
npm install @copilotkit/channels
```

```typescript title="channel.ts"
import { createChannel, Message, Section } from '@copilotkit/channels'
import { slack } from '@copilotkit/channels/slack'
import { mastraAgent } from './agent' // your AG-UI Mastra agent

const channel = createChannel({
  // Point the channel at your Mastra agent (an AbstractAgent, or a per-thread factory).
  agent: mastraAgent,
  adapters: [
    slack({
      botToken: process.env.SLACK_BOT_TOKEN!,
      appToken: process.env.SLACK_APP_TOKEN!,
    }),
  ],
})

channel.onMention(async ({ thread }) => {
  await thread.runAgent()
})

await channel.start()
```

Agent는 일반 AG-UI 입력을 수신하고 일반 AG-UI 이벤트를 내보냅니다. 플랫폼 메커니즘은 어댑터 뒤에 있으므로 동일한 Mastra Agent가 모든 채널에서 변경 없이 실행됩니다. 풍부한 메시지는 JSX로 작성되고 각 플랫폼의 기본 형식(예: Slack의 Block Kit)으로 렌더링되므로 플랫폼에 상응하는 카드가 없는 경우 대화형 카드의 성능이 저하됩니다.

## 느슨하게 {/* #slack */}

[Slack 빠른 시작](https://docs.copilotkit.ai/slack/mastra)은 처음부터 시작하여 채널에서 `@` 멘션할 수 있는 봇을 만든 다음 대화형 버튼 카드를 추가하는 과정을 안내합니다. Slack은 Slack으로 나가는 WebSocket 연결을 여는 Socket Mode를 통해 실행되므로 개발 중에는 공개 URL이나 터널이 필요하지 않습니다.
사용자 환경에서 Slack 자격 증명을 설정합니다.

* `SLACK_BOT_TOKEN`: 봇 사용자 OAuth 토큰(`xoxb-...`)
* `SLACK_APP_TOKEN`: 앱 수준 토큰`connections:write` scope (`xapp-...`)

## 기타 플랫폼 {/* #other-platforms */}

채널 SDK는 Slack에만 국한되지 않습니다. Microsoft Teams 같은 다른 플랫폼도 동일한 `@copilotkit/channels` API에서 실행됩니다. 일치하는 어댑터를 `adapters` 배열에 추가하면 나머지 Agent 코드는 그대로 유지됩니다. 현재 지원되는 플랫폼 목록과 플랫폼별 설정은 [CopilotKit Channels 문서](https://docs.copilotkit.ai/slack/mastra)를 참조하세요.
## 메시지 파이프라인 및 아키텍처 {/* #message-pipeline-and-architecture */}

관리형 채널은 의도적인 자격 증명 분할을 유지하며 이는 Mastra Agent가 별도의 Model 키와 Tool를 사용할 때 중요합니다.

* **당신은 계속**Agent 논리, Model 자격 증명, Tool 및 채널 프로세스.
* **CopilotKit Intelligence 보유**플랫폼 자격 증명, 메시지 전달, 등록, 상태 및 재연결.

사용자가 앱에 메시지를 보내면 차례가 시작됩니다. Intelligence는 플랫폼 이벤트를 수신하고 게이트웨이는 실행 중인 채널 프로세스에 차례를 전달합니다. Mastra Agent가 실행되고 응답을 렌더링합니다. 그런 다음 Intelligence는 응답을 기본 플랫폼 콘텐츠로 반환합니다. 플랫폼 자격 증명은 Agent 프로세스에 절대 입력되지 않으며 Enterprise Intelligence는 데이터 상주를 위해 자체 호스팅될 수 있습니다.

:::note

기본적으로 대화형 작업은 Memory에 존재하며 다시 시작할 때 재설정됩니다. 내구성이 뛰어난 작업 및 상태 저장소(Redis 또는 Postgres)를 사용하여 채널을 백업하면 버튼과 스레드별 상태가 다시 시작해도 유지되고 여러 인스턴스에 걸쳐 유지됩니다.

:::
