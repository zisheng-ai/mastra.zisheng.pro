# 사진관

Studio는 Agent, Workflow 및 Tool를 구축, 테스트 및 관리하기 위한 대화형 UI를 제공합니다. 개발 중에 로컬로 실행하고 추가하세요.[authentication](/docs/studio/auth), 또는[배포](/docs/studio/deployment)팀이 Agent를 관리하고 성능을 모니터링하고 내장된 관찰 기능을 통해 통찰력을 얻을 수 있도록 프로덕션에 적용하세요.

:::팁\[📹 보기]

보다[Mastra Studio overview](https://youtu.be/ojGu6Bi4wYk) for a short walkthrough of building, testing, and managing agents in Studio.

:::

## 스튜디오 시작 {/* #start-studio */}

다음을 사용하여 애플리케이션을 만든 경우`create mastra`, start the development server using the `dev` script. You can also run it directly with `mastra dev`.

```bash npm2yarn
npm run dev
```

서버가 실행되면 다음을 수행할 수 있습니다.

* 다음에서 Studio UI를 엽니다.[`localhost:4111`](http://localhost:4111/) to interact with your agents, workflows, and tools.
* 방문하다[`localhost:4111/swagger-ui`](http://localhost:4111/swagger-ui) to discover and interact with the underlying REST API.

Studio가 실행되는 동안[agents](/docs/agents/overview), [workflows](/docs/workflows/overview), and other parts of your Mastra application in real time.

## 스튜디오 배포 {/* #deploy-studio */}

팀과 Studio를 공유할 준비가 되면 다음을 사용하여 프로덕션에 배포할 수 있습니다.[Studio on Mastra platform](/docs/mastra-platform/studio) or your own infrastructure. Visit the [deployment docs](/docs/studio/deployment) to learn how.

## 프리미티브 {/* #primitives */}

### Agent {/* #agents */}

Agent과 직접 채팅, 전환[models](/models), and tweak settings like temperature and top-p to understand how they affect the output.

Agent와 상호 작용할 때 추론을 따르고 Tool 호출 출력을 볼 수 있습니다. 당신은 또한 할 수 있습니다[observe](#observability) traces and logs to see how responses are generated.

첨부할 수도 있습니다[scorers](#scorers) to measure and compare response quality over time.

Agent 응답 스트림 중에 동일한 스레드에서 후속 메시지를 보낼 수 있습니다. Studio에서는 스트림이 이를 확인할 때까지 메시지를 대기 중으로 표시한 후 해당 후속 작업 아래에 응답을 계속합니다. 동일한 스레드가 열려 있는 다른 Studio 탭에서는 활성 스트림을 관찰할 수 있습니다.

사용[Editor](/docs/editor/overview) to let non-technical team members iterate on agents and version every change, plus run experiments without redeploying.

### Workflow {/* #workflows */}

Workflow우를 그래프로 시각화하고 사용자 정의 입력을 사용하여 단계별로 실행하세요. 실행 중에 인터페이스는 실시간으로 업데이트되어 활성 단계와 사용된 경로를 표시합니다.

Workflow를 실행할 때 Tool 호출, 원시 JSON 출력, 그리고 도중에 발생할 수 있는 모든 오류를 보여주는 자세한 추적도 볼 수 있습니다.

### 프로세서 {/* #processors */}

각 Agent에 연결된 입력 및 출력 프로세서를 봅니다. Agent 세부 정보 패널에는 모든 프로세서가 이름과 유형별로 나열되므로 테스트하기 전에 가드레일과 토큰 제한기와 사용자 지정 프로세서가 올바르게 연결되어 있는지 확인할 수 있습니다.

보다[processors](/docs/agents/processors) and [guardrails](/docs/agents/guardrails) for configuration details.

### MCP 서버 {/* #mcp-servers */}

Mastra 인스턴스에 연결된 MCP 서버를 나열하고 사용 가능한 Tool를 살펴보세요.

### Tool {/* #tools */}

Agent에 할당하기 전에 자체적으로 Tool를 실행하여 동작을 관찰하고 테스트하세요. 문제가 발생하면 Tool를 별도로 다시 실행하여 문제를 디버깅하세요.

### 작업공간 {/* #workspaces */}

내장된 파일 브라우저를 사용하여 Agent의 작업 공간 파일 시스템에서 파일을 찾아보세요. 작업 공간 마운트 간을 전환하고, 디렉터리를 생성하고, 구문 강조를 통해 파일 내용을 확인하세요. 쓰기 가능한 작업 공간에서는 디렉터리 생성 및 파일 삭제가 가능합니다. 읽기 전용 작업 공간에는 그에 따라 레이블이 지정됩니다. 기술 탭에는 검색된 모든 기술과 지침, 참조 및 메타데이터가 나열됩니다. 다음에서 커뮤니티 스킬을 설치하세요.[skills.sh](https://skills.sh) or remove existing ones.

보다[workspaces](/docs/workspace/overview) for configuration details.

### 요청 컨텍스트 {/* #request-context */}

종속성 주입을 통해 Agent의 지침과 Tool에 유입되는 런타임 변수를 설정하세요. 요청 컨텍스트를 JSON으로 편집하거나 Agent가 정의할 때 스키마 기반 양식을 사용하세요.`requestContextSchema`. Values persist across test chats and experiments, so you can trigger conditional flows without restarting.

보다[request context](/docs/server/request-context) for configuration details.

## 평가 {/* #evaluation */}

날짜 필터를 사용하여 점수 지표를 사전 설정 또는 사용자 정의 시간 범위로 제한합니다.

### 득점자 {/* #scorers */}

득점자 탭에는 Agent의 득점자가 실행되는 결과가 표시됩니다. 메시지가 Agent를 통과하면 정의된 채점자가 각 출력을 비동기적으로 평가하고 여기에 결과를 렌더링합니다. 채점자가 다양한 상호 작용에 어떻게 반응하는지 이해하고 테스트 사례 전체에서 성능을 비교하며 개선이 필요한 영역을 식별할 수 있습니다.

### 데이터 세트 {/* #datasets */}

Agent와 Workflow를 평가하기 위한 테스트 사례 컬렉션을 만들고 관리하세요. CSV 또는 JSON에서 항목을 가져오고 입력 및 실측 스키마를 정의하고 특정 버전에 고정하여 실험을 정확하게 재현할 수 있습니다. 다음을 사용하여 실험을 실행하세요.[scorers](/docs/evals/overview) to compare quality across prompts, models, or code changes.

보다[datasets overview](/docs/datasets/overview) for the full API and versioning details.

### 실험 {/* #experiments */}

Agent, Workflow 또는 채점자에 대해 데이터 세트의 모든 항목을 실행하고 결과를 한곳에 수집합니다. 대상을 선택하고, 선택적으로 채점자를 연결하고, 실험을 시작하세요. 결과 보기에는 각 항목의 입력, 출력, 상태 및 개별 점수 분석이 표시됩니다. 두 가지 실험을 나란히 비교하여 Prompt, Model 또는 코드 변경의 영향을 측정하세요.

보다[datasets overview](/docs/datasets/overview) for setup details.

## 설정 {/* #settings */}

Studio와 Mastra 서버 간의 연결을 구성합니다. 설정 페이지에는 다음이 포함됩니다.

* **마스트라 인스턴스 URL**: Mastra 서버의 기본 URL(예:`http://localhost:4111`).
* **API 접두사**: 모든 API 요청에 대한 선택적 경로 접두사(기본값:`/api`).
* **맞춤 헤더**: 모든 요청과 함께 전송되는 키-값 쌍을 추가합니다. 이는 인증 토큰 또는 라우팅 헤더에 유용합니다.
* **주제**: 어두움, 밝음, 시스템 테마 간을 전환합니다.

## 코드 구성 {/* #code-configuration */}

게다가[settings](#settings) UI, you can configure the local development server and Studio also through the [`server`](/reference/configuration#server-options) option in your `src/mastra/index.ts`.

기본적으로 Studio는 다음에서 실행됩니다.[http://localhost:4111](http://localhost:4111). You can change the [`host`](/reference/configuration#serverhost) and [`port`](/reference/configuration#serverport).

Mastra는 또한 다음을 통해 HTTPS 개발을 지원합니다.[`--https`](/reference/cli/mastra#--https) flag, which automatically creates and manages certificates for your project. When you run `mastra dev --https`, a private key and certificate are generated for localhost (or your configured host). Visit the [HTTPS reference](/reference/configuration#serverhttps) to learn more.
