# 사진관

Studio는 Agent, Workflow 및 Tool를 구축, 테스트 및 관리하기 위한 대화형 UI를 제공합니다. 개발 중에 로컬로 실행하고 추가하세요.[authentication](/docs/studio/auth), 또는[배포](/docs/studio/deployment)팀이 Agent를 관리하고 성능을 모니터링하고 내장된 관찰 기능을 통해 통찰력을 얻을 수 있도록 프로덕션에 적용하세요.

:::tip\[📹 보기]

Studio에서 Agent를 빌드, 테스트 및 관리하는 방법을 간략히 살펴보려면 [Mastra Studio 개요](https://youtu.be/ojGu6Bi4wYk)를 참조하세요.
:::

## 스튜디오 시작 {/* #start-studio */}

`create mastra`를 사용하여 애플리케이션을 만들었다면 `dev` 스크립트를 사용하여 개발 서버를 시작하세요. `mastra dev`로 직접 실행할 수도 있습니다.
```bash npm2yarn
npm run dev
```

서버가 실행되면 다음을 수행할 수 있습니다.

* [`localhost:4111`](http://localhost:4111/)에서 Studio UI를 열어 Agent, Workflow, Tool과 상호 작용하세요.
* [`localhost:4111/swagger-ui`](http://localhost:4111/swagger-ui)를 방문하여 기반 REST API를 살펴보고 상호 작용하세요.
Studio가 실행되는 동안 [Agent](/docs/agents/overview), [Workflow](/docs/workflows/overview) 및 Mastra 애플리케이션의 다른 부분을 실시간으로 변경할 수 있습니다.
## 스튜디오 배포 {/* #deploy-studio */}

팀과 Studio를 공유할 준비가 되면 [Mastra 플랫폼의 Studio](/docs/mastra-platform/studio) 또는 자체 인프라를 사용하여 프로덕션에 배포할 수 있습니다. 자세한 방법은 [배포 문서](/docs/studio/deployment)를 참조하세요.
## 프리미티브 {/* #primitives */}

### Agent {/* #agents */}

Agent와 직접 채팅하고 [Model](/models)을 전환하며 temperature와 top-p 같은 설정을 조정하여 출력에 어떤 영향을 미치는지 확인하세요.
Agent와 상호 작용할 때 추론 과정을 따라가고 Tool 호출 출력을 확인할 수 있습니다. 또한 Trace와 로그를 [관찰](#observability)하여 응답이 생성되는 과정을 확인할 수 있습니다.
[스코어러](#scorers)를 연결하여 시간에 따른 응답 품질을 측정하고 비교할 수도 있습니다.
Agent 응답 스트림 중에 동일한 스레드에서 후속 메시지를 보낼 수 있습니다. Studio에서는 스트림이 이를 확인할 때까지 메시지를 대기 중으로 표시한 후 해당 후속 작업 아래에 응답을 계속합니다. 동일한 스레드가 열려 있는 다른 Studio 탭에서는 활성 스트림을 관찰할 수 있습니다.

[Editor](/docs/editor/overview)를 사용하면 비기술 팀 구성원이 Agent를 반복적으로 개선하고 모든 변경 사항을 버전으로 관리하며, 재배포 없이 실험을 실행할 수 있습니다.
### Workflow {/* #workflows */}

Workflow를 그래프로 시각화하고 사용자 정의 입력을 사용하여 단계별로 실행하세요. 실행 중에 인터페이스는 실시간으로 업데이트되어 활성 단계와 사용된 경로를 표시합니다.

Workflow를 실행할 때 Tool 호출, 원시 JSON 출력, 그리고 도중에 발생할 수 있는 모든 오류를 보여주는 자세한 추적도 볼 수 있습니다.

### 프로세서 {/* #processors */}

각 Agent에 연결된 입력 및 출력 프로세서를 봅니다. Agent 세부 정보 패널에는 모든 프로세서가 이름과 유형별로 나열되므로 테스트하기 전에 가드레일과 토큰 제한기와 사용자 지정 프로세서가 올바르게 연결되어 있는지 확인할 수 있습니다.

구성 세부 정보는 [프로세서](/docs/agents/processors)와 [가드레일](/docs/agents/guardrails)을 참조하세요.
### MCP 서버 {/* #mcp-servers */}

Mastra 인스턴스에 연결된 MCP 서버를 나열하고 사용 가능한 Tool를 살펴보세요.

### Tool {/* #tools */}

Agent에 할당하기 전에 자체적으로 Tool를 실행하여 동작을 관찰하고 테스트하세요. 문제가 발생하면 Tool를 별도로 다시 실행하여 문제를 디버깅하세요.

### 작업공간 {/* #workspaces */}

내장 파일 브라우저를 사용하여 Agent의 Workspace 파일 시스템에서 파일을 탐색하세요. Workspace 마운트 간에 전환하고, 디렉터리를 만들고, 구문 강조와 함께 파일 내용을 확인할 수 있습니다. 쓰기 가능한 Workspace에서는 디렉터리 생성과 파일 삭제가 가능합니다. 읽기 전용 Workspace에는 그에 맞는 레이블이 표시됩니다. Skill 탭에는 검색된 모든 Skill과 해당 지침, 레퍼런스 및 메타데이터가 나열됩니다. [skills.sh](https://skills.sh)에서 커뮤니티 Skill을 설치하거나 기존 Skill을 제거하세요.
구성 세부 정보는 [Workspace](/docs/workspace/overview)를 참조하세요.
### 요청 컨텍스트 {/* #request-context */}

종속성 주입을 통해 Agent의 지침과 Tool에 전달되는 런타임 변수를 설정하세요. 요청 컨텍스트를 JSON으로 편집하거나 Agent가 `requestContextSchema`를 정의한 경우 스키마 기반 양식을 사용하세요. 값은 테스트 채팅과 실험 전반에 유지되므로 다시 시작하지 않고도 조건부 흐름을 트리거할 수 있습니다.
구성 세부 정보는 [요청 컨텍스트](/docs/server/request-context)를 참조하세요.
## 평가 {/* #evaluation */}

날짜 필터를 사용하여 점수 지표를 사전 설정 또는 사용자 정의 시간 범위로 제한합니다.

### 득점자 {/* #scorers */}

득점자 탭에는 Agent의 득점자가 실행되는 결과가 표시됩니다. 메시지가 Agent를 통과하면 정의된 채점자가 각 출력을 비동기적으로 평가하고 여기에 결과를 렌더링합니다. 채점자가 다양한 상호 작용에 어떻게 반응하는지 이해하고 테스트 사례 전체에서 성능을 비교하며 개선이 필요한 영역을 식별할 수 있습니다.

### 데이터 세트 {/* #datasets */}

Agent와 Workflow를 평가하기 위한 테스트 사례 컬렉션을 만들고 관리하세요. CSV 또는 JSON에서 항목을 가져오고 입력 및 실측 스키마를 정의하며, 특정 버전에 고정하여 실험을 정확하게 재현할 수 있습니다. [스코어러](/docs/evals/overview)를 사용하여 실험을 실행하고 Prompt, Model 또는 코드 변경에 따른 품질을 비교하세요.
전체 API와 버전 관리 세부 정보는 [데이터세트 개요](/docs/datasets/overview)를 참조하세요.
### 실험 {/* #experiments */}

Agent, Workflow 또는 채점자에 대해 데이터 세트의 모든 항목을 실행하고 결과를 한곳에 수집합니다. 대상을 선택하고, 선택적으로 채점자를 연결하고, 실험을 시작하세요. 결과 보기에는 각 항목의 입력, 출력, 상태 및 개별 점수 분석이 표시됩니다. 두 가지 실험을 나란히 비교하여 Prompt, Model 또는 코드 변경의 영향을 측정하세요.

설정 세부 정보는 [데이터세트 개요](/docs/datasets/overview)를 참조하세요.

## 설정 {/* #settings */}

Studio와 Mastra 서버 간의 연결을 구성합니다. 설정 페이지에는 다음이 포함됩니다.

* **마스트라 인스턴스 URL**: Mastra 서버의 기본 URL(예:`http://localhost:4111`).
* **API 접두사**: 모든 API 요청에 대한 선택적 경로 접두사(기본값:`/api`).
* **맞춤 헤더**: 모든 요청과 함께 전송되는 키-값 쌍을 추가합니다. 이는 인증 토큰 또는 라우팅 헤더에 유용합니다.
* **주제**: 어두움, 밝음, 시스템 테마 간을 전환합니다.

## 코드 구성 {/* #code-configuration */}

[settings](#settings) UI뿐만 아니라 `src/mastra/index.ts`의 [`server`](/reference/configuration#server-options) 옵션을 통해 로컬 개발 서버와 Studio를 구성할 수도 있습니다.
기본적으로 Studio는 [http://localhost:4111](http://localhost:4111)에서 실행됩니다. [`host`](/reference/configuration#serverhost)와 [`port`](/reference/configuration#serverport)를 변경할 수 있습니다.
Mastra는 [`--https`](/reference/cli/mastra#--https) 플래그를 통한 HTTPS 개발도 지원하며, 프로젝트의 인증서를 자동으로 생성하고 관리합니다. `mastra dev --https`를 실행하면 localhost 또는 구성된 호스트용 비공개 키와 인증서가 생성됩니다. 자세한 내용은 [HTTPS 레퍼런스](/reference/configuration#serverhttps)를 참조하세요.
