# 스튜디오 Observability

Studio에는 다음과 같은 Observability 보기가 포함되어 있습니다.

* **측정항목**집계된 성능 데이터용
* **흔적**개별요청검사용
* **로그**내부 및 애플리케이션 로그 검색용

모두 구성하려면 관측성 스토리지 백엔드가 필요합니다.

## 빠른 시작 {/* #quickstart */}

자세한 지침을 보려면 다음을 따르세요.[observability instructions](/docs/observability/overview). To get up and running quickly, add the `@mastra/observability` package to your project and configure it with [LibSQL](/reference/storage/libsql) and [DuckDB](/reference/vectors/duckdb) for a local development setup that supports both traces and metrics.

```bash npm2yarn
npm install @mastra/observability @mastra/libsql @mastra/duckdb
```

그런 다음 다음을 추가하십시오.`src/mastra/index.ts`:

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { LibSQLStore } from '@mastra/libsql'
import { DuckDBStore } from '@mastra/duckdb'
import { MastraCompositeStore } from '@mastra/core/storage'
import {
  Observability,
  MastraStorageExporter,
  MastraPlatformExporter,
  SensitiveDataFilter,
} from '@mastra/observability'

export const mastra = new Mastra({
  // highlight-start
  storage: new MastraCompositeStore({
    id: 'composite-storage',
    default: new LibSQLStore({
      id: 'mastra-storage',
      url: 'file:./mastra.db',
    }),
    domains: {
      observability: await new DuckDBStore().getStore('observability'),
    },
  }),
  // highlight-end
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'mastra',
        exporters: [
          new MastraStorageExporter(), // Persists observability events to Mastra Storage
          new MastraPlatformExporter(), // Sends observability events to Mastra platform (if MASTRA_PLATFORM_ACCESS_TOKEN is set)
        ],
        spanOutputProcessors: [
          new SensitiveDataFilter(), // Redacts sensitive data like passwords, tokens, keys
        ],
      },
    },
  }),
})
```

## 마스트라 플랫폼 {/* #mastra-platform */}

프로젝트 및 배포 전반에 걸쳐 호스팅된 추적, 로그, 측정항목은 다음을 참조하세요.[Observability on Mastra platform](/docs/mastra-platform/observability).

## 측정항목 {/* #metrics */}

구성 가능한 시간 범위(지난 24시간~30일) 동안 Agent, Workflow 및 Tool 성능을 요약하는 대시보드입니다. 맨 위 행에는 총 Agent 실행, Model 비용, 토큰 소비 및 평균 득점자 성능이 표시됩니다. 그 아래의 세부 카드에는 Model 사용량 및 Model당 비용, Agent당 토큰 사용량, 예상 비용이 포함된 시간 경과에 따른 토큰 사용량, 완료 및 오류 수가 포함된 트레이스 볼륨, 대기 시간 백분위수(p50 및 p95), 시간 경과에 따른 득점자 추세가 자세히 나와 있습니다.

방문[metrics overview](/docs/observability/metrics/overview) for more details.

:::메모

측정항목에는 Observability을 위해 별도의 OLAP 저장소가 필요합니다. PostgreSQL, LibSQL 등과 같은 관계형 데이터베이스는 측정항목에 지원되지 않습니다. 다시 시작하면 Memory 내 저장소가 재설정됩니다.

:::

## 흔적 {/* #traces */}

Agent 또는 Workflow를 실행할 때 Observability 탭에는 Model 호출, Tool 실행 및 Workflow 단계와 같은 주요 AI 작업을 강조하는 추적이 표시됩니다. 이러한 추적을 따라가면 데이터가 어떻게 이동하는지, 어디에서 시간이 소비되는지, 내부적으로 무슨 일이 일어나고 있는지 확인할 수 있습니다.

추적 목록 위에서 다음을 엽니다.**Columns** to show or hide input, entity, duration, input token, output token, estimated cost, and custom metadata columns. To display custom metadata, add the top-level key used in `tracingOptions.metadata`. Studio saves the selection in browser storage for the current Mastra server and API prefix.

토큰 및 예상 비용 열에는 측정항목을 지원하는 관측 가능성 저장소가 필요합니다. 이 열은**Branches** view because several branch rows can belong to the same trace.

추적은 하위 수준 프레임워크 세부 정보를 필터링하여 추적에 집중하고 읽을 수 있도록 합니다. 방문[tracing overview](/docs/observability/tracing/overview) for more details.

추적을 내보내려면 다음을 선택하세요.**Download trace JSON** in the trace panel header. This saves the entire trace as a `trace-<id>.json` file, with every span and its full input, output, metadata, and attributes. Use it to share a trace or attach it to a bug report, or alternatively build an evaluation dataset offline.

## 로그 {/* #logs */}

관측 가능성 스토리지로 전달된 내부 Mastra 로그를 찾아보세요. 로그는 전체 텍스트 검색(메시지 콘텐츠, 엔터티 이름 및 추적 ID 전반), 날짜 사전 설정(지난 24시간~30일) 및 수준, 엔터티 유형 및 엔터티 이름에 대한 다중 선택 필터를 제공합니다. 로그를 선택하면 전체 메시지, 구조화된 데이터, 메타데이터를 표시하는 세부정보 패널이 열립니다. 로그가 추적과 연관되어 있는 경우 추적 및 범위 타임라인으로 직접 이동할 수 있습니다.

Observability을 구성하면 로그 전달이 기본적으로 활성화됩니다. 보다[logging](/docs/observability/logging) for level configuration, query examples, and customization details.
