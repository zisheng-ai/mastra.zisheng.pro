# PubSub

Mastra는 게시/구독(pub/sub) 시스템을 내부 이벤트 버스로 사용합니다. 구성 요소는 주제에 이벤트를 게시하고 다른 구성 요소는 해당 주제를 구독하여 반응합니다. 구성하는 백엔드는 해당 이벤트가 한 프로세스 내에서, 한 호스트의 프로세스 간에, 또는 별도의 인스턴스 간에 이동하는 거리를 결정합니다.

백엔드를 한 번 설정하면`Mastra` instance, and the rest of the system uses it without changes. By default, Mastra uses an in-process backend that needs no setup.

## Mastra가 PubSub를 사용하는 방법 {/* #how-mastra-uses-pubsub */}

여러 내장 시스템이 동일한 게시/구독 버스를 통해 이벤트를 게시하고 구독합니다.

* **Workflow 실행**: 스케줄러는`workflow.start` event, and a long-lived worker consumes it to run the workflow. Step and lifecycle events flow over pub/sub during execution.
* **예약된 Workflow**: 스케줄러는 Workflow 주제에 게시하여 마감 실행을 전달합니다. 보다[Scheduled workflows](/docs/workflows/scheduled-workflows).
* **백그라운드 작업**: 작업 관리자는 작업을 작업자 그룹에 파견하고 팬 작업 수명 주기 업데이트를 구독자에게 전달합니다. 이는 백그라운드 작업 스트림이 실시간으로 유지되는 방식입니다. 보다[Background task streaming](/docs/long-running-agents/background-tasks#subscribe-to-all-task-events).
* **Agent 신호**: 활성 Agent 실행에 신호를 보내면 스레드 주제에 이벤트가 게시되므로 다른 프로세스에서 실행 중인 실행이 신호를 받습니다.
* **재개 가능한 스트림**: 스트림 청크는 실행마다 게시되므로 다시 연결하는 클라이언트는 놓친 내용을 재생할 수 있습니다.

이러한 시스템은 하나의 버스에서 실행되기 때문에 선택한 백엔드는 모든 시스템에 동시에 적용됩니다.

## 배송 모드 {/* #delivery-modes */}

백엔드는 다음과 같이 정의된 두 가지 모드 중 하나로 이벤트를 전달합니다.[`PubSub`](/reference/pubsub/base) contract:

* **당기다**: 소비자는 스스로 백엔드에서 읽으며, Mastra는 수명이 긴 작업자 루프를 사용하여 이를 수행합니다. 다음과 같은 분산 백엔드[`RedisStreamsPubSub`](/reference/pubsub/redis-streams) use this mode.
* **푸시**: 소비자가 요청하지 않고 프로세스 중이거나 HTTP를 통해 이벤트가 도착합니다. 기본값[`EventEmitterPubSub`](/reference/pubsub/event-emitter) delivers this way in process.

구독자는 소비자 그룹을 통해 작업을 배포할 수도 있습니다. 같은 그룹의 구성원은 이벤트를 분할하여 각 이벤트가 한 번 처리됩니다. 그룹이 없는 구독자는 모든 이벤트를 수신하며, 이 이벤트는 그룹화되지 않은 모든 구독자에게 스트림을 전달합니다.

## 기본 백엔드 {/* #default-backend */}

설정하지 않았을 때`pubsub` option, Mastra uses [`EventEmitterPubSub`](/reference/pubsub/event-emitter). It delivers events in process using a Node.js [`EventEmitter`](https://nodejs.org/api/events.html#class-eventemitter), so it works without any external service.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

// No pubsub option: Mastra uses EventEmitterPubSub
export const mastra = new Mastra({})
```

프로세스 내에서 실행되기 때문에 이벤트는 지속되지 않으며 다른 프로세스에 도달하지 않습니다. 기본값은 대부분의 애플리케이션을 포괄하는 단일 인스턴스에 적합합니다.

## 백엔드 선택 {/* #choosing-a-backend */}

설정`pubsub` option on the `Mastra` instance to choose a backend. Each backend implements the same [`PubSub`](/reference/pubsub/base) contract, so the rest of your application doesn't change.

결정적인 질문은 구독자가 실행되는 위치입니다.

| 백엔드 | 범위 | 모드 | 패키지 |
| - | - | - | - |
|[`EventEmitterPubSub`](/reference/pubsub/event-emitter) | Single process | Pull and push | `@mastra/core` |
| [`UnixSocketPubSub`](/reference/pubsub/unix-socket-pubsub) | Multiple processes, one host | Push | `@mastra/core` |
| [`RedisStreamsPubSub`](/reference/pubsub/redis-streams) | Distributed, multiple hosts | Pull | `@mastra/redis-streams` |
| [`GoogleCloudPubSub`](/reference/pubsub/google-cloud-pubsub) | Distributed, multiple hosts | Pull | `@mastra/google-cloud-pubsub` |

### 하나의 호스트에 여러 프로세스가 있음 {/* #multiple-processes-on-one-host */}

사용[`UnixSocketPubSub`](/reference/pubsub/unix-socket-pubsub) when several processes on the same machine need to share a stream. It delivers events over a Unix domain socket and elects one process as a broker. If the broker exits, the remaining processes elect a new one.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { UnixSocketPubSub } from '@mastra/core/events'

export const mastra = new Mastra({
  pubsub: new UnixSocketPubSub('/tmp/mastra/events.sock'),
})
```

### 분산 배포 {/* #distributed-deployments */}

둘 이상의 인스턴스나 호스트를 실행할 때 분산 백엔드를 사용하면 모든 인스턴스가 동일한 이벤트를 수신하게 됩니다. 이는 한 인스턴스에서 처리한 요청이 다른 인스턴스에서 실행 중인 작업에 도달해야 할 때마다 중요합니다.

예를 들어, Agent 실행에 신호를 보내려면 신호 이벤트가 프로세스 경계를 ​​넘어 실행을 소유한 인스턴스로 이동해야 합니다. in-process 기본값을 사용하면 해당 인스턴스는 이벤트를 수신하지 않습니다.

아래의 두 백엔드는 프로세스와 호스트 전체에 걸쳐 전달되며 재전송을 위해 이벤트를 유지합니다.

다음 예제에서는[Redis Streams](https://redis.io/docs/latest/develop/data-types/streams/):

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { RedisStreamsPubSub } from '@mastra/redis-streams'

export const mastra = new Mastra({
  pubsub: new RedisStreamsPubSub({
    url: 'redis://localhost:6379',
  }),
})
```

다음 예제에서는[Google Cloud Pub/Sub](https://cloud.google.com/pubsub/docs):

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { GoogleCloudPubSub } from '@mastra/google-cloud-pubsub'

export const mastra = new Mastra({
  pubsub: new GoogleCloudPubSub({
    projectId: 'my-project',
  }),
})
```

## 재개 가능한 스트림 {/* #resumable-streams */}

재개 가능한 스트림을 사용하면 클라이언트가 놓친 이벤트를 다시 연결하고 재생할 수 있으며, 이를 위해서는 백엔드가 최신 기록을 유지해야 합니다. 다음과 같은 분산 백엔드[`RedisStreamsPubSub`](/reference/pubsub/redis-streams) persist events, so they support replay on their own.

진행 중인 배송은 기록을 유지하지 않습니다. 위에 재생을 추가하려면[`EventEmitterPubSub`](/reference/pubsub/event-emitter), wrap it in [`CachingPubSub`](/reference/pubsub/caching-pubsub), which records published events per topic so a late or reconnecting subscriber can catch up before continuing with live events.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { CachingPubSub, EventEmitterPubSub } from '@mastra/core/events'
import { InMemoryServerCache } from '@mastra/core/cache'

const cache = new InMemoryServerCache()

export const mastra = new Mastra({
  pubsub: new CachingPubSub(new EventEmitterPubSub(), cache),
})
```

방문[PubSub reference](/reference/pubsub/base) for the full delivery contract and the configuration options for each backend.
