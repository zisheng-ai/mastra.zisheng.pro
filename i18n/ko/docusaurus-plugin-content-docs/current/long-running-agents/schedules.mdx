# 일정

**추가된 항목:** `@mastra/core@1.50.0`

:::실험적

이 기능은 베타 버전입니다. API가 안정될 때까지 주요 버전 변경 없이 주요 변경 사항이 발생할 수 있습니다.

:::

일정은 크론 주기에 따라 Agent를 실행합니다. 화재가 발생할 때마다 Mastra는 Agent에게 Prompt를 보냅니다.[signal](/docs/long-running-agents/signals) into a thread or as a threadless [`agent.generate()`](/reference/agents/generate) run. Use schedules for recurring agent work such as daily summaries, periodic checks, or scheduled nudges into a conversation.

일정은 지속되므로 다시 시작하고 재배포해도 유지됩니다. 다음을 통해 런타임에 관리합니다.[`mastra.schedules`](/reference/schedules/overview), the canonical create, read, update, and delete (CRUD) surface. The same surface also manages [workflow schedules](/docs/workflows/scheduled-workflows) (pass `workflowId` instead of `agentId`Workflow를 예약하려면)

:::메모

일정에는[storage](/docs/storage/overview) adapter that implements the schedules domain. See the [`mastra.schedules` reference](/reference/schedules/overview) for supported adapters and API behavior.

:::

## 빠른 시작 {/* #quickstart */}

다음 일정은`pinger` agent every hour. It has no thread, so each fire is an isolated `agent.generate()` run.

```typescript title="src/mastra/schedules.ts"
import { Mastra } from '@mastra/core'
import { Agent } from '@mastra/core/agent'
import { LibSQLStore } from '@mastra/libsql'

const pinger = new Agent({
  id: 'pinger',
  name: 'Pinger',
  instructions: 'Report the current system status in one sentence.',
  model: '__GATEWAY_OPENAI_MODEL__',
})

const mastra = new Mastra({
  agents: { pinger },
  storage: new LibSQLStore({ id: 'mastra-storage', url: 'file:./mastra.db' }),
})

await mastra.schedules.create({
  agentId: 'pinger',
  cron: '0 * * * *',
  prompt: 'Give me a status update.',
})
```

Mastra는 일정이 처음 생성될 때 스케줄러를 시작한 다음 지정한 cron에서 Agent를 실행합니다.

## 운율 {/* #cadence */}

cron 표현식에서 실행을 예약합니다. 그만큼`cron` field accepts a standard 5-, 6-, or 7-part cron expression, and it's validated when you create or update the schedule.

`croner`예를 들어 별명도 작동합니다.`@hourly`, `@daily`, `@weekly`, `@monthly`, and `@midnight`. For day-and-time combinations, write the cron field directly:

```typescript
// Every weekday at 9am
await mastra.schedules.create({
  agentId: 'pinger',
  cron: '0 9 * * 1-5',
  prompt: 'Start-of-day check.',
})
```

세트`timezone` to an IANA timezone, for example `America/New_York`, so fire times don't depend on the host's locale. When omitted, the cron resolves against the host's local timezone.

더 읽기 쉬운 크론 구성을 위해 다음과 같은 사용자 영역 빌더를 사용할 수 있습니다.[`cron-time-generator`](https://www.npmjs.com/package/cron-time-generator) and pass its output to `cron`.

## 스레드리스 및 스레드 일정 {/* #threadless-and-threaded-schedules */}

Agent 일정은 두 가지 모드 중 하나로 실행되며, 통과 여부에 따라 결정됩니다.`threadId`.

### 스레드리스 {/* #threadless */}

없이`threadId`, each fire is an isolated `agent.generate()` run. Nothing is written to a conversation thread. This is the simplest mode and suits status checks, reports, and other work that doesn't need conversation context.

### 스레드 {/* #threaded */}

와`threadId`, the schedule sends a [signal](/docs/long-running-agents/signals) into that thread, so the prompt joins the agent's conversation. Threaded schedules require a `resourceId` alongside the `threadId`.

```typescript title="src/mastra/schedules.ts"
await mastra.schedules.create({
  agentId: 'pinger',
  cron: '0 9 * * *',
  prompt: 'Summarize anything new since yesterday.',
  threadId: 'thread-123',
  resourceId: 'user-456',
})
```

스레드 일정은 신호 유형, XML 태그, 태그 속성, 활성 또는 유휴 전달 동작을 포함하여 신호 동작 방식을 제어하는 ​​추가 필드를 허용합니다. 옵션을 반영합니다.[`agent.sendSignal()`](/docs/long-running-agents/signals) accepts and stay JSON-serializable so they persist with the schedule.

이 필드에는`threadId`. For the full threaded input shape, see the [agent schedule input reference](/reference/schedules/overview#createinput).

```typescript
await mastra.schedules.create({
  agentId: 'pinger',
  cron: '0 9 * * *',
  prompt: 'Summarize anything new since yesterday.',
  threadId: 'thread-123',
  resourceId: 'user-456',
  tagName: 'check-in', // renders as <check-in>…</check-in>
  attributes: { source: 'cron' },
  ifActive: { behavior: 'discard' }, // skip if the thread is mid-stream
  ifIdle: {
    behavior: 'wake', // wake the agent if the thread is idle
    streamOptions: { requestContext: { locale: 'en-US' } },
  },
})
```

`providerOptions`모든 실행 시 신호 페이로드에 병합되어 스레드 및 스레드 없는 일정 모두에 적용됩니다.

## 일정 관리 {/* #managing-schedules */}

사용`mastra.schedules` for all schedule operations. The service can create, read, update, pause, resume, manually run, and delete schedules.

```typescript
const schedule = await mastra.schedules.create({
  agentId: 'pinger',
  cron: '0 * * * *',
  prompt: 'Status check.',
})

await mastra.schedules.pause(schedule.id)
await mastra.schedules.resume(schedule.id)
await mastra.schedules.run(schedule.id) // Fire once now, off-schedule
```

`pause`그리고`resume` are durable. `run` fires the schedule once immediately without affecting its cadence. For the complete method list, filters, and patch fields, see the [`mastra.schedules` reference](/reference/schedules/overview).

### Workflow 일정 {/* #workflow-schedules */}

동일한 서비스는 Agent 대신 Workflow를 실행하는 일정을 만듭니다. 통과하다`workflowId` and the workflow-shaped fields:

```typescript
await mastra.schedules.create({
  workflowId: 'daily-report',
  cron: '0 9 * * *',
  inputData: { userId: 'system' },
})
```

이런 방식으로 생성된 Workflow 일정은 선언적 일정과 무관합니다.`schedule` field on `createWorkflow`, see [scheduled workflows](/docs/workflows/scheduled-workflows) for the declarative form and Studio views.

### 맞춤 ID {/* #custom-ids */}

통과하다`id` when you need a predictable handle to look up, update, or delete later.

```typescript
await mastra.schedules.create({
  id: 'nightly-summary',
  agentId: 'pinger',
  cron: '0 9 * * *',
  prompt: 'Summarize anything new since yesterday.',
})
```

참조[`create(input)` reference](/reference/schedules/overview#createinput) for ID normalization rules and duplicate ID behavior.

### 클라이언트에서 {/* #from-the-client */}

동일한 작업을 다음에서 사용할 수 있습니다.`@mastra/client-js` over the `/api/schedules` routes, so you can manage schedules from a separate process or a UI. See the [client-js agent schedules reference](/reference/client-js/agents#agent-schedules) for the client method list.

## 수명주기 후크 {/* #lifecycle-hooks */}

후크를 사용하면 Agent 일정 수명 주기의 주요 지점에서 코드를 실행할 수 있습니다. 예를 들어 실행 시간 매개변수를 계산하거나 결과에 반응합니다. 다음에서 구성하세요.`Mastra` constructor under `schedules`. The hooks are a single flat bundle that runs for every agent's schedules; each hook context carries the firing `agentId`, so branch on it when you need per-agent behavior. Hooks live at the `Mastra` level so they apply to both code-defined and stored agents.

```typescript title="src/mastra/index.ts"
const mastra = new Mastra({
  agents: { pinger },
  storage: new LibSQLStore({ id: 'mastra-storage', url: 'file:./mastra.db' }),
  schedules: {
    prepare: async ({ agentId, schedule, trigger }) => {
      // Return overrides, null to skip this fire, or undefined for defaults
      return { prompt: `Status as of ${trigger.firedAt.toISOString()}` }
    },
    onFinish: async ({ agentId, outcome, runId }) => {
      // Runs on any non-error, non-abort outcome
    },
    onError: async ({ agentId, phase, error }) => {
      // Runs when prepare, the signal, or the agent run threw
    },
    onAbort: async ({ agentId, runId }) => {
      // Runs when the run was aborted mid-stream
    },
  },
})
```

후크는 다음과 같습니다.

* `prepare`: 불이 나기 전에 달려갑니다. 다음과 같은 실행 시간 매개변수를 재정의하는 객체를 반환합니다.`prompt` or `threadId`, `null` to skip the fire, or `undefined` to use the stored defaults.
* `onFinish`: 오류가 없고 중단되지 않은 터미널 상태에 도달한 트리거당 한 번 실행됩니다.
* `onError`: 실패 후 실행`prepare` or the signal. It also runs when the agent run fails.
* `onAbort`: 실행이 중간에 중단되었을 때 실행됩니다.

모든 후크 컨텍스트에는 다음이 포함됩니다.`agentId` (the agent the schedule fired for) alongside `schedule` and `trigger`.

후크 예외가 포착되어 기록됩니다. 작업자를 다시 라우팅하거나 다른 후크를 유발하지 않습니다.
