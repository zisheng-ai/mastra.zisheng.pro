# 개발하다

Mastra 프로젝트가 있으면 Agent를 개발, 실행 및 테스트할 준비가 된 것입니다.

## 로컬에서 Mastra 실행 {/* #run-mastra-locally */}

Agent가 작동하는 모습을 확인하는 가장 빠른 방법은 다음과 같습니다.[Mastra Studio](/docs/studio/overview). From your project root, start Studio and the local development server with [`mastra dev`](/reference/cli/mastra#mastra-dev):

```bash npm2yarn
npx mastra dev
```

오픈 스튜디오[`http://localhost:4111`](http://localhost:4111) to test your agent and inspect its runs.

개발 서버는 Agent, Tool, Workflow용 API도 공개합니다. 열려 있는[`http://localhost:4111/api`](http://localhost:4111/api) to browse what's available, then connect your frontend using the [Mastra Client](/docs/server/mastra-client).

귀하의 변경 사항`src/mastra/` directory automatically restart the development server, so you don't need to restart it manually as you build.

## AI로 구축 {/* #build-with-ai */}

Mastra는 코딩 Agent가 고품질 Mastra 코드를 작성하는 데 도움이 되는 기술과 CLI를 제공합니다.

### 마스트라 스킬 {/* #mastra-skill */}

AI Model에는 Mastra의 API에 대한 최신 지식이 없을 수도 있습니다. 사용[Mastra skill](https://github.com/mastra-ai/skills) to give your coding agent implementation guidance, best practices, and instructions for fetching the latest Mastra documentation.

다음을 사용하여 스킬을 수동으로 설치하십시오.

```bash npm2yarn
npx skills add mastra-ai/skills
```

최신 지침을 얻으려면 정기적으로 기술을 업데이트하십시오.

```bash npm2yarn
npx skills update mastra
```

:::메모

다음을 사용하여 프로젝트를 생성할 때[create mastra](/docs), the command automatically installs the Mastra skill so your coding agent can discover and use it.

:::

### 마스트라 CLI {/* #mastra-cli */}

사용[`mastra` CLI](/reference/cli/mastra) to give your coding agent a feedback loop for testing updates and inspecting results. The CLI gives it access to agents, workflows, tools, memory, evals, traces, and logs.

예를 들어 코딩 Agent는 Agent를 실행한 후 추적을 가져와 결과를 검사할 수 있습니다.

```bash
npx mastra api --url http://localhost:4111 agent run agent '{"messages":"Hello"}'
npx mastra api --url http://localhost:4111 trace list
```

설치하는 것을 기억하세요[Mastra skill](#mastra-skill) to teach your coding agent how to use the CLI.

## 프로젝트 구조 {/* #project-structure */}

프레임워크를 채택할 때 가장 먼저 결정하는 것 중 하나는 프로젝트를 구성하는 방법입니다. 프레임워크 코드를 다음과 같이 유지하는 것이 좋습니다.`src/mastra/`, with related primitives grouped into their own files or folders. Use `src/mastra/index.ts` as the central place to configure and register them.

최소 프로젝트는 다음과 같습니다.

```text
src/
  mastra/
    agents/
      agent.ts
    tools/
      tool.ts
    workflows/
      workflow.ts
    scorers/
      scorer.ts
    skills.ts
    index.ts
```

참조[project structure reference](/reference/project-structure) for the default layout and recommended conventions.

## 파일 기반 Agent {/* #file-based-agents */}

:::실험적

파일 기반 Agent는 베타 버전이며 안정화되기 전에 변경될 수 있습니다.

파일 기반 검색은 다음을 통해서만 실행됩니다.`mastra dev` or `mastra build`. If your app imports `mastra` directly, including through a web framework or server adapter, file-based agents aren't discovered. Register those agents in code or run Mastra as a separate server.

:::

:::팁\[📹 보기]

[첫 번째 파일 기반 Agent를 만드는 방법](https://www.youtube.com/watch?v=5Kfn-oYkJNg\&t=18s)

:::

파일 기반 Agent를 사용하면 Mastra가 자동으로[discovers](/reference/file-based-agents/config#discovery-lifecycle) agents and related primitives from supported files under `src/mastra/`. You organize those files by convention instead of importing and registering each primitive on your [`Mastra`](/reference/core/mastra-class) instance.

파일 시스템은 프로젝트 구조를 직접적으로 나타내므로 귀하와 귀하의 코딩 Agent는 모든 것이 코드에서 어떻게 연결되어 있는지 추적하지 않고도 프로젝트가 어떻게 조화되는지 이해할 수 있습니다.

프로젝트 전반에 걸쳐 파일 기반 Agent를 사용하거나 코드에 정의된 기본 요소와 함께 점진적으로 채택할 수 있습니다. 모든 Mastra 기능이나 사용 사례가 아직 지원되는 것은 아닙니다.

### 첫 번째 Agent 만들기 {/* #create-your-first-agent */}

파일 기반 Agent는 다음의 자체 디렉터리에 있습니다.`src/mastra/agents/`. To create a working agent, add a `config.ts` file for its model and runtime options and an `instructions.md` file for its always-on prompt:

```text
src/mastra/agents/
  writing-assistant/
    config.ts
    instructions.md
```

디렉터리 이름이 Agent의 기본값이 됩니다.`id` and `name`. In this example, Mastra registers the agent as `writing-assistant`.

```typescript title="src/mastra/agents/writing-assistant/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

```markdown title="src/mastra/agents/writing-assistant/instructions.md"
Rewrite text clearly and concisely.
```

달리다`npx mastra dev`, open Studio, and select `writing-assistant` to test it.

### 검색 작동 방식 {/* #how-discovery-works */}

Mastra는 경로를 사용하여 파일 기반 기능을 검색하고 이름을 지정합니다. Agent 디렉터리는 기본 Agent를 제공합니다.`id` and `name`. For example, `tools/search_docs.ts` registers a tool as `search_docs`, while `skills/style-guide.md` registers a skill as `style-guide`. See the extension paths below.

### Agent 확장 {/* #extend-your-agent */}

Agent에 더 많은 기능이 필요할 때 파일이나 디렉터리를 추가하세요.

| 경로 | 추가되는 것 |
| - | - |
|[`tools/<tool-name>.ts`](/reference/file-based-agents/tools) | Functions the model can call |
| [`skills/<skill-name>.md`](/reference/file-based-agents/skills) | Detailed guidance the agent loads when relevant |
| [`memory.ts`](/reference/file-based-agents/memory) | Conversation history and working context |
| [`workspace.ts` and `workspace/`](/reference/file-based-agents/workspace) | Filesystem and shell access |
| [`subagents/<agent-id>/`](/reference/file-based-agents/subagents) | Specialist agents that the parent can delegate to |

각 기능을 사용하는 Agent 옆에 각 기능을 보관하세요. Mastra는 개발 서버가 시작되거나 다시 시작될 때 이러한 파일을 검색하고 등록합니다.

찾아보기[file-based agents reference](/reference/file-based-agents/config) for all supported file conventions and configuration options.
