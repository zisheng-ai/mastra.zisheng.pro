# Mastra 플랫폼 수출업체

그만큼`MastraPlatformExporter`추적, 로그, 메트릭, 점수 및 피드백을 Mastra 플랫폼으로 보냅니다. 이를 사용하여 Mastra 앱의 관측 가능성 데이터를 Mastra 플랫폼의 호스팅 프로젝트로 라우팅합니다.

:::메모

`MastraPlatformExporter`이전에 호출되었습니다`CloudExporter`. The original `CloudExporter`클래스는 여전히 다음에서 내보내집니다.`@mastra/observability`이전 버전과의 호환성을 위해 더 이상 사용되지 않습니다. 새로운 코드는 다음을 사용해야 합니다.`MastraPlatformExporter`.

:::

:::note\[자체 호스팅 또는 독립형 앱]

Mastra 플랫폼이 아닌 자체 인프라에서 Mastra 애플리케이션을 호스팅하는 경우에도 추적, 로그 및 지표를 보려면 배포된 Studio 프로젝트가 필요합니다.`MastraPlatformExporter` sends data to a Studio project, so one must exist before you can use it.

1. [마스트라 프로젝트 만들기](/guides/getting-started/quickstart)아직 가지고 있지 않다면.
2. [스튜디오 배포](/docs/studio/deployment#mastra-platform)Mastra 플랫폼으로`mastra studio deploy`.
3. 따라가다[quickstart steps below](#quickstart) to create an access token and find your project ID.

:::

## 버전 호환성 {/* #version-compatibility */}

* `MastraPlatformExporter`에서부터 사용 가능`@mastra/observability@1.12.0`. In `1.8.0` through `1.11.x` the same exporter includes only as `CloudExporter`. The constructor signature and environment variables are identical.
* \~ 안에`@mastra/observability@1.8.0` through `1.9.1`, set `MASTRA_PLATFORM_OBSERVABILITY_ENDPOINT=https://observability.mastra.ai` in addition to `MASTRA_PLATFORM_ACCESS_TOKEN` and `MASTRA_PROJECT_ID`.
* 에서 시작`@mastra/observability@1.9.2`, the exporter defaults to `https://observability.mastra.ai`, so `MASTRA_PLATFORM_OBSERVABILITY_ENDPOINT` is only required when you want to send telemetry to a different collector.

## 빠른 시작 {/* #quickstart */}

연결하려면`MastraPlatformExporter`, create an access token, find the destination `projectId`, and add the exporter to your observability config.

### 1. 액세스 토큰 생성 {/* #1-create-an-access-token */}

다음 명령을 실행하십시오.

```bash
mastra auth tokens create exporter-token
```

이 명령은 다음과 같이 사용할 수 있는 토큰 비밀을 인쇄합니다.`MASTRA_PLATFORM_ACCESS_TOKEN`.

이미 액세스 토큰이 있는 경우**Observability** value from the Mastra platform instead. You can find it in either of these places:

* 에**Projects** page, open the project list and find the **Observability** row on the project card.
* 프로젝트에**Overview** page, find the **Observability** row directly below the deployment URL.

토큰을 환경 변수로 설정합니다.

```bash title=".env"
MASTRA_PLATFORM_ACCESS_TOKEN=<your-platform-access-token>
```

### 2. 당신의 것을 찾으세요`projectId` {/* #2-find-your-projectid */}

다음 명령을 실행하십시오.

```bash
mastra studio deploy list
```

출력은 다음과 유사합니다.

```text
✅ <your-project-name> (<your-project-id>)
   Latest:   00000000-0000-0000-0000-000000000000 — running
   URL:      https://260407.studio.mastra.cloud
```

이 출력에서 ​​괄호 안의 값은`projectId`:

```text
<your-project-id>
```

환경 변수로 설정하십시오.

```bash title=".env"
MASTRA_PROJECT_ID=<your-project-id>
```

### 3. 환경 변수 설정 {/* #3-set-your-environment-variables */}

환경에서 두 값을 모두 설정하여`MastraPlatformExporter` can authenticate and route telemetry to the correct project:

```bash title=".env"
MASTRA_PLATFORM_ACCESS_TOKEN=<your-platform-access-token>
MASTRA_PROJECT_ID=<your-project-id>
```

당신이 사용하는 경우`@mastra/observability@1.8.0` through `1.9.1`, also set the Mastra platform collector explicitly:

```bash title=".env"
MASTRA_PLATFORM_OBSERVABILITY_ENDPOINT=https://observability.mastra.ai
```

Mastra 플랫폼이 아닌 다른 곳으로 원격 측정을 보내려면 다음을 설정하십시오.`MASTRA_PLATFORM_OBSERVABILITY_ENDPOINT` as well. Pass either a base origin or a full traces publish URL ending in `/spans/publish`.

```bash title=".env"
MASTRA_PLATFORM_OBSERVABILITY_ENDPOINT=https://collector.example.com
```

기본 원점을 통과하면`MastraPlatformExporter` derives the matching publish URLs for traces, logs, metrics, scores, and feedback automatically.

### 4. 활성화`MastraPlatformExporter` {/* #4-enable-mastraplatformexporter */}

다음 예에서는 추가하는 방법을 보여줍니다.`MastraPlatformExporter` to your observability config:

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability, MastraPlatformExporter } from '@mastra/observability'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      production: {
        serviceName: 'api-server',
        exporters: [new MastraPlatformExporter()],
      },
    },
  }),
})
```

세트`serviceName` on the observability config, not on `MastraPlatformExporter` itself.

마구간을 이용하세요`serviceName` value. In Studio, traces can be filtered by **Deployments → Service Name**, so a consistent name makes traces easier to find.

방문하다[Observability configuration reference](/reference/observability/tracing/configuration) for the full observability config shape.

원한다면 전적으로 환경 변수에 의존하세요.

```ts title="src/mastra/index.ts"
new MastraPlatformExporter()
```

와 함께`MASTRA_PLATFORM_ACCESS_TOKEN` and `MASTRA_PROJECT_ID` set, `MastraPlatformExporter` sends data to the Mastra platform project you configured. If you also set `MASTRA_PLATFORM_OBSERVABILITY_ENDPOINT`, it sends data to that collector instead. Visit [MastraPlatformExporter reference](/reference/observability/tracing/exporters/mastra-platform-exporter) for the full list of configuration options.

## 권장 구성 {/* #recommended-configuration */}

포함하다`MastraStorageExporter` if you also want to inspect local traces in Studio or persist observability data to your configured storage.

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import {
  Observability,
  MastraStorageExporter,
  MastraPlatformExporter,
  SensitiveDataFilter,
} from '@mastra/observability'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'mastra',
        exporters: [new MastraStorageExporter(), new MastraPlatformExporter()],
        spanOutputProcessors: [new SensitiveDataFilter()],
      },
    },
  }),
})
```

## 완전한 구성 {/* #complete-configuration */}

`MastraPlatformExporter`기본값은 Mastra 플랫폼입니다. 원격 분석을 다른 수집기로 보내려면 다음을 설정하세요.`MASTRA_PLATFORM_OBSERVABILITY_ENDPOINT` in your environment or pass `endpoint` in code.

```bash title=".env"
MASTRA_PLATFORM_OBSERVABILITY_ENDPOINT=https://collector.example.com
```

다음 예에서는 코드에서 수집기 끝점 및 일괄 처리 동작을 재정의하는 방법을 보여줍니다.

```ts title="src/mastra/index.ts"
new MastraPlatformExporter({
  endpoint: 'https://collector.example.com',
  maxBatchSize: 1000,
  maxBatchWaitMs: 5000,
  logLevel: 'info',
})
```

## Mastra Studio에서 데이터 보기 {/* #viewing-data-in-mastra-studio */}

활성화한 후`MastraPlatformExporter`, open your project in [Mastra Studio](https://projects.mastra.ai) to inspect the exported data.

* 설정한 프로젝트를 엽니다.`MASTRA_PROJECT_ID` to and select **Open Studio**.
* 스튜디오에서 다음으로 이동하세요.**Traces** to inspect agent and workflow traces.
* 필터 메뉴를 열고 사용하세요**Deployments → Service Name** to isolate traces from a specific app or deployment.
* 사용**Logs** page in the project dashboard to inspect exported logs.

Mastra Studio로 배포할 때 다음을 설정하세요.**Deployment → Service Name** to a stable value and keep it aligned with the `serviceName` in your observability config. This makes traces easier to filter in Studio through **Deployments → Service Name** when multiple services or deployments send data to the same project.

## 성능 {/* #performance */}

:::정보

MastraPlatformExporter는 일괄 처리를 사용하여 네트워크 사용을 최적화합니다. 이벤트는 버퍼링되어 일괄적으로 전송되므로 오버헤드가 줄어들고 거의 실시간 가시성이 유지됩니다.

:::

### 일괄 처리 동작 {/* #batching-behavior */}

* 이벤트는 다음까지 일괄 처리됩니다.`maxBatchSize` (default: 1000).
* 배치가 가득 차거나 그 이후에 전송됩니다.`maxBatchWaitMs` (default: 5 seconds).
* 실패한 배치는 지수 백오프를 통해 재시도됩니다.
* Mastra Studio에 연결할 수 없는 경우 내보내기 Tool의 성능이 정상적으로 저하됩니다.
