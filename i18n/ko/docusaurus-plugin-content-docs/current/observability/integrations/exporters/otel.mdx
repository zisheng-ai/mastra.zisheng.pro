# OpenTelemetry 내보내기

OpenTelemetry(OTEL) 내보내기는 표준화된 기술을 사용하여 모든 OTEL 호환 관찰 플랫폼에 추적 및 로그를 보냅니다.[OpenTelemetry Semantic Conventions for GenAI](https://opentelemetry.io/docs/specs/semconv/gen-ai/). 이를 통해 Datadog, New Relic, SigNoz, MLflow, Latitude, Dash0, Traceloop, Laminar, telemetry.dev 등과 같은 플랫폼과 광범위한 호환성이 보장됩니다.

:::info 양방향 OTEL 통합을 찾고 계십니까?

기존 OpenTelemetry 계측이 있고 Mastra 추적이 활성 OTEL 범위에서 컨텍스트를 상속하도록 하려면 다음을 참조하세요.[OpenTelemetry Bridge](/docs/observability/integrations/bridges/otel) instead.

:::

## 설치 {/* #installation */}

각 공급자에는 특정 프로토콜 패키지가 필요합니다. 기본 내보내기와 공급자용 프로토콜 패키지를 설치합니다.

### HTTP/Protobuf 공급자(SigNoz, New Relic, Laminar, MLflow, Latitude, telemetry.dev) {/* #for-httpprotobuf-providers-signoz-new-relic-laminar-mlflow-latitude-telemetrydev */}

```bash npm2yarn
npm install @mastra/otel-exporter@latest @opentelemetry/exporter-trace-otlp-proto
```

### 을 위한`gRPC` Providers (Dash0, Datadog) {/* #for-grpc-providers-dash0-datadog */}

```bash npm2yarn
npm install @mastra/otel-exporter@latest @opentelemetry/exporter-trace-otlp-grpc @grpc/grpc-js
```

### HTTP/JSON 공급자의 경우(Traceloop) {/* #for-httpjson-providers-traceloop */}

```bash npm2yarn
npm install @mastra/otel-exporter@latest @opentelemetry/exporter-trace-otlp-http
```

## 환경변수 {/* #environment-variables */}

모든 공급자는 환경 변수를 통해 제로 구성 설정을 지원합니다. 적절한 변수를 설정하면 내보내기가 자동으로 해당 변수를 사용합니다.

| 공급자 | 환경 변수 |
| - | - |
| 대시0 |`DASH0_API_KEY` (required), `DASH0_ENDPOINT` (required), `DASH0_DATASET` (optional) |
| SigNoz | `SIGNOZ_API_KEY` (required), `SIGNOZ_REGION` (optional), `SIGNOZ_ENDPOINT` (optional) |
| New Relic | `NEW_RELIC_LICENSE_KEY`(필수의),`NEW_RELIC_ENDPOINT`(선택사항) |
| 트레이스루프 |`TRACELOOP_API_KEY`(필수의),`TRACELOOP_DESTINATION_ID`, `TRACELOOP_ENDPOINT`(선택사항) |
| 층류 |`LMNR_PROJECT_API_KEY`(필수의),`LAMINAR_ENDPOINT`(선택사항) |

## 공급자 구성 {/* #provider-configurations */}

### MLflow {/* #mlflow */}

[MLflow](https://mlflow.org/docs/latest/genai/tracing/integrations/listing/mastra)OTLP 엔드포인트를 통해 기본 Mastra 추적을 지원합니다.`/v1/traces`. Use the `custom` provider with HTTP/Protobuf and include the experiment header so traces are routed to the correct MLflow experiment:

```typescript title="src/mastra/index.ts"
new OtelExporter({
  provider: {
    custom: {
      endpoint: `${process.env.MLFLOW_TRACKING_URI}/v1/traces`,
      protocol: 'http/protobuf',
      headers: {
        'x-mlflow-experiment-id': process.env.MLFLOW_EXPERIMENT_ID,
      },
    },
  },
})
```

### 위도 {/* #latitude */}

[위도](https://latitude.so)OTLP 추적을 수집하는 오픈 소스 LLM 관찰 및 평가 플랫폼입니다. 사용`custom` provider with HTTP/Protobuf, pointing at Latitude's ingestion endpoint and authenticating with your API key and project slug:

```typescript title="src/mastra/index.ts"
new OtelExporter({
  provider: {
    custom: {
      endpoint: 'https://ingest.latitude.so/v1/traces',
      protocol: 'http/protobuf',
      headers: {
        Authorization: `Bearer ${process.env.LATITUDE_API_KEY}`,
        'X-Latitude-Project': process.env.LATITUDE_PROJECT,
      },
    },
  },
})
```

다음에서 가입하세요[console.latitude.so](https://console.latitude.so/login), or self-host and point the endpoint at your own ingestion host.

### 원격 측정.dev {/* #telemetrydev */}

[원격 측정.dev](https://telemetry.dev)OTLP/HTTP protobuf 추적을 수집하고 OpenTelemetry GenAI 의미 체계 규칙을 Model, 공급자, 토큰, 대기 시간 및 비용 필드로 정규화합니다. 사용`custom` provider with your project API key:

```bash title=".env"
TELEMETRY_DEV_API_KEY=td_live_...
```

```typescript title="src/mastra/index.ts"
new OtelExporter({
  provider: {
    custom: {
      endpoint: 'https://ingest.telemetry.dev/v1/traces',
      protocol: 'http/protobuf',
      headers: {
        Authorization: `Bearer ${process.env.TELEMETRY_DEV_API_KEY}`,
      },
    },
  },
})
```

### 대시0 {/* #dash0 */}

[대시0](https://www.dash0.com/)자동 통찰력으로 실시간 Observability을 제공합니다.

#### 제로 구성 설정 {/* #zero-config-setup */}

환경 변수를 설정하고 빈 구성으로 내보내기를 사용합니다.

```bash title=".env"
# Required
DASH0_API_KEY=your-api-key
DASH0_ENDPOINT=ingress.us-west-2.aws.dash0.com:4317

# Optional
DASH0_DATASET=production
```

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { OtelExporter } from '@mastra/otel-exporter'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      otel: {
        serviceName: 'my-service',
        exporters: [new OtelExporter({ provider: { dash0: {} } })],
      },
    },
  }),
})
```

#### 명시적 구성 {/* #explicit-configuration */}

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { OtelExporter } from '@mastra/otel-exporter'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      otel: {
        serviceName: 'my-service',
        exporters: [
          new OtelExporter({
            provider: {
              dash0: {
                apiKey: process.env.DASH0_API_KEY,
                endpoint: process.env.DASH0_ENDPOINT, // e.g., 'ingress.us-west-2.aws.dash0.com:4317'
                dataset: 'production', // Optional dataset name
              },
            },
            resourceAttributes: {
              // Optional OpenTelemetry Resource Attributes for the trace
              ['deployment.environment']: 'dev',
            },
          }),
        ],
      },
    },
  }),
})
```

:::정보

대시보드에서 Dash0 엔드포인트를 가져옵니다. 형식으로 되어 있어야 합니다.`ingress.{region}.aws.dash0.com:4317`.

:::

### 데이터독 {/* #datadog */}

[데이터독](https://www.datadoghq.com/)APM은 분산 추적을 통해 애플리케이션 성능 모니터링을 제공합니다. OTLP를 통해 Datadog에 추적을 보내려면 OTLP 수집이 활성화된 상태에서 실행되는 Datadog Agent가 필요합니다.

Datadog은 OTLP 수집을 위해 gRPC를 사용합니다. 이를 위해서는 명시적 가져오기 및[bundler configuration](/reference/configuration#bundlerexternals) to work correctly:

```typescript title="src/mastra/index.ts"
// Explicitly import gRPC dependencies for the bundler
import '@grpc/grpc-js'
import '@opentelemetry/exporter-trace-otlp-grpc'
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { OtelExporter, type ExportProtocol } from '@mastra/otel-exporter'

export const mastra = new Mastra({
  // Add grpc-js to externals so it's handled at runtime
  bundler: {
    externals: ['@grpc/grpc-js'],
  },
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-service',
        exporters: [
          new OtelExporter({
            provider: {
              custom: {
                endpoint: process.env.OTEL_EXPORTER_OTLP_ENDPOINT || 'http://localhost:4317',
                protocol: (process.env.OTEL_EXPORTER_OTLP_PROTOCOL || 'grpc') as ExportProtocol,
                headers: {},
              },
            },
          }),
        ],
      },
    },
  }),
})
```

:::정보

Datadog Agent는 OTLP 수집이 활성화된 상태로 구성되어야 합니다. 다음을 추가하세요.`datadog.yaml`:

```yaml
otlp_config:
  receiver:
    protocols:
      grpc:
        endpoint: 0.0.0.0:4317
```

기본 OTLP 엔드포인트는 다음과 같습니다.`http://localhost:4317` when running the Datadog Agent locally.

:::

:::경고

명시적인 수입`@grpc/grpc-js` and `@opentelemetry/exporter-trace-otlp-grpc` at the top of the file, along with the [`bundler.externals`](/reference/configuration#bundlerexternals) configuration, are required for the gRPC transport to work correctly. Without these, you may encounter connection issues.

:::

:::tip Datadog 네이티브 내보내기

자동 범위 유형 매핑, LLM 범위 분류, gRPC 구성 없이 단순화된 설정과 같은 Datadog 관련 기능의 경우 전용[`@mastra/datadog`](/docs/observability/integrations/exporters/datadog) exporter instead. It provides optimized integration with Datadog's APM platform.

:::

## 신호 {/* #signals */}

내보내기는 두 개의 OpenTelemetry 신호를 보냅니다.

* 추적: 다음을 통해 내보낸 Mastra 스팬`BatchSpanProcessor`.
* 로그: 다음을 통해 내보낸 Mastra 로그 이벤트`BatchLogRecordProcessor`. Logs that carry `traceId` and `spanId` are correlated with traces using both the OTEL log record's native trace context and `mastra.traceId` / `mastra.spanId` attributes, so backends like Datadog, Grafana, and Honeycomb can join logs to traces automatically.

두 신호 모두 기본적으로 활성화되어 있으며 동일한 공급자 구성을 공유합니다. 로그 엔드포인트는 추적 엔드포인트에서 파생됩니다.`/v1/traces` suffix with `/v1/logs`.

신호를 비활성화하려면`signals` option:

```typescript title="src/mastra/index.ts"
new OtelExporter({
  provider: {/* ... */},
  signals: {
    traces: true, // default
    logs: false, // disable log export
  },
})
```

로그를 내보내려면 프로토콜에 맞는 OTLP 로그 내보내기 패키지를 설치해야 합니다.

```bash npm2yarn
# HTTP/JSON
npm install @opentelemetry/exporter-logs-otlp-http
# HTTP/Protobuf
npm install @opentelemetry/exporter-logs-otlp-proto
# gRPC
npm install @opentelemetry/exporter-logs-otlp-grpc @grpc/grpc-js
```

일치하는 로그 내보내기 패키지가 설치되어 있지 않으면 로그 내보내기가 자동으로 비활성화되고 추적이 계속 작동합니다.

## 구성 옵션 {/* #configuration-options */}

### 완전한 구성 {/* #complete-configuration */}

```typescript
new OtelExporter({
  // Provider configuration (required)
  provider: {
    // Use one of: dash0, signoz, newrelic, traceloop, laminar, custom
  },

  // Per-signal toggles. Both default to true.
  signals: {
    traces: true,
    logs: true,
  },

  // Export configuration
  timeout: 30000, // Export timeout in milliseconds
  batchSize: 100, // Number of spans/logs per batch

  // Debug options
  logLevel: 'info', // 'debug' | 'info' | 'warn' | 'error'
})
```

## `OpenTelemetry`의미론적 규칙 {/* #opentelemetry-semantic-conventions */}

수출자는 다음과 같습니다[OpenTelemetry Semantic Conventions for GenAI v1.38.0](https://github.com/open-telemetry/semantic-conventions/tree/v1.38.0/docs/gen-ai), ensuring compatibility with observability platforms:

### 스팬 이름 지정 {/* #span-naming */}

* **LLM 운영**: `chat {model}`
* **Tool 실행**: `execute_tool {tool_name}`
* **Agent 실행**: `invoke_agent {agent_id}`
* **Workflow 실행**: `invoke_workflow {workflow_id}`

### 주요 속성 {/* #key-attributes */}

* `gen_ai.operation.name`- 작업 유형(채팅, Tool.실행 등)
* `gen_ai.provider.name`- AI 제공자(openai, Anthropic 등)
* `gen_ai.request.model`- Model 식별자
* `gen_ai.input.messages`- Model에게 제공되는 채팅 기록
* `gen_ai.output.messages`- Model이 반환한 메시지
* `gen_ai.usage.input_tokens`- 입력 토큰 수
* `gen_ai.usage.output_tokens`- 출력 토큰 수
* `gen_ai.request.temperature`- 샘플링 온도
* `gen_ai.response.finish_reasons`- 완료 이유

## 프로토콜 선택 가이드 {/* #protocol-selection-guide */}

공급자에 따라 올바른 프로토콜 패키지를 선택하십시오.

| 공급자 | 프로토콜 | 필수 패키지 |
| - | - | - |
| 대시0 | gRPC |`@opentelemetry/exporter-trace-otlp-grpc` |
| Datadog | gRPC | `@opentelemetry/exporter-trace-otlp-grpc` |
| SigNoz | HTTP/Protobuf | `@opentelemetry/exporter-trace-otlp-proto` |
| New Relic | HTTP/Protobuf | `@opentelemetry/exporter-trace-otlp-proto` |
| Traceloop | HTTP/JSON | `@opentelemetry/exporter-trace-otlp-http` |
| Laminar | HTTP/Protobuf | `@opentelemetry/exporter-trace-otlp-proto` |
| Custom | Varies | Depends on your collector |

:::경고

공급자에 맞는 올바른 프로토콜 패키지를 설치했는지 확인하세요. 잘못된 패키지가 설치된 경우 내보내기 프로그램에서 유용한 오류 메시지를 제공합니다.

:::

## 문제 해결 {/* #troubleshooting */}

### 누락된 종속성 오류 {/* #missing-dependency-error */}

다음과 같은 오류가 표시되는 경우:

```
HTTP/Protobuf exporter is not installed (required for signoz).
To use HTTP/Protobuf export, install the required package:
  npm install @opentelemetry/exporter-trace-otlp-proto
```

공급자에게 제안된 패키지를 설치합니다.

### 일반적인 문제 {/* #common-issues */}

1. **잘못된 프로토콜 패키지**: 공급자에 맞는 내보내기 프로그램을 설치했는지 확인하세요.
2. **잘못된 엔드포인트**: 엔드포인트 형식이 공급자 요구 사항과 일치하는지 확인하세요.
3. **인증 실패**: API 키와 헤더가 올바른지 확인하세요.
