# 통합 개요

Mastra 관측 가능성 통합은 관측 가능성 데이터가 이동하는 위치와 나가는 동안 변환되는 방식을 제어합니다. 통합을 사용하여 데이터를 Mastra 스토리지에 저장하고, 이를 Mastra 플랫폼으로 전송하고, 외부 관찰 제공자에 연결하거나, 내보낸 범위 데이터를 수정합니다.

## 통합을 사용해야 하는 경우 {/* #when-to-use-integrations */}

* 다음을 사용하여 Studio에서 Observability을 유지하세요.`MastraStorageExporter`.
* 다음을 사용하여 호스팅된 관측 가능성 데이터를 Mastra 플랫폼으로 보냅니다.`MastraPlatformExporter`.
* Datadog, Langfuse 또는 OpenTelemetry 백엔드와 같은 외부 공급자로 추적을 전달합니다.
* 런타임을 종료하기 전에 민감한 값을 수정하세요.

## 통합 경로 선택 {/* #choose-an-integration-path */}

* Studio Workflow: 다음으로 시작[Mastra Storage](/docs/observability/integrations/exporters/mastra-storage).
* 호스팅된 Mastra Workflow: 추가[Mastra platform](/docs/observability/integrations/exporters/mastra-platform).
* 외부 Observability 스택: 사이드바 아래에서 하나 이상의 내보내기 페이지를 선택합니다.`Exporters` section.
* 기존 분산 추적 컨텍스트: 브리지를 사용한 다음 필요에 따라 내보내기를 추가합니다.

## 수출업체 {/* #exporters */}

내보내기는 관측 가능성 데이터를 대상으로 보냅니다.

* [마스트라 스토리지](/docs/observability/integrations/exporters/mastra-storage): Studio에 대한 관측 가능성 데이터를 유지합니다.
* [마스트라 플랫폼](/docs/observability/integrations/exporters/mastra-platform): 호스팅된 관측 가능성 데이터를 Mastra 플랫폼으로 보냅니다.
* 외부 공급자: Datadog, Langfuse, OpenTelemetry 및 기타 지원되는 플랫폼에 대한 내보내기 페이지를 사용합니다.

## 교량 {/* #bridges */}

브리지는 Mastra를 기존 분산 추적 컨텍스트에 연결합니다.

* [OpenTelemetry 브리지](/docs/observability/integrations/bridges/otel): Mastra를 기존 OpenTelemetry 추적과 통합합니다.
* [데이터독 브릿지](/docs/observability/integrations/bridges/datadog): Mastra 추적을 Datadog 및 해당 LLM Observability 제품으로 보냅니다.

## 프로세서 {/* #processors */}

프로세서는 내보내기 전에 범위를 변환하거나 수정합니다.

* [민감한 데이터 필터](/docs/observability/integrations/processors/sensitive-data-filter): 범위가 런타임을 종료하기 전에 민감한 필드를 수정합니다.
