# 편집자

편집기는 Mastra Agent의 CMS처럼 작동합니다. 공동작업자는 코드베이스에 액세스하거나 코드를 작성하지 않고도 Studio에서 상담사의 지침과 Tool를 변경할 수 있습니다. 변경 사항을 적용하기 전에 테스트할 수 있습니다.

TypeScript는 Agent의 기본값을 정의합니다. 편집기는 소스 코드를 업데이트하는 대신 변경 사항을 별도로 저장하므로 공동 작업자는 Agent를 개선하는 동시에 개발자는 Model, ID 및 런타임에 대한 제어권을 유지할 수 있습니다.

에이[deployed Studio](/docs/studio/deployment) makes Editor available to collaborators outside local development.

## 편집기를 사용하는 경우 {/* #when-to-use-editor */}

Agent가 코드에 정의되어 있지만 해당 동작을 담당하는 사람이 코드베이스를 편집하면 안 되는 경우 편집기를 사용하세요. 지침이나 Tool가 자주 변경되고 사용자에게 도달하기 전에 테스트가 필요한 경우에 효과적입니다. 개발자가 애플리케이션의 모든 변경 사항 및 릴리스 Agent 구성을 소유한 경우[agent configuration in code](/docs/agents/overview) instead.

## 빠른 시작 {/* #quickstart */}

설치하다`@mastra/editor`. This quickstart uses LibSQL to store Editor changes:

```bash npm2yarn
npm install @mastra/editor @mastra/libsql
```

추가하다`MastraEditor` and storage to the `Mastra` instance. Existing storage can be reused instead of adding the LibSQL store shown here.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraEditor } from '@mastra/editor'
import { LibSQLStore } from '@mastra/libsql'

export const mastra = new Mastra({
  agents: {/* existing agents */},
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: 'file:./mastra.db',
  }),
  editor: new MastraEditor(),
})
```

## Studio에서 편집기 사용 {/* #use-editor-in-studio */}

\~ 안에[Studio](/docs/studio/overview), open **Agents**, select an agent, then select **Editor**. Collaborators can update the agent's instructions and tools based on its Editor permissions.

데이터베이스 스토리지를 사용하면 변경 사항을 초안으로 저장하여 라이브 Agent에 영향을 주지 않고 테스트할 수 있습니다. 사용할 준비가 되면 초안을 게시하세요.

## 지침 {/* #instructions */}

그만큼**Instructions** section shows the agent's system prompt defined in code. Collaborators can override it or add instruction blocks.

명령 블록에는 현재 요청의 값이 포함될 수 있습니다. 예를 들어,<code>{'{{userName}}'}</code> inserts a name supplied through [request context](/docs/server/request-context). A [display condition](/reference/editor/prompt-blocks#display-conditions) can show a block only for a customer, role, or feature flag.

### Prompt 블록 {/* #prompt-blocks */}

Prompt 블록은 둘 이상의 Agent이 사용할 수 있는 저장된 지침 텍스트입니다. 아래에 하나를 만드세요.**Prompts**, publish it, then open an agent's **Instructions** section and select **Add block**.

예를 들어 지원 Agent, 반품 Agent, 주문 상태 Agent 모두 동일한 환불 정책이 필요할 수 있습니다. 정책을 Prompt 블록으로 저장하고 각 Agent에 추가합니다. 정책이 변경되면 Agent 3개를 편집하는 대신 블록을 한 번 업데이트하고 게시합니다.

Prompt 블록이 변경되면 게시된 버전을 참조하는 모든 Agent가 업데이트를 받습니다. 초안 변경 사항은 미리 보는 동안에만 사용되므로 블록이 게시될 때까지 라이브 Agent에 영향을 주지 않습니다.

참조[prompt blocks reference](/reference/editor/prompt-blocks) for template syntax, conditions, versions, and APIs.

## Tool {/* #tools */}

Tool를 사용하면 Agent이 조치를 취할 수 있습니다. 공동작업자는 Editor에서 사용할 수 있는 Tool 중에서 선택하지만 Studio에서 새로운 Tool를 구현할 수는 없습니다. Tool를 사용할 수 있는 방법은 해당 소스에 따라 다릅니다.

* **프로젝트 Tool**개발자가 Mastra 프로젝트에 구현하고 등록해야 합니다.
* **통합 Tool**개발자가 Composio 또는 Arcade와 같은 공급자를 등록한 후에 사용할 수 있습니다. 그런 다음 공동 작업자는 공급자의 카탈로그를 찾아보고 각 Tool를 코드에 먼저 추가하지 않고도 Tool를 추가할 수 있습니다.
* **MCP Tool**MCP 클라이언트가 구성되면 사용할 수 있게 됩니다. 액세스 권한이 있는 공동작업자는 Studio에서 클라이언트를 생성한 다음 서버에서 제공하는 Tool 중에서 선택할 수 있습니다.

대리인의 경우**Tools** section, collaborators can add the tools it needs or rewrite a tool's description for that agent. A more specific description helps the agent understand when to use the tool without changing the tool itself.

### 프로젝트 Tool {/* #project-tools */}

개발자는 프로젝트 Tool를 다음 사이트에 등록할 수 있습니다.`Mastra` instance to make it available in Editor:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraEditor } from '@mastra/editor'
import { searchOrders } from './tools/search-orders'

export const mastra = new Mastra({
  tools: {
    searchOrders,
  },
  agents: {/* agents */},
  editor: new MastraEditor(),
})
```

Studio Tool 선택기에 Tool가 나열됩니다. 공동작업자는 Agent가 Tool 편집을 허용하는 경우 해당 Agent에 이를 추가할 수 있습니다. Agent의 편집기 보기에는 코드에 연결된 Tool도 나열됩니다.

### 작곡 {/* #composio */}

[작곡](https://composio.dev)GitHub, Slack, Gmail과 같은 서비스를 위한 Tool를 제공합니다. Composio API 키로 공급자를 등록하여 편집기에서 Tool 카탈로그를 사용할 수 있도록 합니다.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraEditor } from '@mastra/editor'
import { ComposioToolProvider } from '@mastra/editor/composio'

export const mastra = new Mastra({
  agents: {/* agents */},
  editor: new MastraEditor({
    toolProviders: {
      composio: new ComposioToolProvider({
        apiKey: process.env.COMPOSIO_API_KEY!,
      }),
    },
  }),
})
```

Composio Tool ID는 다음과 같습니다.`GITHUB_CREATE_ISSUE`. By default, a selected tool uses the connection associated with the agent's author. See [connection scope](https://agent-builder.mastra.ai/tool-providers#connection-scope) to use each caller's connection instead.

### 아케이드 {/* #arcade */}

[아케이드](https://arcade.dev)인증이 내장된 또 다른 Tool 카탈로그를 제공합니다. Arcade API 키로 등록하세요.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraEditor } from '@mastra/editor'
import { ArcadeToolProvider } from '@mastra/editor/arcade'

export const mastra = new Mastra({
  agents: {/* agents */},
  editor: new MastraEditor({
    toolProviders: {
      arcade: new ArcadeToolProvider({
        apiKey: process.env.ARCADE_API_KEY!,
      }),
    },
  }),
})
```

아케이드 Tool ID 사용`Toolkit.ToolName` format, such as `Github.GetRepository`.

### MCP 클라이언트 {/* #mcp-clients */}

공동작업자는 Studio에서 재사용 가능한 MCP 클라이언트를 생성하고 해당 Tool를 Agent에 추가할 수도 있습니다. 저장된 클라이언트는 로컬을 시작할 수 있습니다`stdio` server or connect to a remote HTTP server. Tool filters let each agent use only the tools it needs from that server.

참조[Editor tools reference](/reference/editor/tools) for MCP configuration, conditions, filtering, and resolution order. See [`ToolProvider`](/reference/editor/tool-provider) for provider options.

## 공동작업자가 편집할 수 있는 항목 결정 {/* #decide-what-collaborators-can-edit */}

기본적으로 공동작업자는 Agent의 지침을 변경하고 설명을 포함한 Tool를 관리할 수 있습니다. 대리인의`id`, `name`, and `model` always come from code.

대리인의 것을 이용하세요.`editor` field to limit what can be changed:

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support agent',
  instructions: 'Help customers with Acme products.',
  model: '__GATEWAY_OPENAI_MODEL__',
  editor: {
    instructions: true,
    tools: {
      description: true,
    },
  },
})
```

이 Agent를 사용하면 공동작업자는 지침을 변경하고 이미 연결된 Tool의 설명을 개선할 수 있습니다. Tool를 추가하거나 제거할 수 없습니다.

| `editor` value | What collaborators can change |
| - | - |
| Omitted | Instructions, tools, and tool descriptions |
| `false` | Nothing |
| `{ instructions: true }` | Instructions |
| `{ tools: true }` | Tools and tool descriptions |
| `{ tools: { description: true } }` | Descriptions of tools already added in code |

Studio에서는 다른 모든 항목이 읽기 전용으로 표시됩니다. 보다[editor overrides](/reference/agents/agent#editor-overrides) for the complete configuration.

## 변경 사항이 저장되는 위치 선택 {/* #choose-where-changes-are-stored */}

편집자는 구성된 데이터베이스에 변경 사항을 저장하거나 저장소에 파일로 저장할 수 있습니다.

### 데이터베이스 스토리지 {/* #database-storage */}

데이터베이스 옵션이 기본값입니다. 편집기는 다음에 구성된 저장소를 사용합니다.`Mastra` instance, so the application and Editor can share the same backend.

Editor 데이터에 별도의 백엔드를 사용하려면`editor` option on [`MastraCompositeStore`](/reference/storage/composite#options). Storage domains without an explicit route continue to use its `default` store.

다음 예에서는 애플리케이션 및 편집기 데이터를 별도의 LibSQL 파일에 보관합니다.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraCompositeStore } from '@mastra/core/storage'
import { MastraEditor } from '@mastra/editor'
import { LibSQLStore } from '@mastra/libsql'

export const mastra = new Mastra({
  agents: {/* existing agents */},
  storage: new MastraCompositeStore({
    id: 'mastra-storage',
    default: new LibSQLStore({
      id: 'app-storage',
      url: 'file:./mastra.db',
    }),
    editor: new LibSQLStore({
      id: 'editor-storage',
      url: 'file:./editor.db',
    }),
  }),
  editor: new MastraEditor(),
})
```

### 저장소 파일 {/* #repository-files */}

코드 소스를 사용하여 애플리케이션 코드와 함께 재정의를 유지합니다. 개발자는 풀 요청의 파일을 검토하고 애플리케이션과 함께 배포할 수 있습니다.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraEditor } from '@mastra/editor'

export const mastra = new Mastra({
  agents: {/* existing agents */},
  editor: new MastraEditor({
    source: 'code',
    codePath: './mastra/editor',
  }),
})
```

이 모드에서는 편집된 각 Agent에 하나의 JSON 재정의 파일이 있습니다. 편집기는 TypeScript를 생성하거나 Agent가 생성된 파일을 변경하지 않습니다. 기본적으로 ID가 있는 Agent는`support-agent` gets this file:

```text
mastra/editor/agents/support-agent.json
```

파일에는 Editor에서 관리하는 부분만 포함되어 있습니다. 예를 들어:

```json title="mastra/editor/agents/support-agent.json"
{
  "instructions": "Help customers with Acme products and answer in their language.",
  "tools": {
    "searchOrders": {
      "description": "Look up an order by its number"
    }
  }
}
```

Agent의 Model, 이름 및 기타 코드 소유 필드는 TypeScript 파일에 유지됩니다. Mastra는 JSON을 읽고 Agent가 실행될 때 이러한 값을 적용합니다.

공동작업자가 Studio에 저장할 때 파일을 로컬 파일 시스템에 쓰거나 다운로드할 수 있습니다. 소스 제어 통합을 통해 Studio는 대신 풀 요청을 열 수 있습니다. 그런 다음 Git은 검토 및 버전 기록을 제공합니다.

보다[`MastraEditor`](/reference/editor/mastra-editor#source) for file locations and source options.

## 버전 관리 {/* #versioning */}

데이터베이스 지원 Agent와 Prompt 블록은 초안 및 게시된 버전을 사용합니다. 저장하면 라이브 Agent가 게시된 버전을 계속 사용하는 동안 초안이 생성됩니다. 게시하면 초안이 게시됩니다. 이전 버전을 복원하면 공동작업자가 게시하기 전에 테스트할 수 있는 초안이 생성됩니다.

코드 지원 Agent 재정의에서는 JSON 파일과 Git 기록을 사용합니다.

### 버전을 선택하세요 {/* #select-a-version */}

애플리케이션은 상태(`published` or `draft`) or an exact version ID:

```typescript title="Version selection"
const publishedAgent = await mastra.getAgentById('support-agent', {
  status: 'published',
})

const draftAgent = await mastra.getAgentById('support-agent', {
  status: 'draft',
})

const versionedAgent = await mastra.getAgentById('support-agent', {
  versionId: 'abc-123',
})
```

버전 선택은 다음을 지원합니다.

* A/B 테스트에서 두 버전을 비교합니다.
* 모든 사람을 위해 게시하기 전에 소규모 그룹에 초안을 제공하세요.
* 스테이징에서 최신 초안을 사용하는 동안 게시된 버전으로 프로덕션을 유지하세요.
* 고객을 특정 버전에 고정합니다.

감독자가 하위 Agent를 호출할 때도 동일한 버전 제어가 작동합니다. 개발자는 시스템의 나머지 부분을 변경하지 않고도 초안 하위 Agent를 테스트할 수 있습니다.

참조[Editor versioning reference](/reference/editor/versioning) for version selection, sub-agent behavior, REST endpoints, and SDK methods.

## 프로그래밍 방식의 액세스 {/* #programmatic-access */}

Studio에서 사용할 수 있는 모든 것은 다음을 통해 프로그래밍 방식으로도 사용할 수 있습니다.[`mastra.getEditor()`](/reference/core/getEditor), the REST API, or the Client SDK. Use it to script bulk updates or seed stored configurations from code. It can also power automation that tunes agents based on [evaluation results](/docs/datasets/running-experiments).

부르다`mastra.getEditor()` when application code has access to the Mastra instance:

```typescript title="src/scripts/update-agent.ts"
import { mastra } from '../mastra'

const editor = mastra.getEditor()!

await editor.agent.update({
  id: 'support-agent',
  instructions: 'Help customers with Acme products. Reply in their language.',
})
```

직접`editor.agent.update()` method activates the new version immediately. To create a draft without changing the live agent, use the stored-agent REST API or Client SDK instead:

```bash title="Create a draft through the REST API"
curl -X PATCH http://localhost:4111/api/stored/agents/support-agent \
  -H "Content-Type: application/json" \
  -d '{
    "instructions": "Help customers with Acme products. Reply in their language."
  }'
```

기본 서버 접두사는 다음과 같습니다.`/api`. Developers can set a custom prefix in the server configuration.

참조[`MastraEditor` namespaces](/reference/editor/mastra-editor#namespaces) and [Client SDK agents API](/reference/client-js/agents#stored-agents) for available operations.
