# 배포 개요

Mastra 애플리케이션은 Node.js 호환 환경에 배포할 수 있습니다. Mastra 서버를 배포하거나, 기존 웹 프레임워크와 통합하거나, 클라우드 공급자에 배포하거나,[Mastra platform](/docs/mastra-platform/overview)Observability, Studio 및 서버 배포를 위해.

## 런타임 지원 {/* #runtime-support */}

Mastra는 다음 런타임 환경에 대해 실행할 수 있습니다.

* Node.js `v22.13.0` 이상
* Bun
* Deno
* Cloudflare
## 배포 옵션 {/* #deployment-options */}

### 마스트라 서버 {/* #mastra-server */}

Mastra는 독립적으로 배포할 수 있는 Hono 기반 [서버](/docs/server/mastra-server)를 제공합니다. `mastra build` 명령으로 애플리케이션을 빌드하고 결과물을 원하는 VM, 컨테이너 또는 PaaS 플랫폼에 배포하세요.
인프라, 장기 실행 프로세스 또는 WebSocket 연결에 대한 완전한 제어가 필요한 경우 이 옵션을 사용하십시오. 그만큼[Mastra server deployment guide](/docs/deployment/mastra-server) provides more details.

### 모노레포 {/* #monorepo */}

독립 실행형 배포와 동일한 접근 방식에 따라 Monorepo 설정의 일부로 Mastra 서버를 배포합니다.

읽어보기[monorepo deployment](/docs/deployment/monorepo).

### 마스트라 플랫폼 {/* #mastra-platform */}

[Mastra 플랫폼](/docs/mastra-platform/overview)은 Mastra 프레임워크로 구축한 AI 애플리케이션을 배포, 모니터링, 관리하기 위한 세 가지 제품을 제공합니다.
* [**Observability**](/docs/mastra-platform/observability): Mastra 프로젝트 및 배포 전반에 걸쳐 검색 가능한 추적, 로그 및 메트릭을 위한 독립형 호스팅 제품
* [**사진관**](/docs/mastra-platform/studio): Agent 테스트, Workflow 실행, 추적 검사를 위한 호스팅된 시각적 환경
* [**섬기는 사람**](/docs/mastra-platform/server): Mastra 애플리케이션을 API 서버로 실행하는 프로덕션 배포 대상

자세한 내용은 다음에서 확인하세요.[Mastra platform overview](/docs/mastra-platform/overview).

### 클라우드 Provider {/* #cloud-providers */}

Mastra 애플리케이션은 클라우드 Provider 및 서버리스 플랫폼에 배포될 수 있습니다. Mastra에는 빌드 및 배포 프로세스를 자동화하기 위한 Vercel, Netlify 및 Cloudflare용 기본 제공 배포자가 선택적으로 포함되어 있습니다.

자동 크기 조정, 최소한의 인프라 관리를 위해 또는 이미 이러한 플랫폼 중 하나를 사용하고 있는 경우 이 옵션을 사용하세요.

* [아마존 EC2](/guides/deployment/amazon-ec2)
* [AWS 람다](/guides/deployment/aws-lambda)
* [Azure 앱 서비스](/guides/deployment/azure-app-services)
* [클라우드플레어](/guides/deployment/cloudflare)
* [디지털 오션](/guides/deployment/digital-ocean)
* [쿠버네티스](/guides/deployment/kubernetes)
* [넷티파이](/guides/deployment/netlify)
* [베르셀](/guides/deployment/vercel)

### 모래 상자 {/* #sandbox */}

Mastra 서버를 임시 작업 공간 샌드박스(예: Vercel Sandbox 또는 E2B)에 배포하고 몇 초 만에 라이브 공개 URL을 받으세요.

즉시 미리 보기, CI 파이프라인에서 배포, Agent 구축 앱 확인 또는 신뢰할 수 없는 사용자별 인스턴스 실행에 이 옵션을 사용하세요. 읽기[sandbox deployment guide](/docs/deployment/sandbox).

### 웹 프레임워크 {/* #web-framework */}

Mastra가 웹 프레임워크와 통합되면 프레임워크의 표준 배포 프로세스를 사용하여 애플리케이션과 함께 배포됩니다. 아래 가이드에서는 배포를 위한 프레임워크별 구성 요구 사항을 다룹니다.

기존 Next.js 또는 Astro 애플리케이션에 Mastra를 추가할 때 이 가이드를 사용하세요.

* [Vercel의 Next.js 사용](/docs/deployment/web-framework#with-nextjs-on-vercel)
* [Vercel에서 Astro와 함께](/docs/deployment/web-framework#with-astro-on-vercel)
* [Astro와 함께 Netlify에서](/docs/deployment/web-framework#with-astro-on-netlify)

## Workflow 실행자 {/* #workflow-runners */}

Mastra Workflow는 기본적으로 내장 실행 엔진에서 실행됩니다. 관리형 인프라가 필요한 프로덕션 워크로드에서는 단계 메모이제이션, 자동 재시도, 실시간 모니터링을 제공하는 [Inngest](https://www.inngest.com) 같은 전문 플랫폼에 Workflow를 배포할 수도 있습니다.
실행 옵션은 [Workflow Runner 가이드](/docs/deployment/workflow-runners)를, 설정 지침은 [Inngest 배포 가이드](/guides/deployment/inngest)를 참조하세요.
## 노동자 {/* #workers */}

프로덕션 배포에서 Mastra는 Workflow 조정, 크론 예약, 백그라운드 Tool 실행을 API 서버와 분리된 전용 워커 프로세스에서 실행할 수 있습니다. 따라서 각 작업을 독립적으로 확장하고 오류를 격리할 수 있습니다. 자세한 내용은 [워커](/docs/deployment/workers)를 참조하세요.
