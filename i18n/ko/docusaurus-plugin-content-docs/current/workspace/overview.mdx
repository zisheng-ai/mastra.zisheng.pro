# 작업공간

**추가된 항목:** `@mastra/core@1.1.0`

Mastra 작업 공간은 Agent에 파일 저장 및 명령 실행을 위한 지속적인 환경을 제공합니다. Agent는 작업 공간 Tool를 사용하여 파일을 읽고 쓰고 셸 명령을 실행하며 색인된 콘텐츠를 검색합니다.

작업공간은 다음 기능을 지원합니다.

* **[파일 시스템](/docs/workspace/filesystem)**: 파일 저장(읽기, 쓰기, 나열, 삭제, 복사, 이동, grep)
* **[모래 상자](/docs/workspace/sandbox)**: 명령 실행(셸 명령) 및 백그라운드 프로세스
* **[LSP 검사](/docs/workspace/lsp)**: 언어 서버를 통한 호버, 정의, 구현 쿼리
* **[찾다](/docs/workspace/search)**: 색인화된 콘텐츠에 대한 BM25, 벡터 또는 하이브리드 검색
* **[기술](/docs/workspace/skills)**: Agent를 위한 재사용 가능한 지침

## 작업공간을 사용해야 하는 경우 {/* #when-to-use-workspaces */}

Agent가 로컬 파일 시스템, 셸 명령, 의미 체계 코드 검사, 색인 검색 또는 재사용 가능한 기술 지침에 액세스해야 하는 경우 작업 영역을 사용하세요.

## 작동 원리 {/* #how-it-works */}

Agent에 작업 영역을 할당하면 Mastra는 Agent Tool 세트에 해당 Tool를 포함합니다. 그런 다음 Agent는 이러한 Tool를 사용하여 파일과 상호 작용하고 명령을 실행할 수 있습니다.

지원되는 기능을 원하는 대로 조합하여 작업 공간을 만들 수 있습니다. Agent는 구성된 것과 관련된 Tool만 ​​받습니다.

## 용법 {/* #usage */}

### 작업공간 만들기 {/* #creating-a-workspace */}

인스턴스화하여 작업 공간을 만듭니다.`Workspace` class with your desired features:

```typescript title="src/mastra/workspaces.ts"
import { Workspace, LocalFilesystem, LocalSandbox } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({
    basePath: './workspace',
  }),
  sandbox: new LocalSandbox({
    workingDirectory: './workspace',
  }),
  skills: ['skills'],
})
```

그만큼`skills` array specifies paths to directories containing skill definitions, see [Skills](/docs/workspace/skills).

### 글로벌 작업공간 {/* #global-workspace */}

Mastra 인스턴스에 작업공간을 설정합니다. 모든 Agent은 자신이 직접 정의하지 않는 한 이 작업 영역을 상속받습니다.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Workspace, LocalFilesystem } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
})

const mastra = new Mastra({
  workspace,
})
```

### Agent 수준 작업공간 {/* #agent-level-workspace */}

전역 작업 영역을 재정의하려면 작업 영역을 Agent에 직접 할당하세요.

```typescript title="src/mastra/agents/my-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Workspace, LocalFilesystem } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './agent-workspace' }),
})

export const myAgent = new Agent({
  id: 'my-agent',
  model: '__GATEWAY_OPENAI_MODEL__',
  workspace,
})
```

## 수명주기 및 정리 {/* #lifecycle-and-cleanup */}

Mastra는 런타임에 나열하고 검색할 수 있도록 전역 및 Agent 작업 영역을 등록합니다. 당신이 전화할 때`mastra.shutdown()`, Mastra destroys registered workspaces that it owns. This closes workspace resources such as language servers, browsers, sandbox processes, and filesystem provider handles.

수동 정리의 경우 다음을 사용하십시오.[`mastra.removeWorkspace()`](/reference/core/removeWorkspace). Pass `{ destroy: true }` when the workspace should be destroyed before it's removed from the registry.

정적 공급자는 작업 영역이 소유합니다. 확인자 지원 공급자는 요청 시 작업 영역에서 생성되므로 애플리케이션이 소유합니다. 보다[runtime sandbox lifecycle ownership](/docs/workspace/sandbox#lifecycle-ownership) for the resolver cleanup model.

## 구성 패턴 {/* #configuration-patterns */}

작업공간은 Agent에 필요한 기능에 따라 여러 구성 패턴을 지원합니다. 주요 빌딩 블록은 다음과 같습니다.`filesystem` (file tools) and `sandbox` (command execution), with `mounts` as the way to bridge cloud storage into sandboxes.

### 파일 시스템 + 샌드박스(로컬) {/* #filesystem--sandbox-local */}

로컬 개발을 위해`LocalFilesystem` and `LocalSandbox` pointed at the same directory. Since both operate on the local machine, files written through the filesystem are immediately available to commands in the sandbox:

```typescript
const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  sandbox: new LocalSandbox({ workingDirectory: './workspace' }),
})
```

Agent는 파일 Tool와`execute_command`. This is the simplest full-featured setup.

### 마운트 + 샌드박스(클라우드 스토리지) {/* #mounts--sandbox-cloud-storage */}

샌드박스 내에서 액세스할 수 있는 클라우드 저장소가 필요한 경우 다음을 사용하세요.`mounts`. This FUSE-mounts the cloud filesystem into the sandbox so commands can read and write files at the mount path:

```typescript
const workspace = new Workspace({
  mounts: {
    '/data': new S3Filesystem({
      bucket: 'my-bucket',
      region: 'us-east-1',
      accessKeyId: process.env.AWS_ACCESS_KEY_ID,
      secretAccessKey: process.env.AWS_SECRET_ACCESS_KEY,
    }),
    '/skills': new GCSFilesystem({
      bucket: 'agent-skills',
    }),
  },
  sandbox: new E2BSandbox({ id: 'dev-sandbox' }),
})
```

후드 아래에서,`mounts` creates a [CompositeFilesystem](/docs/workspace/filesystem#mounts-and-compositefilesystem) that routes file tool operations to the correct provider based on path prefix. Commands in the sandbox access the mounted paths directly (e.g., `ls /data`).

여러 경로에 여러 공급자를 탑재할 수 있습니다. 각 마운트 경로는 고유해야 하며 겹치지 않아야 합니다.

:::메모

`filesystem`그리고`mounts` are mutually exclusive, you can't use both in the same workspace. Use `filesystem` for a single provider without a sandbox, or `mounts` when you need to combine cloud storage with a sandbox.

:::

### 파일 시스템만 {/* #filesystem-only */}

싱글을 사용하세요`filesystem` when agents only need to read and write files. No command execution is available.

```typescript
const workspace = new Workspace({
  filesystem: new S3Filesystem({
    bucket: 'my-bucket',
    region: 'us-east-1',
    accessKeyId: process.env.AWS_ACCESS_KEY_ID,
    secretAccessKey: process.env.AWS_SECRET_ACCESS_KEY,
  }),
})
```

Agent는 파일 Tool(`read_file`, `write_file`, `list_directory`, `grep`, etc.) that operate directly against the storage provider.

### 샌드박스 전용 {/* #sandbox-only */}

싱글을 사용하세요`sandbox` when agents only need to execute commands. No file tools are added.

```typescript
const workspace = new Workspace({
  sandbox: new E2BSandbox({ id: 'dev-sandbox' }),
})
```

Agent는`execute_command` tool.

### 동적 파일 시스템(요청별) {/* #dynamic-filesystem-per-request */}

리졸버 함수를 다음으로 전달합니다.`filesystem` to return a different filesystem per request. This is useful for multi-tenant applications or multi-role agents where each request needs a different storage root or different permissions.

```typescript
const workspace = new Workspace({
  filesystem: ({ requestContext }) => {
    const role = requestContext.get('agent-role') || 'guest'
    return new LocalFilesystem({
      basePath: `/workspaces/${role}`,
      readOnly: role !== 'admin',
    })
  },
})
```

하나의 작업공간 인스턴스가 모든 요청을 처리합니다. 해석기는 Tool 실행 시간에 실행되므로 각 요청은 자체 파일 시스템을 갖습니다. 보다[dynamic filesystem](/docs/workspace/filesystem#dynamic-filesystem) for details.

### 동적 샌드박스(요청별) {/* #dynamic-sandbox-per-request */}

리졸버 함수를 다음으로 전달합니다.`sandbox` to return a different sandbox per request. This is useful for multi-tenant deployments where each user or role needs an isolated working directory or different execution permissions.

```typescript
const workspace = new Workspace({
  sandbox: ({ requestContext }) => {
    const userId = requestContext.get('user-id') as string
    return new LocalSandbox({
      workingDirectory: `/workspaces/${userId}`,
    })
  },
})
```

리졸버가 다음과 호환되지 않습니다.`mounts` and `lsp: true`, since both require a concrete sandbox instance at construction time. See [dynamic sandbox](/docs/workspace/sandbox#dynamic-sandbox) for details.

### 어떤 패턴을 사용해야 하나요? {/* #which-pattern-should-i-use */}

| 시나리오 | 패턴 |
| - | - |
| 파일 및 명령을 사용한 로컬 개발 |`filesystem` + `sandbox` (both local, same directory) |
| Cloud storage accessible inside a cloud sandbox | `mounts` + `sandbox` |
| Multiple cloud providers in one sandbox | `mounts` + `sandbox` (one mount per provider) |
| Agent reads/writes files, no command execution needed | `filesystem` only |
| Agent runs commands, no file tools needed | `sandbox` only |
| Multi-role or multi-tenant agent with per-request storage | `filesystem` with resolver function |
| Multi-tenant agent with per-request execution scope | `sandbox` with resolver function |

## Tool 구성 {/* #tool-configuration */}

다음을 통해 Tool 동작을 구성합니다.`tools` option on the workspace. This controls which tools are enabled and how they behave.

```typescript title="src/mastra/workspaces.ts"
import { Workspace, LocalFilesystem, LocalSandbox, WORKSPACE_TOOLS } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  sandbox: new LocalSandbox({ workingDirectory: './workspace' }),
  tools: {
    // Global defaults
    enabled: true,
    requireApproval: false,

    // Per-tool overrides
    [WORKSPACE_TOOLS.FILESYSTEM.WRITE_FILE]: {
      requireApproval: true,
      requireReadBeforeWrite: true,
    },
    [WORKSPACE_TOOLS.FILESYSTEM.DELETE]: {
      enabled: false,
    },
    [WORKSPACE_TOOLS.SANDBOX.EXECUTE_COMMAND]: {
      requireApproval: true,
    },
  },
})
```

### Tool 옵션 {/* #tool-options */}

| 옵션 | 유형 | 설명 |
| - | - | - |
|`enabled` | `boolean \| (context) => boolean` | Whether the tool is available (default: `true`). When a function, evaluated at tool-listing time. |
| `requireApproval` | `boolean \| (context) => boolean` | Whether the tool requires user approval before execution (default: `false`). When a function, evaluated at execution time with access to `args`. |
| `requireReadBeforeWrite` | `boolean \| (context) => boolean` | For write tools: require reading the file first (default: `false`). When a function, evaluated at execution time with access to `args`. |
| `name` | `string` | Custom name for the tool. Replaces the default `mastra_workspace_*` name. |
| `maxOutputTokens` | `number` | Maximum tokens for tool output (default: `2000`). Output exceeding this limit is truncated using tiktoken. |

### 동적 Tool 구성 {/* #dynamic-tool-configuration */}

함수를 허용하는 Tool 옵션은 컨텍스트 개체를 수신하고 부울을 반환합니다. 상황 인식 Tool 동작을 가능하게 합니다.

```typescript title="src/mastra/workspaces.ts"
const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  tools: {
    // Dynamic enabled: disable command execution unless explicitly allowed
    [WORKSPACE_TOOLS.SANDBOX.EXECUTE_COMMAND]: {
      enabled: async ({ requestContext }) => {
        return requestContext['allowExecution'] === 'true'
      },
    },

    // Dynamic requireApproval: only require approval for protected paths
    [WORKSPACE_TOOLS.FILESYSTEM.WRITE_FILE]: {
      requireApproval: async ({ args }) => {
        return (args.path as string).startsWith('/protected')
      },
      requireReadBeforeWrite: true,
    },
  },
})
```

기능`enabled` receive `{ requestContext, workspace }`. Functions for `requireApproval` and `requireReadBeforeWrite` also receive `args` since they're evaluated when the tool is called.

### Tool 이름 다시 매핑 {/* #tool-name-remapping */}

Agent가 기대하는 규칙과 일치하도록 작업 영역 Tool의 이름을 바꿉니다. 구성 키는 원본으로 유지됩니다.`WORKSPACE_TOOLS` constant, only the exposed name changes.

```typescript title="src/mastra/workspaces.ts"
import { Workspace, LocalFilesystem, LocalSandbox, WORKSPACE_TOOLS } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  sandbox: new LocalSandbox({ workingDirectory: './workspace' }),
  lsp: true,
  tools: {
    [WORKSPACE_TOOLS.FILESYSTEM.READ_FILE]: { name: 'view' },
    [WORKSPACE_TOOLS.FILESYSTEM.GREP]: { name: 'search_content' },
    [WORKSPACE_TOOLS.FILESYSTEM.LIST_FILES]: { name: 'find_files' },
    [WORKSPACE_TOOLS.SANDBOX.EXECUTE_COMMAND]: { name: 'execute_command' },
    [WORKSPACE_TOOLS.LSP.LSP_INSPECT]: { name: 'lsp_inspect' },
  },
})
```

Agent이 보니까`view`, `search_content`, `find_files`, `execute_command`, and `lsp_inspect` instead of the default `mastra_workspace_*` names. Tool names must be unique, duplicate names or conflicts with other default names throw an error.

### Tool 후크 {/* #tool-hooks */}

세트`tools.hooks` to run logic before and after every enabled workspace tool call. Hooks run after name remapping, so the hook context includes both the exposed `toolName` and the original `workspaceToolName`:

```typescript title="src/mastra/workspaces.ts"
import { Workspace, LocalFilesystem } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  tools: {
    hooks: {
      beforeToolCall: ({ toolName, workspaceToolName, input }) => {
        console.log(`Running ${toolName} (${workspaceToolName})`, input)
      },
      afterToolCall: ({ toolName, output, error }) => {
        console.log(`Finished ${toolName}`, { output, error })
      },
    },
  },
})
```

반품`{ proceed: false, output }` from `beforeToolCall` to skip the tool call and use `output` as its result.

소유 대리인도 정의한 경우[tool hooks](/docs/agents/using-tools#run-logic-around-tool-calls), workspace hooks run inside the agent hook wrapper. The order is agent `beforeToolCall`, workspace `beforeToolCall`, the tool, workspace `afterToolCall`, and agent `afterToolCall`.

## LSP 검사 {/* #lsp-inspection */}

할 수 있게 하다`lsp` on a workspace to add semantic code inspection through language servers. This adds the `mastra_workspace_lsp_inspect` tool by default, which can return hover information and definition locations, plus implementations for a symbol at a specific cursor position.

보다[LSP inspection](/docs/workspace/lsp) for configuration, examples, and tool name remapping.

### 출력 잘림 {/* #output-truncation */}

Workspace Tool는 LLM 컨텍스트 제한을 초과하지 않도록 큰 출력을 자동으로 자릅니다. 다음과 같은 잘림 레이어가 적용됩니다.

1. **라인 기반 꼬리**: 명령 출력은 기본적으로 마지막 200줄로 제한됩니다(다음을 통해 명령별로 구성 가능).`tail` parameter)
2. **토큰 기반 한도**: Tool 출력은 기본적으로 2000개 토큰으로 제한됩니다.

세트`maxOutputTokens` per tool to adjust the token limit:

```typescript
const workspace = new Workspace({
  // ...
  tools: {
    [WORKSPACE_TOOLS.SANDBOX.EXECUTE_COMMAND]: {
      maxOutputTokens: 5000,
    },
  },
})
```

ANSI 이스케이프 코드(색상, 커서 시퀀스)는 명령 출력이 Model에 도달하기 전에 자동으로 제거됩니다.

### 쓰기 전 읽기 {/* #read-before-write */}

언제`requireReadBeforeWrite` is enabled on write tools, agents must read a file before writing to it. This prevents overwriting files the agent hasn't seen:

* **새 파일**: 읽지 않고도 쓸 수 있습니다(아직 존재하지 않습니다).
* **기존 파일**: 먼저 읽어야합니다
* **외부에서 수정된 파일**: Agent가 파일을 읽은 후 파일이 변경된 경우 쓰기가 실패합니다.

파일 쓰기 안전은 두 계층에서 시행됩니다.

1. **Tool 레이어**: 쓰기 Tool가 실행되기 전에 읽기 추적기는 파일이 마지막으로 읽힌 이후 수정되었는지 여부를 확인합니다. 그렇다면 Tool는`FileReadRequiredError`.
2. **파일 시스템 계층**: 쓰기 시,`writeFile()` compares the file's current modification time against the expected value (passed via `expectedMtime` in write options). If they don't match, it throws a `StaleFileError`. This catches external modifications (for example, an editor saving the file) that happen between the tool-level check and the actual write.

언제`requireReadBeforeWrite` is enabled, workspace tools pass the recorded modification time through automatically. You can also use `expectedMtime` directly when calling `filesystem.writeFile()` outside of tools:

```typescript
const stat = await filesystem.stat('/docs/file.md')
// ... later ...
await filesystem.writeFile('/docs/file.md', newContent, {
  expectedMtime: stat.modifiedAt,
})
```

## 초기화 {/* #initialization */}

부름`init()` is optional in most cases, some providers initialize on first operation. Call `init()` manually when using a workspace outside of Mastra (standalone scripts, tests) or when you need to pre-provision resources before the first agent interaction.

```typescript title="src/mastra/workspaces.ts"
import { Workspace, LocalFilesystem, LocalSandbox } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  sandbox: new LocalSandbox({ workingDirectory: './workspace' }),
})

// Optional: pre-create directories and sandbox before first use
await workspace.init()
```

### 무엇`init()` does {/* #what-init-does */}

초기화는 구성된 각 공급자에 대해 설정 논리를 실행합니다.

* `LocalFilesystem`: 기본 디렉터리가 없으면 만듭니다.
* `LocalSandbox`: 작업 디렉토리를 생성합니다
* `Search`(구성된 경우): 다음 위치에서 파일을 색인화합니다.`autoIndexPaths`, see [Search and Indexing](/docs/workspace/search)

외부 공급자는 연결 설정 또는 인증과 같은 추가 설정을 수행할 수 있습니다.
