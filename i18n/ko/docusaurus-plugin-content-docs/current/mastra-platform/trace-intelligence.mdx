# Mastra 플랫폼의 Trace Intelligence

Trace Intelligence는 Agent의 상호 작용 전반에서 반복되는 패턴을 찾습니다. Mastra Observability에서 캡처한 추적을 분석하고, 4차원에 대한 추적 신호를 생성하고, 유사한 추적 신호를 테마로 클러스터링합니다.

Trace Intelligence를 사용하여 다음과 같은 질문을 조사하세요.

* 사용자는 무엇을 달성하려고 합니까?
* 어떤 목표가 성공하거나, 해결되지 않거나, 차단되는 경향이 있습니까?
* 성공적인 상호작용과 실패한 상호작용에는 어떤 Agent 행동이 나타나나요?
* 사용자 감정은 목표 및 결과와 어떤 관련이 있습니까?

:::비공개 베타 경고
Trace Intelligence는 선택된 Mastra 플랫폼 프로젝트에 대한 초대를 통해 제공됩니다.
:::

## 액세스하기 {/* #get-access */}

1. 제출[Trace Intelligence private beta form](https://mastra.ai/trace-intelligence) to request access.
2. 확인하세요[Mastra platform Observability](/docs/mastra-platform/observability) is enabled and that completed agent traces appear under **Traces**.
3. 최소한 필요합니다`@mastra/core@1.53.0` and `mastra@1.20.2`. Upgrade your project then deploy or redeploy Studio for the enrolled project. Local Studio and server-only deployments aren't supported during the private beta.
4. 배포된 Studio를 열고 다음을 선택하세요.**Intelligence** in the sidebar.
5. 대표 트래픽을 Agent에 보내고 분석 시간을 허용합니다.

Mastra가 프로젝트를 등록하면 Agent 정의나 통화를 변경할 필요가 없습니다.

### 데이터를 사용할 수 있는 경우 {/* #when-data-is-available */}

Trace Intelligence는 반복 패턴을 식별하기 위해 하나의 Agent에서 처리된 추적이 충분해야 합니다. 초기 테마는 일반적으로 최소한**100 completed traces** from that agent have been processed.

아래의 추적 수**Traces** can reach 100 before Trace Intelligence is ready because the analysis pipeline runs asynchronously. Processing can take several minutes after the threshold is reached. Traces that can't be analyzed don't contribute, so 100 is a minimum, not an exact UI trigger.

더 많은 추적이 도착하면 추적 인텔리전스가 자동으로 업데이트됩니다. Studio에서 관계 흐름을 표시하려면 최소한 두 가지 추적 신호 유형에 대한 테마가 필요합니다.

대표 트래픽을 사용하세요. 반복되는 테스트 Prompt의 작은 세트는 하나의 광범위한 테마 또는 대부분 소음과 같은 대표성이 없는 결과를 생성할 수 있습니다.

## 분석 이해 {/* #understand-the-analysis */}

분석 가능한 각 완성 추적은 4개의 추적 신호를 생성합니다.

| 추적 신호 | 의미 |
| - | - |
|**Goal** | What the user is trying to achieve or have completed. |
| **Outcome** | The final completed, partial, blocked, failed, unresolved, or unclear state. |
| **Behavior** | Observable agent actions and patterns, including tool use, omissions, retries, failures, and recovery. |
| **Sentiment** | The user's emotional state or attitude. |

테마는 유사한 추적 신호에서 생성된 클러스터입니다. 클러스터링은 각 추적 신호 유형에 대해 독립적으로 발생합니다. 하나의 추적은 목표, 결과, 행동, 감정 등 모든 차원에서 별도의 주제에 속할 수 있습니다.

### 주제와 관계 {/* #themes-and-relationships */}

순서도는 인접한 추적 신호 열의 주제를 연결합니다.

* 에이**node** represents a theme. Its count is the number of distinct traces assigned to that theme in the selected snapshot.
* 에이**ribbon** connects traces assigned to themes in both adjacent columns. Its width represents the shared trace count.
* 노드나 리본 위에 마우스를 올리거나 초점을 맞춰 해당 관계를 분리합니다.

흐름은 원인이나 실행 순서가 아닌 연관성을 보여줍니다. 예를 들어 목표와 결과 사이의 리본은 두 테마가 모두 동일한 추적에서 발생했음을 의미합니다. 목표가 결과를 초래했다는 것을 보여주지는 않습니다.

### 분포, 기타 및 노이즈 {/* #distributions-other-and-noise */}

흐름 아래의 카드는 각 추적 신호의 테마 분포를 보여줍니다.

* **추적 수**: 선택한 스냅샷의 테마에 할당된 개별 추적 수입니다.
* **무대 점유율**: 테마에 할당된 해당 추적 신호에 대해 분석된 추적의 백분율입니다.

Studio는 각 추적 신호 유형에 대한 가장 일반적인 테마를 보여줍니다. 더 작은 테마를 다음과 같이 결합할 수 있습니다.**Other** to preserve totals without overcrowding the chart.

**소음**선택한 스냅샷의 반복 테마와 일관되게 일치하지 않는 요약이 포함되어 있습니다. 반드시 오류나 품질이 낮은 상호 작용을 나타내는 것은 아닙니다. 소음에는 드문 요청과 새로운 패턴이 포함될 수 있습니다. 또한 모호한 상호 작용이나 관련 없는 사례가 포함될 수도 있습니다. 노이즈 점유율이 크다는 것은 트래픽이 매우 다양하거나 안정적인 테마에 대한 데이터가 부족하다는 것을 의미할 수 있습니다.

### 스냅샷 {/* #snapshots */}

스냅샷은 일련의 추적에 대한 이동 분석 창입니다. 스냅샷은 겹칠 수 있으므로 추적 수를 함께 추가하지 마세요. 트래픽 양은 창 간에 변경될 수 있으므로 추적 수와 단계 공유를 함께 비교하십시오.

테마는 스냅샷 전체에 걸쳐 유지, 사라지기, 분할, 병합 또는 반환될 수 있습니다. 테마 이름과 설명을 고정된 분류가 아닌 생성된 요약으로 처리합니다.

## 추적 인텔리전스 페이지 사용 {/* #use-the-trace-intelligence-page */}

1. 사용**Agent** selector to switch between agents with available analysis. An agent doesn't appear until its first themes are ready.
2. 해당 테마가 포함된 추적으로 모든 열을 필터링하려면 흐름에서 테마를 선택하세요.
3. 선택하다**View theme details** to inspect its description, trace count, stage share, generated examples, and history.
4. 선택하다**Clear filter** to restore the complete flow.

다음을 수행할 수도 있습니다.

* 배포 카드에서 테마를 선택하여 해당 세부 정보와 생성된 예제 요약을 엽니다.
* 선택하다**Noise** in a distribution card to inspect its distribution and generated example summaries.
* 배포 카드를 드래그하여 추적 신호 열을 재정렬하고 다른 관계 관점을 확인하세요.
* 타임라인을 사용하여 스냅샷을 선택하거나**Play** to watch themes change over time.
* 테마 기록을 열어 지속 여부와 적용 범위가 어떻게 변경되었는지 확인하세요.

트레이스가 2,000개가 넘는 스냅샷의 경우 테마별로 흐름을 필터링할 수 없습니다. 다른 스냅샷을 선택하거나 활성 필터를 지워 전체 흐름으로 돌아갑니다. 테마 및 소음 세부 정보는 배포 카드에서 계속 확인할 수 있습니다.

## 문제 해결 {/* #troubleshooting */}

### 인텔리전스는 사이드바에 없습니다. {/* #intelligence-isnt-in-the-sidebar */}

Mastra가 올바른 프로젝트를 등록했는지, 베타 호환 Mastra 버전을 사용하고 있는지, Studio를 재배포했는지 확인하세요. 비공개 베타는 로컬 Studio를 지원하지 않습니다.

### Agent가 누락되었습니다. {/* #an-agent-is-missing */}

완료된 추적이 아래에 나열되어 있는지 확인하세요.**Traces**. The agent is listed only after its first themes are ready. If it recently reached 100 traces, allow time for asynchronous processing.

### 관계 흐름을 사용할 수 없습니다. {/* #the-relationship-flow-is-unavailable */}

흐름에는 두 개 이상의 추적 신호 유형에 대한 테마가 필요합니다. 계속해서 대표 트래픽을 보내고 처리가 완료되도록 허용합니다.

### 대부분의 요약은 노이즈입니다. {/* #most-summaries-are-noise */}

더 많은 대표적인 트래픽을 수집하고 이후의 스냅샷을 비교하세요. 다양하거나 드문 상호 작용은 그룹화하기 어려운 반면, 반복되는 테스트 Prompt는 대표적인 분포를 생성할 수 없습니다.

## 비공개 베타 제한 사항 {/* #private-beta-limitations */}

* Trace Intelligence는 배포된 Studio에 등록된 프로젝트에만 사용할 수 있습니다.
* 초기 분석에는 Agent당 처리된 추적이 100개 이상 필요합니다. 일부 Agent은 더 많은 금액을 요구할 수도 있습니다.
* 결과는 캡처된 추적의 다양성과 품질에 따라 달라집니다.
* 베타 기간 동안 추적 신호 요약, 테마 레이블, 클러스터링, 임계값 및 UI 동작이 변경될 수 있습니다.

피드백을 보고할 때 조직 ID, 프로젝트 ID, Agent ID, 선택한 스냅샷, 문제를 설명하는 테마 또는 소음 예시를 포함하세요.
