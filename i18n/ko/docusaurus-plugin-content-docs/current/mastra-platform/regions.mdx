# 지역

지역은 플랫폼 환경이 실행되는 위치,[hosted database](/docs/mastra-platform/database)배치되고 관측 가능성 데이터가 저장되는 위치입니다. 지역은 환경이 생성될 때 고정되며 나중에 변경할 수 없습니다.

Mastra 플랫폼은 현재 두 개의 거주 구역을 제공합니다.`us` and `eu`, 철도의 특정 컴퓨팅 지역이 지원합니다. 데이터베이스와 관측 가능성은 자동으로 환경의 지역을 따릅니다.

## 지역을 선택하세요 {/* #choose-a-region */}

통과하다`--region` when creating or first deploying to an environment:

```bash
mastra deploy --env production --region eu
mastra env create staging --region us
```

둘 다`mastra deploy --region` and `mastra env create --region` accept either the `us` / `eu`아래 표의 속기 또는 표준 철도 지역 코드입니다. 단축어가 권장되는 형식입니다.

지역이 전달되지 않을 때의 기본값은 다음과 같습니다.`us`, which resolves to `pdx` (Portland, Oregon).

## 사용 가능한 지역 {/* #available-regions */}

거주지 선택자는 두 구역에 걸쳐 네 개의 철도 지역을 제공합니다.`us` and `eu` shorthand resolve to the underlined default in each zone.

| 존 | 철도 코드 | 위치 |
| - | - | - |
|`us` | `pdx` (default) | Portland, Oregon |
| `us` | `iad` | Ashburn, Virginia |
| `us` | `sfo` | San Francisco, California |
| `eu` | `ams`(기본값) | 암스테르담, 네덜란드 |

환경을 특정 데이터 센터에 고정해야 하는 경우 철도 코드를 직접 전달하세요. 통과`us` selects `pdx`, and passing `eu` selects `ams`.

:::참고
배포 파이프라인에 추가 철도 지역이 있습니다(예: 싱가포르,`sin`) but aren't offered in the residency selector yet, because hosted databases and observability don't have local placement outside the US and EU. Passing an unrecognized region falls back to the US default rather than pinning to it.
:::

## 호스팅된 데이터베이스 배치 {/* #hosted-database-placement */}

첨부할 때[environment-scoped database](/docs/mastra-platform/database), the platform picks the provider region closest to the environment. This is server-authoritative, so an explicit `--region` on `mastra env db create <env>` is ignored. The environment's region is the source of truth.

| 환경지역 | 투르소 지역 | Postgres(네온) 지역 |
| - | - | - |
|`pdx` | `sjc` (San Jose) | `aws-us-west-2` (Oregon) |
| `iad` | `iad` (Ashburn) | `aws-us-east-1` (N. Virginia) |
| `sfo` | `sjc` (San Jose) | `aws-us-west-2` (Oregon) |
| `ams` | `ams`(암스테르담) |`aws-eu-central-1`(프랑크푸르트) |

프로젝트 범위 데이터베이스(환경 전반에 걸쳐 공유)는 명시적인`--region` because they aren't bound to a single environment. Use a provider region ID for the flag, not the `us` / `eu` shorthand:

```bash
mastra env db create --kind turso --region fra
mastra env db create --kind neon --region aws-us-east-1
```

Turso는 20개 이상의 지역을 제공하며 Postgres(Neon)는 미국, EU 및 APAC의 AWS 및 Azure 지역에서 사용할 수 있습니다. 참조[Turso regions list](https://docs.turso.tech/features/data-edge#locations) and [Neon regions list](https://neon.com/docs/introduction/regions) for the full set. Passing a code not offered by the provider fails at attach time with the provider's error.

## Observability 공동 위치 {/* #observability-co-location */}

현재 관측 가능성 수집은 두 지역에서 실행됩니다.**US** (Iowa, `us-central1`) and **EU** (Amsterdam). Every environment's traces, logs, and metrics are routed to the ingest region that matches its residency zone:

| 환경지역 | 관찰 가능 영역 |
| - | - |
|`pdx`, `iad`, `sfo`, `us` shorthand | US (Iowa) |
| `ams`, `eu` shorthand | EU (Amsterdam) |

컴퓨팅 및 데이터베이스는 관측 가능성 지원보다 더 많은 철도 및 공급자 지역에 배치될 수 있으므로 공동 배치가 모든 조합에 완벽하지는 않습니다. 에이`us`-zone environment always sends telemetry to US ingest, and an `eu`-zone environment always sends telemetry to EU ingest, even if the underlying Railway region is a specific city not directly served by an ingest endpoint. Data residency is preserved at the zone level. Telemetry from an `eu` environment never crosses into the US.
