# 지역

지역은 플랫폼 환경이 실행되는 위치,[hosted database](/docs/mastra-platform/database)배치되고 관측 가능성 데이터가 저장되는 위치입니다. 지역은 환경이 생성될 때 고정되며 나중에 변경할 수 없습니다.

Mastra 플랫폼은 현재 `us`와 `eu`라는 두 개의 상주 영역을 제공하며, Railway의 특정 컴퓨팅 지역이 이를 지원합니다. 데이터베이스와 Observability는 자동으로 환경의 지역을 따릅니다.
## 지역을 선택하세요 {/* #choose-a-region */}

환경을 생성하거나 처음 배포할 때 `--region`을 전달하세요.
```bash
mastra deploy --env production --region eu
mastra env create staging --region us
```

`mastra deploy --region`과 `mastra env create --region`은 모두 `us` / `eu` 단축어나 아래 표의 표준 Railway 지역 코드를 허용합니다. 단축어가 권장 형식입니다.
지역을 전달하지 않으면 기본값은 `us`이며, 이는 `pdx`(Portland, Oregon)로 결정됩니다.
## 사용 가능한 지역 {/* #available-regions */}

상주 영역 선택기에서는 두 영역에 걸쳐 네 개의 Railway 지역을 제공합니다. `us`와 `eu` 단축어는 각 영역에서 밑줄 친 기본값으로 결정됩니다.
| 존 | 철도 코드 | 위치 |
| - | - | - |
|`us` | `pdx` (default) | Portland, Oregon |
| `us` | `iad` | Ashburn, Virginia |
| `us` | `sfo` | San Francisco, California |
| `eu` | `ams`(기본값) | 암스테르담, 네덜란드 |

환경을 특정 데이터 센터에 고정해야 한다면 Railway 코드를 직접 전달하세요. `us`를 전달하면 `pdx`가 선택되고 `eu`를 전달하면 `ams`가 선택됩니다.
:::참고
배포 파이프라인에는 싱가포르(`sin`)와 같은 추가 Railway 지역이 있지만, 호스팅된 데이터베이스와 Observability가 미국과 EU 이외의 지역 배치를 지원하지 않으므로 아직 상주 영역 선택기에서는 제공되지 않습니다. 인식되지 않는 지역을 전달하면 해당 지역에 고정되지 않고 미국 기본값으로 대체됩니다.
:::
## 호스팅된 데이터베이스 배치 {/* #hosted-database-placement */}

[환경 범위 데이터베이스](/docs/mastra-platform/database)를 연결하면 플랫폼에서 환경과 가장 가까운 Provider 지역을 선택합니다. 이 결정은 서버에서 이루어지므로 `mastra env db create <env>`에 명시적으로 전달한 `--region`은 무시됩니다. 환경의 지역이 기준 정보입니다.
| 환경지역 | 투르소 지역 | Postgres(네온) 지역 |
| - | - | - |
|`pdx` | `sjc` (San Jose) | `aws-us-west-2` (Oregon) |
| `iad` | `iad` (Ashburn) | `aws-us-east-1` (N. Virginia) |
| `sfo` | `sjc` (San Jose) | `aws-us-west-2` (Oregon) |
| `ams` | `ams`(암스테르담) |`aws-eu-central-1`(프랑크푸르트) |

프로젝트 범위 데이터베이스는 여러 환경에서 공유되며 단일 환경에 바인딩되지 않으므로 명시적인 `--region`이 필요합니다. 플래그에는 `us` / `eu` 단축어가 아닌 Provider 지역 ID를 사용하세요.
```bash
mastra env db create --kind turso --region fra
mastra env db create --kind neon --region aws-us-east-1
```

Turso는 20개 이상의 지역을 제공하며 Postgres(Neon)는 미국, EU 및 APAC의 AWS와 Azure 지역에서 사용할 수 있습니다. 전체 목록은 [Turso 지역 목록](https://docs.turso.tech/features/data-edge#locations)과 [Neon 지역 목록](https://neon.com/docs/introduction/regions)을 참조하세요. Provider에서 제공하지 않는 코드를 전달하면 연결 시 Provider 오류와 함께 실패합니다.
## Observability 공동 위치 {/* #observability-co-location */}

현재 Observability 수집은 **US**(Iowa, `us-central1`)와 **EU**(Amsterdam) 두 지역에서 실행됩니다. 각 환경의 Trace, 로그 및 메트릭은 해당 상주 영역과 일치하는 수집 지역으로 라우팅됩니다.
| 환경지역 | 관찰 가능 영역 |
| - | - |
|`pdx`, `iad`, `sfo`, `us` shorthand | US (Iowa) |
| `ams`, `eu` shorthand | EU (Amsterdam) |

컴퓨팅과 데이터베이스는 Observability에서 지원하는 지역보다 더 많은 Railway 및 Provider 지역에 배치될 수 있으므로 모든 조합에서 완벽한 공동 배치가 이루어지는 것은 아닙니다. `us` 영역의 환경은 항상 텔레메트리를 미국 수집 지역으로 보내고, `eu` 영역의 환경은 기반 Railway 지역이 수집 엔드포인트에서 직접 지원하지 않는 특정 도시이더라도 항상 EU 수집 지역으로 보냅니다. 데이터 상주성은 영역 수준에서 유지됩니다. `eu` 환경의 텔레메트리는 미국으로 이동하지 않습니다.
