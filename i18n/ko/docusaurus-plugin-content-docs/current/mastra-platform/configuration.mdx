# 구성

Mastra 플랫폼에 배포하면 CLI가`.mastra-project.json`config 파일을 분석하고 플랫폼 및 선택적으로 로컬에서 환경 변수를 확인합니다.`.env`파일.

이 페이지에서는 두 가지 메커니즘을 모두 설명합니다.

## 프로젝트 구성 {/* #project-config */}

그만큼`.mastra-project.json` file is auto-generated on your first [`mastra deploy`](/docs/mastra-platform/deploy). It links your local project to a platform project. The [GitHub integration](/docs/mastra-platform/github) writes the same file into linked repositories.

후속 배포(CI 포함)에서 올바른 프로젝트를 대상으로 하도록 버전 제어에 커밋합니다.

파일은 다음과 같습니다.

```json title=".mastra-project.json"
{
  "projectId": "06daaac4-89b1-40f0-9e3f-0993e039a627",
  "projectName": "my-project",
  "organizationId": "org_01KNA5YSP52SX4M6YVSXC2MAHP"
}
```

| 필드 | 설명 |
| - | - |
| 프로젝트 ID | 프로젝트의 UUID입니다. 프로젝트가 생성될 때 할당됩니다. |
| 프로젝트이름 | 사람이 읽을 수 있는 프로젝트 이름입니다. 대시보드 및 CLI 출력에서 ​​표시 레이블로 사용됩니다. |
| 조직ID | 프로젝트를 소유한 조직입니다. 모든 배포, API 키 및 리소스의 범위는 이 조직으로 지정됩니다. |

## 환경변수 {/* #environment-variables */}

로컬 env 파일은 선택 사항입니다.[`mastra deploy`](/docs/mastra-platform/deploy) resolves variables from three sources:

* **관리되는 변수**: 다음과 같은 플랫폼 리소스에 의해 주입됩니다.[hosted databases](/docs/mastra-platform/database). The platform defines these, and you can't edit them.
* **저장된 변수**: 대시보드를 통해 프로젝트나 환경에 저장됩니다. 로컬 파일이 필요하지 않고 모든 배포에서 있는 그대로 사용됩니다.
* **로컬 환경 파일**: 명시적인 배포 계층`--env-file` or the ambient `.env` and `.env.local` files on top. Variables from `.env.local` override those in `.env`.

기본 선택에 의존하는 대신 특정 env 파일에 배포를 고정하려면 다음을 전달합니다.`--env-file`:

```bash
mastra deploy --env-file .env.production --yes
```

개발 전용 또는 개인 비밀이 업로드되지 않도록 배포하기 전에 로컬 env 파일을 검토하고 정리하세요.

### Observability {/* #observability */}

다음 환경 변수는 Mastra 플랫폼에서 Observability 제품을 구성합니다.

| 변수 | 설명 |
| - | - |
|`MASTRA_PLATFORM_ACCESS_TOKEN` | Org-scoped access token. The CLI writes this during observability provisioning and uses it for platform authentication. |
| `MASTRA_PROJECT_ID` | UUID of the platform project. `MastraPlatformExporter` uses it to link observability data to the platform project. Studio and Server deploys read the project ID from `.mastra-project.json`. |
| `MASTRA_PLATFORM_OBSERVABILITY_ENDPOINT` | Optional observability endpoint override. This is only set automatically for local platform development. Defaults to `https://observability.mastra.ai`. |
| `MASTRA_ORG_ID` | Overrides the active organization for CLI commands. You can also set it with the `--org` flag on supported commands. |

`MastraPlatformExporter`읽다`MASTRA_PLATFORM_ACCESS_TOKEN` to authenticate platform export.

## 다양한 환경 {/* #multiple-environments */}

단일 프로젝트가 여러 프로젝트에서 동일한 코드베이스를 실행합니다.[environments](/docs/mastra-platform/environments), such as `production` and `staging`. Each environment has its own URL and its own stored variables, plus its own deploy history. One `.mastra-project.json` file covers all of them:

```bash
mastra deploy --env production --yes
mastra deploy --env staging --env-file .env.staging --yes
```

:::참고
이전 플랫폼 버전에서는 환경당 하나의 프로젝트가 필요했습니다. 환경은 해당 패턴을 대체하므로 하나의 프로젝트를 유지하고 대신 환경에 배포하세요.
:::
