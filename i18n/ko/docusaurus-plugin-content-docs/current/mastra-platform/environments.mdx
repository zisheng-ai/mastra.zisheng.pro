# 환경

모든 플랫폼 프로젝트에는 하나 이상의 환경이 포함되어 있습니다.

환경은 자체 URL, 환경 변수 및 배포 기록이 있는 격리된 배포 대상입니다. 그것은 또한 자신의 것을 가질 수 있습니다[hosted database](/docs/mastra-platform/database).

환경을 사용하여 실행`production`, `staging`, 단일 프로젝트 내에서 동일한 코드베이스의 미리보기 버전을 사용할 수 있습니다.

당신의 첫 번째[`mastra deploy`](/docs/mastra-platform/deploy) creates the `production` environment. Create more with the CLI or by deploying to a name that doesn't exist yet.

## 환경 만들기 {/* #create-an-environment */}

환경을 명시적으로 생성합니다.

```bash
mastra env create staging
```

또는 배포를 통해 생성하면 확인 메시지가 표시됩니다.

```bash
mastra deploy --env staging
```

`mastra env create`기본값은`staging` type. Pass `--type` to set `staging` or `preview` explicitly, and `--region`환경이 실행되는 위치를 선택하려면 다음을 수행하세요.

```bash
mastra env create eu-preview --type preview --region eu
```

각 프로젝트에는 하나의`production` environment, created by your first deploy. The region is fixed at creation. Databases attached to an environment are placed near the environment's region automatically, and observability data is routed to the ingest region for the matching residency zone. See [Regions](/docs/mastra-platform/regions) for the supported regions, database placement, and observability co-location. The number of environments per project depends on your plan.

## 환경 나열 {/* #list-environments */}

```bash
mastra env list
```

출력에는 각 환경의 이름, 지역, 활성 배포 상태 및 연결된 데이터베이스에서 삽입된 관리형 환경 변수가 표시됩니다. 통과하다`--json` for machine-readable output in CI.

모두`mastra env` commands resolve their project from `MASTRA_PROJECT_ID`, the `--project` flag, or the `.mastra-project.json` file written by your first deploy, in that order. Run them from your project directory and you never need to name the project.

## 환경변수 {/* #environment-variables */}

환경은 세 가지 범위에서 해당 변수를 확인합니다.

* **관리되는 변수**: 첨부하여 주입[hosted databases](/docs/mastra-platform/database) (for example `TURSO_DATABASE_URL`). The platform defines these, and you can't edit them.
* **환경 범위 변수**: 대시보드를 통해 하나의 환경에 저장됩니다. 스테이징 및 프로덕션 서비스용 API 키와 같이 환경마다 다른 값에 대해 이를 사용합니다.
* **프로젝트 범위 변수**: 프로젝트에 저장되며 모든 환경에서 공유됩니다.

환경 범위 변수와 프로젝트 범위 변수는 함께 설명된 저장 변수입니다.[Deploy](/docs/mastra-platform/deploy#environment-variables) page.

배포가 시작되면 변수가 적용됩니다. 전체 재배포 없이 실행 중인 서비스에 변경된 변수를 적용하려면 다음 안내를 따르세요.

```bash
mastra env restart staging
```

환경 배포가 실제로 실행되는 전체 세트를 보려면 환경 범위 및 프로젝트 범위 값이 병합되고 이름별로 나열된 관리 변수와 함께 로컬 env 파일로 가져옵니다.

```bash
mastra env vars pull staging --output .env.staging
```

관리 변수 값은 배포 시 삽입되며 파일에 기록되지 않습니다. 이름만 있는 설명으로 표시됩니다.

:::참고
환경 변수는 관리되는 데이터베이스 변수를 재정의하지 않습니다. 다른 데이터베이스의 환경을 가리키려면[environment-scoped database](/docs/mastra-platform/database#attach-with-the-cli) instead.
:::

## 배포 기록 {/* #deploy-history */}

모든 환경에 걸쳐 배포를 나열하거나 다음 중 하나로 필터링합니다.

```bash
mastra env deploys
mastra env deploys staging
```

각 행에는 배포 상태, 환경, 타임스탬프 및 현재 활성화된 배포가 표시됩니다. 배포는 다음을 통해 전환됩니다.**queued → uploading → building → deploying → running**, and the platform reports **running** only when the new version is serving traffic.

## 환경의 데이터 격리 {/* #isolate-an-environments-data */}

호스팅된 데이터베이스는 기본적으로 단일 환경으로 범위가 지정되므로 프로덕션 및 스테이징은 각각 자체 데이터베이스를 읽고 씁니다.

```bash
mastra env db create production --kind turso --name my-project-production-db
mastra env db create staging --kind turso --name my-project-staging-db
```

모든 환경에서 하나의 데이터베이스를 공유하려면 다음을 사용하여 연결하세요.`--shared` instead: `mastra env db create --kind turso --shared`.

환경은 공급자당 하나의 데이터베이스만 사용할 수 있습니다. 프로젝트에 이미 공유(`--shared`) database of the same provider, attaching an environment-scoped one is rejected with a variable name conflict, delete the shared database with `mastra env db delete` first. Deleting a database destroys it with the provider along with all of its data, so export anything you need to keep. See [Hosted databases](/docs/mastra-platform/database) for the full scoping model.

## 환경 삭제 {/* #delete-an-environment */}

```bash
mastra env delete staging
```

CLI는 삭제하기 전에 확인을 요청합니다. 환경을 삭제하면 배포 및 저장된 변수가 제거됩니다.
