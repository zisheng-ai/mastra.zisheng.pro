# SignalProvider

**新增于：** `@mastra/core@1.39.0`

用于构建 Signal Provider 的抽象基类。Signal Provider 监视外部来源（API、webhook、事件流），并通过内置订阅注册表将通知 Signal 推送至 Agent thread。

Signal Provider 默认不是处理器。需要拦截 Agent 执行的 Provider 会从 `getInputProcessors()` 或 `getOutputProcessors()` 返回处理器。暴露供 Agent 调用的 Tool 的 Provider 会从 `getTools()` 返回它们。

如需可直接使用的基于 webhook 的 Provider，请参阅 [`WebhookSignalProvider`](/reference/signals/webhook-signal-provider)。

## 使用示例 {/* #usage-example */}

每 30 秒检查一次 API 的轮询 Provider：

```typescript title="src/signals/slack-signals.ts"
import { SignalProvider } from '@mastra/core/signals'
import type { SignalSubscription } from '@mastra/core/signals'

class SlackSignals extends SignalProvider<'slack-signals'> {
  readonly id = 'slack-signals'
  readonly pollInterval = 30_000

  async poll(subscriptions: SignalSubscription[]) {
    for (const sub of subscriptions) {
      const messages = await fetchSlackMessages(sub.externalResourceId)
      if (messages.length > 0) {
        await this.notify(
          {
            source: 'slack',
            kind: 'new-messages',
            summary: `${messages.length} new messages in ${sub.externalResourceId}`,
          },
          { threadId: sub.threadId, resourceId: sub.resourceId },
        )
      }
    }
  }
}
```

注册到 Agent：

```typescript title="src/mastra/index.ts"
import { Agent } from '@mastra/core/agent'

const agent = new Agent({
  id: 'agent',
  signals: [new SlackSignals()],
})
```

Agent 调用 `connect(this)` 并注册 Provider 返回的所有处理器或 Tool，然后开始轮询。

## 方法 {/* #methods */}

### 连接 {/* #connection */}

#### `connect(agent)` {/* #connectagent */}

由 Agent 构造函数调用。建立双向链接，以便 Provider 将 Signal 发送回 Agent。可重写此方法，以在链接建立后执行额外设置。务必调用 `super.connect(agent)`。

```typescript prettier:false
class MySignals extends SignalProvider<'my-signals'> {
  readonly id = 'my-signals'

  override connect(agent) {
    super.connect(agent)
    // additional setup after agent link is established
  }
}
```

#### `__registerMastra(mastra)` {/* #__registermastramastra */}

当 Provider 的 Agent 注册到 Mastra 实例时调用。可重写此方法以访问 storage 或其他 Mastra 服务。务必调用 `super.__registerMastra(mastra)`。

```typescript prettier:false
override __registerMastra(mastra) {
  super.__registerMastra(mastra)
  // this.mastra is now available
}
```

### 处理器和 Tool 集成 {/* #processor-and-tool-integration */}

#### `getInputProcessors()` {/* #getinputprocessors */}

返回此 Provider 需要注册到 Agent 的输入处理器。当 Provider 要拦截 Agent 输入步骤时重写（例如注入上下文提示或检测 Tool 调用）。

```typescript prettier:false
getInputProcessors() {
  return [this]
}
```

返回：`InputProcessorOrWorkflow[]`

#### `getOutputProcessors()` {/* #getoutputprocessors */}

返回此 Provider 需要注册到 Agent 的输出处理器。当 Provider 要拦截 Agent 输出步骤时重写。

```typescript prettier:false
getOutputProcessors() {
  return [this]
}
```

返回：`OutputProcessorOrWorkflow[]`

#### `getTools()` {/* #gettools */}

返回此 Provider 向 Agent 暴露的 Tool。当 Provider 添加可由 Agent 调用的 Tool（如订阅或取消订阅命令）时重写。

```typescript prettier:false
getTools() {
  return {
    subscribe_pr: createTool({ /* ... */ }),
    unsubscribe_pr: createTool({ /* ... */ }),
  }
}
```

返回：`Record<string, unknown>`

### 订阅跟踪 {/* #subscription-tracking */}

#### `subscribe(target, externalResourceId, metadata?)` {/* #subscribetarget-externalresourceid-metadata */}

为 thread 订阅外部资源。这是受保护的方法：请从 Provider 实现内部调用。

```typescript prettier:false
const sub = this.subscribe(
  { threadId: 'thread-1', resourceId: 'user-1' },
  'github:mastra-ai/mastra#123',
  { pr: 123 },
)
```

返回：`SignalSubscription`：创建的订阅，或具有已合并 metadata 的现有订阅。

### 轮询 {/* #polling */}

#### `poll(subscriptions)` {/* #pollsubscriptions */}

在每个轮询周期中使用所有活跃订阅调用。重写以检查外部来源并发出通知。框架会防止轮询周期重叠：若 `poll()` 调用耗时超过 `pollInterval`，则跳过下一周期。

```typescript prettier:false
async poll(subscriptions: SignalSubscription[]) {
  for (const sub of subscriptions) {
    const events = await checkExternalSource(sub.externalResourceId)
    for (const event of events) {
      await this.notify(
        { source: 'my-provider', kind: event.type, summary: event.message },
        { threadId: sub.threadId, resourceId: sub.resourceId },
      )
    }
  }
}
```

#### `startPolling()` {/* #startpolling */}

启动轮询计时器。由 Agent 在 `connect()` 后调用。具有幂等性：多次调用没有影响。

```typescript prettier:false
provider.startPolling()
```

#### `stopPolling()` {/* #stoppolling */}

停止轮询计时器。

```typescript prettier:false
provider.stopPolling()
```

### Webhooks {/* #webhooks */}

#### `handleWebhook(request)` {/* #handlewebhookrequest */}

处理传入的 webhook 请求。重写以解析 payload 并将其与订阅匹配，然后发出通知 Signal。有关可直接使用的实现，请参阅 [`WebhookSignalProvider`](/reference/signals/webhook-signal-provider)。

验证 webhook 请求后，从应用程序定义的 HTTP 端点调用此方法。

```typescript prettier:false
async handleWebhook(request) {
  const payload = request.body as { repo: string, event: string }
  const subs = this.getSubscriptionsForResource(payload.repo)

  for (const sub of subs) {
    await this.notify(
      { source: 'github', kind: payload.event, summary: `Event on ${payload.repo}` },
      { threadId: sub.threadId, resourceId: sub.resourceId },
    )
  }

  return { status: 200, body: { matched: subs.length } }
}
```

返回：`Promise<{ status?: number; body?: unknown }>`

### 生命周期 {/* #lifecycle */}

#### `start()` {/* #start */}

在 `connect()` 后调用以运行异步初始化。当设置需要 Agent 或 Mastra 实例可用时重写。

```typescript prettier:false
async start() {
  await this.loadInitialState()
}
```

#### `stop()` {/* #stop */}

关闭时调用。默认实现会停止轮询并清除所有订阅。

```typescript prettier:false
provider.stop()
```

### 通知 {/* #notifications */}

#### `notify(notification, target)` {/* #notifynotification-target */}

向已连接的 Agent 发送通知 Signal。这是对 `agent.sendNotificationSignal()` 的受保护便捷封装。

```typescript prettier:false
await this.notify(
  {
    source: 'my-provider',
    kind: 'pr-updated',
    summary: 'PR #123 was updated',
    priority: 'high',
    payload: { prNumber: 123 },
  },
  { threadId: 'thread-1', resourceId: 'user-1' },
)
```
