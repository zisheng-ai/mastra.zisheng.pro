# Storage

Mastra 通过 `src/mastra/` 目录下的 `storage.ts` 文件设置项目的默认 [storage](/docs/storage/overview)。该文件默认导出一个 store，用它替代 memory、Workflow、observability 和其他 storage domain 所使用的内置内存 store。

本页介绍基于文件的约定。有关后端选择、storage domain、保留策略和 Provider 的详细信息，请参阅 [storage 概览](/docs/storage/overview)。

## 快速开始

使用 [`LibSQLStore`](/reference/storage/libsql) 创建由本地文件支持的 store：

```typescript title="src/mastra/storage.ts"
import { LibSQLStore } from '@mastra/libsql'

export default new LibSQLStore({
  id: 'mastra-storage',
  url: 'file:./mastra.db',
})
```

Mastra 会先注册 store，再注册 File-based Agent 和 Workflow，因此依赖 storage 的组件会绑定到此 store，而不是默认的内存 store。

## 生产环境后端

`storage.ts` 可以导出任意 Mastra storage adapter，例如 LibSQL、PostgreSQL 或 MongoDB。有关设置模式、Provider 支持和 schema 的详细信息，请参阅 [storage 概览](/docs/storage/overview)、[可观测性信号支持](/docs/observability/overview#signal-support)和 [storage 参考](/reference/storage/overview)。

## 与代码配置的优先级

代码中注册的 storage 优先于 `storage.ts`。当一个项目级 store 足以满足需求时，请使用 `storage.ts`；当设置依赖 `src/mastra/index.ts` 中的运行时连接时，请使用代码注册。
