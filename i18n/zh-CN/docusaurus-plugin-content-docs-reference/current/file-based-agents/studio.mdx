# Studio

Mastra 通过 `src/mastra/` 目录下的 `studio.ts` 文件配置 [Studio](/docs/studio/overview)。该文件默认导出一个 `StudioConfig` 对象，用于 Studio 的身份验证和授权：谁可以访问 Studio，以及通过身份验证的用户可以执行哪些操作。

本页介绍基于文件的约定。有关身份验证 Provider、基于角色的访问控制（RBAC）和细粒度授权（FGA），请参阅 [Studio 身份验证](/docs/studio/auth)。

## 快速开始

本地开发时不需要 `studio.ts`。启动开发 server 并打开 Studio：

```bash npm2yarn
npm run dev
```

在本地开发环境中，无需身份验证即可打开 Studio。准备保护共享部署或生产部署时，再添加 `studio.ts`。

## 添加身份验证

使用身份验证 Provider，要求用户必须登录才能访问 Studio。此示例使用 [WorkOS](/docs/server/auth/workos)：

```typescript title="src/mastra/studio.ts"
import { MastraAuthWorkos } from '@mastra/auth-workos'
import type { StudioConfig } from '@mastra/core/server'

export default {
  auth: new MastraAuthWorkos(),
} satisfies StudioConfig
```

身份验证 Provider 负责确定用户身份。要控制用户登录后可执行的操作，请在同一配置中添加 RBAC 或 FGA。有关完整示例，请参阅 [Studio 身份验证](/docs/studio/auth)。

## 与代码配置的优先级

代码中注册的 Studio 配置优先于 `studio.ts`。当一个项目级 Studio 配置足以满足需求时，请使用 `studio.ts`；当身份验证依赖 `src/mastra/index.ts` 中的运行时连接时，请使用代码注册。
