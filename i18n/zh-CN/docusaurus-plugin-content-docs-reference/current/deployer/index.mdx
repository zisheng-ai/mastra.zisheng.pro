# Deployer

Deployer 通过打包代码、管理环境文件以及使用 Hono 框架提供应用，处理独立 Mastra 应用的部署。具体实现必须为特定部署目标定义 deploy 方法。

## 使用示例 {/* #usage-example */}

要创建自定义 deployer，可以扩展抽象 `Deployer` 类，并使用你的特定部署逻辑实现 `deploy` 方法。示例如下：

```typescript
import { Deployer } from '@mastra/deployer'

class CustomDeployer extends Deployer {
  constructor() {
    super({ name: 'custom-deployer' })
  }

  async deploy(outputDirectory: string): Promise<void> {
    // Prepare the output directory
    await this.prepare(outputDirectory)

    // Bundle the application
    await this._bundle('server.ts', 'mastra.ts', outputDirectory)

    // Custom deployment logic
  }
}
```

## 核心概念 {/* #core-concepts */}

### 部署生命周期 {/* #deployment-lifecycle */}

Deployer 抽象类实现了结构化的部署生命周期：

1. **初始化**：使用名称初始化 deployer，并创建用于依赖管理的 Deps 实例。
1. **环境设置**：`getEnvFiles` 方法识别部署期间要使用的环境文件（.env.production、.env）。
1. **准备**：`prepare` 方法（继承自 Bundler）清理输出目录并创建必要的子目录。
1. **打包**：`_bundle` 方法（继承自 Bundler）打包应用代码及其依赖。
1. **部署**：由子类实现抽象 `deploy` 方法，以处理实际部署过程。

### 环境文件管理 {/* #environment-file-management */}

Deployer 类通过 `getEnvFiles` 方法内置了环境文件管理支持。该方法：

- 按预定义顺序查找环境文件（.env.production、.env）
- 使用 FileService 查找第一个存在的文件
- 返回找到的环境文件数组
- 如果未找到环境文件，则返回空数组

```typescript prettier:false
getEnvFiles(): Promise<string[]> {
  const possibleFiles = ['.env.production', '.env.local', '.env'];

  try {
    const fileService = new FileService();
    const envFile = fileService.getFirstExistingFile(possibleFiles);

    return Promise.resolve([envFile]);
  } catch {}

  return Promise.resolve([]);
}
```

### 打包与部署的关系 {/* #bundling-and-deployment-relationship */}

Deployer 类扩展了 Bundler 类，在打包与部署之间建立了明确的关系：

1. **打包是前置条件**：打包是部署的前置步骤，会将应用代码封装为可部署格式。
1. **共享基础设施**：打包与部署共享依赖管理和文件系统操作等通用基础设施。
1. **专用部署逻辑**：打包侧重于封装代码，而部署会添加面向具体环境的逻辑来部署已打包的代码。
1. **可扩展性**：抽象 `deploy` 方法支持为不同目标环境创建专用 deployer。
