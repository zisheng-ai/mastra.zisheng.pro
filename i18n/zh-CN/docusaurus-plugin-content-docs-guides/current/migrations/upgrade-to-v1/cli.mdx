# CLI

CLI 已移除部署命令、配置标志和起始文件，从而得到简化。同时新增了迁移命令，用于协助升级数据库 Schema。

## 新增

### `mastra migrate` 命令

新的 `mastra migrate` 命令可在升级 Mastra 版本时帮助运行数据库迁移。从可能存在数据不兼容问题的旧版本升级时尤其有用。

```bash
npx mastra migrate
```

该命令会打包项目并连接到已配置的 Storage，然后运行所有必要的迁移。目前支持迁移可能阻碍创建唯一约束的重复 span 条目。

有关何时需要此迁移，请参阅 [Storage 迁移指南](/guides/migrations/upgrade-to-v1/storage#duplicate-spans-migration)。

## 已移除

### `mastra deploy` 命令

CLI 中已移除 `mastra deploy` 命令。此变更通过移除特定厂商的部署逻辑来简化 CLI。

迁移时，请选择适合你的[部署平台](/docs/deployment/overview)。

### `mastra build` 的 `--env` 标志

`mastra build` 命令中已移除 `--env` 标志。此变更简化了构建命令。

迁移时，请使用 `mastra start --env <env>` 在自定义环境中启动构建产物。

```diff
- mastra build --env production
+ mastra build
+ mastra start --env production
```

### `mastra dev` 的 `--port` 标志

`mastra dev` 命令中已移除 `--port` 标志。端口现在通过 Mastra 实例配置进行设置，使端口配置集中在一处。

迁移时，请在 Mastra 实例上使用 `server.port`，而不是 CLI 标志。

```ts
const mastra = new Mastra({
  server: {
    port: 3001,
  },
})
```

### CLI 中的 Telemetry 选项

CLI 命令中的 `telemetry` 选项（包括 `--no-telemetry` / `-nt` 标志）已移除。Telemetry 配置不再由 CLI 提供，这是因为相关功能已迁移到 observability 包。

迁移时，请从 CLI 命令中移除 telemetry 标志，并使用 `@mastra/observability` 提供 tracing 功能。
