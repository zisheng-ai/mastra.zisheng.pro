此模板是编写各迁移指南的样式规范。请以此为依据组织本目录中的文件，不得偏离此结构。

请遵循 `.cursor/rules/writing-documentation.mdc` 中关于正文写作的说明。

找出所有需要记录的变更后，应将其分为“已变更”和“已移除”两大类。

示例：

```md
## Changed

## Removed
```

所有变更都必须放在这两个部分下。

每项变更（无论属于“已变更”还是“已移除”）都应使用三级标题。必须严格遵循此格式。

示例：

```md
## Changed

### `oldFunction` to `newFunction`
```

标题就位后，每项变更都必须遵循固定结构，不得偏离。

先用一两句话简要描述变更，再用一句话说明变更原因。

每项变更的第三部分必须说明如何将现有代码迁移到新版本。内容应简洁清晰，同时尽量不要删减过多信息。随后必须提供使用“diff”语法的代码块，并在其中展示待修改代码的迁移前后示例。

示例：

````md
## Changed

### `oldFunction` to `newFunction`

The `oldFunction` has been renamed to `newFunction`. This change improves clarity and consistency across the API.

To migrate, replace all instances of `oldFunction` with `newFunction` in your codebase.

```diff
- const result = oldFunction(args);
+ const result = newFunction(args);
```
````

如果迁移并非简单的查找替换，可在代码块前添加说明。如果需要多个步骤，请使用编号列表清楚说明每一步。
