# Agent 概览

Agent 使用 LLM 和 Tool 解决开放式任务。它们会推理目标，并决定使用哪些 Tool。它们会保留对话记忆并持续迭代，直到模型给出最终答案或满足可选的停止条件。

Agent 会生成结构化响应，你可以在 UI 中渲染这些响应或以编程方式处理。你可以直接使用 Agent，也可以将其组合到 Workflow 或多 Agent 系统中。

## 何时使用 Agent {/* #when-to-use-agents */}

当任务是开放式的，且无法预先确定具体步骤时，请使用 Agent。Agent 会决定调用哪些 Tool、循环多少次以及何时停止。你只需提供目标和约束，无需定义每个步骤。对于控制流明确、预先确定的多步骤流程，请改用 [Workflow](/docs/workflows/overview)。

观看 [Mastra Agent 快速入门](https://www.youtube.com/watch?v=G8tXjcseNjg)，快速了解如何创建和测试 Mastra Agent。

## 快速开始 {/* #quickstart */}

从 `@mastra/core` 实例化 `Agent` 类并提供必填属性，以创建 Agent：

```typescript title="src/mastra/agents/test-agent.ts"
import { Agent } from '@mastra/core/agent'

export const testAgent = new Agent({
  id: 'test-agent',
  name: 'Test Agent',
  instructions: 'You are a helpful assistant.',
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

`instructions` 定义 Agent 的行为、个性和能力。它们是系统级提示词，用于确立 Agent 的核心身份和专长。`model` 使用 Mastra 的[模型路由器](/models)，以 `'provider/model-name'` 格式指定。

要让整个应用都能使用该 Agent，请将其注册到 Mastra 实例（通常位于 `src/mastra/index.ts`）中：

```typescript {5} title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { testAgent } from './agents/test-agent'

export const mastra = new Mastra({
  agents: { testAgent },
})
```

注册后，可以从 Workflow、Tool 或其他 Agent 调用它，并可访问内存、日志和可观测性功能等共享资源。

有关可用属性和配置的更多信息，请参阅 [Agent 参考](/reference/agents/agent)。

:::tip

使用 [Studio](/docs/studio/overview) 通过不同消息测试 Agent，检查 Tool 调用和响应，并调试 Agent 行为。

:::

## 使用 Agent {/* #use-your-agent */}

注册后，使用 [`mastra.getAgentById()`](/reference/core/getAgentById) 获取 Agent。调用 `.generate()` 获得完整响应，或调用 `.stream()` 实时传输 token。你可以从 [Workflow 步骤](/docs/workflows/agents-and-tools)、[Tool](/docs/agents/using-tools)、[Mastra Client](/reference/client-js/mastra-client)、路由处理程序、[服务器适配器](/docs/server/server-adapters)或命令行调用 Agent。请参阅[指南](/guides)，了解如何在所选框架中使用 Agent。

从 Mastra 实例引用 Agent 时，请使用 `mastra.getAgentById()`，以确保它能访问实例级存储、日志和 Agent 注册表等共享服务。直接导入的 Agent 仍可使用自己的本地配置运行，但无法访问这些共享服务。

<Tabs>
  <TabItem value="generate" label=".generate()">
    在所有 Tool 调用和步骤完成后返回完整响应。结果包括 `text`、`toolCalls`、`toolResults`、`steps` 和 token `usage` 统计信息。

    有关响应结构（包括 Tool 调用和 Tool 结果的 payload），请参阅 [`Agent.generate()` 参考](/reference/agents/generate)。

    ```ts
    const agent = mastra.getAgentById('test-agent')
    const response = await agent.generate('Help me organize my day')
    console.log(response.text)
    ```
  </TabItem>

  <TabItem value="stream" label=".stream()">
    返回一个可在 token 到达时使用的流。结果公开 `textStream` 用于增量输出，还公开 `toolCalls`、`toolResults`、`steps` 和 token `usage` 的 Promise，它们会在流结束时解析。

    有关流结构（包括 Tool 调用和 Tool 结果的 payload），请参阅 [`MastraModelOutput` 参考](/reference/streaming/agents/MastraModelOutput)。

    ```ts
    const agent = mastra.getAgentById('test-agent')
    const stream = await agent.stream('Help me organize my day')

    for await (const chunk of stream.textStream) {
      process.stdout.write(chunk)
    }
    ```
  </TabItem>
</Tabs>

## 多 Agent 系统 {/* #multi-agent-systems */}

多 Agent 系统使用多个 Agent 解决对单个 Agent 而言过于宽泛或专业化的任务。你无需构建一个包含数十个 Tool 和冗长指令集的 Agent，而是可以将职责拆分给各个专用 Agent，再由协调者汇总结果。

阅读[多 Agent 系统概念概览](/guides/concepts/multi-agent-systems)，了解如何在 Mastra 中应用不同模式。
