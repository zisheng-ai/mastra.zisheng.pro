# Harness 概览

Harness 让 Agent 能够持续完成长期、复杂的目标，同时确保其工作持久、可见且可引导。它会在重试和中断期间保留进度，并让用户和其他系统能够检查进度、补充上下文、批准操作、重新引导 Agent 或将其停止。

在 Mastra 中，Harness 是指用于管理 Agent、使其工作不局限于一次不间断运行的一组能力。你可以单独采用其中某项能力，也可以按需组合使用。

[`AgentController`](/docs/harness/agent-controller) 是专为交互式 Agent 应用设计的 Harness。它在基础 [`Agent`](/docs/agents/overview) 循环之上，增加了按用户或任务隔离的 Session、持久化的 thread 和状态、可切换的模式与模型、Tool 权限和审批、Subagent 编排，以及事件和显示状态的 stream。

只要工作需要持续一段时间，Agent Harness 就能发挥作用。常见示例包括：推动变更完成 CI 和审查的 coding agent；并行协调多项任务的软件工厂；随事件发展而调整的 SRE Agent；以及根据客户、信号和对话变化作出响应的市场推广 Agent。

## 何时使用 Harness {/* #when-to-use-a-harness */}

请根据 Agent 的需求选择起点。你可以使用一项或多项能力。

| 如果你希望 | 从这里开始 | 原因 |
| - | - | - |
| 在客户端断开连接或 Server 重启后仍保留运行 | [持久化 Agent](/docs/long-running-agents/durable-agents) | 持久化运行状态，并允许客户端重新连接到其 stream。 |
| 在不阻塞的情况下运行耗时的 Tool、Workflow 或 Subagent | [后台任务](/docs/long-running-agents/background-tasks) | 异步完成工作，并将结果返回给 Agent。 |
| 让 Agent 持续工作，直到达成目标 | [目标](/docs/long-running-agents/goals) | 评估 thread 范围内的目标，直到目标完成或达到运行预算。 |
| 按周期时间自动开始工作 | [Schedules](/docs/long-running-agents/schedules) | 按 cron Schedule 启动隔离运行，或向现有 thread 发送 prompt。 |
| 补充上下文、重新引导进行中的工作，或唤醒空闲 thread | [Signals](/docs/long-running-agents/signals) | 立即传递输入，或保留到下一轮再传递。 |
| 响应 GitHub、Slack、持续集成或其他外部系统中的变化 | [Signal Provider](/docs/long-running-agents/signal-providers) | 跟踪订阅，并将匹配的事件转发到 Agent thread。 |
| 构建包含 Session、模式、状态、审批和事件的交互式产品 | [AgentController](/docs/harness/agent-controller) | 围绕共享 Agent 运行时托管隔离 Session。 |
| 让用户引导交互式运行、将后续工作加入队列或停止运行 | [AgentController](/docs/harness/agent-controller) | 通过每个 Session 提供运行控制。 |
