# 部署概览

Mastra 应用可以部署到任何与 Node.js 兼容的环境。你可以部署 Mastra Server、与现有 Web 框架集成、部署到云 Provider，或使用 [Mastra platform](/docs/mastra-platform/overview) 实现 Observability、Studio 和 Server 部署。

## 运行时支持 {/* #runtime-support */}

Mastra 可以在以下任何运行时环境中运行：

- Node.js `v22.13.0` 或更高版本
- Bun
- Deno
- Cloudflare

## 部署选项 {/* #deployment-options */}

### Mastra Server {/* #mastra-server */}

Mastra 提供了一个由 Hono 驱动、可独立部署的 [Server](/docs/server/mastra-server)。使用 `mastra build` 命令构建应用，并将输出部署到你选择的 VM、容器或 PaaS 平台。

当你需要完全控制基础设施、使用长时间运行的进程或 WebSocket 连接时，请使用此选项。[Mastra Server 部署指南](/docs/deployment/mastra-server)提供了更多详细信息。

### Monorepo {/* #monorepo */}

将 Mastra Server 作为 monorepo 设置的一部分进行部署，方法与独立部署相同。

阅读 [monorepo 部署](/docs/deployment/monorepo)。

### Mastra platform {/* #mastra-platform */}

[Mastra platform](/docs/mastra-platform/overview) 提供三种产品，用于部署、监控和管理使用 Mastra 框架构建的 AI 应用：

- [**Observability**](/docs/mastra-platform/observability)：独立托管产品，可跨 Mastra 项目和部署搜索 Trace、日志和指标
- [**Studio**](/docs/mastra-platform/studio)：托管的可视化环境，用于测试 Agent、运行 Workflow 和检查 Trace
- [**Server**](/docs/mastra-platform/server)：将 Mastra 应用作为 API Server 运行的生产部署目标

请在 [Mastra platform 概览](/docs/mastra-platform/overview)中了解更多信息。

### 云 Provider {/* #cloud-providers */}

Mastra 应用可以部署到云 Provider 和 serverless 平台。Mastra 为 Vercel、Netlify 和 Cloudflare 提供可选的内置部署器，用于自动执行构建和部署流程。

如果你需要自动扩缩容、尽量减少基础设施管理，或已在使用其中某个平台，请使用此选项。

- [Amazon EC2](/guides/deployment/amazon-ec2)
- [AWS Lambda](/guides/deployment/aws-lambda)
- [Azure App Services](/guides/deployment/azure-app-services)
- [Cloudflare](/guides/deployment/cloudflare)
- [Digital Ocean](/guides/deployment/digital-ocean)
- [Kubernetes](/guides/deployment/kubernetes)
- [Netlify](/guides/deployment/netlify)
- [Vercel](/guides/deployment/vercel)

### Sandbox {/* #sandbox */}

将 Mastra Server 部署到临时 Workspace Sandbox（例如 Vercel Sandbox 或 E2B），几秒内即可获得可用的公开 URL。

此选项适用于即时预览、从 CI 流水线部署、验证由 Agent 构建的应用，或运行每用户隔离的不可信实例。请阅读 [Sandbox 部署指南](/docs/deployment/sandbox)。

### Web 框架 {/* #web-framework */}

当 Mastra 与 Web 框架集成时，它会使用框架的标准部署流程与应用一起部署。以下指南介绍部署时针对各框架的配置要求。

将 Mastra 添加到现有 Next.js 或 Astro 应用时，请使用这些指南。

- [在 Vercel 上与 Next.js 配合使用](/docs/deployment/web-framework#with-nextjs-on-vercel)
- [在 Vercel 上与 Astro 配合使用](/docs/deployment/web-framework#with-astro-on-vercel)
- [在 Netlify 上与 Astro 配合使用](/docs/deployment/web-framework#with-astro-on-netlify)

## Workflow runner {/* #workflow-runners */}

Mastra Workflow 默认使用内置执行引擎运行。对于需要托管基础设施的生产工作负载，也可以将 Workflow 部署到 [Inngest](https://www.inngest.com) 等专用平台，这些平台提供步骤记忆、自动重试和实时监控。

请访问 [Workflow Runner 指南](/docs/deployment/workflow-runners)了解执行选项，并参阅 [Inngest 部署指南](/guides/deployment/inngest)获取设置说明。

## Worker {/* #workers */}

在生产部署中，Mastra 可以在独立于 API Server 的专用 Worker 进程中运行 Workflow 编排、cron 调度和后台 Tool 执行。这样可以独立扩展各项功能并隔离故障。详情请参阅 [Workers](/docs/deployment/workers)。
