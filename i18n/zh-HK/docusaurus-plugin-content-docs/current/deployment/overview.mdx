# 部署概覽 {/* #deployment-overview */}

Mastra 應用程式可以部署至任何兼容 Node.js 的環境。你可以部署 Mastra 伺服器、與現有網頁框架整合、部署至雲端 Provider，或使用 [Mastra 平台](/docs/mastra-platform/overview)來進行可觀測性分析、使用 Studio，以及部署伺服器。

## Runtime 支援 {/* #runtime-support */}

Mastra 可以在以下任何 Runtime 環境中運行：

- Node.js `v22.13.0` 或更新版本
- Bun
- Deno
- Cloudflare

## 部署選項 {/* #deployment-options */}

### Mastra 伺服器 {/* #mastra-server */}

Mastra 提供由 Hono 驅動、可獨立部署的[伺服器](/docs/server/mastra-server)。使用 `mastra build` 命令建置應用程式，然後將輸出部署至你偏好的 VM、容器或 PaaS 平台。

當你需要完全控制基礎設施、運行長時間程序或使用 WebSocket 連線時，請選用此方式。詳情請參閱 [Mastra 伺服器部署指南](/docs/deployment/mastra-server)。

### Monorepo {/* #monorepo */}

按照獨立部署的相同方式，將 Mastra 伺服器部署為 monorepo 設定的一部分。

請參閱 [monorepo 部署](/docs/deployment/monorepo)。

### Mastra 平台 {/* #mastra-platform */}

[Mastra 平台](/docs/mastra-platform/overview)提供三項產品，用於部署、監察和管理以 Mastra 框架建置的 AI 應用程式：

- [**Observability**](/docs/mastra-platform/observability)：獨立的託管產品，可搜尋多個 Mastra 項目及部署的 Trace、日誌和指標
- [**Studio**](/docs/mastra-platform/studio)：託管的視覺化環境，可用於測試 Agent、運行 Workflow，以及檢視 Trace
- [**Server**](/docs/mastra-platform/server)：生產環境部署目標，以 API 伺服器形式運行你的 Mastra 應用程式

詳情請參閱 [Mastra 平台概覽](/docs/mastra-platform/overview)。

### 雲端 Provider {/* #cloud-providers */}

Mastra 應用程式可以部署至雲端 Provider 和無伺服器平台。Mastra 為 Vercel、Netlify 和 Cloudflare 提供可選用的內置 deployer，以自動執行建置和部署流程。

如需自動擴縮、盡量減少基礎設施管理，或你已在使用其中一個平台，請選用此方式。

- [Amazon EC2](/guides/deployment/amazon-ec2)
- [AWS Lambda](/guides/deployment/aws-lambda)
- [Azure App Services](/guides/deployment/azure-app-services)
- [Cloudflare](/guides/deployment/cloudflare)
- [Digital Ocean](/guides/deployment/digital-ocean)
- [Kubernetes](/guides/deployment/kubernetes)
- [Netlify](/guides/deployment/netlify)
- [Vercel](/guides/deployment/vercel)

### Sandbox {/* #sandbox */}

將 Mastra 伺服器部署至臨時 Workspace Sandbox（例如 Vercel Sandbox 或 E2B），並可在數秒內取得可公開存取的即時 URL。

此方式適合用於即時預覽、從 CI pipeline 部署、驗證由 Agent 建置的應用程式，或為每位使用者運行不受信任的獨立 instance。請參閱 [Sandbox 部署指南](/docs/deployment/sandbox)。

### 網頁框架 {/* #web-framework */}

Mastra 與網頁框架整合後，會使用該框架的標準部署流程，連同你的應用程式一併部署。以下指南涵蓋部署時各框架的特定設定要求。

如要將 Mastra 加入現有 Next.js 或 Astro 應用程式，請參閱以下指南。

- [在 Vercel 上配合 Next.js 使用](/docs/deployment/web-framework#with-nextjs-on-vercel)
- [在 Vercel 上配合 Astro 使用](/docs/deployment/web-framework#with-astro-on-vercel)
- [在 Netlify 上配合 Astro 使用](/docs/deployment/web-framework#with-astro-on-netlify)

## Workflow runner {/* #workflow-runners */}

Mastra Workflow 預設使用內置執行引擎運行。對於需要託管基礎設施的生產工作負載，也可以將 Workflow 部署至 [Inngest](https://www.inngest.com) 等專用平台；這些平台提供步驟 memoization、自動重試和實時監察功能。

如要了解執行選項，請參閱 [Workflow runner 指南](/docs/deployment/workflow-runners)；如要了解設定方法，請參閱 [Inngest 部署指南](/guides/deployment/inngest)。

## Worker {/* #workers */}

在生產環境部署中，Mastra 可以在與 API 伺服器分開的專用 worker 程序內，運行 Workflow orchestration、cron 排程和背景 Tool 執行。這讓你可以獨立擴縮各項功能，並隔離故障。詳情請參閱 [Worker](/docs/deployment/workers)。
