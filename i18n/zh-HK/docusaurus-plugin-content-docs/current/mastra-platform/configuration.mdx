# 設定

部署至 Mastra platform 時，CLI 會產生 `.mastra-project.json` 設定檔，並從平台及（可選）本機 `.env` 檔案解析環境變數。

本頁說明這兩種機制。

## 項目設定

首次執行 [`mastra deploy`](/docs/mastra-platform/deploy) 時，系統會自動產生 `.mastra-project.json` 檔案。它會將本機項目連結至平台項目。[GitHub 整合](/docs/mastra-platform/github)亦會將同一檔案寫入已連結的 repository。

請將它提交至版本控制，確保之後的部署（包括從 CI 部署）都以正確項目為目標。

你的檔案大致如下：

```json title=".mastra-project.json"
{
  "projectId": "06daaac4-89b1-40f0-9e3f-0993e039a627",
  "projectName": "my-project",
  "organizationId": "org_01KNA5YSP52SX4M6YVSXC2MAHP"
}
```

| 欄位 | 說明 |
| - | - |
| projectId | 項目的 UUID，在建立項目時指派。 |
| projectName | 便於閱讀的項目名稱，用作控制台及 CLI 輸出的顯示標籤。 |
| organizationId | 擁有項目的組織。所有部署、API 金鑰及資源都限定於此組織。 |

## 環境變數

本機 env 檔案並非必要。[`mastra deploy`](/docs/mastra-platform/deploy) 會從三個來源解析變數：

- **受管理變數**：由[託管式資料庫](/docs/mastra-platform/database)等平台資源注入。這些變數由平台定義，你無法編輯。
- **已儲存變數**：透過控制台儲存於項目或環境。每次部署都會原樣使用，無須本機檔案。
- **本機 env 檔案**：部署會在上述變數之上疊加明確指定的 `--env-file`，或目前環境中的 `.env` 和 `.env.local` 檔案。`.env.local` 中的變數會覆寫 `.env` 中的變數。

如要將部署固定使用特定 env 檔案，而不依賴預設選擇，請傳入 `--env-file`：

```bash
mastra deploy --env-file .env.production --yes
```

部署前請檢查並清理本機 env 檔案，避免上載只供開發使用或屬於個人的秘密資料。

### Observability

以下環境變數用於設定 Mastra platform 上的 Observability 產品。

| 變數 | 說明 |
| - | - |
| `MASTRA_PLATFORM_ACCESS_TOKEN` | 限定於組織的存取權杖。CLI 會在佈建可觀測性時寫入此值，並用它向平台驗證身份。 |
| `MASTRA_PROJECT_ID` | 平台項目的 UUID。`MastraPlatformExporter` 用它將可觀測性資料連結至平台項目。Studio 和 Server 部署會從 `.mastra-project.json` 讀取項目 ID。 |
| `MASTRA_PLATFORM_OBSERVABILITY_ENDPOINT` | 可選的可觀測性端點覆寫值。只有在本機平台開發時才會自動設定。預設為 `https://observability.mastra.ai`。 |
| `MASTRA_ORG_ID` | 覆寫 CLI 指令所使用的作用中組織。受支援的指令亦可透過 `--org` 旗標設定。 |

`MastraPlatformExporter` 會讀取 `MASTRA_PLATFORM_ACCESS_TOKEN`，以驗證平台匯出的身份。

## 多個環境

單一項目會在多個[環境](/docs/mastra-platform/environments)中執行同一程式碼庫，例如 `production` 和 `staging`。每個環境都有自己的 URL、已儲存變數及部署記錄。一個 `.mastra-project.json` 檔案即可涵蓋所有環境：

```bash
mastra deploy --env production --yes
mastra deploy --env staging --env-file .env.staging --yes
```

:::note
舊版平台規定每個環境使用一個項目。環境功能已取代這種模式，因此請保留單一項目，並改為部署至不同環境。
:::
