# Mastra platform 上的 Trace Intelligence

Trace Intelligence 可在 Agent 互動中找出反覆出現的模式。它會分析 Mastra Observability 擷取的 Trace，按四個維度產生 Trace signal，並將相似的 Trace signal 聚合成主題。

你可以使用 Trace Intelligence 探究以下問題：

- 使用者嘗試完成甚麼？
- 哪些目標通常能成功、仍未解決或受到阻礙？
- 成功及失敗的互動分別出現哪些 Agent 行為？
- 使用者情緒與目標及結果有何關係？

:::warning 私人 beta
Trace Intelligence 以邀請形式向指定 Mastra platform 項目開放。
:::

## 取得存取權

1. 提交 [Trace Intelligence 私人 beta 表格](https://mastra.ai/trace-intelligence)申請存取權。
1. 確認已啟用 [Mastra platform Observability](/docs/mastra-platform/observability)，而已完成的 Agent Trace 會顯示於 **Traces** 下。
1. 至少需要 `@mastra/core@1.53.0` 及 `mastra@1.20.2`。升級項目，然後為已加入計劃的項目部署或重新部署 Studio。私人 beta 期間不支援本機 Studio 及只部署伺服器的方式。
1. 開啟已部署的 Studio，然後在側欄選擇 **Intelligence**。
1. 將具代表性的流量傳送至 Agent，並預留時間進行分析。

Mastra 將項目加入計劃後，你無須變更 Agent 定義或呼叫。

### 資料何時可用

Trace Intelligence 需要從同一 Agent 取得足夠的已處理 Trace，才能識別反覆出現的模式。一般至少處理該 Agent 的 **100 個已完成 Trace** 後，才會提供初始主題。

由於分析管線以非同步方式運行，**Traces** 下的 Trace 數目可能在 Trace Intelligence 準備就緒前已達 100。達到門檻後，處理可能仍需數分鐘。無法分析的 Trace 不會計算在內，因此 100 是最低數目，而非確切的 UI 觸發條件。

收到更多 Trace 時，Trace Intelligence 會自動更新。Studio 至少需要兩種 Trace signal 類型的主題，才能顯示關係流程。

請使用具代表性的流量。少量重複測試提示可能產生欠代表性的結果，例如只有一個廣泛主題或大部分屬於 Noise。

## 了解分析

每個可分析且已完成的 Trace 都會產生四個 Trace signal：

| Trace signal | 含義 |
| - | - |
| **Goal** | 使用者希望達成或完成的事項。 |
| **Outcome** | 最終的完成、部分完成、受阻、失敗、未解決或不明確狀態。 |
| **Behavior** | 可觀察的 Agent 操作及模式，包括使用 Tool、遺漏、重試、失敗及復原。 |
| **Sentiment** | 使用者的情緒狀態或態度。 |

主題是由相似 Trace signal 產生的群集。每種 Trace signal 類型會獨立聚類。同一個 Trace 在 Goal、Outcome、Behavior 及 Sentiment 每個維度中，都可以屬於不同主題。

### 主題及關係

流程圖會連接相鄰 Trace signal 欄中的主題：

- **節點**代表主題。其數目是在所選 snapshot 中指派給該主題的不同 Trace 數目。
- **帶狀線**連接在兩個相鄰欄中都指派了主題的 Trace。寬度代表共用 Trace 數目。
- 將游標移至或聚焦節點或帶狀線，即可單獨顯示其關係。

流程顯示關聯，而非因果關係或執行次序。例如 Goal 與 Outcome 之間的帶狀線，代表兩個主題都在同一批 Trace 中出現；它並不表示該目標導致該結果。

### 分佈、Other 及 Noise

流程下方的卡片顯示每個 Trace signal 的主題分佈：

- **Trace count**：所選 snapshot 中指派給某主題的不同 Trace 數目。
- **Stage share**：該 Trace signal 所分析的 Trace 中，指派給某主題的百分比。

Studio 會顯示每種 Trace signal 類型最常見的主題。為保持總數正確而不令圖表過於擁擠，它可能將較小的主題合併至 **Other**。

**Noise** 包含在所選 snapshot 中未能持續配對至反覆主題的摘要。它不一定代表錯誤或低質素互動。Noise 可以包括罕見請求及新出現的模式，亦可包括含糊的互動或不相關個案。Noise 佔比較高，可能代表流量變化很大，或資料不足以建立穩定主題。

### Snapshot

snapshot 是涵蓋一組 Trace 的移動分析視窗。不同 snapshot 可以重疊，因此請勿將它們的 Trace 數目相加。由於不同視窗之間的流量可以改變，請同時比較 Trace count 及 stage share。

主題可在不同 snapshot 中持續、消失、分拆、合併或再次出現。請將主題名稱及說明視為產生的摘要，而非固定分類法。

## 使用 Trace Intelligence 頁面

1. 使用 **Agent** 選擇器切換至已有可用分析的 Agent。Agent 要在首批主題準備就緒後才會顯示。
1. 在流程中選擇主題，將每一欄篩選為包含該主題的 Trace。
1. 選擇 **View theme details**，檢查其說明、Trace count、stage share、產生的例子及歷史記錄。
1. 選擇 **Clear filter** 還原完整流程。

你亦可以：

- 在分佈卡片選擇主題，以開啟其詳細資料及產生的例子摘要。
- 在分佈卡片選擇 **Noise**，檢查其分佈及產生的例子摘要。
- 拖動分佈卡片以重新排列 Trace signal 欄，從不同角度查看關係。
- 使用時間線選擇 snapshot，或選擇 **Play** 觀看主題隨時間變化。
- 開啟主題的歷史記錄，查看它是否持續出現，以及涵蓋範圍如何改變。

如 snapshot 有超過 2,000 個 Trace，則無法按主題篩選流程。請選擇另一個 snapshot，或清除作用中篩選以返回完整流程。你仍可從分佈卡片查看主題及 Noise 詳細資料。

## 疑難排解

### 側欄沒有 Intelligence

確認 Mastra 已將正確項目加入計劃、你使用與 beta 相容的 Mastra 版本，並已重新部署 Studio。私人 beta 不支援本機 Studio。

### 找不到某個 Agent

確認其已完成 Trace 已列於 **Traces** 下。Agent 只會在首批主題準備就緒後列出。如最近才達到 100 個 Trace，請預留時間進行非同步處理。

### 無法使用關係流程

流程至少需要兩種 Trace signal 類型的主題。請繼續傳送具代表性的流量，並等待處理完成。

### 大部分摘要都是 Noise

收集更多具代表性的流量，並比較較後的 snapshot。多變或罕見的互動較難分組，而重複的測試提示可能產生欠代表性的分佈。

## 私人 beta 限制

- Trace Intelligence 只適用於已加入計劃的項目，並須在已部署的 Studio 中使用。
- 初始分析要求每個 Agent 至少有 100 個已處理 Trace；部分 Agent 可能需要更多。
- 結果取決於已擷取 Trace 的多樣性及質素。
- Trace signal 摘要、主題標籤、聚類、門檻及 UI 行為可能在 beta 期間變更。

報告意見時，請附上組織 ID、項目 ID、Agent ID、所選 snapshot，以及能說明問題的主題或 Noise 例子。
