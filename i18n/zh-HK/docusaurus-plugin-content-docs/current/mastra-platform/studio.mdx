# Mastra platform 上的 Studio

Mastra platform 上的 Studio 是託管式視覺 Workspace，可用於測試 Agent、執行 Workflow 及檢查 Trace。如果你想與團隊共用 Studio，而不自行託管 Studio UI，便可使用它。

你可以如下所示從 CLI 部署 Studio，或連結 GitHub repository 以推送觸發部署。連結 repository 的流程請參閱 [GitHub 整合](/docs/mastra-platform/github)。

:::note
`mastra studio deploy` 是較早期的分拆部署途徑。新項目應使用統一的 [`mastra deploy`](/docs/mastra-platform/deploy) 指令，該指令加入部署前驗證、環境及由 CLI 管理的資料庫。
:::

## 快速開始

<Steps>
  <StepItem>
    按照[開始使用指南](/docs)建立你的第一個 Mastra 項目。
  </StepItem>

  <StepItem>
    全域安裝 `mastra` CLI：

    ```bash npm2yarn
    npm install -g mastra
    ```
  </StepItem>

  <StepItem>
    使用單一指令部署 Studio：

    ```bash
    mastra studio deploy
    ```

    部署成功後，CLI 會輸出已部署 Studio instance 的 URL。
  </StepItem>
</Steps>

首次部署時，CLI 會提示你建立新項目或選擇現有項目，然後在項目目錄建立 `.mastra-project.json` 檔案。此檔案會將本機項目連結至平台項目，並包含 `projectId`、`projectName` 及 `organizationId`。請將此檔案提交至 repository，讓 CI/CD 知道應部署至哪個項目。

## 部署的運作方式

`mastra studio deploy` 指令會建構項目，並將 `src/mastra/` 編譯至 `.mastra/output`。它會將輸出封裝為 artifact ZIP，然後上載並部署至雲端 Sandbox。

部署會依次經歷 **queued → uploading → starting → running**，發生問題時則為 **failed**。如果項目已有 Sandbox 正在運行，平台會就地更新，不會造成停機；否則會建立全新的 Sandbox。instance URL 按項目 slug 指派，並在不同部署之間保持穩定。

完整旗標清單及 CI/CD 用法請參閱 [`mastra studio deploy` CLI 參考](/reference/cli/mastra#mastra-studio-deploy)。

## 環境檔案

本機 env 檔案並非必要。項目目錄中有 `.env` 或 `.env.*` 檔案時，部署會將其中的環境變數一併封裝。

存在多個 env 檔案時，CLI 會提示你選擇。如要以非互動方式選擇，請傳入 `--env-file`：

```bash
mastra studio deploy --env-file .env.production --yes
```

如要在 `production` 和 `staging` 執行同一程式碼庫，請改用統一的 [`mastra deploy --env`](/docs/mastra-platform/deploy#deploy-to-another-environment) 指令。[環境](/docs/mastra-platform/environments)已取代以往每個環境使用一個項目的模式。

## 以非互動方式建立新項目

`mastra studio deploy` 可在首次執行時建立項目。如果 `--project <name>` 與任何現有項目不符，CLI 會以該值作為新項目名稱，並在確認後建立。配合 `--yes` 使用即可完全以指令碼執行：

```bash
mastra studio deploy --project "my-new-project" --yes
```

在 CI 或 AI 編程助手中，請使用此方式，而非只能互動使用的 `mastra studio projects create`。
