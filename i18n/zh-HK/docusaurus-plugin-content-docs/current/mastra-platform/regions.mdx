# 區域

區域控制平台環境的執行位置、[託管資料庫](/docs/mastra-platform/database)的設置位置，以及 Observability 資料的儲存位置。區域會在建立環境時固定，之後無法變更。

Mastra platform 目前提供 `us` 和 `eu` 兩個資料駐留地區，由 Railway 上的特定運算區域支援。資料庫和 Observability 會自動跟隨環境的區域。

## 選擇區域 {/* #choose-a-region */}

建立環境或首次部署至環境時，請傳入 `--region`：

```bash
mastra deploy --env production --region eu
mastra env create staging --region us
```

`mastra deploy --region` 和 `mastra env create --region` 都接受 `us` / `eu` 簡寫，或下表所列的標準 Railway 區域代碼。建議使用簡寫。

未傳入區域時，預設值為 `us`，並會解析為 `pdx`（俄勒岡州波特蘭）。

## 可用區域 {/* #available-regions */}

資料駐留選擇器提供分佈於兩個地區的四個 Railway 區域。`us` 和 `eu` 簡寫會解析為各地區中以底線標示的預設區域。

| 地區 | Railway 代碼 | 位置 |
| - | - | - |
| `us` | `pdx`（預設） | 俄勒岡州波特蘭 |
| `us` | `iad` | 維珍尼亞州阿什本 |
| `us` | `sfo` | 加利福尼亞州三藩市 |
| `eu` | `ams`（預設） | 荷蘭阿姆斯特丹 |

如需將環境固定於特定數據中心，請直接傳入 Railway 代碼。傳入 `us` 會選擇 `pdx`，傳入 `eu` 則會選擇 `ams`。

:::note
部署管線中還有其他 Railway 區域（例如新加坡 `sin`），但資料駐留選擇器尚未提供這些區域，因為託管資料庫和 Observability 目前無法在美國及歐盟以外就近設置。傳入無法識別的區域時，系統會回退至美國預設區域，而不會固定於所傳入的區域。
:::

## 託管資料庫位置 {/* #hosted-database-placement */}

附加[環境範圍資料庫](/docs/mastra-platform/database)時，平台會選擇最接近環境的 Provider 區域。此決定以伺服器為準，因此在 `mastra env db create <env>` 明確指定的 `--region` 會被忽略。環境區域才是最終依據。

| 環境區域 | Turso 區域 | Postgres (Neon) 區域 |
| - | - | - |
| `pdx` | `sjc`（聖荷西） | `aws-us-west-2`（俄勒岡州） |
| `iad` | `iad`（阿什本） | `aws-us-east-1`（北維珍尼亞） |
| `sfo` | `sjc`（聖荷西） | `aws-us-west-2`（俄勒岡州） |
| `ams` | `ams`（阿姆斯特丹） | `aws-eu-central-1`（法蘭克福） |

項目範圍資料庫（由不同環境共用）並非綁定於單一環境，因此接受明確指定的 `--region`。此旗標須使用 Provider 區域 ID，而非 `us` / `eu` 簡寫：

```bash
mastra env db create --kind turso --region fra
mastra env db create --kind neon --region aws-us-east-1
```

Turso 提供超過 20 個區域，而 Postgres (Neon) 則可在美國、歐盟及亞太區的 AWS 和 Azure 區域使用。完整清單請參閱 [Turso 區域清單](https://docs.turso.tech/features/data-edge#locations)及 [Neon 區域清單](https://neon.com/docs/introduction/regions)。如果傳入 Provider 不支援的代碼，附加時便會失敗，並顯示 Provider 的錯誤。

## Observability 並置 {/* #observability-co-location */}

Observability 擷取目前在兩個區域執行：**美國**（愛荷華州，`us-central1`）及**歐盟**（阿姆斯特丹）。每個環境的 Trace、日誌和指標都會路由至符合其資料駐留地區的擷取區域：

| 環境區域 | Observability 區域 |
| - | - |
| `pdx`、`iad`、`sfo`、`us` 簡寫 | 美國（愛荷華州） |
| `ams`、`eu` 簡寫 | 歐盟（阿姆斯特丹） |

運算及資料庫可設於更多 Railway 和 Provider 區域，超出 Observability 支援的範圍，因此並非每種組合都能完全並置。`us` 地區的環境一定會將遙測資料傳送至美國擷取區域，而 `eu` 地區的環境一定會傳送至歐盟擷取區域，即使底層 Railway 區域位於擷取端點未直接覆蓋的特定城市亦然。資料駐留會在地區層級維持；來自 `eu` 環境的遙測資料絕不會跨境進入美國。
