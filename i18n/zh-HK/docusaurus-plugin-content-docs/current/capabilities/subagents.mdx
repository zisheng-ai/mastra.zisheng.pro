# Subagent

**新增於：** `@mastra/core@1.8.0`

Subagent 是另一個 Agent 可以向其委派任務的專門 Agent。將它們加至父 Agent 的 `agents` property，然後呼叫 [`Agent.stream()`](/reference/streaming/agents/stream) 或 [`Agent.generate()`](/reference/agents/generate)。父 Agent 會根據其指示和各 Subagent 的 `description`，決定何時及如何委派任務。

## 何時使用 Subagent

當任務需要具備不同專長的 Agent 合作時，請使用 Subagent。父 Agent 決定何時委派，並將 context 傳給各 Subagent，然後綜合它們的結果。

常見使用情況：

- 一個 Agent 收集資料、另一個 Agent 製作內容的研究及寫作 Workflow
- 每個階段都需要不同專業知識的多步驟任務
- 需要精細控制委派行為的任務

:::note

協調 Subagent 的父 Agent 通常稱為 supervisor。Supervisor pattern 是在 Mastra 建立多 Agent 系統的方法之一。其他 pattern 請參閱[概念概覽](/guides/concepts/multi-agent-systems)。

:::

## 快速開始

以清晰的描述定義 Subagent，然後將它們加至父 Agent：

```typescript title="src/mastra/agents/parent-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'
import { LibSQLStore } from '@mastra/libsql'

const researchAgent = new Agent({
  id: 'research-agent',
  // highlight-next-line
  description: 'Gathers factual information and returns bullet-point summaries.',
  model: '__GATEWAY_OPENAI_MODEL_MINI__',
})

const writingAgent = new Agent({
  id: 'writing-agent',
  // highlight-next-line
  description: 'Transforms research into well-structured articles.',
  model: '__GATEWAY_OPENAI_MODEL_MINI__',
})

// highlight-start
const parentAgent = new Agent({
  id: 'parent-agent',
  instructions: `You coordinate research and writing using specialized agents.
    Delegate to research-agent for facts, then writing-agent for content.`,
  model: '__GATEWAY_OPENAI_MODEL__',
  agents: { researchAgent, writingAgent },
  memory: new Memory({
    storage: new LibSQLStore({ id: 'storage', url: 'file:mastra.db' }),
  }),
})
// highlight-end

const stream = await parentAgent.stream('Research AI in education and write an article', {
  maxSteps: 10,
})

for await (const chunk of stream.textStream) {
  process.stdout.write(chunk)
}
```

## 委派 hook

委派 hook 讓你在委派發生時截取、修改或拒絕委派。你可以在 `delegation` 選項下設定，位置可以是 Agent 的 `defaultOptions`，亦可以是每次呼叫。

### `onDelegationStart`

在父 Agent 委派給 Subagent 前呼叫。傳回物件以控制委派：

- `proceed: true`：允許委派（預設行為）
- `proceed: false`：以 `rejectionReason` 拒絕委派
- `modifiedPrompt`：改寫傳給 Subagent 的 prompt
- `modifiedMaxSteps`：限制 Subagent 的 iteration 次數

```typescript title="src/mastra/agents/parent-agent.ts"
const stream = await parentAgent.stream('Research AI trends', {
  maxSteps: 10,
  delegation: {
    onDelegationStart: async context => {
      console.log(`Delegating to: ${context.primitiveId}`)

      // Modify the prompt for a specific agent
      if (context.primitiveId === 'research-agent') {
        return {
          proceed: true,
          modifiedPrompt: `${context.prompt}\n\nFocus on 2024-2025 data.`,
          modifiedMaxSteps: 5,
        }
      }

      // Reject delegation after too many iterations
      if (context.iteration > 8) {
        return {
          proceed: false,
          rejectionReason: 'Max iterations reached. Synthesize current findings.',
        }
      }

      return { proceed: true }
    },
  },
})
```

`context` 物件包括：

| Property | 說明 |
| - | - |
| `primitiveId` | 獲委派的 Subagent ID |
| `prompt` | 父 Agent 正在傳送的 prompt |
| `iteration` | 目前的 iteration 編號 |
| `requestContext` | Subagent run 將會收到的 request context |

### 委派邊界的 request context

每次委派都會收到一個 request context，其 entry 由父 run 進行 shallow copy，但不包括 run scope 的身份 key。在 Subagent run 期間設定或刪除 entry，不會影響父 Agent 的 context。在 `context.requestContext` 上設定 entry，並在 `onDelegationStart` 中處理，即可將值傳給獲委派的 run：

```typescript title="src/mastra/agents/parent-agent.ts"
const stream = await parentAgent.stream('Research AI trends', {
  maxSteps: 10,
  delegation: {
    onDelegationStart: async context => {
      context.requestContext.set('audience', 'technical')
    },
  },
})
```

Subagent 會在其 Tool 和動態設定中讀取這些 entry，例如 `instructions: ({ requestContext }) => ...`。詳情請參閱 [Request Context](/docs/server/request-context)。如要與 durable Agent 配合使用，值必須可以 JSON serialize。

### `onDelegationComplete`

在委派完成後呼叫。用它檢查結果、提供意見，或停止執行：

- `context.bail()`：立即停止父 Agent 的 loop
- 傳回 `{ feedback: '...' }`：加入會儲存至父 Agent 記憶的意見，供後續 iteration 查看

```typescript title="src/mastra/agents/parent-agent.ts"
const stream = await parentAgent.stream('Research AI trends', {
  maxSteps: 10,
  delegation: {
    onDelegationComplete: async context => {
      console.log(`Completed: ${context.primitiveId}`)

      // Bail on errors
      if (context.error) {
        context.bail()
        return {
          feedback: `Delegation to ${context.primitiveId} failed: ${context.error}. Try a different approach.`,
        }
      }
    },
  },
})
```

`context` 物件包括：

| Property | 說明 |
| - | - |
| `primitiveId` | 已運行 Subagent 的 ID |
| `result` | Subagent 的回應 |
| `error` | 委派失敗時的錯誤 |
| `bail()` | 停止父 Agent loop 的 function |

## 訊息篩選

預設情況下，Subagent 會收到父 Agent 的完整對話 context。使用 `messageFilter` 控制共享哪些訊息，例如移除敏感資料或限制 context 大小。

```typescript title="src/mastra/agents/parent-agent.ts"
const stream = await parentAgent.stream('Research AI trends', {
  maxSteps: 10,
  delegation: {
    messageFilter: ({ messages, primitiveId, prompt }) => {
      // Remove messages containing sensitive data
      return messages
        .filter(msg => {
          const content =
            typeof msg.content === 'string' ? msg.content : JSON.stringify(msg.content)
          return !content.includes('confidential')
        })
        .slice(-10) // Only pass the last 10 messages
    },
  },
})
```

Callback 會收到 `messages`（完整對話記錄）、`primitiveId`（Subagent ID）及 `prompt`（委派 prompt）。請傳回篩選後的訊息 array。

## Subagent 結果 context

Subagent 完成後，父 Agent 的模型會在後續 iteration 中收到 Subagent 的文字回應。巢狀 Tool 呼叫及 Subagent metadata（例如 thread 及 resource ID）不會加至父 Agent 的模型 context。

應用程式碼和 UI integration 仍可檢查 Tool 結果 payload 中的 `subAgentToolResults` 及委派原始結果其餘部分。

這樣既可保留 debug 和顯示資料，亦不會將巢狀 Tool argument 或 output 傳回父 Agent 的下一次模型呼叫。

設定 `includeSubAgentToolResultsInModelContext`，即可在父 Agent 的模型 context 中加入完整 Subagent 結果，包括巢狀 Tool 結果及 Subagent metadata。

```typescript title="src/mastra/agents/parent-agent.ts"
await parentAgent.generate('Research AI trends', {
  delegation: {
    includeSubAgentToolResultsInModelContext: true,
  },
})
```

## Iteration 監察

父 Agent loop 的每次 iteration 完成後都會呼叫 `onIterationComplete`。用它監察執行或引導下一次 iteration，也可以提早停止執行。

```typescript title="src/mastra/agents/parent-agent.ts"
const stream = await parentAgent.stream('Research AI trends', {
  maxSteps: 10,
  onIterationComplete: async context => {
    console.log(`Iteration ${context.iteration}/${context.maxIterations}`)
    console.log(`Finish reason: ${context.finishReason}`)

    // Inject feedback to guide the agent
    if (!context.text.includes('recommendations')) {
      return {
        continue: true,
        feedback: 'Please include specific recommendations in your analysis.',
      }
    }

    // Stop early when the response is sufficient
    if (context.text.length > 1000 && context.finishReason === 'stop') {
      return { continue: false }
    }

    return { continue: true }
  },
})
```

傳回 `{ continue: true }` 以繼續 iteration，或傳回 `{ continue: false }` 以停止。可加入選用的 `feedback`，將引導內容注入對話。當 `feedback` 與 `continue: false` 一起使用時，模型可能會獲得最後一次 turn，以產生包含意見的文字回應，但只限目前 iteration 仍然 active（例如在 Tool 呼叫後）的情況，否則不會提供額外 turn。

## 記憶隔離

Mastra 會在委派期間隔離 Subagent 記憶。Subagent 會收到完整對話 context，以作出更好的決策，但只有其特定委派 prompt 和回應會儲存至其記憶。

運作方式：

1. **轉送完整 context**：父 Agent 委派時，Subagent 會收到父 Agent 對話中的所有訊息
1. **限定範圍的記憶儲存**：只有委派 prompt 和 Subagent 回應會儲存至 Subagent 的記憶
1. **每次呼叫使用全新 thread**：每次委派都使用獨有 thread ID，確保清晰分隔

因此，Subagent 既可取得所需 context，其記憶亦不會被父 Agent 的整段對話塞滿。詳情請參閱[多 Agent 系統中的記憶](/docs/memory/overview#memory-in-multi-agent-systems)。

## Tool 核准傳遞

Tool 核准會沿委派鏈傳遞。當 Subagent 使用設有 `requireApproval: true` 的 Tool 或呼叫 `suspend()` 時，核准 request 會出現在父 Agent 的 stream 中。

```typescript
const sensitiveDataTool = createTool({
  id: 'get-user-data',
  requireApproval: true,
  execute: async input => {
    return await database.getUserData(input.userId)
  },
})

const dataAgent = new Agent({
  id: 'data-agent',
  tools: { sensitiveDataTool },
})

const parentAgent = new Agent({
  id: 'parent-agent',
  agents: { dataAgent },
  memory: new Memory(),
})

const stream = await parentAgent.stream('Get data for user 123')

for await (const chunk of stream.fullStream) {
  if (chunk.type === 'tool-call-approval') {
    console.log('Tool requires approval:', chunk.payload.toolName)
  }
}
```

## 取消

當你傳入 `abortSignal` 至父 Agent 的 [`stream()`](/reference/streaming/agents/stream) 或 [`generate()`](/reference/agents/generate) 呼叫時，Mastra 會將同一 signal 轉送給獲委派的 Subagent。呼叫 `AbortController.abort()` 會在執行中的 Subagent run 到達下一個步驟時取消，而不會讓它們運行至完成。

```typescript
const controller = new AbortController()

const stream = await parentAgent.stream('Research AI trends', {
  abortSignal: controller.signal,
})

// Cancel the parent agent and any in-flight subagents
controller.abort()
```

## 任務完成評分

Agent 不一定在首次嘗試時就產生完整而正確的 output。任務完成 scorer 可以在每次 iteration 後驗證任務是否完成。如驗證失敗，父 Agent 會繼續 iteration。失敗 scorer 的意見會加入對話 context，讓 Subagent 看到欠缺的內容。

```typescript
import { createScorer } from '@mastra/core/evals'

const taskCompleteScorer = createScorer({
  id: 'task-complete',
  name: 'Task Completeness',
}).generateScore(async context => {
  const text = (context.run.output || '').toString()
  const hasAnalysis = text.includes('analysis')
  const hasRecommendations = text.includes('recommendation')
  return hasAnalysis && hasRecommendations ? 1 : 0
})

const stream = await parentAgent.stream('Research AI in education', {
  maxSteps: 10,
  isTaskComplete: {
    scorers: [taskCompleteScorer],
    strategy: 'all',
    onComplete: async result => {
      console.log('Task complete:', result.complete)
    },
  },
})
```

### 評分準則 scorer

內置 rubric scorer 讓你以 checklist 定義「正確」的標準，並讓 Agent 自我評估及 iteration，直至符合所有準則或達到 `maxSteps`。

它是一個 **LLM-as-judge** scorer。每次 iteration 後，獨立的 grader 模型會按 rubric 檢查 Agent output。所有必要準則都通過後，loop 就會結束。未通過的準則會將意見加至對話，讓 Agent 再次嘗試。

此功能最適合成功準則清晰而可驗證的任務。使用方式如下：

```typescript title="src/mastra/agents/rubric-scorer.ts"
import { Agent } from '@mastra/core/agent'
import { createRubricScorer } from '@mastra/evals/scorers/prebuilt'

const parentAgent = new Agent({
  id: 'parent-agent',
  instructions: 'You coordinate research and writing using specialized agents.',
  model: '__GATEWAY_OPENAI_MODEL__',
  agents: { researchAgent, writingAgent },
})

const rubricScorer = createRubricScorer({
  model: '__GATEWAY_OPENAI_MODEL_MINI__',
  criteria: [
    { description: 'The response includes an analysis section' },
    { description: 'The response includes concrete recommendations' },
  ],
})

const stream = await parentAgent.stream('Research AI in education', {
  maxSteps: 10,
  isTaskComplete: {
    scorers: [rubricScorer],
    strategy: 'all',
  },
})
```

完整 API 詳情請參閱 [rubric scorer 參考資料](/reference/evals/rubric)。

## 撰寫有效的指示

清晰的指示是有效委派的關鍵。

父 Agent 的 `instructions` 應列明可用資源和每項資源的使用時機，亦應定義協調行為和成功準則。

每個 Subagent 都應有清晰的 `description`，說明其用途及傳回格式，包括父 Agent 應於何時使用它。

父 Agent 會使用這些描述作出委派決策。

```typescript
const parentAgent = new Agent({
  id: 'parent-agent',
  instructions: `You coordinate research and writing tasks.

Available resources:
- researchAgent: Gathers factual data and sources (returns bullet points)
- writingAgent: Transforms research into narrative content (returns full paragraphs)

Delegation strategy:
1. For research requests: Delegate to researchAgent first
2. For writing requests: Delegate to writingAgent
3. For complex requests: Delegate to researchAgent first, then writingAgent

Success criteria:
- All user questions are fully answered
- Response is well-formatted and complete`,
  agents: { researchAgent, writingAgent },
})
```

## 在背景運行 Subagent

Subagent 呼叫會以 Tool 呼叫形式 dispatch，因此可以作為[背景任務](/docs/long-running-agents/background-tasks)運行。當一個或多個委派長時間運行，而你不希望它們阻塞父 Agent 回應時，這很有用。

在 Mastra instance 上啟用 [backgroundTasks manager](/reference/configuration#backgroundtasks)，然後在父 Agent 上選擇加入 Subagent：

```typescript title="src/mastra/agents/parent-agent.ts"
const parentAgent = new Agent({
  id: 'parent-agent',
  instructions: 'Coordinate research and writing using the available agents.',
  model: '__GATEWAY_OPENAI_MODEL__',
  agents: { researchAgent, writingAgent },
  // highlight-start
  backgroundTasks: {
    tools: {
      researchAgent: { enabled: true, timeoutMs: 900_000 },
      writingAgent: { enabled: true, timeoutMs: 900_000 },
    },
  },
  // highlight-end
})

const stream = await parentAgent.streamUntilIdle('Research AI in education and write an article', {
  memory: { thread: 't1', resource: 'u1' },
})
```

請使用 [`streamUntilIdle()`](/reference/streaming/agents/streamUntilIdle) 而非 `stream()`，讓 stream 保持 open，直至 Subagent 完成，而父 Agent 有機會回應其結果。

如果某個 Subagent 未列於父 Agent 的 `backgroundTasks.tools` 下，但本身有符合背景執行資格的 Tool，父 Agent 仍會將 Subagent 作為背景任務 dispatch，並繼承其設定。詳情請參閱[繼承 Subagent 設定](/docs/long-running-agents/background-tasks#inheriting-from-the-subagent)。

## Subagent 版本控制

使用 [editor](/docs/editor/overview) 時，你可以控制父 Agent 在 runtime 使用各 Subagent 的哪個已儲存版本。在 Mastra instance 或每次呼叫上設定版本覆寫：

```typescript
const result = await parentAgent.generate('Research and write about AI safety', {
  versions: {
    agents: {
      'research-agent': { status: 'published' },
      'writing-agent': { versionId: 'draft-456' },
    },
  },
})
```

版本覆寫會自動透過委派傳遞。解析次序和伺服器 API 用法的詳情，請參閱 [Subagent 版本控制](/reference/editor/versioning#sub-agent-versioning)。
