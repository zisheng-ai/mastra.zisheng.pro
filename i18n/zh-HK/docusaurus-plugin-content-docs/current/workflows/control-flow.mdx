# 控制流程

Workflow 會運行一連串預先定義的任務，而你可以控制如何執行該流程。任務會分為**步驟**，並可視乎要求以不同方式執行。它們可以依次或平行運行，亦可根據條件採用不同 path。

每個步驟都透過已定義的 schema 連接至 Workflow 的下一個步驟，令資料保持受控及一致。

## 核心原則

- 第一個步驟的 `inputSchema` 必須與 Workflow 的 `inputSchema` 相符。
- 最後一個步驟的 `outputSchema` 必須與 Workflow 的 `outputSchema` 相符。
- 每個步驟的 `outputSchema` 必須與下一個步驟的 `inputSchema` 相符。
  - 如不相符，請使用 [Input data mapping](#input-data-mapping) 將資料轉換為所需結構。

## 使用 `.then()` 串連步驟

使用 `.then()` 按次序運行步驟，讓每個步驟都能存取上一個步驟的結果。

![使用 .then() 串連步驟](/img/workflows/workflows-control-flow-then.jpg)

```typescript {27-28} title="src/mastra/workflows/test-workflow.ts"
const step1 = createStep({
  inputSchema: z.object({
    message: z.string(),
  }),
  outputSchema: z.object({
    formatted: z.string(),
  }),
})

const step2 = createStep({
  inputSchema: z.object({
    formatted: z.string(),
  }),
  outputSchema: z.object({
    emphasized: z.string(),
  }),
})

export const testWorkflow = createWorkflow({
  inputSchema: z.object({
    message: z.string(),
  }),
  outputSchema: z.object({
    emphasized: z.string(),
  }),
})
  .then(step1)
  .then(step2)
  .commit()
```

## 使用 `.parallel()` 同時執行步驟

使用 `.parallel()` 同時運行步驟。Workflow 會等待所有平行步驟完成，才繼續下一個步驟。每個步驟的 `id` 會用於定義後續步驟的 `inputSchema`；該 ID 亦會成為 `inputData` 物件上的 key，用於存取上一個步驟的值。然後，後續步驟可以參照或合併平行步驟的 output。

![使用 .parallel() 同時執行步驟](/img/workflows/workflows-control-flow-parallel.jpg)

```typescript {39} title="src/mastra/workflows/test-workflow.ts"
const step1 = createStep({
  id: 'step-1',
})

const step2 = createStep({
  id: 'step-2',
})

const step3 = createStep({
  id: 'step-3',
  inputSchema: z.object({
    'step-1': z.object({
      formatted: z.string(),
    }),
    'step-2': z.object({
      emphasized: z.string(),
    }),
  }),
  outputSchema: z.object({
    combined: z.string(),
  }),
  execute: async ({ inputData }) => {
    const { formatted } = inputData['step-1']
    const { emphasized } = inputData['step-2']
    return {
      combined: `${formatted} | ${emphasized}`,
    }
  },
})

export const testWorkflow = createWorkflow({
  inputSchema: z.object({
    message: z.string(),
  }),
  outputSchema: z.object({
    combined: z.string(),
  }),
})
  .parallel([step1, step2])
  .then(step3)
  .commit()
```

### Output 結構

步驟平行運行時，output 是以每個步驟的 `id` 作為 key、該步驟 output 作為值的物件。你可以獨立存取每個平行步驟的結果。

```typescript title="src/mastra/workflows/test-workflow.ts"
const step1 = createStep({
  id: 'format-step',
  inputSchema: z.object({ message: z.string() }),
  outputSchema: z.object({ formatted: z.string() }),
  execute: async ({ inputData }) => ({
    formatted: inputData.message.toUpperCase(),
  }),
})

const step2 = createStep({
  id: 'count-step',
  inputSchema: z.object({ message: z.string() }),
  outputSchema: z.object({ count: z.number() }),
  execute: async ({ inputData }) => ({
    count: inputData.message.length,
  }),
})

const step3 = createStep({
  id: 'combine-step',
  // The inputSchema must match the structure of parallel outputs
  inputSchema: z.object({
    'format-step': z.object({ formatted: z.string() }),
    'count-step': z.object({ count: z.number() }),
  }),
  outputSchema: z.object({ result: z.string() }),
  execute: async ({ inputData }) => {
    // Access each parallel step's output by its id
    const formatted = inputData['format-step'].formatted
    const count = inputData['count-step'].count
    return {
      result: `${formatted} (${count} characters)`,
    }
  },
})

export const testWorkflow = createWorkflow({
  id: 'parallel-output-example',
  inputSchema: z.object({ message: z.string() }),
  outputSchema: z.object({ result: z.string() }),
})
  .parallel([step1, step2])
  .then(step3)
  .commit()

// When executed with { message: "hello" }
// The parallel output structure will be:
// {
//   "format-step": { formatted: "HELLO" },
//   "count-step": { count: 5 }
// }
```

**重點：**

- 每個平行步驟的 output 都以其 `id` 作為 key
- 所有平行步驟都會同時執行
- 下一個步驟會收到包含所有平行步驟 output 的物件
- 你必須定義後續步驟的 `inputSchema`，以符合此結構

### 處理步驟失敗

如任何平行步驟擲回錯誤，整個 parallel block 都會失敗。要建立可應付部分步驟失敗的彈性平行 Workflow（例如多個研究 Agent 中有一個的 auth token 已過期），請在步驟本身使用 try/catch 處理錯誤：

```typescript title="src/mastra/workflows/test-workflow.ts"
const resilientStep = createStep({
  id: 'researcher',
  inputSchema: z.object({ query: z.string() }),
  outputSchema: z.object({
    brief: z.string().nullable(),
    failed: z.boolean(),
  }),
  execute: async ({ inputData }) => {
    try {
      const result = await fetchExternalData(inputData.query)
      return { brief: result, failed: false }
    } catch {
      return { brief: null, failed: true }
    }
  },
})
```

這樣步驟必定會以 typed result 成功，而 downstream 步驟可以篩走失敗結果：

```typescript title="src/mastra/workflows/test-workflow.ts"
const writerStep = createStep({
  id: 'writer',
  inputSchema: z.object({
    'researcher-a': z.object({ brief: z.string().nullable(), failed: z.boolean() }),
    'researcher-b': z.object({ brief: z.string().nullable(), failed: z.boolean() }),
  }),
  outputSchema: z.object({ synthesis: z.string() }),
  execute: async ({ inputData }) => {
    const briefs = Object.values(inputData)
      .filter(v => !v.failed && v.brief)
      .map(v => v.brief)
    return { synthesis: briefs.join('; ') }
  },
})
```

要了解何時使用 `.parallel()` 或 `.foreach()`，請參閱[選擇合適 pattern](#choosing-the-right-pattern)。

## 使用 `.branch()` 加入條件邏輯

使用 `.branch()` 根據條件選擇要運行的步驟。分支中的所有步驟都需要相同的 `inputSchema` 和 `outputSchema`，因為分支需要一致的 schema，讓 Workflow 可以採用不同 path。

![使用 .branch() 建立條件分支](/img/workflows/workflows-control-flow-branch.jpg)

```typescript {30-33} title="src/mastra/workflows/test-workflow.ts" prettier:false
const step1 = createStep({...})

const stepA = createStep({
  inputSchema: z.object({
    value: z.number()
  }),
  outputSchema: z.object({
    result: z.string()
  })
});

const stepB = createStep({
  inputSchema: z.object({
    value: z.number()
  }),
  outputSchema: z.object({
    result: z.string()
  })
});

export const testWorkflow = createWorkflow({
  inputSchema: z.object({
    value: z.number()
  }),
  outputSchema: z.object({
    result: z.string()
  })
})
  .then(step1)
  .branch([
    [async ({ inputData: { value } }) => value > 10, stepA],
    [async ({ inputData: { value } }) => value <= 10, stepB]
  ])
  .commit();
```

### Output 結構

使用條件分支時，只會執行首個 condition evaluate 為 `true` 的分支。Output 結構與 `.parallel()` 類似，結果以已執行步驟的 `id` 作為 key。

```typescript title="src/mastra/workflows/test-workflow.ts"
const step1 = createStep({
  id: 'initial-step',
  inputSchema: z.object({ value: z.number() }),
  outputSchema: z.object({ value: z.number() }),
  execute: async ({ inputData }) => inputData,
})

const highValueStep = createStep({
  id: 'high-value-step',
  inputSchema: z.object({ value: z.number() }),
  outputSchema: z.object({ result: z.string() }),
  execute: async ({ inputData }) => ({
    result: `High value: ${inputData.value}`,
  }),
})

const lowValueStep = createStep({
  id: 'low-value-step',
  inputSchema: z.object({ value: z.number() }),
  outputSchema: z.object({ result: z.string() }),
  execute: async ({ inputData }) => ({
    result: `Low value: ${inputData.value}`,
  }),
})

const finalStep = createStep({
  id: 'final-step',
  // The inputSchema must account for either branch's output
  inputSchema: z.object({
    'high-value-step': z.object({ result: z.string() }).optional(),
    'low-value-step': z.object({ result: z.string() }).optional(),
  }),
  outputSchema: z.object({ message: z.string() }),
  execute: async ({ inputData }) => {
    // Only one branch will have executed
    const result = inputData['high-value-step']?.result || inputData['low-value-step']?.result
    return { message: result }
  },
})

export const testWorkflow = createWorkflow({
  id: 'branch-output-example',
  inputSchema: z.object({ value: z.number() }),
  outputSchema: z.object({ message: z.string() }),
})
  .then(step1)
  .branch([
    [async ({ inputData }) => inputData.value > 10, highValueStep],
    [async ({ inputData }) => inputData.value <= 10, lowValueStep],
  ])
  .then(finalStep)
  .commit()

// When executed with { value: 15 }
// Only the high-value-step executes, output structure:
// {
//   "high-value-step": { result: "High value: 15" }
// }

// When executed with { value: 5 }
// Only the low-value-step executes, output structure:
// {
//   "low-value-step": { result: "Low value: 5" }
// }
```

**重點：**

- 只會按 condition evaluate 次序執行一個分支
- Output 以已執行步驟的 `id` 作為 key
- 後續步驟應處理所有可能的分支 output
- 下一個步驟需要處理多個可能分支時，請在 `inputSchema` 使用 optional field
- Condition 會按定義次序 evaluate

## 輸入資料映射

使用 `.then()`、`.parallel()` 或 `.branch()` 時，有時需要轉換上一個步驟的 output，以符合下一個步驟的 input。此時可以使用 `.map()` 存取 `inputData` 並轉換，建立適合下一個步驟的資料結構。

![使用 .map() 進行 mapping](/img/workflows/workflows-data-mapping-map.jpg)

```typescript {9} title="src/mastra/workflows/test-workflow.ts" prettier:false
const step1 = createStep({...});
const step2 = createStep({...});

export const testWorkflow = createWorkflow({...})
  .then(step1)
  .map(async ({ inputData }) => {
    const { foo } = inputData;
    return {
      bar: `new ${foo}`,
    };
  })
  .then(step2)
  .commit();
```

`.map()` method 會為較複雜的 mapping 情況提供額外 helper function。

**可用 helper function：**

- [`getStepResult()`](/reference/workflows/workflow-methods/map#using-getstepresult)：存取特定步驟的完整 output
- [`getInitData<any>()`](/reference/workflows/workflow-methods/map#using-getinitdata)：存取 Workflow 的初始 input data
- [`mapVariable()`](/reference/workflows/workflow-methods/map#using-mapvariable)：使用 declarative object syntax 擷取及重新命名 field

### Parallel 和 Branch output

處理 `.parallel()` 或 `.branch()` output 時，你可以使用 `.map()` 轉換資料結構，再傳給下一個步驟。如需 flatten 或重組 output，此功能尤其有用。

```typescript prettier:false title="src/mastra/workflows/test-workflow.ts"
export const testWorkflow = createWorkflow({...})
  .parallel([step1, step2])
  .map(async ({ inputData }) => {
    // Transform the parallel output structure
    return {
      combined: `${inputData["step1"].value} - ${inputData["step2"].value}`
    };
  })
  .then(nextStep)
  .commit();
```

你亦可以使用 `.map()` 提供的 helper function：

```typescript prettier:false title="src/mastra/workflows/test-workflow.ts"
export const testWorkflow = createWorkflow({...})
  .branch([
    [condition1, stepA],
    [condition2, stepB]
  ])
  .map(async ({ inputData, getStepResult }) => {
    // Access specific step results
    const stepAResult = getStepResult("stepA");
    const stepBResult = getStepResult("stepB");
    
    // Return the result from whichever branch executed
    return stepAResult || stepBResult;
  })
  .then(nextStep)
  .commit();
```

## Loop 步驟

Workflow 支援不同的 loop method，讓你重複步驟直至或只要符合條件，或 iterate array。Loop 可以與 `.then()` 等其他 control method 組合。

### 使用 `.dountil()` loop

使用 `.dountil()` 重複運行步驟，直至 condition 變為 true。

![使用 .dountil() 重複執行](/img/workflows/workflows-control-flow-dountil.jpg)

```typescript prettier:false {14} title="src/mastra/workflows/test-workflow.ts"
const step1 = createStep({...});

const step2 = createStep({
  execute: async ({ inputData }) => {
    const { number } = inputData;
    return {
      number: number + 1
    };
  }
});

export const testWorkflow = createWorkflow({})
  .then(step1)
  .dountil(step2, async ({ inputData: { number } }) => number > 10)
  .commit();
```

### 使用 `.dowhile()` loop

使用 `.dowhile()` 在 condition 維持 true 時重複運行步驟。

![使用 .dowhile() 重複執行](/img/workflows/workflows-control-flow-dowhile.jpg)

```typescript prettier:false {14} title="src/mastra/workflows/test-workflow.ts"
const step1 = createStep({...});

const step2 = createStep({
  execute: async ({ inputData }) => {
    const { number } = inputData;
    return {
      number: number + 1
    };
  }
});

export const testWorkflow = createWorkflow({})
  .then(step1)
  .dowhile(step2, async ({ inputData: { number } }) => number < 10)
  .commit();
```

### 使用 `.foreach()` loop

使用 `.foreach()` 對 array 中每個項目運行相同步驟。Input 必須為 `array` 類型，loop 才能 iterate 其中的值，並將步驟邏輯套用至每個值。何時使用 `.foreach()` 或其他 method 的指引，請參閱[選擇合適 pattern](#choosing-the-right-pattern)。

![使用 .foreach() 重複執行](/img/workflows/workflows-control-flow-foreach.jpg)

```typescript prettier:false {15} title="src/mastra/workflows/test-workflow.ts"
const step1 = createStep({
  inputSchema: z.string(),
  outputSchema: z.string(),
  execute: async ({ inputData }) => {
    return inputData.toUpperCase();
  }
});

const step2 = createStep({...});

export const testWorkflow = createWorkflow({
  inputSchema: z.array(z.string()),
  outputSchema: z.array(z.string())
})
  .foreach(step1)
  .then(step2)
  .commit();
```

#### Output 結構

`.foreach()` method 必定傳回包含每次 iteration output 的 array。Output 次序與 input 次序相符。

```typescript title="src/mastra/workflows/test-workflow.ts"
const addTenStep = createStep({
  id: 'add-ten',
  inputSchema: z.object({ value: z.number() }),
  outputSchema: z.object({ value: z.number() }),
  execute: async ({ inputData }) => ({
    value: inputData.value + 10,
  }),
})

export const testWorkflow = createWorkflow({
  id: 'foreach-output-example',
  inputSchema: z.array(z.object({ value: z.number() })),
  outputSchema: z.array(z.object({ value: z.number() })),
})
  .foreach(addTenStep)
  .commit()

// When executed with [{ value: 1 }, { value: 22 }, { value: 333 }]
// Output: [{ value: 11 }, { value: 32 }, { value: 343 }]
```

#### Concurrency 限制

使用 `concurrency` 控制處理多少個 array 項目。預設值為 `1`，會依次運行步驟。增加此值可讓 `.foreach()` 同時處理多個項目。

```typescript prettier:false title="src/mastra/workflows/test-workflow.ts"
const step1 = createStep({...})

export const testWorkflow = createWorkflow({...})
  .foreach(step1, { concurrency: 4 })
  .commit();
```

#### 彙總 `.foreach()` 後的結果

由於 `.foreach()` 會輸出 array，你可以使用 `.then()` 或 `.map()` 彙總或轉換結果。`.foreach()` 之後的步驟會收到整個 array 作為 input。

```typescript title="src/mastra/workflows/test-workflow.ts"
const processItemStep = createStep({
  id: 'process-item',
  inputSchema: z.object({ value: z.number() }),
  outputSchema: z.object({ processed: z.number() }),
  execute: async ({ inputData }) => ({
    processed: inputData.value * 2,
  }),
})

const aggregateStep = createStep({
  id: 'aggregate',
  // Input is an array of outputs from foreach
  inputSchema: z.array(z.object({ processed: z.number() })),
  outputSchema: z.object({ total: z.number() }),
  execute: async ({ inputData }) => ({
    // Sum all processed values
    total: inputData.reduce((sum, item) => sum + item.processed, 0),
  }),
})

export const testWorkflow = createWorkflow({
  id: 'foreach-aggregate-example',
  inputSchema: z.array(z.object({ value: z.number() })),
  outputSchema: z.object({ total: z.number() }),
})
  .foreach(processItemStep)
  .then(aggregateStep) // Receives the full array from foreach
  .commit()

// When executed with [{ value: 1 }, { value: 2 }, { value: 3 }]
// After foreach: [{ processed: 2 }, { processed: 4 }, { processed: 6 }]
// After aggregate: { total: 12 }
```

你亦可以使用 `.map()` 轉換 array output：

```typescript prettier:false title="src/mastra/workflows/test-workflow.ts"
export const testWorkflow = createWorkflow({...})
  .foreach(processItemStep)
  .map(async ({ inputData }) => ({
    // Transform the array into a different structure
    values: inputData.map(item => item.processed),
    count: inputData.length
  }))
  .then(nextStep)
  .commit();
```

#### 串連多個 `.foreach()` 呼叫

串連 `.foreach()` 呼叫時，每個呼叫都會處理上一個步驟的 array output。當 array 中每個項目都需要依次經過多個步驟轉換時，這十分有用。

```typescript title="src/mastra/workflows/test-workflow.ts"
const chunkStep = createStep({
  id: 'chunk',
  // Takes a document, returns an array of chunks
  inputSchema: z.object({ content: z.string() }),
  outputSchema: z.array(z.object({ chunk: z.string() })),
  execute: async ({ inputData }) => {
    // Split document into chunks
    const chunks = inputData.content.match(/.{1,100}/g) || []
    return chunks.map(chunk => ({ chunk }))
  },
})

const embedStep = createStep({
  id: 'embed',
  // Takes a single chunk, returns embedding
  inputSchema: z.object({ chunk: z.string() }),
  outputSchema: z.object({ embedding: z.array(z.number()) }),
  execute: async ({ inputData }) => ({
    embedding: [/* vector embedding */],
  }),
})

// For a single document that produces multiple chunks:
export const singleDocWorkflow = createWorkflow({
  id: 'single-doc-rag',
  inputSchema: z.object({ content: z.string() }),
  outputSchema: z.array(z.object({ embedding: z.array(z.number()) })),
})
  .then(chunkStep) // Returns array of chunks
  .foreach(embedStep) // Process each chunk -> array of embeddings
  .commit()
```

如要處理多份文件，而每份文件都會產生多個 chunk，你可以選擇：

**選項 1：在單一步驟中處理所有文件，並控制 batching**

```typescript prettier:false title="src/mastra/workflows/test-workflow.ts"
const downloadAndChunkStep = createStep({
  id: "download-and-chunk",
  inputSchema: z.array(z.string()),  // Array of URLs
  outputSchema: z.array(z.object({ chunk: z.string(), source: z.string() })),
  execute: async ({ inputData: urls }) => {
    // Control batching/parallelization within the step
    const allChunks = [];
    for (const url of urls) {
      const content = await fetch(url).then(r => r.text());
      const chunks = content.match(/.{1,100}/g) || [];
      allChunks.push(...chunks.map(chunk => ({ chunk, source: url })));
    }
    return allChunks;
  }
});

export const multiDocWorkflow = createWorkflow({...})
  .then(downloadAndChunkStep)  // Returns flat array of all chunks
  .foreach(embedStep, { concurrency: 10 })  // Embed each chunk in parallel
  .commit();
```

**選項 2：對文件使用 foreach 並彙總 chunk，然後再對 embedding 使用 foreach**

```typescript title="src/mastra/workflows/test-workflow.ts"
const downloadStep = createStep({
  id: 'download',
  inputSchema: z.string(), // Single URL
  outputSchema: z.object({ content: z.string(), source: z.string() }),
  execute: async ({ inputData: url }) => ({
    content: await fetch(url).then(r => r.text()),
    source: url,
  }),
})

const chunkDocStep = createStep({
  id: 'chunk-doc',
  inputSchema: z.object({ content: z.string(), source: z.string() }),
  outputSchema: z.array(z.object({ chunk: z.string(), source: z.string() })),
  execute: async ({ inputData }) => {
    const chunks = inputData.content.match(/.{1,100}/g) || []
    return chunks.map(chunk => ({ chunk, source: inputData.source }))
  },
})

export const multiDocWorkflow = createWorkflow({
  id: 'multi-doc-rag',
  inputSchema: z.array(z.string()), // Array of URLs
  outputSchema: z.array(z.object({ embedding: z.array(z.number()) })),
})
  .foreach(downloadStep, { concurrency: 5 }) // Download docs in parallel
  .foreach(chunkDocStep) // Chunk each doc -> array of chunk arrays
  .map(async ({ inputData }) => {
    // Flatten nested arrays: [[chunks], [chunks]] -> [chunks]
    return inputData.flat()
  })
  .foreach(embedStep, { concurrency: 10 }) // Embed all chunks
  .commit()
```

**串連 `.foreach()` 的重點：**

- 每個 `.foreach()` 都會處理上一個步驟的 array
- 如果 `.foreach()` 內的步驟傳回 array，output 會成為 array of arrays
- 需要時使用 `.map()` 配合 `.flat()` flatten 巢狀 array
- 對於複雜 RAG pipeline，選項 1（在單一步驟中處理 batching）通常提供更好的控制

#### Foreach 內的巢狀 Workflow

`.foreach()` 之後的步驟只會在所有 iteration 完成後執行。如果需要為每個項目運行多個依次操作，請使用巢狀 Workflow，而非串連多個 `.foreach()` 呼叫。這會將每個項目的所有操作放在一起，令 data flow 更清晰。

```typescript title="src/mastra/workflows/test-workflow.ts"
// Define a workflow that processes a single document
const processDocumentWorkflow = createWorkflow({
  id: 'process-document',
  inputSchema: z.object({ url: z.string() }),
  outputSchema: z.object({
    embeddings: z.array(z.array(z.number())),
    metadata: z.object({ url: z.string(), chunkCount: z.number() }),
  }),
})
  .then(downloadStep) // Download the document
  .then(chunkStep) // Split into chunks
  .then(embedChunksStep) // Embed all chunks for this document
  .then(formatResultStep) // Format the final output
  .commit()

// Use the nested workflow inside foreach
export const batchProcessWorkflow = createWorkflow({
  id: 'batch-process-documents',
  inputSchema: z.array(z.object({ url: z.string() })),
  outputSchema: z.array(
    z.object({
      embeddings: z.array(z.array(z.number())),
      metadata: z.object({ url: z.string(), chunkCount: z.number() }),
    }),
  ),
})
  .foreach(processDocumentWorkflow, { concurrency: 3 })
  .commit()

// Each document goes through all 4 steps before the next document starts (with concurrency: 1)
// With concurrency: 3, up to 3 documents process their full pipelines in parallel
```

**使用巢狀 Workflow 的原因：**

- **更佳平行處理**：使用 `concurrency: N` 時，多個項目會同時運行完整 pipeline。串連 `.foreach().foreach()` 會先讓所有項目完成步驟 1，等待後才全部進入步驟 2；巢狀 Workflow 則讓各項目獨立推進
- 每個項目的所有步驟會一併完成，然後才收集結果
- 比建立巢狀 array 的多個 `.foreach()` 呼叫更清晰
- 每次巢狀 Workflow 執行都各自獨立，並有自己的 data flow
- 更易分開測試及重用每個項目的邏輯

**運作方式：**

1. 父 Workflow 將每個 array 項目傳給巢狀 Workflow 的一個 instance
1. 每個巢狀 Workflow 都會為該項目運行其完整步驟序列
1. `concurrency > 1` 時，多個巢狀 Workflow 會平行執行
1. 巢狀 Workflow 的最終 output 會成為結果 array 中的一個 element
1. 所有巢狀 Workflow 完成後，父 Workflow 的下一個步驟會收到完整 array

## 選擇合適 pattern

請使用本節作為選擇合適 control flow method 的參考。

### 快速參考

| Method | 用途 | Input | Output | Concurrency |
| - | - | - | - | - |
| `.then(step)` | 依次處理 | `T` | `U` | 不適用（每次一個） |
| `.parallel([a, b])` | 對相同 input 執行不同操作 | `T` | `{ a: U, b: V }` | 全部同時運行 |
| `.foreach(step)` | 對每個 array 項目執行相同操作 | `T[]` | `U[]` | 可設定（預設：1） |
| `.branch([...])` | 選擇條件 path | `T` | `{ selectedStep: U }` | 只運行一個分支 |

### `.parallel()` 與 `.foreach()`

**當一個 input 需要不同處理時，請使用 `.parallel()`：**

```typescript
// Same user data processed differently in parallel
workflow.parallel([validateStep, enrichStep, scoreStep]).then(combineResultsStep)
```

**當多個 input 需要相同處理時，請使用 `.foreach()`：**

```typescript
// Multiple URLs each processed the same way
workflow.foreach(downloadStep, { concurrency: 5 }).then(aggregateStep)
```

### 何時使用巢狀 Workflow

**在 `.foreach()` 內** — 當每個 array 項目都需要多個依次步驟時：

```typescript prettier:false
// Each document goes through a full pipeline
const processDocWorkflow = createWorkflow({...})
  .then(downloadStep)
  .then(parseStep)
  .then(embedStep)
  .commit();

workflow.foreach(processDocWorkflow, { concurrency: 3 })
```

使用單一 `.foreach()` 可令結果維持 flat。串連 `.foreach().foreach()` 會建立巢狀 array。

**在 `.parallel()` 內** — 當平行分支需要自己的多步驟 pipeline 時：

```typescript prettier:false
const pipelineA = createWorkflow({...}).then(step1).then(step2).commit();
const pipelineB = createWorkflow({...}).then(step3).then(step4).commit();

workflow.parallel([pipelineA, pipelineB])
```

### 串連 pattern

| Pattern | 運作方式 | 常見使用情況 |
| - | - | - |
| `.then().then()` | 依次執行步驟 | 簡單 pipeline |
| `.parallel().then()` | 平行運行，然後合併 | Fan-out/fan-in |
| `.foreach().then()` | 處理所有項目，然後彙總 | Map-reduce |
| `.foreach().foreach()` | 建立 array of arrays | 避免使用 — 改用巢狀 Workflow 或 `.map()` 配合 `.flat()` |
| `.foreach(workflow)` | 每個項目使用完整 pipeline | 對每個 array 項目執行多步驟處理 |

### 同步：下一個步驟何時運行？

`.parallel()` 和 `.foreach()` 都是 synchronization point。只有在所有平行分支或所有 array iteration 完成後，Workflow 的下一個步驟才會執行。

```typescript
workflow
  .parallel([stepA, stepB, stepC]) // All 3 run simultaneously
  .then(combineStep) // Waits for ALL 3 to finish before running
  .commit()

workflow
  .foreach(processStep, { concurrency: 5 }) // Up to 5 items process at once
  .then(aggregateStep) // Waits for ALL items to finish before running
  .commit()
```

這表示：

- `.parallel()` 會將所有分支 output 收集到物件，再傳給下一個步驟
- `.foreach()` 會將所有 iteration output 收集到 array，再傳給下一個步驟
- 結果完成時無法「串流」至下一個步驟

### Concurrency 行為

| Method | 行為 |
| - | - |
| `.then()` | 依次執行 — 每次一個步驟 |
| `.parallel()` | 所有分支同時運行（沒有 limit 選項） |
| `.foreach()` | 透過 `{ concurrency: N }` 控制 — 預設為 1（依次執行） |
| `.foreach()` 中的巢狀 Workflow | 遵循父 Workflow 的 concurrency 設定 |

**效能提示：** 對於 `.foreach()` 中受 I/O 限制的操作，請增加 concurrency 以平行處理項目：

```typescript
// Process up to 10 items simultaneously
workflow.foreach(fetchDataStep, { concurrency: 10 })
```

## Loop 管理

你可以視乎希望 loop 如何結束，以不同方式實作 loop condition。

常見 pattern 會檢查 `inputData` 傳回的值，並設定 iteration 上限。到達 limit 時亦可以中止執行。

### 中止 loop

使用 `iterationCount` 限制 loop 運行次數。如果次數超過 threshold，請擲回錯誤，令步驟失敗並停止 Workflow。

```typescript prettier:false title="src/mastra/workflows/test-workflow.ts"
const step1 = createStep({...});

export const testWorkflow = createWorkflow({...})
  .dountil(step1, async ({ inputData: { userResponse, iterationCount } }) => {
    if (iterationCount >= 10) {
      throw new Error("Maximum iterations reached");
    }
    return userResponse === "yes";
  })
  .commit();
```
