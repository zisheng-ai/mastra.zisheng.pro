# Human-in-the-loop (HITL)

部分 Workflow 需要暫停並等待人為 input 後才能繼續。Workflow [暫停](/docs/workflows/suspend-and-resume#pausing-a-workflow-with-suspend)時，可以傳回訊息，解釋暫停原因及繼續所需的內容。然後，Workflow 可根據收到的 input [恢復](#resuming-workflows-with-human-input)或 [bail](#handling-human-rejection-with-bail)。此方法適合手動核准、拒絕、受限制的決策，或任何需要人為監督的步驟。

## 暫停 Workflow 以等待人為 input

Human-in-the-loop input 的運作方式與使用 `suspend()` [暫停 Workflow](/docs/workflows/suspend-and-resume) 大致相同。主要分別是需要人為 input 時，你可以傳回帶有 payload 的 `suspend()`，為使用者提供如何繼續的 context 或指引。

![使用 suspend() 暫停 Workflow](/img/workflows/workflows-suspend.jpg)

```typescript {12-17,22-26} title="src/mastra/workflows/test-workflow.ts"
import { createWorkflow, createStep } from '@mastra/core/workflows'
import { z } from 'zod'

const step1 = createStep({
  id: 'step-1',
  inputSchema: z.object({
    userEmail: z.string(),
  }),
  outputSchema: z.object({
    output: z.string(),
  }),
  resumeSchema: z.object({
    approved: z.boolean(),
  }),
  suspendSchema: z.object({
    reason: z.string(),
  }),
  execute: async ({ inputData, resumeData, suspend }) => {
    const { userEmail } = inputData
    const { approved } = resumeData ?? {}

    if (!approved) {
      return await suspend({
        reason: 'Human approval required.',
      })
    }

    return {
      output: `Email sent to ${userEmail}`,
    }
  },
})

export const testWorkflow = createWorkflow({
  id: 'test-workflow',
  inputSchema: z.object({
    userEmail: z.string(),
  }),
  outputSchema: z.object({
    output: z.string(),
  }),
})
  .then(step1)
  .commit()
```

## 提供使用者意見

Workflow 暫停時，你可以找出已暫停的步驟並讀取其 `suspendPayload`，以存取 `suspend()` 傳回的 payload。

```typescript {12} title="src/test-workflow.ts"
const workflow = mastra.getWorkflow('testWorkflow')
const run = await workflow.createRun()

const result = await run.start({
  inputData: {
    userEmail: 'alex@example.com',
  },
})

if (result.status === 'suspended') {
  const suspendStep = result.suspended[0]
  const suspendedPayload = result.steps[suspendStep[0]].suspendPayload

  console.log(suspendedPayload)
}
```

### Output 範例

步驟傳回的資料可以包括原因，協助使用者了解恢復 Workflow 所需的內容。

```typescript
{
  reason: 'Confirm to send email.'
}
```

## 以人為 input 恢復 Workflow

與[重新啟動 Workflow](/docs/workflows/suspend-and-resume#restarting-a-workflow-with-resume) 相同，收到人為 input 後，使用帶有 `resumeData` 的 `resume()` 繼續 Workflow。Workflow 會從暫停的步驟恢復。

![使用 resume() 重新啟動 Workflow](/img/workflows/workflows-resume.jpg)

```typescript {13}
const workflow = mastra.getWorkflow('testWorkflow')
const run = await workflow.createRun()

await run.start({
  inputData: {
    userEmail: 'alex@example.com',
  },
})

const handleResume = async () => {
  const result = await run.resume({
    step: 'step-1',
    resumeData: { approved: true },
  })
}
```

### 使用 `bail()` 處理人為拒絕

使用 `bail()` 在某個步驟停止執行 Workflow，而不會觸發錯誤。當使用者明確拒絕操作時，此功能十分有用。Workflow 會以 `success` 狀態完成，而呼叫 `bail()` 之後的任何邏輯都會略過。

```typescript {6-10}
const step1 = createStep({
  execute: async ({ inputData, resumeData, suspend, bail }) => {
    const { userEmail } = inputData
    const { approved } = resumeData ?? {}

    if (approved === false) {
      return bail({
        reason: 'User rejected the request.',
      })
    }

    if (!approved) {
      return await suspend({
        reason: 'Human approval required.',
      })
    }

    return {
      message: `Email sent to ${userEmail}`,
    }
  },
})
```

## 多輪人為 input

需要在多個階段取得 input 的 Workflow，使用相同的 suspend pattern。每個步驟都會定義 `resumeSchema`，以及通常包含可用於提供使用者意見之原因的 `suspendSchema`。

```typescript {11-16,21-25} title="src/mastra/workflows/test-workflow.ts" prettier:false
const step1 = createStep({...});

const step2 = createStep({
  id: "step-2",
  inputSchema: z.object({
    message: z.string()
  }),
  outputSchema: z.object({
    output: z.string()
  }),
  resumeSchema: z.object({
    approved: z.boolean()
  }),
  suspendSchema: z.object({
    reason: z.string()
  }),
  execute: async ({ inputData, resumeData, suspend }) => {
    const { message } = inputData;
    const { approved } = resumeData ?? {};

    if (!approved) {
      return await suspend({
        reason: "Human approval required."
      });
    }

    return {
      output: `${message} - Deleted`
    };
  }
});

export const testWorkflow = createWorkflow({
  id: "test-workflow",
  inputSchema: z.object({
    userEmail: z.string()
  }),
  outputSchema: z.object({
    output: z.string()
  })
})
  .then(step1)
  .then(step2)
  .commit();
```

每個步驟都必須依次恢復；每個已暫停步驟都要另行呼叫 `resume()`。此方法透過一致的 UI 意見和每個階段的清晰 input 處理，協助管理多步驟核准。

```typescript {4,11}
const handleResume = async () => {
  const result = await run.resume({
    step: 'step-1',
    resumeData: { approved: true },
  })
}

const handleDelete = async () => {
  const result = await run.resume({
    step: 'step-2',
    resumeData: { approved: true },
  })
}
```
