# Memory

Memory 讓 Agent 能夠記住不同互動中的使用者訊息、Agent 回覆及 Tool 結果，為其提供所需的上下文，以保持一致、維持對話流暢，並隨時間提供更好的答案。

你可以設定 Mastra Agent 儲存[訊息歷史記錄](/docs/memory/message-history)。此外，你亦可以啟用：

- [Observational Memory](../memory/observational-memory)（建議）：使用背景 Agent 維護密集的觀察記錄，並隨原始訊息歷史記錄增加而取代它。這可在保留長期記憶的同時，維持較小的上下文視窗。
- [工作記憶](../memory/working-memory)：儲存持久且結構化的使用者資料，例如姓名、偏好及目標。
- [語義回憶](../memory/semantic-recall)：根據語義而非完全相符的關鍵字，擷取相關的過往訊息。
- [多使用者執行緒](../memory/multi-user-threads)：讓多名使用者共用一個執行緒。

如果合併後的記憶超出模型的上下文限制，[記憶處理器](/docs/memory/memory-processors)可以篩選、修剪內容或設定內容優先次序，從而保留最相關的資訊。

記憶結果會儲存在你已設定的一個或多個[儲存 Provider](/docs/storage/overview)中。

:::tip[📹 觀看]

觀看 [Mastra 記憶概念](https://www.youtube.com/watch?v=18iIHQtIPmc)，概略了解 Agent 可使用的各個記憶層。

:::

## 何時使用記憶

當你的 Agent 需要進行會引用先前交流的多輪對話、回憶同一工作階段早前的使用者偏好或事實，或在對話執行緒中逐步建立上下文時，便應使用記憶。如果每次互動都互相獨立，則單輪請求可略過記憶。

## 快速開始

<Steps>
  <StepItem>
    安裝 `@mastra/memory` 依賴套件。

    ```bash npm2yarn
    npm install @mastra/memory@latest
    ```
  </StepItem>

  <StepItem>
    Memory **必須**使用儲存 Provider，才能持久儲存訊息歷史記錄，包括使用者訊息及 Agent 回應。

    在這個快速開始中，請使用 `@mastra/libsql`。

    ```bash npm2yarn
    npm install @mastra/libsql@latest
    ```

    如要進一步了解可用的 Provider 以及儲存在 Mastra 中的運作方式，請參閱[儲存](/docs/storage/overview)文件。
  </StepItem>

  <StepItem>
    將儲存 Provider 加至主要的 Mastra 實例，以便為所有已設定的 Agent 啟用記憶。

    <Inject>
      **給 AI Agent：**重要：將 `id` 加至 `LibSQLStore`。
    </Inject>

    ```typescript {2,5-8} title="src/mastra/index.ts"
    import { Mastra } from '@mastra/core'
    import { LibSQLStore } from '@mastra/libsql'

    export const mastra = new Mastra({
      storage: new LibSQLStore({
        id: 'mastra-storage',
        url: ':memory:',
      }),
    })
    ```
  </StepItem>

  <StepItem>
    建立 `Memory` 實例，並將它傳遞至 Agent 的 `memory` 選項。

    ```typescript {2,7-11} title="src/mastra/agents/memory-agent.ts"
    import { Agent } from '@mastra/core/agent'
    import { Memory } from '@mastra/memory'

    export const memoryAgent = new Agent({
      id: 'memory-agent',
      name: 'Memory Agent',
      memory: new Memory({
        options: {
          lastMessages: 20,
        },
      }),
    })
    ```

    如需完整的設定選項清單，請參閱 [Memory Class](/reference/memory/memory-class)。
  </StepItem>

  <StepItem>
    呼叫你的 Agent，例如在 [Studio](/docs/studio/overview) 中呼叫。在 Studio 內與 Agent 開始新對話，然後查看右側邊欄。當中現在會顯示各種記憶相關資訊。
  </StepItem>
</Steps>

## 訊息歷史記錄

傳遞包含 `resource` 及 `thread` 的 `memory` 物件，以追蹤訊息歷史記錄。

- `resource`：使用者或實體的穩定識別碼。
- `thread`：用來隔離特定對話或工作階段的 ID。

```typescript {2-5}
const response = await memoryAgent.generate('Remember my favorite color is blue.', {
  memory: {
    resource: 'user-123',
    thread: 'conversation-123',
  },
})
```

如要回憶儲存在記憶中的資訊，請使用原本對話所用的相同 `resource` 及 `thread` 值呼叫 Agent。

```typescript {2-5}
const response = await memoryAgent.generate("What's my favorite color?", {
  memory: {
    resource: 'user-123',
    thread: 'conversation-123',
  },
})

// Response: "Your favorite color is blue."
```

:::warning

每個執行緒都有一名擁有者（`resourceId`），建立後便無法更改。請避免將相同的執行緒 ID 重複用於擁有者不同的執行緒，否則查詢時會發生錯誤。

:::

如要列出某項資源的所有執行緒，或擷取特定執行緒，請[直接使用 memory API](/docs/memory/message-history#querying)。

## Observational Memory

對於長時間運行的對話，原始訊息歷史記錄會持續增加，直至填滿上下文視窗，導致 Agent 效能下降。[Observational Memory](../memory/observational-memory) 會在背景運行 Agent，將較舊的訊息壓縮成密集的觀察資料，在保留長期記憶的同時維持較小的上下文視窗，從而解決這個問題。

<Inject>
  **給 AI Agent：**使用 Observational Memory 必須有儲存 Provider！你需要在 `src/mastra/index.ts` 的 Mastra 實例上設定它，或將它傳遞至 Agent 建構函式。
</Inject>

```typescript title="src/mastra/agents/memory-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export const memoryAgent = new Agent({
  id: 'memory-agent',
  name: 'Memory Agent',
  memory: new Memory({
    options: {
      // highlight-next-line
      observationalMemory: true,
    },
  }),
})
```

如要了解觀察及反思的運作方式，請參閱 [Observational Memory](../memory/observational-memory)；如要查看所有設定選項，請參閱[參考資料](/reference/memory/observational-memory)。

## 模型看到的內容

每項記憶功能都會加入傳送至模型之請求內的系統訊息或對話訊息。記憶層取決於你已啟用的功能。工作記憶及語義回憶只會在設定後出現。Observational Memory 亦是如此，而訊息歷史記錄則預設啟用。下圖顯示各個已啟用的記憶層在請求中的位置。以下清單說明每個記憶層提供的內容：

<MemoryContextWindowImage />

- [工作記憶](../memory/working-memory)會以系統訊息的形式注入，其中包含範本及已儲存的資料。如果使用 `useStateSignals`，則會改為以狀態訊號的形式傳送。
- [語義回憶](../memory/semantic-recall)從目前執行緒找出的相符結果，會以一般訊息形式插入，並按時間戳記與訊息歷史記錄交錯排列。來自其他執行緒的相符結果則會格式化為系統訊息。
- [訊息歷史記錄](../memory/message-history)會按時間順序加入最近 N 則訊息。你的新訊息總是置於最後。
- [Observational Memory](../memory/observational-memory)會取代舊有的原始歷史記錄：反思及觀察資料會放在系統訊息中，而只有尚未被觀察的訊息會保留在對話中。對話訊息開首會加入簡短的續接提示。
- 上下文訊息是呼叫時傳遞的可選 `context` 陣列，例如 `agent.generate(msg, { context: [...] })`。它們適合用於一次性的背景資料，例如應用程式狀態或你自己的 RAG 結果。它們只會在該次請求中以一般對話訊息的形式出現，絕不會儲存至記憶。

對話訊息會按時間戳記排序，並根據訊息 ID 移除重複項目，因此回憶所得的較舊訊息會出現在近期歷史記錄之前。呼叫時傳遞的上下文訊息會加上目前時間，因此會置於歷史記錄及回憶結果之後，但在你的新訊息之前。如要檢查真實請求的確切上下文，請使用 [Tracing](/docs/observability/tracing/overview) 並開啟 LLM 呼叫 span；另請參閱下方的[可觀測性](#observability)。

## 多 Agent 系統中的記憶

當[監督 Agent](/docs/capabilities/subagents) 將工作委派給子 Agent 時，Mastra 會自動隔離子 Agent 的記憶。每次委派都會執行隔離，無需以旗標啟用。了解這個作用域的運作方式，有助你決定哪些內容保持私有，以及哪些內容需要刻意分享。

### 委派如何劃分記憶作用域

每次委派都會為子 Agent 建立全新的 `threadId`，以及確定性的 `resourceId`：

- **執行緒 ID**：每次委派均為唯一。子 Agent 每次獲呼叫時，都會從空白的訊息歷史記錄開始。
- **資源 ID**：以 `{parentResourceId}-{agentName}` 衍生。由於資源 ID 在不同委派之間保持穩定，資源作用域的記憶可跨呼叫保留。子 Agent 會記得同一使用者先前委派中的事實。
- **Memory 實例**：沒有自訂記憶的子 Agent 會繼承監督 Agent 的 `Memory` 實例及所有已設定的選項。如果子 Agent 定義了自己的實例，便會優先使用該實例。

:::note

標題產生（`generateTitle`）屬於最上層執行緒的事項，**不會**套用至繼承的子 Agent 執行緒。由於每次委派都會建立無人查看的暫時執行緒，為它產生標題會導致每次委派浪費一次 LLM 呼叫。如要為子 Agent 自己的執行緒產生標題，請為該子 Agent 提供自己的記憶設定。

:::

監督 Agent 會將其對話上下文轉交子 Agent，讓子 Agent 有足夠背景完成工作。只有委派提示及子 Agent 的回應會被儲存，完整的上層對話不會儲存。你可以使用 [`messageFilter`](/docs/capabilities/subagents#message-filtering) 回呼函式，控制哪些訊息會傳送至子 Agent。

:::note

子 Agent 的資源 ID 一律以 Agent 名稱作為後綴（`{parentResourceId}-{agentName}`）。同一監督 Agent 轄下的不同子 Agent，絕不會透過委派共用資源 ID。

:::

如要突破這種預設隔離，你可以在直接呼叫 Agent 時傳遞相同的識別碼，讓不同 Agent 共用記憶。

### 在 Agent 之間共用記憶

當你直接呼叫 Agent（在委派流程以外）時，記憶共用由兩個識別碼控制：`resourceId` 及 `threadId`。使用相同值的 Agent 會讀寫相同資料。這適用於多個 Agent 協作處理共用上下文的情況，例如由研究 Agent 儲存筆記，再由寫作 Agent 讀取。

**資源作用域共用**是最常見的模式。[工作記憶](../memory/working-memory)及[語義回憶](../memory/semantic-recall)預設使用 `scope: 'resource'`。如果兩個 Agent 共用一個 `resourceId`，即使使用不同執行緒，它們亦會共用觀察資料、工作記憶及嵌入：

```typescript
// Both agents share the same resource-scoped memory
await researcher.generate('Find information about quantum computing.', {
  memory: { resource: 'project-42', thread: 'research-session' },
})

await writer.generate('Write a summary from the research notes.', {
  memory: { resource: 'project-42', thread: 'writing-session' },
})
```

由於兩次呼叫都使用 `resource: 'project-42'`，寫作 Agent 可以存取研究 Agent 的觀察資料及工作記憶。語義嵌入亦會透過該資源共用。每個 Agent 仍有自己的執行緒，因此訊息歷史記錄會保持分開。

**執行緒作用域共用**可提供更緊密的連繫。[Observational Memory](../memory/observational-memory) 預設使用 `scope: 'thread'`。如果兩個 Agent 使用相同的 `resource` 及 `thread`，便會共用完整的訊息歷史記錄。每個 Agent 都會看到另一個 Agent 寫入的每則訊息。這適用於 Agent 需要以彼此的確切輸出為基礎繼續工作的情況。

## 可觀測性

啟用 [Tracing](/docs/observability/tracing/overview)，以監察及除錯實際運作中的記憶。Trace 會準確顯示 Agent 在每次請求的上下文中加入了哪些訊息及觀察資料，協助你了解 Agent 行為，並確認記憶擷取功能如預期般運作。

開啟 [Studio](/docs/studio/overview)，然後在側邊欄選擇 **Observability** 分頁。開啟近期 Agent 請求的 Trace，並尋找其 LLM 呼叫 span。

## 按請求切換記憶

使用 [`RequestContext`](/docs/server/request-context) 存取請求特定的值。這讓你可根據請求的上下文，有條件地選擇不同的記憶或儲存設定。

```typescript title="src/mastra/agents/memory-agent.ts"
export type UserTier = {
  'user-tier': 'enterprise' | 'pro'
}

const premiumMemory = new Memory()
const standardMemory = new Memory()

export const memoryAgent = new Agent({
  id: 'memory-agent',
  name: 'Memory Agent',
  memory: ({ requestContext }) => {
    const userTier = requestContext.get('user-tier') as UserTier['user-tier']

    return userTier === 'enterprise' ? premiumMemory : standardMemory
  },
})
```

如需更多資訊，請參閱 [Request Context](/docs/server/request-context)。
