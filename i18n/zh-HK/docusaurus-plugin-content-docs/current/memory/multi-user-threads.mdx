# 多使用者執行緒

多個使用者可以共用同一個 Mastra 執行緒，而每個使用者都有自己的姓名及功能角色。你需要在訊息正文中攜帶說話者身分，讓 Agent 從同一個共用執行緒讀取內容時，能夠分辨不同使用者。

## 何時使用多使用者執行緒

當多人透過同一個 Agent 就同一主題協作時，請使用多使用者執行緒：

- 由編輯、審閱者及批核者共同處理的協作文件
- 由一個助手服務多名參與者的群組聊天
- 不同角色具有不同權限的多方審閱

## 所有參與者共用一個 `resourceId`

一個執行緒只屬於一個 `resourceId`，因此共用執行緒上的所有參與者都需要傳入相同值。不要使用使用者 ID（單一使用者應用程式的預設做法），而應以對話本身作為 `resourceId` 的鍵，例如共用文件使用 `doc_${docId}`，群組聊天則使用 `room_${roomId}`。所有人都指向同一個 `resourceId` 後，便會讀寫相同的歷史。

## 以說話者身分標記每則使用者訊息

模型需要知道每一輪由誰發言。由於訊息正文是唯一會保留在歷史中，並重新進入上下文的部分，因此請將每則使用者訊息包在小型 `<turn>` 標籤中，當中包含說話者的 ID、姓名及角色。標籤會一直附於訊息，因此召回先前的對話輪次時，模型仍可看到誰說了甚麼。

使用小型輔助函式建立標籤。以下範例是其中一種做法；請將它複製到你的項目，並按使用者資料的結構加以調整：

```typescript title="src/mastra/identity.ts"
export type Speaker = {
  id: string
  name: string
  role: string
}

function escapeAttr(value: string) {
  return value
    .replace(/&/g, '&amp;')
    .replace(/"/g, '&quot;')
    .replace(/</g, '&lt;')
    .replace(/>/g, '&gt;')
}

export function asUserTurn(speaker: Speaker, text: string) {
  const id = escapeAttr(speaker.id)
  const name = escapeAttr(speaker.name)
  const role = escapeAttr(speaker.role)
  return {
    role: 'user' as const,
    content: `<turn author_id="${id}" author_name="${name}" functional_role="${role}">
${text}
</turn>`,
  }
}
```

在 Agent 的指示中教它如何讀取 `<turn>` 標籤。Agent 必須已設定 `memory`，才能使用 `thread` 及 `resource` 呼叫：

```typescript title="src/mastra/agents/collab.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'
import { LibSQLStore } from '@mastra/libsql'

const memory = new Memory({
  storage: new LibSQLStore({ id: 'collab-storage', url: 'file:./collab.db' }),
  options: {
    lastMessages: 20,
  },
})

export const collabAgent = new Agent({
  id: 'collab',
  name: 'CollabAgent',
  model: '__GATEWAY_OPENAI_MODEL_MINI__',
  memory,
  instructions: `
You are a collaborative document assistant. Multiple users talk to you in the SAME thread.

Every user message is wrapped in a <turn> tag carrying the user's identity:

  <turn author_id="u_alice" author_name="Alice" functional_role="editor">
  ...message text...
  </turn>

Rules:
1. Address users by their author_name.
2. Respect functional_role: editors propose changes, reviewers approve.
3. When attributing past statements, read author_name from the surrounding <turn> tag.
4. Do not echo the <turn> tags back at users.
  `.trim(),
})
```

使用包裝後的訊息呼叫 Agent。每名參與者共用相同的 `thread` 及 `resource`：

```typescript title="src/mastra/call.ts"
import { asUserTurn } from './identity'

const docResourceId = 'doc_42'
const docThreadId = 'doc_42'

const alice = { id: 'u_alice', name: 'Alice', role: 'editor' }
const bob = { id: 'u_bob', name: 'Bob', role: 'reviewer' }

await collabAgent.generate([asUserTurn(alice, 'My favorite color is teal.')], {
  memory: { thread: docThreadId, resource: docResourceId },
})

await collabAgent.generate([asUserTurn(bob, 'I want QA sign-off before publish.')], {
  memory: { thread: docThreadId, resource: docResourceId },
})
```

`<turn>` 標籤會保留在訊息正文中，因此在之後的對話輪次召回歷史時，模型仍會看到誰說了甚麼。

## 與記憶層配合使用

使用者標記模式可以配合每一個記憶層使用。請根據對話需要記住各使用者相關事實的時間長度選擇記憶層：

- **短對話**（單一工作階段，或小得足以放進 `lastMessages` 的執行緒），或需要逐字記錄誰說了甚麼時：只使用[訊息歷史](#message-history-alone)。歷史中的使用者標籤已經足夠，不需要額外記憶層。
- **長時間運行的執行緒**（對話增長至超出 `lastMessages`，並需要在歷史淘汰後保留各使用者相關事實）：使用[觀察式記憶](#with-observational-memory-recommended)。
- **需要結構化的參與者清單，或儲存配接器不支援 OM**（OM 需要 LibSQL、PG 或 MongoDB）：使用[工作記憶](#with-working-memory)。

我們建議使用觀察式記憶或工作記憶其中一種，因為兩者涵蓋的需要有所重疊。同時運行兩者會增加延遲及 token 成本，但效益不大。

### 只使用訊息歷史

對於短對話，或需要逐字記錄誰說了甚麼的情況，歷史中的使用者標籤已經足夠。`lastMessages` 會將先前的對話輪次連同完整的歸屬資料帶回上下文：

```typescript title="src/mastra/agents/collab-basic.ts"
import { Memory } from '@mastra/memory'
import { LibSQLStore } from '@mastra/libsql'

const memory = new Memory({
  storage: new LibSQLStore({ id: 'collab-storage', url: 'file:./collab.db' }),
  options: {
    lastMessages: 20,
  },
})
```

模型會從目前訊息的 `<turn>` 標籤讀取身分，亦會從透過 `lastMessages` 帶回的先前已標記訊息讀取身分。

### 配合觀察式記憶使用（建議）

[觀察式記憶](../memory/observational-memory)（OM）會將各使用者相關事實擷取到背景記錄，而不會耗用 Agent 的 Tool 額度。預設 Observer 模型可直接讀取 `<turn>` 標籤，並產生 `Alice stated her favorite color is teal.` 及 `Bob asked for QA sign-off before publish.` 等歸屬內容。

當儲存空間支援 OM 時，多使用者執行緒應優先使用 OM 而非工作記憶。OM 會自動擷取事實，可擴展至任意數目的參與者，而且毋須維護範本。啟用時毋須覆寫任何設定：

```typescript title="src/mastra/agents/collab-om.ts"
import { Memory } from '@mastra/memory'
import { LibSQLStore } from '@mastra/libsql'

const memory = new Memory({
  storage: new LibSQLStore({ id: 'collab-storage', url: 'file:./collab.db' }),
  options: {
    lastMessages: 20,
    observationalMemory: true,
  },
})
```

OM 需要支援它的儲存配接器：`@mastra/libsql`、`@mastra/pg`、`@mastra/mongodb` 或 `@mastra/oracledb`。

:::note

如果你將 Observer 切換至能力較弱的模型，並發現事實被歸納至籠統的 `User`，請使用 [`observation.instruction`](/reference/memory/observational-memory) 教導 Observer 如何讀取 `<turn>` 標籤。

:::

### 配合工作記憶使用

當 OM 不適用時，例如儲存配接器不支援 OM，或你需要一份結構化、具確定性，且 Agent 可在每輪讀寫的參與者清單，請使用工作記憶。

預設[工作記憶](../memory/working-memory)範本假設每個執行緒只有一名使用者（「First Name」、「Last Name」等）。對於多使用者執行緒，請提供包含參與者清單的範本：

```typescript title="src/mastra/agents/collab-wm.ts"
import { Memory } from '@mastra/memory'
import { LibSQLStore } from '@mastra/libsql'

const memory = new Memory({
  storage: new LibSQLStore({ id: 'collab-storage', url: 'file:./collab.db' }),
  options: {
    lastMessages: 20,
    workingMemory: {
      enabled: true,
      scope: 'thread',
      template: `# Document Collaboration State

## Participants
<!-- One entry per known collaborator. Use author_id as the stable key. -->
<!-- - **<author_name>** (<author_id>, <functional_role>): <their position> -->

## Open Questions

## Decisions
`,
    },
  },
})
```

設定 `scope: 'thread'`，令參與者清單屬於文件，而不是任何個別使用者。另加一項指示，要求 Agent 每當新的 `author_id` 出現在 `<turn>` 中時，便將新參與者附加至清單。

如要進一步了解範本，請參閱[自訂範本](../memory/working-memory#custom-templates)。

## 保安

請從經驗證的請求上下文設定 `speaker`，切勿從請求正文設定。如果客戶端可以自行選擇 `author_id`，一名使用者便可冒充另一名使用者。請使用[請求上下文](/docs/server/request-context)，從驗證層讀取已驗證的使用者，並在呼叫 Agent 前於伺服器上建立 `<turn>` 標籤。
