# 多用戶執行緒

多名用戶可以共用同一個 Mastra 執行緒，而每名用戶都有自己的名稱和職能角色。你可在訊息內文中附上發言者身分，讓 Agent 從單一共用執行緒讀取內容時，仍能分辨不同用戶。

## 何時使用多用戶執行緒

當多個人透過同一個 Agent 就相同主題協作時，可使用多用戶執行緒：

- 由編輯、審閱者和審批者共同處理的協作文件
- 由一個編程助手服務多名參與者的群組對話
- 不同角色擁有不同權限的多方審閱

## 所有參與者共用一個 `resourceId`

一個執行緒只屬於一個 `resourceId`，因此共用執行緒上的所有參與者都需要傳入相同的值。不要使用用戶 ID（單用戶應用程式的預設做法），而應根據對話本身設定 `resourceId`；例如，共用文件可使用 `doc_${docId}`，群組對話則可使用 `room_${roomId}`。當所有人都指向相同的 `resourceId`，他們便會讀寫同一份記錄。

## 在每則用戶訊息中標記發言者身分

模型需要知道每一輪是誰在發言。訊息內文是唯一會保留在記錄中並重新載入至上下文的位置，因此請將每則用戶訊息包在小型 `<turn>` 標籤內，並加入發言者的 ID、名稱和角色。標籤會一直附在訊息上，所以系統重新載入之前的對話輪次時，模型仍能看到每句說話出自誰人。

使用小型輔助函式建立標籤。以下範例是其中一種做法；請將它複製至你的項目，並按你的用戶資料結構調整：

```typescript title="src/mastra/identity.ts"
export type Speaker = {
  id: string
  name: string
  role: string
}

function escapeAttr(value: string) {
  return value
    .replace(/&/g, '&amp;')
    .replace(/"/g, '&quot;')
    .replace(/</g, '&lt;')
    .replace(/>/g, '&gt;')
}

export function asUserTurn(speaker: Speaker, text: string) {
  const id = escapeAttr(speaker.id)
  const name = escapeAttr(speaker.name)
  const role = escapeAttr(speaker.role)
  return {
    role: 'user' as const,
    content: `<turn author_id="${id}" author_name="${name}" functional_role="${role}">
${text}
</turn>`,
  }
}
```

在 Agent 的 instructions 中，教它如何讀取 `<turn>` 標籤。Agent 必須已設定 `memory`，這樣才能使用 `thread` 和 `resource` 呼叫它：

```typescript title="src/mastra/agents/collab.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'
import { LibSQLStore } from '@mastra/libsql'

const memory = new Memory({
  storage: new LibSQLStore({ id: 'collab-storage', url: 'file:./collab.db' }),
  options: {
    lastMessages: 20,
  },
})

export const collabAgent = new Agent({
  id: 'collab',
  name: 'CollabAgent',
  model: '__GATEWAY_OPENAI_MODEL_MINI__',
  memory,
  instructions: `
You are a collaborative document assistant. Multiple users talk to you in the SAME thread.

Every user message is wrapped in a <turn> tag carrying the user's identity:

  <turn author_id="u_alice" author_name="Alice" functional_role="editor">
  ...message text...
  </turn>

Rules:
1. Address users by their author_name.
2. Respect functional_role: editors propose changes, reviewers approve.
3. When attributing past statements, read author_name from the surrounding <turn> tag.
4. Do not echo the <turn> tags back at users.
  `.trim(),
})
```

使用經包裝的訊息呼叫 Agent。每名參與者都共用相同的 `thread` 和 `resource`：

```typescript title="src/mastra/call.ts"
import { asUserTurn } from './identity'

const docResourceId = 'doc_42'
const docThreadId = 'doc_42'

const alice = { id: 'u_alice', name: 'Alice', role: 'editor' }
const bob = { id: 'u_bob', name: 'Bob', role: 'reviewer' }

await collabAgent.generate([asUserTurn(alice, 'My favorite color is teal.')], {
  memory: { thread: docThreadId, resource: docResourceId },
})

await collabAgent.generate([asUserTurn(bob, 'I want QA sign-off before publish.')], {
  memory: { thread: docThreadId, resource: docResourceId },
})
```

`<turn>` 標籤會保留在訊息內文中，因此系統在之後的對話輪次重新載入記錄時，模型仍能看到每句說話出自誰人。

## 與記憶層配合使用

用戶標記模式可與每個記憶層配合使用。請按對話需要記住每名用戶資料的時間長短選擇合適的層：

- **短對話**（單一工作階段，或規模足以容納於 `lastMessages` 的執行緒），或需要逐字記錄每句說話出自誰人時：只使用[訊息記錄](#message-history-alone)。記錄中的用戶標籤已經足夠，無需額外記憶層。
- **長期執行緒**（對話內容超出 `lastMessages`，而且需要在記錄被移除後仍保留每名用戶的資料）：使用[觀察式記憶](#with-observational-memory-recommended)。
- **需要結構化參與者清單，或儲存適配器不支援 OM**（OM 需要 LibSQL、PG 或 MongoDB）：使用[工作記憶](#with-working-memory)。

我們建議使用觀察式記憶或工作記憶其中之一，因為兩者涵蓋的需要有所重疊。同時運行兩者會增加延遲和 token 成本，卻沒有太大效益。

### 只使用訊息記錄

對於短對話，或需要逐字記錄每句說話出自誰人時，記錄中的用戶標籤已經足夠。`lastMessages` 會將之前的對話輪次連同完整的發言者資料重新載入至上下文：

```typescript title="src/mastra/agents/collab-basic.ts"
import { Memory } from '@mastra/memory'
import { LibSQLStore } from '@mastra/libsql'

const memory = new Memory({
  storage: new LibSQLStore({ id: 'collab-storage', url: 'file:./collab.db' }),
  options: {
    lastMessages: 20,
  },
})
```

模型會從目前訊息的 `<turn>` 標籤，以及透過 `lastMessages` 重新載入並已加上標籤的之前訊息中讀取身分資料。

### 配合 Observational Memory 使用（建議）

[Observational Memory](../memory/observational-memory)（OM）會將每名用戶的資料擷取至背景記錄，而不會耗用 Agent 的 Tool 額度。預設 Observer 模型能直接讀取 `<turn>` 標籤，並產生如 `Alice stated her favorite color is teal.` 和 `Bob asked for QA sign-off before publish.` 的發言者資料。

如果你的儲存空間支援 OM，在多用戶執行緒中應優先選用 OM，而非工作記憶。OM 會自動擷取資料、可擴展至任意數量的參與者，而且無需維護範本。啟用時不必覆寫任何設定：

```typescript title="src/mastra/agents/collab-om.ts"
import { Memory } from '@mastra/memory'
import { LibSQLStore } from '@mastra/libsql'

const memory = new Memory({
  storage: new LibSQLStore({ id: 'collab-storage', url: 'file:./collab.db' }),
  options: {
    lastMessages: 20,
    observationalMemory: true,
  },
})
```

OM 需要支援它的儲存適配器：`@mastra/libsql`、`@mastra/pg`、`@mastra/mongodb` 或 `@mastra/oracledb`。

:::note

如果你將 Observer 改為較弱的模型後，發現資料都歸入通用的 `User`，請使用 [`observation.instruction`](/reference/memory/observational-memory) 教 Observer 如何讀取 `<turn>` 標籤。

:::

### 配合工作記憶使用

當 OM 並不可行時，便應使用工作記憶；例如，儲存適配器不支援 OM，或需要 Agent 在每一輪都能讀寫結構化而且結果一致的參與者清單時。

預設[工作記憶](../memory/working-memory)範本假設每個執行緒只有一名用戶（「First Name」、「Last Name」等）。對於多用戶執行緒，請提供包含參與者清單的範本：

```typescript title="src/mastra/agents/collab-wm.ts"
import { Memory } from '@mastra/memory'
import { LibSQLStore } from '@mastra/libsql'

const memory = new Memory({
  storage: new LibSQLStore({ id: 'collab-storage', url: 'file:./collab.db' }),
  options: {
    lastMessages: 20,
    workingMemory: {
      enabled: true,
      scope: 'thread',
      template: `# Document Collaboration State

## Participants
<!-- One entry per known collaborator. Use author_id as the stable key. -->
<!-- - **<author_name>** (<author_id>, <functional_role>): <their position> -->

## Open Questions

## Decisions
`,
    },
  },
})
```

設定 `scope: 'thread'`，讓參與者清單屬於文件，而非任何個別用戶。加入一項 instruction，指示 Agent 每當新的 `author_id` 出現在 `<turn>` 中時，便將新參與者加到清單末尾。

如要進一步了解範本，請參閱[自訂範本](../memory/working-memory#custom-templates)。

## 安全性

請從已驗證的請求上下文設定 `speaker`，切勿從請求內文設定。如果客戶端可以自行選擇 `author_id`，一名用戶便可冒充另一名用戶。使用 [Request Context](/docs/server/request-context) 從驗證層讀取已驗證的用戶，並在呼叫 Agent 前於伺服器上建立 `<turn>` 標籤。
