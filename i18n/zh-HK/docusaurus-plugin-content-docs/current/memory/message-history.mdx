# 訊息歷史

訊息歷史是最基本亦最重要的記憶形式。它讓 LLM 在上下文視窗中看到近期訊息，使 Agent 能夠引用較早的交流內容，並作出連貫回應。

你亦可以擷取訊息歷史，在 UI 中顯示過往對話。

:::info
每則訊息都屬於一個執行緒（對話），以及一項資源（與訊息相關聯的使用者或實體）。詳情請參閱[執行緒與資源](#threads-and-resources)。
:::

:::warning
當你在客戶端應用程式中使用記憶時，客戶端應**只傳送新訊息**，而不是完整的對話歷史。

傳送完整歷史並無必要，因為 Mastra 會從儲存空間載入訊息；而且當客戶端的時間戳記與已儲存的時間戳記衝突時，亦可能引致訊息排序錯誤。

如需 AI SDK 範例，請參閱[使用 Mastra Memory](/guides/build-your-ui/ai-sdk-ui#using-mastra-memory)。
:::

## 執行緒與資源

Mastra 使用兩個識別碼整理對話：

- **執行緒**：包含一連串訊息的對話工作階段。
- **資源**：擁有該執行緒的實體，例如使用者、機構、項目，或應用程式中的其他領域實體。

Studio 會自動為你產生執行緒及資源 ID。自行呼叫 `stream()` 或 `generate()` 時，請明確提供這些識別碼。

## 開始使用

安裝 Mastra 記憶模組，以及適用於你的資料庫的[儲存配接器](/docs/storage/overview#supported-providers)。以下範例使用 `@mastra/libsql`，它會將資料儲存在本機的 `mastra.db` 檔案中。

```bash npm2yarn
npm install @mastra/memory@latest @mastra/libsql@latest
```

訊息歷史需要儲存配接器，才能持久儲存對話。如果你尚未設定，請在 Mastra 執行個體上設定儲存：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: 'file:./mastra.db',
  }),
})
```

在 Agent 中建立 [`Memory`](/reference/memory/memory-class) 執行個體：

```typescript title="src/mastra/agents/test-agent.ts"
import { Memory } from '@mastra/memory'
import { Agent } from '@mastra/core/agent'

export const agent = new Agent({
  id: 'test-agent',
  memory: new Memory({
    options: {
      lastMessages: 10,
    },
  }),
})
```

呼叫 Agent 時，訊息會自動儲存至資料庫。你可以指定 `threadId`、`resourceId`，以及可選的 `metadata`：

<Tabs>
  <TabItem value="generate" label=".generate()">
    ```typescript
    await agent.generate('Hello', {
      memory: {
        thread: {
          id: 'thread-123',
          title: 'Support conversation',
          metadata: { category: 'billing' },
        },
        resource: 'user-456',
      },
    })
    ```
  </TabItem>

  <TabItem value="stream" label=".stream()">

    ```typescript
    await agent.stream('Hello', {
      memory: {
        thread: {
          id: 'thread-123',
          title: 'Support conversation',
          metadata: { category: 'billing' },
        },
        resource: 'user-456',
      },
    })
    ```
  </TabItem>
</Tabs>

:::info

呼叫 `agent.generate()` 或 `agent.stream()` 時，系統會自動建立執行緒及訊息；你亦可以使用 [`createThread()`](/reference/memory/createThread) 及 [`saveMessages()`](/reference/memory/memory-class) 手動建立。

:::

你可以透過兩種方式使用這些歷史：

- **自動加入**：Mastra 會自動擷取近期訊息並將其加入上下文視窗。預設會加入最後 10 則訊息，讓 Agent 的回應以對話為依據。你可以使用 `lastMessages` 調整此數目，但在大部分情況下都毋須特別處理。
- [**手動查詢**](#querying)：如需更精細的控制，可使用 `recall()` 函式直接查詢執行緒及訊息。這讓你能夠準確選擇要在上下文視窗中加入哪些記憶，或擷取訊息以在 UI 中呈現對話歷史。

:::tip

啟用記憶後，[Studio](/docs/studio/overview) 會使用訊息歷史，在聊天側邊欄中顯示過往對話。

:::

## 產生執行緒標題

啟用 `generateTitle` 後，Mastra 可以根據對話文字記錄，自動產生描述性的執行緒標題。當你建立的聊天介面會在執行緒清單或側邊欄呈現對話標題時，便可使用此選項。

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support agent',
  instructions: 'Answer customer support questions.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    options: {
      generateTitle: true,
    },
  }),
})
```

標題會在 Agent 回應後以非同步方式產生，不會影響回應時間。

如要最佳化成本或行為，請提供較小的 [`model`](/models) 及自訂 `instructions`：

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support agent',
  instructions: 'Answer customer support questions.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    options: {
      generateTitle: {
        model: '__GATEWAY_OPENAI_MODEL_MINI__',
        instructions: 'Generate a one-word title.',
      },
    },
  }),
})
```

## 存取記憶

如要使用查詢、複製或刪除執行緒與訊息的記憶函式，請在 Agent 上呼叫 `getMemory()`：

```typescript
const agent = mastra.getAgentById('test-agent')
const memory = await agent.getMemory()
```

`Memory` 執行個體讓你可以使用列出執行緒、召回訊息、複製對話等函式。

## 查詢

使用以下方法擷取執行緒及訊息，以在 UI 中顯示對話歷史，或用於自訂記憶擷取邏輯。

:::warning
記憶系統不會強制執行存取控制。執行任何查詢前，請在應用程式邏輯中確認目前使用者獲授權存取所查詢的 `resourceId`。
:::

### 執行緒

使用 [`listThreads()`](/reference/memory/listThreads) 擷取某項資源的執行緒：

```typescript
const result = await memory.listThreads({
  filter: { resourceId: 'user-123' },
  perPage: false,
})
```

分頁瀏覽執行緒：

```typescript
const result = await memory.listThreads({
  filter: { resourceId: 'user-123' },
  page: 0,
  perPage: 10,
})

console.log(result.threads) // thread objects
console.log(result.hasMore) // more pages available?
```

你亦可以按 metadata 篩選，並控制排序次序：

```typescript
const result = await memory.listThreads({
  filter: {
    resourceId: 'user-123',
    metadata: { status: 'active' },
  },
  orderBy: { field: 'createdAt', direction: 'DESC' },
})
```

如要按 ID 擷取單一執行緒，請使用 [`getThreadById()`](/reference/memory/getThreadById)：

```typescript
const thread = await memory.getThreadById({ threadId: 'thread-123' })
```

### 訊息

取得執行緒後，使用 [`recall()`](/reference/memory/recall) 擷取其中的訊息。它支援分頁、日期篩選及[語義搜尋](/docs/memory/semantic-recall)。

基本召回會傳回執行緒中的所有訊息：

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  perPage: false,
})
```

分頁瀏覽訊息：

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  page: 0,
  perPage: 50,
})
```

按日期範圍篩選：

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  filter: {
    dateRange: {
      start: new Date('2025-01-01'),
      end: new Date('2025-06-01'),
    },
  },
})
```

按淺層訊息 metadata 篩選：

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  filter: {
    metadata: {
      category: 'billing',
      escalated: true,
      priority: 2,
      archivedAt: null,
    },
  },
})
```

Metadata 篩選條件只會配對淺層純量值：`string`、有限的 `number`、`boolean` 及 `null`。

所有指定的 metadata 鍵都採用 AND 語義。`null` 篩選條件只會配對明確的 `null` 值。缺少 metadata 鍵時不會配對。

Metadata 鍵必須以字母或底線開頭，並且只可包含英數字元。長度不得超過 128 個字元，而且不可使用 `__proto__`、`constructor` 或 `prototype` 等保留的 prototype 鍵。

效能視乎儲存後端而定。部分後端可以將部分篩選條件推送至資料庫；其他後端則會先套用執行緒、資源及日期限制，然後掃描候選訊息，再進行分頁。

按 ID 擷取單一訊息：

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  include: [{ id: 'msg-123' }],
})
```

按 ID 擷取多則訊息及其周邊上下文：

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  include: [
    { id: 'msg-123' },
    {
      id: 'msg-456',
      withPreviousMessages: 3,
      withNextMessages: 1,
    },
  ],
})
```

按語義搜尋（設定方法請參閱[語義召回](/docs/memory/semantic-recall)）：

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  vectorSearchString: 'project deadline discussion',
  threadConfig: {
    semanticRecall: true,
  },
})
```

### UI 格式

訊息查詢會傳回 `MastraDBMessage[]` 格式。如要在前端顯示訊息，你可能需要將它們轉換成 UI 程式庫所預期的格式。例如，[`toAISdkV5Messages`](/reference/ai-sdk/to-ai-sdk-v5-messages) 可將訊息轉換成 AI SDK UI 格式。

## 複製執行緒

複製執行緒會建立現有執行緒及其訊息的副本。這適合用於建立對話分支、在可能具破壞性的操作前建立檢查點，或測試對話的不同變化。

```typescript
const { thread, clonedMessages } = await memory.cloneThread({
  sourceThreadId: 'thread-123',
  title: 'Branched conversation',
})
```

你可以篩選要複製的訊息（按數量或日期範圍）、指定自訂執行緒 ID，並使用公用程式方法檢查複製關係。

如需完整 API，請參閱 [`cloneThread()`](/reference/memory/cloneThread) 及[複製公用程式](/reference/memory/clone-utilities)。

## 刪除訊息

如要從執行緒移除訊息，請使用 [`deleteMessages()`](/reference/memory/deleteMessages)。你可以按訊息 ID 刪除，或清除執行緒中的所有訊息。
