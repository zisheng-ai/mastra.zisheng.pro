# 訊息記錄

訊息記錄是最基本亦最重要的記憶形式。它讓 LLM 在上下文視窗中查看近期訊息，使 Agent 能夠參考較早前的交流並連貫地回應。

你亦可以擷取訊息記錄，在 UI 中顯示過往對話。

:::info
每則訊息都屬於一個 thread（對話）和一個 resource（與其關聯的使用者或實體）。詳情請參閱 [Thread 和 resource](#threads-and-resources)。
:::

:::warning
在客戶端應用程式中使用記憶時，客戶端應**只傳送新訊息**，而非完整的對話記錄。

由於 Mastra 會從儲存空間載入訊息，傳送完整記錄屬於重複操作；若客戶端的時間戳記與已儲存的時間戳記互相衝突，亦可能導致訊息排序錯誤。

如需 AI SDK 範例，請參閱[使用 Mastra Memory](/guides/build-your-ui/ai-sdk-ui#using-mastra-memory)。
:::

## Thread 和 resource

Mastra 使用兩個識別碼來整理對話：

- **Thread**：包含一連串訊息的對話工作階段。
- **Resource**：擁有 thread 的實體，例如使用者、機構、項目，或應用程式中的其他領域實體。

Studio 會自動為你產生 thread 和 resource ID。自行呼叫 `stream()` 或 `generate()` 時，請明確提供這些識別碼。

## 開始使用

安裝 Mastra 記憶模組，以及適用於你資料庫的[儲存轉接器](/docs/storage/overview#supported-providers)。以下範例使用 `@mastra/libsql`，它會將資料儲存在本機的 `mastra.db` 檔案中。

```bash npm2yarn
npm install @mastra/memory@latest @mastra/libsql@latest
```

訊息記錄需要儲存轉接器才能持久保存對話。如尚未設定，請在 Mastra 實例上設定儲存空間：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: 'file:./mastra.db',
  }),
})
```

在 Agent 中建立一個 [`Memory`](/reference/memory/memory-class) 實例：

```typescript title="src/mastra/agents/test-agent.ts"
import { Memory } from '@mastra/memory'
import { Agent } from '@mastra/core/agent'

export const agent = new Agent({
  id: 'test-agent',
  memory: new Memory({
    options: {
      lastMessages: 10,
    },
  }),
})
```

呼叫 Agent 時，訊息會自動儲存至資料庫。你可以指定 `threadId`、`resourceId`，以及選填的 `metadata`：

<Tabs>
  <TabItem value="generate" label=".generate()">

    await agent.generate('Hello', {
      memory: {
        thread: {
          id: 'thread-123',
          title: 'Support conversation',
          metadata: { category: 'billing' },
        },
        resource: 'user-456',
      },
    })
    ```
  </TabItem>

  <TabItem value="stream" label=".stream()">

    await agent.stream('Hello', {
      memory: {
        thread: {
          id: 'thread-123',
          title: 'Support conversation',
          metadata: { category: 'billing' },
        },
        resource: 'user-456',
      },
    })
    ```
  </TabItem>
</Tabs>

:::info

呼叫 `agent.generate()` 或 `agent.stream()` 時，系統會自動建立 thread 和訊息；你亦可以使用 [`createThread()`](/reference/memory/createThread) 和 [`saveMessages()`](/reference/memory/memory-class) 手動建立它們。

:::

你可以透過兩種方式使用這些記錄：

- **自動加入**：Mastra 會自動擷取近期訊息並將其加入上下文視窗。預設會加入最近 10 則訊息，讓 Agent 的回應緊扣對話內容。你可以使用 `lastMessages` 調整此數目，但大多數情況下都無需處理這項設定。
- [**手動查詢**](#querying)：如需更多控制，可使用 `recall()` 函數直接查詢 thread 和訊息。這讓你能精確選擇要在上下文視窗中加入哪些記憶，或擷取訊息以在 UI 中呈現對話記錄。

:::tip

啟用記憶後，[Studio](/docs/studio/overview) 會使用訊息記錄，在聊天側邊欄顯示過往對話。

:::

## 產生 thread 標題

啟用 `generateTitle` 後，Mastra 可根據對話文字記錄自動產生描述性的 thread 標題。如你建立的聊天介面會在 thread 清單或側邊欄顯示對話標題，可使用此選項。

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support agent',
  instructions: 'Answer customer support questions.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    options: {
      generateTitle: true,
    },
  }),
})
```

標題會在 Agent 回應後以非同步方式產生，不會影響回應時間。

如要最佳化成本或行為，請提供較小的 [`model`](/models) 和自訂 `instructions`：

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support agent',
  instructions: 'Answer customer support questions.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    options: {
      generateTitle: {
        model: '__GATEWAY_OPENAI_MODEL_MINI__',
        instructions: 'Generate a one-word title.',
      },
    },
  }),
})
```

## 存取記憶

如要存取用於查詢、複製或刪除 thread 和訊息的記憶函數，請在 Agent 上呼叫 `getMemory()`：

```typescript
const agent = mastra.getAgentById('test-agent')
const memory = await agent.getMemory()
```

你可以透過 `Memory` 實例使用列出 thread 和回想訊息等函數，亦可複製對話及執行更多操作。

## 查詢

使用以下方法擷取 thread 和訊息，以在 UI 中顯示對話記錄，或用於自訂記憶擷取邏輯。

:::warning
記憶系統不會強制執行存取控制。執行任何查詢前，請在應用程式邏輯中確認目前使用者獲授權存取正在查詢的 `resourceId`。
:::

### Thread

使用 [`listThreads()`](/reference/memory/listThreads) 擷取某個 resource 的 thread：

```typescript
const result = await memory.listThreads({
  filter: { resourceId: 'user-123' },
  perPage: false,
})
```

以分頁方式瀏覽 thread：

```typescript
const result = await memory.listThreads({
  filter: { resourceId: 'user-123' },
  page: 0,
  perPage: 10,
})

console.log(result.threads) // thread objects
console.log(result.hasMore) // more pages available?
```

你亦可以按 metadata 篩選並控制排序次序：

```typescript
const result = await memory.listThreads({
  filter: {
    resourceId: 'user-123',
    metadata: { status: 'active' },
  },
  orderBy: { field: 'createdAt', direction: 'DESC' },
})
```

如要按 ID 擷取單一 thread，請使用 [`getThreadById()`](/reference/memory/getThreadById)：

```typescript
const thread = await memory.getThreadById({ threadId: 'thread-123' })
```

### 訊息

取得 thread 後，使用 [`recall()`](/reference/memory/recall) 擷取其訊息。此方法支援分頁、日期篩選和[語意搜尋](/docs/memory/semantic-recall)。

基本回想會傳回 thread 中的所有訊息：

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  perPage: false,
})
```

以分頁方式瀏覽訊息：

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  page: 0,
  perPage: 50,
})
```

按日期範圍篩選：

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  filter: {
    dateRange: {
      start: new Date('2025-01-01'),
      end: new Date('2025-06-01'),
    },
  },
})
```

按淺層訊息 metadata 篩選：

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  filter: {
    metadata: {
      category: 'billing',
      escalated: true,
      priority: 2,
      archivedAt: null,
    },
  },
})
```

Metadata 篩選器只會配對淺層純量值：`string`、有限的 `number`、`boolean` 和 `null`。

所有指定的 metadata key 均採用 AND 語意。`null` 篩選器只會配對明確的 `null` 值。缺少的 metadata key 不會配對。

Metadata key 必須以英文字母或底線開首，並且只能包含英數字元。長度不得超過 128 個字元，亦不能使用 `__proto__`、`constructor` 或 `prototype` 等保留的 prototype key。

效能取決於儲存後端。部分後端可將篩選器的部分條件推送至資料庫，其他後端則會先套用 thread、resource 和日期限制，再掃描候選訊息，最後才分頁。

按 ID 擷取單一訊息：

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  include: [{ id: 'msg-123' }],
})
```

按 ID 擷取多則訊息及其前後文：

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  include: [
    { id: 'msg-123' },
    {
      id: 'msg-456',
      withPreviousMessages: 3,
      withNextMessages: 1,
    },
  ],
})
```

按語意搜尋（設定方法請參閱[語意回想](/docs/memory/semantic-recall)）：

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  vectorSearchString: 'project deadline discussion',
  threadConfig: {
    semanticRecall: true,
  },
})
```

### UI 格式

訊息查詢會傳回 `MastraDBMessage[]` 格式。如要在前端顯示訊息，你可能需要將訊息轉換成 UI 依賴套件所預期的格式。例如，[`toAISdkV5Messages`](/reference/ai-sdk/to-ai-sdk-v5-messages) 會將訊息轉換成 AI SDK UI 格式。

## 複製 thread

複製 thread 會建立現有 thread 及其訊息的副本。這適合用於建立對話分支、在可能造成破壞的操作前建立檢查點，或測試不同的對話版本。

```typescript
const { thread, clonedMessages } = await memory.cloneThread({
  sourceThreadId: 'thread-123',
  title: 'Branched conversation',
})
```

你可以篩選要複製的訊息（按數量或日期範圍）、指定自訂 thread ID，並使用實用工具方法檢查副本關係。

如需完整 API，請參閱 [`cloneThread()`](/reference/memory/cloneThread) 和[複製實用工具](/reference/memory/clone-utilities)。

## 刪除訊息

如要從 thread 移除訊息，請使用 [`deleteMessages()`](/reference/memory/deleteMessages)。你可以按訊息 ID 刪除，或清除 thread 中的所有訊息。
