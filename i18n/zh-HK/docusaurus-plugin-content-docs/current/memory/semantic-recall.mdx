# 語義召回

如果你問朋友上週末做了甚麼，他們會在記憶中搜尋與「上週末」相關的事件，然後告訴你所做的事情。Mastra 的語義召回運作方式與此有點相似。

:::tip[📹 觀看影片]

觀看 [Mastra 語義召回](https://www.youtube.com/watch?v=UVZtK8cK8xQ\&pp=ygUVbWFzdHJhIHdvcmtpbmcgbWVtb3J5)，了解 Agent 如何從過往對話擷取相關訊息。

:::

## 語義召回的運作方式

語義召回是一種以 RAG 為基礎的搜尋。當訊息已不在[近期訊息歷史](./message-history)中時，它可協助 Agent 在較長的互動中維持上下文。

它使用訊息的向量嵌入進行相似度搜尋，並與向量儲存空間整合，而且可以設定擷取訊息周邊的上下文視窗。

![顯示 Mastra Memory 語義召回的圖表](/img/semantic-recall.png)

啟用後，新訊息會用來查詢向量 DB，以尋找語義相似的訊息。

取得 LLM 回應後，所有新訊息（使用者、助手及 Tool 呼叫／結果）都會插入向量 DB，以便在之後的互動中召回。

## 使用 `recall()` 方法

`listMessages` 會使用執行緒 ID 及基本分頁擷取訊息，而 [`recall()`](/reference/memory/recall) 則額外支援**語義搜尋**。當你需要按語義而非新舊程度尋找訊息時，請配合 `vectorSearchString` 使用 `recall()`：

```typescript
const memory = await agent.getMemory()

// Basic recall - similar to listMessages
const { messages } = await memory!.recall({
  threadId: 'thread-123',
  perPage: 50,
})

// Semantic recall - find messages by meaning
const { messages: relevantMessages } = await memory!.recall({
  threadId: 'thread-123',
  vectorSearchString: 'What did we discuss about the project deadline?',
  threadConfig: {
    semanticRecall: true,
  },
})
```

import { Memory } from '@mastra/memory'
import { Agent } from '@mastra/core/agent'

const agent = new Agent({

## 召回設定

以下選項控制語義召回行為：

1. **topK**：要擷取的相似訊息數目
1. **messageRange**：每個配對項目要包含的周邊訊息
1. **scope**：搜尋目前執行緒，還是某項資源的所有執行緒
1. **filter**：限制搜尋結果的 metadata 條件

```typescript {5-9}
const agent = new Agent({
  id: 'agent',
  memory: new Memory({
    options: {
      semanticRecall: {
        topK: 3, // Retrieve 3 similar messages
        messageRange: 2, // Include 2 messages before and after each match
        scope: 'resource', // Search all threads for this resource
        filter: { projectId: { $eq: 'project-a' } },
      },
    },
  }),
})
```

:::note

LibSQL、OracleDB、PostgreSQL、MongoDB 及 Upstash 儲存配接器支援 `scope: 'resource'`。

:::

### Metadata 篩選

`filter` 選項會將語義召回結果限制為執行緒 metadata 相符的訊息。

```typescript {5-10}
const agent = new Agent({
  id: 'agent',
  memory: new Memory({
    options: {
      semanticRecall: {
        scope: 'resource',
        filter: {
          projectId: { $eq: 'project-a' },
          category: { $in: ['work', 'personal'] },
        },
      },
    },
  }),
})
```

篩選條件會配對儲存訊息時一併儲存在訊息嵌入上的 metadata。如果執行緒 metadata 之後變更，現有嵌入會保留先前的 metadata，直至再次儲存這些訊息或為其建立索引。

支援的篩選運算子：

- `$and`：邏輯 AND
- `$eq`：等於
- `$gt`：大於
- `$gte`：大於或等於
- `$in`：位於陣列中
- `$lt`：小於
- `$lte`：小於或等於
- `$ne`：不等於
- `$nin`：不在陣列中
- `$or`：邏輯 OR

以下範例展示常見使用情境的 metadata 篩選條件：

```typescript
// Filter by project
const options = {
  semanticRecall: { filter: { projectId: { $eq: 'my-project' } } },
}

// Filter by multiple categories
const options = {
  semanticRecall: { filter: { category: { $in: ['work', 'research'] } } },
}

// Filter by project and priority
const options = {
  semanticRecall: {
    filter: {
      $and: [{ projectId: { $eq: 'project-a' } }, { priority: { $gte: 3 } }],
    },
  },
}
```

## Embedder 設定

語義召回依靠[嵌入模型](/reference/memory/memory-class)將訊息轉換成嵌入。Mastra 透過 Model Router 使用 `provider/model` 字串支援嵌入模型；你亦可以使用任何與 AI SDK 相容的[嵌入模型](https://sdk.vercel.ai/docs/ai-sdk-core/embeddings)。

### 使用 Model Router（建議）

最簡單的方法是使用支援自動完成的 `provider/model` 字串：

```ts title="src/mastra/agents/index.ts"
import { Memory } from '@mastra/memory'
import { Agent } from '@mastra/core/agent'
import { ModelRouterEmbeddingModel } from '@mastra/core/llm'

const agent = new Agent({
  id: 'agent',
  memory: new Memory({
    embedder: new ModelRouterEmbeddingModel('openai/text-embedding-3-small'),
    options: {
      semanticRecall: true,
    },
  }),
})
```

支援的嵌入模型：

- **OpenAI**：`text-embedding-3-small`、`text-embedding-3-large`、`text-embedding-ada-002`
- **Google**：`gemini-embedding-001`
- **OpenRouter**：存取不同 Provider 的嵌入模型

```ts {7}
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'
import { ModelRouterEmbeddingModel } from '@mastra/core/llm'

const agent = new Agent({
  id: 'agent',
  memory: new Memory({
    embedder: new ModelRouterEmbeddingModel({
      providerId: 'openrouter',
      modelId: 'openai/text-embedding-3-small',
    }),
  }),
})
```

Model Router 會自動偵測環境變數中的 API 金鑰（`OPENAI_API_KEY`、`GOOGLE_API_KEY`、`OPENROUTER_API_KEY`）。Google 模型亦會退而使用 `GOOGLE_GENERATIVE_AI_API_KEY`。

### 使用 AI SDK 套件

你亦可以直接使用 AI SDK 嵌入模型：

```ts {2,7}
import { Memory } from '@mastra/memory'
import { Agent } from '@mastra/core/agent'
import { ModelRouterEmbeddingModel } from '@mastra/core/llm'

const agent = new Agent({
  id: 'agent',
  memory: new Memory({
    embedder: new ModelRouterEmbeddingModel('openai/text-embedding-3-small'),
  }),
})
```

### 使用 FastEmbed（本機）

如要使用 FastEmbed（本機嵌入模型），請安裝 `@mastra/fastembed`：

```bash npm2yarn
npm install @mastra/fastembed@latest
```

然後在記憶中設定：

```ts {3,7}
import { Memory } from '@mastra/memory'
import { Agent } from '@mastra/core/agent'
import { fastembed } from '@mastra/fastembed'

const agent = new Agent({
  id: 'agent',
  memory: new Memory({
    embedder: fastembed,
  }),
})
```

## PostgreSQL 索引最佳化

使用 PostgreSQL 作為向量儲存空間時，你可以設定向量索引，以最佳化語義召回效能。對於有數千則訊息的大規模部署，這點尤其重要。

PostgreSQL 同時支援 IVFFlat 及 HNSW 索引。Mastra 預設會建立 IVFFlat 索引，但 HNSW 索引一般能提供更佳效能，特別是對於使用內積距離的 OpenAI 嵌入。

```typescript {18-23}
import { Memory } from '@mastra/memory'
import { PgStore, PgVector } from '@mastra/pg'

const agent = new Agent({
  memory: new Memory({
    storage: new PgStore({
      id: 'agent-storage',
      connectionString: process.env.DATABASE_URL,
    }),
    vector: new PgVector({
      id: 'agent-vector',
      connectionString: process.env.DATABASE_URL,
    }),
    options: {
      semanticRecall: {
        topK: 5,
        messageRange: 2,
        indexConfig: {
          type: 'hnsw', // Use HNSW for better performance
          metric: 'dotproduct', // Best for OpenAI embeddings
          m: 16, // Number of bi-directional links (default: 16)
          efConstruction: 64, // Size of candidate list during construction (default: 64)
        },
      },
    },
  }),
})
```

有關索引設定選項及效能調校的詳細資訊，請參閱 [PgVector 設定指南](/reference/vectors/pg#index-configuration-guide)。

## 停用語義召回

語義召回預設為停用（`semanticRecall: false`）。每次呼叫都會增加延遲，因為新訊息會先轉換成嵌入並用於查詢向量資料庫，然後才傳送至 LLM。

在以下情況應保持停用語義召回：

- 訊息歷史可為目前對話提供足夠上下文。
- 你正在建立對效能敏感的應用程式，例如即時雙向音訊，而嵌入及向量查詢的延遲會變得明顯。

## 查看召回的訊息

啟用 tracing 後，透過語義召回擷取的所有訊息都會出現在 Agent 的 Trace 輸出中，並與近期訊息歷史（如已設定）一同顯示。
