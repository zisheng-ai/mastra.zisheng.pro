# 開發

建立 Mastra 項目後，你便可開始開發、執行及測試 Agent。

## 在本機執行 Mastra

要最快查看 Agent 的運作情況，可使用 [Mastra Studio](/docs/studio/overview)。在項目根目錄中，使用 [`mastra dev`](/reference/cli/mastra#mastra-dev) 啟動 Studio 和本機開發伺服器：

```bash npm2yarn
npx mastra dev
```

在 [`http://localhost:4111`](http://localhost:4111) 開啟 Studio，以測試 Agent 並檢查其執行記錄。

開發伺服器亦會為 Agent、Tool 和 Workflow 提供 API。在 [`http://localhost:4111/api`](http://localhost:4111/api) 瀏覽可用項目，然後使用 [Mastra Client](/docs/server/mastra-client) 連接前端。

當 `src/mastra/` 目錄有變更時，開發伺服器會自動重新啟動，因此你在建立項目時無需手動重新啟動。

## 使用 AI 建立

Mastra 提供 Skill 和 CLI，協助編程助手編寫高質素的 Mastra 程式碼。

### Mastra Skill

AI 模型未必具備 Mastra API 的最新知識。使用 [Mastra Skill](https://github.com/mastra-ai/skills)，為編程助手提供實作指引、最佳做法，以及取得最新 Mastra 文件的說明。

使用以下命令手動安裝 Skill：

```bash npm2yarn
npx skills add mastra-ai/skills
```

定期更新 Skill，以取得最新指引：

```bash npm2yarn
npx skills update mastra
```

:::note

使用 [create mastra](/docs) 建立項目時，命令會自動安裝 Mastra Skill，讓編程助手能夠找到並使用它。

:::

### Mastra CLI

使用 [`mastra` CLI](/reference/cli/mastra)，讓編程助手可透過反饋循環測試更新並檢查結果。CLI 可讓它存取 Agent、Workflow、Tool、記憶、Evals、Trace 和日誌。

例如，編程助手可執行 Agent，然後擷取 Trace 以檢查結果：

```bash
npx mastra api --url http://localhost:4111 agent run agent '{"messages":"Hello"}'
npx mastra api --url http://localhost:4111 trace list
```

請記得安裝 [Mastra Skill](#mastra-skill)，讓編程助手學會使用 CLI。

## 項目結構

採用框架時，其中一項最先要作出的決定是如何組織項目。我們建議將框架程式碼保留在 `src/mastra/` 下，並把相關基礎元件分組至各自的檔案或資料夾。使用 `src/mastra/index.ts` 作為設定和註冊這些元件的中心位置。

最精簡的項目結構如下：

```text
src/
  mastra/
    agents/
      agent.ts
    tools/
      tool.ts
    workflows/
      workflow.ts
    scorers/
      scorer.ts
    skills.ts
    index.ts
```

如需了解預設配置和建議慣例，請參閱[項目結構參考](/reference/project-structure)。

## 檔案式 Agent

:::experimental

檔案式 Agent 目前處於 beta 階段，穩定版本推出前可能會有變更。

檔案式探索只會透過 `mastra dev` 或 `mastra build` 執行。如果應用程式直接匯入 `mastra`（包括透過網絡框架或伺服器配接器匯入），系統不會找到檔案式 Agent。請在程式碼中註冊這些 Agent，或將 Mastra 作為獨立伺服器執行。

:::

:::tip[📹 觀看]

[如何建立第一個檔案式 Agent](https://www.youtube.com/watch?v=5Kfn-oYkJNg\&t=18s)

:::

使用檔案式 Agent 時，Mastra 會自動從 `src/mastra/` 下受支援的檔案中[找到](/reference/file-based-agents/config#discovery-lifecycle) Agent 及相關基礎元件。你可按慣例組織這些檔案，而無需在 [`Mastra`](/reference/core/mastra-class) 實例中逐一匯入和註冊每個基礎元件。

檔案系統會直接呈現項目結構，因此你和編程助手無需追查程式碼中的連接方式，也能了解項目各部分如何組合。

你可在整個項目中使用檔案式 Agent，亦可配合程式碼中定義的基礎元件逐步採用。目前並非所有 Mastra 功能或使用情境都獲支援。

### 建立第一個 Agent

檔案式 Agent 位於 `src/mastra/agents/` 下的專屬目錄中。要建立可運作的 Agent，請加入 `config.ts` 檔案來設定模型和執行階段選項，並加入 `instructions.md` 檔案來設定其常駐提示：

```text
src/mastra/agents/
  writing-assistant/
    config.ts
    instructions.md
```

目錄名稱會成為 Agent 的預設 `id` 和 `name`。在此範例中，Mastra 會將 Agent 註冊為 `writing-assistant`。

```typescript title="src/mastra/agents/writing-assistant/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

```markdown title="src/mastra/agents/writing-assistant/instructions.md"
Rewrite text clearly and concisely.
```

執行 `npx mastra dev`，開啟 Studio，然後選擇 `writing-assistant` 進行測試。

### 探索機制的運作方式

Mastra 使用路徑探索並命名檔案式功能。Agent 目錄會提供 Agent 的預設 `id` 和 `name`。例如，`tools/search_docs.ts` 會將 Tool 註冊為 `search_docs`，而 `skills/style-guide.md` 會將 Skill 註冊為 `style-guide`。請參閱下方的擴充路徑。

### 擴充 Agent

當 Agent 需要更多功能時，請加入檔案或目錄：

| 路徑 | 加入的功能 |
| - | - |
| [`tools/<tool-name>.ts`](/reference/file-based-agents/tools) | 模型可呼叫的函式 |
| [`skills/<skill-name>.md`](/reference/file-based-agents/skills) | Agent 在相關情況下載入的詳細指引 |
| [`memory.ts`](/reference/file-based-agents/memory) | 對話記錄和工作上下文 |
| [`workspace.ts` and `workspace/`](/reference/file-based-agents/workspace) | 檔案系統和 shell 存取權 |
| [`subagents/<agent-id>/`](/reference/file-based-agents/subagents) | 上層可委派任務的專門 Agent |

將每項功能放在使用它的 Agent 旁。開發伺服器啟動或重新啟動時，Mastra 會探索並註冊這些檔案。

瀏覽[檔案式 Agent 參考](/reference/file-based-agents/config)，了解所有支援的檔案慣例和設定選項。
