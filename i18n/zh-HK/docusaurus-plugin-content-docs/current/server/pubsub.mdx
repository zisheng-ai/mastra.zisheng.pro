# PubSub

Mastra 使用 publish/subscribe（pub/sub）系統作為內部 event bus。組件將事件發佈至 topic，其他組件則訂閱這些 topic 並作出反應。你配置的 backend 會決定事件的傳送範圍：在單一進程內、同一 host 的多個進程之間，或不同 instance 之間。

你只需在 `Mastra` instance 上設定一次 backend，系統其他部分便可直接使用，毋須改動。Mastra 預設使用毋須設定的 in-process backend。

## Mastra 如何使用 PubSub

多個內置系統會透過同一條 pub/sub bus 發佈及訂閱事件：

- **Workflow 執行**：scheduler 發佈 `workflow.start` 事件，由長期運行的 worker 接收並執行 Workflow。執行期間，step 及 lifecycle 事件會經 pub/sub 傳送。
- **排程 Workflow**：scheduler 透過向 Workflow topic 發佈事件，分派到期的 run。請參閱[排程 Workflow](/docs/workflows/scheduled-workflows)。
- **背景 task**：task manager 將工作分派至 worker group，並把 task lifecycle 更新廣播至 subscriber，讓背景 task stream 保持即時更新。請參閱[背景 task 串流](/docs/long-running-agents/background-tasks#subscribe-to-all-task-events)。
- **Agent signal**：向執行中的 Agent run 傳送 signal 時，系統會在 thread topic 上發佈事件，讓另一進程中執行的 run 接收 signal。
- **可恢復串流**：每個 run 的串流 chunk 都會被發佈，因此客戶端重新連線時，可重播錯過的內容。

由於這些系統都在同一條 bus 上運行，你選擇的 backend 會同時套用至所有系統。

## 傳送模式

Backend 會以 [`PubSub`](/reference/pubsub/base) 合約所定義的兩種模式之一傳送事件：

- **Pull**：consumer 主動從 backend 讀取資料；Mastra 透過長期運行的 worker loop 執行此操作。[`RedisStreamsPubSub`](/reference/pubsub/redis-streams) 等分散式 backend 使用此模式。
- **Push**：事件毋須 consumer 主動要求便會送達，可在進程內或經 HTTP 傳送。預設的 [`EventEmitterPubSub`](/reference/pubsub/event-emitter) 會在進程內以此方式傳送。

Subscriber 亦可透過 consumer group 分配工作。同一 group 的成員會分擔事件，確保每個事件只處理一次。沒有 group 的 subscriber 會接收每個事件，令串流廣播至所有未分組的 subscriber。

## 預設 backend

如未設定 `pubsub` 選項，Mastra 會使用 [`EventEmitterPubSub`](/reference/pubsub/event-emitter)。它透過 Node.js [`EventEmitter`](https://nodejs.org/api/events.html#class-eventemitter) 在進程內傳送事件，因此毋須任何外部服務即可運作。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

// No pubsub option: Mastra uses EventEmitterPubSub
export const mastra = new Mastra({})
```

由於它在進程內運行，事件不會持久儲存，亦不會傳送至其他進程。預設設定適合涵蓋大多數應用程式的單一 instance。

## 選擇 backend

設定 `pubsub` 選項於 `Mastra` instance 上，以選擇 backend。每個 backend 都實作相同的 [`PubSub`](/reference/pubsub/base) 合約，因此應用程式其他部分毋須改動。

關鍵問題是 subscriber 在哪裏運行。

| Backend | 範圍 | 模式 | 套件 |
| - | - | - | - |
| [`EventEmitterPubSub`](/reference/pubsub/event-emitter) | 單一進程 | Pull 及 push | `@mastra/core` |
| [`UnixSocketPubSub`](/reference/pubsub/unix-socket-pubsub) | 同一 host 的多個進程 | Push | `@mastra/core` |
| [`RedisStreamsPubSub`](/reference/pubsub/redis-streams) | 分散式、多個 host | Pull | `@mastra/redis-streams` |
| [`GoogleCloudPubSub`](/reference/pubsub/google-cloud-pubsub) | 分散式、多個 host | Pull | `@mastra/google-cloud-pubsub` |

### 同一 host 上的多個進程

如同一部機器上的多個進程需要共用串流，請使用 [`UnixSocketPubSub`](/reference/pubsub/unix-socket-pubsub)。它透過 Unix domain socket 傳送事件，並選出一個進程作為 broker。如 broker 結束，其餘進程會選出新的 broker。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { UnixSocketPubSub } from '@mastra/core/events'

export const mastra = new Mastra({
  pubsub: new UnixSocketPubSub('/tmp/mastra/events.sock'),
})
```

### 分散式部署

如運行多個 instance 或 host，請使用分散式 backend，確保每個 instance 都收到相同事件。當一個 instance 處理的請求需要傳送至另一個 instance 上運行的工作時，這一點尤其重要。

例如，向 Agent run 傳送 signal 時，signal event 必須跨越進程邊界，送達擁有該 run 的 instance。使用預設的 in-process backend 時，該 instance 永遠不會收到事件。

以下兩個 backend 都可跨進程及 host 傳送事件，並持久儲存事件以便重新傳送。

以下範例使用 [Redis Streams](https://redis.io/docs/latest/develop/data-types/streams/)：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { RedisStreamsPubSub } from '@mastra/redis-streams'

export const mastra = new Mastra({
  pubsub: new RedisStreamsPubSub({
    url: 'redis://localhost:6379',
  }),
})
```

以下範例使用 [Google Cloud Pub/Sub](https://cloud.google.com/pubsub/docs)：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { GoogleCloudPubSub } from '@mastra/google-cloud-pubsub'

export const mastra = new Mastra({
  pubsub: new GoogleCloudPubSub({
    projectId: 'my-project',
  }),
})
```

## 可恢復串流

可恢復串流讓客戶端重新連線並重播錯過的事件，因此 backend 必須保留近期記錄。[`RedisStreamsPubSub`](/reference/pubsub/redis-streams) 等分散式 backend 會持久儲存事件，故本身已支援重播。

In-process 傳送不會保留記錄。如要在 [`EventEmitterPubSub`](/reference/pubsub/event-emitter) 上加入重播功能，請以 [`CachingPubSub`](/reference/pubsub/caching-pubsub) 包裝它。後者會按 topic 記錄已發佈的事件，讓較遲加入或重新連線的 subscriber 在繼續接收即時事件前補回遺漏內容。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { CachingPubSub, EventEmitterPubSub } from '@mastra/core/events'
import { InMemoryServerCache } from '@mastra/core/cache'

const cache = new InMemoryServerCache()

export const mastra = new Mastra({
  pubsub: new CachingPubSub(new EventEmitterPubSub(), cache),
})
```

請參閱 [PubSub 參考](/reference/pubsub/base)，了解完整傳送合約及每個 backend 的配置選項。
