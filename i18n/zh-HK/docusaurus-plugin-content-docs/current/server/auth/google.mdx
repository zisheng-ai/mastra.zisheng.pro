# Google

`@mastra/auth-google` 依賴套件使用 Google Workspace，為 Mastra 提供身份驗證及按角色存取控制。它支援採用加密 session cookie 的 OAuth 2.0 / OIDC 登入流程、驗證 Google ID token，並把 Google Workspace 群組對應至 Mastra 權限。

當 Studio 用戶以 Google 登入，而存取權應限於一個或多個 Google Workspace 網域時，便可使用此依賴套件。

## 先決條件

本指南使用 Google Workspace 身份驗證。請確保你已：

1. 建立或選取 Google Cloud 項目
1. 為網頁應用程式設定 OAuth client
1. 把 Mastra SSO callback URL 加入已授權的 redirect URI
1. 如計劃使用 RBAC，配置 Google Workspace 群組

如使用 Google Groups RBAC，亦要配置具備全網域委派的 Google Workspace service account，並授予 Directory API 唯讀群組 scope：

```text
https://www.googleapis.com/auth/admin.directory.group.readonly
```

請確保已設定環境變數。

```env title=".env"
GOOGLE_CLIENT_ID=your-client-id.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=your-client-secret
GOOGLE_REDIRECT_URI=http://localhost:4111/api/auth/sso/callback
GOOGLE_COOKIE_PASSWORD=a-random-string-at-least-32-characters-long
GOOGLE_ALLOWED_DOMAINS=example.com

GOOGLE_SERVICE_ACCOUNT_EMAIL=service-account@project.iam.gserviceaccount.com
GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n"
GOOGLE_WORKSPACE_ADMIN_EMAIL=admin@example.com
```

:::note

`GOOGLE_COOKIE_PASSWORD` 會加密 session cookie。如省略此設定，系統會使用自動產生的值，但伺服器重新啟動後便會失效。在生產環境中，請明確設定此值。

`MastraAuthGoogle` 會自動讀取 `GOOGLE_*` 身份驗證變數。以上所示的 service account 變數，則由你傳給 `MastraRBACGoogle` 的配置程式碼讀取。

:::

## 安裝

使用 `MastraAuthGoogle` 類別前，請安裝 `@mastra/auth-google` 依賴套件。

```bash npm2yarn
npm install @mastra/auth-google
```

## 使用範例

### 配合環境變數的基本用法

設定上述環境變數後，所有 constructor 參數均為選填：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthGoogle } from '@mastra/auth-google'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthGoogle(),
  },
})
```

:::warning

請使用 `allowedDomains` 或 `GOOGLE_ALLOWED_DOMAINS` 強制限制 Workspace 存取。Mastra 會檢查 Google 已驗證的 `hd` claim，而非電郵地址的 suffix。

:::

### 自訂配置

如不想依賴環境變數，可直接傳入 constructor 選項：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthGoogle } from '@mastra/auth-google'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthGoogle({
      clientId: process.env.GOOGLE_CLIENT_ID,
      clientSecret: process.env.GOOGLE_CLIENT_SECRET,
      redirectUri: process.env.GOOGLE_REDIRECT_URI,
      allowedDomains: ['example.com'],
    }),
  },
})
```

### 配合 Google Groups RBAC 的身份驗證

加入 `MastraRBACGoogle`，把 Google Workspace 群組對應至 Mastra 權限：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthGoogle, MastraRBACGoogle } from '@mastra/auth-google'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthGoogle(),
    rbac: new MastraRBACGoogle({
      serviceAccount: {
        clientEmail: process.env.GOOGLE_SERVICE_ACCOUNT_EMAIL!,
        privateKey: process.env.GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY!,
        subject: process.env.GOOGLE_WORKSPACE_ADMIN_EMAIL!,
      },
      roleMapping: {
        'admins@example.com': ['*'],
        'engineering@example.com': ['agents:*', 'workflows:*', 'tools:*'],
        'viewers@example.com': ['agents:read', 'workflows:read'],
        _default: [], // users with unmapped groups get no permissions
      },
    }),
  },
})
```

### 跨 Provider 用法

使用其他身份 Provider（Auth0、Clerk 等）登入，並透過 Google Workspace 群組進行 RBAC。傳入 `getUserKey` 函式，從其他 Provider 的用戶物件解析 Google Directory API 用戶金鑰：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthAuth0 } from '@mastra/auth-auth0'
import { MastraRBACGoogle } from '@mastra/auth-google'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthAuth0(),
    rbac: new MastraRBACGoogle({
      getUserKey: user => {
        if (!user || typeof user !== 'object') return undefined

        const { email } = user as { email?: unknown }
        return typeof email === 'string' ? email : undefined
      },
      serviceAccount: {
        clientEmail: process.env.GOOGLE_SERVICE_ACCOUNT_EMAIL!,
        privateKey: process.env.GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY!,
        subject: process.env.GOOGLE_WORKSPACE_ADMIN_EMAIL!,
      },
      roleMapping: {
        'engineering@example.com': ['agents:*', 'workflows:*'],
        'admins@example.com': ['*'],
        _default: [],
      },
    }),
  },
})
```

請瀏覽 [MastraAuthGoogle](/reference/auth/google)，查看所有可用配置選項。

## 角色對應

`roleMapping` 選項把 Google Workspace 群組電郵地址對應至 Mastra 權限字串陣列。權限採用 `resource:action` 格式，並支援 wildcard：

```typescript
const rbac = new MastraRBACGoogle({
  roleMapping: {
    // full access to everything
    'admins@example.com': ['*'],

    // full access to agents and workflows
    'engineering@example.com': ['agents:*', 'workflows:*'],

    // read-only access
    'viewers@example.com': ['agents:read', 'workflows:read'],

    // users whose groups don't match any key above
    _default: [],
  },
})
```

預設會使用群組電郵地址作為角色 ID。如要按群組名稱或其他屬性對應，請使用 `mapGroupToRoles`。`_default` key 會為 Google Workspace 群組不符合任何其他 key 的用戶指派權限。

## Client 端設定

啟用身份驗證後，向 Mastra 路由發出的請求必須通過身份驗證。使用 `GOOGLE_CLIENT_SECRET` 啟用 SSO 時，`MastraAuthGoogle` 會使用 Google 登入，並在登入後設定加密 session cookie。

### Cookie session（建議）

如需發出跨 origin 請求（例如 `:3000` 上的 frontend 呼叫 `:4111` 上的 Mastra），請在 Mastra 伺服器上啟用 CORS credentials：

```typescript title="src/mastra/index.ts"
export const mastra = new Mastra({
  server: {
    auth: new MastraAuthGoogle(),
    cors: {
      origin: 'http://localhost:3000',
      credentials: true,
    },
  },
})
```

配置 client 以加入 credentials：

```typescript title="lib/mastra-client.ts"
import { MastraClient } from '@mastra/client-js'

export const mastraClient = new MastraClient({
  baseUrl: 'http://localhost:4111',
  credentials: 'include',
})
```

### Bearer token

你亦可以把 Google ID token 當作 Bearer token 傳入。Mastra 會使用 Google 的 JSON Web Key Set（JWKS）endpoint 驗證 token：

```typescript title="lib/mastra-client.ts"
import { MastraClient } from '@mastra/client-js'

export const createMastraClient = (idToken: string) => {
  return new MastraClient({
    baseUrl: 'http://localhost:4111',
    headers: {
      Authorization: `Bearer ${idToken}`,
    },
  })
}
```

請瀏覽 [Mastra Client SDK](/docs/server/mastra-client)，查看更多配置選項。

## 疑難排解

- **登入後出現 401**：檢查 `GOOGLE_CLIENT_ID`、`GOOGLE_CLIENT_SECRET` 及 `GOOGLE_REDIRECT_URI` 是否與 Google Cloud OAuth client 相符。
- **Workspace 用戶遭拒絕**：確認 `GOOGLE_ALLOWED_DOMAINS` 與 Google ID token 的 `hd` claim 相符。
- **一般 Gmail 帳戶遭拒絕**：配置 `allowedDomains` 後，這是預期行為，因為 Gmail 帳戶沒有 Workspace `hd` claim。
- **RBAC 傳回預設權限**：系統未能解析用戶的角色。請確認用戶電郵或自訂 `getUserKey`、Google 群組成員資格及 `roleMapping`。如 Directory API lookup 失敗，Provider 會拋出錯誤，而非傳回 `_default`。
- **Cookie 未有隨跨 origin 請求傳送**：設定 `credentials: "include"` 供 `MastraClient` 使用，並在 `server.cors` 中配置 frontend origin 及 `credentials: true`。
- **重新啟動後 session 遺失**：把 `GOOGLE_COOKIE_PASSWORD` 設為至少 32 個字元的固定值。如未設定，開發環境會使用自動產生的金鑰，而且每次重新啟動都會改變。
