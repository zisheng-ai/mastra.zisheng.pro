# 伺服器概覽

Mastra 以 HTTP 伺服器形式運行，將你的 Agent、Workflow 及其他功能公開為 API 端點。伺服器負責請求路由、執行 middleware、驗證及串流回應。

:::info

本頁介紹 [`server`](/reference/configuration#server-options) 配置選項；這些選項會傳遞至 `Mastra` constructor。如要以你自己的 HTTP 伺服器（Hono、Express 等）運行 Mastra，請參閱[伺服器 Adapter](/docs/server/server-adapters)。

:::

## 伺服器功能

- **[Middleware](/docs/server/middleware)**：攔截請求，以進行驗證、記錄、CORS，或注入請求專屬的 context。
- **[自訂 API Route](/docs/server/custom-api-routes)**：加入你自己的 HTTP 端點來擴充伺服器，並可存取 Mastra instance。
- **[Request Context](/docs/server/request-context)**：根據 runtime 條件，向 Agent、Tool 及 Workflow 傳遞請求專屬的值。
- **[伺服器 Adapter](/docs/server/server-adapters)**：以 Express、Hono 或你自己的 HTTP 伺服器運行 Mastra，而非使用產生的伺服器。
- **[自訂 Adapter](/docs/server/custom-adapters)**：為未獲官方支援的 framework 建立 Adapter。
- **[Mastra Client SDK](/docs/server/mastra-client)**：用於從瀏覽器或伺服器環境呼叫 Agent、Workflow 及 Tool 的 type-safe 客戶端。
- **[A2A](/docs/agents/a2a)**：透過 A2A agent card 及 task stream 公開 Agent，並支援推送通知。
- **[驗證](/docs/server/auth)**：使用 JWT、Clerk、Supabase、Firebase、Auth0 或 WorkOS 保護端點。

## 配置

將 `server` object 傳遞至 `Mastra` constructor，以配置伺服器：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    port: 3000, // Defaults to PORT env var or 4111
    host: '0.0.0.0', // Defaults to MASTRA_HOST env var or 'localhost'
  },
})
```

請參閱[配置參考](/reference/configuration#server-options)，了解所有可用的伺服器選項。

## 部署伺服器

Mastra 伺服器可部署至任何兼容 Node.js 的環境。你可以使用 [Mastra 平台](/docs/mastra-platform/overview)或自己的基礎設施部署至 production。請參閱[部署文件](/docs/deployment/overview)了解詳情。

## 伺服器架構

Mastra 使用 [Hono](https://hono.dev) 作為底層 HTTP 伺服器 framework。使用 `mastra build` 建構 Mastra 應用程式時，它會在 `.mastra` 目錄中產生基於 Hono 的 HTTP 伺服器。

伺服器提供：

- 所有已註冊 Agent 及 Workflow 的 API 端點
- 自訂 API Route 及 middleware
- 跨 Provider 的驗證
- 用於 runtime 配置的 Request Context
- 保護回應的串流資料遮罩

## REST API

你可在 [http://localhost:4111/api/openapi.json](http://localhost:4111/api/openapi.json) 的 OpenAPI 規格中查看所有可用端點，當中詳列每個端點及其請求與回應 schema。

如要以互動方式探索 API，請前往 [http://localhost:4111/swagger-ui](http://localhost:4111/swagger-ui) 的 Swagger UI。你可在瀏覽器中查看端點並直接測試。

:::note

OpenAPI 及 Swagger 端點在 production 預設停用。如要啟用，請分別將 [`server.build.openAPIDocs`](/reference/configuration#serverbuild) 及 [`server.build.swaggerUI`](/reference/configuration#serverbuild) 設為 `true`。

:::

## OpenAI Responses API

Mastra 公開兼容 OpenAI 的 Responses 及 Conversations route，讓你以 Mastra Agent 作為 Responses API。這些 route 是建基於 Agent 的 Adapter，位於 Mastra Agent、memory 及 storage 之上，因此請求會經由所選的 Mastra Agent 執行，而非作為原始 Provider proxy。

這些 API 目前屬實驗性質。

使用 `agent_id` 選擇應處理請求的 Mastra Agent。初始請求會直接傳送至 Agent，而已儲存的後續輪次可使用 `previous_response_id` 繼續。你亦可傳遞 `model`，為單一請求覆寫 Agent 已配置的 model。如省略 `model`，Mastra 會使用 Agent 已配置的 model。

Responses route 支援串流、function calling（Tool）、使用 `previous_response_id` 的已儲存延續內容、透過 `conversation_id` 建立 conversation thread、使用 `providerOptions` 傳遞 Provider 專屬選項，以及透過 `text.format` 輸出 JSON。

如要了解完整請求及回應合約，請參閱 [Responses API 參考](/reference/client-js/responses)及 [Conversations API 參考](/reference/client-js/conversations)。如要查看完整 HTTP route 清單，請參閱[伺服器 route](/reference/server/routes#responses-api)。

## 串流資料遮罩

串流傳送 Agent 回應時，HTTP 層會先從每個 chunk 中遮蔽 system prompt、Tool 定義、API 金鑰及類似資料，才傳送至客戶端。此功能預設啟用。

此行為只能透過[伺服器 Adapter](/docs/server/server-adapters#stream-data-redaction)配置。伺服器 Adapter 同樣預設啟用串流資料遮罩。

## TypeScript 配置

Mastra 要求 `module` 及 `moduleResolution` 設定兼容現代 Node.js。不支援 `CommonJS` 或 `node` 等舊式選項。

```json {4-5} title="tsconfig.json"
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ES2022",
    "moduleResolution": "bundler",
    "esModuleInterop": true,
    "forceConsistentCasingInFileNames": true,
    "strict": true,
    "skipLibCheck": true,
    "noEmit": true,
    "outDir": "dist"
  },
  "include": ["src/**/*"]
}
```
