# Studio

Studio 提供互動式介面，讓你建立、測試及管理 Agent、Workflow 和 Tool。你可以在開發期間於本機運行 Studio、加入[身份驗證](/docs/studio/auth)，或將其[部署](/docs/studio/deployment)至生產環境，讓團隊管理 Agent、監察效能，並透過內置的可觀測性功能取得深入分析。

:::tip[📹 觀看影片]

觀看 [Mastra Studio 概覽](https://youtu.be/ojGu6Bi4wYk)，快速了解如何在 Studio 中建立、測試及管理 Agent。

:::

## 啟動 Studio

如果你使用 `create mastra` 建立應用程式，請使用 `dev` 腳本啟動開發伺服器。你亦可以直接使用 `mastra dev` 運行。

```bash npm2yarn
npm run dev
```

伺服器運行後，你可以：

- 開啟 [`localhost:4111`](http://localhost:4111/) 的 Studio 介面，與 Agent、Workflow 和 Tool 互動。
- 前往 [`localhost:4111/swagger-ui`](http://localhost:4111/swagger-ui)，探索底層 REST API 並與其互動。

Studio 運行期間，你可以即時編輯 Mastra 應用程式中的 [Agent](/docs/agents/overview)、[Workflow](/docs/workflows/overview)及其他部分。

## 部署 Studio

準備好與團隊共用 Studio 時，你可以使用 [Mastra 平台上的 Studio](/docs/mastra-platform/studio) 或自己的基礎設施，將其部署至生產環境。詳情請參閱[部署文件](/docs/studio/deployment)。

## 基本元件

### Agent

直接與 Agent 對話、切換[模型](/models)，並調整 temperature 和 top-p 等設定，以了解它們如何影響輸出。

與 Agent 互動時，你可以追蹤其推理過程並查看 Tool 呼叫的輸出。你亦可以[觀察](#observability) Trace 和日誌，了解回應的產生方式。

你亦可以附加 [scorer](#scorers)，持續衡量及比較回應質素。

在 Agent 串流回應期間，你可以在同一對話串傳送跟進訊息。Studio 會將該訊息顯示為待處理，直至串流確認訊息為止，然後在跟進訊息下方繼續顯示回應。其他開啟了同一對話串的 Studio 分頁亦可觀察進行中的串流。

使用 [Editor](/docs/editor/overview)，讓非技術團隊成員反覆調整 Agent、為每項變更建立版本，並在無需重新部署的情況下進行實驗。

### Workflow

以圖形方式呈現 Workflow，並使用自訂輸入逐步運行。執行期間，介面會即時更新，顯示目前步驟及所採用的路徑。

運行 Workflow 時，你亦可以查看詳細 Trace，其中顯示 Tool 呼叫、原始 JSON 輸出，以及過程中可能發生的任何錯誤。

### Processor

查看附加至每個 Agent 的輸入及輸出 Processor。Agent 詳情面板會按名稱和類型列出每個 Processor，讓你在測試前確認防護措施、token 限制器及自訂 Processor 均已正確連接。

有關配置詳情，請參閱 [processor](/docs/agents/processors)及[防護措施](/docs/agents/guardrails)。

### MCP 伺服器

列出附加至 Mastra 執行個體的 MCP 伺服器，並探索其可用 Tool。

### Tool

單獨運行 Tool 以觀察其行為，並在指派給 Agent 前進行測試。如有問題，可獨立重新運行 Tool 以除錯。

### Workspace

使用內置檔案瀏覽器，瀏覽 Agent Workspace 檔案系統中的檔案。你可以切換 Workspace 掛載點、建立目錄，以及使用語法醒目提示查看檔案內容。可寫入的 Workspace 允許建立目錄及刪除檔案；唯讀 Workspace 則會有相應標示。Skills 分頁會列出所有已找到的 Skill，包括其指示、參考資料及 metadata。你可以從 [skills.sh](https://skills.sh) 安裝社群 Skill，或移除現有 Skill。

有關配置詳情，請參閱 [Workspace](/docs/workspace/overview)。

### 請求上下文

設定運行時變數，透過依賴注入傳送至 Agent 的指示和 Tool。你可以使用 JSON 編輯請求上下文；如果 Agent 定義了 `requestContextSchema`，亦可以使用由 schema 驅動的表單。值會在測試對話和實驗之間保留，讓你無需重新啟動即可觸發條件流程。

有關配置詳情，請參閱[請求上下文](/docs/server/request-context)。

## 評估

使用日期篩選器，將分數指標限制於預設或自訂時間範圍內。

### Scorer

Scorers 分頁會在 Agent 的 scorer 運行時顯示其結果。訊息通過 Agent 時，已定義的 scorer 會以非同步方式評估每項輸出，並在此顯示結果。你可以了解 scorer 如何回應不同互動、比較各測試案例的效能，並找出可改善之處。

### Dataset

建立及管理測試案例集合，以評估 Agent 和 Workflow。從 CSV 或 JSON 匯入項目並定義輸入和標準答案 schema，亦可固定至特定版本，確保實驗可完全重現。使用 [scorer](/docs/evals/overview) 進行實驗，比較不同提示、模型或程式碼變更的質素。

如需完整 API 及版本管理詳情，請參閱 [Dataset 概覽](/docs/datasets/overview)。

### 實驗

針對 Agent、Workflow 或 scorer 運行 Dataset 中的所有項目，並集中收集結果。選擇目標、按需要附加 scorer，然後觸發實驗。結果檢視會顯示每個項目的輸入、輸出、狀態及個別分數明細。並排比較兩項實驗，以衡量提示、模型或程式碼變更帶來的影響。

有關設定詳情，請參閱 [Dataset 概覽](/docs/datasets/overview)。

## 設定

配置 Studio 與 Mastra 伺服器之間的連線。設定頁面包括：

- **Mastra 執行個體 URL**：Mastra 伺服器的基礎 URL（例如 `http://localhost:4111`）。
- **API 前綴**：所有 API 請求的可選路徑前綴（預設為 `/api`）。
- **自訂標頭**：加入隨每個請求傳送的鍵值配對，適用於身份驗證 token 或路由標頭。
- **主題**：切換深色、淺色或系統主題。

## 程式碼配置

除了使用[設定](#settings)介面外，你亦可以使用 [`server`](/reference/configuration#server-options) 選項，在 `src/mastra/index.ts` 中配置本機開發伺服器和 Studio。

Studio 預設在 [http://localhost:4111](http://localhost:4111) 運行。你可以變更 [`host`](/reference/configuration#serverhost) 和 [`port`](/reference/configuration#serverport)。

Mastra 亦透過 [`--https`](/reference/cli/mastra#--https) flag 支援 HTTPS 開發，並會自動為你的項目建立和管理憑證。運行 `mastra dev --https` 時，系統會為 localhost（或你配置的 host）產生私密金鑰和憑證。詳情請參閱 [HTTPS 參考資料](/reference/configuration#serverhttps)。
