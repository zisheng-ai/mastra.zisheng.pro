# Studio

Mastra 會透過 `src/mastra/` 直屬的 `studio.ts` 檔案設定 [Studio](/docs/studio/overview)。該檔案會預設匯出一個用於 Studio 身份驗證和授權的 `StudioConfig` 物件：哪些人可以存取 Studio，以及已驗證身份的用戶可以執行哪些操作。

本頁說明檔案式慣例。如需了解身份驗證 Provider、角色型存取控制 (RBAC) 及細緻授權 (FGA)，請參閱 [Studio 身份驗證](/docs/studio/auth)。

## 快速開始 {/* #quickstart */}

在本機開發時，你不需要 `studio.ts`。啟動開發伺服器並開啟 Studio：

```bash npm2yarn
npm run dev
```

在本機開發環境中，Studio 會直接開啟而無需身份驗證。當你準備好保護共享或生產環境部署時，再加入 `studio.ts`。

## 加入身份驗證 {/* #add-authentication */}

使用身份驗證 Provider，要求用戶必須先登入才能存取 Studio。以下範例使用 [WorkOS](/docs/server/auth/workos)：

```typescript title="src/mastra/studio.ts"
import { MastraAuthWorkos } from '@mastra/auth-workos'
import type { StudioConfig } from '@mastra/core/server'

export default {
  auth: new MastraAuthWorkos(),
} satisfies StudioConfig
```

身份驗證 Provider 負責識別用戶身份。如要設定用戶登入後可執行的操作，請在相同設定中加入 RBAC 或 FGA。完整範例請參閱 [Studio 身份驗證](/docs/studio/auth)。

## 與程式碼設定的優先次序 {/* #precedence-with-code */}

以程式碼註冊的 Studio 設定優先於 `studio.ts`。如果整個項目使用一項 Studio 設定已足夠，請使用 `studio.ts`；如果身份驗證取決於 `src/mastra/index.ts` 中的執行階段連接方式，請使用程式碼註冊。
