# OtelBridge

:::warning

OpenTelemetry Bridge 目前仍屬**實驗性質**。API 及設定選項可能會在日後版本變更。

:::

讓 Mastra tracing 與 OpenTelemetry 基礎架構雙向整合。為 Mastra 操作建立原生 OTEL span，並從使用中的 OTEL span 繼承 context。同時亦會將 Mastra log event 轉送至全域註冊的 OTEL `LoggerProvider`，並在原始 Mastra span 的 OTEL context 下發出每個 log，讓 Trace 與 log 自動建立關聯。

## 建構函數

```typescript
new OtelBridge()
```

## 方法

### `executeInContext`

```typescript prettier:false
executeInContext<T>(spanId: string, fn: () => Promise<T>): Promise<T>
```

在 Mastra span 的 OTEL context 中執行非同步函數。在該函數內執行且已配置 OTEL instrumentation 的程式碼，會具有正確的 parent 關係。

### `onLogEvent`

```typescript prettier:false
async onLogEvent(event: LogEvent): Promise<void>
```

將 Mastra log event 轉送至全域註冊的 OTEL `LoggerProvider`。Trace 關聯會按以下次序解析：

1. 如果 log 帶有 bridge 已有對應 OTEL span 的 `spanId`，便會在該 span 儲存的 OTEL context 下發出 log。
1. 否則，如果 log 帶有 `traceId` 及 `spanId`，這些 ID 會附加至所發出 log record 的 `SpanContext`。
1. 否則，log 會在當前使用中的 OTEL context 下發出。

如果未有全域註冊的 `LoggerProvider`，則不會發出任何內容，也不會顯示提示。

### `flush`

```typescript prettier:false
async flush(): Promise<void>
```

如果全域 OTEL tracer provider 及 logger provider 支援 `forceFlush`，便強制 flush 兩者。這對 serverless 環境尤其有用，可在 runtime 終止前清空 telemetry。

### `shutdown`

```typescript prettier:false
async shutdown(): Promise<void>
```

關閉 bridge 並清理資源。結束所有未有正確關閉的 span。

## 用法範例

### 基本用法

```typescript
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { OtelBridge } from '@mastra/otel-bridge'

const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-service',
        bridge: new OtelBridge(),
      },
    },
  }),
  agents: { myAgent },
})
```

### 配合匯出器使用

Bridge 可以與匯出器同時使用。Bridge 會處理 OTEL context，而匯出器則將資料傳送至其他目的地：

```typescript
import { Mastra } from '@mastra/core'
import { Observability, MastraStorageExporter } from '@mastra/observability'
import { OtelBridge } from '@mastra/otel-bridge'
import { LangfuseExporter } from '@mastra/langfuse'

const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-service',
        bridge: new OtelBridge(), // Handles OTEL context
        exporters: [
          new MastraStorageExporter(), // Studio access
          new LangfuseExporter({
            // Additional destination
            publicKey: process.env.LANGFUSE_PUBLIC_KEY,
            secretKey: process.env.LANGFUSE_SECRET_KEY,
          }),
        ],
      },
    },
  }),
})
```

## `OpenTelemetry` 設定要求

OtelBridge 需要使用中的 OpenTelemetry SDK 才能運作。Bridge 會從 OTEL 的 ambient context 讀取資料。

請參閱 [OtelBridge 指南](/docs/observability/integrations/bridges/otel#configuration)以了解完整設定指示，包括如何設定 OTEL instrumentation 及執行應用程式。

## Tag 支援

OtelBridge 支援以 Trace tag 進行分類及篩選。Tag 只會套用至 root span，並以 `mastra.tags` 屬性加入原生 OTEL span。

### 用法

```typescript
const result = await agent.generate('Hello', {
  tracingOptions: {
    tags: ['production', 'experiment-v2', 'user-request'],
  },
})
```

### Tag 的儲存方式

Tag 會在 `mastra.tags` span 屬性中，儲存為經 JSON stringify 的陣列：

```json
{
  "mastra.tags": "[\"production\",\"experiment-v2\",\"user-request\"]"
}
```

此格式可確保與所有兼容 OTEL 的後端及 Collector 配合使用。
