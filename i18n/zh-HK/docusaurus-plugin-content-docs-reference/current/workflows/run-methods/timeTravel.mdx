# Run.timeTravel()

`.timeTravel()` 方法會從任何指定步驟開始重新執行 Workflow，並使用已儲存的 snapshot 資料或你提供的自訂 context。你可以用它偵錯失敗的 Workflow，並以不同輸入測試個別步驟。它亦可從錯誤中復原，而毋須重新執行整個 Workflow。

## 使用範例 {/* #usage-example */}

```typescript
const run = await workflow.createRun()

const result = await run.timeTravel({
  step: 'step2',
  inputData: { value: 10 },
})
```

## 延伸使用範例 {/* #extended-usage-examples */}

### 使用自訂 context 進行 time travel {/* #time-travel-with-custom-context */}

```typescript
const result = await run.timeTravel({
  step: 'step2',
  context: {
    step1: {
      status: 'success',
      payload: { value: 0 },
      output: { step1Result: 2 },
      startedAt: Date.now(),
      endedAt: Date.now(),
    },
  },
})
```

### Time travel 至巢狀 Workflow 步驟 {/* #time-travel-to-nested-workflow-step */}

```typescript
// Using dot notation
const result = await run.timeTravel({
  step: 'nestedWorkflow.step3',
  inputData: { value: 10 },
})

// Using array of step IDs
const result = await run.timeTravel({
  step: ['nestedWorkflow', 'step3'],
  inputData: { value: 10 },
})
```

### 使用初始 state 進行 time travel {/* #time-travel-with-initial-state */}

```typescript
const result = await run.timeTravel({
  step: 'step2',
  inputData: { value: 10 },
  initialState: {
    counter: 5,
    metadata: { source: 'time-travel' },
  },
})
```

### 使用巢狀 Workflow context 進行 time travel {/* #time-travel-with-nested-workflows-context */}

```typescript
const result = await run.timeTravel({
  step: 'nestedWorkflow.step3',
  context: {
    step1: {
      status: 'success',
      payload: { value: 0 },
      output: { step1Result: 2 },
      startedAt: Date.now(),
      endedAt: Date.now(),
    },
    nestedWorkflow: {
      status: 'running',
      payload: { step1Result: 2 },
      startedAt: Date.now(),
    },
  },
  nestedStepsContext: {
    nestedWorkflow: {
      step2: {
        status: 'success',
        payload: { step1Result: 2 },
        output: { step2Result: 3 },
        startedAt: Date.now(),
        endedAt: Date.now(),
      },
    },
  },
})
```

## 注意事項 {/* #notes */}

- Time travel 依賴持久化的 Workflow snapshot，因此必須先設定 storage
- 重新執行 Workflow 時，Workflow 會從 storage 載入現有 snapshot（如有）
- 目標步驟之前的步驟結果會根據 snapshot 或所提供的 context 重建
- 系統會使用所提供或重建的輸入資料，從指定步驟開始執行
- Workflow 會從該處繼續執行直至完成
- 即使 Workflow 尚未執行過，只要為起始步驟提供自訂 context 或輸入資料，亦可使用 time travel。
