此範本是填寫個別遷移指南的樣式指引。請以此為依據，組織此目錄內的檔案。你不得偏離這個結構。

請依照 `.cursor/rules/writing-documentation.mdc` 的指示撰寫正文內容。

找出所有需要記錄的變更後，應將它們分成兩大類：「Changed」及「Removed」。

範例：

```md
## Changed

## Removed
```

所有變更都必須放在這兩個章節之下。

每項變更（無論是「changed」還是「removed」）都應使用 h3 標題。你必須嚴格遵從此格式。

範例：

```md
## Changed

### `oldFunction` to `newFunction`
```

標題就緒後，每項變更都必須依照完全一致的結構撰寫。你不得偏離這個結構。

用一至兩句話簡述變更，然後用一句話解釋變更原因。

每項變更的第三部分必須說明如何將現有程式碼遷移至新版本。內容應精簡清晰，但不要刪減過多資訊。其後必須提供使用「diff」語法的程式碼區塊，並以該語法在區塊內顯示需要修改的程式碼「遷移前」及「遷移後」範例。

範例：

````md
## Changed

### `oldFunction` to `newFunction`

The `oldFunction` has been renamed to `newFunction`. This change improves clarity and consistency across the API.

To migrate, replace all instances of `oldFunction` with `newFunction` in your codebase.

```diff
- const result = oldFunction(args);
+ const result = newFunction(args);
```
````

如果遷移需要執行的步驟多於尋找及取代，你可以在程式碼區塊前加入額外說明。如果需要多個步驟，請使用編號清單逐步清楚說明。
