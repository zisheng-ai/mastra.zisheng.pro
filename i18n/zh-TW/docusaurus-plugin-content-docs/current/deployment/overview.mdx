# 部署概覽

Mastra 應用程式可部署至任何與 Node.js 相容的環境。你可以部署 Mastra 伺服器、與現有 Web 框架整合、部署至雲端供應商，或使用 [Mastra 平台](/docs/mastra-platform/overview)進行可觀測性分析、使用 Studio 及部署伺服器。

## Runtime 支援 {/* #runtime-support */}

Mastra 可在下列任何 runtime 環境中執行：

- Node.js `v22.13.0` 或更新版本
- Bun
- Deno
- Cloudflare

## 部署選項 {/* #deployment-options */}

### Mastra 伺服器 {/* #mastra-server */}

Mastra 提供由 Hono 驅動、可獨立部署的[伺服器](/docs/server/mastra-server)。使用 `mastra build` 指令建置應用程式，再將輸出部署至偏好的 VM、容器或 PaaS 平台。

需要完整掌控基礎架構、長時間執行的處理程序或 WebSocket 連線時，請使用此選項。[Mastra 伺服器部署指南](/docs/deployment/mastra-server)提供更多詳細資訊。

### Monorepo {/* #monorepo */}

將 Mastra 伺服器部署為 monorepo 設定的一部分，方法與獨立部署相同。

請閱讀 [monorepo 部署](/docs/deployment/monorepo)。

### Mastra 平台 {/* #mastra-platform */}

[Mastra 平台](/docs/mastra-platform/overview)提供三項產品，可用來部署、監控及管理以 Mastra 框架建置的 AI 應用程式：

- [**可觀測性**](/docs/mastra-platform/observability)：獨立的託管產品，可搜尋各 Mastra 專案與部署的 Trace、記錄及指標
- [**Studio**](/docs/mastra-platform/studio)：用於測試 Agent、執行 Workflow 及檢查 Trace 的託管視覺化環境
- [**伺服器**](/docs/mastra-platform/server)：以 API 伺服器形式執行 Mastra 應用程式的正式環境部署目標

詳情請參閱 [Mastra 平台概覽](/docs/mastra-platform/overview)。

### 雲端供應商 {/* #cloud-providers */}

Mastra 應用程式可部署至雲端供應商與無伺服器平台。Mastra 內含適用於 Vercel、Netlify 與 Cloudflare 的選用內建部署器，可將建置和部署流程自動化。

需要自動擴展、儘量減少基礎架構管理，或已使用其中一個平台時，請使用此選項。

- [Amazon EC2](/guides/deployment/amazon-ec2)
- [AWS Lambda](/guides/deployment/aws-lambda)
- [Azure App Services](/guides/deployment/azure-app-services)
- [Cloudflare](/guides/deployment/cloudflare)
- [Digital Ocean](/guides/deployment/digital-ocean)
- [Kubernetes](/guides/deployment/kubernetes)
- [Netlify](/guides/deployment/netlify)
- [Vercel](/guides/deployment/vercel)

### Sandbox {/* #sandbox */}

將 Mastra 伺服器部署至暫時性的 Workspace Sandbox（例如 Vercel Sandbox 或 E2B），幾秒內即可取得可用的公開 URL。

此選項適合即時預覽、從 CI pipeline 部署、驗證 Agent 建置的應用程式，或為每位使用者執行不受信任的獨立執行個體。請閱讀 [Sandbox 部署指南](/docs/deployment/sandbox)。

### Web 框架 {/* #web-framework */}

Mastra 與 Web 框架整合後，會使用該框架的標準部署流程，隨應用程式一同部署。下列指南涵蓋部署時各框架特有的設定需求。

將 Mastra 加入現有的 Next.js 或 Astro 應用程式時，請使用這些指南。

- [在 Vercel 上搭配 Next.js](/docs/deployment/web-framework#with-nextjs-on-vercel)
- [在 Vercel 上搭配 Astro](/docs/deployment/web-framework#with-astro-on-vercel)
- [在 Netlify 上搭配 Astro](/docs/deployment/web-framework#with-astro-on-netlify)

## Workflow 執行器 {/* #workflow-runners */}

Mastra Workflow 預設使用內建執行引擎。若正式環境工作負載需要代管基礎架構，也可將 Workflow 部署至 [Inngest](https://www.inngest.com) 等專用平台，以使用步驟記憶化、自動重試及即時監控功能。

執行選項請參閱 [Workflow 執行器指南](/docs/deployment/workflow-runners)，設定說明請參閱 [Inngest 部署指南](/guides/deployment/inngest)。

## Workers {/* #workers */}

在正式環境部署中，Mastra 可在與 API 伺服器分離的專用 worker 處理程序內執行 Workflow 協調、cron 排程及背景 Tool。如此便能獨立擴展各項職責並隔離故障。詳情請參閱 [Workers](/docs/deployment/workers)。
