# Studio

Studio 提供互動式 UI，讓你建置、測試及管理 Agent、Workflow 和 Tool。你可以在開發期間於本機執行、加入[驗證](/docs/studio/auth)，或[部署至](/docs/studio/deployment)正式環境，讓團隊管理 Agent、監控效能，並透過內建可觀測性取得深入分析。

:::tip[📹 觀看影片]

觀看 [Mastra Studio 概觀](https://youtu.be/ojGu6Bi4wYk)，快速瞭解如何在 Studio 中建置、測試及管理 Agent。

:::

## 啟動 Studio

若應用程式是以 `create mastra` 建立，請使用 `dev` 指令碼啟動開發伺服器；也可以直接執行 `mastra dev`。

```bash npm2yarn
npm run dev
```

伺服器啟動後，你可以：

- 開啟 [`localhost:4111`](http://localhost:4111/) 的 Studio UI，與 Agent、Workflow 和 Tool 互動。
- 前往 [`localhost:4111/swagger-ui`](http://localhost:4111/swagger-ui)，探索底層 REST API 並與之互動。

Studio 執行期間，你可以即時編輯 Mastra 應用程式中的 [Agent](/docs/agents/overview)、[Workflow](/docs/workflows/overview)及其他部分。

## 部署 Studio

準備與團隊共用 Studio 時，可使用 [Mastra platform 上的 Studio](/docs/mastra-platform/studio) 或自己的基礎架構，將其部署至正式環境。詳情請參閱[部署文件](/docs/studio/deployment)。

## 基本元件

### Agents

直接與 Agent 對話、切換[模型](/models)，並調整 temperature 和 top-p 等設定，瞭解它們如何影響輸出。

與 Agent 互動時，你可以追蹤其推理過程並查看 Tool 呼叫輸出，也能[觀察](#observability) Trace 與記錄，瞭解回應的產生方式。

你也可以附加[評分器](#scorers)，持續評量及比較回應品質。

在 Agent 串流回應期間，你可以於同一討論串傳送後續訊息。Studio 會先將訊息顯示為等待中，直到串流確認後，再於該後續訊息下方繼續回應。開啟同一討論串的其他 Studio 分頁也能觀察進行中的串流。

使用 [Editor](/docs/editor/overview)，讓非技術團隊成員反覆調整 Agent、為每項變更建立版本，並在不重新部署的情況下執行實驗。

### Workflows

將 Workflow 視覺化為圖形，並使用自訂輸入逐步執行。執行期間，介面會即時更新，顯示目前步驟與實際採取的路徑。

執行 Workflow 時，也可查看詳細 Trace，其中會顯示 Tool 呼叫、原始 JSON 輸出，以及過程中可能發生的錯誤。

### Processors

查看附加至各 Agent 的輸入與輸出處理器。Agent 詳細資料面板會依名稱與類型列出每個處理器，讓你在測試前確認防護機制、權杖限制器及自訂處理器均已正確連接。

設定詳情請參閱[處理器](/docs/agents/processors)與[防護機制](/docs/agents/guardrails)。

### MCP servers

列出附加至 Mastra 執行個體的 MCP 伺服器，並探索其可用 Tool。

### Tools

單獨執行 Tool 以觀察行為，並在指派給 Agent 前進行測試。若發生問題，可單獨重新執行 Tool 來偵錯。

### Workspaces

使用內建檔案瀏覽器瀏覽 Agent Workspace 檔案系統中的檔案。你可以切換 Workspace 掛載點、建立目錄，並以語法醒目提示查看檔案內容。可寫入的 Workspace 允許建立目錄及刪除檔案；唯讀 Workspace 則會有相應標示。Skills 分頁會列出所有找到的 Skill，以及其操作說明、參考資料與中繼資料。你可以從 [skills.sh](https://skills.sh) 安裝社群 Skill，或移除現有 Skill。

設定詳情請參閱 [Workspace](/docs/workspace/overview)。

### Request context

設定執行階段變數，透過相依性注入傳入 Agent 指示與 Tool。你可以使用 JSON 編輯 request context；若 Agent 定義了 `requestContextSchema`，也可使用由結構描述驅動的表單。值會在測試對話與實驗之間保留，因此不必重新啟動即可觸發條件流程。

設定詳情請參閱 [request context](/docs/server/request-context)。

## 評估

使用日期篩選器，將分數指標限制在預設或自訂的時間範圍內。

### Scorers

Scorers 分頁會在 Agent 評分器執行時顯示結果。訊息通過 Agent 時，已定義的評分器會以非同步方式評估每項輸出，並在此呈現結果。你可以瞭解評分器對不同互動的反應、比較測試案例之間的效能，並找出可改善之處。

### Datasets

建立及管理測試案例集合，以評估 Agent 和 Workflow。從 CSV 或 JSON 匯入項目並定義輸入與標準答案結構描述，也可鎖定特定版本，確保實驗可精確重現。搭配[評分器](/docs/evals/overview)執行實驗，比較不同提示詞、模型或程式碼變更的品質。

完整 API 與版本控制詳情請參閱[資料集概觀](/docs/datasets/overview)。

### Experiments

針對 Agent、Workflow 或評分器執行資料集中的所有項目，並集中收集結果。選擇目標、視需要附加評分器，再觸發實驗。結果檢視會顯示各項目的輸入、輸出、狀態與個別分數明細。並排比較兩項實驗，即可衡量提示詞、模型或程式碼變更造成的影響。

設定詳情請參閱[資料集概觀](/docs/datasets/overview)。

## 設定

設定 Studio 與 Mastra 伺服器之間的連線。設定頁面包含：

- **Mastra instance URL**：Mastra 伺服器的基底 URL（例如 `http://localhost:4111`）。
- **API prefix**：所有 API 請求的選用路徑前綴（預設為 `/api`）。
- **Custom headers**：加入每個請求都會傳送的鍵值組，適合用於驗證權杖或路由標頭。
- **Theme**：切換深色、淺色或系統主題。

## 程式碼設定

除了[設定](#settings) UI 外，也可透過 `src/mastra/index.ts` 中的 [`server`](/reference/configuration#server-options) 選項設定本機開發伺服器與 Studio。

Studio 預設在 [http://localhost:4111](http://localhost:4111) 執行。你可以變更 [`host`](/reference/configuration#serverhost) 與 [`port`](/reference/configuration#serverport)。

Mastra 也透過 [`--https`](/reference/cli/mastra#--https) 旗標支援 HTTPS 開發，並會自動為專案建立及管理憑證。執行 `mastra dev --https` 時，系統會為 localhost（或設定的主機）產生私密金鑰與憑證。詳情請參閱 [HTTPS 參考文件](/reference/configuration#serverhttps)。
