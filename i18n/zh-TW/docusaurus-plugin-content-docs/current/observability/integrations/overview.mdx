# 整合總覽

Mastra Observability 整合可控制 Observability 資料的傳送目的地，以及資料匯出時的轉換方式。你可以透過整合將資料儲存在 Mastra Storage、傳送至 Mastra 平台、連線至外部 Observability Provider，或遮蔽匯出的 span 資料。

## 使用整合的時機

- 使用 `MastraStorageExporter`，讓 Observability 資料可在 Studio 中使用。
- 使用 `MastraPlatformExporter`，將代管的 Observability 資料傳送至 Mastra 平台。
- 將 Trace 轉送至 Datadog、Langfuse 或 OpenTelemetry 後端等外部 Provider。
- 在敏感值離開 runtime 前加以遮蔽。

## 選擇整合方式

- Studio Workflow：先從 [Mastra Storage](/docs/observability/integrations/exporters/mastra-storage) 開始。
- 代管的 Mastra Workflow：加入 [Mastra 平台](/docs/observability/integrations/exporters/mastra-platform)。
- 外部 Observability 技術堆疊：在側邊欄的 `Exporters` 區段中選擇一或多個 Exporter 頁面。
- 現有的分散式 Trace context：使用 Bridge，並視需要加入 Exporter。

## Exporter

Exporter 會將 Observability 資料傳送至目的地：

- [Mastra Storage](/docs/observability/integrations/exporters/mastra-storage)：保存 Observability 資料，供 Studio 使用。
- [Mastra 平台](/docs/observability/integrations/exporters/mastra-platform)：將代管的 Observability 資料傳送至 Mastra 平台。
- 外部 Provider：使用 Datadog、Langfuse、OpenTelemetry 與其他支援平台的 Exporter 頁面。

## Bridge

Bridge 會將 Mastra 連線至現有的分散式 Tracing context：

- [OpenTelemetry Bridge](/docs/observability/integrations/bridges/otel)：將 Mastra 整合至現有的 OpenTelemetry Trace。
- [Datadog Bridge](/docs/observability/integrations/bridges/datadog)：將 Mastra Trace 傳送至 Datadog 及其 LLM Observability 產品。

## Processor

Processor 會在匯出前轉換 span 或遮蔽其中的資料：

- [Sensitive Data Filter](/docs/observability/integrations/processors/sensitive-data-filter)：在 span 離開 runtime 前遮蔽敏感欄位。
