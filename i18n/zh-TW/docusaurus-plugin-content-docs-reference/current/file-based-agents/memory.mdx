# Memory

檔案式 Agent 會從 default export [`Memory`](/reference/memory/memory-class) instance 的 `memory.ts` 檔案取得 [Memory](/docs/memory/overview)。本頁說明檔案式慣例；如需訊息歷史、語意回憶、Storage 與 processor 的資訊，請參閱 Memory 文件。

若沒有 `memory.ts` 或 `config.memory`，Agent 預設不具備 Memory。除非你自行傳入先前的 context，否則每次 `generate()` 或 `stream()` 呼叫開始時，都不會有已記住的對話 state。

## 快速開始

在 Agent 的 `config.ts` 旁建立 `memory.ts`：

```typescript title="src/mastra/agents/weather/memory.ts"
import { Memory } from '@mastra/memory'

export default new Memory()
```

這個預設匯出的 instance 會成為 Agent 的 `memory`。如果你的應用程式在主要 Mastra instance 上設定了 Storage Provider，Memory 資料就會儲存在該處。詳情請參閱 [Storage](/docs/storage/overview)。

呼叫 Agent 時使用相同的 `resource` 與 `thread` 值，即可延續對話：

```typescript title="src/app/weather-chat.ts"
const response = await weatherAgent.generate('Remember that I prefer Celsius.', {
  memory: {
    resource: 'user-123',
    thread: 'weather-chat',
  },
})
```

## 設定 Memory

若預設行為不足以滿足需求，請將選項傳給 `new Memory()`。

```typescript title="src/mastra/agents/weather/memory.ts"
import { Memory } from '@mastra/memory'

export default new Memory({
  options: {
    lastMessages: 20,
    workingMemory: {
      enabled: true,
      scope: 'resource',
    },
  },
})
```

constructor 選項請參閱 [`Memory` 參考文件](/reference/memory/memory-class)。相關 Memory 功能請參閱以下頁面：

- [Storage](/docs/storage/overview)：設定 Memory 資料的持久化方式。
- [語意回憶](/docs/memory/semantic-recall)：依語意擷取相關的過往訊息。
- [Memory processor](/docs/memory/memory-processors)：在 Memory 將訊息加入模型 context 前，進行篩選、裁剪或轉換。

## 與 config 的優先順序

`config.memory` 優先於 `memory.ts`。如果兩者都不存在，組合完成的檔案式 Agent 將不具備 Memory。完整合併表請參閱 [`config.ts` 優先順序](/reference/file-based-agents/config#precedence)。
