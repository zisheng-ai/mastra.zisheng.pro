# Studio

Mastra 會透過 `src/mastra/` 正下方的 `studio.ts` 檔案設定 [Studio](/docs/studio/overview)。此檔案會 default export 一個 `StudioConfig` 物件，用於設定 Studio 的驗證與授權：誰可以存取 Studio，以及通過驗證的使用者可以執行哪些操作。

本頁說明檔案式慣例。若要了解驗證 Provider、角色型存取控制（RBAC）與細粒度授權（FGA），請參閱 [Studio 驗證](/docs/studio/auth)。

## 快速開始

進行本機開發時不需要 `studio.ts`。啟動開發伺服器並開啟 Studio：

```bash npm2yarn
npm run dev
```

在本機開發環境中，Studio 不需要驗證即可開啟。準備保護共用或正式環境部署時，再加入 `studio.ts`。

## 新增驗證

使用驗證 Provider，要求使用者必須登入才能存取 Studio。以下範例使用 [WorkOS](/docs/server/auth/workos)：

```typescript title="src/mastra/studio.ts"
import { MastraAuthWorkos } from '@mastra/auth-workos'
import type { StudioConfig } from '@mastra/core/server'

export default {
  auth: new MastraAuthWorkos(),
} satisfies StudioConfig
```

驗證 Provider 負責判定使用者身分。若要設定使用者登入後可以執行的操作，請在同一份設定中加入 RBAC 或 FGA。完整範例請參閱 [Studio 驗證](/docs/studio/auth)。

## 與程式碼設定的優先順序

以程式碼註冊的 Studio 設定優先於 `studio.ts`。當整個專案使用一份 Studio 設定即可時，請使用 `studio.ts`；若驗證取決於 `src/mastra/index.ts` 中的執行階段接線，請改用程式碼註冊。
