此範本是填寫個別遷移指南的風格指南。請以此作為本目錄中檔案結構的指引，不得偏離這個結構。

撰寫說明文字時，請遵循 `.cursor/rules/writing-documentation.mdc` 的指示。

找出所有需要記錄的變更後，應將它們分成兩大類：「Changed」與「Removed」。

範例：

```md
## Changed

## Removed
```

所有變更都必須放在這兩個區段之下。

每項變更（無論是「changed」或「removed」）都應使用 h3 標題。你必須完全遵循此格式。

範例：

```md
## Changed

### `oldFunction` to `newFunction`
```

標題就緒後，每項變更都必須遵循完全一致的結構，不得偏離這個結構。

先用一或兩句話簡述變更，再用一句話說明變更原因。

每項變更的第三個元素必須說明如何將現有程式碼遷移至新版本。內容應簡潔清楚，但不要刪減過多資訊。接著必須提供使用「diff」語法的程式碼區塊，並在區塊內以該語法呈現需要變更之程式碼的「遷移前」與「遷移後」範例。

範例：

````md
## Changed

### `oldFunction` to `newFunction`

The `oldFunction` has been renamed to `newFunction`. This change improves clarity and consistency across the API.

To migrate, replace all instances of `oldFunction` with `newFunction` in your codebase.

```diff
- const result = oldFunction(args);
+ const result = newFunction(args);
```
````

如果遷移作業不只是尋找並替換，可以在程式碼區塊前補充說明。如果需要多個步驟，請使用編號清單清楚說明每個步驟。
